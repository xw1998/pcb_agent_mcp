# 23 · 两张"读不到原文"的表：闭式拟合与行为反演

> 这一篇回答一个很具体的问题：**IPC-2152 与 IEC 60664-1 的表格都不在开源世界里能合法拿到的东西里，那凭什么敢把它们当答案发出去？**
>
> 两条路都被走过一遍，而且都不靠"我记得这个值"：
> 载流走**闭式拟合**（把别人公开的拟合式抄过来，用物理性质与锚点验它），
> 爬电/间隙走**行为反演**（编译 KiCad 的实现，反推阶梯，再用 20 万点对拍）。
> 结论是一样的：**数字的出处不是"我读对了表"，而是"我能证明这段代码的行为和我一致"。**

---

## 23.1 问题：付费标准 + 互相矛盾的公开复现

`creepage_required` / `clearance_required` 这两个工具从一落地就是 fail-closed 的，
原因在 `docs/05`「猜一个安全间距，比不给答案更糟」。当时留的口子是
"往 `data/creepage_tables.json` 里灌一张 verified 的表"，而这件事一直没人做，
因为**没有任何一条路能诚实地做完**：

| 路 | 为什么走不通 |
|---|---|
| 抄付费标准的表 | 无法在仓库里核对；转写错误无法被任何规则发现（两篇博客互相抄也能通过"两个来源"检查） |
| 抄网上流传的"IPC-2221 图表数字" | 不同出处的同一个格子互相矛盾，且都是 OCR 来的，没有一条能追到原始图表 |
| 自己拟合一份 | 拟合式一旦没有出处，就是"我编了一个模型"——比不答更糟 |

于是分成两条不同的路，各自用**能自证的手段**兜住：

- **载流（IPC-2152）**：别人已经把公开的拟合式写出来了（Brooks & Adam 2015 对 Table 3-1 的拟合），
  KiCad 10.0 原封不动地把系数抄进了 `common/track_width_calculations.cpp`。
  那就抄系数、写清出处，然后用**锚点复现 + 物理性质**验它（见 23.2）。
- **爬电/间隙（IEC 60664-1）**：没有任何公开的拟合式，但有一个**开源实现**
  （KiCad 10.0 `pcb_calculator/calculator_panels/iec60664.cpp`，1355 行，头部写着
  `// Based on IEC60664-1 : 2020-05`）。那就**编译它、反演它、对拍它**（见 23.3）。

两条路的共同点：**发布出去的每个数字都能被这台机器重新生成一遍**，
`_scratch/` 里留着全部探针程序，谁怀疑都可以重跑。

## 23.2 载流：闭式拟合，而不是"图表数字转写"

`width_for_current(..., standard="ipc2152")` 的实现是

```
ΔT = K · I^a · W^b · Th^c          (W、Th 单位 mil，I 单位 A，ΔT 单位 °C)
```

外层 `K=215.3, a=2.0, b=-1.15, c=-1.0`；内层按铜厚就近分档：

| 铜厚 | K | a | b | c |
|---|---|---|---|---|
| 0.5 oz | 120 | 2.0 | −1.10 | −1.52 |
| 1 oz | 200 | 1.9 | −1.10 | −1.52 |
| 2 oz | 300 | 2.0 | −1.15 | −1.52 |
| 3 oz | 262.5 | 1.9 | −1.15 | −1.52 |

`THICKNESS_MIL_PER_OZ = 1.378`，标称厚度 0.689 / 1.378 / 2.756 / 4.134 mil。

**为什么可以"抄"**：系数逐字来自开源实现，出处在 `data/ipc2152_tables.json` 的 `sources` 里写清楚，
并注明它是对 Table 3-1 的**拟合**——这条比什么都重要，因为**拟合式不等于原表**，
它丢掉的东西必须自己说出来（见 `model_limits`：超出 35 A 无出处、超出 −40~150 °C 无出处、
via 载流不在本模型范围内）。

**验它的三条线**（`safety_table_check(which="ipc2152")` 全都在跑）：

1. **形状**：`K>0`、电流指数 `>1`、宽度与厚度指数 `<0`。写错符号的系数集一定过不了。
2. **锚点复现**：文件里存了 9 条手算锚点（例如 1 A / 10 °C / 1 oz / 外层 = **0.2773 mm**、
   同条件内层 = **0.2484 mm**），代码必须复现到 0.5 % 以内。
3. **物理探针**：电流随铜厚上升、随 ΔT 上升；**内层不得被简单降额 2×**
   （老 IPC-2221 手册里的那条 2× 规则在新模型里不成立，能过这条的数才是 2152 而不是 2221）。

第三条第 3 点是这套校验真正的价值：**一个错误的系数集很可能仍然能命中一两个锚点，
但很难同时让"内层 < 外层且不差 2 倍"与"电流随铜厚单调上升"同时成立。**

另外两处代码在贸易：

- 系数放在**两个地方**（`calc/current.py` 的常量 + JSON 的文档副本）。
  缺 JSON 时仍能算（常量兜底），但**两边一旦漂移立刻 `INTERNAL_CHECK_FAILED`**，
  不允许"数据文件悄悄变成第二真相"。
- `via_current_allowed(standard="ipc2152")` 回 `STANDARD_SCOPE`：
  **过孔载流不在这个拟合里**，不给就是不给，不许拿平面导线的答案顶替。

## 23.3 爬电/间隙：把开源实现当"可执行的原文"

### 为什么不手抄表

`iec60664.cpp` 里的阶梯有 800 多步，横跨 PD1~PD4 × 材料组 I~IIIb × PCB 材料列开关，
再叠上 reinforced ×2、海拔修正、5.2.5 的瞬态电压替换规则。手抄一定会错，而且**错了看不出来**。

### 方法：编译 → 反演 → 对拍

1. **编译原实现**（只补了一个 `#include <cstdlib>`，因为本机 GCC 4.8 的 `<math.h>` 不带 `abs`）。
2. **反演阶梯**：对每个 (PD, 材料组, PCB 标志) 组合，用首选电压序列（10/12.5/16/…/100000）
   探一遍，并在**段内几何中点**再探一次，用"中点值 ≠ 端点值"判定这一段是**真斜坡**还是**阶梯**。
   这一步是关键坑：第一版用 `x*(1+1e-12)` 判斜坡，会跨到下一档，把所有点都标成斜坡。
3. **对拍**：三套独立探针，共 **188 528 个点**，0 失配。

| 探针 | 点数 | 它管什么 |
|---|---|---|
| `grid.csv` | 3 760 | 公共 API + 首选电压网格 + 断点两侧 ε，覆盖 clamp / reinforced / 海拔 / 冲压表 / 槽宽 |
| `sweep.csv` | 93 120 | 密集几何扫描（1.01 步长），basic 与 reinforced、瞬态/峰值/海拔交叉 |
| `raw.csv` | 91 648 | **原始阶梯函数**（`#define private public` 绕过封装），−1 无歧义 |

对拍规则写死在 `_scratch/iec_ref/verify_all.py` 的 docstring 里，三条：

- C++ 返回 `-1` = 阶梯到头，公共 API 会把它变成 `creepage = clearance`；**端口拒答等于通过**；
- `Compute()` 还要求 `creepage >= clearance`，这条 clamp 在 `spacing()` 里实现，
  **不在 `creepage_mm()` 里**，所以公共 API 上的期望值是 `max(表值, 占位 clearance)`；
- `clearance` 两个分支（瞬态 / 峰值）**任一越界就整题无解**——这是 C++ 的行为
  （`clearance1 == -1 || clearance2 == -1 ⇒ 双双置 -1`），端口复刻成拒答，
  而不是"留下还活着的那个分支"（那会**低估**间距，是最危险的错法）。

### 三处只有"行为对拍"才能发现的错

1. **PCB 材料列在低压区被 clamp 掩盖**。第一版反演探的是 `GetCreepageDistance()`，
   它已经被 clamp 到 clearance，于是"表值 < clamp"的整段阶梯根本不可见，
   端口在 `CREEPAGE,4,2,1,1` 上给 0.2 而 C++ 给 0.04。改成直接读
   `GetBasicCreepageDistance()` 才修对。
2. **PD2 × IIIa 的斜坡被当成阶梯**。160 V 以上是 `v/100`（源码第 1057 行，全文件**唯一**
   一个非常数返回），二分出来的"断点"退化成 `(160.000000000005, 1.6000000000000518)`。
   修法是把这段折成线性步 `{"slope":0.01,"intercept":0}`，并用段内中点探针证明它真是斜坡。
3. **间隙表的断点是"猜"的**。第一版把断点列表从上一版 JSON 里继承，
   于是 Table F.8 的 0.04/0.06/0.1/0.12/0.15/0.2/0.25 kV 与 Table F.2 的 40/50 kV
   **整段消失**——端口在这些区间返回的是下一档的值（偏大，看似"安全"，实际是错的数字）。
   修法见 23.4。

### 端口自己也不能"只过对拍"

`data/iec60664_tables.json` 是**生成**出来的，所以风险不是"手抖打错一个数"，
而是"生成器丢了一步 / 排错序 / 把阶梯折成了斜坡"。`safety_table_check(which="iec60664")`
的 8 条检查全部针对这类失败：

| 检查 | 抓什么 |
|---|---|
| `edition_named` | 版本号必须写出来（`IEC 60664-1:2020-05`） |
| `verified_flag` | 生成物必须被显式标成 verified，否则 `_load()` 就拒答 |
| `two_independent_sources` | 两个独立来源（标准 + 被复刻的实现） |
| `creepage_grid_complete` | 32 条阶梯齐全（4 PD × 4 材料组 × 2 PCB 标志） |
| `clearance_peak_pd_independent` | Table F.8 不含污染等级，四份必须**逐字节相同** |
| `ladders_sane_and_monotone` | 阈值严格递增、距离不随电压下降、`max_v` 与最后一步一致、线性段过原点 |
| `physics_probes` | PD1 ≤ PD2 ≤ PD3；电压翻倍距离不下降 |
| `limits_are_declared` | `not_covered` 至少 3 条（**能力边界必须写在数据里**） |

`tests/test_iec60664.py` 还有一层**变异测试**：删一步、制造重复阈值、让阶梯下降、
改坏 `max_v`、把线性段挪出原点、删掉一个 PD、让 Table F.8 依赖污染等级、把 verified 改 False
——每一种都必须让校验器判死。**没有这一层，校验器可以靠"什么都不查"通过。**

## 23.4 断点必须"恢复"，不能"继承"

第一版间隙表把断点列表从旧 JSON 继承（`ct_bounds = old_bounds | {0.01, 120}`），
这是自引用的死循环：**丢掉过的断点永远回不来**。

修法是 `_scratch/iec_ref/gen6.cpp`：对每条阶梯

1. 从 0.001 kV 起按 1.002 的比率走，比较相邻两点的返回值；
2. 一变就在 `(x, next]` 里二分到 1e-12 相对精度，得到"新值第一次出现的位置"；
3. **snap 到 1e-6**（这两张表的阈值全是短小数：0.04、0.06、0.1、…、50），
   再用 `f(thr*(1+1e-9))` 复核 snap 没落错边（阈值是**上界**语义：`if (v <= T) return c`）；
4. 打印 `(T, 上一步的值)`，继续从 `T` 往后走。

新版断点：Table F.2 逐 PD 26/21/20/17 步，Table F.8 30 步（PD 无关）。
重新生成后 `verify_all.py` 三套全 0。

## 23.5 端口对外的诚实边界

`creepage_mm` / `clearance_mm` / `spacing` 的 `precision` 字段写的是：

> Table value, not a continuous function … Numbers reproduce the KiCad 10.0
> transcription of IEC 60664-1:2020-05 exactly; **that transcription has not been
> independently diffed against the paid standard text.**

这句话是这一层的地基：**能证明的是"和开源实现逐点一致"，不能证明的是"和付费原文一致"。**
所以配套的 `not_covered` 写了 6 条硬边界：

- **PD4 的 creepage 不是标准量**——实现里返回常量 1.6 mm，那是 artefact；
  端口 `STANDARD_SCOPE` 拒答并点名这个 artefact。
- **均匀场（homogeneous field）不做**——参考实现的面板根本不暴露场选择，
  实现没有使用者的列只会扩大假绿面积。
- **海拔修正只管 clearance**（Table A.2），creepage 不修正——端口把这句话塞进 `extra`，
  免得用户以为改个海拔两个数都会涨。
- **solder mask 不是 conformal coating**——想靠涂覆放宽爬电，得走 IEC 60664-3 的覆盖率验证。
- **阶梯到头就拒答**（`OUT_OF_VALIDITY`），不向上外推。
- 别的安规族（IEC 62368-1 / 61010-1 / 仪器标准）**继续 fail-closed**，
  绝不允许"借 60664 的数用"。

## 23.6 这一篇真正的结论

1. **"表"不是唯一的知识载体，行为也是。** 编译一份开源实现，用 20 万点对拍，
   能得到的保证比"我照着 PDF 抄了一遍"更强——它连 clamp、边界、-1 传播这些
   原文里没有文字说明的行为都一起证明。
2. **继承来的常量是最贵的技术债。** 断点列表从上一版继承，看起来省事，
   实际是把第一次的错误永久固化。凡是"边界在哪"这种信息，必须每次重新测。
3. **校验器必须有变异测试。** 8 条检查能被 8 种注入错误全部抓住，才叫校验；
   否则只是打印了一堆 `ok: true`。
4. **能力边界要写进数据文件。** `not_covered` 不是注释，是 `check_which` 的一条判据——
   删掉它校验就挂，这样边界不会在后续重构里被悄悄搬走。
