# 圆弧蛇形等长线：把 45° 齿换成圆角弧（0.1.23）

用户原话（在图上框选 DDR 蛇形区后）：「这个等长线画的不对，应该是圆弧蛇形线不是这样的三角线这个是不对的」。

---

## 1. 结论先写

- 0.1.22 的 `board_tune_length` 只会一种齿：**45° 三角齿**（`route.tune._serpentine`
  的形态，两端点不变、每齿落在 45° 栅格）。用户判它是错的。
- 本版给同一个工具加 **`style`** 参数：`"chamfer"`（默认，老行为逐位不变）与
  `"arc"`。`arc` 画的是**圆角方波**：沿轴直线 → 半径 r 的 90° 弧 → 垂直爬升 h →
  半径 r 的 90° 弧回到轴方向。切点连续（相邻片端点相接、切向相同），无拐点、
  无三角尖角，整条波形只落在段的一侧（`side=±1`）。
- 每齿长度闭式：`h + r(π − 2)`（两段 90° 弧的长度和 `2·(πr/2)` 减去被爬升吃掉的
  `2r`）。这不是估算，是写进测试的等式（`test_the_reported_length_is_the_path_not_a_sample_of_it`
  断言 3 档下总长 `= 8 + extra`，`places=5`）。
- **进文件的是真弧**：`(arc (start) (mid) (end) (width) (layer) (net))`，长度从三点
  算（`edit.ops.arc_length_mm`），复测也从三点算（`route.tune_board._node_arc_length`
  → `OPS.arc_length_mm`），**不用弦长近似**。0.1.22 里 `arcs_not_counted` 的口径
  是本版要修的那类假：弧一旦计入长度，字段必须叫 `arcs_counted`（本版已全局改名）。

---

## 2. 形状定义与落点

```
        arc r        climb h        arc r
  ─────▶( 90° )──┐             ┌──( 90° )◀─────
                 └─── 侧向 ────┘
```

| 片段 | 几何 | 长度 |
| --- | --- | --- |
| lead-in | 段起点 → 波形起点（同轴直线） | `t0` |
| 90° 弧 | 以 `r` 为半径、切于轴 | `πr/2` |
| 爬升 | 垂直轴、长 `h` | `h` |
| 90° 弧 | 同上、反向 | `πr/2` |
| 回程 | 沿轴反向，与 lead-in 同长 | 同 lead-in |
| tail | 波形终点 → 段终点 | 剩余 |

齿数取偶数（这样波形回到轴上，tail 才能接回原段终点而不留半段悬空）。

- 代码：`src/pcb_agent_mcp/route/tune_board.py::arc_meander(seg, extra_mm, amp_max, side, r_ladder, shift)`；
  写入 `edit/build.py::track_arc(sx, sy, mx, my, ex, ey, width, layer, net_code, sp, uid)`；
  校验/复测 `edit/ops.py::arc_length_mm(s, m, e)` 与 `add_track_arc`（三条硬拒绝：
  层不以 `.Cu` 结尾、三点共线 `cross < 1e-9`、两端点相同）。
- `adapters/kicad_pcb.py` 的 arc 节点原先只留端点，会逼得复测走弦长；本版补 `"mid"`，
  让 `arc_length_mm` 精确。
- 拒绝原因不新增术语，沿用 0.1.22 的 `does_not_fit` / `clearance` / `keepout` /
  `board_edge` / `copper_is_locked` / `replacement_budget` / `no_candidate_segment`；
  `does_not_fit` 现在带 `"style": "arc"`。

### 为什么需要滑动与降档

弧蛇形的最小可加长度有下界：一个齿至少 `h_min + r(π−2)`（`h_min = ARC_H_MIN = 0.05`、
半径取自 `ARC_R_LADDER = (0.35, 0.30, …, 0.06)`）。而且**可行性与「想加多长」不单调**——
0.35 mm 的波形会被邻居拒，0.30 mm 的同位置能过。所以搜索是两层：先按
`ARC_EXTRA_FACTORS = (1.0, 0.85, …, 0.18)` 降档要「尽量多但要放得下」，再按
`ARC_SHIFTS = (0.0, 0.5, −0.5, 0.25, −0.25)` 把波形在段内余量里平移。

三处只在真板上才会现形的修正（都进了测试）：
1. `t0 > 0` 时必须补 lead-in，否则网在段首**断开**（会变成 unconnected）。
2. 尾片长度为 0 时不输出（`add_track` 会因两端点相同被拒）。
3. 0.1.22 的计算式 `extra = min(deficit, T.max_extra(len, amp))` 是 **45° 齿的容量公式**
   （每 mm 振幅吃 2 mm 段长），用在弧上会静默掐死加长量（实测把 DQS1P / CLK 压在
   0.62 / 0.38）。`style="arc"` 分支改为直接要完整 `deficit`，由 `arc_meander`
   自己判能不能放下。

## 3. 净空怎么判（不许因为「是弧」就放宽）

弧按弦逐段判，和 `board_route` 用的是同一个精确多边形判据：

- `_arc_chords(s, m, e)`：按矢高 `ARC_CHORD_SAG_MM = 0.01` 采样，**端点强制回填调用方
  的精确点**（不能让采样误差把两片接缝掰开）。
- `_pieces_probe(pieces, width)`：直片探针宽度 `width`，弧的每根弦宽度 **`width + 2*sag`**。
  加宽 `2·sag` 恰好抵消「弦比弧偏里」的那点 `sag` ⇒ **测出来的间隙=真实间隙**
  既不会得到偏保守的假拒绝，也不会被弦读成更远。
- `_pieces_blockers` / `_pieces_floor_hits` / `_occupy_pieces` 三条路：搜索用前两条、
  接受后用第三条把栅格也占上，避免后续段踩进刚画好的弧。

## 5. 口径变更（必须显式写，不许悄悄改）

历史上有过一条硬约束「**不要用圆弧线**」（0.0.151，`docs/142` 把 151 条铜弧全换成
45° 斜切）。**本版按用户 2026-11-14 的明确指令作废该口径**：等长蛇形线要的正是圆弧，
且这里新增的弧与 `docs/142` 删掉的弧不是同一种东西——
`docs/142` 删的是转角 90° 圆角弧（弦恒 45°），本版加的是**沿轴的等长波形**，
不改变走线方向、只在一条已布好的直段上换形。其余场合（布线转角）仍按 45° 约束。

同时作废的还有 0.1.22 的两句文档口径：`arc not counted`（`arcs_not_counted`）
→ 现在 `arcs_counted`，弧长计入 `length_mm`。

## 6. 没做到（不许读成「DDR 全部等长了」）

- **只修了三对**（DQS0/DQS1/CLK）。未修：lane0（11.90 → 11.16）、lane1（10.15 → 6.73）、
  addr/cmd vs CLK（32.08 → 32.06）。后三个是 **16–32 mm 的缺口，属重新布线**，
  不是蛇形能填的，`plan` 对它们报 `length_not_matched` 并逐网点名原因。
- 弧蛇形只做**单侧单波形**，不做多波形叠放；`amp_max` 由调用方给，本版没用超过 0.5 mm。
- 没有把弧叠到 `_v19`（45° 齿版）之上：`_v20` 从 `_v18` 重新复制，45° 铜整块丢弃；
  `_v19` 仅作对照证据保留，不再往下走。
