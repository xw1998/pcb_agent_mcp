# 阶段 2d —— lane 内等长的可行性边界：这条走廊装不下，不是调不出来

本文只回答一个问题：**DDR lane（9 网一组，tol 0.50 mm）的等长为什么调不出来，是算子不行，还是板子不行？**

答案是后者，并且把它量成了两张可以复核的表：一张是「每条网单独拥有整块板时能吃下多少长度」，一张是「这个数字随两条杠杆怎么变」。两条杠杆分别是**我们自己的 0.2 mm 安全余量**和**振幅档位**。结论是余量是主因、档位不是，而放掉余量之后仍然有 5 条网吃不下自己欠的数 —— 那 5 条是几何级不可调，落点是布局，不是调长。

本轮不升版本、不进 CHANGELOG（沿用 184–187 的先例）。

三条读数：

1. **在可写的口径下（0.2 mm 闸门 + 现有振幅档），两条 lane 各有 5 条网一个毫米也加不出来。** `plan()` 只能把这 5 条以外的网闭合，而 lane skew 是由最欠的那条网单独钉死的（lane0 `/DDR_DQ1` 5.9107、lane1 `/DDR_DQ10` 6.3142）⇒ **整 lane 的 tol 0.50 不可能由调长达标**。
2. **0.2 mm 余量是主因。** 把 floor 放回这块板网规则的 0.1（`apply_plan` 会拒，所以只是诊断口径，不写盘），lane0 的短网 5→2、lane1 的 5→4。也就是说 `DM0/DQ2/DQ3/DQ6` 之所以「一个毫米也加不出来」，原因不是没有物理空间，是我们自己给写盘留的余量把物理空间吃掉了。
3. **余量放掉之后还剩 5 条网真的吃不下。** `/DDR_DQ1` 差 **1.9646**、`/DDR_DQ12` 差 **1.9578**、`/DDR_DQ13` 差 **1.8127**、`/DDR_DQ10` 差 **1.7543**、`/DDR_DQ15` 差 **0.2308**。这五条把整块板给它们也不够 —— 这是**布局**的答案（球位映射、escape 顺序、走廊里给波场留出的带宽），不是调长的答案。
4. **补振幅档不是主瓶颈。** 在 0.2 闸门下把 0.40/0.45 补进阶梯只多救回 `/DDR_DQ3` 一个网（`plan()` 的阶梯 `AMPLITUDE_LADDER=(1.0,0.75,0.5,0.35,0.25)` 对 0.1 mm 线宽只能落到 0.50/0.35/0.25 三档，缺 0.40–0.45 甜区）；换成 0.1 floor 之后补档**一个也不多**，因为那时限制已经不是振幅而是走廊宽度。

## §2 每网欠多少：从扇出几何算出来的下限

lane 的 tol 是「相对最长网」的，所以先要有一个**与布线无关**的每网下限。取每个网两端焊盘中心的欧氏距离 d，再算 DDR 的八方向下限 `octile = max(|dx|,|dy|) + (√2−1)·min(|dx|,|dy|)`，两者之差就是这条网**无论怎么布**都至少要绕出来的长度（`_fanout_floor.py`）。

| lane | octile spread（最远−最近） | 最短 | 最长 |
|---|---|---|---|
| lane0 | **4.9681** | `/DDR_DQ1` 11.8894 | `/DDR_DQ4` 16.8575 |
| lane1 | **6.2121** | `/DDR_DQ10` 10.6867 | `/DDR_DM1` 16.8988 |

已布铜的实际离散是 **5.9107 / 6.3142**，都已经超出几何下限 0.94 / 0.10 —— 也就是说布线本身已经把差距做得比几何要求更宽（同组走廊阶段 2b 的老毛病：先布的网付绕行，代价被全组继承）。

每网的「欠」与几何下限的分解（`_fanout_floor.py` 的 per-net `deficit`）：lane0 的 `DQ1 5.9107 / DM0 5.0820 / DQ5 5.0678 / DQ7 4.3192 / DQ3 4.0814 / DQ0 2.0636 / DQ2 1.8314 / DQ6 0.3385`，lane1 的 `DQ10 6.3142 / DQ8 5.6178 / DQ14 4.5672 / DQ12 3.7136 / DQ13 1.8127 / DQ9 1.4172 / DQ11 0.7615 / DQ15 0.2308`。**注意这些数全部由最欠的那一条决定，与其余网无关** —— 这也是为什么 §1 里「短网数」比「闭合了几个网」有用的多。

## §3 `plan()` 在整 lane 上的真实读数：279 个 op，skew 一位不动

把整 lane 当一组交给 `plan(tol_mm=0.50, style="arc", floor_mm=0.2, max_replacements=64)`：

| lane | 输入 skew | 输出 skew | 闭合的网（≤0.5） | 仍然开着的网 |
|---|---|---|---|---|
| lane0 | 5.9107 | **5.9107** | 5/9 | `DQ1 5.9107 / DM0 5.0820 / DQ3 4.0814 / DQ2 1.8314` |
| lane1 | 6.3142 | 6.3142（+0.000001，取整） | 6/9 | `DQ10 6.3142 / DQ12 3.7136 / DQ13 1.8127` |

两条 lane 合计 **279 个 op / 7 段被替换 / 136 段新增**（一次 `plan` 同时跑两组）。lane0 是分毫未动，因为 skew 不是平均量，是 `max`：只要最欠的那条网（`/DDR_DQ1` / `/DDR_DQ10`）一个毫米都加不出来，其余网加到天上去，skew 也纹丝不动。

**这条读数改写了后续所有判据**：调长工作的验收指标必须是「binding 网能不能动」，而不是「闭合了几个网」。闭合 11/18 与闭合 0/18 在 lane 的 tol 上是同一件事 —— 而 §1 的 2×2 表正好说明这 4 + 3 条开着的网与 `headroom` 判 `shortfall` 的网是同一批（`DQ2` 在那里也是 0），两套独立的量法互相对上了。

## §4 振幅档不是主瓶颈（四档扫描 + 补档）

`plan()` 的振幅候选是 `[base] + [a for a in AMPLITUDE_LADDER if a < base]`，`base = max(0.5, 3√2 × width)`。0.1 mm 线宽 ⇒ `base = 0.5`，候选只有 **0.50 / 0.35 / 0.25** 三档，0.40–0.45 这一段的甜区是缺的。四档扫描（`_ladder_sweep.py`）：

| 配置 | 闭合 | 多出来的是 |
|---|---|---|
| stock（0.50/0.35/0.25） | 11/18 | — |
| midband（0.45/0.40/0.35/0.30/0.25/0.20） | 12/18 | `/DDR_DQ3` |
| cap 0.60 | 12/18 | `/DDR_DQ3` |
| cap 0.70 | 12/18 | `/DDR_DQ3` |

四档的 lane skew **全部保持 5.911 / 6.314 不变**。§1 的 2×2 矩阵给出了同一结论的另一种读法：补档在 0.2 闸门下多救回 `DQ3` 一条，换到 0.1 floor 后一条也不多。

所以 `AMPLITUDE_LADDER` 该不该补 0.40/0.45？**该补**（它是一条网的区别，且没有代价），但它**不是**这条 lane 调不出来的原因，不要把它当解法。

## §5 走廊横截面与 0.2 mm 余量的算术

在 y = 14.0 / 15.5 / 17.0 / 18.5 / 20.0 做横截面（`_xsec.py`）：lane 是一条真实的平行带，**相邻网中心距 0.25–0.30 mm**（同层边缘间距仅 0.15–0.20），且**各网分布在不同层**（F.Cu / B.Cu / In2.Cu），只有同层邻居才互相限制。

一个高 h 的圆弧齿需要的横向空间是 `h + width/2 + floor`：

- 0.25 mm 中心距 ⇒ 同层可用高度 `0.25 − 0.125(半线宽) − 0.20(floor) = < 0`，**放不下任何齿**；
- 0.30 mm 中心距 ⇒ `0.30 − 0.125 − 0.20 = −0.025`，同上；
- 要放一个**可读**的齿（`ARC_H_LEGIBLE_MM = 0.15`，阶段 2c 定的下限），至少需要 `0.15 + 0.125 + 0.20 = 0.475 mm` 的中心距。

走廊是 0.25–0.30 密排的，而齿要 0.475 —— **这就是 `too_shallow` 的来源**，也解释了为什么 `/DDR_DQ6` 只欠 **0.3385** mm 却一个齿也放不下：它不是没地方，它是每一段都被贴着。

而 5.9 mm 的 deficit 不是靠一个齿补的。按 `arc_meander` 的每齿加长 `h + r(π−2)` 与沿轴节距 `run + 2r`，要在一段 8 mm 长的铜上补 5.9 mm，需要振幅 ≥0.35 的波场**铺满整段**，也就是整条走廊都必须为它让出 0.475 以上的中心距。**这已经不是在现有走廊里画线的问题，是走廊要给谁留带宽的问题。**

两处端点级的硬证据（`_room_probe.py` + 直接几何核对）：

- `/DDR_DQ3` 的段端点在 `(20.4, 18.1)`，与 `/DDR_DQS0N`（In2.Cu）间距 **0.15 mm**（网规则 0.1 ⇒ 既有合法铜；apply floor 0.2 ⇒ short by 0.05）。任何从段端点起步的蛇形都会踩到 0.2 floor，所以「最密形状」`t_max`（`slack = L − advance = 0`、波从段起点开始）在段端点必然被拒 —— 必须把齿数向下扫才能避开端点，这正是 §6 用搜索而不是闭式的原因。
- `/DDR_DQ1` 在全板自由、floor 0（只关可读性下限）的条件下一共只有 **1** 个 legible fit，最多加 1.064 mm；`/DDR_DQ10` 与 `/DDR_DQ13` 各 **0** 个。这三条与 §1 的 2×2 里的「0」互相印证（DQ1 在 0.1 floor 下能到 3.946，是因为 §1 用的是 planner-alone，允许在多个段上叠加；`_room_probe` 只找「整段一次加完」）。

## §6 `headroom()`：一次单向的终局判定

`route/tune_board.py` 新增：

```python
headroom(board, groups=None, bundle=None, keepout_rects=None, pitch_mm=0.1,
         amp_ladder=None, layers=None, floor_mm=FLOOR_MM, style="arc",
         max_replacements=32)
```

对组内每条网，给它一个「本网当前长度 + 欠的数 + 0.2」的目标（`HEADROOM_EXTRA_MM`，够不着就行，探针到量即停），让它**单独**跑一次 `plan(..., with_headroom=False)`，取 `after_mm − before_mm` 作为这条网能吃下的长度。每组给出 `verdict ∈ {tunable, blocked_by_geometry}`、`binding_net`、`shortfall_mm`，每网给出 `need_mm / reachable_add_mm / gap_mm / status ∈ {already_within_tol, reachable, shortfall} / blocks`。

三个刻意的设计：

1. **用规划器自己量，不用闭式上界。** 我上一轮写过一版「振幅 × 半径 × 齿数」的理论上界，它给出 `/DDR_DQ3` capacity = 0 —— 而 `plan()` 明明把它闭合了。根因是 `t_max` 形状在段端点被 0.15 mm 的既有铜拒掉（§5 那条），闭式里没有这个对象。**算小的上界就是假的 `blocked_by_geometry`，也就是说错答案。** 只要上界需要下扫齿数才能对，它就已经是搜索了 —— 那不如直接用同构的搜索。
2. **`blocked_by_geometry` 是终局结论，`tunable` 不是承诺。** 一条网在整块板上独自都吃不下，那么再加余量、再换顺序、再重跑都没用，这是布局的答案；反之「自己有地方」完全不保证「同时都有地方」，因为九条网争同一条走廊。这条不对称必须写在返回值里，不能靠调用方猜。
3. **对 floor 单调，所以「放掉余量」不会把已下的结论推翻。** 在更松的 floor 下判出的 shortfall，在更严的 floor 下一定还是 shortfall —— `blocked_by_geometry` 只会变得更少，不会变错。这就是为什么 `plan(..., with_headroom=True)`（`plan()` 默认 floor 0，按网规则判）报出的短网比 0.2 闸门下少（§1 的 2×2 两列），而两个数都是对的：它们是**两个 floor 上的两个陈述**。返回值里的 `floor_mm` 就是这次用的那个。
4. **默认不跑。** 每条网一次完整 `plan()`，lane0 实测 **108.4 s / 9 网**（其中每个 `plan()` 都要重建一次 6 层栅格，`Grid` 构造约 11 s 是主要成本），lane1 104.8 s。所以 `plan(..., with_headroom=False)` 是默认值，`with_headroom=True` 才挂 `headroom` 块；`plan()` 的 docstring 里写明了这个代价。

工具层对应一个开关：`board_tune_length` 新增 `headroom`（默认 `false`），`true` 时每组的 `headroom` 块随报告一起返回。默认关，因为它是 `plan()` 成本的倍数而不是常数。

配 3 个单测（`tests/test_tune_board.py::TestHeadroomIsOneWay`）：

- 一条网有地方 ⇒ `tunable`、`binding_net=None`、`shortfall_mm=0`，并且它的参照网是 `already_within_tol` 而**不被算成** shortfall；
- 把一条网夹在两个 0.46 mm 的合法邻居之间（`0.46 − 0.125 − 0.20 = 0.135 < 0.15` 可读下限）⇒ `blocked_by_geometry`、`binding_net` 指名、`blocks` 非空、且 `gap_mm == need_mm − reachable_add_mm`；
- `plan()` 默认不带 `headroom` 块，`with_headroom=True` 才带。

## §7 下一步：这是布局的答案

把 §1 的表倒过来读，就得到下一步该做什么：

1. **band 生成时预留波场。** 现在 band 是按最小间距（0.25–0.30 mm 中心距）密排的，结果一条网都放不下可读齿。若在 band 里为「最欠的那 3–5 条网」预留一条**每条 0.5 mm 宽**的走线通道，它们就有地方画振幅 0.35、节距 0.63 的波场；代价是 band 变宽（DDR 区可用宽度要先量）。
2. **改 escape 顺序，让 pad-to-pad 距离本来就接近。** lane 的 octile spread 4.97 / 6.21 是**扇出几何**给出的，已布铜又把它拉宽到 5.91 / 6.31。若 fanout 阶段就按「让同组网的两端路径长度接近」排序（而不是现在的 span 升序占走廊），欠的数会小很多 —— 这是阶段 2b 的同一个结论，只是这次有了每网的绝对下限可以对着做。
3. **0.2 mm 余量要重新谈一次。** 它是 `edit.apply_plan` 的 `ruleset.precondition.CLEARANCE_FLOOR_MM`，而这块板的 DDR 网规则只要 0.1；本轮的读数是这个余量单独造成 lane0 3 条网、lane1 1 条网从「能加」变成「加不出来」。**但放掉它不是免费的**：阶段 2c 已经量过 floor 0.12 时 10 对间距掉进 0.1–0.2（最差 0.1255）。这条要用户定，本轮只把账算清楚，不擅自改闸门。

三件的优先级：**1 与 2 是「让空间存在」，3 是「把已有空间算成可用」**，必须 1/2 先做，否则 3 只是把 5 条短网变成 2 条。
