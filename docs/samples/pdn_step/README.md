# `pdn_step_response` 的三个 deck：拿 ngspice 对表

这三副 deck 不是示例，是**独立实现**。`pdn_step_response` 自己的两条内建自检
（DC 锚、电荷恒等式）能抓住「积分器漂了」和「某条支路没进节点方程」，但抓不住
「整个拓扑建错了」——那种错只有换一个求解器才看得见。

用仓库自带的 ngspice 跑（`vendor/ngspice/bin/ngspice_con.exe`）：

```
vendor/ngspice/bin/ngspice_con.exe -b docs/samples/pdn_step/onepole.cir
```

`Iload <node> 0` 是**电流沉**（从该节点抽走电流），方向与工具里 `step_a > 0`
（负载变重、轨往下掉）一致。三副 deck 里的 R 与 L 都串在不同的内部节点上，
因为 SPICE 里同一对节点上的 R 与 L 是并联，不是串联。

## 实测（2026-11-01，ngspice-47）

一阶：`1 Ω` 稳压器 + `1 µF` 串 `10 mΩ` ESR，`1 A` 阶跃，`t_stop = 20 µs`。

| t | 本工具 | ngspice | 相对 |
|---|---|---|---|
| 1 ns | −0.010880673 | −0.010880297 | 0.0035 % |
| 10 ns | −0.019653895 | −0.019655121 | 0.0062 % |
| 100 ns | −0.103179482 | −0.103233044 | 0.052 % |
| 1.01 µs | −0.634964039 | −0.635762950 | 0.126 % |
| 5.05 µs | −0.992906016 | −0.992990650 | 0.0085 % |
| 20 µs | −0.999999997 | −1.000000000 | <0.0001 % |

LC 环：`50 mΩ` + `10 nH` + `1 µF`（无 ESR），`1 A` / `50 ns`，`t_stop = 3 µs`。

| 量 | 本工具 | ngspice | 差 |
|---|---|---|---|
| 峰值 | −0.110376 V @ 212.5 ns | −0.111801 V @ 213.8 ns | 峰值低 1.27 % |
| 尾部 | −0.050007 V | −0.049999 V | 0.016 % |

峰值偏低**是预期方向**：后向欧拉有数值阻尼，所以本工具报的 Q 是下界（写进了
`precision`）。时刻差 1.3 ns（0.6 %）。

bulk 在板子另一端：`1 mΩ` 稳压器 + `2 mΩ`/`1 nH` 板 + `100 µF` 串 `2 mΩ`
在 bulk 节点，`10 A` / `400 ns`，`t_stop = 40 µs`。

|---|---|---|---|
| 峰值 | −0.052937 V @ 396.8 ns | −0.053159 V @ 400.0 ns | 峰值低 0.42 % |
| 尾部 | −0.030000 V | −0.030000 V | <0.001 % |

## 这条对表**没有**证明什么

- ngspice 的 `.tran` 默认是梯形法（TRAP），本工具是后向欧拉。两者在同一个网格上
  本来就不该逐位相同，所以上面这些差里有一部分是**方法差**，不是错。
- 三副 deck 都是**线性**的（无半导体、无温漂、无容值随偏压变化）。非线性情形
  本工具根本没有建模，谈不上一致。
- 一阶那副用 `PWL(0 0 1p 1)` 近似理想阶跃（1 ps）。真实阶跃在 SPICE 里同样会让
  `di/dt` 由步长决定，这正是本工具拒绝无 `rise_ns` 的电感网络的理由。
