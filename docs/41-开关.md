# 41. 开关 S/W：两个电导，一个状态，三条只能量出来的阈值

`0.0.34` 之后按名字拒绝的清单只剩 `J`、`S`、`W`、`A`。`S`/`W` 被挑出来先做，理由和 `F`/`H`/`K`
不同：它们**不是**线性的 stamp，而是「两个电阻里现在装的是哪一个」——但正因为是电导，每一点都
可以对着 ngspice 逐位对账，不需要新模型、也不需要第二套表达式体系。

这一篇记四件事：为什么开关**没有自己的未知量**、状态为什么不能塞进牛顿迭代里、阈值判据为什么
只能量出来（手册与直觉都给了错误答案），以及瞬态「边沿差 18.9%」到底该归给谁。

---

## 41.1 两张卡、四个端子、两个电导

```
Sname n+ n- nc+ nc- model [ON|OFF]   ; 压控：控制量是节点对 (nc+, nc-) 的电压
Wname n+ n- vname    model [ON|OFF]  ; 流控：控制量是**元件 vname** 的支路电流
```

`S` 有四个端子，因为控制是**电压**，而电压是两点之差。`W` 只有三个：它的第三个字段和 `F`/`H`
一样是**元件名**（`40` §40.1 的老坑），不是节点——写成 `W1 1 2 3 swl` 会把 `3` 当节点，于是读
一个不存在的电流、永远 0 A、开关永远断开，deck 依旧 `status: ok`。所以解析器在 `W` 的第三格上
做与 `F`/`H` 同一条检查：带 `=` 或能当数字读（`_looks_numeric`）直接拒绝，名字不在
`branch_name`（`V`/`E`/`H`/`L`/`BV`）里报 "no branch current"。

两条卡都**不占未知量**：开通就是 `RON` 的一条电导，断开就是 `ROFF` 的一条电导。这一条决定了下
面所有事——没有新行、没有新状态变量，只有 `assemble` 里 `1/R` 取哪一个。

报告因此必须把「装的是哪一个」摊开：`state`（on/off）、`resistance_ohm`、`conductance_s`、
`current_a`、`power_w`、`control_voltage_v`（`S`）或 `control_current_a` + `controlled_element`
（`W`）、`threshold`、`hysteresis`、`initial_state`。否则「开关状态选错」在答案里完全隐形：两个
状态给出的都是**数值正确、自洽**的解，只是电阻不同。

## 41.2 状态是状态，不是一条公式

开关和二极管最根本的区别：二极管是**连续**的非线性（`pnjlim` 会把迭代拽住），开关是**分段常数**
的。于是「在牛顿里每轮按当前解重算状态」不能照抄——那样会在两轮迭代之间来回翻，收敛到哪一侧取决
于迭代路径，还会把「某个状态恰好自洽」当成答案。

本实现的口径在 DC 与瞬态上是**同一种**：状态在一次求解里**锁存**，收敛后再问「这个解同意它吗」，
不同意就翻转并**重解**，最多 8 次，超了报 `NOT_CONVERGED`（DC 侧 hint 说双稳，瞬态侧 hint 说给
滞回或把控制挪开带边）。

一开始写的是「DC 每次 `assemble` 用 `x_prev` 重算状态」，那是**错的**，错在看不见的地方：它把
`ON`/`OFF` 当成了**锁**。实测 ngspice-47 三张 deck 才发现 `ON`/`OFF` 只是**起始状态**：

| 控制 | 卡 | ngspice 的工作点 | 说明 |
|---|---|---|---|
| 0 V | `ON` | **open**（4.995 mV） | 0 V 低于 `VT−VH`，起始状态被第一次判断推翻 |
| 5 V | `OFF` | **closed**（4.950 V） | 镜像同理 |
| 1.2 V（`VT=1 VH=0.5` 带内） | `ON` | **closed** | 带内两个状态都不矛盾，**种子决定答案** |
| 1.2 V（同上） | 无 | open | 缺省 off |

只有第三行同时证明了两件事：`ON` 不是锁（前两行），种子不是可丢的初值（第三行——「从迭代量重算」
的第一步看到 0 V 就把种子扔了）。所以状态在求解期间必须锁存，只在**收敛后**复核。瞬态的翻转数
写进 `switch_flips`（只在 deck 里有开关时出现），所以「有一个开关在动」是可观测的，而不是靠猜。

## 41.3 阈值判据是量出来的

三条都**与直觉相反**，三条都是拿 ngspice-47 一点一点试出来的（`probe_thr2.py` / `probe_hys.py`，
改完 16/16 与引擎一致）：

1. **滞回宽度是 `VT ± VH`，整宽，不是半个 `VH`。** `VT=1、VH=0.5` 的开通条件是 `> 1.5`，不是
   `> 1.25`。慢斜坡爬到 1.2 V 时，`VH=0` 的开关已经闭合，`VH=0.5` 的仍然断开。
2. **`VH=0` 时用 `>=`。** 控制恰好等于 `VT` 时引擎判**闭合**（1.000000 V 就关）。这是一条约定
   ——在恰好 `VT` 处两个状态都自洽——所以它只能由「跟谁对账」定，不能由「读者觉得」定。
3. **DC 也走滞回带，不是瞬时比较。** 工作点里 `VT=1、VH=0.5`、控制 1.0 V 的开关仍然是 **open**：
   滞回不是「瞬态才有的历史」，而是「从初态出发要越过 `VT+VH` 才翻」这条规则在 DC 上同样成立。
   关断侧边界同样实测：0.4 V 关、0.5 V（= `VT−VH`）仍开。

写成一句话：`off→on` 要 `value > VT + VH`（`VH=0` 时 `>=`），`on→off` 要 `value >= VT − VH`。

## 41.4 拒绝清单

模型参数缺省 `VT=0`、`VH=0`、`RON=1`、`ROFF=1e6`，缺省值写进 `defaulted` 让调用方看得见。以下
一律拒绝（`NETLIST_INVALID`），不钳位、不猜：

- 模型缺失 / 类型不对：`S` 要 `SW`、`W` 要 `CSW`（拿 `D()` 模型给开关会报 "needs a SW model"）；
- 未知参数**点名**（`VON=3` → "not a parameter of a SW switch"，并列出 `VT, VH, RON, ROFF`）；
- `RON <= 0`：MNA 里没有零阻电导，`RON=0` 是「理想短路」，拒绝（`R=0` 与 `|k|>1` 同一条先例：
  不可能的输入不能变成一个正常答案）；
- `ROFF <= 0`、`ROFF < RON`（"conducts BETTER when open"——这不是开关，是写错了）；
- `VH < 0`；
- 卡的形状不对：`S` 六格、`W` 五格，尾格只能是 `ON`/`OFF`，多一格报 "is not a field of a S card"
  并把形状 `Sname n+ n- nc+ nc- model` 印出来。

## 41.5 一个开关拿掉自己的控制：没有状态可给

```
R1 1 3 10k
R2 3 0 1k
S1 3 0 3 0 smod      ; 闭合就把 node 3 拉低，而 node 3 正是它的控制电压
```

闭合时控制读约 0.5 mV（判断开），断开时读 0.45 V（判闭合）——**两个状态都不自洽**。本实现在
DC 报 `NOT_CONVERGED`，并附 `hint`：开关可能自己拿掉自己的控制 ⇒ 双稳，滞回在 DC 帮不上忙。
不给「碰巧停下的那个状态」，因为那是一个看起来收敛的错答案。

## 41.6 三口径对账

deck 一律 `V1=5 V`、`RON=10`、`ROFF=1 M`、负载 `1 k` 串在开关后面（开关与负载**串联**，所以断开
时 `V(2) = 5·1k/(1k+1M) = 4.995 mV`，不是 4.995 V——这一条把测试里写错的期望值全抓了出来）。

| 口径 | 判据 | 数字 |
|---|---|---|
| DC 结构 | 通/断两个状态各自的电导 | 4.950495049 V / 4.995005 mV；`state` on/off；`R` 10 Ω / 1 MΩ |
| DC 对 ngspice | 4 组控制值（5、0、1.0、1.000001）逐节点 | `max_abs_diff_v = 0.0`（控制端口不取电流也一并核到） |
| `W` 对 ngspice | `Rg=1k` 与 `10k` 两种栅极 | 逐节点 0.0；`i(Vs)` 的**符号**按引擎口径（+5 mA 开、−5 mA 关） |
| AC | 状态由偏置点决定后冻结 | 开通 `0.4472136∠−26.565°`；断开 `Zp/(1M+Zp)` = `7.0675e-4∠−44.97°`（`Zp = 1k∥1µF`）**逐位 0.0** |
| 瞬态 | 非边沿 | 步长 20 µs：**0.299%**；2 µs：**0.182%** |
| 瞬态 | 开关边沿 | 20 µs：18.9%；2 µs：**2.74%** |

最后两行必须**归因**而不是修掉：差异集中在 1.020–1.100 ms 的开关边沿，本内置求解器是**固定步长**，
ngspice 自适应细步。步长从 20 µs 降到 2 µs，边沿差 18.9% → 2.74%、非边沿差 0.30% → 0.18%，两条
都随步长变小——所以它属于「边沿被量化到网格」，不属于阈值判据或电导写错。此外 AC 与 DC 是**逐位
零**，这才是钉住「状态是哪个」的证据：如果 `VT±VH` 或 `>=` 写反，4 组控制值里至少有一组会整档翻。

## 41.7 仍然不做

- `J`（JFET）、`A`（XSPICE 器件与第二套器件描述语言）继续按名字拒绝：它们各自需要一份器件方程
  或另一套描述语言，不是一条 stamp。
- 开关**没有二阶物理**：没有电荷注入、没有结电容/输出电容、没有先断后合（break-before-make）、
  没有开关时刻的尖峰、没有 `POLY()` 控制。开关在仿真里是「瞬时换成另一个电阻」，这一点写进
  `NOT_COMPUTED`，而不是靠调用方猜。
- 只认 `SW`/`CSW` 的四个/四个参数（`VT, VH, RON, ROFF` / `IT, IH, RON, ROFF`）：`RON` 不允许为 0，
  没有「理想开关」这个模式。
- 噪声里开关只贡献当前状态的 `4kT/R`（机制名 `thermal_switch`）：没有开关时刻的宽带噪声。
