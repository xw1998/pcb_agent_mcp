# 59 · 阻焊 web / 丝印线宽与字高 / 铜到成品孔壁：三条从"不算"变成"算"的量

0.0.55 的 `dfm_capability` 里有一段 `not_checked_by_design`，八条。其中三条读起来像是
"这项工艺参数没人管"：

1. `mask_web` —— 两块开窗之间还剩多窄的阻焊；
2. `silk_width` —— 丝印笔画最细多少、字最小多高；
3. `copper_to_hole` —— 别的网络的铜离钻孔多近。

板厂的能力表里这三条都是**必填项**（"最小阻焊桥 0.10 mm""最小丝印线宽 0.15 mm"
"铜到孔壁 0.25 mm"），而我们只能回一句"不检查"。0.0.56 把这三条变成**实测**：

> **三条都是"量出来 + 说清出处"的量。文件没写的数不当默认值用，而是排除、计数、
> 并在 `where` 里写明"真最小值可能更小"。板厂没给 `plating_um` 就拒绝回答成品孔壁
> 距离，而不是按 0 算一个到钻壁的、看起来合格的另一个数。**

## 59.1 为什么这三条以前不算：各自有一个"看起来很麻烦"的理由

- **阻焊 web**：直觉上需要把开窗多边形往外偏 `margin`，再量两块偏移后多边形的距离。
  多边形偏移是个近似活儿（圆角、自交、退化），一近似就会在 0.005 mm 量级上骗人。
- **丝印线宽**：`fp_text` / `gr_text` 的笔画宽度和字高分散在 `(stroke (width x))`、
  `(effects (font (size w h)))`、`(effects (font (thickness x)))` 三处，KiCad 5 与 6+
  写法还不一样；读错一处就得到一个假的数。
- **铜到孔壁**：差一个 `plating`。量到钻壁还是量到成品壁是两个不同的量，而 `plating`
  是板厂工艺参数、文件里根本没有；随便取一个 25 µm 就等于编数。

三条里只有第一条是"真的难"，后两条是"没人做"。0.0.56 三条都做了，靠的是三个不引入
近似的换算。

## 59.2 阻焊 web：开窗间距用圆盘膨胀恒等式，不偏移多边形

一个开窗 = 铜形状按 `margin` 做 Minkowski 膨胀，膨胀核是半径 `margin` 的圆盘。对圆盘
膨胀有一条**恒等式**：

    dist(A ⊕ D_r1 , B ⊕ D_r2) = dist(A, B) − r1 − r2

即"两个膨胀后形状的距离"就等于"两个原始形状的距离减两个半径"。所以**不需要真的把
多边形往外偏**：量铜与铜的距离，再减两个 `margin`，结果**精确**，不含任何近似。

于是 `web = dist(铜A, 铜B) − margin_A − margin_B`，其中两个 `margin` 各按下面的优先级
取值（这是 KiCad 的优先级，不是我们定的）：

| 优先级 | 来源 | 记录在 |
| --- | --- | --- |
| 1 | pad 自己的 `(solder_mask_margin x)` | `mask_margin_source: "pad"` |
| 2 | footprint 的 `(solder_mask_margin x)` | `"footprint"` |
| 3 | `(setup (pad_to_mask_clearance x))` | `"setup"` |
| 4 | 三处都没写 = **0** | `"absent_treated_as_zero"` |

第 4 档是唯一一个"填了一个数"的地方，而它填的 0 是 KiCad 自己写进
`(setup (pad_to_mask_clearance ...))` 的值（字段留空时就是 0），并且**每一块开窗都会
在 `present["pad_to_mask"]["expansion"]["pads_from"]` 里记账**：

```json
"pad_to_mask": {"present": true,
                "expansion": {"rule": "pad (solder_mask_margin) > footprint (solder_mask_margin) > (setup (pad_to_mask_clearance ...)), absent = 0",
                              "board_default_mm": 0.05,
                              "pads_from": {"setup": 3}}}
```

两条容易做错的：

- **正面与背面绝不配对**。`*.Mask` 展开成 `F.Mask` + `B.Mask` 两个具体面。把
  `*.Mask` 当一层会把正面开窗和背面开窗拿去比较，量出来的是板厚而不是阻焊桥。
- **`web <= 0` 是"合并"，不是"0 宽的桥"**。开窗叠在一起 = 中间根本没有阻焊，这是
  常见合法形态（大膨胀的密脚 QFN）。报 "0 mm web" 会被读成"桥太细做不出来"，
  是完全不同的判词。所以：合并对数在 `note` 里报出来，verdict 是 `not_applicable`
  并写明"每一对相邻开窗都合并了（N 对），这块板上没有阻焊桥"。

搜窗口是 5 mm（`window_mm`），按 layer 分组后用 x 扫描线预筛（`reach = window +
2·max_margin`），只比 bbox 在窗口内的对。窗口内没找到就报 `lower_bound: 5.0` 而不是
一个数——真值可能更大，这个方向的误差是**保守**的。

读数取整到 1e-6 mm（纳米）。理由不是好看：`0.2999999999999986` 对 `0.3` 的精确比较会
**FAIL**，那是一个由双精度最后一位决定的判词，不是板子的判词。

## 59.3 丝印：宽度读三处，字高读 `(size w h)` 的**第二个**数

- 笔画宽度：`(stroke (width x))`，回落 pre-6 的内联 `(width x)`。两处都没有 ⇒
  `width_mm = None`。
- 文字：`fp_text` 的文字是第 3 个原子，`gr_text` 是第 2 个；高度取
  `(effects (font (size w h)))` 的 **`h`**。这里必须说清楚为什么：`EDA_TEXT::Format`
  写出去的是 `GetTextSize().x` 再 `.y`，`.x` 是字格宽度、`.y` 是字高，板厂的"最小
  字高"规则说的是后者。读第一个数会把一块合格的板报成 0.6 mm 字高。
- 笔画粗细 `(thickness x)` 也读了，但它**不参与**判定（fab 的字高规则是关于字高，
  KiCad 默认笔画粗细是程序设置）。

`None` **不会**被默认值替换，这条是硬规矩：

> KiCad 的回落值是一个程序设置，不是这块板的属性。给一个没写宽度的丝印线编一个
> 0.15 mm，"我读不到"就变成了"我检查过了"。

所以没写宽度的条目被**排除并计数**，`where` 里明写：

```
board-level gr_line on F.SilkS; 2 other silk item(s) state no line width and are
excluded, so the true minimum may be smaller
```

这句话是有代价的：它承认这个数是个**上界**。因此它只能用来证明"合格"（若上界都
≥ 限值，那真值也 ≥ 限值），不能用来证明"不合格"。这一点写进了 `PRECISION`。

还有一个只有踩过才知道的坑（0.0.56 开发中真踩了）：

- 板级图形叫 `gr_line`/`gr_rect`/…，封装级叫 `fp_line`/`fp_rect`/…，**两套名字空间**。
  一开始板级循环复用了封装级的 `_GRAPHIC_KINDS`（只有 `fp_*`），结果**每一条板级丝印、
  板级开窗、板级铜图形都被静默丢掉**，`board.silk` 恒为空。修法是分开两个元组
  （`_GRAPHIC_KINDS` / `_BOARD_GRAPHIC_KINDS`），并留一条负控制
  （`test_a_copper_graphic_never_enters_the_silk_facts`）盯住"种类 + 层共同决定归属"。

## 59.4 铜到成品孔壁：`dist − drill/2 − plating`，`plating` 从不默认

一个孔的成品壁 = 钻壁 + 镀层厚度。所以：

    gap = dist(另一网络的铜, 孔心) − drill/2 − plating

`plating` 来自能力文档的 **`plating_um`**（微米，如 `25`），它是**工艺参数**，和限值
同源，所以放在同一个文档里、走同一套校验（`read_plating`）：

- 没给 ⇒ `min_copper_to_hole` 的 verdict 是 `not_checked`，`note` 写
  "the capability document states no `plating_um`, so the finished hole wall is
  unknown; measuring to the drill wall would answer a different question"。
  **绝不当 0**：差的就是这个数，按 0 算会给出一个看起来合格、实为另一个量的答案。
- 负数 / 非有限数 ⇒ `CAPABILITY_VALUE_INVALID`。

两处排除，两个不同的理由：

1. **拥有这个孔的 pad 不算**。它的铜是环形环（`min_pth_annular_ring_mm` 管），不是间距。
   不收窄这条就会让每一块通孔板都报"0.0 mm 铜距孔壁"——一个 1.2 mm 盘配 0.6 mm 孔，
   环是 0.3 mm，贴着孔壁。
2. **同网络的铜不算**。过孔自己接出去的那条走线是连接，不是间距。

一条实测把两个数摆在一起（同一块板、同一个 1.05 mm 限值）：

| `plating_um` | 算出来的 gap | 判词 |
| --- | --- | --- |
| `0` | **1.100** | pass |
| `100` | **1.000** | **fail** |

算例：铜（0.2 mm 宽走线，中心线距孔心 1.5 mm）→ `1.5 − 0.1 = 1.4`；孔钻径 0.6 ⇒
`− 0.3 = 1.1`；再减镀层。**同一条指令换个工艺参数，判词翻面**——这就是为什么它必须
来自文档而不能来自我们的记忆。

## 59.5 仍然不算什么（`NOT_CHECKED_BY_DESIGN` 还是 8 条）

条数没变，是**收窄**不是删除（`docs/README.md` 里"8 类量不出来的项目"这句话因此
仍然成立）。三条被收窄成"真正剩下的那部分"：

- **阻焊**：还剩**mask-defined pad**（开窗比铜小）与"开窗到板边/开窗到阻焊本身边缘的
  sliver"。前者是另一种判据（KiCad 的 DRC 也不管），后者不是"两个开窗之间的桥"。
- **丝印**：还剩"文件不写线宽的条目"（现在被排除计数）与"丝印压焊盘"（需要焊盘遮挡
  计算与板厂的光绘裁剪规则，不是几何距离）。
- **成品孔**：还剩 **barrel taper / 孔径公差**，以及 **镀后环形环**。环形环这里仍然
  量到**钻壁**——镀层会让成品环变小，但改 `min_pth_annular_ring_mm` 就是**静默改变
  既有答案**，所以只登记为残余限制，不在这一版动。

## 59.7 默认答案不变的自证（以及哪三处是登记过的改变）

**没变的：**

- 既有 11 条规则的读数与判词逐位不变。主夹具同一次 `dfm_check` 里
  `min_copper_gap` 仍 **4.4**、`min_copper_to_edge` 仍 **0.875**、追到
  `min_pad_ring` / `min_hole_web` / `min_slot_width` 都取原值 ⇒
  `overall=pass, passed=15, failed=0`。
- `dependencies = []`（零 runtime 依赖）仍然成立；`TOOLS` 仍 **164**：
  `plating_um` 放在**能力文档**里，没有新增工具参数，也没有新增工具。
- 新功能对**不写这三条限值**的既有调用零影响：`min_silk_*` / `min_mask_web` /
  `min_copper_to_hole` 不写在 `rules` 里时，对应 fact 一律
  `why: "...so the sweep was skipped"`，`not_stated` 列表里照旧点名。

**登记过的三处改变**（都会让 `dfm_capability` / `dfm_check` 的输出与 0.0.55 不同，
这里明写，不留在暗处）：

1. `rules_known` **11 → 15**，`coverage_pct` 分母从 11 变 15。同一份只写了 3 条规则的
   能力文档，`coverage_pct` 会从 27.3 % 掉到 20.0 %——这不是覆盖变差，是分母变准。
2. `present["pad_to_mask"]` 从 `{present: false, note: "parsed only on demand"}` 变成
   `{present: true, expansion: {...}}`。0.0.55 那句"只在需要时解析"是真的（当时确实
   不解析），现在不真了，所以改。
3. `present` 新增 `silk` 一项。

**没有静默改变答案**的地方（特意留着不动，只登记）：

- 环形环仍量到钻壁（见 59.5）；
- KiCad 的"无宽度丝印"仍不给默认值（宁可报一个上界）。

## 59.8 与 0.0.55 的关系

0.0.55 的题目是"每个没填的数都要点名"（`data/magnetic_materials.json`，`null` 而不是回忆）。
0.0.56 是同一个纪律落在 DFM 上：**能算的算到出处，不能算的说清楚差哪一步，工艺参数
从文档来而不是从记忆来**。所以三条原来"不算"的量现在算了，而 `plating_um` 缺了就
拒答——拒答和"给一个到钻壁的数"在读者眼里是两件事，后者会被当成前者用。

## 59.9 三个可复用的坑

1. **两个名字空间**：`gr_*` 与 `fp_*` 不是同一套 kinds。共用元组会静默丢条目，
   而丢掉的条目不会报警——只会让"最小值"变成一个别人给的值（这次是 0.15 的 text
   顶替了 0.12 的 line）。
2. **"合并"不等于"0"**：几何上 web ≤ 0 是一个**定性**事实（没有阻焊），把它写成一个
   数字会跨越判据的语义。
3. **浮点最后一位不能决定判词**：多边形距离带噪声，读数在 1e-6 mm 上取整之后再比。
