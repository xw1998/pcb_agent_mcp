# 126 · 过孔选址：这个孔在法律上放得下吗，余量多少

`board_via_sites`。

## 1. 为什么需要

服务器里能「算」过孔（电流、电阻、热、围栏），`board_stitch_vias` 能在接地栅格上
**放**缝合孔，但没有一个工具回答布线路上的那个问题：**这附近有没有一个合法的孔，
哪一个余量最大。**

这个缺口有代价，不是假设的。缝合那一轮：16 个接地孤岛里只有 4 块放得下 0.45 的孔，
而那 4 块里有 2 块把孔放进了 PD13/PD14 的走线 —— 脚本是自己重建板子、读 DRC 才知道的，
一次一轮。

## 2. 怎么算

候选点（栅格）合法当且仅当：

1. 在板框内，且离板边 ≥ 边距 + 半径；
2. 在**每一层**它穿过的铜层上，离别的网的焊盘/走线/过孔/**铺铜** ≥ 间距 + 半径；
3. 它的钻孔离任何已有钻孔 ≥ `min_hole_to_hole`。

`room_mm` 是这三条里最紧的那条的余量，所以 `room_mm = 0.05` 就是「最紧的一侧只剩
0.05 mm」。`limited_by` 指名是哪一条（`board edge` / `pad on F.Cu` / `zone on F.Cu` /
`existing hole`），`nearest` 给出最近的那个对象。

**`net` 是这个工具的关键参数**：给了网，该网自己的铜不算障碍（孔就长在自己的线/焊盘上，
这正是它连接的方式）；不给，则一切铜都算障碍（给「随便哪个网」找位置）。但**钻孔间距
是工艺规则，任何网都不豁免**。

## 3. 判据与对照

十三条，在 `tests/test_via_sites.py`。成对的关键对照：

| 事实 | 对照（能反向失败的） |
|---|---|
| 空板只剩板边一条约束，余量 = 边距 −（边距规则 + 半径） | 离边 0.2 mm 的点必须被拒，且 `killed_by` 指到 `edge_clearance` |
| 别的网的焊盘 0.5 mm 外吃掉余量 | **同一个焊盘**，把孔要成那个焊盘的网 → 余量回到板边值（自己的铜不吃余量） |
| 别网的铺铜**默认不拒**，但必须报 `inside_pours` | 同一个几何加 `pours_block=true` → 必须被拒并计 `pour_interior`（一个开关两种答案） |
| 两个 0.3 钻孔要 0.55 中心距 | 0.5 拒、0.6 收（同一块板，只挪 0.1 mm，且 `net` 一样 ⇒ 量的是规则不是板子） |
| 全板 0.2 mm 栅格 79200 个候选过慢 | 必须**拒绝**并给出「约 0.40 mm 才装得下」，不是超时 |
| 窗口按给的 region / x,y+半径 走、并被裁到板内 | 窗口落在板外必须报 `ARG_RANGE`，不是「没有合法点」 |

## 4. 铺铜到底算不算障碍（一个我先做错、后来推翻的判据）

第一版把别的网的**铺铜内部**当成硬障碍：孔落在里面就拒。这在工艺上是错的 —— 灌铜
会绕着新加的孔重切，所以孔落在别网的平面上不是短路，只是**咬掉一块铺铜**。判据错了，
读数就会错得很自信：

```
（错判据）U1 上边扇出处：441 个候选，合法 2 个，最大余量 0.124 mm
（正判据）同一处          ：441 个候选，合法 16 个，最大余量 0.325 mm
                          限制来自 $1I8749/OSC_IN 的走线，不是铺铜
                          inside_pours = ["GND"]（会咬掉 GND 平面一块）
```

所以现在默认**不把铺铜当障碍**（与 `board_cut_capacity` 同一个理由），但每个点都报
`inside_pours`，让调用者知道会咬哪块平面；要严格口径就 `pours_block=true`，此时连
铺铜边界也参与算余量，答案回到「2 个合法点」。

下边那处同样从「0 个合法点」变成「40 个，最大余量 0.225 mm，限制来自 PC7 的走线」。

真板全板扫描（0.5 mm 栅格）：12905 个候选、5473 个合法、最大余量 5.75 mm。

## 5. 三处实现缺陷，都只有测试能抓到

1. **单格查找**：桶查询只看了候选点所在的那一格，于是 0.5 mm 外的焊盘"查不到"，
   所有余量都退化成板边值（19.55 mm）—— 一个看起来非常漂亮的错答案。改成按环查，
   0 环没有就查 1 环。
2. **半径扣两次**：把钻孔当成半径 drill/2 的圆去算距离，又减了一次 drill/2，于是
   0.10 mm 合法余量的点被拒。改成「点是点，半径后减」。
3. **铺铜按多边形整体采样**：GND 面是 **21451 个顶点**的单个多边形，
   `point_in_polygon` 每个候选一次就是 3500 万次边测试（2.7 s / 441 个候选）。
   改成「边进桶（只碰附近的边）+ 扫描线掩膜回答『在里面吗』」后同一次查询 0.12 s。
   全板 0.2 mm 栅格（79200 个候选）仍然过慢，于是**拒绝**并给出「0.40 mm 才装得下」
   的建议，而不是超时。

第 1、2 条都是「错得很自信」那一类：结果不是一个明显崩掉的数字，而是 19.55 这种
看起来合理的数。第 4 个错（把铺铜当固定铜）见上一节，性质不同 —— 它不在代码里，
在判据里。

## 6. 没有做的事

- 不放置、不写板：只报合法点与余量。`board_stitch_vias` 才是放置的工具。
- 不判「这个孔有用」：孔可能合法但没意义（离任何该网铜都远）。`not_claimed` 写在返回里。
- 不跨工艺判断：孔到板边的铜距、槽孔、背钻都不在范围内。
