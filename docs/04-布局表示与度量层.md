# 布局表示：从"坐标"到"关系 + 度量 + 预算"

日期：2026-10-27
承接 01/02/03。本篇解决：**模拟电路里布局本身就是设计，错了 DRC 也不会报。现在的表示完全没管这件事。**

---

## 0. 三个反例：为什么"给坐标"是错的表示

**反例 1｜差分对**
AI 收到两个电阻的坐标 `(12.0,8.0)` / `(14.2,8.0)`，看不出它们是不是对称、旋转是否一致、离热源是否等距。
但设计者脑子里的那句话是：「R1、R2 关于 x=13.1 对称，同向，且到 Q1 等距」。
**这是关系，不是坐标。**

**反例 2｜共质心排布**
匹配对要求 A-B-B-A 交错、共用质心。给出四个坐标，AI 既看不出这是共质心，也无法判断"现在是不是"。
**这是模式，不是坐标。**

**反例 3｜Kelvin 取样**
电流检测要走独立取样线，从焊盘边缘双线引出。给出坐标，AI 无法知道"这两根线在焊盘里共用了一段 1.8mm"。
**这是拓扑/共路径长度，不是坐标。**

⇒ **布局的表示必须是「关系谓词 + 模式 + 可测指标」，坐标是求解器的输出，不是 AI 的输入。**

## 1. 预算链：布局约束不能凭空来

「布局很重要」如果不可量化，就无法判定对错。所以必须先有**设计目标 → 预算 → 布局约束 → 可测指标**这条链：

```yaml
# L1 spec 新增段
budgets:
  offset_drift:  {max: 10uV/C,  driven_by: [matching, thermal_gradient]}
  noise:         {max: 5uVrms,  driven_by: [loop_area, coupling, guard]}
  gain_error:    {max: 0.1%,    driven_by: [matching, kelvin_shared_path]}
  stability:     {phase_margin_min: 45deg, driven_by: [fb_node_length, ground_star]}
```

每条布局约束必须**声明它服务哪个预算**。反过来，每个预算必须有至少一条布局约束在守。

**没有这个链，AI 只能凭常识摆件，而常识不足以达到 0.1% 的增益误差。**

## 2. 布局规格语言（10 类约束，全部可机判）

### 2.1 group / flow（功能块与信号流）

```yaml
groups:
  - id: frontend
    parts: [J1, R1, R2, U1, C1]
    order: [J1, R1, U1, C1]        # 信号流顺序
    bbox: {max: [12, 10]}          # 紧凑度目标
    flow: ltr                      # 输入在左，输出在右
    no_cross: true                 # 内部走线尽量不交叉（可判：看 ratsnest 交叉数）
```

### 2.2 symmetry（对称）—— 模拟的核心

```yaml
- kind: symmetry
  members: [R1, R2]
  axis: {type: vertical, x: 13.1}     # 或 horizontal / about: {ref: U1, pin: 3}
  tol: 0.10mm                          # 中心偏移容差
  orientation: same                    # same | mirror | rotational
  serves: gain_error
```

可机判量：`offset = |dist(R1,axis) - dist(R2,axis)|`、`orientation_match`、`delta_anchor`（到各自锚点引脚的距离差）。

### 2.3 pattern（结构化排布模式）

```yaml
- kind: common_centroid
  members: [R3, R4, R5, R6]
  about: U2
  layout: ABBA            # interdigitated | ABBA | cross_quad | common_centroid
  orientation: rotational # 每个单元转 90°，消除方向性误差
  spacing: 0.5mm
  serves: matching
```

**这是 AI 最该做的事：选模式、指定成员、给容差。** 坐标由求解器按模式生成。人类工程师也是这么工作的——没人逐像素摆共质心。

### 2.4 thermal（热对称与梯度）

```yaml
- kind: thermal_match
  members: [Q1, Q2]            # 匹配管对
  max_delta_t: 1.0C
  same_isotherm: true          # 两管中心应在同一条等温线上
  serves: offset_drift
- kind: thermal_keepaway
  heat_sources: [U3]           # LDO/DCDC
  sensitive: [U1, R1, R2, RT1]
  min_gap: 8mm                 # 或按 ΔT 阈值
```

可机判量需要**温度场**（见 §4）。

### 2.5 proximity / apart（近与远）

```yaml
- {kind: near,   a: C1, b: "U1.VIN",  max: 2.0mm, serves: loop_area}
- {kind: near,   a: C1, b: "U1.GND",  max: 2.0mm, serves: loop_area}
- {kind: apart,  a: U3, b: U1,        min: 8mm,   serves: noise}
- {kind: same_side, parts: [L1, D1]}               # 同层/同面
- {kind: inside, a: frontend, box: [2,2,20,14]}
```

`near` 的距离度量**不能用欧氏距离**——模拟里要的是"沿电流回流路径的环路面积"（§2.6）。

### 2.6 parasitic（寄生：长度 / 面积 / 共路径）

```yaml
- kind: max_loop_area
  nets: ["VIN", "GND"]        # 这两条 net 构成的供电环路
  max: 20mm2
  serves: noise
- kind: max_length
  net: FB                      # 反馈节点，高阻易受扰
  max: 8mm
  serves: stability
- kind: kelvin
  sense: [SENSE_P, SENSE_N]
  across: R_shunt
  max_shared_path: 0.5mm       # 与功率路径的共路径长度
  serves: gain_error
```

**Kelvin 共路径长度**是这个表示里最值钱的一个量：DRC 完全不管，而它直接决定电流采样精度。

### 2.7 isolation / guard（隔离与屏蔽环）

```yaml
- kind: guard_ring
  around: [FB, IN_HI_Z]
  net: AGND                   # 或 driven_guard: U4.OUT
  width: 0.3mm
  closed: true                # 必须闭合（可判）
- kind: isolate
  groups: [analog, digital]
  min_gap: 3mm
  no_crossing_nets: true
```

### 2.8 ground（接地拓扑 —— 天然适合图表示）

```yaml
- kind: ground_topology
  style: star                  # star | single_point | plane | split_plane
  star_point: {ref: U1, pin: GND}
  max_star_points: 1
  split: [{nets: [AGND, DGND], join_at: {ref: U1, pin: GND}}]
  serves: noise
```

可机判量：**星点个数**、**AGND/DGND 是否只在指定点相连**、**跨分割走线数**。
这是"给图 + 给关系"的最佳平衡：接地是拓扑，用图判断，用数字报告。

### 2.9 orientation / fixed（朝向与固定件）

```yaml
- {kind: orientation, ref: J1, rot: 0,    reason: "外壳开孔在左侧"}
- {kind: orientation, ref: D1, pin1: up,  reason: "装配一致性"}
- {kind: fixed, refs: [J1, J2, H1, H2], reason: "结构件/连接器，位置由外壳决定"}
```

`fixed` 的器件是布局求解的边界条件——**必须先标出来**，否则求解器会把连接器挪到板中央。

### 2.10 side / shield（单面与屏蔽）

```yaml
- {kind: single_side, parts: analog, side: top, reason: "模拟区单面，底面完整地"}
- {kind: shield_zone, box: [x,y,w,h], layers: [F.Cu], reason: "预留屏蔽罩"}
- {kind: keepout_z, box: [...], z_max: 3mm, reason: "外壳内腔高度"}
```

## 3. 度量层：布局质量报表（与 DRC 并列的第二套闸门）

**这是"信息不够"的直接解。** DRC 回答"合不合规则"，布局报表回答"达不达设计目标"。

```
LAYOUT CHECKS   (step 7, backend=local-solver)
  L1 symmetry(R1,R2) axis x=13.10   offset 0.08mm  (tol 0.10)   ✅ margin 0.02
  L2 centroid(R3..R6) about U2      pattern ABBA ok            ✅
  L3 thermal(Q1,Q2)  ΔT 0.42C       (max 1.0)  same isotherm     ✅
  L4 loop_area(VIN,GND)  34.0mm2    (max 20)   ⚠ 超 14mm2  ← 服务 noise
       成因: C1 距 U1.VIN 4.6mm（要求 ≤2.0），环路被拉长
       建议动作: 移 C1 至 F1 矩形(6.0x4.5@30,26) 内, 预计 18mm2
  L5 kelvin(R_shunt) shared_path 1.8mm (max 0.5)  ❌ 服务 gain_error
       成因: SENSE_P 与功率线在 pad7 处共用 1.8mm
  L6 ground star_points = 2 (max 1)  ❌ 服务 noise
       AGND 在 U1.GND 与 C7 两处连通
  L7 guard(FB) 缺失  ❌ 服务 noise
  L8 aggressor(U3.SW) → victim(FB) 4.1mm (min 5.0)  ⚠ margin -0.9
  L9 bbox(frontend) 13.4x9.1 (max 12x10)  ⚠ 宽超 1.4

  预算消耗: noise 已用 68% 余量(2/3 项告警) | gain_error 已破 | offset_drift ok
```

三条设计原则：

1. **报余量（margin），不只报 pass/fail。** 布局坏常常不是违规，是余量被吃掉；只报布尔会让 AI 看不出"快死了"。
2. **每条告警带成因 + 可执行的建议动作**，动作要引用具体自由矩形/FREE RECT，让 AI 能直接采纳。
3. **按预算汇总**，让 AI 知道"现在哪个设计目标最危险"——这是它做取舍的依据。

## 4. 两个必须新建的"场"

栅格占位图只表达"有没有东西"，模拟布局要的是两个连续场：

### 4.1 温度场（粗栅格）

```yaml
thermal_field:
  pitch: 2.0mm
  source_model: "per-part power_w from spec/BOM; 简单热扩散核"
  grid: [[24.1, 24.3, 24.6, ...], ...]     # °C，或归一化梯度
  isotherms: [0.5C, 1.0C, 2.0C]            # 给出的等温线间隔
```

用途：判 `thermal_match` 的 ΔT、判"敏感器件是否落在热源等温区内"。
**精度诚实标注**：这是估算场（无场求解器），只做相对比较，不做绝对温度结论。

### 4.2 回流路径场（return-path）

```yaml
return_path:
  net: GND
  method: "平面连续性 + 最短回流近似"
  per_net_length: {FB: 9.2mm, SENSE_P: 7.8mm}   # 信号 + 回流的总环路长度
  cross_split_count: 0
  loop_area: {VIN_GND: 34.0mm2, SW_OUT: 12.5mm2}
```

用途：算 loop_area、判跨分割、算共路径。
**这是 03 篇里"参考平面连续性"那条致命缺口的落地方式。**

## 5. 相对方位查询（比坐标好用一百倍）

```yaml
relative(ref: C3, to: U1)
→ { bearing: "SE", dx: +2.4, dy: -1.0, dist: 2.6,
    same_side: true, rot_delta: 90,
    in_same_group: false,
    on_axis: null }
```

模型对"C3 在 U1 东偏南 2.6mm，同面，转了 90°"的推理能力，远高于对 `(28.1,14.0) vs (25.7,15.0)` 的推理。

## 6. 布局特有的丢失项（本篇新增）

| 信息 | 状态 | 后果 |
|---|---|---|
| 匹配/对称关系 | 原表示完全没有 | AI 摆完不知道对不对，只能问人 |
| 排布模式（共质心/交错） | 没有 | AI 逐坐标摆，几乎必然不匹配 |
| 温度场与热对称 | 没有 | 匹配管对 ΔT 失控 → 温漂 |
| 环路面积 | 没有 | 按欧氏距离摆去耦 → 噪声超标 |
| Kelvin 共路径 | 没有 | 电流采样精度毁于 1.8mm 共用段 |
| 接地拓扑（星点/分割/连接点） | 只有覆铜 `~` | 双点接地、AGND/DGND 乱连 |
| 屏蔽环闭合性 | 没有 | 高阻节点被干扰 |
| 结构固定件（连接器/孔/外壳） | 我上一版只在 blocker 里有 | 求解器会把连接器挪走 |
| 装配方向/极性一致性 | 没有 | 装配出错 |
| 设计预算（噪声/增益/温漂） | **源缺失** | 布局"对不对"无法判定 |

## 7. 流程调整：布局必须有独立闸门

```
spec(含 budgets) 
  → place_auto()        求解器出坐标（用 pattern + symmetry + thermal + fixed 作约束）
  → layout_report()     ★独立闸门：按预算报余量，不是 DRC
  → AI 按报告改 spec（换区域/换模式/放宽容差）→ 重跑
  → layout_pass         预算全部有余量  才允许进入布线
  → route_auto()
```

**关键：布局与布线之间必须有一道"预算闸门"。** 现在所有 MCP 都是"摆完直接布"，这就是模拟板翻车的标准路径——布局错了布线再好也救不回来。

---

## 8. 验收

1. **可判定性**：给定 spec，`layout_report` 必须对每条约束输出 `measured / limit / margin / serves`。少一项即不合格。
2. **反例测试**：故意摆一个"DRC 全绿但增益误差超标"的布局（对称偏移 0.4mm、Kelvin 共路径 2mm），`layout_report` 必须报红并指出成因。
3. **预算闭环**：每条 `budgets` 至少有 1 条约束在守；没有守护约束的预算必须报 `unprotected`（这是 spec 缺陷，不是布局缺陷）。
4. **求解器边界**：所有 `fixed` 器件位置在求解前后必须逐位相同。

---

## 9. 结论

布局信息丢失的根因**不是"没给坐标"，而是"没有度量层"**：

- 人类工程师判断布局靠的是**关系**（对称、共质心、同温、等距、环路）和**预算**（噪声/增益/温漂）；
- 现有 MCP 只提供坐标和图元，所以 AI 只能凭常识摆；
- 正确做法：**AI 写关系与模式 → 求解器出坐标 → 度量层报余量 → AI 按余量调整**。

一句话：**布局的"对错"必须从 DRC 里独立出来，做成一套按设计预算判定的闸门。** 否则"布局很重要"就只是一句正确的废话，AI 无法据此行动。
