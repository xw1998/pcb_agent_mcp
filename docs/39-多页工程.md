# 39. 多页（层级）原理图：先问对是哪棵树

到 0.0.32 为止，原理图写路径的每一道闸门都建立在同一个假设上：**一个 `.kicad_sch` 文件就是一张图**。
这个假设在单页工程里成立，在层级工程里会让服务**静默回答另一个问题**——而且是那种"数字齐全、
判决通过"的错。

这一篇记录把"一张图"改成"一棵树"之后必须重新回答的四件事：树从哪读、页号归谁、引擎该问哪棵树、
sheet pin 与 hierarchical label 谁说了算；以及每一步配的**能失败的对照**。

---

## 39.1 被推翻的前提：单文件闸门问的是另一个问题

0.0.32 的 `apply` 闸门做的是：把**待测文件**复制进一个临时目录，再让 kicad-cli 在那里跑网表与 ERC。
对单页图纸这是**精确正确**的——那张图就是那个工程。

对层级工程它是错的，而且错得看不出来：临时目录里只有那一个文件，KiCad 打开它，看到 `(sheet ...)`
节点指向的 `power.kicad_sch` 不在，于是它要么报错、要么当"这张图没有子页"答下去。两种结果都被
本服务当成判据用了。

实测（`complex_hierarchy` demo + `ampli_ht.kicad_sch`，kicad-cli **10.0.7**）：

| 问法 | 网表 | ERC |
|---|---|---|
| 问整棵树（本版） | **52 nets** | **73 violations** |
| 只问一个文件副本（0.0.32） | 那张图自己的 nets，父页与兄弟页全缺 | 子页的违规一条都看不见 |

也就是：**旧闸门对层级工程给出的是一个"没有子页的项目"的答案，并且把它当作"改前"与"改后"的
共同基线**。改前改后都错同一处，差值看起来还是干净的——这是最坏的一类假绿。

修法不是"再加一道闸门"，而是**两边问同一组文件**：

```
before = materialise(整棵树, 待测文件=磁盘上的原文)
after  = materialise(整棵树, 待测文件=提案文本)
```

`fidelity/hierarchy.py` 的 `materialise()` 把树里每个可达的 `.kicad_sch` 按**同一相对布局**复制进
一个临时目录，只替换被编辑的那一个文件；两个引擎调用都在副本里跑，`finally` 里整个目录删掉。

同一个文件被两个 sheet 引用时**只复制一次**，并在 `skipped` 里说明原因（"the file is used by more
than one sheet"）——复制两遍会在副本里造出两个不同的文件，那等于改写了工程布局。复制不了的
（`Sheetfile` 落到入口目录之外）列进 `skipped`/`outside`，同时 `tree` 闸门把"引擎看到的是残缺树"
这件事说出口，而不是继续拿它当判据。

**负控制**（`tests/test_sch_sheets.py`）：指向一个不存在的子图 →

```
hierarchy_diff.new   = [{"issue": "missing_file", ...}]
blocking             != []
apply                → EditError GATE_BLOCKED
根文件字节           byte-identical
```

**同一个 bug 家族的第三例**（修的时候抓到的，记在这里当教训）：`describe(path, text=...)` 的 `text`
原本只对**入口文件**生效。demo 的入口（`ampli_ht.kicad_sch`）不是工程根，于是提案文本被静默丢弃，
新 sheet 在 after 里根本不出现，`blocking` 因此为空——闸门"通过"了一次它从未看见的改动。现在
`text` 与 `edited` 配对，只有被编辑的那个文件用提案文本，别的一律从磁盘读。

## 39.2 树从哪读：`(sheet)` 节点，不是文件名

一棵 KiCad 树的全部事实都在 `(sheet ...)` 节点里：

```
(sheet
  (at 261.62 93.98) (size 54.61 57.15)
  (uuid "17d5901d-...")
  (property "Sheetname" "fpga-hp-banks")
  (property "Sheetfile" "fpga-hp-banks.kicad_sch")
  (pin "FPGA-PL_CLKSYS_N" input (at ...) (uuid "..."))
  (instances
    (project "vme-wren"
      (path "/80fa765c-.../38c7add5-..." (page "3")))))
```

三条容易读错的地方：

| 直觉 | 事实 |
|---|---|
| 页号就是文件名/序号 | 页号只活在 `(instances (project … (path … (page …))))` 里，一个节点可以有多条 |
| 根文件也有 `sheet_instances`，子文件也该有 | **子文件没有** `sheet_instances`；根文件的 `(path "/" (page "1"))` 才是根页号 |
| 同一个文件出现两次 = 重复文件 | 那是**一个文件两条实例路径**（两套位号、两个页号），不是重复 |

`walk()` 因而按"文件 + 实例路径"递归：一个文件被两个 sheet 引用就走两遍、报两个节点；一个文件
出现在自己的祖先链里就是 `cycle`，走查在那里停下并说明（KiCad 会拒绝打开这样的工程）。
`find_root()` 只做一件事：找**没有任何兄弟文件把它写成 Sheetfile** 的那个文件；两个兄弟都指它时
判 `ambiguous` 并拒绝挑一个（那是同一个目录里两个工程，不是本服务能替调用方决定的事）。

## 39.3 页号是**工程**全局的：一个节点写几条路径条目

`vme-wren` demo（17 个 sheet 节点、73 页）给了一条硬事实：**页号在工程里唯一、全局递增**，
不是"每张图从 1 开始"。于是当被编辑的页本身被实例化多次时，新加的 sheet 节点必须**每个实例一条**
`(path … (page …))`：

```
(instances (project "vme-wren"
  (path "/root/sheet-a" (page "11"))
  (path "/root/sheet-b" (page "12"))))
```

只写第一条的后果不是"少一条语法"，而是**每个实例都显示同一个页号**：文件能打开、网表不变、
打印出来的图纸页码是错的——一个"看着像成功"的失败。

实测（`complex_hierarchy`：同一个 `ampli_ht.kicad_sch` 被两个 sheet 引用）：

| | 0.0.32 之前 | 本版 |
|---|---|---|
| 往该文件加一个 sheet | 一条条目、两个实例都读 **page 2**（与已有的 2 页相撞） | 两条条目、**page 4 / 5** |
| `duplicate_pages` | 有 | `{}` |

于是 `add_sheet` 的页号规则改成：**先看工程**（`hierarchy.instance_paths()`：这个文件在哪几个实例
路径下、各自第几页、工程最大页号是多少），看不到工程（内存文档、文件还没落盘）才退回"本文件
最大页号 + 1"。三条由此而来的拒绝：

- 多实例 + 显式 `page` → `ARG_INVALID`（一个页号不能命名一个被实例化 N 次的页，也不替调用方猜
  哪条是"第一条"）；
- 页号在工程**任何位置**已用 → `PAGE_EXISTS`（负控制：往根页写 `page=9`，而 9 是两层以下的
  leaf 的页号）；
- `PAGE_EXISTS` 的报错里列出**全部**在用页号，不是只列本文件的。

## 39.4 五道闸门 + 一棵树

`apply` 现在报七个字段，其中 `engine` 是"两次引擎调用都跑了"，`tree` 是"引擎被问的那棵树是完整的"：

```
['bytes_written', 'token_identity', 'postconditions', 'tree', 'engine', 'netlist', 'erc']
```

`tree` 的判据只有一条：**复制前后都不缺文件、都不含环**。它不判"改动对不对"，它判"上面那两个
引擎答案是不是同一棵树的答案"。实测 demo：

```
before: files 2, missing [], skipped [ampli_ht.kicad_sch: used by more than one sheet]
after : files 3, missing [], skipped [同上]
```

**负控制**：把一个子图从磁盘上删掉再 apply → `tree.ok = False` → `GATE_BLOCKED`，理由是
"the sheet tree the engine was asked about was incomplete"。这条负控制存在的意义是：没有它，
`tree` 闸门可以永远返回 `ok: True` 而不被发现。

`hier_written`（返回体里的 `hierarchy`）是**无条件**算的：`engine: false` 时也要报"写完之后这棵树
长什么样"，否则 `engine: false` 看起来像"什么都没检查"。顺带修掉的同一类假绿：`blocking` 原本只在
`propose` 里生成、`apply` 并不看——现在它落进 plan 字典，`apply` 第一行就拒绝（实测：指向
不存在的子图 + `engine: False` 曾经**真的写进去了**）。

## 39.5 sheet pin 是**承诺**，不是装饰

`add_sheet(pins=["VCC"])` 写下的是：这张子图的 `VCC` 引脚接到了父页。它成立的前提是
**子图里有一个叫 `VCC` 的 `hierarchical_label`**。本服务不替调用方创建那个 label（那是另一个文件
的改动，见 §39.6），也不假装它存在——它让 ERC 说话：

| 情形 | ERC 新出现的违规 | 判决 |
|---|---|---|
| 子图里没有该 label | `hier_label_mismatch` + `pin_not_connected` | 拦截并回滚（文件 byte-identical） |
| 先往子图放好 `hierarchical_label "VCC"` 再 `add_sheet` | `hier_label_mismatch` **消失**（只剩子图自身的 `label_dangling` 等，因为它从未接入工程时不计） | 通过 |

这是本模块里最值钱的一条正控制：**它证明拦截来自"label 不在"这件事本身**，而不是来自"ERC 变多了"
这个粗糙的判据——后者会把任何一次 ERC 抖动都当成拒绝理由。

## 39.6 为什么不把"建新页"塞进 plan

`new_schematic_file` 是**独立工具**，不在 op 表里。理由是原子性：一个 plan 现在只原子地写一个文件
（`token_identity` + 字节回滚都建立在这条上）。把"建文件 + 改父页"合成一个 plan 就要多文件事务，
而多文件回滚在"中途磁盘满"这类情况下没有诚实的答案。

于是多页工程的标准动作是两步、并且两步都是可核验的：

1. `schematic_new_file(path, paper="A4")` — 建一个 200 字节的空页，写完立刻用 `from_text` 自检
   （`bytes_identical` + `token_identity` 都 True 才算成功），失败回滚删除；
2. `schematic_propose(add_sheet, file=新建的页)` — 父页上的那个框。

"一个框指向一个什么都没有的页"正是 ERC 要拒绝的东西，所以第二步只有在 §39.5 的正控制成立时
才会通过。这个顺序把"我到底在建什么"摊开给调用方看，而不是藏在一次大改动里。

拒绝清单（全部是 `ARG_INVALID`/`PAGE_EXISTS`/`SHEET_*`，没有静默降级）：

| 输入 | 为什么拒绝 |
|---|---|
| `Sheetfile: "../power.kicad_sch"` / `sub/x.kicad_sch` | 落点不在本服务能核验的目录里；"树"的定义就没了 |
| `Sheetfile: "power.txt"` | sheet 只能指向 schematic |
| `page` 与本页/本工程任何页重复 | 见 §39.3 |
| 多实例页 + 显式 `page` | 一个页号不能命名 N 个实例 |
| `set_sheet_field` 改 `Sheetname`/`Sheetfile` 之外 | 其余字段是几何（`at`/`size`），该由布局改而不是文本改 |
| `set_sheet_field` 写同值 | `OP_NOOP`（改一行等于不改，却被算成"改过"） |
| 让树成环（`Sheetfile` 指回祖先） | `cycle` → blocking |
| `delete_sheet` | **从不删文件**：返回 `file_kept` / `other_sheets_using_it` / `orphaned` |

## 39.8 仍然不做

- **页面尺寸/图框模板**：`new_file` 只写 `paper`，不写 `(title_block)`、不套公司图框。
- **改 `Sheetfile` 指向后搬文件**：`set_sheet_field` 只改文本，不移动/复制磁盘文件；指向不存在的
  文件会被下一道闸门拦（`missing_file`），但"顺手帮你搬过去"不在本服务的行为里。
- **跨页批量重命名/重编号**：改一张图是一等公民，改整个工程不是（见 §39.1 的教训：一次改动跨越
  多个文件，`token_identity` 与字节回滚就不再是同一个保证）。
- **sheet pin 的电气类型与 label shape 一致性**：pin 有 `input/output/bidirectional/tri_state/passive`，
  label 有 `input/output/…`，两者不匹配 KiCad 只给 warning；本服务照样只报 warning，不升级成拒绝
  （升级会把"能打开的工程"判成"不能写的工程"）。
- **KiCad 5 的老层级写法**（`(sheet ... )` + 顶层 `(sheet_instances)` 里列所有页）：只读能读到，
  写按 9/10 的形状写；老格式的往返没有实测过。
- **`.esch`（立创）的多页**：立创侧仍然整类拒写。
