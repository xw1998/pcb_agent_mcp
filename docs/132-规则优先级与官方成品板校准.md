# 132 · 规则集、优先级，和 18 块官方成品板的校准

这一版回答三个问题，一个都不能靠自称：

1. **规则从哪来**——每条规则的数值必须有一句能引用的原文，不能是我拍的。
2. **谁先谁后**——规则有优先级，先满足高优先级；低优先级不许抢占"下一步"。
3. **这些规则对不对**——拿 18 块**已经被做出来、被公开发布**的 KiCad 官方 demo 板倒推：
   如果规则说它们"做不出来"，那错的是规则，不是板子。

第 3 条是这一版最重要的动作。规则写得再整齐，没有一块真板反驳过它，就只是文档。

## 1. 规则从三个地方来，一共 55 条

| 来源 | 条数 | 数值出处 | 归到哪一层 |
|---|---|---|---|
| 厂商能力库 `jlc/data/jlc-pcb-capabilities.json` | 29（PCB）+ 20（SMT，仅在 `process.smt` 声明时加载） | 每条带 `src` / `tier`(T0/T1/T2) / `url` / 逐字 `quote` | P0（丝印 3 条降 P4，见 §4.5） |
| 设计目录 `calc/rules.py`（布局） | 22 | 工艺手册与工程惯例，`severity` 是原文口径 | 按后果分 P1/P2/P3/P4 |
| 本包自己量的几何规则 | 4 | 量出来的数，不是引文（连通性 / 45° /  courtyard / 出框） | P1 ×1，P2 ×2，P3 ×1 |

P0 只有厂商极限这一层，是因为**只有厂商极限能判"做不出来"**。别的一切都是"做出来不好用"。

## 2. 五级优先级

| 级 | 含义 | 能不能阻塞 |
|---|---|---|
| **P0** | 板厂会拒单：线宽/线距/孔径/焊环/孔边距/铜到板边/槽宽/板厚/铜厚/表面处理 | 能 |
| **P1** | 能造出来，但一定会出问题：网络不通、去耦太远、参考面断裂、电源线不够宽、RF 换层无回流 | 能 |
| **P2** | 装不上或装上了不好修：器件重叠、器件出框、晶振下走线、无块电容、无测试点、丝印压焊盘 | 能 |
| **P3** | 信号质量与工艺美学：45°、差分等长、RF 3W/弯曲半径/阻抗、缝合过孔、天线净空 | **不阻塞**，进 `flagged` |
| **P4** | 印得不好看：丝印字高线粗、丝印到焊盘、晶振地守护环 | **不阻塞** |

三条硬规矩，都是被真板逼出来的：

- **severity ≠ priority**。目录里 `min_trace_width` 的 severity 是 `Low`（它只是一条惯例），
  但板厂真的会拒 6 mil 以下的单，所以它是 P0；`rf_z0_tolerance` 的 severity 是 `High`，
  但阻抗偏 5% 的板照样装配、照样连通，所以它是 P3。严重度说的是"多难受"，
  优先级说的是"在哪一步拦住你"。
- **只有 P0/P1/P2 能阻塞**。第一轮校准里有 6 块官方量产板因为历史角度走线被判
  `blocked_at_P3`——那是让 agent 去磨倒角，而不是去修一块不能用的板。P3/P4 的 fail
  只写进 `flagged`，且只在没有阻塞项时才出现在返回里。
- **阻塞层之下全部 `deferred`**，并保留 `graded_state`。`first_action` 只从阻塞层取，
  按 margin 升序——最接近限值的那条排第一。低层的 fail 永远不许当"下一步"。

### 4.1 八类假阳性，每一条都是我们的错

第一轮跑完，6 块官方量产板被判"做不出来"，vme-wren 被判 `blocked_at_P2`。逐条查下来，
**没有一条是板的问题**。八类假阳性里前四类出在规则/口径，后四类出在 adapter 的几何读法。

| # | 假阳性 | 症状 | 根因 | 修法 | 权威对照 |
|---|---|---|---|---|---|
| 1 | NPTH 当镀通孔 | `pic_programmer` 报焊环 0 mm，判 unbuildable | 4.3 mm 安装孔是无铜孔，本来就没有焊环；`_hole_list` 不带 `pad_type`，`min_th_annular` 把它算进去了 | oracle 带出 `pad_type`；measure 按 `_plated()` 分流镀通/非镀通，新增 `min_npth_drill` / `min_npth_ring` | 该板重新判为 P3 通过 |
| 2 | 丝印填充图形当线宽 | 6 块板丝印"0.01 mm 线宽" | `fp_poly` 的 `width` 是填充轮廓，不是笔画；而且丝印细是印不漂亮，不是做不出来 | 排除 `_SILK_AREA_KINDS`（`fp_poly`/`gr_poly`/`fp_rect`/`gr_rect`）；`PCB.SILK.*` 三条整体降到 P4 | KiCad DRC 从不对丝印细报错 |
| 3 | 无网络铜造出 0 间距 | `openair-max` 报 0.0 mm 短路 | `net=None` 的焊盘 bbox 覆盖整颗器件的其它焊盘，跟别人的铜算出"重叠" | 无网络铜退出异网间距扫描，另报 `copper_items_without_net` 计数——宁可少判，并把这笔账露出来 | 该板真实最近间距是 **0.091 mm**（`In1.Cu` 两条线），不是 0 |
| 4 | oracle 拼写导致盲判 | 三条规则永远 `undetermined` | oracle 返回 `{"measured": ...}`，ruleset 只认 `{"value": ...}` | `_norm()` 归一；`unmeasurable` 以 `no ` 开头视为 `NONE_PRESENT`（对象不存在 = 不适用，不是"没量"） | — |
| 5 | 板框断链 → 碎裂成内槽 | `vme-wren` 报 1338 个器件出框、bbox 只 67 mm（真板 160 mm）、板框变成"内槽" | 板框是 1e-3 量级连起来的折线，`_chain_segments(tol=1e-6)` 断链后，最大碎片被当成板框、其余被当成 cutout | `_CHAIN_TOL = 1e-3`；未闭合的链记 `board.outline_open` | 修后：单条闭合轮廓 **160.1 × 233.5 mm**、cutouts 0、open 0；器件出框归零 |
| 6 | custom 焊盘被旋转两次 | `vme-wren` 的 `L1`（VLCF5020，fp 转 180°）两个焊盘相交 ⇒ 造出 `Net-(IC32-SW)`↔`5VREG` 的 **0.0 mm 假短路**；`Q201.1` 焊环读数也被带偏 | KiCad 的 `(at x y rot)` 对 pad 而言是**绝对角**（已含 fp 旋转）；`canonical.pad_points` 会按 `pad["rotation"]` 转一次，adapter 又按 fp 角转一次 | adapter **完全不再旋转 polygon**（只保留用于 `pad["x"]/["y"]` 的 `ca/sa`） | 修后 `L1.1` 155.679–157.279 / `L1.2` 151.779–153.239，两盘间距 **2.44 mm**；`kicad-cli pcb drc` 对该板报 **610 条违规、0 条 clearance** |
| 7 | through via 在内层凭空多出焊环 | `vme-wren` 一个 via 与 `/FP_IO7`（net 203）走线相切 0.0 mm | 文件里有 `(remove_unused_layers yes)`：KiCad 只在 via 真正连接的层上保留铜环；我们把 12 层全算成有铜 | 新增 `_resolve_via_copper()`：`keep = 首末层(keep_end_layers) ∪ zone_layer_connections ∪ 同网 zone 层 ∪ 邻近同网 track 端点层`，写回 `v.layers` / `v.layers_span`，记 `board.via_copper_resolved` | 修后该 via 解析为 `['F.Cu','In5.Cu','B.Cu']`（span 12）；全板 **4370/4374** 个 via 被解析；audit 225 s → 87 s；KiCad DRC clearance 仍为 0 |
| 8 | `connect` 焊盘被当成间距对 | `StickHub` 的 `JP1` 两个梳状 custom 焊盘异网相切 0.0 mm ⇒ 判 P0 unbuildable | `(pad "1" connect custom ...)` 是焊锡桥/连接盘，KiCad DRC 刻意**不检查其间距** | oracle 给条目打 `pad_connect` 标记；measure 的间距扫描跳过任一侧带此标记的对（**只打标记不删除**，因为删除会影响连通性判据） | `kicad-cli pcb drc` 对 StickHub = **0 条违规**；修后 P0 全 pass（转 `blocked_at_P1`，因为该板真的没连通） |

四类 adapter 缺陷（#5–#8）的共同点是：**我们自己的几何读法错了，错得还很像"板有问题"**。
每条都先用 `kicad-cli pcb drc --severity-all` 做了权威对照：KiCad 说没有的，一定是我们的读法有缺陷；
KiCad 说有的（jetson 357 条 clearance、CM5 的 0.15 焊环），不能改。

另修两处口径问题：

- **板厚吸附**：`cm5_minima` 的叠层总量是 1.5296 mm，不是选项里的 1.6——差的是叠层公差，
  不是错板。改成就近吸附（容差 0.1 mm）并记 `process_snapped`；超出容差不吸附，
  留给调用方。
- **同一数字只许一个 owner**：`openair-max` 的 0.15 mm 线宽过了 JLC 1 oz 却在目录规则
  `layout.min_trace_width`（0.1524）那里 fail，同一块板同一个数得出两个结论。
  `min_trace_width` / `min_via_hole` 两条改由厂商库判（带 quote、随工艺变），
  目录条目只保留可发现性说明（`graded_by`）。

## 5. 规则合理性：哪些被验证，哪些被推翻，哪些还没量

先看清一件事：**18 块里 7 块在声明工艺时被 P0 拦下、1 块被 P1 拦下**。这不是规则在乱咬人，而是
「官方 demo」不等于「官方可量产」——demo 是用来看功能演示的，不是拿去下单的。
但反过来也必须说清 P0 判的是什么：**判的是「按声明的这道 2 层 / 1 oz 工艺」，不是「这块板永远不能做」。
焊环 0.15 mm 在更贵的工艺上有余量，边距 0.19 在别的板厂可能就过。所以每一条 P0 fail 必须带
`process` 和逐字 `quote`，否则会被读成一句判决书。**

### 5.1 被真板正向验证的

- **P0 的层划分成立**：18 块里 **11 块 P0 全 pass**（其中 6 块只带 P3 flagged、4 块有 20+ 条
  `undetermined`、1 块真未连通）、**7 块被 P0 拦**——被拦的每一条都能指到具体焊盘/过孔坐标与
  数值（§4.2），没有一条是「整块板都不像话」的笼统判定。规则给的不是印象，是位置。
- **P1 的连通性是最有用的单条规则**：不声明工艺时，`layout.connectivity_complete` 把
  两块未布线正对照 + StickHub + One-Air-Max **四块全部拦在 P1**，且每块都给出未连通对数
  （StickHub 2 处）；已布线、P0 也干净却仍未连通的板子，只能靠它拓下来。
- **"未声明工艺就不许有 P0 结论"**：第一轮 6 块量产板被误判 unbuildable，全部来自这条没做。

### 5.2 仍 `undetermined` 的规则，缺的是"设计意图"，不是测量手段

P0 之外，17 块板里恒定为 `undetermined` 的有 20 条。它们的共同点：**板文件里没有这个事实**。

| 缺的 fact | 归哪条规则 | 缺什么 | 谁来补 |
|---|---|---|---|
| `signal_crosses_plane_split` | `layout.reference_plane_continuous` (P1) | 哪根线是"信号"、参考面是哪一层 | `facts=` 输入，需 net class / 层映射 |
| `decoupling_max_distance_to_pin_mm` | `layout.decoupling_distance` (P1) | 电容服务的是哪个电源引脚 | `facts=`，需原理图/网表 |
| `decoupling_via_in_path` | `layout.decoupling_same_layer` (P1) | 同上 + 是否有过孔在路径里 | `facts=` |
| `layer_changes_without_return_via` | `layout.layer_change_return_via` (P1) | 哪些网是高速/RF | `facts=`，需 net class |
| `power_trace_width_mm` | `layout.power_trace_width` (P1) | 每条电源网要过多少电流 | `facts=`，需电流预算 |
| `ics_without_bulk_cap` | `layout.bulk_per_ic` (P2) | 哪些器件是 IC、几路电源 | `facts=`，需 BOM + 引脚 |
| `power_pad_has_thermal_vias` | `layout.power_pad_thermal_vias` (P2) | 哪些焊盘是要散热的功率焊盘 | `facts=` |
| `silkscreen_over_pad` | `layout.silkscreen_over_pad` (P2) | 需要阻焊开窗信息（可从阻焊层推，未做） | 可在 measure 里补，欠账 |
| `test_points_on_rails_and_connectors` | `layout.test_points_present` (P2) | 哪些是电源轨、哪些是外部连接器 | `facts=` |
| `stitching_via_pitch_mm` | `layout.stitching_via_pitch` (P3) | 工作频率 → λg | `facts=` + 叠层 |
| `rf_min_bend_radius_mm` / `rf_min_spacing_to_other_trace_mm` / `rf_min_distance_to_edge_mm` / `has_right_angle_bend_on_rf` / `rf_line_z0_error_pct` / `antenna_min_distance_to_other_rf_mm` | 6 条 P3 | 哪根线是 RF / 天线，目标阻抗是多少 | `facts=` + 叠层 |
| `diffpair_gap_varies` | `layout.diffpair_gap_constant` (P3) | 哪一对是差分对 | `facts=` |
| `crystal_has_guard_ring` | `layout.crystal_guard` (P4) | 地守护环算不算（几何可推，未做） | measure 欠账 |
| `min_mask_expansion` | `PCB.MASK.EXPANSION_MIN` (P0) | 阻焊开窗相对焊盘的扩展量 | measure 欠账（要读阻焊层几何） |

`board_rule_audit` 的 `facts=` 通道就是给这张表准备的：**谁有那份意图，谁填**。
不填不是失败，是 `undetermined`——但 `undetermined` 永远不计入 pass，也永远不冒充"通过"。

### 5.3 被真板否掉的写法

- **"P0 用目录惯例"**：被 6 块量产板否掉，改成只用厂商库。
- **"丝印细 = 造不出来"**：被 6 块板否掉，降 P4（板厂不会因为丝印细拒单）。
- **"间距类判据用 bbox 就够"**：被 `openair-max` 的 0.0 否掉，改成 bbox 只做剪枝、距离用精确几何。
- **"下界不能当读数"**：被自己的 P0 层否掉——`min_copper_to_edge` / `min_th_hole_gap` 常常只给
  下界，弃用会让整个 P0 层永久 `undetermined`。改成：下界已满足 `>=` 限值即判 pass 并标
  `measured_from: "lower_bound"`；下界已超 `<=` 限值即判 fail。证据是"至少这么小"，不是"大概这么小"。

## 7. 状态门已经接到写工具上（0.0.131）

规则能判"这块板能不能造"，状态门判"现在能不能动它"。门在 `ruleset/precondition.py`，
由 `edit/plan.py` 的 `propose` 与 `apply_plan` 各跑一次，六条检查全部机器可裁决：

| 检查 | 判什么 | 不满足时 |
|---|---|---|
| `rules_baseline` | 规则集能加载，且每条阻塞规则（P0/P1/P2）都有来源、每条 fab 限值都有原文引文 | 拒绝 |
| `drc_engine` | DRC 引擎在不在（kicad-cli） | 找不到 → 拒绝；`options.engine=false` 是调用方自己的开关，只记为未定，不覆写契约 |
| `outline_known` | 板框存在且闭合，所以"离板边太近"是个事实 | 落铜时拒绝；只动丝印/机械层时降为未定 |
| `mech_unchanged` | 本次计划没有偷偷改 Edge.Cuts | 拒绝，除非显式 `allow_edge_changes=true` |
| `clearance_no_worse` | 本次计划没有把不同网络铜拉到 0.2 mm 以内 | 拒绝（**增量判据**，见下） |
| `process_declared` | P0 限值有没有可对照的工艺声明 | 只报，不判，且明确不是 pass |

三处设计要点：

1. **增量而非绝对**。`clearance_no_worse` 拒绝的是"这次计划新造出来的"贴近对，
   不是板子上本来就有的。真板随手就能找到 0.1 mm 的既有对，要求"先修好历史才许编辑"
   会让门在最需要编辑的板上失效。
2. **propose 与 apply 跑同一份数**。propose 把 `outline` / `clearance_after` /
   `clearance_before` 存进 `preconditions_input`，apply 直接复用复判；只有
   `rules_baseline` 与 `drc_engine` 在 apply 时重读（规则文件与引擎可能在两次调用之间变）。
   门与它守的那份提案因此不会给出两个说法。
3. **关闭开关 = 行为零变化**。`options.preconditions=false` 时回复里连
   `preconditions` 键都不出现——一个没跑过的门不能看起来像跑过并通过的门。

拒绝时抛 `PRECONDITION_NOT_MET`，`extra.preconditions` 带完整六条读数；
`apply_plan` 的文案是 `refusing to write: <检查名>: <原因>`。

另外 `board_fab_package` 加了 DRC 门（默认开）：出包前对**这个文件**跑一次
`kicad-cli` DRC（`--refill-zones`），有 error 或未连通项就 `FAB_REFUSED_UNCLEAN`
拒绝出包，warning 只记录。`drc_gate=false` 只跳过检查，不会把脏板变干净。

端到端实测（`pic_programmer` 官方 demo）：从 (100,-120) 往 (112,-120) 加铜被
`refused_at_clearance_no_worse` 拒（0→3 对 <0.2 mm，最紧 0.0 mm）；(200,-130)→(210,-130)
五门全过并写入成功（`gates_passed` 含 `bytes_written`/`drc`/`engine`/`postconditions`/`token_identity`）。

规则只会说"不许"，画板需要一个**目标**。`board_design_baseline` 把语料量一遍给出 p10/p50/p90。

**语料只留真正造得出来的那批**：每块板按**它自己的叠层**声明工艺（层数从 stackup 数出来，

三条写死的口径：

1. **`blocks_nothing`**：这段永远不拦写、不给 pass，落在中间 80% 之外只说明"和这批板不同"。
2. **`marginal` 与"真违规"分开报**：差 ≤0.01 mm 记为 `marginal`——仍然算 P0 不合格、仍然被剔出语料，

3. **`lower_bound` / `unknown` 不当真值**：搜索窗内没有更近的对时给的是下界，带 `floor_values`；

语料取不到时报 `CORPUS_NOT_FOUND` 并列出试过的目录——不许用两块板凑出一组"档位"。
`only_buildable` 默认 **false**（全部 18 块），显式打开才只用这 13 块；`suggested` 段给起点值，
写死被 P0 限值、电流与工艺压过。

## 9. 逐段加宽：线宽不是板级一个数（0.0.135）

`board_design_baseline` 给了区间（0.15 / 0.35 / 0.80），但**没有哪一段线可以按 p50 加宽**——
能不能加宽是这一段自己的几何事实。`board_width_ladder`（只读）按到**异网铜**（走线含弧线、
焊盘、过孔）的真实距离逐段算 `max_width_mm`，并把结果分组装进 `set_track_width` 的 `uuids`。

天空星实板（862 条走线 = 705 `segment` + 157 `arc`，全部 0.15 mm）实测：

| 加宽后线宽 | 条数 |
|---|---|
| 0.15（一格都没让） | 805 |
| 0.204 | 1 |
| 0.25 | 3 |
| 0.30 | 37 |
| 0.50 | 3 |
| 0.60 | 13 |

**只有 57 条让得出位置**，其余 805 条在 0.15 mm 上已经贴着邻居。这不是工具失败，是这块板的密度：
它的 0.15 mm 走线正是走在 0.15 mm 间距的相邻焊盘之间，`clearance_mm=0.2` 下一点余量都没有。

三条口径：

1. **`clearance_mm` 必须传 0.2**，不能取项目里的 0.15。`propose` 的状态门
   `precondition.clearance_no_worse` 用的就是 `CLEARANCE_FLOOR_MM = 0.2`，拿 0.15 算出来的
   「刚好合规」计划会被自己的门拒（实测：59 对 vs 110 对 <0.2）。
2. **弧线也是走线**。`_track_nodes` 必须 `items("segment") + items("arc")`，否则 157 条弧线
   在加宽/改宽的选中器里整个消失，报 `SEGMENT_NOT_FOUND`。
3. **加宽完必须官方重填铺铜**。不重填时新铜与旧填充区之间是 0.0000，实测会多出 **66 条**
   假 clearance 违规；`kicad-cli pcb drc --refill-zones --save-board` 之后回到 123 条基线。

## 10. 逐孔放孔：过孔尺寸是逐孔的，不是整板的（0.0.135）

同一块板 **201 个过孔全是 0.45/0.25**。想整板抬到 0.5/0.3 是几何上做不到的：
0.60 mm 间距的扇出（PE2/PE3/PE4/PE5/PE6 那一排）里，0.45 直径正好给出 0.15 铜间距。

`via_room`（只读，`house_style.py`）逐孔给出四个约束里最紧的那个：

| 约束 | 说明 |
|---|---|
| 异网铜间距 | 孔 ↔ 异网走线（弧线用折线）/焊盘/过孔，阈值取 `max(显式, 双方 netclass)` |
| **孔壁间距** | 孔 ↔ 孔，**不分网**——钻文件里两个孔挨太近就是一个孔，项目限值 `min_hole_to_hole = 0.25` |
| 焊盘钻孔 | 孔壁穿到焊盘钻孔里 |
| 环宽 | `size - drill >= 2 * min_annular_width(0.1)` ⇒ 钻 0.30 的孔尺寸至少 0.50 |

铺铜**不做约束**（`ZONE_FILLER` 会绕开外来铜），这是刻意的：拿填充区当障碍会把上限锁死在当前值。

实测（`clearance_mm=0.15`）逐孔上限：最大 1.90 mm，p50 0.65，**7 个孔钉在 0.45**
（5 个在 0.60 扇出里、1 个被走线 `$1N4756` 卡、1 个离 `U1.28` 只有 0.10 mm）。
孔壁最近间距 **0.35 mm** ≥ 0.25 ⇒ 钻孔可以从 0.25 抬到 0.30。

`clearance_mm=0.2`（与状态门同口径）后 `board_via_ladder` 的实际计划：

| 目标 | 孔数 |
|---|---|
| 0.50 / 0.30 | 110 |
| 0.49 / 0.28 | 2 |
| 0.46 / 0.25 | 1 |
| 留在 0.45 / 0.25 | 88 |

`board_apply` 四门全绿（`bytes_written` sha256 一致、`token_identity` 一致、113 条 postcondition
全部从文件重读通过、DRC 无新增），官方重填后 **DRC 仍 123 条、`clearance` 归零，逐类与改前完全一致**。

三条裁边规则是踩出来的，不是想出来的：

1. **等号也算被限**。目标 0.5000 落在上限 0.5000 上时若当"没被限"，就原样写 0.5000，
   而 0.5000 与邻居的浮点间距是 0.1999999…，门读成新违规。⇒ `want >= cap - 1e-9` 一律按被限处理，
   只对被限的值向下取整到 0.01。
2. **先裁尺寸再算环宽**。`ann_room = size - 2*min_ann` 必须用裁过的 size；用裁前的会写出
   `0.49/0.30`（环宽 0.095），被 DRC 拒 `annular_width wanted 0.1, got 0.095`，整个 plan 回滚。
3. **环宽相等不裁**。`0.50/0.30` 合法（恰好 0.10），`0.50/0.29` 是把合法值裁成怪数。

## 11. 泪滴：只加在放得下的拐角（0.0.135）

参考板有 763 个泪滴，天空星 0 个。`add_teardrop`（`curve=false`，直边；`curve=true` 需要
`pad 内半径 > 半个线宽`，本板 `r == tw/2` 恒退化，报 `ARG_INVALID`）。

- 邻接判据必须是 **0.02 mm**，不是 0.3 mm：0.3 会把"路过但不连"的段算成本拐角的走线，
  直接报 `NO_TRACK`。
- `length` 从**焊盘中心**量，所以触角对小焊盘够、对大焊盘不够（`B1.1` 宽 2.97 mm）。
  `postcondition` 要求 `reach > r*1.05`，用 `length = r + max(0.12, 0.8*tw)` 才全部满足
  （231/231 verified）。
- 第一轮 231 个拐角全上：DRC 新增 **13 条**（3 条 `shorting_items` + 10 条 clearance 0.095/0.1/0.022）。
  按违规坐标映射到最近的 pad（board 的 y 是 DRC 的 y 取负），删掉 **10 个** op
  （`D4/D5/D6/D7/D8.1`、`U1.12/U1.13`、`U5.1/U5.2`、`B1.1`）后 **0 新增**，实写 **221 个**。
- 官方重填后 **DRC 123 条 = 基线**（96 `lib_footprint_issues` + 27 `silk_over_copper`，clearance 0）。
- `unconnected_items` 从 47 变 49，逐对核过：**不是新的断网**，是同一批 4 处既有断点换了报告锚
  （原来报"焊盘 ↔ 8.0 mm 走线"，加了泪滴后报"焊盘 ↔ 0.85 mm 走线"），另有 1 对重复上报。
  这块重建板本来就有 47 处未连通（它没有原板的布线数据），泪滴既没修好也没弄坏它们。

### 登记一个假绿：engine 门不重填铺铜就比 DRC

`board_apply` 的 engine 门在"扩铜撞铺铜"场景下**没有**报出新增违规（`_apply1.json` 里
`identical:false` 却没有 clearance 差异结论）。根因：门拿来比较的两次 DRC 有一次没重填填充区，
新旧填充区之间的 0.0000 gap 让"新增"这个判据本身不可比。

在采用 `--refill-zones --save-board` 作为固定口径之前，**加了铜之后必须自己重填再跑 `board_drc`**，
不要相信门的"没新增"。**0.0.136 已按第二种口径修掉，见第 12 节**——注意结论不是"门不够严"，
而是"DRC 结构上给不出这个答案"。

## 12. 铺铜为这次编辑让出了多少（0.0.136）

第 11 节登记的假绿，修法不是把门调严，而是换量。**重填后的铺铜永远靠"把自己挖掉"来满足
clearance**，所以只要板上有 zone，`new_blocking_total == 0` 就是构造性成立的：再严的 DRC 也
问不出"铺铜被动了多少"。能问出来的是面积。

- `engine.drc(..., save_to=)`：`--refill-zones --save-board` 写进 scratch 副本再拷出，
  输入文件仍然只读；不带这个参数时行为逐位不变。
- `gates.drc.pour`：逐 zone 给 `before_mm2` / `after_mm2` / `delta_mm2` /
  `pour_gave_up_mm2` / `pour_gained_mm2`，`decision` 句里写明"铺铜被重塑了：整体 ±X mm²
  （GND@F.Cu +5.32, +3V3@F.Cu −3.18）"。
- `gates.drc.unconnected`：`before` / `after` / `delta`，并写明**这是计数不是判词**。

三条必须先量再写的口径：

1. **同一文件连续重填 3 次，四个 zone 的面积逐位相同（delta 全 0）**。第 12 节这条是它成立
   的前提：一个对自己都会漂的量不能当判据。对照之下 `unconnected` 的**条目集合**在两次
   重填之间会变（2 对 zone-zone vs 13 对，总数都 49），所以它只报计数。
2. **孔环绕向是假设，不是事实**：shoelace 求和取**绝对值**（sky_star 四个 zone 全为负，
   说明 KiCad 统一顺时针写铜），并逐 zone 校验"铺铜不可能大于自己的 outline"。不通过就
   `comparable: false`、`zones_unusable: [...]`，**不给数**——宁可没数，不给错数。
3. **面积 = 各 `filled_polygon` 环面积之和**，孔必须反向绕；第 2 条就是抓这件事的闸门。

真板实测（`examples/sky_star`，把一条 1.6 mm 的 GND 走线加宽到 0.60，它横穿 +3V3 铺铜）：

| 读数 | 值 |
|---|---|
| DRC 违规 | 123 → 123（0 新增，正如上面说的是构造性成立） |
| `pour` GND@F.Cu | 251.90 → 257.22 mm²（**+5.32**） |
| `pour` +3V3@F.Cu | 1767.29 → 1764.11 mm²（**−3.18**） |
| `pour` 整体 | **+2.14 mm²**，`pour_changed: true` |
| `unconnected` | 49 → 49（`delta: 0`，不构成判词） |

GND 涨、+3V3 跌是可解释的：GND 走线加宽后自己在 GND 铜里，而它占掉的空间从 +3V3 铺铜里
扣；整体为正说明还顺带接回了原本被丢弃的孤岛。这三个数在 0.0.135 之前一个都没有。

测试：`tests/test_pour_delta.py`（6 条），最难的两条是"同一块板两次必须正好 0"和"铺铜比自己
的 outline 还大必须拒答"。

## 13. 去耦距离量的是铜走的路，不是焊盘之间的直线（0.0.137）

P1 里两条一直 `undetermined` 的去耦规则（`layout.decoupling_distance` /
`layout.decoupling_same_layer`）现在有测量了，但**其中第一条只给数、不给判词**，原因见下。

### 13.1 量什么：按网络的铜路径

`measure` 现在为每条网络建一张**分层铜图**：走线（含弧线的折线化）、过孔（跨层边）、
焊盘（锚点作为节点，任何落在焊盘多边形内的线端点或过孔都与它相连）。节点用
`(layer, x*1e4, y*1e4)` 量化，所以文件里 `-95.10000000000198` 和 `-95.1` 是同一个点。

- `decoupling_max_distance_to_pin_mm` = 电容的某个焊盘 → 同网络上**多脚器件（≥3 脚）**
  焊盘的最短铜路径，逐电容取最有利的那个焊盘，再对全板取最大。证据等级仍是 L0
  （只读文件），但量的是**电流要走的路**，不是穿过板材的直线。
- `decoupling_via_in_path` = 同一张图把**过孔边删掉**再走一遍：某个焊盘对在那个子图里
  到不了，说明这条连接**不可能不换层**。

### 13.2 为什么不给判词：分母不是规则要的那批电容

规则说的是"去耦电容"，而板文件里只有"C 开头的位号"。自动筛出来的是**所有通过走线连到
多脚器件的电容**，里面混着开关消抖电容、滤波器电容——它们本来就不该在 3 mm 内。把这样的
数字判成 pass/fail 就是把未知洗成决定。

所以现在的行为是：**数照给，判词不给**。检查项里 `state: undetermined`、
`measured: 50.75`、`measured_state: fail`、`reason` 写明"这批分母不是去耦电容，最坏的是
C9.2→U1.49"。调用方自己知道"哪个电容服务哪个引脚"时，把
`facts={"decoupling_max_distance_to_pin_mm": 2.1}` 传进 `board_rule_audit`，这条就按
它判（`facts` 覆盖测量值时 cap 自动让开）。

### 13.3 真板读数（`examples/sky_star`）

| 读数 | 值 |
|---|---|
| `decoupling_max_distance_to_pin_mm` | **50.75 mm**（C9.2 → U1.49，网络 `$1I8749/$2N1200`） |
| 该网络铜总长 | 54.09 mm（所以 50.75 是绕行后的真实长度，不是图算错） |
| 有铜路径的电容 / 全部电容 | **9 / 27** |
| `decoupling_via_in_path` | **true**，1/9（C9 在无过孔子图里到不了） |
| 无路径的 18 个 | 全是 GND / +3V3 上的电容：那两个网络由**铺铜**承载，文件里没有走线可量 |

这 18 个不是"通过"，是"这条路不存在可测量的对象"——它们单独计数并在 `note` 里点名。

### 13.4 反假绿对照（`tests/test_decoupling.py`，8 条）

- 铺铜承载的网络**必须**报"没有路径"，不许把 0 距离直线当答案；
- **两脚器件不是被去耦的引脚**（1 mm 外的同网电阻不能把 10 mm 的数洗成 1 mm）；
- 过孔在网络上但不在实际路径里 ⇒ 规则仍 pass（"有 via"和"必须过 via"是两件事）；
- 单面 SMD 焊盘从 B.Cu 侧到不了 ⇒ 必须报被迫换层。

判词这边：`undetermined` + `measured_state` + 没有 `margin`（被 cap 掉的检查不许带判决
边际）；调用方传值后 `pass`/`fail` 与 `margin` 都回来。

## 14. 参考平面：栅格只负责筛，0.02 mm 的精确读数才负责判（0.0.138）

### 14.1 这条规则问的是"回流有没有断"

`layout.reference_plane_continuous`（P1，Critical）问的不是"两层之间有没有铜"，
而是**信号走线底下那一段回流铜是不是一整片**。判据只有一种形态：走线在中心线上采样，
出现"未覆盖 → 覆盖 → 未覆盖"的**内在空档**（两端都踩在铜上）就算跨分割；
只有一端未覆盖的不算——那是"跑到铺铜边缘外"，性质不同，单独计数。

### 14.2 为什么必须两遍：栅格会给好板子造出缺口

第一遍用 0.2 mm 扫描线栅格（`_raster`，even-odd，所有填充多边形一起算，所以洞读成洞）
把"不是全程覆盖"的走线筛出来；第二遍对**每一条**被筛出来的走线，用 0.02 mm 步长的
精确 even-odd 射线法（`_Scan`，边界按 1 mm 分带索引）重读，只有重读同意的才上报。

这一层不是保险，是**必须**的：在 sky_star 上第一遍报了 27 条，重读掉了 2 条——
都是走线中心线离铺铜边界不到 0.1 mm 的情形，而那正是 0.2 mm 栅格的分辨率极限。
把"边界附近的半格"当成"缺口"，就是在一张好板子上凭空造出 25 处跨分割。

反过来，栅格还可能**漏**：比 0.2 mm 更窄的缺口，如果整条走线其余部分都被覆盖，
第一遍看不见。这个上限写在 `method` 里，不假装没有。

### 14.3 真板读数（`examples/sky_star`，1.0 s）

| 层 / 参考层 | 跨分割走线 | 内在空档最宽 |
|---|---|---|
| F.Cu over B.Cu | **27** | **6.98 mm**（`$1I8749/$2N1200`，去耦网络） |
| B.Cu over F.Cu | **92** | **5.74 mm**（同一网络，横向 22.6 mm 那条） |
| 合计 | **119 / 862 条** | — |

典型的空档剖面（B.Cu 那条 22.6 mm 直线）：
0.50 → 2.04 → **5.74** → 0.20 → 0.22 → 0.22 → 0.56 → 0.46 mm。
空档之间那些 0.2~0.6 mm 的"铜岛"是对面层垂直走线的残条——也就是这条
信号的回流被一串垂直走线切成了碎片。这正是两层板最典型的回流问题，不是量错了。

两处独立读数相互印证：

- 同一批走线，用另一个实现（`G.point_in_polygon` 逐环奇偶，不走栅格）重测，
  5.74 / 4.04 / 3.64 mm 等读数逐位一致；
- F.Cu 那 2 条被栅格误报的走线，重读后是 0 个未覆盖采样 ⇒ 不报。

### 14.4 判词现在带证据

判 fail 的检查项里直接带 `evidence`（"119 track(s) …；最宽的是 … 6.98 mm"）
和前 8 条 `examples`（网络、层、参考层、未覆盖长度、起点坐标）。规则库这边只多了一行
接线：`m[fact]["where"]` 与 `examples` 进检查项，没有测量时不出这两个字段。

### 14.5 反假绿对照（`tests/test_reference_plane.py`，7 条）

- 实心铺铜底下走线 ⇒ **不报**（而且 `examples` 必须为空）；
- 4 mm 的洞，走线进洞再出来 ⇒ 报，且 `uncovered_mm ≈ 4.0`；
- 0.4 mm 的洞（两个栅格格宽）⇒ 仍要报；
- **贴着铺铜边界 0.05 mm 走的走线 ⇒ 不许报**（sky_star 误报的原型，栅格说没覆盖、
  重读说是铜）；
- 走线跑出铺铜边缘 ⇒ 只进 `note` 计数，不算跨分割；
- 层序拿不到（无 stackup 且不是两层）⇒ `undetermined`，理由写"哪层是参考层未知"；
- 板上没有铺铜 ⇒ `unmeasurable`，理由写"没有参考平面可跨"。

## 15. 回流过孔与电源线宽：一条只量不判，一条只量一半（0.0.139）

这两条规则（P1 的 `layout.layer_change_return_via`、`layout.power_trace_width`）的共同点是
**要判就必须知道板文件里没有的东西**。所以这一轮把"量"这一半做完整，把"判"这一半写成
显式的闸门，而不是替调用方猜一个数。

### 15.1 哪个网是回流网：从铺铜推导，不从网名推导

`_pour_nets(board)` 取非 keepout、且带 `filled_polygons` 的 zone 的 net。理由很直接：
**一块板在哪张网上铺铜，就是在拿那张网当回流路径**，不管它叫 `GND`、`VSS` 还是 `AGND0`。
测试里故意把回流网命名为 `VRAIL`——如果实现里硬编码了 `GND`，那条用例直接空转通过。

sky_star 的推导结果是 `{+3V3, +5V, GND}`：这块板是两层板，+3V3 与 +5V 也都铺了铜。
所以"回流过孔"在这一块板上指**铺铜网上的任何过孔**（54 个），而"信号过孔"是
没有铺铜的网上的过孔（147 个）。

### 15.2 读数

| 项 | 值 |
|---|---|
| 换层无回流过孔 | **146 / 147**（1.0 mm 门槛） |
| 最坏一条 | `$1N4905` at (131.57, -88.49)，离最近回流过孔 **13.255 mm** |
| 次坏两条 | `PC4` 12.761 mm、`PB10` 12.544 mm |
| 电源线宽（铺铜网最窄段） | **0.15 mm**（GND at (141.47, -116.00)） |
| 铺铜网上有走线的 | 2 个网 / 18 条走线 |
| 只有铺铜、没有走线可量 | `+3V3`（进 `note`，不进数字） |

### 15.3 为什么不把 146/147 判 fail

规则原文问的是 RF 与快速信号在换层处的回流过孔。**板文件里没有"哪些网是快的"**
—— 这是一块 GPIO 开发板，146 个换层过孔里绝大多数是 GPIO 排针的扇出，本来就该走
内部信号，不该每个都配地孔。把它判成 fail，就是在一块已量产、工作正常的板上
制造 146 条"缺陷"，属于把未知洗成决定。

所以这一条走 cap：`state = undetermined`、`measured = 146`、`measured_state` 保留、
**去掉 `margin`**，并在 `reason` 里写明分母是"population"（分不出 RF 与 GPIO）。
调用方知道自己的板子上哪些网是快的，`facts={"layer_changes_without_return_via": 0}`
一给就判 pass —— cap 自动让开。同一套机制在 0.0.137 的去耦两条上已经用过。

### 15.4 线宽：量的是下界，限值不在这个工具里

`power_trace_width_mm` 取铺铜网里**最窄**的一段走线，理由见 §9：一条 2 mm 宽的轨
在 router 让开焊盘留下的 0.2 mm 脖子上照样是保险丝。sky_star 的 0.15 mm 是整块板
所有铺铜网走线里最窄的一段。

但"0.15 mm 够不够"取决于电流，电流不在板文件里。限值由 `_limit_width_for_current`
算，它要 `current_a` + `current_standard`（IPC-2221 的系数与 IPC-2152 差 3 倍以上），
缺任一个就拒答。实测三条路径：

| `facts` | 结果 |
|---|---|
| 不给 | `undetermined`，`reason` 含 `current_a` |
| `{"current_a":0.3,"current_standard":"ipc2221","copper_oz":1.0}` | **pass**，limit 0.0574 mm |
| `{"current_a":2.0,"current_standard":"ipc2221"}` | **fail**，`margin` 0.6359 mm |

这一条与 15.3 的区别：回流过孔是**分母错**（不知道哪些网是快的），线宽是**限值缺**
（知道宽度、缺电流）。两种情况都输出 `undetermined`，但一个 cap 一个拒答，原因不同。

### 15.5 反假绿对照（`tests/test_return_vias.py`，10 条）

- 过孔离回流过孔 0.4 mm ⇒ 不计数；5 mm ⇒ 计数且 `nearest_return_via_mm ≈ 5.0`；
- 回流网叫 `VRAIL` ⇒ 照样认（证明不硬编码 `GND`）；
- 板上没有铺铜过孔 ⇒ 拒；板上没有铺铜 ⇒ 拒（"没有参考平面可跨"）；
- 0.2 mm 与 0.5 mm 两段走线 ⇒ 报 0.2 mm（最窄段才是数字）；
- 同板 0.1 mm 的信号线 ⇒ 不参与（不是铺铜网）；
- 某个网只有铺铜、没有走线 ⇒ 进 `note`，不进数字；
- 所有铺铜网都没有走线 ⇒ 拒（"量不到任何电源走线"）；
- cap：`state == undetermined`、`measured == 1.0`、**没有 `margin`**、`reason` 含 "population"；
  `facts` 给 0 ⇒ `pass`；
- 线宽：不给电流 ⇒ `undetermined` 且 `reason` 含 `current_a`；给 2 A ⇒ `fail` 且 `margin > 0`。

## 16. 器件间距读的是画出来的轮廓，而"相接"不是"重叠"（0.0.140）

### 16.1 bbox 会把成品板判成违规

器件碰撞这条规则原先只有 bbox。bbox 在每个角上都比 courtyard 大，于是 KiCad 的
`pic_programmer`（2 层、已量产）上，P3 与 C7 被报成 0.295 mm × 6.6 mm 的重叠，
而它们**画出来的轮廓**相距 2.05 mm。一条在成品板上凭空造出碰撞的规则，比一条
什么都不说的规则更坏。

现在 `courtyard.contours` 是**板空间里的闭合轮廓**：`fp_rect`/`fp_poly`/`fp_circle`
直接给环，`fp_line`/`fp_arc` 首尾相接的链由 `_chain` 合成环。间距用精确多边形距离。
只有**一个都画不出闭合环**的器件才退回 bbox，而 bbox 只作候选（`undetermined`），
从不出判词。

圆的那条曾经读成"中心/边缘"，于是半径变成 √2 倍、还错位到角上：一个 1.0 mm 的
安装孔会跟 2.8 倍半径内的一切碰撞。测试 `test_a_circle_courtyard_keeps_its_radius`
把它钉住。

### 16.2 轮廓是笔的中心线，不是墨

库统一用 0.05 mm 画 courtyard。把 stroke 半宽外扩到轮廓上，每一对 flush 摆放都会
凭空重叠 0.05 mm——royalblue54L_feather 27 对、stickhub 64 对全部变成碰撞。KiCad 的
courtyard 判的是闭合多边形，线宽只是显示属性，所以轮廓取中心线。

### 16.3 相接 ≠ 重叠：`_interiors_meet`

`dist_polygon_polygon` 对"贴边"和"真重叠"都返回 0，但判词完全不同。royalblue54L 和
stickhub 的库把 courtyard 画成器件外形，两个器件正好贴着摆（R5 的下边 IS R7 的上边），
0.0 mm clearance 在 KiCad 里是合法的。

三个判据，缺一不可：

1. 两条边**横截**相交（交点不在端点）；
2. 一个顶点**严格**落在对方内部（到边界距离 > 1e-6）；
3. 一条边的**中点**严格落在对方内部。

第 3 条是为"两个矩形共用两条边的延长线"准备的：U1 = [8,12]×[9,11]、U2 = [11,13]×[9,11]
真有 1×2 mm 的公共面积，可所有顶点都落在对方边界上、所有交点都在端点，判据 1、2
都看不见，而 U1 右边中点 (12,10) 确实在 U2 内部。flush 摆放里这个中点落在**边界**上，
不满足"严格内部"，所以第 3 条不会把贴边读成碰撞。

判据 3 漏判的后果只是"没报"，方向安全；造假失败的后果是拒绝一块成品板。

### 16.4 共线在浮点下不是 0：方向判据要带容差

royalblue54L 的 U2 右边落在 x = 150.68，C1 左边落在 150.67999999999998——纳米整数里
是同一个点，叉积却是 1.8e-13。严格的 `< 0` 把它读成"两端点在异侧"，于是判横截，
13 对 flush 摆放被报成碰撞。容差按**边长平方**缩放（叉积量纲是 mm²），实测 13 对 → 11 对。

### 16.5 反向对照（`tests/test_courtyard.py`，11 条）

| 场景 | 期望 |
|---|---|
| 间距 1 mm | `value 0`、`where` 含 `clears by` |
| 中心线贴合（14.0 摆位） | `value 0`、`touching == [{U1,U2}]`、`note` 含 `touch exactly` |
| 贴合但坐标差 4e-15（14.000000000000004） | `value 0`（浮点共线仍算贴合） |
| 真重叠 0.05 mm（13.95） | `value 1`（容差不吞真重叠） |
| 真重叠 1 mm（13.0） | `value 1`、`where == drawn courtyards overlap` |
| 四条 `fp_line` 接成环 | 照样能判重叠 |
| 圆 r=1.0 对邻居留 0.2 mm | `value 0`（半径不是 √2 r） |
| 轮廓不闭合 | `supports == undetermined` |
| 器件不画 courtyard | `supports == undetermined`（bbox 只作候选） |
| 两个都不画 | 也不是"一对"，`value 1` 但仍是 `undetermined` |

### 17.2 参考平面：成品板否证了这条判词

重写后 `_reference_plane` 取**铺铜面积最大的网**作回流网，断流门槛 1.0 mm。11/12 块
可测成品板都有 >1 mm 的跨缝（video 的 297 条虚警归零后仍剩跨缝）。一个缝隙只破坏
"快信号"，而板文件从不声明哪些网是快信号 —— 与 §15.3 的回流过孔同构。所以这一条
降级为 `CAP_FACTS`：`state = undetermined`、`measured` 与 `evidence` 保留、
`bands` 分档给出缝隙分布，调用方给 `facts={"signal_crosses_plane_split": 0}` 才判 pass。
