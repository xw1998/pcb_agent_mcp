# RK3506 核心板 —— 电源走线落铜、网络表顺序事故与两条读数口径

日期：2026-11-13　版本：0.1.11

本篇只记两件事：**板子上真的出现了铜**（手工 45° 走线 + 官方铺铜），以及在把一个 45×45、140 邮票孔、188 网的板子交给 KiCad 10 的过程中踩到的、会静默给出错答案的五条机制。

板上一根走线都不是自动布出来的：`tools/route_som.py` 里 47 行 `TRACKS` / 41 条 `VIAS` / 2 块 `ZONES` 是逐条写死的坐标，`--audit` 是它的机械校验，`--route` 只把这张表翻译成 ops。

## 2 网络表必须在 footprint 之前 —— 70/140 个邮票孔丢网

**现象**：`pcbnew` 读 J1 只有 70 个 pad 有网；但 sexpr 里 140 个 pad 每一行都写着 `(net N "name")`。DRC 报 `shorting_items 4`、`holes_co_located 8`、`solder_mask_bridge 8`、`copper_edge_clearance +8`，全部指向 `<no net>` 的 J1 焊盘。

**排查**：`NetsByNetcode()` 里 code 1 显示的是 `/LCDC_D0`，而文件净表写的是 `1 = /+5V_IN` ⇒ 编号被重建过。逐层排除了重复 pad 号、重复 net 表、空格、`remove_unused_layers`、以及两条游离的 `(net 1 "/+5V_IN") (net 2 "/GND")`（这两条确实存在，删了，但不是根因）。

**根因**：板级子节点顺序是

```
… ['footprint',2], ['net',1], ['footprint',2], ['net',1], … ['net',159], ['footprint',1], ['net',5], ['footprint',8]
```

即 188 行净表被**散插在 45 个 footprint 之间**。KiCad 是在解析 pad 的那一刻查它**已经看到**的净表：条码在后、pad 在前，pad 就落成 net 0。后 8 个 footprint 的 pad 因为净表在它们之前反而正常 —— 所以坏的不是整块板，是"后面那些"，这就解释了为什么恰好 70 个（140 的一半）丢网。

**修法**：`_fixorder.py` 把板级所有 `(net ...)` 整体搬到 `title_block` 之后（按 code 0..n 排序并断言连续唯一），其余子节点保持原序。修后 `nets 188 / fps 45 / J1 140 withnet 140 / pads without net 0`，铺铜面积不变。

**但这条修法在 KiCad 自己保存过一次之后就没有对象了**：0.1.11 的板文件里**一个板级 `(net ...)` 节点都没有**，而 `pcbnew` 照样读出 188 个网。原因是 KiCad 10 由 pad 反推网络，板级净表是可省的冗余。这件事直接推翻了两个读数的写法：

- `route_som.pads()` 原来从板级净表建 `code → name`，净表没了 ⇒ 每个 pad 的 net 都是空串 ⇒ **每一条走线的每一个端点都被报成 loose end**（142 段全线飘红）。
- `route_som.audit()` 的 "net is on the board" 检查同样只读一个地方 ⇒ 报 `boards_nets 0`，并把 17 个网判成"不在板上"。

两处都改成**两个地方都读**：pad 上的 `(net "/NAME")`（单原子，KiCad 10 写法）与板级 `(net 12 "/NAME")`（双原子，我们自己的 writer 写法）。`check()` 的 `nets` 也从 `len(board nets) - 1`（净表没了就是 **-1**）改成"按 pad 去重计数"。

> 口径：**一处信息能存在两个地方，就不能只读一个地方，并且不能把"没读到"当成"没有"。** `-1` 这种数就是它在报警。

## 3 KiCad 10 写回会丢掉 board 级 `net_class`，规则要进 `.kicad_pro`

`pcbnew.SaveBoard` 之后文件里 `"net_class" in txt == False`。而 DRC 的最小线宽/最小过孔/严重度是从**工程文件**读的，不是从板。所以 0.4/0.2 的过孔必须在三处同时成立：

1. 板内 legacy `net_class Default`（`via_dia 0.4 / via_drill 0.2`），保证我们自己 writer 出的板自洽；
2. `rk3506_som.kicad_pro` 的 `net_settings.classes = [{name Default, clearance 0.2, track_width 0.2, via_diameter 0.4, via_drill 0.2, …}]`；
3. `rk3506_som.kicad_pro` 的 `board.design_settings.rules`：`min_via_diameter 0.40`、`min_through_hole_diameter 0.20`、`min_via_annular_width 0.10`、`min_clearance 0.2`、`min_track_width 0.2`、`min_copper_edge_clearance 0.30`、`min_hole_to_hole 0.25`。

只改 (1) 会得到 `via_diameter 44` + `drill_out_of_range 45`：via-in-pad 是 0.40/0.20，而 DRC 默认 `min_via_diameter` 0.5、netclass 0.6/0.3。**两处必须同时改，少一处就是 45 条违规。**

顺带一个坑：`_refill.py` 原来有个"补回 net_class"的分支 `txt.find('(net 0 "")')`，在 KiCad 10 的板子上恒返回 -1 ⇒ `assert` 会在**一块健康的板上**停住。已改成三分支：有就跳过、有旧式净表就补、两者都没有就**去工程文件里核实 classes 存在**，不在就报错。断言不该断言一个对方从来不写的节点。

## 4 半孔焊盘必然违反 copper_edge_clearance

140 个半孔圆心落在 x = 0 / 45 的板边上，盘半径 0.425 ⇒ 必然越界 0.425 mm。任何正间距都不可能满足。处置：

- `rule_severities.copper_edge_clearance = "ignore"`（先承认这条规则在这块板上不适用）；
- **同时在 `route_som.audit()` 里补一条等价校验**：对每条 TRACK 的每条（斜切后的）边按 0.05 mm 步长采样，采样点若不在任何 J1 焊盘矩形内，则要求 `min(px - w/2, 45 - px - w/2, py - w/2, 45 - py - w/2) >= 0.30 mm`。

这就是"降级一条规则必须补一条代码级校验"的做法：被 ignore 的那条规则原本能抓到的问题（走线贴板边），仍然会被抓住。

## 5 5V 入口支线只能是 0.25 宽

四条 5V 支线要从 x = 43.93 的竖干接进 E 边的半孔。半孔盘的铜从 **44.575** 起，板边在 **45.0**，铜要留 0.30 ⇒ 支线中心最东只能到 44.725 - w/2。实测三档：

- `w 0.90 @ 44.60`：东缘 45.05，越界；
- `w 0.70 @ 44.45`：`audit` 报 loose end（44.45 + 0.35 = 44.80 尚未进入 44.575 起的盘铜……实际端点落在了盘的 x 范围外）；
- `w 0.25 @ 44.60`：铜 44.475..44.725，越界那 0.15 mm 已经在半孔焊盘内，被豁免条款吃掉 ⇒ audit PASS、DRC 0 新增。

数字是几何逼出来的，不是审美选的，写进表里的注释就是为了让下一个人不要"顺手加宽"。

## 6 斜切长度必须 ≥ 线宽，否则 45° 会被看成圆角

`chamfer()` 原来按 `CHAMFER = 0.30`（宽线 0.50）切角。在 0.60 宽的 3V3 干线上，0.30 的斜边**短于笔画宽度**，绘图时两端圆头盖过来 —— 放大到 115 px/mm 看图，读出来的是"圆弧过渡"，看不出 45°。这不是渲染骗人，是斜边比线宽还短时它本来就不构成一个"面"。

改法：`d = max(d, width)`，即斜边至少一个线宽长（普通断开拐角的做法）。60 条以上的转角随之重新排布，`assert_45()` 仍然全部落在 {0, 45, 90, 135}°，DRC 分型不变。

**连带**：斜切变长会**吃掉拐角附近的分支点**。C1 的 5V 支线原来从 `(29.20, 30.92)` 起，而 3V3…5V 干线在 `(29.20, 31.40)` 的转角现在从 y 30.90 就开始切 —— 支线端点落进斜切缺口内 0.02 mm，`audit` 报 loose end。修法不是把斜切改回去，而是让支线**从直线段离开**：`(29.20,30.50) → (28.82,30.88) 45° → (28.40,30.88)`，落点仍在 C1.1 盘的 y 范围内。

> 口径：**拐角一旦按线宽切开，任何"贴着角点"的分支都要重新验一遍**；0.02 mm 的差在图纸上不存在，在 DRC 里是悬空。

## 7 铺铜只认官方 ZONE_FILLER，DRC 只在重铺后算数

- 铜面由 `pcbnew.ZONE_FILLER(b).Fill(b.Zones())` + `pcbnew.SaveBoard` 生成，没有任何自写光栅。参数：`clearance 0.15 / min_thickness 0.10 / connect_pads solid / priority 0`。
- `route_som.check()` 的 DRC 口径改成 `E.drc(path, refill=True, project=<同目录 .kicad_pro>)`。不重铺时 `filled_polygon` 是空的，新加的走线到铺铜的距离按 0 算 —— **那个读数是错的，不是更严**：实测它会报 2 条"只在铺铜没铺时才悬空"的线端。
- `/GND` 铺铜从走线前 1918.321 降到 1891.837 mm²（被走线挖掉的部分）；`/+5V_IN` 23.776 与 `/+3V3` 150.486。
- `isolated_copper` 曾在 `/+5V_IN` 上出现 1 条：竖干 y 36.00..2.40 与铺铜 y 37.20..43.00 不相交 ⇒ 竖干起点改 `(43.93, 37.60)`，伸进铺铜里。
