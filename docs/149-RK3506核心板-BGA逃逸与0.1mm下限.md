## 2. 设计下限从 0.2 降到 0.1

U1 是 333 球 BGA，外围环节距 **0.5618 mm**，焊盘直径 0.25 mm ⇒ 球间隙 **0.312 mm**。在 0.2 mm 线宽下任何两球之间都放不下一根线（0.2 > 0.312 − 2×0.1 的可用余量口径下，单侧余量只剩 0.056 mm 且过孔无处安放）。这不是“放宽规则掩盖 DRC”，是物理能力：

- 改 `rk3506_som.kicad_pro` 的 `board.design_settings.rules`：`min_clearance 0.1`、`min_track_width 0.1`、`min_via_diameter 0.2`、`min_through_hole_diameter 0.1`、`min_via_annular_width 0.05`、`min_hole_to_hole 0.15`、`min_copper_edge_clearance 0.3`。
- 同时改 `net_settings.classes[0]`（Default）：`clearance 0.1 / track_width 0.1 / via 0.2 / drill 0.1`。
- 两处都要改：板上 legacy `net_class` 会被 `SaveBoard` 丢弃，规则只认 `.kicad_pro`。
- 代价核算：DRC 562 → 63（clearance 项），这是真实能力提升；剩下的 199 条 `via_dangling` 是“还没接线”。

## 3. `pitch/2` 事故（本轮最大的几何 bug）

逃逸过孔放在 4 球中心的 interstitial 位置。第一版把偏移写成 `p = pitch / √2`，结果是**每个过孔都落在斜对角那颗球的焊盘边缘上**——实测到 A3 球心只有 **0.233 mm**，而焊盘半径 0.125 + 过孔半径 0.1 = 0.225 mm，只剩 0.008 mm。

根因：球心到对角球心距离是 `pitch·√2`，但 interstitial 是**两条相邻边的中心**，偏移是 `pitch/2` 而不是 `pitch/√2`。改成 `p = pitch / 2.0` 后实测：

- `via_to_via_gap 0.3618 mm`（0.5618 − 0.2）
- `via_to_ball_pad_gap 0.1723 mm`（0.5618/2 − 0.125 − 0.1）
- `stub_w 0.1`、过孔 `0.2/0.1`

`0.1723 mm` 在 0.1 mm 规则下有 0.0723 mm 余量，是刀锋但合法。这也顺带解释了内层容量：内层（In2/In3/In4/B.Cu）只有过孔没有 SMD pad，过孔之间净空 0.362 mm ⇒ **每道缝只能过一根 0.1 mm 线**，中缝余量 0.031 mm。

## 4. `unconnected-(U1-NC-Pad1G2)` 让后置校验失败

`apply_plan` 一次成功落 834 op，但第一次尝试时 160/161 号 op 过不了 `postconditions`。原因：该球所属网络名是 `unconnected-(U1-NC-Pad1G2)`，名字里带**圆括号**，写入 pcb 后重新解析时与原文不一致（sexpr 圆括号被当成嵌套）。

修法：`plan()` 跳过 `unconnected-*` 与 `/NC_*`，单独计入 `stats["nc"]`（12 个）。不再靠转义字符串硬撑。

## 5. 段级过滤（把 `refused 52` 打到 0）

只做“过孔到球心/到 pad”的点级检查时，52 个球放不下——因为 stub 是一段线，它的**中段**可以穿过别的球心。补两条段级约束后归零：

- `_pt_seg(px,py,x1,y1,x2,y2)`：候选点到既有球心的距离（`SEG_BALL 0.30`）
- `_seg_seg(a,b)`：两段 stub 之间的最小距离，相交返回 0.0（`SEG_SEG 0.20`）

另外把候选表从“只 ring-1”扩成 `CANDS = [(step,sx,sy) for step in 1..3 for sx,sy in 四象限]`，先上后下，让 ring-1 被占的球往 ring-2/3 逃。

最终读数：`balls 429 / placed 417 / refused 0 / nc 12 / ops 834`。

## 6. `precheck_clearance_mm` 必须与规则对齐

`edit/plan.py:228` 的预检阈值取 `options.get("precheck_clearance_mm", 0.2)`；`ruleset/precondition.py:42` 的 `CLEARANCE_FLOOR_MM = 0.2` 只是 fallback。规则降到 0.1 后不同步这个参数，`clearance_no_worse` 会以 `tightest 0.0 mm` 拦下整批 op。落铜调用：

```python
apply_plan(..., confirm=True,
           options={"allow_new_violations": True, "precheck_clearance_mm": 0.1})
```

## 7. DDR 端点顺序：直线阶梯在物理上不可能

按 U1 侧 x 排序 vs 按 U2 行主序排序，逆序数 **130/1225**。试遍 U2 的 8 种朝向（镜像 × 4 旋转）× 2 个扫向，最小逆序 **133**（`mir+1 rot90 sweep=col`、`mir-1 rot0 sweep=row`）。

结论：DDR 的 50 条线**不能**用单调阶梯扇出，必须分组 + 绕行。这是“满层平面 + 密集 BGA”的几何事实，不是布线器参数问题。

## 8. 丝印：位号统一移 F.Fab

0.562 mm 的 BGA 加 3 路 buck 让 33 条位号压焊盘、18 条压别的丝印。处理方式：

- 45 个 Reference 全部移到 **F.Fab**（可见），Value 移到 F.Fab 并隐藏 ⇒ `silk_overlap 18 → 0`。
- 压铜的 3 条图形（SW1 的拨杆 4 段 + U2 的 pin-1 圆点）移到 F.Fab ⇒ `silk_over_copper 3 → 0`。
- 板上改了封装就必须同步改库，否则 `lib_footprint_mismatch` 会一直报。本轮把 `Package_Switch_SMD_4.2x3.2-4P-P2.20_SKRPACE010.kicad_mod` 的 4 段拨杆与 `Package_FBGA-96_..._MT41K256M16.kicad_mod` 的 pin-1 `fp_circle` 一并改到 F.Fab，读数 **2 → 0**。

## 9. `lib_footprint_issues 34` 是假警报

隔离配置目录 `KICAD_CONFIG_HOME=_kc` 里没有全局库表，所有标准库封装（`Capacitor_SMD`、`Resistor_SMD`、`Crystal`…）都“找不到”。

修法：

```bash
cp ~/AppData/Roaming/kicad/10.0/fp-lib-table _kc/10.0/fp-lib-table
cp ~/AppData/Roaming/kicad/10.0/sym-lib-table _kc/10.0/sym-lib-table
```

读数 34 → 0。教训：任何“库问题”读数前，先确认 `KICAD_CONFIG_HOME` 里有全局库表，否则读到的全是隔离环境的空库。

另附：`_rawdrc2.py` 会把板拷到 temp 目录跑，连带丢掉 `fp-lib-table` 与 `lib/`，产生假 `lib_footprint_issues`（本轮先后看到 45 / 17 / 34 三个不同数）。准确读法是**在 `examples/rk3506_som/` 原地跑** `kicad-cli pcb drc`。
