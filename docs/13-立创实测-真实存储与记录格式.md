## 0. 三条被推翻的猜测

| 旧说法 | 实测 | 证据 |
| --- | --- | --- |
| `.epro` 里是 append-only 日志，同一对象多行，按 `ticket` 取胜 | 记录流是**普通快照**：一个 tag 一行，`LINE` 895 行就是 895 条走线；没有重复 id 需要回放 | 194 个工程里 `by_tag` 的 id 全部唯一（`test_epro.py` 的 `unique_arity` 用例复算） |
| 坐标是 0.01 英寸整数 | 坐标恒为 **mil**（0.0254 mm），且**带小数**（`475`、`632.795`、`4072.9432`） | 见 §2 单位证明 |
| 一次保存 = 追加成员 + 在 `project.json.pcbs` 里登记 | 一次保存 = **原地重写那一个 `.epcb` 成员**，其余成员与 `project.json` 字节不变 | 见 §1 两次保存的逐成员比对 |

## 1. 保存行为：逐成员比对两次相邻保存

同一工程、同一天、同一个人连续保存两次：

```
ProPrj_2.4G底板控制板_2025-03-14-17-03-57.epro
ProPrj_2.4G底板控制板_2025-03-14-17-08-57.epro
```

逐成员 sha256 对比结果：

```
129 个成员字节完全相同
  1 个成员变化：PCB/f780928032c54be2935ae6b2256fce39.epcb
                609,392 字节 -> 607,523 字节（变小）
project.json   完全相同
成员增删        0
```

⇒ 结论：**正常保存是原地重写一个成员**。上一版说的「新增成员 + 写进
`project.json.pcbs`」其实是另一种动作——用户**新建了一块 PCB 文档**（`pcbs`
列表随新建增长，保存不增长）。

这条事实直接决定了写路径的形状：`edit/epro_edit.py` 只重写一个成员，
并用六道闸门证明「除了它，其他成员与未被点名的行一个字节都没动」。

## 2. 单位：数字恒为 mil，标签只是显示单位

决定性证据（`RULE` 记录，标签写 `"mm"`）：

```
["RULE", id, "viaSize",          true, ["mm", 9.8425, 12.0079, 196.8504]]
["RULE", id, "trackWidth",       true, ["mm", 5, 10, 100]]
```

按 **mil** 读正好是人话：

| 字段 | 存的值 | 按 mil 解读 | 按标签 "mm" 解读 |
| --- | --- | --- | --- |
| viaSize[0] | 9.8425 | 0.25 mm | 9.84 mm（荒谬） |
| viaSize[1] | 12.0079 | 0.305 mm | 12 mm |
| viaSize[2] | 196.8504 | 5.0 mm | 197 mm |
| trackWidth | 5 / 10 / 100 | 0.127 / 0.254 / 2.54 mm | 5 / 10 / 100 mm |

旁证：走线宽度出现 `19.685 / 39.3701 / 78.7402 / 98.4252`，正是 0.5 / 1 / 2 / 2.5 mm；
过孔 `12.0078 / 24.0158` 正是 0.305 / 0.61 mm；板框在 mil→mm 下得到
190.0 × 124.5 mm、21 × 40 mm、46.35 × 66 mm 这种正常板尺寸，在 mm→mm 下得到「米」。

`CANVAS[3]`（`"mm"|"mil"`）是**用户的显示单位**，不是存储单位。写路径因此：
所有操作参数用 mm，唯一的换算点在 `epro_edit._mil()`（`mm / 0.0254`，保留 4 位小数，
整数写成 int 与厂商一致）。

```jsonc

["NET","$1N1089",null,null,1,null,0,null]
["COMPONENT","e0",0,1,3145,2255,0,{"Unique ID":"gge1",...},0]
["ATTR","e0e96",0,"e0",3,2120,3275,"Designator","T1",0,1,"default",45,6,0,0,3,0,0,0,0,0]
["PAD_NET","e0","1","$1N1089","ie72"]

["VIA","e725",0,"SWB","",3513.22,4072.9432,12.0078,24.0158,0,null,null,0,[]]
["STRING","e6509",0,4,6700,200,"电压调节","Helvetica",78.7402,...,-270,1,0,0,0]
```

### 3.1 各 tag 的 arity 与字段（实测，1000W 板为样本）

| tag | 条数 | arity | 关键下标 |
| --- | --- | --- | --- |
| `COMPONENT` | 187 | 9 | `[1]`id `[3]`层(1 TOP/2 BOTTOM) `[4]`x `[5]`y `[6]`旋转(度) |
| `ATTR` | 559 | 22 | `[3]`宿主 id `[5]`x `[6]`y `[7]`键 `[8]`值；键有 `Designator`/`Device`/`Footprint` |
| `PAD_NET` | 469 | 5 | `[1]`元件 id `[2]`焊盘号 `[3]`net `[4]`封装文档内的 PAD 对象 id |
| `PAD`（板级自由焊盘） | 271 | 27 | `[3]`net `[4]`层 `[5]`焊盘号 `[6]`x `[7]`y `[9]`孔 `[10]`形状 |
| `LINE` | 895 | 11 | `[3]`net `[4]`层 `[5..8]`x1,y1,x2,y2 `[9]`线宽 |
| `ARC` | — | 12 | `[3]`net `[4]`层 `[5..8]`端点 `[9]`sweep `[10]`线宽 |
| `VIA` | 125 | 14 | `[3]`net `[5]`x `[6]`y `[7]`钻孔 `[8]`外径（**恒为 1:2，且 [7]<[8]**） |
| `STRING` | 26 | 18 | `[3]`层 `[4]`x `[5]`y `[6]`文本 `[7]`字体 `[8]`字号 |
| `POUR` | 4 | 12 | `[3]`net `[4]`层 `[5]`flag `[6]`名字 `[8]`轮廓（**嵌套一层**）`[9]`[模式,n] |
| `POURED` | — | 6 | `[1]`id `[2]`pour id `[3]`0 `[4]`是否填充 `[5]`轮廓 |
| `FILL` | 18 | 9 | `[3]`net `[4]`层 `[5]`flag `[7]`[["R",x,y,w,h,rot,r]] |
| `REGION` | — | — | `[3]`层 `[4]`flag `[5]`禁布标志 `[6]`轮廓 |
| `POLY` | 59 | 8 | `[4]`层 `[6]`几何：`x,y,("L"|"ARC"),…` 或 `["CIRCLE",x,y,r]` |
| `LAYER` | 119 | 9 | `[1]`层号(int) `[2]`名字（`TOP`/`BOTTOM`/`OUTLINE`…）`[3]`显示名 |
| `NET` | 96 | 8 | `[1]`名字（第一条名字是空串） |
| `LAYER_PHYS` | — | 7 | 叠层相邻与铜厚（**没有介电厚度**） |
| `RULE` | 5 | 5 | `[1]`id `[2]`规则名 `[3]`启用 `[4]`[显示单位, 值…] |

**`POUR[5] / FILL[5] / REGION[4]` 不是距离。** 全库只出现 `0.2`（12,232 次）或
`1`（168 次）两个值 ⇒ 是标志位。因此适配器报 `clearance_raw` 并令
`clearance=None`，**拒绝**把它换算成 mm（换算出来会是一个假数字）。

### 3.2 板级 `PAD` 是自由焊盘，不是库封装焊盘

1000W 板有 271 条 `PAD` 记录（绝对 mil 坐标，例如 `x=186, y=4, hole=3.2mm,
layer=MULTI`），而它的 187 个元件共 732 个焊盘。`PAD` 记录**没有任何字段指向
`COMPONENT`** ⇒ 它们是板上的自由焊盘/定位孔/测试点。适配器单列为
`board.source["free_pads"]`，不与 `footprints[].pads` 混在一起。

### 3.3 焊盘与 net 的唯一联系：`PAD_NET`

`PAD_NET[4]` 是**封装文档内的 PAD 对象 id**。全库实测：

```
能对上封装文档的 PAD_NET 行：8159
其中 [4] == 该封装内第一个同号 PAD 对象：8149
其中 [4] ∈ 该封装内所有同号 PAD 对象：8159  ← 100%
```

剩下 10 条不是「第一个」的原因也查清了：通孔焊盘在封装里存了**上下两片**
（例如同一焊盘号有 `e176e3 / e176e14 / e176e16`），元件会为**每一片**写一行
`PAD_NET`，所以那 10 条指向第 2、3 片。

⇒ 写路径 `set_pad_net` 需要新增行时，按「封装文档里该焊盘号的**每一个** PAD 对象
各写一行」来做，而这个 id 是从封装文档里**读出来**的；读不到就拒绝
（`PAD_OBJECT_UNKNOWN` / `PAD_NOT_FOUND`），绝不编一个 id。

## 4. 容器与 SQLite 工程

`.epro` 是普通 ZIP；成员命名实测：

```
project.json
PCB/<uuid>.epcb
FOOTPRINT/<uuid>.efoo
SHEET/<uuid>/<n>.esch
SYMBOL/<uuid>.esym
BLOB/  FONT/  INSTANCE/  PANEL/  POUR/  SHEET/  FOOTPRINT/  PCB/
```

`.eprj` / `.eprj2` 是 SQLite（头 `SQLite format 3`），实测表结构：

```
documents(uuid, title, display_title, description, docType, dataStr,
          sheet_id, ticket, sort_ticket, created_at, updated_at,
          creator_uuid, schematic_uuid, project_uuid, image, parent_uuid)
coppers(path, project_uuid, dataStr, ticket)      -- PCB 数据在这里，path = <pcb_uuid>_0
texts(FONT)  resources(BLOB)  components  devices  boards  schematics
projects(ticket, g_ticket, boards, branch_uuid)   history_data(加密快照)
branches  project_structures(structure JSON)
```

**写路径明确拒写 SQLite**（`WRITE_UNSUPPORTED_FORMAT`）：一块板的行旁边就是
`projects.ticket / g_ticket`、按文档的 `ticket / sort_ticket` 与加密的
`history_data` 快照；一次不推进 ticket、不写 history 的 `UPDATE` 正是应用可以
静默判为「陈旧」的那种改动。报错是诚实的，写入会看起来像成功。
读可以：`adapters/__init__.detect_format` 认 SQLite，两份快速入门工程的
`.eprj2` 都能打开（`footprints 34 / pads 23 / tracks 98 / nets 18`，
板框 80×60 mm 闭合，`thick 1.6`）。

## 5. `.epro` 重打包的字节保真

`EproDocument.to_bytes()` 无参调用必须**逐字节等于输入**。这件事是有难度的：
`zipfile` 重写成员时会改 `external_attr`（0 → 0o600<<16）和 `extract_version`
（10 → 20）。所以未改动的成员按**原始字节区间**照抄，只有被改的成员重新打包头部。

194 个 `.epro` 全部逐字节通过。（附带修掉一个真缺陷：新增成员时 central directory
的 local-header-offset 字段是 index 16 / 字节偏移 42，早先写成 index 19 会越界。）

## 6. 几何口径（实测，含未定论的部分）

| 事实 | 结论 | 强度 |
| --- | --- | --- |
| 坐标单位 | mil，Y **不**翻转 | 强（§2） |
| 元件旋转 | `COMPONENT[6]` 度，顺时针为正 → 焊盘局部坐标按 `+angle` 旋转 | 强：60 个归档共 9874 个焊盘，54.1% 精确落在铜端点 |
| 底面元件 | 只镜像 `y`（`-py`），x 不镜像 | **弱**：35.1% 落点（`-x` 20.7%，不处理 32.2%）⇒ 只声明，不声称 |
| 未落点的 45.9% | 未布线焊盘没有铜端点可比对 | 解释成立，但不作为证明 |
| `["R",x,y,w,h,rot,r]` | 矩形填充，绕自身中心旋转，并置 flag | 中：读回后 bbox 与 DRC 一致 |
| `ELLIPSE` 焊盘 | 用 circle/oval 近似，差异写进 `pad_shape_note` | 声明而非声称 |
| 未闭合板框 | **不拟合假轮廓**：报 open chains、最近自由端距离、按实测边算 bbox | 设计决定 |
