# 33 `.subckt` 与层次展开：内置引擎自己拍平

## 33.1 为什么是「解析完再展开」，而不是「新写一个层次求解器」

到 `0.0.26` 为止，内置引擎的立场是**按名字拒绝** `.subckt` / `X`：能力差就如实说，把 deck 交给
ngspice 去跑（`docs/21` §21.6a）。这条立场没错，但它把「装了引擎」变成了使用子电路的唯一门槛，
而 `.subckt` 恰恰是真实工程里最常见的写法——运放、门电路、无源网络、参数化分压器全是子电路。

新增一条**层次求解路径**（自己的节点合并、自己的 MNA 装配）不是解法：那等于在同一份代码里维护
两套方程，两套的收敛判据还不一样，出错时没人分得清是模型错还是装配错。

所以选的是第三种：**照常解析，然后把层次拍平成一份平铺 deck，交给既有的求解器**。拍平之后
求解器看到的仍是它一直认识的那八种元件，收敛行为、温度缩放、`not_computed` 全部沿用，一行不改。
子电路因此变成**纯语法层的能力**，不进方程层。

一个副作用是关键的：既然拍平后得到的是一份普通 deck，那么「拍平对不对」就可以用
**同一份电路的手写平铺版本**来对账（§33.7）——这是不依赖任何外部引擎的自证。

## 33.2 节点命名：照抄 ngspice 的 `<实例>.<本地>` 小写

展开后内部节点名 = **`<实例路径>.<本地名>`，全小写**；元件名同样加小写前缀。
嵌套时路径自然串起来：顶层 `X9` 里的 `X1` 里的节点 `m` → `x9.x1.m`。

这不是审美选择，是**让 `cross_check` 变成真比较**的唯一办法。`cross_check=True` 靠节点名在
两个引擎的结果之间配对；如果内置用自己的命名，配上的节点数就是 0，而 0 个共同节点会被读成
「一致」。ngspice 的 rawfile 里打印的就是 `x1.m` 这种小写形式，逐字对齐之后
`compared_nodes` 才会真的到 2 以上。

因此有一条硬要求写进了测试：**同一份电路，层次写法和手写平铺写法的节点电压必须逐位相同**
（实测差 < 1e-12，`tests/test_spice_subckt.py::ExpansionIsFaithful`）。这条要求不依赖外部引擎，
是拍平实现自身的正确性判据。

## 33.3 参数与表达式白名单

`.subckt NAME p1 p2 PARAMS: r=1k gain={r*2}`：

- **引脚必须在参数之前**；`PARAMS:` 前缀可写可不写，裸 `r=1k` 也行；
- 默认值在**调用者的作用域**里求值（所以默认值可以引用调用者看得见的参数）；
- 实例上的 override 同样允许表达式，例如 `X1 a b NAME r=3k` 或 `X2 a b NAME r={base/2}`；
- 表达式只做 `+ - * / **`，走 `ast` 白名单遍历，**不用 `eval`**。

为什么只做五个运算符：函数（`sqrt`、`sin`）、节点引用（`V(a)`）、`.model` 参数里的表达式，都是
**看起来对、实际算别的**的典型来源。半实现的表达式语言正是「看起来对的错答案」的生产机，
所以超出白名单的一律按名字拒绝（`sqrt() is not supported`），不做「尽力猜一下」。

数值侧还有三道闸：除零、指数绝对值 > 64、溢出或结果非有限，全部 `ValueError`。

已实测：分压子电路 `x1.m = 4.999999997`；`9 V` 下默认参数给 `4.5 V`、实例覆盖
`r=3k` 给 `6.75 V`；`{r2*2}` 给 `6.0`；负控制是「默认与覆盖必须差 > 5%」——
如果参数根本没传进去，两个数会一样，这条断言就会失败。

## 33.4 局部 `.model` 的作用域

子电路体内定义 `.model` 时，模型名被改成 `<实例路径>.<模型名>` 并登记进这一份展平 deck 的模型表；
**体内没定义、外面定义的名字保持全局不变**。

这样两个子电路各自写 `.model dg D(IS=…)` 时互不覆盖（测试用 IS 差 1e5 倍的两个二极管证明电流
差 > 10 倍），同时不破坏「全局模型在子电路里可见」。

## 33.5 接地引脚：`0` / `gnd` / `gnd!` / `vss` 塌成唯一全局地

引脚绑定时走既有的 `_node()`，所以子电路内的地和顶层的地是同一个节点——这就是 SPICE 的
ground 语义，不是新发明。

这里踩过一个**很难看的坑**：接地引脚在归一之后是 `None`（不是字符串 `"0"`），而 `_node(None)`
原本会 `str(None)` 变成名为 `"None"` 的节点。结果是一个嵌套实例把地隔离成了一个假节点，
输出变成 `{'None': 11.999999928}`，`x9.mid` 从 `6 V` 变 `12 V`——**答案翻倍且看不出错**。
修法是 `_node()` 开头 `if name is None: return None`。测试里专门有一条断言结果字典里
**不存在** `"None"` 这个键。

## 33.6 五类必须拒绝的错误

拍平阶段能提前发现的错误，全部在解析期报掉，绝不「跳过这一张卡继续跑」：

| 错误 | 消息要点 |
|---|---|
| 未定义的子电路 | `unknown subcircuit 'xxx'` |
| 引脚数不符 | 列出给了几个、定义里几个、定义里的引脚名 |
| 未声明的参数 | 列出 `.subckt` 声明了哪些 |
| 自引用（含链式 `a → b → a`） | `instantiates itself` |
| 嵌套超过 `SUBCKT_MAX_DEPTH = 32` | 报深度而不是栈溢出 |

另外四条方向相反的纪律：

- 顶层 `.param` 当时专门报「`.param is not implemented here; parameters exist only on
  `.subckt` definitions and on their X instances`」——不假装支持，也不让它变成「未知指令」。
  **这条在 `0.0.28` 被推翻**：顶层与体内 `.param` 都能用了，见 `34-参数与作用域.md`。
- 体内嵌套 `.subckt` 拒绝；体内除 `.model`/`.param` 以外的指令拒绝。
- 缺 `.ends` 时，若先遇到单行 `.end`，报 **`missing .ends, not a stray directive`**
  （`.end` 是 `.ends` 的前缀，判断顺序必须是先 `.ends` 后 `.end`）。
- 文件结束仍未关闭的子电路，报 `never closed by .ends`。

`NOT_IMPLEMENTED_CARDS` 里 `"X"` 已删除；`NOT_COMPUTED` 里原来那句「subcircuits (.subckt),
hierarchical netlists」换成了两条**范围明确**的限制（当时是「顶层 `.param` 与非常数表达式」；
嵌套定义与体内的非 `.model` 指令）。`0.0.28` 之后第一条改成只讲「需要函数的参数」。

## 33.7 与手写平铺逐位相同：这条自证为什么比「和 ngspice 一致」更硬

`RealEngineAgrees` 会跑 ngspice 的 `cross_check`（要求 `compared_nodes >= 2` 且
`max_abs_diff_v < 1e-6`），但这条**只能证明两个引擎在这份 deck 上同意**，它证明不了拍平本身对。

真正证明拍平对的是：把同一电路手写成平铺 deck，两边逐节点比。
`div` 分压器实测 `x1.m = 4.999999997`，平铺版 `mid` 与之差 < 1e-12；嵌套版 `x9.mid = 6.0` 同样对齐。
这条判据是**能失败的**：任意一个引脚绑错、任意一个节点名合并错，差值就是量级级别的。

## 33.8 诚实登记：浮空岛两引擎必然分歧，而且与层次无关

写这一节是因为它在本轮被当成 bug 查了很久。

一份**DC 没有到地通路**的浮空岛，内置给 `0 V`，ngspice 给约 `2.5 V`。根因是 `gmin` 约定不同
（内置只用 `gmin` 做收敛辅助、不把它当真实电导；ngspice 会），不是拍平的错。

决定性证据：把**同一结构手写成平铺 deck**，两个引擎的分歧幅度**逐位相同**
（`2.501057919` 对 `2.501057919`）。所以这条分歧在 `0.0.27` 之前就存在，与层次展开无关。

于是它没有被「修掉」，而是被写进测试
（`test_a_deck_with_a_floating_island_is_where_the_two_engines_part`），并断言两边分歧幅度一致。
隐藏一个既有分歧，比保留它更容易让人把后来的错误归因到层次上。

## 33.9 边界（`0.0.27` 之后仍然不做）

- `.subckt` 里嵌 `.subckt`：拒绝。ngspice 允许，但作用域规则与命名会变成另一套设计问题，先不摊。
- ~~顶层 `.param`：拒绝。~~ **已实现（`0.0.28`）**，见 `34-参数与作用域.md`；仍然拒绝的是
  参数里用函数 / 引用节点电压 / 引用 `.model` 参数。
- `.model` 参数里的表达式：拒绝（拍平时模型参数还没经过表达式求值）。
- 表达式函数（`sqrt`/`sin`/`if`…）与节点引用：拒绝。
- ~~行为源 `B`、传输线 `T/O/U`、`.noise`：仍然不在内置里。~~ **`B` 自 `0.0.29`、`T` 自
  `0.0.30`、`O`/`U` 自 `0.0.31`、`.noise` 自 `0.0.32`** 都已进内置（分别见 `35`、`36`、`37`、
  `38` 篇）；委派仍然保留，但不再是唯一出路。
- 浮空岛：两引擎分歧保留并登记（§33.8），不出「修正值」。
