# 94 经验累积：把「好板子怎么布」写成能被违反的规则，再随包发出去

## 94.1 这一篇要回答的问题

`docs/02 §B` 里「经验累积」一直只是一个名字。`0.0.91`/`0.0.92` 之后，手上有 6 个真实立创工程、
20 块已经画完并出货的板子（16 522 段铜、12 805 个过孔），于是这篇要回答三个问题：

1. 这些板子**共同的习惯**能不能写成机器可判的条目？写成什么形态？
2. 一条「经验」被**违反**时，它说的是「这板子有缺陷」还是「这板子和大多数不一样」？这两句话不能混。
3. 语料只活在开发者机器上，怎么让它**跟着包一起发出去**，而且发出去的数字不会和运行时漂开？

## 94.2 两条链，一条红线

| | `hard` | `soft` |
| --- | --- | --- |
| 它是什么 | 有失败侧、**板上可测**的规则 | 好板子的**习惯** |
| 被违反时 | `violated` ⇒ 进 `report()["hard_violations"]`，是一条**缺陷** | `outside_habit` ⇒ 进 `report()["outside_habit"]`，是一个**问题**，不是缺陷 |
| 例子 | 通孔焊盘的层码跨层；via 环宽 < 0.1 mm | 走线落在 45° 栅格上；电源线比信号线宽 |

**红线：候选（candidate）永不自己变成规则。** `promote()` 必须 `confirm=true` **且**给出 `reason`；
不给 `confirm` 是 `ARG_INVALID`，不是「默认同意」。跨机器导入（`experience_import`）落进来的一律是
`candidate`，**导入不是提升**。

## 94.3 判词是闭集，而且四个档不是一回事

`_holds(entry, observed)` 只回答「成立 / 不成立 / 量不出来」，`_verdict()` 再决定用哪个词：

| 判词 | 什么时候 | 进 `report()` 的哪个列表 |
| --- | --- | --- |
| `passes` | 判据成立 | — |
| `violated` | **只对 hard** 成立不了 | `hard_violations` |
| `outside_habit` | **只对 soft** 成立不了 | `outside_habit` |
| `verified` / `unverified` | **只有 `pad_placement_verified`**（这条问的是「读者能不能担保输入」，不是板子好坏） | `unverified` |
| `not_checkable_here` | 这块板没有能决定它的数据 | `not_checkable_here` |

「量不出来」**不是** pass。旧写法把 `pad_placement_verified` 判成 `violated`，等于把每块离线立创板
塞进缺陷列表，说的却是「我没法担保焊盘位置」——那是读者的自认，不是板子的错，所以单独一档。

## 94.4 七个度量（闭集，没有第八个）

| 度量 | 读什么 | 种子里的条目 |
| --- | --- | --- |
| `tracks_off_45_grid` | 每段铜的角度对 45° 网格的偏离；另报中位/p90 | `track-angle-on-45`（soft，`max_off_grid_share 0.02`） |
| `via_annular_ring_below` | `(diameter − drill)/2` 低于下限的 via 个数 | `via-annular-ring`（hard，`min_mm 0.1`） |
| `distinct_via_geometries` | 逐板不同的 `(diameter, drill)` 组合数 | `via-palette-single`（soft，`max_distinct 1`） |
| `power_wider_than_signal` | 电源网最窄线是否仍宽于信号网最宽线 | `power-wider-than-signal`（soft） |
| `distinct_track_widths` | 逐板不同线宽数 | `track-width-palette`（soft，`max_distinct 12`） |
| `through_hole_pads_single_layer` | 带孔焊盘是不是只写了一层；**两种方言都认** | `lceda-through-hole-spans`（hard） |
| `pad_placement_verified` | 焊盘位置有没有被独立验证过 | `lceda-pad-placement-unverified`（hard） |

度量是闭集：`experience_candidate` 传一个不在表里的名字就 `ARG_INVALID`，**不是**「先收下以后再说」。

## 94.5 语料与分母：21 个数字，每个都带自己的分母

`data/experience_seed.json` 的顶层 `corpus` 写清来源，每条的 `evidence.sources` 写清分母：

| 条目 | 成立 / 不成立 | 分母是什么 |
| --- | --- | --- |
| `track-angle-on-45` | 16 336 段在栅格上 / 186 段不在（1.1258 %） | 20 块板、16 522 段带网铜；偏差中位 8.13°、p90 21.16°、最大 22.50°；最差一块 144 段 |
| `via-annular-ring` | 19 块达标 / 0 块过薄 | 19 块有 via 的板；逐板最小环 0.152（11 块）/ 0.153（4）/ 0.10（4） |
| `via-palette-single` | 15 块一种几何 / 4 块两种以上 | 19 块有 via 的板 |
| `power-wider-than-signal` | 18 块成立 / 1 块不成立 | 19 块板；19 个电源网关键字；**没有电源网或没有信号网的板两边都不计** |
| `track-width-palette` | 19 块 ≤12 种 / 1 块 19 种 | 20 块板；逐板线宽数 `[1,4,4,4,4,5,6,6,6,8,8,8,9,9,9,10,12,12,12,19]` |
| `lceda-through-hole-spans` | 235 个带孔焊盘 / 0 例外 | 6 个打包工程里**已放置**焊盘的带孔数（不是 4724 条 pad 记录里的 413，见 §94.6） |
| `lceda-pad-placement-unverified` | 0 块担保得了 / 6 块担保不了 | 6 个打包工程 |

**这些数字不是手抄的**：`corpus.measured_with` 写着 `pcb_agent_mcp.experience.observe`——
生成种子的脚本（`_scratch/build_exp_seed.py`，不入库）走的是**运行时判板子的同一份代码**。
两套公式各自演化、随包数字和运行时数字悄悄漂开，是这类「随包知识」最容易出的错。

## 94.6 两个浮点/单位陷阱，都是被真实板子撞出来的

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| 一块**真实出货板**上 1497 个 via 被判「环宽过薄」 | `(0.5 − 0.3)/2 = 0.09999999999999998 < 0.1` | `RING_EPS_MM = 1e-6`，比较写成 `ring < floor - RING_EPS_MM` |
| 5 块好板被判「有两种 via 几何」 | 同一个 24 mil via 一个文件写 `0.6096 mm`、另一个写 `0.61 mm`；`round(x, 4)` 把它们分成两组 | 分组改 `round(x, 3)` ⇒ 回到 15 / 19 |

第一条正是「数值先量后写」救回来的一次：如果种子照旧写，它会说「1 块板违反一条硬规则」。

另外两个**看起来像 bug、其实不是**的差异，已经写进条目的 `sources` 里分开陈述，避免下次再被当成回归：

- `413` 是 **4724 条 pad 记录（含库定义）** 里层码 `12` 的条数；`235` 是**已放置** footprint 里带孔的焊盘数。
  另有 2 个层码 MULTI 但无孔的松散焊盘——所以规则是「层码 12 **或** 有孔」，不是「层码 12」。
- 底面元件**不镜像**（`docs/93 §6`）；`pad_placement_verified` 恒为 `false` 是那条实测的**结论**，不是缺数据。

## 94.7 种子 id 在每一个写入口都被拒

`candidate` / `promote` / `outcome` / `import` 四条路一致拒绝 `exp.seed.*`。理由写在代码注释里：
**否则一个候选就能影子掉一条在役硬规则，等于没人确认就关掉了它。**

`library()` 仍会报 `shadowed_seed_ids`，但只剩下「手改文件」能触发，且会上报点名。

## 94.8 七个工具与开关

| 工具 | 做什么 |
| --- | --- |
| `experience_recall` | 按 kind / scope / metric 查库（默认只列 active） |
| `experience_check` | 对一块板跑一遍度量，出判词四个列表分开的报告 |
| `experience_candidate` | 写一条 candidate（不生效） |
| `experience_promote` | `confirm=true` + `reason` 才生效 |
| `experience_outcome` | 记一次成立/不成立，只计数，**不改状态** |
| `experience_export` / `experience_import` | 换机器；导入落 candidate |

本地库在 `PCB_AGENT_HOME/experience.json`（`schema 1`）；种子是**只读**的。
`PCB_AGENT_EXPERIENCE=0` 时七个工具都给 `DATA_UNAVAILABLE`，**不是**空列表——「关掉了」和「库里是空的」
必须是两个答案。默认开着且**不改变任何既有答案**，靠的是没有任何既有工具调用它。

## 94.9 判据与负控制（`tests/test_experience.py` 24 例，自检 9104–9112）

| 类 | 用例要点 | 负控制（改回去就红） |
| --- | --- | --- |
| `TheSeed` | 7 条 active、3 hard / 4 soft；每条都点名一个度量；种子只读；手改出的影子会被上报 | `the_metrics_the_seed_uses_are_the_ones_this_module_knows` —— 种子里出现一个模块不认识的度量就红 |
| `TheVerdicts` | 好板全 `passes`；坏板两个硬违反 + 两个 `outside_habit` + 一个 `unverified`；**soft 永不说 `violated`**；量不出来不是 pass；`0.1` 环不算 below；同一 via 两种单位算一个；`report()` 不落盘 | `test_the_ring_at_exactly_the_floor_is_not_below` 与 `test_one_via_written_two_ways_is_one_geometry` 就是上面两个陷阱的回归 |
| `TheLoop` | 候选不进 active；promote 需人；二次 promote 拒；outcome 只计数；retire；不可检查的度量在门口被拒 | `test_a_candidate_does_not_join_the_active_library` |
| `ImportIsNotAPromotion` | 导入落 candidate；种子 id 被 `skipped` | 断言 7 条 seed 全部 `skipped` |
| `TheTools` | 七个工具的信封；关闭时 `DATA_UNAVAILABLE` | `PCB_AGENT_EXPERIENCE=0` 分支 |

实测：`tests.test_experience` **24/24**；`--selftest` **327/327**（新增 9104–9112 共 9 个编号，
其中一条是「候选不会自己变成规则」、一条是「硬规则与习惯分开判」、一条是「什么都不会自己提升」）。

## 94.10 一句话

经验不是「好板子的样子」，而是**能被违反的条目 + 一个说清分母的现场**。所以这一层只做三件事：
把习惯写成判据、把违反分成「缺陷」与「问一句」、把语料的数字用判板子的同一份代码量出来再随包发出去。
它**不会**让 AI 自动学会布线——`board_route` 的规则仍只从板/工程/调用方取，取不到就拒绝。
