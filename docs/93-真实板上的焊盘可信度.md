# 93 真实板上的焊盘可信度：通孔跨层、底面不镜像、以及一道叫 `pad_trust` 的闸门

## 93.1 这一篇要回答的问题

`0.0.91` 把 `board_dangling_copper` 推出去之后，第一个问题不是「它还差什么功能」，而是
**「它在真实板子上说的是真话吗」**。答这个问题只有一条路：拿真板子跑。用的是用户自己的
6 个立创工程、20 块已经画完的板子（从在线工程备份里只读复制到 `_scratch/corpus/`，不入库），
总共 16 522 段铜。结果是一块 6 层开发板报出 **342 条 tail / 170 片浮铜 / 310 条「可切」**。

310 条「可切」在一块画完并出货的板子上，本身就是个不可能的数字。于是逐条核对自由端与焊盘
的关系（同网匹配）：

| 自由端落在哪里 | 条数 | 该怎么读 |
| --- | --- | --- |
| 恰好在自己网的 pad 中心 | 35 | **本应算附着，却没算** |
| 落在**别的网**的 pad 中心 | 101 | 焊盘位置本身不可信 |
| 不在任何 pad 上 | 206 | 未知 |

第一行是真缺陷，第二行是更麻烦的东西：它说明这个读取器**说得出「焊盘在哪」，但那句话
不一定对**。两件事都必须先修，否则这工具的每一条「可切」都是拿别人的错位当自己的证据。

## 93.2 通孔焊盘不是单面焊盘

`.epcb` 的 `PAD` 记录里 `[4]` 是**焊盘自己的层码**。实测 6 个工程 4724 个焊盘：

| 层码 | 有孔 | 个数 |
| --- | --- | --- |
| `1`（TOP） | 否 | 4308 |
| `2`（BOTTOM） | 否 | 3 |
| `12`（多层） | **是** | 413 |

**「12」与「有孔」严格互为充要，零例外。** 而旧代码完全忽略这个字段，改用**元件所在的层**，
于是从 `BOTTOM` 走到一个 TOP 面通孔焊盘的走线，被 `_pad_piece` / `_pad_reach` 里的
`if l in copper` 过滤掉——焊盘根本没进索引，铜看起来就悬空了。

取证不止于层码：全语料 **235 个通孔焊盘 100% 被写成单层**，且 **64 个 `BOTTOM` 走线端点
精确落在通孔焊盘中心**（同网）。两条独立读数指向同一个结论。

修法：`epro._pad_layers()` 对「有孔」或「层码 12」给 `["*.Cu"]`。这个通配不是新约定——
`dangling.py`、`fanout.py`、`route/router.py`、`oracle.py` 早就在读它（KiCad 的通孔焊盘
本来就这么写）。旧的单层值另存在 `layers_as_written` 里，不静默消失。

修后那块板：**342 → 338 tail、170 → 99 浮铜**。

## 93.3 底面元件不镜像

旧文档（`docs/13 §6`）写的是「底面元件只镜像 `y`，35.1% 落点，**弱**，只声明不声称」。
这次重测，发现那个 35.1% 量的是**错的假设**。方法：对每个带网焊盘，把它按某个候选变换
放到板上，问「这个点是否精确落在**本网**铜端点上」（容差 0.05 mm），同时数**异网**误撞
作为对照：

| 变换 | 顶面 2002 pad | 底面 547 pad | 异网误撞（顶/底） |
| --- | --- | --- | --- |
| **不镜像** | **62.1%** | **82.6%** | 1 / 3 |
| `-y` | 37.0% | 53.2% | 1 / 2 |
| `-x` | 3.0% | 6.0% | 0 / 0 |
| `-x,-y` | 1.7% | 3.5% | 0 / 0 |

不镜像在两个面上都最好，异网误撞也最少 ⇒ 次序不是容差放宽的产物。物理上也说得通：
立创把底面元件当成「放到反面、照样按顺时针转」，而不是把整个封装对 `y` 取负。

顺带修掉一处读半天才看懂的写法：`place()` 里原本「先 `py = -py`，再在闭包里
`y_local = -y_local if mirrored`」——两次取负相互抵消，行为本来就是不镜像。现在直算。
底面**自定义多边形焊盘**也不再翻转：中心不翻、形状翻，形状就和自己的位置自相矛盾。

**这条命中率是下界，不是精度。** 未布线的焊盘、只靠铺铜喂的焊盘根本没有铜端点可比对。
所以 `pad_transform.verified_by_app` 仍然是 `false`——这决定了下一节。

## 93.4 所以工具要先问一句：这块板的焊盘能不能信

一条 tail 被判「可切」，前提是「这段铜接不到任何东西」。而「接不到」是拿**焊盘位置**量出来的。
如果焊盘位置是推导的、而且推导只有 62.1%，那这句话就变成了：**「我把焊盘放错了」被说成
「你的铜是悬空的」**。

`dangling.pad_trust(board)` 把它写成两条事实的合取，不给默认值：

1. 焊盘几何确实读到了（`present["pads"]["present"]`）；
2. 位置要么构造上就精确（KiCad），要么经过应用核验
   （`source["pad_transform"]["verified_by_app"] is not False`）。

任一条不成立 ⇒ 每条 tail 与每片浮铜都带 `cuttable: false` + `why_not: "pad_placement_untrusted"`，
`removal_ops` 返回空列表，工具信封里的 `pad_trust` 说明是哪一条不成立、为什么，
`message` 直说「只列候选、不切」。

于是**立创板上 `trusted` 恒 false**，工具在那一边退化成一份候选清单。这不是能力打折，
是 62.1% 这个数字直接推出来的结论：拿它去证明「接不到」，证明不了。

KiCad 板（构造上精确）与所有既有单测行为逐位不变——这是「新功能默认关时行为零变化」的
同一条纪律：**闸门只在证据不足时才关**。

## 93.5 判据与负控制（`tests/test_dangling.py` 22 → 28 例）

| 类 | 用例要点 | 负控制（改回去就红） |
| --- | --- | --- |
| `PadTrust` | KiCad 板算可信；同一块板 `verified_by_app=false` 时 `cuttable==0`、每条 `why_not` 命名、两种 `removal_ops` 都空；`present["pads"]=False` 是**另一个** `reason` | 同一块板可信时那条 tail 仍 `cuttable=1`、`ops` 非空 ⇒ 闸门不是「一律拒绝」 |
| `ThroughHoleSpansEveryLayer` | 层码 1/2/12 的层规则；有孔即多层（层码是第二证人，不是唯一证人）；`B.Cu` 走线接在顶面通孔焊盘上时 tail 与 floating 都是 0 | 把该焊盘改回 `["TOP"]`，同一段铜立刻变成 **1 片浮铜** |

`test_a_track_on_the_far_side_attaches_to_a_through_hole_pad` 里的对照是这一轮最直接的复现：
同样两段铜、两个焊盘，只改 `layers` 一个字段，答案从「什么都没有」变成「一片浮铜」。

实测：`test_dangling` **28/28**（28.4 s）、`test_epro` 26 例、`test_epro_edit` 49 例、
`test_lceda_records` 19 例全绿、`--selftest` **324/324**。

## 93.6 一句话

这一篇没有加功能：它把一句已经在说的话改成了**说得起的话**。悬空铜的判据（一个附着点、
不是任何 pad 的唯一铜）没有动——动的是它的**前提**：先把焊盘读数修对（通孔跨层、底面不镜像），
再在读数本身不足以支撑判决时，**明说「这里我不该判」**。
