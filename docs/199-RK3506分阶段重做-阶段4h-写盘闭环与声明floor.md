# 阶段 4h —— 把计划真的写进板子：写后长度从文件重测，与计划值一模一样

`198` 的 §5 第 1 条留了一句「没有写盘」。这一轮把它补上：`198` 的 114 条 op（`style=chamfer`、`floor_mm=0.2`）真的写进了板子，而且长度不是拿内存里的计划值复述，是**重新解析写出来的文件**再量的。

结论一句话：**写盘链路是通的、写后读数与计划值逐位一致（skew 6.468 → 5.930，等于 `198 §3` 算出的 5.930）**；但这块板子上「写」比「算」多一道关——`edit.apply_plan` 的 `clearance_no_worse` 状态闸门，它按 0.2 mm 判，而这条 lane 的 netclass 就是 0.105 mm。

## §1 结论先行

1. **写盘必须两段，不是一段**：tune 的 op 里有 `delete_track`，它按 uuid 点名牌上已有的段；而这条 lane 的 118 条 op（阶段 4e/4f 的 pinched plan）**从来没落到盘上**，只活在探针 JSON 里。所以第一段先把那 118 条写进文件，第二段才可能在**真 uuid**上规划并写下蛇形。一段式会直接死在 `no track matches that selector`（本轮第一次尝试的原话）。
2. **两段都过闸了，闸门自己给的判词是「没有新违规」**：第一段 `decision` = "every gate passed: the bytes on disk are the planned bytes, re-parsing reproduces the planned tree, each operation's postcondition was re-read from the file, KiCad re-read both files, and its DRC reports no new violation"，第二段同文 ⇒ 字节门、token 身份门、后置条件门、KiCad 引擎门、DRC 差分门**五道全过**。
3. **写后长度与计划值逐位相同**：写之前（内存投影）skew 6.468，写第二段之前（磁盘）6.468，写完之后（磁盘重测）**5.930**；`198 §3` 尊重档的预测也是 **5.930** ⇒ 「计划可写」这一步没有代价，写下去不变形。
4. **但 0.2 mm 闸门会先拦下这条 lane 自己**：把闸门的 floor 设成 0.2 时，第一段就被拒——`clearance_no_worse: this plan takes the board from 1849 to 1979 different-net pair(s) closer than 0.2 mm; tightest is 0.1 mm at [26.9009, 26.876]` ⇒ **那条 lane 的铜本身就比 0.2 mm 近**（netclass 0.105）。这是 `198 §3` 那笔「35 对 ↔ 1.130 mm」交换在**写盘层**的同一个事实，不是新问题：要么把 floor 声明成设计自己的 netclass（本轮的读法），要么这条 lane 写不进去。
5. **本轮的 floor 是声明出来的数，不是绕闸**：`precheck_clearance_mm=0.105` 是 `edit` 公开的工具选项（「多近算太近」），这里填的是 netclass 真值 0.105；理由与代价见 §1 第 4 条与 §4 第 2 条，`allow_new_violations` 一次都没用。

## §2 怎么读的

`D:/tmp/_t4g.py`（不进仓库）：

1. 读 `_s1d.esc2.kicad_pcb`（阶段 4f 的板），把 pinched plan 的 **118 条 op 注入内存**，先量一遍——这就是 `198` 里那份 BEFORE（skew 6.468）；
2. **第一段**：复制成 `_t4g_write.kicad_pcb`，用 `edit.propose` + `edit.apply_plan` 把 **118 条真写进去**，再解析文件量一遍；
3. **第二段**：对**写出来的文件**重跑 `TB.plan(12 网, style=chamfer, floor_mm=0.2)`（这时 uuid 是真的），拿到 **114 条 op**，同样 propose + apply；
4. 重新解析文件量长度，再让 `board_drc` 说话。

读法：

1. **写后逐网数字与 `198 §3` 的尊重档表逐条对上**（CLKP 16.406、DQ0 17.808、DQ7 17.733……）⇒ 这不是「另一批 op 碰巧也到 5.930」，是同一批 op 从纸面搬到了盘上。
2. **落齿的网正好是 `198 §7` headroom 判 `reachable` 的那几条的反面**：能落齿的 DQ0/DQ7/DQ6/CLKP/DM0 里，DQ0 与 DQ7 已进 tol；5.930 的残余全落在 headroom 判 `shortfall` 的 DQ1/DQ3/DQS0N/DQS0P 上（这一轮它们 0 颗 op）——两条独立读数指向同一批网。
3. **同一批 DRC 读数在写前写后完全一致**：`kicad_defaults` 口径下 `error 1693 / warning 122`（`clearance 499`、`annular_width 199`、`track_width 199`…），`unconnected 216`，**写前写后一个数都不差** ⇒ 蛇形本身在这套规则下没有新增违规（这些数是板子本来就有的，不是本轮带来的；见 §4 第 1 条）。
4. **`/DDR_DQ2` 写后 17.667（差 0.141）是收敛的**：它本来就在 tol 0.10 边上，这一轮 0 颗 op（`198 §1` 第 4 条说过 arc 表达不了亚毫米增量，chamfer 的齿又落不下），所以它停在原地——不是写坏了。

## §4 未做项 / 口径欠账

1. **这份 DRC 是 `kicad_defaults`，不是工程自己的规则**：副本旁边没有 `.kicad_pro`，`rule_source` 明确写着 `kicad_defaults`，`project=` 参数传了工程文件也没把它改掉（读数仍是 1693/122）⇒ 1693 这个绝对数**不可引用为「板子有 1693 个错」**，它只说明「写前写后逐项相同」。要让绝对数有意义，得把板子放在 `rk3506_som.kicad_pro` 旁边再跑——登记为欠账。
2. **写盘用的 floor 是声明值 0.105**（见 §1 第 5 条）：这是「按设计自己的 netclass 判」，与关掉闸门不是一回事，但也不等于「0.2 mm 已经被满足」。板上 1849 对 <0.2 mm 的既存对仍在。
3. **`preconditions` 一次都没关**：本轮的两次 apply 都是闸门自己对完五道门后放行；没有用 `preconditions=false`、也没有用 `allow_new_violations`。
4. 阶段 4 的其余欠账（`+5V_IN` 母线、`+0V9_*` 无 zone、`+1V35_DDR` 未覆盖 U6、`boot_sw` 朝向、`hole_in_pad` 9、旧 `via_in_pad` 9、`copper_under_magnetics` 1、5 处半路由、旧锐角、`track_dangling` 25）一条都没动。
5. 写出来的板子只存在 `D:/tmp/_t4g_write.kicad_pcb`，**没有**替换 `examples/rk3506_som/rk3506_som.kicad_pcb`——要不要接受这条 lane 的 0.1 mm 间距，是设计决定（`198 §5` 第 3 条），不是这一轮的读数。
