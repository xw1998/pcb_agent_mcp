# 90 · 沿长度这一路的熔化潜热：每个节点一个焓状态，平台是精确相界面

> 0.0.86 给 `fusing_current` 加了潜热（标量 `1+β`），0.0.87 给 `repetitive_pulse_rating` 加了潜热
> （一个集总温度，闭式发/歇映射）。剩下 `fusing_current_taper`——沿长度一个节点一段的**一维 PDE**。
> 它不能乘一个标量：铜的 `rho(T)` 在 Thomas 三对角解里，潜热得作为**每个节点的状态**存在，
> 而且「哪些节点正停在平台上」本身是未知量。本文记这件事怎么做的、拿什么当锚、以及一条我自己先写错的话。

## 1. 缺口

`fusing_current_taper` 的 `value`（给 `current_a` 时）一直是「到 1083 °C 的时间」。
熔穿要再付储层的账：绝热、单节点下 `t_melt/t_onset = 1+β = 1.253093`（25 °C），
也就是旧答案比真熔穿**短 20.2 %**（0 °C 短 19.2 %，100 °C 短 23.1 %）。

偏偏这一路最不能糊：颈缩熔断问的正是「哪一段先熔、旁边铜能拖多久」，
而导热会**不成比例**地延长 onset 与平台（见 §6），把一个标量修正直接乘上去等于把机制抹掉。

## 2. 形式：每节点一个焓，平台精确，无糊状带

每个节点带 `(T, phi)`，`phi ∈ [0,1]` 是该节点的**熔化质量分数**：

```text
E_i = C_i (T_i - Tm) + phi_i L_i
C_i = rho_m c_p A_i l_i        （感热容量）
L_i = rho_m L_f A_i l_i        （潜热储层）
```

- `phi = 0` 固态，`phi = 1` 全液，`0 < phi < 1` 表示**这个节点正坐在熔点温度上**、
  温度动不了、只有储层在填。
- 平台是**精确**的：这种节点的未知量是 `phi` 而不是 `T`，所以不需要任何「糊状温度带」、
  不需要任何宽度参数。**没有可调的东西，也就没有可调错的东西。**

### 2.1 一个要害：`phi` 项在非相变节点上必须相消

反演是先把能量解出来，再按 `f = E/L` 分三段：

```text
f <= 0  固态:  T = Tm + E/C
f >= 1  液态:  T = Tm + (E - L)/C
0 < f < 1 平台: phi = f 且 T = Tm
```

所以**不需要**相位判断——`E → T` 是可逆的，无条件成立。
我第一版坚持「只有上一时刻已在平台上的节点才钉住」，结果是活跃集在 `[1] ↔ [0]` 之间
振荡（`active_set_iters_max` 打满 80），最后接受的是振荡中间的垃圾状态，
`L = 0` 都对不上 `_taper_run`，温度直接爆到 3.7e6 °C。

同一处还有一个更隐蔽的错：`rhs` 里多写了 `phi_old·L/dt`。这个项在非相变节点上**是相消的**

```text
E^{n+1} = E^n + dt·Q   =>   C·T' = C·T + Q
```

把它当源项加进去，等于把 0.325 J 的储层整块灌进解：`x = (0.6·1083 + 325)/0.6 = 1627`，
恰好多个 `L/C = 542 K`。**修法：`rhs = C/dt·T_old + a`，与 `_taper_run` 逐字相同。**

### 2.2 亚步插值不能吃钉住的解

平台节点解出来恰好是 `Tm`，如果直接拿它插值，`frac = (Tm-T_old)/(Tm-T_old) = 1`，
整步塌成一步——`t_onset` 会落在步边界上（I = 5 A 时得 2.27 s 而不是 2.266922 s）。

修法：**保存第一次（尚未钉住的）解 `x_first` 专供插值**。改完之后
`t_onset_s` 与同参数 sensible 的 `t_melt_s` **逐位相同**，这条本身就是跨模型自检。

### 2.3 两个时间回答两个问题

| 键 | 含义 | 与 sensible 的关系 |
|---|---|---|
| `t_onset_s` | 某节点**首次到达** `melt_c` | 必须**逐位等于** sensible 的 `value` |
| `t_melt_s`（= `value`） | 某节点**完全液化** | sensible 没有这个概念 |

口径与 `fusing_current` 的两档一致：`value` 在 latent 档就是熔穿。
停止点与 `_taper_run` 对齐（在事件上停、状态留在最后一个**完成**步），否则剖面差一步。

## 3. 锚（都不是本模块自己的输出）

| 锚 | 期望 | 实测 |
|---|---|---|
| `latent_j_kg = 0` 等价 | 与 `_taper_run` 逐位相同 | 单节点/多节点、`k=0/400`、`ends` 有无，`temperature_c` 全部逐位相等 |
| 绝热单节点 | `t_full/t_onset → 1+β = 1.253093` | 2000 步 1.253527、20000 步 1.253202、200000 步 **1.253095**（偏差 +3.5e-4 → +1.4e-6） |
| `t_onset_s` == sensible `value` | 逐位 | 颈缩 I=5/8 A：2.266922 / 0.613506，完全相同 |
| 能量守恒 | `energy_balance_rel` 随 dt 收敛 | 6.24e-4 → 8.75e-5 → **1.39e-5**（同上三档） |
| `β` 与 `fusing_current` 同一个数 | 0.253092719 | `_taper_latent_share(25)` 与 `latent_heat_share_of_i2t(25)` 在 1e-15 内相同 |

`β` 是**两个模型之间的锚**，不是新常量：几何、面积、`rho20` 在比值里全部约掉，
剩下的就是 `(L_f/c_p)·alpha/(r(Tm)·ln(r(Tm)/r(Ta)))`。

## 4. 默认关是逐位不变，而且不是靠分支

没有写成 `if latent: return _taper_run(...)`——那是假控制（两条路径迟早会分叉）。
`latent_j_kg = 0` 走的是**同一套算术**：储层全零 ⇒ 平台永不进入 ⇒ 每个节点的投影就是感热解。
自检和测试都直接比整个信封：`melting_model` 缺省 == 显式 `"sensible"`，
且默认信封里**一个 latent 键都不许出现**。

## 5. 二分下界的缩放

二分下界原来是「绝热到熔点的电流」。latent 档下这个电流**已经熔穿**，当起点是反的。
熔穿让 `I²t` 乘 `1+β`，所以下界电流除以 `sqrt(1+β)`：

```text
i_lo /= sqrt(1 + beta_amb)
```

## 6. 延迟是输出，而且我先把这句话写错了

`melt_delay_pct = 100·(t_full - t_onset)/t_onset`。

我最初在 `melt_delay_note` 里写的是「它是绝热 `latent_share_of_i2t` 的**下界**，随电流升高逼近它」。
**这话被自己的实测打掉了。**导热对 onset 与平台的作用不成比例：onset 被拖长、平台又多付一份导热损失，
比值可以越过 β、也可以远远超过它。实测（dt = 2e-4 s，`ends_c = 25`，均匀 10 mm × 0.5 mm，k = 400）：

| 电流 | `t_onset_s` | `t_full` | 延迟 % |
|---|---|---|---|
| 8 A | 1.423424 | 2.5174 | **76.855** |
| 10 A | 0.426462 | 0.5798 | 35.956 |
| 14 A | 0.160687 | 0.2072 | 28.946 |
| 20 A | 0.069813 | 0.0886 | 26.911 |
| 26 A | 0.039553 | 0.0498 | 25.907 |
| 30 A | 0.029240 | 0.0370 | 26.538 |
| 40 A | 0.016070 | 0.0202 | 25.696 |
| 60 A | 0.006957 | 0.0088 | 26.488 |

同一段铜，端点绝热时反而**稳稳在 β 之下**（1/0.5/1 mm 颈缩：4 A 8.458 %、12 A 8.653 %、30 A 9.670 %、50 A 12.510 %）。
所以延迟是**边界条件 + 几何 + 电流**的联合输出：导热占比小的构型远低于 β，导热占比大的构型远高于 β。
`melt_delay_note` 现在写的是这些可复现的数，测试里也钉死 10 A / 35.956 % 一格。

## 7. dt 是唯一的分辨率

平台由「能量反演 + 亚步插值」定位，所以延迟只锐到 `dt`。同一构型（1.0/0.5/1.0 mm，I = 20 A）：

| dt | sensible 值 | latent 值 | `t_onset_s` | 延迟 % |
|---|---|---|---|---|
| 5e-3（默认 `t_end/2000`，`t_end=10`） | 0.181339 | 0.2000 | 0.181339 | 10.291 |
| 1e-3 | 0.184607 | 0.2020 | 0.184607 | 9.421 |
| 2.5e-4 | 0.185213 | 0.2020 | 0.185213 | 9.064 |
| 1e-4 | 0.185334 | 0.2020 | 0.185334 | 8.993 |

所以信封里报 `time_resolution_s`，并明说「延迟只锐到这一步，再细的读数不是模型给的」。

## 8. 未做

- **熔穿之后**：体积变化、熔流、表面张力成球、接头合金化/金属间化合物。都不做——铜在第一个节点
  全液时已经失效，这些都在问题之后。这一条在 `calc_capabilities` 里从
  「Melting, by name」改写为「Melting, past the melt-through」，条数不变（23），因为要登记的缺口
  从「三个工具都没有潜热」变成了「三个工具都有潜热、但都没有熔后行为」。
- **横向梯度**：taper 仍是一维轴向，只有 `ends_c` 这一个边界温度，没有对流、没有 rho(T) 之外的材料非线性。
- **潜热值不开放**：`latent_heat_j_kg` 与 `fusing_current` 一致，不进 schema（默认铜的 208.7 kJ/kg）；
  想换成别家数据得改代码，不给你一个静默改物理的旋钮。

## 9. 一句话

沿长度这一路的潜热不是乘一个数：它把「1083 °C 就是终点」换成「1083 °C 之后还有一段要付账」，
而这一段在 PDE 里必须作为每节点状态存在。平台做成精确相界面之后，模型里**没有一个新的可调参数**——
唯一的旋钮是步长，而步长是被报出来的。
