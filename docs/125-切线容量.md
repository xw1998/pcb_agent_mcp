# 125 · 切线容量：这条线上能过几条线，又有几条网必须过

`board_cut_capacity`。这是本服务器里第一个问「**布局层面**成不成立」的工具，前面所有
工具问的都是单个对象（这个焊盘能不能出去、这块铺铜是几块）。

## 1. 为什么需要

画 sky_star 时反复卡在同一类地方：**单个焊盘都出得去，整块板却过不去**。`escape` 说每个
焊盘都有逃逸方向，`width_scan` 说 LQFP 边上只能出 0.3，可这些读数加起来仍然回答不了
「这个布局还能不能画」。

缺的那一问是：**一条线把板子切成两半，两半之间有多少条通道，又有多少个网必须跨过去。**
一个网在线的两侧都有焊盘，就一定得有铜跨过去；每跨一次占掉一条通道。于是

```
必须跨过去的网数  >  线上所有层的通道总数
```

就不可能画通 —— 不需要布线器，不需要层分配，也不需要耐心。这是**必要条件**，而且是在
画第一根线之前就能算出来的。

## 2. 怎么算

- 切线：给一点 `(x, y)` 和线的走向 `angle_deg`（90 = 竖线），默认取板框对角线 × 1.5 长，
  再用板框裁掉外面那段（板外不是通道）。
- 通道（lane）：线上没被铜占住、且离铜至少 `clearance_mm` 的连续区间。一段宽 `W` 能塞下
  `n` 条线当 `n*track + (n-1)*clearance <= W`，取最大整数 `n`。
- 必须过（`must_cross`）：焊盘中心在线的两侧都出现过的网，且**当前还没有**自己的走线真的
  穿过这条线。已经穿过的从需求里扣掉，否则半成品板的读数会把已付的账再算一次。
- 障碍：默认 `pads + vias + tracks`（画出来的铜都算，一条走线占住的通道就不是空的），
  但**默认不算铺铜** —— 灌铜会绕着过去的线重切，把它算成固定障碍会让每一条铺过铜的线都
  读成「满」。`sensitivity` 三档（`pads_vias` / `pads_vias_tracks` / `with_pours_too`）
  把「忽略它省多少」摆出来，所以「满」永远不会含糊成「因为一片会被重切的铜而满」。

## 3. 判据与对照

十条，在 `tests/test_cut_capacity.py`。最关键的六条：

| 事实 | 对照（能反向失败的） |
|---|---|
| 空板只有 1 条通道，宽度=板宽 | 线画在板外必须报 `OUTSIDE_BOARD`，不能回「0 条通道」 |
| 一条穿线走线把它切成 2 段，且少掉的正好是 `线宽 + 2×clearance` | 同一根走线放到够不着线的地方，必须回到 1 段、容量回到空板值 |
| 两侧都有焊盘的网必须过 | 同一个器件整件挪到线一侧，必须从需求里消失 |
| 已经穿过的网不再计入需求 | 不做这件事，半成品板的读数会把已付的账再算一次 |
| 铺铜默认不挡 | `obstacles=[...,"zones"]` 必须让数字变（灌满整块 = 该层 0 条） |
| 需求 > 容量 ⇒ `capacity_exceeded` 且 `slack` 为负 | 同一个板把唯一那个洞加宽 1.7 mm，判定必须翻回 `within_capacity` |

最后一条是整组里最重要的对照：**判定跟着几何走，不跟着搭建走**。

## 4. 真板读数，以及一个被推翻的假设

sky_star（44 × 72 mm、2 层、296 个走线段）：

```
竖切 x=130.3（P1 排针列正中）：通道 361 条，必须过的网 5 个 ⇒ within_capacity
竖切 x=166.7（P2 排针列正中）：通道 364 条，必须过的网 6 个 ⇒ within_capacity
横切 y=中线：               通道 180 条，必须过的网 21 个 ⇒ within_capacity
```

排针列 2.54 间距、焊盘之间还剩 1.65~2.1 mm，一列能过 159~204 条线。

**这推翻了我自己一直背着的一个判断**：改通孔那一轮踩到 12 个网在 B.Cu 上穿过焊盘行、
DRC 报 33 条违规，我当时的解释是「通道不够」。实测说**不是**：那一列有三百多条通道，
12 个网在两个数量级之下。真正的原因在单个焊盘的逃逸宽度（`width_scan` 读到的 0.3）和
走廊布线本身，不是「线上没有位置」。

一个工具的价值不只在它量出了什么，也在它能把一个错的解释量掉。

## 5. 一个被测试抓到的实现缺陷

lane 边界用「先按 0.05 采样、再二分到 0.001」求。第一版二分把「进入障碍」和「离开障碍」
两种情况写成了同一个参数比较，其中一种方向反了 —— 结果障碍区间**两边各短 0.05 mm 左右**，
0.4 宽的走线读成 0.703。图上完全看不出来，只有测试问「少掉的正好是 0.8 吗」才现形。

改法是把契约写死：`_cut_edge(hits, s_hit, s_miss, ...)` 显式收「一个命中点 + 一个未命中点」，
返回两者之间的边，误差 ≤ res/2，与调用顺序无关。现在同一条走线读回 0.800。

## 6. 没有做的事

- 不选网、不指定哪条网走哪条通道，不画线。`not_claimed` 写在返回里。
- 不判「宽的那段能不能拐过去」：那是 `board_routability` 和走廊的事。
- 不把「通道够」读成「能画通」：它只是必要条件，`verdict=within_capacity` 不代表可布。
