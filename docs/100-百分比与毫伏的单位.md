# 100 · 同一个量的两种写法：2.94 mV 报成「3.3 V 的 89.19 %」

> 它回答的问题：`board_ir_drop` 明明算对了压降（2.94 mV），为什么同一段回答里
> 多出一个 **89.19 %** 的字段，而它和那两个数都对不上？
>
> 它推翻的前提：**「派生字段不用管，反正原文都在」**——派生字段是别人唯一会读的那一个。

---

## 100.0 两句话

1. `worst_sink_drop_pct_of_3v3` 拿**毫伏**除以**3.3 伏**再乘 100，结果放大了 **1000 倍**：
   STM32F412 核心板上 `J2A.1 → U1.1` 走 0.5 A，真实压降 2.943 mV = **0.089 %**，字段报 **89.19 %**。
2. 修法是补上 `/1000`，并加一条**自洽测试**：这个百分比必须等于
   `100 × max_drop_mv / 1000 / 3.3`。这条测试不是形式——它是唯一能抓住这类错的形状。

---

## 100.1 这个数是怎么被抓到的

做 STM32F412 核心板的 IR drop 时顺手把它打印出来：

```
+3V3  J2A.1 → U1.1, 0.5 A, 铺铜参与建模
  max_drop_mv                       2.943345
  worst_sink_drop_pct_of_3v3       89.192273     ← ？
  total_copper_loss_w               0.001471
  worst_current_density             95.24 A/mm²（F.Cu 0.15 mm 宽）
```

`2.943 mV / 3300 mV = 0.089 %`。而 89.19 / 0.089 ≈ 1000——这不是浮点误差，
是**单位**：`max_drop` 的变量名里就写着 `_mv`，可下一行当伏特用了。

一条辅助判断：如果 3.3 V 上真的掉了 89 %，那 U1 拿到的是 0.36 V，MCU 根本起不来；
而这块板的 `total_copper_loss_w` 只有 **1.47 mW**（0.5 A 里 2.94 mV ⇒ 0.5 × 0.00294 = 1.47 mW，
自洽）。**两个字段互相矛盾时，通常是其中一个的单位错了，而不是电路错了。**

---

## 100.2 为什么它能活到 0.0.100

因为在 `tests/test_board_ir_drop.py` 里，`max_drop_mv`、`total_copper_loss_w`、
`current_density_a_per_mm2`、`edge_count`、`node_count` 全都有断言，**唯独这个百分比一个都没有**。
它从加进去那天起就没被人算过一遍——而它恰恰最容易被读者当成结论（「压降占电源的百分比」）。

同一类错的其它形状，一并记下来，以后按这个清单查：

| 形状 | 例子 |
|---|---|
| 同一量的两种单位 | mV 当 V（本篇） |
| 比值分母用错 | 用额定值而不是实测值 |
| 百分比与绝对值不联动 | 改了绝对值、百分比还在旧口径 |
| 单位换算与 `quantize` 相互作用 | µm 与 mm 混用后的阈值比较 |

---

## 100.3 测试怎么写才有用

新增 `test_pct_agrees_with_mv`，两条断言：

```python
# 1. 自洽：百分比必须由同一个 max_drop_mv 推出来
100.0 * v["max_drop_mv"] / 1000.0 / 3.3
# 2. 绝对值：20 mm 的 0.5 mm / 35 µm 铜在 1 A 下是 19.7029 mV ⇒ 0.597056 %
```

第 1 条是**结构性**的（抓单位与联动），第 2 条是**独立性**的（抓两条一起错，比如连
`max_drop_mv` 都错了）。只写第 1 条，等于让两个字段互相作证；只写第 2 条，则下次换个
3.3 V 以外的电源就漏。

这条经验已按 94 篇的机制登记为工程经验候选（`exp.ir-drop-pct-must-agree-with-mv`），
**候选不会自己变成规则**，要人确认后才 `promote`。

---

## 100.4 边界

- 只改这一个字段，`max_drop_mv` / `total_copper_loss_w` / 电流密度 / 网络拓扑的算法一个字节没动；
- 该字段的**含义**没变（仍是「最坏受端压降占 3.3 V 的比例」），变的是它终于算对了；
- 如果调用方此前拿这个字段做过判断，那些判断是按 1000 倍的数做的——这是一次**对外可见的
  数值变更**，不是 bugfix 级别的静默修正，所以它单独占一个版本号（0.0.100）并在 CHANGELOG 首行写明。
