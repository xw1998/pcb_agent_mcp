# 34 参数与作用域：一个数从 `.param` 走到元件

## 34.1 为什么先做 `.param` 而不是接着做行为源

`0.0.27` 让内置引擎自己拍平 `.subckt`，但拍平只能解**子电路参数**：顶层 `.param` 仍然被按名字
拒绝，`R1 1 0 {r}` 这种写法在顶层直接报「no subcircuit parameter scope in effect」。

这条边界看起来无害，实际上把子电路能力砍掉一半——真实的子电路几乎都靠参数化（`r=1k`、
`w={2*u}`），而参数在顶层没有来源，用户只能给每处 `X` 实例写死一个 override。
参数化是**整个 deck 的公共语言**，不是子电路的私产。

所以这一版补的第一件事是：`.param` 在顶层与 `.subckt` 体内都成立，值按依赖顺序解析。

## 34.2 只有一个数字读取器，白名单也只有一个

`.param r=1k b={a*3}` 与 `.subckt div a b params: r=1k` 走同一套代码：

- 值是**数字**（含 `1k` / `4.7u` / `2.2meg` / `1e3` 这些后缀）或 `{…}` 表达式；
- `{…}` 里只有 `+ - * / **` 与参数名，走 `ast` 白名单（`docs/33` §33.3 已经写死，本版不改）；
- 函数、节点引用、`.model` 参数里的表达式仍然按名字拒绝。

**刻意不接受不带括号的表达式**（`.param r=1k*2`）。ngspice 接受它，本版要求写成 `{1k*2}`。

理由不是洁癖，是这条约束把「句法」压成一样东西：如果 `.param` 的值可以是裸表达式，那么
「一个 token 是数字还是表达式」需要在四个地方各写一遍（元件值、子电路默认值、实例 override、
`.param`），四个地方的边界迟早会不一样。现在只有一处。

## 34.3 严格读数字：`1k*2` 曾经被静默读成 1000

这是本轮抓到的**真缺陷**，不是设计选择。

`_value("1k*2")` 的行为是：从头扫描能组成数字的字符，遇到 `*` 停下，再拿剩下的 `k*2` 认单位
后缀——于是它返回 **1000**，而 `*2` 被完全吃掉。也就是说 `R1 1 0 1k*2` 在旧版里会**静默地**得到
1 kΩ，用户以为写了 2 kΩ。

对一个整天在算阻抗的工具，这是最坏的那一类错误：答案安静、合理、且差一倍。

修法是给 `.param` 与 `{…}` 位置加一道严格判定：整个 token 必须匹配
`^[+-]?(\d+(\.\d*)?|\.\d+)(e[+-]?\d+)?[a-z]*$`（数字 + 可选指数 + 可选单位字母）。不匹配就是
错误，消息里直接把正确写法写出来：`'1k*2' is neither a number nor a {…} expression (write
{1k*2} if it is arithmetic)`。

元件值现在也走这条（`_value_or_expr` 共用），所以 `R1 1 0 1k*2` 同样报错。这是**收紧**，
会在升级时打断一份依赖旧宽松行为的 deck——但那正是应当打断的地方。

## 34.4 依赖顺序：不是「先写的先算」

`.param b={a*3} a=1k` 合法（前向引用），`.param a={b+1} b={a+1}` 必须报错（循环）。
两者在句法上完全一样，只能靠求解过程区分：

1. 把所有 `.param` 收成待解列表；
2. 反复扫，每轮把当前作用域里能算的算掉；
3. **一轮里一个都没算掉**时，说明剩下的互相等待——此时把第一个失败的名字连同「它引用的那个
   名字自己也还没解出来」一起报出来，并列出仍在校等集合。

于是两种错误有了不同的消息：

- 循环：`line 1: param 'a' refers to 'b', which is itself unresolved (still waiting: a, b) -
  a circular definition cannot be resolved`
- 拼写错误：`line 1: param r: 'q' is not a parameter in scope here (none)`

这条区分不是文案工整：循环是「这份 deck 必须改结构」，拼错是「换个名字」。用同一句话说，用户
会去改错地方。

## 34.5 作用域链：全局 → 子电路参数 → 实例覆盖 → 体内 `.param`

一个名字按这个顺序找，靠后的遮蔽靠前的：

| 层 | 来自 | 谁写的 |
|---|---|---|
| 全局 | 顶层 `.param` | 整份 deck |
| 子电路参数 | `.subckt … params: r=1k` 的默认值 | 定义者 |
| 实例覆盖 | `X1 a b div r=2k` | 调用者 |
| 体内 `.param` | `.subckt` 体内的 `.param rr={r*2}` | 定义者，可用前三层 |

体内 `.param` 在当前实例的 env 里求值，所以 `rr={r*2}` 取的是**这个实例**的 `r`。测试用
`r=2k` 覆盖得到 `rr=4k`（9 V 下 2.25 mA）。

**体内 `.param` 不是实例参数**：`X1 a b leg rr=3k` 会被拒绝（`.subckt 'leg' does not declare
rr`）。否则「覆盖一个本地中间量」会让派生量的语义取决于调用者，而那个量在原定义里是算出来的。

全局参数对子电路体可见（`R1 a b {vdd}` 读顶层 `vdd`）——这条在真实 deck 里到处都是，且它
与「本地同名遮蔽」不冲突：测试里全局 9k、体内 1k，答案走 1k（9 倍差距，做不出假绿）。

## 34.6 源的三个数字槽共用同一个读取器

`V`/`I` 源有四处数字：`dc` 值、`ac 幅度 相位`、波形参数（`pulse(...)` 的七个）、以及裸写的
DC 值。这四处过去各写一遍 `_value(...)`，于是「参数能进元件但进不了源」这种半接状态很容易发生
（`0.0.26` 的间距参数就这样掉过一次）。

本版把它们统一交给 `_value_or_expr` + `_resolve_element()`：解析期允许 `{…}`，展开期一次性
解成数字。副作用是这条不再依赖记忆——写新卡时不需要问「这个槽收不收参数」。

`tests/test_spice_param.py::SourcesTakeParameters` 逐槽验证：`dc={vdd}` 落在 2.5 V；`ac {mag} 0`
让节点幅度正好 0.5；`pulse(0 {vhi} …)` 解析后**每个参数都是 float**（这条断言本身就否掉
「参数原样传进求解器」）。

## 34.7 负控制：每一条都能失败

| 断言 | 如果机制不在会怎样 |
|---|---|
| 分压 `r2=3k` 得 6.75 V，改成 `r2=1k` 得 4.5 V | 参数被解了但没传下去 ⇒ 两个数相同 |
| `x1.m` 与手写平铺 `mid` 逐位相同（§33.7） | 展开/解析错 ⇒ 差量级 |
| 前向引用 `b={a*3} a=1k` 给 1/3000 A | 顺序解析 ⇒ 直接报错 |
| `1k*2` 必须被拒 | 回到旧宽松行为 ⇒ 静默返回 1000 |
| 体内 `r=1k` 遮住全局 `9k` ⇒ 9 mA | 遮蔽没生效 ⇒ 1 mA（差 9 倍） |
| 与 ngspice `cross_check` 比到 ≥2 个节点、差 < 1e-6 | 解析顺序或数值错 ⇒ 差出来 |

## 34.8 仍然不做

- `.param` 里用函数（`sqrt`、`sin`）、引用节点电压、引用 `.model` 参数：拒绝，名字写在消息里。
- 不支持 `.func` / `.global` / 参数覆盖（`.step`）：仍按未实现指令拒绝。
- 元件值仍只做「数字或 `{…}`」；不引入「值 = 表达式含单位混写」（`{1k}+{2k}` 是两段，不是语言）。
- ~~行为源 `B`、传输线、`.noise` 仍然只能走委派。~~ **均已进内置**：`B` `0.0.29`、`T`
  `0.0.30`、`O`/`U` `0.0.31`、`.noise` `0.0.32`（见 `35`/`36`/`37`/`38` 篇）。
