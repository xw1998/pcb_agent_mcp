# 阶段 4k —— 「蛇形线像三角」与「为什么不用铺铜和平面分割」

用户三句话：

> 「还有就是绕的蛇形线不是正常的像是三角你看人家正常的做等长看看是mcp的原因还是你的原因？还有我发现你似乎并不喜欢用电源和大电流路径铺铜是什么原因也不喜欢用平面分割」

本轮不写新判定，只做两件事：**归因**（是我还是 MCP），**修仪器**（让下一次能看见）。两条归因都不好听，照实写。

## §1 结论先行

1. **三角线的直接原因：三处默认值写的都是 `chamfer`**。`route/tune.py::_serpentine` 是 45 度三角波的实现；`route/tune_board.py::plan(style=...)` 与 `tools.py::board_tune_length` 的 schema 默认值也都是 `"chamfer"`。所以「MCP 默认画三角」+「我照默认跑」**两边都有责**，而且我的责任更重：默认值是给人看的，我一次都没看。现在 `plan` 与工具 schema 的默认都改成 `"arc"`，`chamfer` 变成只能显式要求的形状（`sty` 白名单里保留，因为窄通道里它仍是唯一画得出来的形状，见 §5）。
2. **圆弧蛇形在交付板上是真的画出来了，但一半看起来仍是倒角**。本板文件里 **0 条 arc track**（4110 tracks 全是直线）；用同一组 12 条 DDR lane 跑 `style="arc"` 得到 **84 段圆弧**，半径分布 0.06×28 / 0.08×20 / 0.10×4 / 0.12×4 / 0.15×28 —— **48/84（57%）的半径小于线宽 0.10**，mid 离弦 0.0176–0.0439 mm（中位 0.0234）。0.06 mm 半径在 0.1 mm 线上，肉眼就是倒角。见 §2 的图与读数。
3. **「看起来圆」的门槛是 r ≥ 线宽，而这道门槛在 DDR 束里经常没有空间**。`arc_meander` 的齿形是「直线—90° 弧—直爬 h—90° 弧回来」，每齿加长 `h + r*(pi-2)`，需要的横向空间约 `2*amp`。把 r 下限设成硬墙的代价实测：**84 弧 → 28 弧（0.10）/ 24 弧（0.15）/ 0 弧（0.20）**，受影响的网从 7 条降到 2 条、1 条、0 条。所以正确形态不是「拒绝」，而是**默认取 r ≥ 1.0×线宽，几何不允许时画小弧并计数**（`totals.sub_legible_meanders`、每条网的 `radius_mm` / `radius_floor_mm` / `sub_legible`），显式传 `arc_r_min_mm` 才把它当要求（`reason=no_legible_radius`，并报出地板半径、最小可行半径与该半径买到的 sagitta）。
4. **等长预算现在按段封顶**：一段最多花掉 `(L-0.5)/2` 个振幅的横向空间。没有这个上限时，32 mm 的亏空会在一段 8 mm 的线上变成 **32 齿、齿距 0.25 mm 的梳子**——那不是等长线，是实心块。代价写清楚：同一组 12 条网，加上限前 **467 ops / 232 弧 / 9 条网**，加上限后 **171 ops / 84 弧 / 7 条网**，`matched` 两次都是 **0/1**。**能力被上限换掉了一部分，判词一次没变**。
5. **「不喜欢铺铜」不是偏好，是缺一个 planner**。交付板上 4 个 zone 全部继承自立创复刻（`/GND@In1 1877.16 mm²`、`/+5V_IN@In3 23.65`、`/+1V35_DDR@In3 prio=1 330.39`、`/+3V3@In3 206.72`），**我一次都没调用过 `board_add_zone`**。能力齐备（`board_add_zone` + 官方 `ZONE_FILLER` + `set_zone_priority` + `reserve_region` + `board_fill_zones` + `board_pour_audit`），但 `route/` 里**没有任何「电源分配/铺铜规划」阶段**，也没有「由电流需求推宽度与铺铜面积」的 planner。缺的是流程与判据，不是工具。
6. **平面分割在仓库里只有一种表达**：同层多网 = 各自 outline + `priority`。本板 In3 就是三网共享（`/+1V35_DDR` prio=1、`/+3V3` prio=0、`/+5V_IN` prio=0），In1 只有 `/GND`。新增的 `board_power_copper` 把这件事读成 `plane_map`（每层每网的 owner/优先级/面积/是否真填过），这是第一次有工具能回答「分割在哪、谁跟谁共层」。
7. **最糟的一条读数**：内核轨与模拟电源**零铺铜、全靠 0.1 mm 信号线宽**。`/+1V8_ANA` 91 段**全 0.1 mm**、`/+0V9_ANA` 58 段全 0.1、`/+0V9_PMU` 43 段全 0.1、`/+0V9_LOGIC` 71/75 段 0.1、`/+0V9_CPU` 35/45 段 0.1、`/+0V675_REF` 51 段全 0.1。用 IPC-2221 反算，0.1 mm 外层 1 oz 在 10 ℃ 温升下约 0.9 A —— RK3506 的 VDD_CPU 不是这个量级该用的宽度。
8. **旧的 `power_net_thin` 旗标本身是错的**：它只看 `widest < 0.25`，于是「有平面兜底的电源网」也被骂细（`/+3V3` 有 206.72 mm² 平面，仍会因为 0.1 mm 的 escape 段挨骂）。现在它**要求「没有填充平面」**才成立，同时 `board_net_report` 每行多一个 `plane_mm2`。
9. **`_is_powerish` 认不出 `+1V8_ANA` 这种名字**：老表只有 `+3V3/+5V/VCC/GND…`，核心轨一条都命中不了。也就是说「为什么不用电源铺铜」这个问题的**所有既有报告其实都没看过这些网**。现在按「带符号」或「名字里有电压」（`1V8`、`0V675`）也认，并把「挂在电源上的信号」（`+3V3_PG`、`USB0_VBUSDET`、`3V3_EN`）挡掉——否证见 §7。
10. **顺手修掉仪器的一个谎言**：`snapshot.render` 把 arc track 画成弦。任何「弧线好不好看」的判断之前它都在骗人。现在按采样折线画，并新增 `drawn.arcs` 让「这层有几条弧被画了」变成数字（§4）。

## §3 半径下限：偏好还是要求

第一版把下限设成硬墙（r ≥ 1.71×线宽，即 sagitta ≥ 0.5×线宽），结果**打挂 19 个既有测试**、并且把交付板的等长能力砍到 0 —— 那不是「更严格」，那是「不工作」。改成 1.0×线宽并做成两模式后，同一组 12 网实测：

| 模式 | ops | arcs | 有齿的网 | r 分布 | sub_legible |
|---|---|---|---|---|---|
| 默认（偏好：r ≥ 1.0×线宽，不够就降级画并计数） | 171 | **84** | 7/12 | 0.06×28, 0.08×20, 0.10×4, 0.12×4, 0.15×28 | **7** |
| 要求 `arc_r_min_mm=0.10` | 58 | 28 | 2/12 | 0.12×4, 0.15×24 | 0 |
| 要求 `arc_r_min_mm=0.15` | 49 | 24 | 1/12 | 0.15×24 | 0 |
| 要求 `arc_r_min_mm=0.20` | 0 | 0 | 0/12 | – | 0 |
| 要求 `arc_r_min_mm=0.25` | 0 | 0 | 0/12 | – | 0 |

`matched` 五档全是 **0/1**（这条 lane 组没被拉进 0.10 mm 容差），所以下限**不改判词，只改毛刺**。三种拒绝原因在工具面是分开的：`too_shallow`（这个振幅下没有形状，climb 低于 `ARC_H_LEGIBLE_MM=0.15`）、`no_legible_radius`（给了地板但没有合法半径，带 `r_floor_mm` / `smallest_radius_mm` / `sagitta_of_smallest_mm`）、`does_not_fit`（这段线的空间不够放任何齿）。`keepout`/`crosses_keepout`/`inside_keepout` 这类**硬阻挡优先**（`_HARD_BLOCKERS`）：调用方要改的是布局，不该被一句「太浅」挡在后面。

为什么不能把 0.06 当错误：0.1 mm 线宽要一段 0.5 mm 的修正，最少需要 2 齿 × 0.335 mm ≈ 0.67 mm 的弧长；几何给不出时只有两条路——画小弧，或者什么都别画。**画小弧并说出来**是可用于生产的那个。

## §4 仪器自身的两个缺陷（先修仪器，再谈形状）

1. **`snapshot.render` 把弧画成弦**（`D:/tmp/_snap_arc.py`）。track 循环现在用 `_points` 画折线（`_capsule` 逐段），`_bboxes` 也按 `_points` 取包围盒，`drawn` 里新增 `arcs` 计数，`model` 文案写明。修之前出的图一律作废（`D:/tmp/_arc_meander.png`），因为「弧画成直线段」会让任何形状判断失真——这也是我此前看图说「是圆弧」却拿不出数字的原因。
2. **`board_tune_length` 不给半径**（`_tune_length`）。返回值只报 `meanders`，不报半径，于是「小弧看起来像倒角」这件事在接口上根本不可见。现在 `last` 里有 `radius_mm` / `radius_floor_mm` / `sub_legible`，`totals` 里有 `sub_legible_meanders`，工具信封里也有同名的一行。

两个测试锁住这两处：`tests/test_see_and_judge.py` 的 `test_an_arc_track_is_drawn_as_its_curve_not_its_chord`（同一块弧铜，按折线画的像素必须不同于按弦画的），`tests/test_tune_board.py` 的 `test_a_radius_below_the_floor_is_drawn_and_counted_not_refused`（默认给 `sub_legible=True` 且 `r < r_floor`；显式 `r_min_mm` 则给 `no_legible_radius`）。

## §5 圆弧与 45 度齿的横向空间代价

0.6 mm 通道、8.5 mm 段、0.25 mm 线宽，把 10 mm 亏空补到目标：

- `chamfer`：收 **1.5 mm**，`matched`；
- `arc`：只到 9.73/10.0（还差 0.27 mm），随后以 `too_shallow`（climb 0.0665 < 0.15）拒绝。

结论：**圆弧蛇形要 ~2× 的振幅才能买到同样的长度**。这不是实现缺陷，是几何：三角齿每齿直立，圆弧齿要先用一个 90° 弧把线拐上去、再用一个弧拐回来，拐弯本身不产生长度。所以我给「窄通道里收不满」的既有测试显式改成 `style="chamfer"`，并在测试 `docstring` 里写明理由 —— 那种通道里 `chamfer` 不是「我觉得好看」，而是**唯一存在的形状**。

## §6 电源铜账（回答「为什么不用铺铜和平面分割」）

### §6.1 既有报告看不见这些网

`oracle._is_powerish` 老实现只查子串：`+3V3 / +5V / +12V / VCC / VDD / VBUS / VBAT / VIN / 3V3 / 5V / AGND / GND / VREF`。本板的 `/+1V35_DDR`、`/+1V8_ANA`、`/+0V9_*`、`/+0V675_REF` **一条都不命中** —— 也就是说「电源网细不细」这句话，过去根本没覆盖到真正吃电流的那些网。现在按「名字带 `+`/`-`」或「名字里有电压量」（`^数字V数字`）也认，并把「挂在电源上的信号」（尾词 `DET/EN/SENSE/FB/INT/STAT/PG/ALERT/FLAG/OK/FAULT`）排除：`+3V3_PG` 不导电，`USB0_VBUSDET` 也不是电源——**判据必须能说「这不是电源」**，否则它只会把所有带 V 的信号都骂一遍。

`required_width_mm`（2 A、10 ℃、1 oz、外层）**只在没有平面的网上给**：0.786 mm。内核轨现有 0.1 mm ⇒ 差 **7.9 倍**。这件事不能用「加宽」解决——F.Cu 上没有 0.786 mm 的空间，正确答案是**铺一块面**。

### §6.3 平面分割现状（`plane_map`）

- `In1.Cu`：`/GND` prio 0，1877.16 mm² —— 单网，无分割。
- `In3.Cu`：`/+1V35_DDR` prio **1** 330.39、`/+3V3` prio **0** 206.72、`/+5V_IN` prio **0** 23.65 —— 三网共层，靠 outline + 优先级分开。`/+3V3` 与 `/+5V_IN` 同为 prio 0：**同层同优先级的两块面，这个格式本身无法说明谁优先**，只有 outline 不重叠才没事。
- `In2.Cu` / `In4.Cu` / `F.Cu` / `B.Cu`：**无任何 zone**（In2/In4 是 DDR 走线层，F/B 是信号层）。
- 内核轨一条面都没有：`/+0V9_CPU/LOGIC/ANA/PMU`、`/+1V8_ANA`、`/+0V675_REF` 全部 `traces_only`。

### §6.4 归因

| 层 | 事实 |
|---|---|
| 能力 | 齐备：`board_add_zone`（caller 给 polygon，内部调**官方 `ZONE_FILLER`**）、`board_fill_zones`、`set_zone_priority`、`reserve_region`、`board_pour_audit`、`board_pour_connectivity`、`board_pour_fragments`、`board_cross_split`、`board_power_loop`、`width_for_current` |
| 流程 | **缺**：`route/` 没有「电源分配」阶段。既有的 `plan()` 只做长度/间距，没有「这个网该不该铺、铺哪层、铺多大、平面从哪到哪」 |
| 我 | **一次都没调过 `board_add_zone`**。4 个 zone 全部是复刻立创板时继承来的 |
| 判据 | **缺**：没有「由电流、温升、铜厚推最小宽度与最小面积」的判据；`power_net_thin` 是唯一相关的一条，而它只看宽度、且认不出这些网名 |

所以「MCP 不喜欢铺铜」这个说法准确的形式是：**它能铺但不会自己决定铺什么**。这一轮把它从「不会说」推到「能说」：`board_power_copper` 给出每网的载体类型、面积份额、最窄段载流、需求宽度、平面分割表。**决定铺什么**仍然没有实现，这是下一轮的事（§9）。
