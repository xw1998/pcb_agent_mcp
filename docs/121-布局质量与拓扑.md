# 121 · 布局质量与拓扑：把「像坨屎」变成读数

日期：2026-11-07　版本：0.0.121

## 起因（用户的原话）

> 「为什么让你照着人家的板子画没问题？而自己画的却像坨屎？是缺少什么东西呢？我很明确感知到你缺了什么但是我又无法说出来」

这句话的答案不是「技巧」，是**判据的形状**。照抄时参考板给了真值，偏差可以逐项 diff；
自己画时手上只剩 `board_drc` 和 `layout_review`——**它们只有通过/不通过**。在「勉强合规」到
「行业内正常」这一大片区域里，所有布局得分相同，判据是平的，生成就没有梯度可爬。

`docs/117` §1 的那块 v36 板就是证据：`clearance 0`、`isolated_copper 0`、直角只剩焊盘处
不可避的几个，**而两面地之间一个缝合过孔都没有**。所有检查通过，板子是错的。

这一版补两层，外加一类记录：

| 层 | 工具 | 回答什么 |
|---|---|---|
| 度量 | `board_layout_metrics` | 这块板的节奏、朝向、对齐、留白、密度、簇分离**数值**；给参考集时给分位 |
| 拓扑 | `board_topology` | 哪些器件是同一功能组、组之间怎么连、电源往哪流（**先分区后坐标**的那一步） |
| 记录 | `pattern_add kind='pitfall'` | 差样本：症状 / 原因 / 修法，可绑到某一条度数与分位 |

## 一、度量的定义（全部可从 canonical 板算出）

| 读数 | 定义 | 越好是 |
|---|---|---|
| `spacing_median_mm` | 每个封装**原点**到最近邻原点的距离分布（median/p10/p90/min） | 无方向 |
| `spacing_cv` | 上述距离的变异系数 | 越低 |
| `orientation_on_axis_share` | 旋转角落在 0/90/180/270 ±1° 的比例 | 越高 |
| `alignment_share` | 与至少一个其他器件在一条轴上对齐（轴差 ≤0.25 mm、另一轴 ≤30 mm）的器件比例 | 越高 |
| `edge_margin_median_mm` | 封装 bbox 到板框最近边的距离分布，负值=伸出板外 | 无方向 |
| `density_cv` | 5 mm 网格上器件数计数的变异系数 | 越低 |
| `density_empty_share` | 空网格占比 | 无方向 |
| `cluster_separation_ratio` | 组内最近邻中位 ÷ 组间最近距离中位 | 越高 |

每条都带 `how`（怎么量的）与 `thresholds`（用的那个假设值）。**阈值是判据的假设，不是世界的
测量**：`CROWDED_MM=1.0`、`LONELY_MM=20`、`ALIGN_TOL_MM=0.25`、`GRID_MM=5`、
`ON_AXIS_TOL_DEG=1`、`ADOPT_MM=15`，改一个，下面所有 share 都跟着变，所以它印在答案里。

**为什么这些能替代「感觉」**：人一眼看出「不对」，本质是分布里的**分位**：间距节奏乱了、
朝向有一半不齐、某块区域密度塌陷。这些量一旦算出来，就有排序，也就有梯度。

## 二、分位的口径（三条硬约束）

1. **没有参考集就没有分位**，答案直接说 `no reference set`，不编语料。
2. **无方向的指标不给 percentile**（`spacing_median_mm`、`edge_margin_median_mm`、
   `density_empty_share`）：给 `position_pct` 与 `reference_median`，并明说它不代表好坏。
   一度把它算成 percentile，于是「间距等于参考中位」被读成「100 分」，这是错的。
3. **参考集里全是同一块板的副本不算语料**：用 refs 集合判断，命中就
   `usable_for_judgement: False`，并给出 `same_reference_set_as_this_board`。
   本机实测：拿 `_scratch/f412rg` 里 3 个备份版本当参考，工具报
   「all 3 reference board(s) carry the same references as this one — a backup folder
   is copies, not a corpus」。少于 5 块同样不可用于判断。

## 三、拓扑：人画板真正先做的那一步

`board_topology` 的分组规则（全部印在 `how` 里）：

1. **主控靠扇出找**：焊盘最多的器件（≥16 脚）标记 `mcu`。理由是本机 F412 板上 MCU 的网名是
   `PA0/PA11/+3V3`，没有任何关键词表能覆盖真实网名。
2. 其余器件按**网名命中数投票**分组：`memory`（QSPI/FLASH/SPI/NCS/W25/SSI/NOR/EMMC…）、
   `clock`（XTAL/OSC/HSE/LSE）、`usb`（D+/D-/CC1/CC2/SBU…）、`debug`（SWD/SWCLK/JTAG…）、
   `uart`。投票而不是首个命中：一颗 flash 有 `W25_CS/W25_CLK/W25_IO0..3` 六票。
3. 只碰电源轨的器件 = `power`（GND/VCC/3V3/VBAT…）。
4. 都没命中的器件：**15 mm 内**就并入最近组（记 `adopted`），否则进 `unclassified` ——
   **不猜**。

`flow` 从 `power` 出发按「共享网数」做广度优先，给出 `order` 与 `hops`；连不上的组进
`unreached`，不放到 hop 0 假装连着。

本机实测（`_scratch/f412rg/stm32f412rg_core.kicad_pcb`，32 个器件）：

```
mcu 2（U1 + C8：VCAP1 去耦，被就近并入）  memory 4（U3 + R4/R5/R6）
clock 7   usb 3（J1/J2B/U4）   debug 1（J4）   power 15
links: clock--power 28 网、clock--usb 18、debug--usb 3 …
flow: power → mcu → clock → debug → memory → usb（unreached: 无）
```

分组本身不是布局。它的用途是：**先有簇，才有「哪块区域该留白」**；没有簇，只能逐个放器件，
那就是「合规但丑」的生成方式。

## 四、差样本（`pattern_add kind='pitfall'`）

字段：`symptom`（症状，≥8 字）、`cause`（原因，≥8 字）、`fix`（修法，≥8 字），
可选 `metric`（必须是 `board_layout_metrics` 的一个读数名）与 `below_percentile`。
`metric` 写一个没人能量第二次的名字会被拒——「绑不到读数的症状是故事」。

状态机与 recipe / layout 相同：`add` 只写 candidate，`pattern_verify` 要
`confirm=true` + 理由 + 一条 `{from, reading}`。

本机已入库一条（candidate）：`pat.pitfall.density-collapse` ——
「右半边空着，全挤在左下角」，绑 `density_cv`、`below_percentile=10`。

## 五、边界（写死）

* **没有自动布局**：`board_layout_metrics` 只量，`board_topology` 只分组与排序，
  `pattern_layout_plan` 只算坐标并报冲突。落位仍由人（或人定 anchor 后由 `board_propose`）。
* **度量不是判词**：`authoritative: false`，最终判词只能 `board_drc` 给。
* **分位不是判决**：落在 p10 以下是一个**问题**，不是缺陷；它说的是「离参考集远」。
* **拓扑是启发式**：主控靠扇出、其余靠网名投票；认不出的进 `unclassified`，规则印在答案里。

## 六、还没做

* 参考语料还没有随包发出的一批**不同**板子（seed 那 20 块板的结果只以经验条目的形式存在，
  没有逐板的读数序列）。现在的分位只能由调用者指定参考集。
* `density_cv` 只数器件，不数铜；铺铜的密度梯度是另一件事。
* `cluster_separation_ratio` 用组间最近距离，对「两块板拼在一起」这种形状不敏感。
* 还没把 pitfall 反过来用在生成上（例如「本板命中 pitfall X，先改 X 再布线」）。

## 七、F412 核心板实测：量出来之后，发现「丑」不在布局

2026-11-07 拿 `_scratch/f412rg/stm32f412rg_core.kicad_pcb`（4 层、32 器件、556 段铜、129 过孔）练手。

### 7.1 两个真缺陷，都是量的时候才暴露

1. **footprint 的 layer 被铜图形覆盖**。`adapters/kicad_pcb.py` 里画铜图形的循环复用了变量
   `layer`，于是每个含铜图形的封装都把自己的层改成了 `F.Fab`/`B.Fab`：
   本机实测 **30/32 器件报 `F.Fab`**，`board_components(layer="B.Cu")` 恒空，
   `pattern_layout_from_board` 的 `side` 全靠猜。已修（改名 `glayer`），现在 30 `F.Cu` + 2 `B.Cu`。
2. **5 mm 密度网格对小板不适用**。53×30 mm 的板、32 个器件 ⇒ 77 格、0.42 器件/格，
   **73% 空格是算术必然**，`density_cv` 于是把一块器件铺得挺开的板读成「塌陷」。
   改成按板面和器件数自适应（`2*sqrt(area/parts)`，夹在 4–20 mm）：同一块板
   cell 14.26 mm、2.67 器件/格、空格 33%、CV 0.897 —— 不再误报。

修正后这块板的布局读数：间距中位 3.31 mm、朝向在轴 1.000、对齐 0.844、
簇分离 2.98、密度 CV 0.897。**布局并不塌陷**；`board_topology` 也分得干净
（mcu 2 / memory 4 / clock 7 / usb 3 / debug 1 / power 15，flow = power→mcu→clock→
debug→memory→usb）。

### 7.2 真正丑的是走线，不是位置

渲染顶层就能看到：336 段铜里有大量**贯穿全板的长斜线**，它们在铺铜里切出一片片黑色菱形的
无铜区。人对「乱」的第一眼判断来自这个图案，不是器件坐标。

### 7.3 能做的、且不破坏电气的三件事（都做了）

| 动作 | 工具 | 结果 |
|---|---|---|
| 顶层 + 底层加 GND 铺铜 | `board_propose(add_zone)` → `board_apply` → `board_fill_zones(in_place)` | 4 个 zone 全部填充，总铜面积 2487 → 4368 mm² |
| 缝合过孔 | `board_stitch_vias(place, pitch_mm=4.5)` | +40 个 GND 过孔（129 → 169），DRC 通过 |
| 铺铜净空 0.3 → 0.2 mm | `set_zone_params` + 重填 | F.Cu 铜 811 → 969 mm²（+19%），多边形 8 → 6 块（更整片），DRC 仍 clean |

踩到的三处，都记下来：

1. **`add_zone` 的 points 是 canonical 坐标（mm，Y 向上）**，我按文件坐标给，zone 落到板外，
   填充 **0 个多边形**而工具不报错（outline_area 仍有 1542 mm²）。改 `y` 取反才对。
2. **thermal 连接在这块板上会被 DRC 判死**：加铜后出现 8 个 `starved_thermal`
   （花焊盘只有 1 根桥），`board_apply` 的 DRC 差集闸门直接回滚。改 `connect_pads=solid`
   写入，0 新增违规。
3. **`board_stitch_vias` 的几何判决与 KiCad 的 DRC 有三个不一致的点**：
   pitch 3.0 mm 时被拦三次（clearance 0.1264 / 0.0979 / 0.0150 mm，要求 0.15），
   加 `clearance_mm=0.25`、缩孔到 0.5/0.25 都仍被拦；只有 pitch 4.5 mm 才一次通过。
   即工具认为「可用」的点里有它自己没算到的间距，这是待修的缺陷（不是配置问题）。

### 7.4 结论

这块板的「丑」是**布线秩序**，改它要重画 556 段铜——而自动布线在本仓库是禁令，
所以只能手工重画，不是这一轮能收的活。这一轮把能做的做完了：
铜从「两层内层平面 + 顶底空着」变成「四层都铺满、169 个缝合孔、DRC clean」。
