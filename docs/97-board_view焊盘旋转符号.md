# 97 · `board_view` 的焊盘坐标在旋转封装上差 25.4 mm：两个翻转叠加成一次镜像

> 它回答的问题：同一个焊盘，为什么 `board_view` 说它在 `x = -10.16`，KiCad 说它在
> `x = 15.24`？两者差的 25.4 mm 不是精度问题，是**符号问题**。
>
> 它推翻的前提：**「`board_view` 的焊盘坐标已经对过了」**——对过，但只对过
> `rotation = 0` 的封装，而那块板上绝大多数封装恰好都是 0 度。

---

## 97.0 两句话

1. `_at()` / `_xy()` 已经把文件的 Y（向下）取负成 Y-up，`_rotate()` 又按**文件帧**
   的约定用 `-deg`。两个翻转叠加，于是每个**非零角度**的封装把自己的焊盘绕着封装
   原点**镜像**了一次。
2. 旋转为 0 时 `_rotate` 直接返回原值，错误被完全遮住。这就是它能活这么久的原因：
   现有板上 32 个封装里，出问题的那两个（`J2A` / `J2B`，90°）从来没被断言过。

---

## 97.1 现象：同一个焊盘，两个坐标

跑 STM32F412RGT6 核心板的 `board_view`（`kind = "pads"`），`J2B` 这一排 2.54 排针：

| 焊盘 | `board_view` 报 | `kicad-cli pcb drc` 报文里写 | 差 |
|---|---|---|---|
| `J2B.3` `[PC15]` | `x = -2.54` | `at (7.62, -26.67)` | 10.16 mm |
| `J2B.6` `[PB7]` | `x = -10.16` | `at (15.24, -26.67)` | 25.4 mm |

`J2B` 的封装原点在 `(2.54, -26.67)`，旋转 `90`。焊盘 6 在封装内的局部坐标是
`(0, 12.7)`——按 90° 逆时针转，应该落在封装原点的 **+X** 方向 12.7 mm 处，也就是
`2.54 + 12.7 = 15.24`。`board_view` 把它转到了 **−X** 方向：`2.54 − 12.7 = -10.16`。

**这不是算错了一个数，是镜像了。** 焊盘 3 的局部 `y` 是 `0`，所以它的 x 只被翻转
坐标系推到 `-2.54`（本该 `7.62`），差 10.16 —— 同一批错误的不同投影。

---

## 97.2 根因：两次翻转叠在一起

`fidelity/views.py` 里有两条坐标约定同时生效：

```
文件帧（KiCad）：X 向右为正，Y **向下**为正
视图帧（本模块）：X 向右为正，Y **向上**为正
```

`_at()` 在把封装摆上去的时候，已经把局部偏移的 Y 取过负（`local_y = -file_y`），
这一步把点从文件帧搬进了视图帧。**搬完就已经是 Y-up 了**，此时旋转应当用普通的
逆时针矩阵 `(+deg)`。

但旧代码写的是：

```python
a = math.radians(-deg)      # ← 这是「还没翻 Y」时才对的角度
```

`-deg` 属于文件帧的约定（文件帧里 Y 向下，逆时针看起来就是数学上的顺时针）。把它
用在**已经翻过 Y** 的点上，等于把同一个翻转做两遍 ⇒ 旋转退化成反射：

```
R(-θ) ∘ flip_Y  =  flip_Y ∘ R(+θ)
```

也就是「旋转经过一次镜像后，方向反了」。90° 时反射把 `(0, 12.7)` 送到 `(0, -12.7)`，
再落到封装原点左边 —— 就是上表的 `-10.16`。

修法只有一行：

```python
a = math.radians(deg)
```

---

## 97.3 三条独立证据：错的是视图层，不是画错了板

不先分清「谁错」就动手，等于赌。这里三条互不依赖的读数指向同一个结论：

1. **`kicad-cli pcb drc --format json`**（外部权威）：`items[].pos` 明写
   `J2B` 的 PTH 焊盘 6 at `(15.24, -26.67)`、焊盘 3 at `(7.62, -26.67)`。
2. **canonical 层 `kicad_pcb.parse_board()`**（另一条独立管线）：同一块板给出
   `J2B.3 = (7.620, 26.670)`、`J2B.6 = (15.240, 26.670)`，与 KiCad 一致（Y 取正，
   视图层取负，绝对值相同）。
3. **`tests/test_kicad_pad_placement.py` 的 `PAD_TRUTH`**：这些常量是早先用
   pcbnew 10.0.7 直接打印出来的，其中就有「footprint rotated 90°, pad written
   without an angle → (10, 8)」这类条目。

三条都说 15.24，只有 `board_view` 说 `-10.16` ⇒ 是**视图层的单点 bug**，canonical 层
与文件本身都没问题。这也排除了「焊盘本来就画在那儿，是 KiCad 显示得不一样」。

## 97.4 修复与回归

改 `_rotate` 的符号，并把上面这段证据写进 docstring（下一个人不该再猜一遍）：

```python
def _rotate(x, y, deg):
    """Turn a footprint-local offset by the footprint's angle. ..."""
    if not deg:
        return (x, y)
    a = math.radians(deg)
    c, s = math.cos(a), math.sin(a)
    return (x * c - y * s, x * s + y * c)
```

`_rotate` 全仓只有一处调用（`views.py` 的 pads 分支），改动面最小。

新增回归用例 `test_a_rotated_footprint_puts_its_pads_where_kicad_does`，内联一段最小
`.kicad_pcb`，覆盖三个角度：

| 封装 | 角度 | 焊盘局部坐标 | 断言绝对坐标 |
|---|---|---|---|
| `U1` | 90° | `(0, 8)` | `(10.0, -8.0)` |
| `U2.1` | 45° | `(2, 2)` | `(11.414214, -8.585786)` |
| `U2.2` | 45° | `(2, -2)` | `(11.414214, -11.414214)` |
| `J9.6` | 90° | `(0, 12.7)` | `(15.24, 3.81)` |

`J9` 就是 F412 板上 `J2B` 那个情形（原点 `(2.54, -3.81)`、90°、pad6 局部 `(0, 12.7)`），
并额外断言 `x − 2.54 == 12.7`，把「旋转必须把它送到 +X 侧」这件事显式写死。

修复后同一块板的实测：

```
U1.1  20.9950 / 18.9900
J2A.3  7.6200 /  3.8100
J2A.6 15.2400 /  3.8100
J2B.3  7.6200 / 26.6700
J2B.6 15.2400 / 26.6700      ← 修前 -10.16
J4.2  50.0000 / 14.7600
```

全部与 KiCad DRC 报文逐位一致。

## 97.5 影响面：哪些读数要重算

`board_view` 是**排布、间隙、摆放、扇出**这类判断的输入，所以：

- **不受影响**：旋转角为 0 的封装（那块板上 32 个里 30 个），以及所有不吃焊盘
  绝对坐标的工具（DRC 自己算、zone 填充、导出）。
- **受影响**：任何拿 `board_view` 焊盘坐标去和**别的量**比的地方。已知至少一处
  ——`_scratch/f412rg/warn_probe.py` 用 `x_mm/y_mm` 去匹配「过孔压在焊盘上」，
  修复前跑出来的「只有 1 处」是**错的匹配结果**（它漏掉了所有旋转封装附近的贴盘
  过孔）。这块板 DRC 里 `hole_to_hole` 有 16 条，必须用修好的坐标重跑才能拿到真实
  清单。

## 97.6 教训

1. **`rotation = 0` 是正确的默认值，也是最贵的掩盖。** 一个只在非零角度出错的
   函数，可以在几百个测试全绿的情况下带着镜像错误上线——因为没有任何用例给它
   一个非零的输入。
2. **符号类 bug 不会自己变小。** 它给的是绝对值看着离谱、但「像是精度问题」的数
   （10.16 / 25.4 都是 2.54 的整数倍，非常像「算错了一个网格」），最容易被当成
   舍入误差糊过去。
3. **判定「谁错」必须用外部权威。** 这次用的是 `kicad-cli` 的 DRC 报文 + canonical
   管线 + pcbnew 实测常量三条，缺一条都可能误判成「板画错了」而去改刀路。
