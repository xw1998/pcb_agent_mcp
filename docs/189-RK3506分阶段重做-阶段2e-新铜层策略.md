# 阶段 2e —— 新铜层策略：`layers` 回答「能从哪里起步」，不回答「铜可以放在哪」

本文只回答一个问题：**内层 DDR 的方案为什么老是漏回 F.Cu，是门口径的问题，还是 API 少了一个概念？**

答案是后者，并且 185/186 把这件事归因给「栅格门 vs 精确门」的口径分裂是**错的**——本轮实测把这个归因推翻，改用一条可以直接读的判据收口：把「终端收集层」和「新铜许可层」分开（`new_copper_layers`）。同一块板、同一组 12 网，改之前 4 条网的身上有 F.Cu 铜，改之后 **0 条**，总铜长只多 1.0%。

本轮不升版本、不进 CHANGELOG（沿用 184–188 的先例）。

## §1 结论先行

| 口径 | 层分布（段数） | via | ops | routed | elapsed | 碰 F.Cu 的网 |
|---|---|---|---|---|---|---|
| `layers=F.Cu,In2.Cu,B.Cu`（1 历史行为） | In2.Cu 45 / B.Cu 30 / **F.Cu 16** | 10 | 101 | 12/12 | 19.7 s | **4**（DQ0 / DQ1 / DQ3 / DQ5） |
| `layers=F.Cu,In2.Cu,B.Cu` + `new_copper_layers=In2.Cu,B.Cu` | In2.Cu 43 / B.Cu 44 | **7** | 94 | **12/12** | 89.5 s | **0** |

两条读数：

1. **终端钉在内层并不能把铜留在内层。** 12 网里 12 条都从内层逃逸点起步（`terminal_override` 把两个端点都钉在 In2.Cu / B.Cu），搜索照样把 4 条网的中段走到 F.Cu 上去——因为 `layers` 同时被当成「哪些层可以摆终端」和「哪些层可以放铜」，F.Cu 在第一个问题上的答案必须留（逃逸桩就在那儿），在第二个问题上的答案却是「不许」。
2. **禁掉之后代价很小，而且几乎全落在不该变的网之外。** 12 条网里 **8 条长度逐位不变**（delta 0.000 mm），中位差 0.000；总长 162.730 → 164.424 mm（**+1.69 mm，+1.0%**）；最差是 `/DDR_DQ0` +1.764 mm。via 反而少 3 个（10 → 7）。没有一条网掉。

所以 2e 的正确形态是**加一个概念**，不是**换一把门**。`via_gate="raster"|"exact"` 作为能力保留（见 §4），但它不是本阶段的解——见 §5 的成本。

## §2 被推翻的归因：为什么不是「门口径」

185/186 的原始观察是：钉内层终端后，`exact` 门会让 3–4 条网直接掉（搜索按栅格门摆了一个 via，写入阶段被精确门拒掉），而掉的救法当时是「让它们也可以用 F.Cu」。于是那个阶段写下的归因是「栅格门与精确门口径分裂 ⇒ 搜索规划的 via 写入时被拒 ⇒ 为了让它们活下来只好放开 F.Cu」。

本轮实测这个链条**不成立**：同一块板、同样钉内层终端，`via_gate="raster"`（就是被指为罪魁的那个门）**12/12 全过、0 rejected ops**，一条也没掉。掉网不再复现，`fallback 到 F.Cu` 也就不是被迫的。

F.Cu 铜的真正来源在路径的**中段**：32 格宽的内层走廊装不下 12 条并行走线时，搜索会爬一层到空着的 F.Cu 上走一段再下来。这不是门口径能管的——两个门（栅格 / 精确）都认为那个 via 合法，铜也确实合法，只是**不是这张板要的画法**。

判据因此从「哪个门对」改成「新铜允不允许落在那层」，这正是 §3 拆出来的那个参数。

## §3 两个数字的分工

`plan(layers=...)` 一直是两个问题共用同一个答案：

- **Q1「哪些焊盘是可用的起点」** — `_pad_terminals(board, grid, routing)` 按它收集终端；
- **Q2「这条网的新铜可以放在哪」** — A* 的步进层集合、emit 的段与孔的层。

在一块「焊盘全在外层、工艺要求总线走内层」的板子上，Q1 的答案必须包含外层（否则一个终端都收集不到），Q2 的答案必须排除外层。共用一个数字，就只能二选一，于是选了 Q1 ⇒ 中段爬上外层。

`new_copper_layers` 只回答 Q2：

```
plan(..., layers=["F.Cu", "In2.Cu", "B.Cu"],      # 终端可以从这三层起步
         new_copper_layers=["In2.Cu", "B.Cu"])     # 但新铜只许落在这两层
```

实现上三件事：

1. **栅格仍是全层**。`Grid` 用 `grid_layers` 建（`routing + planes`），所以 via 的 64-gon 精确检查仍然要过 F.Cu 上的铜——「不许用那层」不等于「那层不存在」。这一点如果做反了（按许可层建栅格），via 会以为 F.Cu 是空的，写入阶段被精确门成批拒掉，就退回到 185/186 那种掉网。
2. **步进被限**。`grid.astar(..., walk_layers=)` 只在这几层上走；一个落在许可层之外的节点仍然可以当起点/终点（终端就在那儿），但它**没有出步**，唯一下法是 via。
3. **终端被筛，且筛掉要具名**。终端自己挂的层集合被取交集；交集为空的焊盘不是「悄悄不参与」，而是整条网进 `failed`，`reason.code = no_terminal_on_new_copper_layers`，`detail` 里带 pad 编号、坐标和它原本的层。`stats.terminals_off_new_copper_layers` 给总数。

第三条是本项目的常规口径：**没路由**和**没问**是两件事，前者必须留下名字。用 SMD 单向焊盘（只在 F.Cu）配 `new_copper_layers=["B.Cu"]` 就会走到这条路，5 个单测里有一条专门钉它。

## §4 `via_gate` 作为能力保留

`_via_gate(grid, net, exact=False)` 是 A* 在为一个 via 付代价之前的门：

- `"raster"`（默认，历史行为）：只看占用栅格。便宜、而且**乐观**——它知道这格没被明显占住，不知道 0.6 mm 的环能不能塞进两个「恰好压线」的邻居之间。
- `"exact"`：再加一把 emit 阶段的同一把尺子（`grid.via_blockers`，64-gon，按对端各用各的规则）。栅格先做廉价拒绝，精确检查在栅格说 yes 之后才付钱。

这条能力与 §2 的结论不冲突：它治的是「搜索摆了一个写不进去的 via」，而本板 12 网在 raster 门下 **rejected_ops = 0**，没有这种 via 可治。所以本轮把默认留在 `raster`，`exact` 作为旋钮暴露（`board_route` 的 `via_gate`），并用 4 个单测钉住它的两个反向失败：`exact` 从不跑精确检查（那这个旋钮就是谎话）、`exact` 跳过廉价栅格检查（那它在每个被挡的格子上白付几何成本）。

同一策略下两档实测（12 网，其余参数完全相同）：

| `via_gate` | routed | ops | 层分布 | rejected_ops | sweeps/rips | elapsed |
|---|---|---|---|---|---|---|
| `raster` | 12/12 | 94 | In2.Cu 43 / B.Cu 44 | 0 | 2 / 3 | 89.5 s |
| `exact` | 12/12 | 94 | In2.Cu 43 / B.Cu 44 | 0 | 2 / 3 | **718.3 s** |

两条：**`exact` 给出的 ops 与 `raster` 逐字节相同**（同一份 JSON 序列化相等，含每条段的起止坐标），也就是说这块板上它一个决定也没改变；**代价是 8.0×**。所以它现在有明确的开与不开的判据，不是审美：只有当 `rejected_ops` 里真的出现被精确门拒掉的 via 时才值得开，本板这个数是 0。

## §5 成本：时间花在哪

`new_copper_layers` 的 89.5 s vs 19.7 s（4.5×）**不是每格变慢**，而是搜索变难之后触发了一次重来：

| stats | 历史行为 | inner-only |
|---|---|---|
| `sweeps` | 1 | 2 |
| `rip_passes` | 0 | 1 |
| `rips` | 0 | 3 |
| `ops` | 101 | 94 |

`/DDR_DQ1` 第一次没找到（内层走廊被别的网先占了，外层又不许爬），第二遍 + 一轮 rip-up（拉掉 3 条重叠的网一起重路由）把它救回来了。这就是「禁一层」的真实代价：**搜索空间小了，短视的解也更少了，偶尔要重来一次**。这条读数也说明为什么不能默认开 `exact`——那是给每个候选节点加一次几何测试，与这里的重来成本相乘。

## §7 下一步

1. **`hook` 到布局层**：本阶段证明了「铜可以限制在内层」，但没证明「内层装得下」。12 网挤 32 格走廊仍然要靠 rip-up 救 `/DDR_DQ1`；188 §7 的「band 预留波场」是让它第一次就过得去的那件事。
2. **阶段 3 的既有欠账**（C19–C26 退耦、电源区走线、5 处半路由、`hole_in_pad`、`copper_under_magnetics`、旧锐角、旧 `via_in_pad`、In3 zone 重塑、`track_dangling`）不受本阶段影响，仍是下一批。
3. **`exact` 门的定位**留作能力：只有当某块板的 raster 门真的在规划写不进去的 via（`rejected_ops` 里有 `clearance` 的 via）时才值得打开，判断依据就是这个计数，不是感觉。
