# 35 行为源 `B`：一个表达式从卡面走到雅可比

## 35.1 为什么先做它，而不是接着做传输线

`0.0.28` 之后内置引擎已经能拍平层次、能解参数，但它仍然**只会线性元件加四种受控源**。真实
deck 里最难绕开的那一类是行为源：`B1 out 0 V = 0.5 * V(in) + 1m * V(in)^2`、软启动斜坡
`V = min(10, 1000*time)`、以及几乎每个厂商模型开头都有的 `V = ... laplace(...)`。

在此之前 B 卡是**按名字拒绝**的（`NOT_IMPLEMENTED_CARDS` 里有 `"B"`）。拒绝是诚实的，但它把
一整类 deck 挡在门外，而且挡掉的东西有一个共同点：**它们全靠表达式，不靠新器件物理**。表达式
不需要器件模型表，需要的是一个能算、能求导、能报语法错的求值器——这是可以在 stdlib 里做完的。

所以这一版做 B 源，传输线 `T/O/U` 与 `.noise` 当时仍然不做（它们要新物理，不是新语法）——
后来三个都补上了：`T` `0.0.30`、`O`/`U` `0.0.31`、`.noise` `0.0.32`。

## 35.2 表达式在解析期编成一棵树，不在求解期解析字符串

`B1 2 0 V=...` 的右侧先经过 `_b_translate`（拼写翻译）再经过 `ast` 白名单变成一棵元组树
（`_b_walk`），求解期只对这棵树求值（`_b_run`）。

这个顺序不是性能考虑，是**错误归属**：语法错必须在解析阶段报一次，并且带行号与卡面原文：

```
line 2: B1: cannot read the expression 'V(1)+*2'
```

如果留到牛顿第一次迭代再 `eval`，用户会拿到「不收敛」，然后去查浮空节点——查一个不存在的问题。
`0.0.29` 里表达式有值问题（`1/0`）与方程不收敛是**两个不同的 `reason_code`**
（`EXPRESSION_INVALID` 对 `NOT_CONVERGED`），理由同上：一个要改算术，一个要改拓扑。

## 35.3 节点引用必须按源码文本取，因为 `V(1)` / `V(n-1)` / `V(in)` 在 Python 里都不是节点名

这是本轮最容易被写错的一处。直观做法是「用正则把 `V(` 和 `)` 之间的东西当名字」，然后把这些
名字换成 Python 变量。三种真实写法会立刻打脸：

| 卡面写法 | 直接塞进 Python 会被读成 | 后果 |
|---|---|---|
| `V(1)` | 数字 `1` | 表达式变成常数，静默丢掉节点 |
| `V(n-1)` | `n - 1`（减法） | 要么 NameError，要么算出一个数 |
| `V(in)` | `in` 关键字 | `invalid syntax` |

三种错法的共同点：**错法都是「语法上成立」的**，所以不会在写代码时暴露，只会在某个 deck 上给出
一个安静的错答案。

修法是先做**文本替换**再做语法分析：`_B_NODE_CALL` 把每个 `V(…)` 整体换成一个占位符
`_vbnode<N>_`，同时把 `(n+, n-)` 记进 `refs`；`_b_walk` 遇到以 `_vbnode` 开头的 `Name` 就回查
`refs`，转成 `("v", 节点, 参考节点)`。这样节点名从头到尾按**源码文本**流转，一次都没有经过
Python 标识符。

顺带得到两条：`V(2,3)`（差分）与 `V(2)`（对地）由 `refs` 里的二元组直接区分；`V(9)` 指向一个
别的卡都没提过的节点时，`_Circuit.__init__` 报
`line N: B1 reads node '9', which no other card connects`，而不是读成 0 V 变成一个常数源。

`I(...)` 在这条路径上**按名拒绝**：本求解器的未知量是节点电压与少数支路电流，没有「任意元件
电流」这个变量；悄悄返回 0 会让 `I(V1)` 变成一个零源，那是错答案而不是缺失。

## 35.4 参数在构建期折成数字，不在求解期查表

`B1 2 0 V={k}*V(1)` 里的 `k` 在**解析期**就被折成数字（`_b_fold`）。如果留到求解期，名字不在
作用域时的表现会是「每一轮迭代都算不出值」，报出来是不收敛；而它其实是**构建错误**。

所以折叠点选在构建期，错误消息也就是作用域的错误消息：

```
line 1: B1: 'q' is not a parameter in scope here (.param or .subckt params:)
```

`{}` 在 SPICE 里是分组而不是字典，所以 `_b_translate` 最后把 `{`/`}` 换成 `(`/`)`——参数本身
是 `Name`，折叠之后就是数字，两件事不冲突。

## 35.5 运算符：`&&` `||` `!` `<>` `^`，条件有两种写法

`&&`→`and`、`||`→`or`、`!`→`not`（`!=` 保护）、`<>`→`!=`、`^`→`**`（SPICE 里 `^` 是乘方，
不是异或）、`1k`→`(1*1000.0)`（后缀走同一张 `SUFFIX` 表）。

条件有两条路：SPICE 经典的 `cond ? a : b` 与 `if(cond, a, b)`。

**ngspice-47 没有 `if()` 函数**——实测 `Error: no such function 'if'`。这条直接决定了判据怎么写：
与真引擎对拍的用例**必须**用 `? :` 拼写，否则「两引擎给出不同答案」里混进了方言差异，那不是在
量数值，是在量拼写。

`? :` 的翻译是重排而不是新算子：`(cond ? a : b)` → `((a) if (cond) else (b))`，递归处理嵌套
三元（最内层先展开）。缺 `:` 单独报 `has a '?' with no matching ':'`，因为那是拼写错，不是语法
不支持。

**顺序陷阱（本轮真踩到）**：三元展开出来的源码里含有 Python 的 `if` 关键字，而 `if(`→`_if_(` 的
重命名是同一条流水线上的下一道工序。如果先展开三元、后改名，`(a) if (cond) else (b)` 里的
`if (` 会被改成 `_if_`，得到 `'((4) _if_ ((_vbnode0_>2)) else (1))'` 与
`invalid syntax. Perhaps you forgot a comma?`。所以顺序写死：**先 `if(` 改名，再展开 `? :`**。

## 35.6 AC 里按偏置点线性化，与 SPICE 的定义一致

`AC` 分析不重新解非线性：先解工作点，再对表达式在当前偏置处线性化——`B1 2 0 V=V(1)*0.5` 的
增量增益是 0.5；`B1 2 0 V=0.001*V(1)^2` 在 `V(1)=2` 处是 0.004（`2*0.001*2`）。线性化用的就是
装配时已经在算的雅可比列（`_b_partials`），所以 AC 与 `.op` 不会各有一套导数。

`laplace(...)` 在这一层按名拒绝：它是复频域算子（要看 `s`），不是这个求解器的一个函数。拒绝它
比「在 `s=jω` 上随便算一下」诚实得多——后者会给出形状对、幅度错的频响，而频响正是用户要看的
那个数。

## 35.7 差分：中央差分，失败一侧退化为单侧

`_b_partials` 对每个依赖节点做中央差分（步长按 `1e-7*max(1,|V|)` 缩放）。

问题出在**定义域边界**：`B1 2 0 V=sqrt(V(1))` 在 `V(1)=0` 处，中央差分要算 `sqrt(-1e-6)`，
Python 抛 `math domain error`，整张 deck 就报「表达式无值」——而 `sqrt(0)` 明明有值。

修法是两侧各自 try：一侧成功就用单侧差分（`(f(v+h)-f(v))/h`），两侧都失败才报错。代价是一阶
精度而不是二阶，所以这类图的收敛会比中央差分慢一两轮——这条是**已知逼近**，不是缺陷，也不假装
它是中央差分。

## 35.8 抓到的真缺陷：全局残差尺度让 1 V 级误差被当成收敛

本轮动手查的是一个**看起来完全正常**的答案：`V1 1 0 4000 / R1 1 2 1k / R2 2 0 1k` 的分压，
节点 1 回来 `-3998.999996`。

根因在 `_newton` 的 KCL 残差判据：原来是**全局**尺度 `1e-9 + 1e-6*max|x|`。一个 4000 V 的节点
把 `max|x|` 抬到 4000，门槛于是变成 4 mV——1 kΩ 支路上 1 mA 的残差（也就是 1 V 的误差）轻松
通过，牛顿在还没解开的时候宣布收敛。

改成**按行**：`denom = 1e-9 + 1e-6 * (该行最大的 |A[r][c]*x[c]|)`，`res = max(|acc|/denom)`。
同一张 deck 现在 7 次迭代收敛到 4000.000 / 2000.000。

这个缺陷不是 B 源引入的，是 B 源把它逼出来的：行为源的初始猜测更容易把节点推到伏特级，于是
「全局尺度」这个近似第一次真的踩到它。修完 `test_spice*.py` 全绿，selftest 里加了一条 4 kV 的
守卫（`id 144`）。

## 35.9 负控制：每一条都能失败

| 断言 | 如果机制不在会怎样 |
|---|---|
| `V=V(1)*0.5` 在 10 V 上给 5.000 V，卡值改成 0.25 给 2.500 V | 表达式没真正求值 ⇒ 两个数相同 |
| `V(2)*V(2)` 在 3 V 上给 9.000 | 节点被读成常数 ⇒ 常数平方 |
| `B1` 的 `I=` 得负电流（`I=1m` 让 1 kΩ 上落 −1 V） | 电流方向写反 ⇒ 符号错 |
| `V=time*1000` 在 1 ms 给 1 V，`.op` 里 `time=0` | `time` 没接进瞬态 ⇒ 全程常数 |
| `.subckt` 两实例各读自己的 `V(in)` 得 6 / 10 V | 实例重命名漏了 ⇒ 两实例同值 |
| AC 线性增益 2 与 `0.001*V(1)^2` 在 2 V 处给 0.004 | AC 用了错的导数 ⇒ 差一个因子 2 |
| `? :` 与 `if()` 在 builtin 上同值；`? :` 与 ngspice 差 < 1e-6 | 三元重排错 ⇒ 取错分支 |
| `1/0` 是 `EXPRESSION_INVALID` 不是 `NOT_CONVERGED` | 两类错误混在一起 ⇒ 用户去查拓扑 |
| `laplace()` / `I(V1)` / `V(9)` 都必须报错 | 宽松实现 ⇒ 静默常数源 |
| 4 kV 分压 4000.000 / 2000.000 | 回到全局尺度 ⇒ 误差到伏特级仍判收敛 |

## 35.10 仍然不做

- `laplace()`（复频域）、`I(Vname)`（别的元件的电流）、`ddt`/`idt`（算子）、B 源噪声：
  全部**按名**拒绝，理由写进消息，并且都进了 `NOT_COMPUTED`。
- ~~传输线 `T`/`O`/`U`、`.noise`：仍然委派 ngspice 或拒绝。~~ 已全部进内置（`36`/`37`/`38` 篇）；
  仍然委派或拒绝的只剩多图纸（层级）原理图与失真/蒙特卡洛分析。
- 表达式里不做字符串、不做 `**` 以外的矩阵/向量语义；每个 B 源只有**一个**表达式——
  `B1 1 0 V=2 I=3` 直接报 `gives both V= and I=: a behaviour source is one equation`，
  因为把它交给表达式编译器只会得到一句关于 `2 I=3` 的语法错，而真正的问题在卡面歧义。
- 差分步长是固定缩放（`1e-7*max(1,|V|)`），不给用户调；需要更高精度的场合应当改用显式器件模型。
