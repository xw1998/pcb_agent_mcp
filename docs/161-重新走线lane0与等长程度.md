# 161 · lane0 整条重走 + 等长程度

版本 0.1.24 · 2026-11-14 · 板：`examples/rk3506_som/rk3506_som_routed.kicad_pcb` 的 lane0 版本（工作区 `_v24f.kicad_pcb`）

用户指令：「开始重新走线，然后告诉我等长程度」。

结论先行：**lane0 的 11 根网全部重布完成（旧铜一根不留），9 根做到 17.022 mm（组内极差 0.000076 mm），DQS0 差分对内部做到 12.476 mm（对内 0.000344 mm），DQ3 结构性 23.916 mm 未能匹配**。`copper_clearance(0.1)` 0 对，KiCad DRC **41 violations / 8 unconnected，与 0.1.23 基线 `_v20` 逐类别相同、无新增 clearance**。

## 1. 为什么必须整条重走

0.1.23 的等长只动 DQS0/DQS1/CLK 三对，lane0 是旧铜。把新铜叠加到旧铜上不是「补」而是「替换」：旧铜与新区相撞，实测 3–21 对 0.0 mm 重叠。所以 lane0 的 11 根网必须先全部删掉再重布（`_strip.py` 在空板起点 `_v22_stripped.kicad_pcb` 上剥掉 337 个对象）。

## 2. 两个只有真板才现形的布线缺陷（本轮修掉）

### 2.1 平面层被当成布线层

`route.router.plan` 的 `layers` 缺省 = 板上有铜的所有层，于是信号网被画到 `In1.Cu`(/GND) 与 `In3.Cu`(/+3V3) 两个平面层上，DRC 当场 45 条 clearance。本板 `layers_routing=['F.Cu','In2.Cu','In4.Cu','B.Cu']`、`layers_plane={'In1.Cu':'/GND','In3.Cu':'/+3V3'}` ⇒ 调用必须显式传 4 个信号层。**这条不是 API 缺陷，是调用纪律**：平面层的存在意义就是不许走线，工具把「没指定」解释成「都可以」是可接受默认，但做 DDR 时必须点名。

### 2.2 栅格相位与焊盘相位打架（`grid.py` + `router.py`，本轮新增 `origin`）

`Grid` 缺省把网格原点放在板 bbox 角上。U1 是 0.5621 mm 节距、0.250 mm 盘的 333 球 BGA，焊盘中心落在 `.x749/.x001` 这类相位上，与 0.05 mm 网格差 0.001–0.049 mm。后果极隐蔽：搜索沿焊盘之间画出一条 **距邻盘 0.099 mm** 的线，精确检查按 0.1 mm 判 **差 0.001 mm 拒收**——现象是「明明有 0.10 余量的通道，就是布不进去」。

修法不是放宽判据，是把栅格相位锚到焊盘中心：

```python
Grid(board, layers, pitch, bundle, ..., origin=[18.0749, 24.1001])
# 内部：self.x0 = ox + floor((self.x0-ox)/pitch)*pitch（y 同理）
```

`origin` 只改相位、不改 extent（`x1/y1` 逐位不变，测试 `TestTheLatticeCanBeAnchoredOnThePads` 两例反向对照：锚定后焊盘中心落在格点上，不锚定则偏 >1e-4 mm）。

`route.router.plan(..., grid_origin=[...])` 透传。

## 3. 布线的三个阶段

| 阶段 | 做法 | 结果 |
| --- | --- | --- |
| A | 11 网一次性协商 8 轮（`_r_neg3.json`，555 s） | 10/11 布通，DQS0N 失败，最长 17.051 |
| B | 先让最难的 DQ3 + DQS 对在空板上选路，其余 8 网协商（`_v23_full`） | **11/11 布通**，但 DQ3 = 23.916 |
| C | 等长（`board_tune_length`，`style=arc`） | 见 §4 |

阶段 B 的 11 网原始长度（`_v23_full.kicad_pcb`）：

```
DQ0 11.136  DQ1 12.499  DQ2 12.322  DQ3 23.916  DQ4 15.282  DQ5 15.338
DQ6 13.160  DQ7 15.503  DQS0N 12.476  DQS0P 10.961  DM0 17.022
```

### 3.1 搜索预算是真瓶颈，但 DQ3 不是

`grid.MAX_BUDGET=400000`（≈4 s）下 DQ1 必失败；把预算提到 1.5 M 后 DQ1 24.5 s 布通、11.87 mm。**所以「失败」有 budget 与真阻塞两种，必须分开报**。

DQ3 是后者：1200 k 预算仍 24.157 mm，`VIA_COST` 从 9.0 降到 1.0 仍 24.157 mm，三次读数逐位相同。它的路径是绕通道的大弯（F→B→In2→F→In4 五次换层、6 个过孔）。DQ3 拿到 14.805 mm 的唯一场合是「它第一个布、板子还空」（`_r_trio`），但那样其余 8 网必然吃长弯或失败 ⇒ **lane0 总需求超出这块 BGA 扇出通道的容量，任何分配都有一个网当牺牲品**。

### 3.2 DQS 差分对无弯折空间（精确到过孔）

等长要把 DQS0N 从 12.476 拉到 17.022、DQS0P 从 10.961 拉，两者最长直线段旁边都有别人的过孔：

| 网 | 卡它的过孔 | 需要 | 实际 | 差 |
| --- | --- | --- | --- | --- |
| DQS0N | `/DDR_DM1` via@(19.800,14.000) F.Cu | 0.1000 | 0.0975 | **0.0025** |
| DQS0P | `/DDR_DQ6` via@(19.000,12.600) In2.Cu | 0.1000 | 0.0859 | **0.0141** |

振幅阶梯降到 0.25 mm 仍过不去（`actual_mm` 0.0975 / 0.0815）。⇒ 差分组只能停在自己的最短长度上，**对 17.022 的目标不可达**。

## 4. 等长程度（本轮交付的读数）

用 `board_tune_length`（`style=arc`，`pitch_mm=0.05`，`allow_new_violations=true`，`precheck_clearance_mm=0.1`）分两组写盘：

- 组 1 `DQ0..DQ7 + DM0`，目标 **17.022**（DM0 的原始长度，作为基准）
- 组 2 `DQS0N + DQS0P`，目标 **12.476**（两个网里较长的那根，只能向它对齐）

| 网 | 0.1.23 基线 `_v20` | 重走 `_v23_full` | 交付 `_v24f` |
| --- | --- | --- | --- |
| DQ0 | 13.029578 | 11.135534 | **17.021995** |
| DQ1 | 12.322313 | 12.499138 | **17.022006** |
| DQ2 | 13.484182 | 12.321930 | **17.021996** |
| DQ3 | 22.370597 | 23.916043 | 23.916043 |
| DQ4 | 21.919735 | 15.281981 | **17.021998** |
| DQ5 | 23.480353 | 15.337615 | **17.021998** |
| DQ6 | 14.592055 | 13.159798 | **17.022003** |
| DQ7 | 24.225895 | 15.503301 | **17.022000** |
| DQS0N | 13.256299 | 12.476346 | 12.476346 |
| DQS0P | 13.256298 | 10.960660 | 12.476002 |
| DM0 | 24.190403 | 17.021930 | 17.021930 |
| **全组极差** | **11.903582** | 12.955383 | **11.440041** |
| **DQ 子组极差** | 11.903582 | — | **0.000076** |
| **DQS 对内极差** | 0.000001 | 1.515686 | **0.000344** |

读法（三条，不许合并）：

1. **DQ 子组 9 网（含 DM0）已等长到 0.08 µm 级**，这是等长工具能做到的极限（坐标 6 位小数舍入）。
2. **DQS0 对内配对 0.34 µm**，从 1.516 mm 的不配对修到配对——差分对内部必须配对，这条比「与 DQ 组同长」更硬。
3. **DQ3 与「DQS 组 vs DQ 组」两条没匹配**：DQ3 比组基准长 6.894 mm；DQS 对整组比 DQ 组短 4.546 mm。两者原因不同（前者=通道容量、后者=过孔卡死），都写进 §3.1/§3.2。

**不得读成「DDR 全部等长了」**：lane0 的 11 根里 10 根内部自洽，但 DQS↔DQ 的 4.546 mm 与 DQ3 的 6.894 mm 都是真实缺口；lane1、addr/cmd 本轮一根没动。

## 5. 写盘后必须过的三道门（本轮实测）

1. `copper_clearance(0.1)`：**0 对**（写盘前后都 0）。
2. KiCad DRC：**41 violations / 8 unconnected**，类别 `29 via_dangling + 11 lib_footprint_issues + 1 zones_intersect + 8 unconnected`，与基线 `_v20` 逐类别相同 ⇒ 本轮没引入新问题。
3. 复测长度：`_len6.py`（KiCad 自带 python + `tune_board.measure`）逐网重算，与工具回报值差 ≤1e-5 mm。

### 5.1 一个必须记住的坑：新过孔会让铺铜的填充过期

第一次跑 DRC，交付板报 **86 violations**，多出的 45 条全是 `Via [/DDR_*] on F.Cu - B.Cu` 对 `Zone [/GND] In1.Cu` / `Zone [/+1V35_DDR] In3.Cu`，`实际 0.0000 mm`。原因是旧填充多边形仍盖在过孔位置上——**填铜是文件里的静态几何，加了过孔不会自动重算**。

修法只能是官方 `ZONE_FILLER`（`D:/KiCad/10.0/bin/python.exe` + `pcbnew.LoadBoard` + `ZONE_FILLER.Fill(board.Zones())` + `Save`）。重铺后 86 → 42，剩下的 **1 条**是真违规：`Via /DDR_DQ5 @(23.250,-10.800)` 与 `Pad G8 /GND of U2` 相距 **0.0985 mm**（需 0.1，差 0.0015）。

### 5.2 我们的精确检查与 KiCad 在这一条上不一致

`copper_clearance` 当时报 0 对，KiCad 报差 1.5 µm。两颗球的真实几何：U2 焊盘 `0.4572`（不是 0.25）、间距 0.8 ⇒ 盘心到缝中线 0.4、`0.4 - 0.2286 - 0.1 = 0.0714`……而实际落点离盘心 0.4271、`0.4271 - 0.2286 - 0.1 = 0.0985`。**过孔尺寸 0.2 在这块焊盘间距上要求盘心距 ≥ 0.4286 mm，而网格步长 0.05 给的最近格点只有 0.4271 ⇒ 差 1.5 µm 是网格量子，不是几何不可能**。

修法不是改判据而是换一次布线：把 DQ5 剥掉、单独重布（1.5 M 预算，19.6 s，15.508 mm）后落点换位，重铺 + DRC ⇒ **41 / 8，clearance 0**。随后 `board_tune_length` 把 DQ5 从 15.508 等长到 17.022（2 齿）。

**这条口径写死**：本仓库的 `copper_clearance` 只能当第一道粗筛，**判官永远是 `kicad-cli pcb drc --severity-all`**；两者不一致时以 KiCad 为准，并去查我们的检查漏了哪一类对象（这里漏的是「过孔 vs 大焊盘」的尺寸口径，登记为缺陷）。

## 6. 等长工具本轮修掉的一个真缺陷（`route/tune_board.py`）

现象：DQS0 对明明算得出来（`after_skew_mm 0.000346`，4 次弯折），一 `apply` 就崩——

```
pcb_agent_mcp.edit.ops.OpError: delete_track needs a selector: 'uuid' or 'near'
```

根因：等长循环会把「这一计划刚造出来的片子」再弯一次（同一段 2 mm 要走 10 mm，一次弯不够）。这些新片**在文件里还不存在**，`inv` 里 `uuid` 是 `None`，而循环每接受一次就 `ops.append({"op":"delete_track","uuid": seg["uuid"]})` ⇒ 第二次起就在删一个没有选择器的对象。0.1.23 之前它没暴露，因为那时没有「多齿落在同一原段」的用例。

修法：**ops 改成按「原段」归集、最后一次性发出**。每个 `block` 记住文件里那根段的 `uuid` 与正在生长的 atom 表；再弯只改 atom 表，写盘时一根段只有一条 `delete_track(uuid=<文件里那根>)` 加整条最终路径。

```python
blk["items"][at:at+1] = [{"atom": a, "inv": i} for a, i in zip(made_atoms, inv_added)]
...
for blk in blocks[net]:
    ops.append({"op": "delete_track", "uuid": blk["uuid"]})
    for item in blk["items"]:      # line + arc 按顺序发
```

顺带修两条诚实性问题：`extra <= 1e-6`（段太短放不下一个齿）以前是静默 `continue` ⇒ 现在报 `does_not_fit / segment_too_short_for_a_tooth`；`floor_pairs` 的 `uuid` 对合成片取 `NaN` ⇒ 改报所属原段的 uuid。

回归测试 `tests/test_tune_board.py::TestArcMeander::test_copper_that_needs_more_than_one_tooth_still_writes`：2 mm 段要走 12 mm ⇒ `meanders > 1`、`delete_track` 恰好 1 条且带 uuid、写盘后两网长度差 ≤0.05。

## 8. 没做到，点名

- **DQ3 = 23.916 mm 未匹配**：三次独立复核（400 k / 1200 k / `VIA_COST=1.0`）读数逐位相同 ⇒ 是通道容量的结构性结果，不是搜索没搜到。要修只能改布线拓扑（换层数、改扇出、或把 DQ3 排到最前而让别的网吃长弯）。
- **DQS0 对与 DQ 组相差 4.546 mm**：两个过孔（`DM1 via@(19.800,14.000)`、`DQ6 via@(19.000,12.600)`）把弯折空间卡死，振幅降到 0.25 mm 仍差 0.0025 / 0.0141 mm。
- **lane1、addr/cmd 本轮一根没动**。
- **`copper_clearance` 漏判过孔对大焊盘的间距**（U2 的 0.4572 盘），本轮靠 KiCad DRC 抓到并换位修掉，检查口径本身仍是缺陷（未修）。
