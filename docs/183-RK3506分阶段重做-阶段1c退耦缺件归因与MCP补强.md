# 183 · RK3506 分阶段重做 —— 阶段 1c「退耦缺件」归因与 MCP 补强

承接 `docs/181`（阶段 1 布局）、`docs/182`（阶段 1b 电源布局）。

用户原话：**「卧槽，退耦电容呢？没退耦电容不对啊，这mcp又缺了什么导致的还是你自身导致的？」**

结论先说：**不是布局弄丢的，是设计输入本来就没有；而 MCP 一条规则能看见它、现在缺的就是这条。**
本版把那条规则补上（`layout.hf_per_rail`），并在同一块板上量出 8 个电源域无一例外。

## 1. 三问三答

| 问 | 答 | 数字 |
|---|---|---|
| 是我布局时删掉的？ | **不是**。交付板 `rk3506_som.kicad_pcb` 与工作副本 `_rl1.kicad_pcb` 的 BOM **逐件相同**（45 件一对一，18 颗电容一个不少），阶段 1/1b 只做 `move_footprint` 与 `delete_copper`，没有一次 `delete_footprint` | 45 / 45，18 / 18 |
| 是 MCP 算错？ | **不是算错，是没有这一问**。三条相关规则各自都「绿」：`ics_without_bulk_cap` = **0**（「all 8 IC(s) on a poured rail have a 1 uF or larger capacitor」）、`decoupling_distance` 在 1b 之后读成 `unmeasurable`（换层后被清铜，无铜路径）、`decoupling_via_in_path` 同样 `unmeasurable`。**没有任何一条问过「这个域到底有没有 ≤220 nF」** | 0 / unmeasurable / unmeasurable |
| 那板子为什么没有？ | **输入侧就没有**。电源树文档 `docs/144` 给每个域只配一颗 10uF/4.7uF 输出电容；`docs/144` 第 25/68 行明写 ACODEC 的 VCM「1µF + 100nF」、AVDD1V6「1µF」要去耦，而网表把这两处接成 `NC_1B11` / `NC_1B12`（板上有这两个空球）—— **设计输入自己矛盾** | 8 域 0 颗 100nF |

一句能落地的话：**这条板子的电源分配「有储能、没有旁路」**，而 MCP 的规则集把「有 1uF」当成了「去耦到位」。

## 4. MCP 缺的是哪一条

现有三条能量「电容离得多远」「有没有走线换层」「有没有 ≥1uF」：

| 规则 | 事实 | 在这块板上读到 | 为什么看不见缺件 |
|---|---|---|---|
| `layout.decoupling_distance` | `decoupling_max_distance_to_pin_mm` | `unmeasurable`（「no capacitor reaches a multi-pin part through routed copper」） | 量的是**已有电容的铜路径**；靠铺铜承载的电源网根本没有 track 路径可量（1b 之前读 6.554 mm，1b 清铜之后直接不可测）。**从头到尾没问过「有没有」** |
| `layout.decoupling_same_layer` | `decoupling_via_in_path` | 同上 | 同上 |
| `layout.bulk_per_ic` | `ics_without_bulk_cap` | **0 = pass** | 只认 ≥1uF；一颗 10uF 就把整条轨判成「已覆盖」，而 10uF 在开关沿上是感性的 |

所以这不是「规则算错了」，是**规则集的覆盖面缺一块**：能看见「摆得好不好」，看不见「该有的有没有」。

## 5. 补的那一条：`layout.hf_per_rail`

**判据（P1，High）**：每一条给多个管脚供电的轨，轨上必须有一颗 ≤220 nF 的电容。

- **轨是什么**（`_hf_caps`，`ruleset/measure.py`）：接在 ≥6 脚的器件上、且「网名说它是电源」或「板子自己铺了这块铜」的网，扣掉回流网（最大铺铜面积的那一条 + 任何名字像地的网）。
- **为什么扣回流网**：退耦电容是**对**着回流网量的，把地当轨会把全世界的板都报红。
- **边界网处理（反向失败对照）**：`/USB0_VBUSDET` 名字里有 `VBUS`，但它只接两个脚、身上没有电容、也没铺铜 —— 这是检测线不是轨。它被列进 `note` 而不参与计数，而不是悄悄算成一条「裸轨」。
- **判据故意粗**：轨上任何位置有一颗小电容就算过。**「离得多近」是 `layout.decoupling_distance` 的事**，在这里再问一次会让本规则变成摆位判据，而它要抓的是料表。
- **220 nF 的来处**：`_BULK_FARADS` 是 1uF，1uF 及以上算储能；220 nF 及以下算旁路。100nF 通过、1uF 不通过 —— 这一点由测试从两侧各钉一次。

落点四处：

| 文件 | 改了什么 |
|---|---|
| `src/pcb_agent_mcp/ruleset/measure.py` | 新增 `_hf_caps(board, pours)` → 事实 `rails_without_hf_cap`；挂进 `_assembly_facts`；`facts()` 里 `take("rails_without_hf_cap", ...)` |
| `src/pcb_agent_mcp/calc/rules.py` | 新增 `layout.hf_per_rail`（power integrity / High / count / count_max / 0 / L0） |
| `src/pcb_agent_mcp/ruleset/projection.py` | 新增投影条目（`layer_policy` / `audit_only`）：料表决定，布线器加不了件 |
| `src/pcb_agent_mcp/ruleset/audit.py` | 优先级 **P1**（`_CATALOG_LEVEL`） |
| `tests/test_layout_facts.py` | `TestHfCapacitor` 五个：只有 bulk → 报 1；同轨 100nF → 0；1uF 不算（阈值另一侧）；别轨的 100nF 不算；回流网永远不算轨 |
| `tests/test_skills.py` / `test_rule_projection.py` | 台账条数门 27 → 28 |

规则条数从 27 变 28，两处「条数是门」的断言同步改了 —— 那条注释本来就写着「改动台账就得同步改这里」。

## 8. 这条规则会不会误伤别的板

先例是 `_test_points`：`royalblue54L_feather` 铺了 70 个网，全当轨会报「`/Connectors/ANALOG.A0` 上没有测试点」。本规则同样**不从「铺了铜」直接推「这是轨」**，而是要求「名字说它是电源」或「铺了铜且接 ≥3 脚」。合成测试里四条反向对照（1uF 不算、别轨不算、回流网不算、只有 bulk 不算）就是钉住这一点。

诚实的残留：网名不叫电源的轨（`Net-(U1-Pad7)` 之类）会被漏掉，读数是「少报」不是「错报」；这一点写在 `method` 里，不藏在代码里。
