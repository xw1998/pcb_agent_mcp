# 规则为什么没进生成端：投影台账与两条新通道（0.1.21）

用户原话：「那这些经验规则布局布线时为什么没用上呢？」

这一版不解释「我本来打算用」，只回答四个可以拿文件行号核对的问题：规则停在哪、
27 条各自能不能被生成器吃下、吃到什么形状、本版把哪几条真接上了。

---

## 1. 结论先写

**规则停在审计端。** 27 条 `LAYOUT_RULES` 在全库只有三处消费点：

| 位置 | 用途 |
| --- | --- |
| `src/pcb_agent_mcp/ruleset/audit.py:264` / `:436` | 事后审计，把每条判成 pass/fail/undetermined |
| `src/pcb_agent_mcp/calc/rule_sources.py:209-213` | 出处覆盖 CLI，数「有几条有出处」 |
| `tests/` | 钉住上面两件事 |

生成端（`route/`、`edit/`）在 0.1.20 之前**一次都没有 import 过规则目录**。0.1.19 新增的
`ruleset/design_constraints.py` 把禁布矩形导出来，但只被它自己、它的测试和文档引用，
**没有任何生成器 import 它**——它导出的是一张 JSON，要外部脚本手动读。

**只有一个形式真被投影出去了**，就是「矩形禁布」（6 条规则共用 7 个 owner）。其余
26 条从来没有进过任何搜索空间。

根因不是「忘了调」，是**形状不对**：规则写成「板子上有没有 X」的**测量谓词**
（`trace_under_magnetic` 是数出来的），生成需要「这个候选段允许不允许」的**许可谓词**
或「这个网必须多宽」的**下限**。两者之间缺一层投影，缺了这层，把规则对象直接递给布线器也没用。

---

## 2. 27 条的投影台账（`ruleset/projection.py`）

每条规则被放进一个**形式**格子与一个**状态**格子。形式说它该变成什么形状，状态说今天到哪一步：

形式：`rect_keepout` / `net_geometry` / `paired` / `layer_policy` / `audit_only`
状态：`projected` / `by_construction` / `not_wired` / `audit_only`

`table()` 做漂移检查：目录里多一条而这里没分类 → 抛 `ProjectionError`；这里多一条而目录没有 → 也抛。
一条没人分类的规则不会再被算成「已投影」。

本板（`_v18.kicad_pcb`）实测计数：

```
27 rules: projected 9 / by_construction 2 / not_wired 7 / audit_only 9
```

**projected（9）**——本仓库代码今天真消费：

| 规则 | 形式 | 消费它的代码 |
| --- | --- | --- |
| `magnetic_keepout` / `_deep` / `magnetic_via_keepout` / `crystal_keepout` / `crystal_keepout_adjacent` | rect_keepout | `design_constraints.keepout_rects` → `route.router.plan(keepout_rects=)` → `route.grid.Grid` |
| `min_trace_width` / `min_via_hole` | net_geometry | `route.rules.apply_overrides`（全局下限） |
| `power_trace_width` | net_geometry | 同上，按网名匹配到的电源网给 0.508 mm 下限 |
| `rf_spacing_3w` | net_geometry | 同上，`clearance_factor=3.0`，落成 `3 × 该网宽度` |

**by_construction（2）**——发射器产生不出这种违规，所以规则成立不是因为被读了：

- `rf_right_angle_bend`：`route/corners.py` 只出 0/45/90/135，且不出圆弧。
- `layer_change_return_via`：`plan(return_path=True)` 是默认，`route/return_path.py` 每次换层补回流过孔。

**not_wired（7）**——形状清楚、通道缺，缺什么写在 `why` 里：

| 规则 | 缺什么 |
| --- | --- |
| `magnetic_keepout_graze` | 「擦边距离」是审计的精确测量；矩形只挡焊盘外框，投成矩形会把没做到的报成做到 |
| `crystal_guard` | 地环是要**加**的铜，矩形只能表达「不许进」 |
| `rf_to_board_edge` | 布线器只有**一个**铜到板边数，RF 单独放宽需要逐网板边规则 |
| `rf_z0_tolerance` | `resolve` 收 `impedance_targets` 能从叠层反推线宽，但「哪个网、多少欧」是设计输入，目录里没有 |
| `diffpair_skew` / `diffpair_gap_constant` | 只在板子**声明**了 `diff_pairs` 时成立；从网名猜 p/n 是拿猜测当约束 |
| `rf_bend_radius` | 半径是圆弧，本项目禁用圆弧（用户长期指令），属范围外而非缺代码 |

**audit_only（9）**：`reference_plane_continuous` / `stitching_via_pitch` / `decoupling_distance` /
`decoupling_same_layer` / `bulk_per_ic` / `power_pad_thermal_vias` / `antenna_keepout` /
`silkscreen_over_pad` / `test_points_present`——都是整层属性、摆位属性或非铜对象，布线器动不了。

## 3. 通道一：矩形禁布真进布线器

`route/grid.py:70` 新增 `extra_keepouts`，`route/grid.py:499` 的 `_add_rule_keepouts` 把每个矩形
走**和板内 keepout 完全相同的两条路**：

1. 栅格：`_fill_ring`（`route/grid.py:456`，从 `_mark_keepouts` 抽出来复用）按最大 margin 填死；
2. 判官：`seg_blockers` / `via_blockers` 走 `self.keepouts`，对每段做精确环检。

**为什么必须两条都走**：只标栅格，搜索会绕开，但一段被 propose 出来的段穿过矩形仍然会被报成干净；
只走判官，搜索会一遍遍撞同一堵墙。这是「栅格不是判官」的另一半。

**没 owner 或没规则号的矩形被丢弃并点名**（`grid.dropped_rule_keepouts`）：一个没人能重新推导的
阻塞，也没人能审计。

`route/router.py:393` 的 `plan(..., keepout_rects=...)` 接上，返回值新增
`rule_keepouts {used, dropped, cells_raster}`。

## 4. 通道二：规则数字是下限（`route/rules.py:615`）

`apply_overrides(bundle, overrides)` 支持 `track_mm` / `clearance_mm` / `clearance_factor` /
`via_drill_mm` / `via_diameter_mm`，**每个数都当下限用**：

- 规则比板子 DRC 更松 → 记 `not_applied`，同时报 `rule_mm` 与 `board_mm`。这样
  「没喂进去」和「喂进去没起作用」是两个可分的结论，不是一个含糊的「已应用」。
- `clearance_factor` 而该网没有宽度 → 抛 `RULES_INVALID`：3W 没有 W 不是距离。
- 钻孔 ≥ 焊盘直径 → 抛「没有环宽」。
- 面内 `min_clearance_floor` 永远压过规则，规则不能把间距改小。

## 5. 本版抓到的两个真 bug

1. **电源网一个都没匹配上**。KiCad 的网名是 `/+3V3`（带 sheet 路径），首版电源网正则锚在字符串开头，
   于是这块板 9 个电源网全部没命中，`power_trace_width` 看起来「已投影」实际作用于零。
   加 `bare_net()` 去 sheet 路径；正例 `/+0V675_REF`、`/+0V9_CPU`、`/+1V35_DDR`、`/+5V_IN`，
   反例 `/GND`（铺铜问题不是线宽）、`/DDR_A0`、`/SDMMC_D0`、`/USB0_VBUSDET`。
2. **`bare_net` 第一版是死循环**：`while text.startswith("")` 里空针恒真，整个投影卡在第一个网上。
   改成单次 `rsplit`，并把「会不会终止」这件事交给测试。

## 6. 验证

**单元**（`tests/test_rule_projection.py`，17 个）——每条都带反向对照：

- 27 条全覆盖且计数不是全乐观（`not_wired ≥ 5`、`audit_only ≥ 5`）；
- 目录多一条 / 表里多一条都抛异常；
- 同一个格子：不传矩形时必须 `free`、`seg_blockers` 必须空；传矩形后必须 `not free`、必须有
  `reason=keepout` 且 `why ∈ {inside_keepout, crosses_keepout}`；
- 缺 owner 的矩形：`rule_keepouts==0`、`dropped_rule_keepouts==1`、格子仍 free；
- 层不在布线集 → 跳过而不是放大到别的层；
- 0.2 mm 的规则不能把板子已有的 0.6 mm 改薄，且要报出两个数；
- 3W 无宽度报 `RULES_INVALID`；钻孔 0.9 mm 报「没有环宽」；
- 真实网名正反例；工具返回 27 条且不改文件 mtime。

**回归**：`test_route + test_design_constraints + test_rule_sources + test_ruleset +
test_rule_projection + test_blockers + test_45_corners` = **202 passed**。

**交付板**：`_v18.kicad_pcb`（4209 段）用本版投影出的 7 个矩形逐段做线段-矩形裁剪，
**穿过规则的铜 0 段**。这不是「本版修好了那块板」——0.1.19 已修；这是说这张表现在由
「规则目录 + 板子本身」推导，与手写 JSON 的结果一致，可以替换它。

## 7. 没做（不许读成做了）

- `not_wired` 的 7 条一条没接：差分对仍要板子声明（从网名猜 p/n 是猜），RF 到板边仍是全板一个数
  （布线器没有逐网板边规则），`rf_bend_radius` 因本项目禁圆弧出局。
- `layer_policy` 9 条仍只由审计判：整层与摆位不是候选段的属性，布线器没有对应通道。
- 没有用新通道重画这块板。重画要改 `_mazeH.py`，那是工作区脚本，不是包内代码；
  包内 `route/` 是另一套布线器，用它重画等于换实现，须另立一版并给逐段对照。
- 摆位仍不由规则生成（`legal_window` 只答器件-器件冲突）。

## 8. 怎么自己核

```bash
# 27 条的 status / form / why，加上本板的禁布矩形与逐网下限
python -m pcb_agent_mcp.ruleset.projection BOARD.kicad_pcb

# 工具侧
pcb_rule_projection(path="BOARD.kicad_pcb")

# 测试
python -m pytest tests/test_rule_projection.py -q
```
