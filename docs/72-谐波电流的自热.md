# 一个脉冲串不是一个频率 —— 功率相加，温度不相加

日期：2026-11-01　工具：`ac_self_heating(...)` 新增 `harmonics` / `dc_current_a`（`calc/acthermal.py`，纯 stdlib）

`71` 把「铜在频率上是多少欧姆」接到了「这根铜会热到多少度」上，但它只接受**一个**频率。
现实里最需要问这句话的场合恰恰不是单频：

- 开关电源的纹波是 DC 上叠一串谐波（buck、boost、半桥）；
- 电机驱动的相电流是 PWM 方波，边沿的高次谐波比基波还伤铜；
- 走线里同时有 DC 偏置和一条几百 kHz 的纹波。

把这些折成「一个频率 + 一个 RMS 电流」是行业里常见的偷懒，而**偷懒的代价是可量化的**——
这一篇就是把它量出来，并给出该用什么替代。

---

## 1 判据

| # | 要守住的事 | 能被什么违反 |
|---|---|---|
| 1 | 只有一个谐波时，答案必须与单频路径**逐位相同** | 任何"重新推一遍"而不是"同一套算术"的实现 |
| 2 | 功率相加（`P = Σ I_k²·R_k`），温度不相加 | 任何取最大项、任何拿 RMS 电流乘单一电阻 |
| 3 | DC 项看**整个截面**，高次谐波只看到**趋肤壳** | 拿同一个 `R/R_dc` 套在所有项上 |
| 4 | 总指数必须是**逐项指数的功率加权平均**，且与实测值恒等（1e-9） | 硬编码 0.5、或按项数平均 |
| 5 | 回路增益要**相加**：各自安全的两个电流，合起来可能跑飞 | 只看最大一项，或只看 RMS 后的等效电流 |
| 6 | transition 区**不猜指数** | 把 0.987 硬说成 1 |

第 1 条是这一轮的锚：它不是"差不多"，是 `==`。第 5 条是负控制，见 §8。

---

## 2 模型：同一个求值入口，多跑几次

`71` 的核心求值是

```
g(dT) = dT − I²·Rth·R(Ta + dT)          R(T) 由 _one() 给出
```

频谱版只是把括号里那一项换成求和：

```
g(dT) = dT − Rth · Σ_k I_k² · R(f_k, Ta + dT)
```

`R(f_k, T)` 仍然走**同一个** `_one()`：sheet 走 `69` 的薄板精确解，round 走 `70` 的
Riccati 走针。没有第二条求值通路——这是 §4 能做到逐位的前提。

DC 项单独处理，走 `_r_dc()`：

```
ρ(T) = ρ20·(1 + α·(T − 20))
sheet: R_dc = ρ·L / (W·t)        round: R_dc = ρ·L / (π(a2² − a1²))
```

`R_dc ∝ ρ` 一次方，所以它的 `dlnR/dlnρ` **精确等于 1**，不是 0.999 也不是"看起来像 1"。

---

## 3 功率相加，温度不相加

这是这一篇唯一一个"物理常识"，但它有一个不那么常识的推论。

每个谐波都在**同一根铜**里耗散 `I_k²·R(f_k)`。铜只有**一个**温度点（这是 `71` 就写明的
边界：集总 `Rth`，不是分布式热路），所以正确的合成方式是把功率加起来，再让**这一个**
温度去和**所有**项的电阻自洽：

```
P(T) = Σ_k I_k²·R_k(T)        ← 相加的是瓦特
T    = Ta + Rth·P(T)          ← 只解一次温度
```

不能做的两件事：

1. **不能先算每个谐波各自的温升再相加**。`dT_1 + dT_2` 会把同一个 `Rth` 用两次，等于把
   热路并联了；而且它假设两个温度同时存在，而铜只有一个温度。
2. **不能把 RMS 电流乘一个电阻**。`I_rms² · R(f_some)` 需要先回答「用哪个 f」，而这个
   问题没有正确答案——正是 §7 要量的那个偏差。

---

## 4 单谐波必须逐位等于单频答案（这一轮最强的判据）

如果新分支是"重新推一遍"，它会在第 15 位上漂。所以实现上做了两个刻意的选择：

**(a) 分组与单频路径完全相同。** 单频路径算的是 `k*r`，其中 `k = I²·Rth`、`r = R(T)`；
多频分支算的是 `Σ (I_k²·Rth)·R_k`。**逐项的 k 与 r 与单频路径一字不差**，只是多了一项。

**(b) 指数不做加权平均。** 只有一项时直接返回 `_beta_at()` 的值，而不是走
`w·b/tot`（那会在末位漂 1 ulp）。

结果是最硬的：五个形状维度上，`dT`、`P`、`dlnR/dlnρ`、`dlnR/dlnρ_cold`、runaway 增益、
迭代次数、熔点余量**全部 `==`**。

| 形状 | `dT`（K） | 逐位相同 |
|---|---|---|
| sheet 20×1×35 µm @ 100 MHz | 1.58531 | ✅ |
| sheet `faces="two"` | 0.788378 | ✅ |
| sheet 粗糙度 `rq=1 µm` | 1.61693 | ✅ |
| round 实心 1 mm | 0.506997 | ✅ |
| round 管 0.3 mm / 25 µm 镀层 | 0.146779 | ✅ |

基准点（1 MHz / 3 A / 20 mm×1 mm×35 µm / `Rth` 20）：`dT = 1.83292 K`、
`P = 0.0916456 W`、`β = 0.986895`。这条同时进了自检（rid 1851/1852）与
`TestSpectrumEquivalent` 的 6 个案例。

## 5 DC 项看整个截面，高次项只看壳

buck 纹波那个例子（1 A DC + 0.4 A@500 kHz + 0.13 A@1.5 MHz + 0.07 A@2.5 MHz +
0.04 A@3.5 MHz，20 mm×1 mm×35 µm，`Rth` 60）逐项长这样：

| 项 | 电流 | `R`（Ω） | `R/R_dc` | 功率占比 | regime |
|---|---|---|---|---|---|
| DC | 1 A | 0.0100727 | **1** | **0.8444** | dc |
| 500 kHz | 0.4 A | 0.0100896 | 1.00167 | 0.13530 | dc |
| 1.5 MHz | 0.13 A | 0.0102234 | 1.01496 | 0.01448 | transition |
| 2.5 MHz | 0.07 A | 0.0104865 | 1.04108 | 0.00431 | transition |
| 3.5 MHz | 0.04 A | 0.0108703 | **1.07919** | 0.00146 | transition |

答案：`T = 25.7157 ℃`、`dT = 0.715716 K`、`P = 0.0119286 W`、`I_rms = 1.08784 A`、
`β = 0.998584`。

注意 DC 项那一行：`R/R_dc` **恰为 1.0**（不是 1.0000x），因为它就是 `R_dc`；
而 3.5 MHz 那一项看到 7.9 % 的额外电阻。**这两件事必须同时成立**——如果实现给所有项
乘同一个 `R/R_dc`（= 1.07919），总功率会从 `0.0119286 W` 变成 `0.0128732 W`，
**偏高 7.92 %**（温升同量级偏高），而真实差别只有 0.07 %。
`TestSpectrumPower` 里有一条独立算 `ρ·20/(1×0.035)` 来钉这个值。

## 6 总指数是**测量**，且与逐项是恒等式

`71` 的枢纽是 `β = dlnR/dlnρ`（对 ρ 中心差分），它决定"跑飞"是哪一种。频谱版里
`β` 依然是对**总功率**求的同一个导数：

```
β_total = dlnP/dlnρ
```

因为 `P = Σ I_k²·R_k` 且每项的 `I_k²` 与 ρ 无关，

```
dlnP/dlnρ = Σ_k (P_k/P) · (dlnR_k/dlnρ)
```

——**加权平均，权重是功率占比**。这不是近似，是恒等式，所以它成了一个自检：
`dlnP_dlnrho_weighted_check` 与 `dlnr_dlnrho` 必须相等，容差 `1e-9·max(1,|β|)`。
（容差这么紧是因为它算的是恒等式而不是拟合；早先版本拿 `_sig(x,6)` 后的功率去加权，
6 位舍入把误差推到 ~1e-6，正好卡在容差上——改成用原始功率累加才收干净。）

实测：全高频谱（1 GHz 1 A + 2 GHz 0.6 A，`Rth` 40）拿到 `β = 0.5`、
`beta_deviation = 7.97e-11`（对功率加权期望 0.5 的偏差）；buck 纹波拿到
`β = 0.998584`，期望值同（DC 0.84 + 500 kHz 0.13 都算 1，三项 transition 不进期望）。

两个极性都验证过：`dc` 与 `wall-limited` 记 1.0，`skin-dominated` 记 0.5。
`wall-limited` 记 1.0 是 `70` 的结论：镀层太薄时电流早就铺满整个壁厚，电阻对 ρ 是线性的，
趋肤不参与。

## 7 两个"更简单的模型"各自差多少，往哪边差

用户真正会写的错误答案有两种，工具两个都报，并且**报方向**：

| 简化 | 定义 | buck 纹波 | 全高频谱 |
|---|---|---|---|
| 全当 DC | 用真 `R_dc` 算 `P = I_rms²·R_dc` | **0.0718 %**（`all_dc_model_rel_diff`） | **94.66 %**，低估 |
| 全压一个频率 | 把 RMS 电流全压在功率最大的那一项上 | **0.0957 %**（`single_frequency_model_rel_diff`） | **10.05 %**，低估（`direction="under"`） |

buck 那一列是**控制**：它证明这两个数不是"永远很大"。1 A DC 承担 84 % 的功率，
谐波最高只看到 1.079 倍电阻，所以两种偷懒都在 0.1 % 以内——**这种场合偷懒是对的**，
工具也不该吓人。

全高频那一列是**反例**：两个项都在 1 GHz 以上，`R/R_dc` 分别是 16.27 和 23.01，
频谱真实功率是 DC 模型的 18.7 倍。此时：

- 「全当 DC」差 94.66 %，且**低估**（真实更热）；
- 「全压 1 GHz」差 10.05 %，也**低估**——因为 2 GHz 那一项（占 33.7 % 功率）被按
  1 GHz 的电阻收费（`0.169872 Ω` 对真值 `0.240235 Ω`），**少算了 29.3 %** 的电阻。

方向本身是信息：这两个简化都只会让你**低估**温升，不会高估。所以"我按 RMS 算过了"
不是保守估计，而是乐观估计。

**这两个数只能读成"差多少"，不能读成误差棒。** 它们各自对应一个特定的替代模型，
不构成真值附近的区间。

命名上有个坑：单频分支本来就有一个 `dc_linear_model_*`，语义是"保持同一冷电阻、只丢掉
指数"。频谱版丢掉的东西更多（连频率差一起丢），所以**换名**叫 `all_dc_model_*`，
并且频谱结果里**不出现** `dc_linear_model_*`——同一个键名不能在两处指两件事
（测试里用 `assertNotIn` 锁死）。

## 8 负控制：9 A + 9 A

这是整条分支最该被记住的一条。

0.1 mm 宽 / 20 mm 长 / 35 µm，`Rth` 20：

| 输入 | 结果 |
|---|---|
| 9 A、100 Hz 单频 | 冷回路增益 **0.627201**，稳态 `dT = 436.506 K`（`P = 21.8253 W`），稳 |
| 9 A DC（走 `electrothermal_trace`，本工具按设计拒绝 `dc_current_a` 单独出现） | `dT = 436.506 K`、`P = 21.8253 W`、增益 **0.627201**，稳 |
| **9 A DC + 9 A@100 Hz** | `THERMAL_RUNAWAY`，冷增益 **1.2544**，无稳态 |

文案用的是频谱版的方程：

> no steady state at any temperature: `g(dT) = dT - Rth*P(dT)` is still negative at
> 1110 C (dT 1085 K), and with dlnR/dlnrho = 1.0000 it stays negative for ever

增益恰好是单臂的 **2 倍**（1.2544 / 0.6272 = 2.0000…）：`g(dT)` 里 `I²R` 是二次的，
两个等幅电流各贡献一份，所以 `P` 翻倍、增益翻倍。**这就是"功率相加"在 runaway 上的
表现**：任何只看最大一项、或先算 RMS 再查一次表的实现，都会把这个案例判成安全。

这也是 `71` §4 那条纪律的延续：两种 runaway 是两个答案。频谱版的指数取功率加权，
本例三项指数全为 1（DC 精确 1、100 Hz 落在 `dc` regime），所以措辞选"任何温度都不
自洽"而不是"根在熔点外"。

## 9 transition 区不猜指数

`71` 已经立过这条：粗糙度把 β 拉到 0.361 时 `beta_expectation` 只能闭嘴。
频谱版把它推进一步——**任一项**落在 transition 区，整个"期望值"就不能给：

> at least one term sits in the transition region (frequency_hz = 1e+06), where the
> exponent is neither 1/2 nor 1, so there is nothing to compare the measured 0.987 against

1 MHz 在 35 µm 铜上正是 `s ≈ 1` 的地方（`regime = transition`），实测 β = 0.987 —
比 1 小一点、比 0.5 大很多，任何一个"就近取整"都能自圆其说，所以只能报"测到了什么"。
buck 那个例子里 1.5/2.5/3.5 MHz 三项都在 transition，同样整条不给期望值。

给的是 `beta_deviation = None` + 一句说明，**不是**拿最接近的那个 regime 顶上。

## 10 输出形状：多频不给"单一电阻"

单频答案是 `R`、`R/R_dc`、`skin_depth`、`regime`、`unit_gain_current_a`、`headroom_current`。
频谱没有其中任何一个的对应物：

- 没有"这个频谱的电阻"这个东西（每项不同）；
- 没有"频谱的趋肤深度"（每项不同频率）；
- 没有"把电流加到多少会跑飞"（因为有多个电流）。

所以**这些键在频谱模式下直接不出现**（不是置 `None` —— 置 `None` 会被读成"算不出来"，
而它们本来就不存在），代之以：

```
value.model_kind            "one_frequency" | "spectrum"
value.n_terms               项数（含 DC 项）
value.rms_current_a         sqrt(Σ I_k²)
value.power_cold_w          冷态总功率（诊断用）
value.unit_gain_current_scale   sqrt(1 / cold_gain)
value.terms[]               每项一行
```

`unit_gain_current_scale` 是这个模式的"灵敏度"：**把每个幅值都乘上它，冷增益正好到 1**。
实测 1 MHz/3 A 那例是 `12.0191`（`scale²·cold_gain = 1.0000`），全高频谱是 `7.18292`。
单频分支的 `unit_gain_current_a` 是它的特例（只有一个电流，不用缩放）。

`terms[]` 每行 13 个字段：`kind`、`frequency_hz`、`current_a`、`resistance_hot_ohm`、
`power_hot_w`、`r_over_rdc_hot`、`regime_hot`、`skin_depth_um_hot`、`roughness_k_hot`、
`dlnr_dlnrho_term`、`x_outer_hot`、`x_wall_hot`、`power_share`。

`model_kind` 这个键是**必须**的：两种模式的 `value` 形状不同，消费方需要一个判别键，
否则只能靠"看有没有 `terms`"去猜。

## 12 十四处"本来就该报错"

频谱是猜测的温床，所以拒绝臂比单频多一倍：

| 输入 | 码 | 为什么必须拒 |
|---|---|---|
| `current_a` 与 `harmonics` 同给 | `ARG_INVALID` | 两种形态互斥，静默选一个就是猜 |
| 顶层 `frequency_hz` 与 `harmonics` 同给 | `ARG_INVALID` | 同上 |
| `harmonics: []` | `ARG_INVALID` | 空频谱等于没给电流 |
| **只给 `dc_current_a`** | `ARG_INVALID` | 那是 `electrothermal_conductor` / `electrothermal_trace` 的活；这条必须排在 `current_a` 必填检查**之前**，否则先报 `ARG_REQUIRED` |
| 同一频率两条电流 | `ARG_INVALID` | 两条同频电流要按**相量**相加，本模型没有相位；把幅值相加最多高估 2 倍损耗 |
| `frequency_hz = 0` | `BAD_PARAMETER` | 0 Hz 就是 DC，走 `dc_current_a`（那里 `R_dc` 是精确的） |
| 条目里有未知键 | `BAD_PARAMETER`（列出键名） | 拼错 `current_A` 会静默变成"没给电流" |
| 条目缺 `current_a` | `ARG_REQUIRED` | —— |
| 条目缺 `frequency_hz` | `ARG_REQUIRED` | —— |
| `current_a < 0` | `ARG_RANGE` | 幅值 |
| `dc_current_a < 0` | `ARG_RANGE` | 幅值 |
| `harmonics` 不是 list | `BAD_PARAMETER` | —— |
| 条目不是 object | `BAD_PARAMETER` | —— |
| `len(harmonics) > 32` | `ARG_RANGE` + hint | 32 是 `_MAX_HARMONICS`，与 schema 的 `maxItems` 同一个数；再往上通常说明该做傅里叶分解而不是喂一张表 |

另有一条：**频谱同样要 `rth_c_per_w`**。`Rth` 缺失不是"用 0 顶上"，而是无法回答。

## 13 明说的边界

**（a）所有谐波共用一个 `Rth`。** 这是集总热路的定义，不是近似：铜只有一个温度点。
真要问"哪一段先热"，那是 `62` 的一维梯度或 `61` 的层间耦合，不是这里。

**（b）没有相位。** 只吃幅值（RMS）。所以同频相加必须由用户自己做（工具拒绝）。
半个周期的正负半波在这里没有区别——对自热而言这是对的（`I²` 不吃符号），
但对"峰值电流是否触到饱和/熔断"是另一回事，那是 `fusing_current*` 的活。

**（c）没有互调、没有邻近效应。** 每一项的 `R(f_k)` 是**孤立**导线在该频率上的电阻。
相邻走线的涡流、同一束线里的 proximity effect 都不在里面。密集并行的高频大电流会
低估——这个低估量级既没算也没报。

**（d）不分解波形。** 工具不做 FFT：给它什么谐波表就用什么。从时域波形出发的那一步
（占空比 → 傅里叶系数）在工具外面。

**（e）DC 与 AC 之间不区分"平均温度"与"峰值温度"。** 还是 `71` 的那句话：稳态、
集总、线性 `ρ(T)`。脉冲的瞬态温升（`Zth(t)` 那条曲线）不在这里。

**（f）32 项上限是工程选择，不是物理。** 超过就报 `ARG_RANGE` 而不是静默截断。

## 14 口径与成本

- 调用一次 buck 五项频谱 **1.8 ms**（本机，`--selftest` 含 5 条相关检查后总时长仍 < 1 s）。
- 每项一次 `_one()`，二分约 15–20 次求值 ⇒ 成本大致线性于项数。
- `dependencies = []` 仍成立：全程只用 `math`。
- 新增测试 **33 例**（`tests/test_acthermal.py` 62 → **95**），自检 **5 条**
  （`242/242` → **`247/247`**），**工具数仍是 173**（同一个工具加参数，不是新工具）。

## 15 结论

- **一个脉冲串不是一个频率。** 每个谐波在同一根铜里各自耗散 `I_k²·R(f_k)`，
  功率相加、温度不相加，然后只解一次温度。
- **偷懒的代价是可量化的**：buck 纹波偷懒是 0.07 %（可以偷懒），全 GHz 频谱偷懒是
  94.66 %（偷懒就是错的），而且**只会低估**。
- **DC 项看整个截面**（`R/R_dc` 恰为 1），高次项只看壳（本例 3.5 MHz 是 1.079）。
- **总指数是功率加权平均**，与逐项指数恒等（1e-9），不是拟合。
- **回路增益会相加**：9 A + 9 A 各自稳、合起来跑飞，增益恰为单臂 2 倍。
- **单谐波逐位等于单频答案**（五个形状维度全部 `==`），单频路径的可见变化只有三处、
  没有一个数值动了。
