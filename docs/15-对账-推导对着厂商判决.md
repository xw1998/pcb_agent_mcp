# 15 对账：推导出来的事实，对着厂商自己的判决

> 一句话：**我们算的间距不是判决，是测量。** 要证明这个测量没错，唯一的办法是拿
> 同一个文件、同一件事，让厂商的引擎自己说一遍，然后两个方向数：**它报的我们漏了几条（recall）、
> 我们报的它没报几条（extra）**。本篇就是这十三块真实板子上的账。

## 1. 为什么非要这么做

[11](11-保真层-转换还是推导.md) 定的规矩是：几何派生量一律带 `authoritative: false`，
因为"D 的量"和"厂商的判决"是两种东西。但"不是判决"不该等于"不用负责"——
如果我们的间距测量系统性偏低 30%，所有 `board_clearance` 的答案都会把人往窄线上赶，
而且**看不出来错**。

所以 `board_cross_check` 不是又一个度量工具，它是一次**对账**：

```
同一份 .kicad_pcb
  ├─ 我们：Oracle 把铜按层展开成多边形，算每一对的边到边距离，按各自网络类的规则判"低于阈值"
  └─ 厂商：kicad-cli 10.0.7 跑它自己的 DRC，拿 clearance / shorting_items 两类
       ↓
  双向配对（位置匹配，容差 0.1 mm）
       ↓
  recall（它报的我们也有吗） + extra（我们报的它报不报） + at_the_limit（我们判不了的）
```

`board_cross_check` 只对 **clearance** 有厂商对应物；`free_space` / `pour_connectivity` /
`cross_split` / `loop_area` 一律回 `not_comparable` 并说出理由——**没人能反驳的度量，
不叫对，叫没验过。**

| ecc83-pp_v2 | 5.4 | 0 | 0 | — | — | 0 | 0 | 0 | `no_signal` |

**合计：厂商报了 56 条可比违规，我们一条不漏（recall 56/56 = 1.0）；我们多报 91 对，全部是"保守侧"。**

读法有三条，缺一条这张表就会骗人：

1. **`no_signal` 不是"通过"，是"没有可比信号"。** 八块板上厂商的 DRC 里根本没出现
   clearance 违规（或者只有 `lib_footprint_mismatch` / `track_dangling` 这类和铜间距无关的检查），
   于是既证明不了我们漏，也证明不了我们准。这八块板的价值在别处：它们是**压力样本**——
   四千到一万个铜 item 上没崩、没超时、也没冒出成片假阳。
2. **`extra` 不是错误，是模型的方向。** 我们报的每一对都比规则窄，但厂商不报，原因是模型差异
   而不是我们算错：我们按"边到边最小距离"算，KiCad 的 clearance 检查对同一网络、对铺铜、
   对 pad 的圆角处理都有它自己的口径。多报的方向是**让人把线放宽**，代价是浪费面积；
   漏报的方向是**让人把线做窄**，代价是板子回来短路。宁可多报。
3. **`at_the_limit` 是明说"我判不了"。** 差距和规则相差 < 0.002 mm 的对（CM5 33 对、
   video 30 对、StickHub 20 对、tinytapeout 10 对）单独计数，不进 recall 也不进 extra：
   双精度下这个差是噪声，判决只能由厂商给。

## 3. 先把"不可比"的摘出去（否则 recall 是假的）

这一节是本轮最长的一段，因为每一次给"漏报"找理由，都必须有独立证据钉住边界。

### 3.1 铺铜（zone / pour）

One-Air-Max 和 tinytapeout 各有 1 条 DRC 违规的对方是**填充区**
（`填充区[GND]...` / zone）。zone 根本不在我们的 item 列表里——不是漏算，是没建模。
它们被单列进 `drc_only_not_modelled`，**不计入 recall**，并在 `verdict_text` 里写出来。
如果把它们算成我们漏报，这两块板的 recall 会永远是 0.92，看起来像解析器不准，实际是模型范围小。

### 3.2 铜对铜的"刚好接触"（`shorting_items`）

KiCad 把同一件物理事实拆成两类：`clearance`（间距 0.0000，刚好接触）与
`shorting_items`（重叠）。microwave 的 8 条里有 6 条是 `shorting_items`——
第一版只数 `clearance`，于是 recall 0.5，看着像我们漏了一半。
把两类合并成 `comparable_checks` 之后 8/8。**这是分类按字段名走的错，不是按物理条件走。**

### 3.3 差分对内部（`diff_pair_gap` 而不是 class clearance）

CM5 上我们一度报出 **5419 对** 0.0 间距的假违规。根因之一：同一条差分对
（`D+`/`D-`、`CLK_P`/`CLK_N`）的**走线和过孔**，厂商用 `diff_pair_gap` /
`diff_pair_via_gap` 判，不用网络类的 clearance 判。

但豁免不能写宽。第一版"同一差分对全豁免"直接把 RoyalBlue 的 13 条降到 9 条——
那 4 条是 USB-C 连接器上**同一对的 pad 与 pad**，厂商确实按 class clearance 报。
两条独立证据把这个边界钉死：

| 证据 | 现象 | 结论 |
|---|---|---|
| CM5_MINIMA_3 | 走线/过孔的差分对内间距，DRC 一条不报（我们曾报 5406 对） | 非 pad-pad 的差分对内部必须单列 |
| RoyalBlue54L | DRC 13 条里 J3.A6 vs J3.A7（同一 USB 对的两个 pad）确实被报 | pad-pad 不豁免 |

于是 `_dp()` 首行就是 `if kind_a == kind_b == "pad": return False`。
CM5 落成 `no_signal`（extra 0、差分对 5406 条只在 `ours_only_diff_pair_*` 里报数），
RoyalBlue 仍是 13/13。

### 3.4 板边与孔规则、阻焊与钢网

`copper_edge_clearance` / `annular_width` / `drill_out_of_range` / `solder_mask_bridge`
这些检查**完全没建模**（我们根本没有板边距离、环宽、孔环这几类几何）。
它们在 `drc.check_types_in_report` 里被点名、在 `other_check_types_ignored` 里列出，
进 `not_measured` 三条之一。`comparison` 只比 `clearance*`（不含 edge）与 `shorting_items`。

### 3.5 局部 clearance 优先于网络类

CM5 的 U702 封装在 `(footprint ...)` 节点上写了 `(clearance 0.125)`，而它属于 0.13 的类。
厂商接受 0.125 ⇒ 局部规则优先。剩下 7 对假阳正是这些 pad，读上局部的 `clearance`
之后归零。同一条规则也写在 `(pad ...)` 里，两级都解析。

### 3.6 `F&B.Cu` 是通配层，`np_thru_hole` 且 size==drill 的焊盘没有铜

CM5 的另一个 5419 来源：两个模块封装里安装孔焊盘的层写的是 `F&B.Cu`（正反两面通配）。
把它当层名去比较，等于给一个不存在的层造了成对 item；而那些 `np_thru_hole` 且
宽高 ≤ 钻孔的焊盘**根本没有铜**，KiCad 的 DRC 不比较。修法：`F&B.Cu`/`*.Cu` 展开成
`F.Cu`+`B.Cu`（只取 stackup 里真有的），无铜 NPTH 直接跳过。

### 3.7 网络类成员不在 class 里

KiCad 7+ 的 `.kicad_pro` 把成员关系放在 `net_settings.netclass_assignments`
（net 路径 → 类列表）和 `netclass_patterns`（通配）。不读它，RoyalBlue 的
`USB_DIFF`(0.2032) 类里一个 net 都没有，全部按 Default 0.15 判 ⇒ 13 条全被
"自家 class 规则"清掉，recall 0.0，看起来像解析器全错，实际是规则没读全。
读上之后 13/13。

## 4. 焊盘的几何：另找一个裁判（`pcbnew`）

间距对账只能证明"错了会被发现"，不能证明每个焊盘位置都对。位置单独对：

`tests/test_kicad_pad_placement.py` 用 **KiCad 自己的 Python API**
（`pcbnew.LoadBoard()` → `fp.Pads()` → `GetPosition()/GetSize()/GetOrientation()/HitTest()`）
作为真值，在四块 demo 板上把每个焊盘的轮廓取出，再对我们的 `pad_points()` 做
**9×9 外扩探测**（内缩、边界、外扩各档），逐点问 `HitTest()` 同一个点算不算在焊盘里：

```
412 个 pad（含圆/矩形/圆角矩形/椭圆/自定义多边形/带 drill offset 的）
20188 次 HitTest 探测
0 处不一致
```

坐标系口径：`pcbnew` 报的是文件帧（Y 向下），canonical 是 Y 向上，所以 `canonical_y == -pcbnew_y`。
这条口径本身就是一个坑：文件帧里 `Y` 取反时**旋转的方向也反了**，一个 `y = -y` 顺手把
全局角度取反，2118 个 pad 里 1030 个跑到 111 mm 外，而所有自洽性检查全绿——
只有拿 pcbnew 的数字比才现形。

## 5. 厂商抓到的七处（每一处都是"我们自认为对"）

| # | 我们以为 | 实际 | 追下去的样子 | 修完 |
|---|---|---|---|---|
| 1 | `y = -y` 只是镜像 | 旋转的正负号跟着翻 | 2118 pad 里 1030 个偏到 111 mm 外，DRC 干净的板报出成片假违规 | pcbnew 逐点对账 412 pad / 20188 probe / 0 mismatch |
| 2 | 封装铜图形只要跟着封装旋转 | 还要跟着封装**平移** | microwave 四个 `POLY` 全堆在板原点（x −135.75..135.75，真位置 x≈67/338），pad↔poly 两条真违规永远够不着，还多出 4 对 polygon↔polygon 假违规 | 平移补上，pad↔poly 8 对 0.0 全命中 |
| 3 | `dist_point_polygon` 能判"点在不在里面" | 它量的是到**边界**的距离 | pad 中心到自己边界 0.306 mm > 容差 0.1 ⇒ 全判 miss，microwave 只 matched 4/8 | 先 `point_in_polygon`，再退回边界距离；8/8 |
| 4 | `shorting_items` 是另一件事 | 和 clearance 0.0000 是同一物理条件 | microwave recall 0.5 | 合并计数；8/8 |
| 5 | 网络类里写着成员 | 成员在 `.kicad_pro` 的 assignments 里 | RoyalBlue 13 条全漏，recall 0.0 | 读 assignments + patterns；13/13 |
| 6 | `F&B.Cu` 是一个层名 | 它是"正反两面"的通配 | CM5 假阳 5419 对 | 展开成 F.Cu+B.Cu；跳过无铜 NPTH |
| 7 | 差分对内一律不比 | pad-pad 仍按类规则 | RoyalBlue 13 → 9 | `_dp` 首行排除 pad-pad；13/13 |

共同点：**这七处没有一处会崩、会抛异常、会让自测变红。** 它们全都产出"自洽但错"的答案。
唯一能把它们逼出来的东西，是外部的、我们没参与写的那个引擎。

## 6. 实测上限（这条也是测出来的）

一块 **88.7 MB** 的真实板（jetson-agx-thor-baseboard，四层以上、上万个 item）上跑 DRC：
两次都没拿到报告——**823 s** 与 **2543.8 s**，第二次是 `ENGINE_FAILED`。
所以本服务的 DRC 调用默认超时 900 s，超时后 `status=error` + `reason_code`，
**不降级、不缓存上一次的结果**。大板请先用 `board_stats` 判断规模。

## 7. 还是推导的部分（不算在 recall 里）

`ours.not_measured` 恒定三条，随每个回答一起返回：

1. **zone / pour 铜**——走线与填充区之间的间距完全不比；
2. **板边与孔规则**——`copper_edge_clearance` / `annular_width` / `drill_out_of_range`；
3. **阻焊与钢网层**——`solder_mask_bridge` 等。

另外四个派生量**没有厂商对应物**，`board_cross_check` 对它们回 `not_comparable` 并说明：
`free_space`（KiCad 没有"这能放什么"的查询）、`pour_connectivity`（DRC 的
`isolated_copper` 问的是"孤立铜"，不是"pad 是否真在填充里"）、`cross_split`、`loop_area`。
它们的可信度只能靠模型本身说清（`precision` / `assumptions`），不能靠对账。

## 8. 复现

```bash
python -m pytest tests/test_kicad_pad_placement.py -q   # 412 pad / 20188 probe（需装 KiCad）
python -m pytest tests/test_crosscheck.py -q            # 对账口径与不可比项的单测
```

对十三块 demo 板重跑全量 sweep 的脚本在 `_scratch/run_cc_sweep.py`（不进包，
依赖本机 `D:\KiCad\10.0`）；表由 `_scratch/cc_table.py` 汇总。
两块板的单份结果（含每一对的 `gap_mm` 与每一条 DRC 的 `description`）落在
`_scratch/cc_real/*.json`，用于事后核对某条具体违规到底是怎么配上的。
