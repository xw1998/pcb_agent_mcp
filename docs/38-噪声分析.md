# 38 噪声分析 `.noise`：一次伴随求解，把「哪来的噪声」变成可对账的数

## 38.1 为什么噪声要单开一篇：它问的不是「电压多少」，是「这个电压有多可信」

前三十七篇里每个答案都是「某点的电压/电流/温度是多少」。噪声换了个问法：

> 这个节点的电压，有多少是电路自己生成的、无法被信号区分的抖动？

这个问法有三个后果，正好对应本篇的三条硬约束：

1. **它必须有一个偏置点**。热噪声 `4kT/R` 与电阻的电压无关，但散粒噪声 `2q|Id|`、MOS 的
   `(2/3)gm` 都在**工作点**求值。所以没有 `.op` 就没有噪声——不是「不准」，是没有定义。
2. **它必须有一个传递函数**。噪声是一个电流源，它对输出的贡献是 `|Z_transfer|²·S_i`，
   同一个 `4kT/R` 在短路旁边贡献 0、在开路旁边贡献满。所以本模块的密度**不是**把各元件的
   密度加起来，而是每个源都过一遍传递。
3. **它必须有一个频带**。谱密度是「每赫兹」的量，用户真正会用的是一个带内的 rms。
   而带内 rms 是积分，积分就必须说清「积到哪、用什么规则积」。

所以 `.noise` 的答案不是一个数，是四样东西：逐点谱密度、带内 rms、每个元件的份额、
输入折算密度。少一样都会被读错：

- 只给谱密度 → 用户不知道总噪声；
- 只给 rms → 用户不知道是哪一段带、哪个器件贡献的；
- 给份额不给折算 → 用户不知道「换成输入端相当于多少」。

## 38.2 语法，以及为什么它比 ngspice 宽松一点点

```
.noise V(out)        <source> dec|oct|lin <n> <fstart> <fstop>
.noise V(out,ref)    <source> ...
```

- 输出可以是单端 `V(2)`，也可以写差分 `V(2,3)`（内部按 `e[2] += 1, e[3] -= 1` 处理，
  地记作 `None` 而不是 0 号节点）。写成 `I(1)` 按名拒绝——噪声是**电压**密度，
  `I(1)` 不是输出；写成 `V(0)` 拒绝——它只指地，输出恒零，这种「漂亮的安静」正是本模块
  要消灭的东西。
- `<source>` 必须是 `V` 或 `I` 卡。这是**输入参考源**：它的单位激励定义了增益，
  进而定义了输入折算密度。
- `dec|oct` 在 `ln f` 上均匀，`lin` 在 `f` 上均匀；频率网格与 `.ac` 共用同一个
  `_sweep_freqs`，所以同一张卡上的 `dec 10` 在两个分析里是同样的 61 个点。
- 点数为 1 时允许，但积分恒为 0——答案里会带一条告警说「一个点没有带」，
  而不是返回一个看起来正常的 `0 V rms`。

**与 ngspice 的差别（写在这里，因为它是行为差异不是缺陷）**：ngspice 要求 `.noise` 的输入源
**带 `AC` 说明**，否则 `Warning: Noise input source v1 has no AC value` 然后
`doAnalyses: ac input not found`，整份 deck 中止。内置不要求：输入源的作用只是定义单位激励，
我们自己在右端项里盖一个单位向量（`bu`），所以 `.noise V(2) V1 ...` 在 `V1 1 0 5` 上也能跑。
这条差异在实测中被反复踩到——`diode.cir` / `mos.cir` / `bjt.cir` 三份对拍 deck 第一次都给
了 `ngspice exited with 1`，加上 `AC 1` 才出来。**所以委派路径的 deck 要带 `AC`，内置不必。**

## 38.3 为什么是伴随法，而不是「每个噪声源解一次」

朴素做法：N 个噪声源，每个在 a/b 两节点之间注入 1 A，解一次 AC，读输出，N 次求解。

实际做法：**转置一次矩阵，解一次就拿到全部**。

设 `A` 是 `.ac` 那套复数 MNA 矩阵，`e_out` 是输出选择向量（`V(2)` → 第 2 行 1），解

```
Aᵀ y = e_out
```

那么在 a、b 两节点之间注入的任意电流源，其输出响应就是

```
h_ab = y[a] - y[b]
```

于是每个源的贡献是 `|h_ab|²·S_i`，**一次线性求解覆盖全部源**。三条性质：

1. **它不可能与 `.ac` 打架**：`A` 就是 `.ac` 的矩阵，`y` 只是它反着读。测试里
   `gain_mag` 与同一张 deck 的 `.ac` 的 `|V(2)|` 在 61 个点上逐个对齐（`_close(..., 1e-9)`）。
2. **它是精确的**：偏置点定下来之后，电路是线性的，噪声方程是小信号方程，没有近似阶。
   所以误差**不在数值上，在模型上**（见 §38.8）。
3. **它对源的数量不敏感**：一个 100 个电阻的网络与 1 个电阻一样，每频点一次求解。

增益 `gain = |Σ y[k]·bu[k]|`，`bu` 是输入源的单位激励（电压源置其支路行 1.0；
电流源在两端节点加 ±1）。输入折算密度 = `onoise / gain`。

## 38.4 机制：只有四条，而且每条都写明公式

| 元件 | 机制名 | 谱密度（A²/Hz） | 注入点 | 出处 |
|---|---|---|---|---|
| `R` | `thermal` | `4kT/R` | 两端 | Nyquist |
| `D` | `shot` | `2q·\|Id\|` | 阳极→阴极 | 散粒 |
| `Q` | `shot_collector` | `2q·\|Ic\|` | 集电极→发射极 | 散粒 |
| `Q` | `shot_base` | `2q·\|Ib\|` | 基极→发射极 | 散粒（与 `Ic` 的独立） |
| `M` | `channel_thermal` | `4kT·(2/3)·gm` | 漏→源 | 饱和区沟道热噪声 |

`kT` 用 CODATA-2018 的精确值（`1.380649e-23`），`q = 1.602176634e-19`，
温度取电路自己的温度（`.temp` 或 `temp_c`），不是常数。

**没有的东西说清楚，比补上去更重要**：没有 `1/f`（flicker）、没有 burst、没有
induced gate noise、没有雪崩噪声、没有电阻的 `1/f` 分量。所以对低频 CMOS 电路，
本模块给的是**下限**——真实器件在 kHz 以下的噪声可能高一个数量级。

理想源、`C`、`L` **按构造无噪声**：答案的 `assumptions.noiseless_by_construction` 直接写这句。
电容的 ESR 噪声是那颗 ESR 电阻的噪声——那是你写了或没写的 `R` 卡，不是我们替你补的。

## 38.5 对账一：解析解，逐位

RC 低通（1 kΩ / 1 µF，27 °C），`kT = 4.14415e-21`：

| 量 | 解析 | 内置 | 差 |
|---|---|---|---|
| 1 Hz 点密度 | `sqrt(4kTR/(1+(2πfRC)²))` | `4.071291874e-09` | < 3e-9 相对 |
| 单只 1 kΩ 的 `sqrt(4kTR)` | `4.0713722372192895e-09` | `4.071372237e-09` | 1e-10（打印位数） |
| 两只 1 kΩ 并联 `sqrt(4kT·500)` | `2.8788949176724045e-09` | `2.878894918e-09` | 同上 |
| 四只 1 kΩ 串联（= 单只 ×2） | `8.142744474438579e-09` | `8.142744474e-09` | 同上 |
| 带内 rms `dec 10, 1 Hz..1 MHz` | arctan 闭式 `6.42419041041798e-08` | `6.424132021e-08` | −0.0009 % |
| 全带 `sqrt(kT/C)` | `6.437404735994157e-08` | （扫到 1 MHz 的带内值更低是对的） | 0.2 %（1 Hz 以下那 0.4 % 的 `v²`） |

「四只串成 ×2」这条是关键的负控制：**串联不是相加**。一个只会把密度相加的实现会读 ×4
（`4kT/R` 四份噪声电流相加，若忘了它们看到的阻抗也变了），而正确答案是总电阻 4 kΩ 的
`sqrt(4kT·4k)`，正好是单只的 2 倍。

再加一条更锋利的：**理想电压源短路一只电阻时读 0**。`V1 1 0 0` 与 `R1 1 0 1k` 并联，
`4kT/R` 还在（`sources` 里照样列出、`psd` 逐位相同），但传递 `h = 0`，
`contributions_v2_per_hz = {"R1": 0.0}`。把密度相加的实现会在这里读出 `sqrt(4kTR)`——
一个「看着合理」的错答案。

## 38.6 积分规则跟着网格走：一种规则不可能同时适合两种扫描

```
dec/oct 扫在 ln f 上均匀  ⇒  在 ln f 上做梯形：∫S df = ∫S·f d(ln f)
lin     扫在 f 上均匀     ⇒  在 f 上做梯形
```

实测（RC 低通，参照是 arctan 闭式，扫 1 Hz..1 MHz）：

| 网格 | 点数 | 带内 rms | 相对闭式 |
|---|---|---|---|
| `dec 5` | 31 | `6.42395748e-08` | −0.0036 % |
| `dec 10` | 61 | `6.424132021e-08` | −0.00091 % |
| `dec 25` | 151 | `6.424181061e-08` | −0.00015 % |
| `dec 100` | 601 | `6.424189825e-08` | −0.00001 % |
| `lin 200` | 200 | `2.044104426e-07` | **+217.6 %** |
| `lin 1000` | 1000 | `9.471902614e-08` | **+47.1 %** |
| `lin 2000` | 2000 | `7.372208475e-08` | +14.5 % |
| `lin 20000` | 20000 | `6.391816402e-08` | −0.70 % |

`lin` 那一列不是实现错误，是**带宽被扫掉了**：RC 的拐点在 159 Hz，`lin 1000` 的第一个梯形
宽度就是 1 kHz，拐点当场被跨过去。所以：

- 答案里有一个 `method` 字段，写明「这次是 ln f 梯形还是 f 梯形」；
- 文档与工具描述都写「**带就是扫描**」——带外噪声不在这个数里，粗扫描可能错过窄峰。

这条也解释了为什么不能只给一个「最优规则」：同一条代码，`dec` 上必须用 log，`lin` 上必须用
线性，否则上表的两列会互换。测试里两种网格各有一条，且互为负控制
（`test_the_sweep_grid_decides_the_integration_rule`）。

## 38.7 对账二：真引擎，四个电路

`engine="ngspice"` 把 `.noise` 交出去；`cross_check=True` 让两个引擎解同一份 deck，
比的是**输出谱密度逐点相对差**（不是节点电压——噪声没有「节点电压」这个概念）：

| 电路 | 内置 | ngspice-47 | 逐点最大相对差 |
|---|---|---|---|
| 1k/1k 分压 | `2.878894918e-09` | `2.878894417e-09` | `1.7e-07` |
| RC 低通 | `4.071291874e-09`（1 Hz） | 同 | `1.7e-07` |
| 二极管 `IS=1e-14`，0.6 V + 1 kΩ | `2.283233345e-09` | `2.287894e-09` | `0.20 %` |
| MOSFET `W=10u L=1u KP=1e-4`，饱和 | `5.256118952e-09` | `5.256119e-09` | `1.7e-07` |
| BJT `IS=1e-16 BF=100`，10 k/1 k | `2.158232735e-08` | `2.152041e-08` | `0.29 %` |

二极管与 BJT 的 0.2~0.3 % 不是数值误差：`cross_check` 的 note 写死了这条——
**两个引擎各自求自己的偏置点**，所以这个小数目证明的是「传递算对了」，不是「器件模型对」。
MOS 那一行才是逐位对上的（同一个 `(2/3)gm`，同一套 `W/L`，同一个饱和区）。

**`inoise_total` 故意不比较**：ngspice 的输入折算总量是「输出积分 ÷ 一个增益」，
内置是「逐频点除 `|A(f)|²` 再积分」，两者不是同一个量（RC 例子里内置 `4.0803e-06`、
ngspice `4.568e-06`）。所以交叉校验只比谱，并在 note 里写清不比的理由。

委派路径还多一件事：`.noise` 的 rawfile 有**两个 plot**
（`Noise Spectral Density Curves` 与 `Integrated Noise`），所以 `_parse_raw` 现在返回
`bytes_used`，`_raw_plots` 顺着它逐 plot 走。实测第二 plot 的 `Title:` **前面没有换行**
（二进制紧跟），按 `\nTitle:` 切分会把它吞掉。

## 38.8 顺手抓到的真缺陷：MOSFET 的 `W=`/`L=` 被静默忽略

这一轮做 MOSFET 噪声时发现：`M1 3 2 0 0 nmos W=10u L=1u` 里的 `W=`/`L=` **一直没被解析**，
`_mos_currents` 用的是 `KP` 本身，等于所有器件的 `W/L` 都被当成 1。后果：

- 每个真实 deck 的器件**弱 10~100 倍**（`W/L = 10` 是 10 倍跨导）；
- 噪声的 `gm` 直接继承这个错误，于是「器件噪声」全错。

修复后 `el["wl"] = (W/L)*M`，几何量进 `el["geometry"]`，`AD/AS/PD/PS` 这类**不建模**的参数
记进 `_ignored_params`（诚实：不假装我们算了结电容）。验证方式不是「看起来对了」，而是
**用 `.op` 的节点电压数值微分求 `gm`**：`V2` 加 1 mV 阶跃，`Id = (5 − V(3))/1 kΩ`，得
`gm = 1.0005e-03`，而噪声报的 `psd = 1.10507e-23` 对 `4kT(2/3)gm = 1.10562e-23` 差 5e-4；
`W` 加倍 `psd` 严格加倍（`2.21014e-23`）。

这条修复对旧读数无影响：`tests/test_spice.py` 里唯一的 MOS 用例不带 `W/L`，
所以基线漂移为零——这也是「静默忽略」能活这么久的原因。

## 38.9 拒绝清单（每条都有用例）

| 情况 | 判词 | 为什么 |
|---|---|---|
| 输出点名的节点没有卡连接 | `NETLIST_INVALID` | 一个没接的节点读 0 V，拼写错误会回来成一个「漂亮的安静答案」 |
| 输入源不在网表里 | `NETLIST_INVALID` | 增益无从定义 |
| 卡缺字段（`got 6 tokens`） | `NETLIST_INVALID` | 少一个数就是另一张卡 |
| 输出写成 `I(1)` | `NETLIST_INVALID` | 噪声是电压密度 |
| 输出写成 `V(0)` | `NETLIST_INVALID` | 只指地，输出恒零 |
| 输入源是 `E` 卡 | `ARG_INVALID` | 只接受 `V`/`I` |
| `fstart >= fstop` 或 `<= 0` | `ARG_RANGE` | 空的带 |
| 扫描词不是 `dec/oct/lin` | `NETLIST_INVALID` | —— |
| 偏置点不收敛 | `NOT_CONVERGED` | `4kT/R`、`2qId`、`gm` 都在偏置点求值 |
| 矩阵奇异（浮空节点 / 电压源回路） | `SINGULAR` | 那里的噪声密度是无穷，给「大数」就是假答案 |
| `.print` | `NETLIST_INVALID` | 内置未实现该指令；同份 deck 走委派可以跑通（有测试） |

覆盖不到的点：**扫描点数超过 `max_points`** 时不是拒绝，而是截断并给出告警
（「只要了前 200 点，积分只覆盖已解出的带」）。

## 38.10 负控制：每一条判据都有一个能失败的样子

| 判据 | 能失败的样子 |
|---|---|
| 单只电阻 `4kT/R` | 常数/温度/`4` 任一错都差一个因子 |
| `sqrt(4kTR)` | 少乘 `R` 就是电流密度 |
| 1k‖1k = `sqrt(4kT·500)` | 密度相加会读 `sqrt(4kT·1000)` |
| 四只串联 = ×2 | 密度相加会读 ×4 |
| 短路电阻读 0 | 密度相加会读 `sqrt(4kTR)` |
| 逐点对 RC 解析式 | 少一个极点在 159 Hz 就露 |
| 带内 rms 对 arctan | 规则错/网格错差 0.9 % 以上 |
| `dec` 准 `lin` 偏 | 反过来就说明「规则写死成一种」 |
| `gain` 与 `.ac` 逐点一致 | 伴随法与 AC 用两份矩阵就会分叉 |
| 输入折算 = 输出/增益 | 用「输出积分 ÷ 一个增益」会与逐点除差 12 % |
| 增益为零 → `null` + 告警 | 直接除会印 `inf`，看起来像发现 |
| 二极管 `D/R` 比与频率无关 | Id 取错节点、或漏传递，比值会随 f 漂 |
| MOS `psd = 4kT(2/3)gm` | `W/L` 丢掉时差 10 倍 |
| 27 °C vs 327.15 °C = `sqrt(2)` | 温度写死成常数时差 √2 |

## 38.11 仍然不做

- **`1/f`（flicker）、burst、induced gate noise、雪崩**：给的是下限，不是总量。
- **交流损耗与器件自热**：噪声不随温度迭代（`temp_c` 是输入，不是解）。
- **失真相干噪声、Monte Carlo 器件离散**：`.noise` 只有一个偏置点下的线性化。
- **多噪声输出**：一张 deck 一个输出。要两个就改卡再跑。
- **`noise` 的 `.tran` 版本**（时域噪声）：需要随机轨迹，不是本模块的范畴。
- **`.noise` 不检查 AC 说明**：内置不需要，ngspice 需要——这是差异，不是缺陷（§38.2）。
