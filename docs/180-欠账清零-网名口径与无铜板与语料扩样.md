## 1. `bundle_share`：问题不是「需要网名」，是「问错了对象」

上一版写的是「这个读数需要网名，12 块语料有 8 块为 0」。这一版先量了一遍，**两句话都要改**：

实测 2026-11-16，逐块统计「有多少根 track 带网名」：

| 板 | `board.nets` 表项 | track 数 | 带网名的 track | 不同网名数 |
| --- | --- | --- | --- | --- |
| **sky_star（人画）** | **0** | 929 | **929** | 103 |
| **rk3506_som（本项目自画）** | **0** | 4110 | **4110** | 168 |
| pic_programmer | **0** | 370 | **370** | 33 |
| 其余 11 块语料板 | 14–589 | 59–7932 | 全部 | 8–371 |

**每一块板，每一根 track 都带网名。** 而 sky_star、rk3506、pic_programmer 三块板的 `(net …)` **表**是空的。
旧判据写的是：

```python
nets_known = bool(board.nets) and any(s["net"] not in (None, "") for s in segs)
```

`bool(board.nets)` 问的是**表**。于是本项目自己的两块板（表为空、每根 track 都有名字）被判成「没有网名」，
`bundle_share` 挂上 `degraded` 标志，而它们其实是这个仓库里最不缺网名的两块板。**一个读数报「我读不准」，
比它读不准更糟**——`degraded` 会让引用者把真实读数当成噪声。

新口径问 track，并且只把 `(net 0)` / 空名算作「无名」（KiCad 里 `net 0` 就是「没网」）：

```python
named_segments = sum(1 for s in segs if s["net"] not in (None, "", "0", 0))
nets_known = named_segments > 0
```

读数因此多两格：`nets_known`、`segments_with_net`、`net_table_entries` —— 「表里有几条」和「有多少根 track 带名字」
分开报，读者自己看得到这两件事不是一回事。

### 1.1 那 0.0 不是缺失，是量出来的零

改完口径后 14 块有铜板全部 `net_source: "names"`，`bundle_share` 一格没变（旧代码的抑制逻辑本来就在用网名，
只是**标签**标错了）。所以「8 块为 0.0」这个说法也得改：

| `bundle_share` | 板 |
| --- | --- |
| 0.0（**实测零**，7 块） | complex_hierarchy / ecc83 / interf_u / multichannel / pic_programmer / royalblue_nfc_antenna / sonde_xilinx |
| > 0（7 块） | cm5_minima 0.189、kit_dev_coldfire 0.257、openair-max 0.118、royalblue54L_feather 0.351、stickhub 0.132、tiny_tapeout 0.189、video 0.312（手画 0.245、自画 0.160 不计入语料） |

7 块零来自「两层板、每根线自己走自己的」——0.15–0.70 mm 的带子里确实没有第二张网。这是**真的**，不是没测到。
文档与 `CALIBRATION` 的 note 都改成这个说法，并保留 `degraded` 标志位（真无名时代理仍然只是代理）。

### 1.2 真无名时的替代：连通分量代理

万一遇到真的没有网名的文件（`(net 0)` 满盘），现在不再直接把「o 不是同一个 net」当「凭什么不算并行」——
那样蛇形的牙齿会自己算成 bundle。替代品是**连通性**：

- 同一层上**共享端点**（`JOIN_MM` 内）的两段合并；
- 一段的**端点落在另一段的中段**（t-junction，复用 `_lands_on`）也合并；
- 交叉不算连接（两段在内部相交仍各是各的），所以两张网穿过同一块区域不会被并成一个。

并查集跑完，`bundle_share` 用「同组不算彼此的 bundle」代替「同网不算」，返回值里 `net_source` 写
`"connected copper"`。这是**过并而不是漏并**（一条连续的折线被画成两张网才会误并，而布线器不会这么输出），
所以它仍然标 `degraded`，`why_degraded` 逐句写清代理是什么、什么时候会错。

反向对照（`tests/test_aesthetics.py`）：

- 无网名的**蛇形**（三段连成 U）⇒ `bundle_share == 0.0`，`net_source == "connected copper"`；
- 无网名两根**真不同**的网并行 0.3 mm ⇒ `> 0.9`；拉远到 12 mm ⇒ `0.0`；
- 无网名**支线落在干线中段** ⇒ 同一导体 ⇒ `0.0`；
- 有名字但**表为空**（本项目自己的板就是这个形态）⇒ `nets_known == True`、`net_source == "names"`。

## 2. 无铜板：点名，并且摘掉它在 `route` 上的假绿

`microwave` 是纯教学工程：0 根 track、0 个填充 zone、8 个 pad。它在 `route` 上原本读 **`shape_pass`**
——因为**没有任何形状可以失败**。这与仓库里反复写的「一块没有铜的板不能说它满足了板边规则」
是同一类假绿，只是发生在 `route`。

三处改动：

1. **`copper_inventory(board)`**：`evaluate()` 的返回值里多一个 `copper` 块
   （`tracks` / `vias` / `zones` / `filled_zones` / `pads`，随子进程 JSON 一起回传）。
   `filled_zones` 只数**有 `filled_polygons` 且不是 keepout** 的 zone —— keepout 不是铜，空填充也不是。
2. **`COPPER_STEPS = ("bus", "route", "closure")`**：无铜板在这三步上的 `pass` 一律改判 `n/a`
   并写明「这块板没有铜 => 没东西可判，不是通过」。只降 `pass`，不动 `fail` / `error` / `blocked`。
3. **报告点名**：`run_corpus` 返回 `copper_free`（板名 + tracks + filled_zones + pads + 原因），
   并在 stdout 单独一段打印。没有这份名单，读者看到 `route 14/14` 无从知道里面有没有空文件。

`is_copper_free` 还写了一条反向条件：**inventory 缺失 ⇒ 不是无铜板**。「没看」不等于「空」，
否则一块超时/解析失败的板会被当成干净板。

反向对照（`tests/test_plan_sequence.py`，+6 例）：无铜板被点名且 `bus/route/closure` 的 `pass` 计数为 0、
`frame`（讲 pad 与板框，不讲铜）仍然被正常判；一根 track 就不算无铜；**全由铺铜交付的电源板**
（0 track + 1 个填充 zone）不算无铜——否则会把它唯一的那块铜扔掉；缺 inventory / 空 dict 都不算无铜。

实跑前后：

```
before   route   pass 0  fail 13  n/a 0   judged 13   (microwave 静默算进 pass)
after    route   pass 0  fail 14  n/a 1   judged 14
         copper-free boards (no track, no filled plane) - not counted as passing any copper rule:
           microwave.kicad_pcb      tracks=0   filled_zones=0   pads=8
```

### 3.1 `floorplan`：扩两层板**不可能**解决问题

重跑后 `floorplan` 仍然只判得了 2 块，而且两块都在 high 层。但真因不是样本量：

```
cm5_minima.kicad_pcb         n/a   {"crossing_nets": 0, "nets_priced": 0, "note": "no net reaches a board-edge terminal"}
...（15 块里 13 块都是这一句）
royalblue54L_feather         fail  {"airwire_mm_best": 677.9, "airwire_mm_now": 778.3, ...}
stickhub                     fail  {"airwire_mm_best": 103.4, "airwire_mm_now": 103.9, ...}
```

`floorplan` 的**适用条件**是「有一个网络抵达板边端子」——它比的是「器件摆得好的话飞线能省多少」，
没有板边端子的板没有这个量。15 块里只有 2 块满足，而这 2 块恰好都在 high 层。

所以「扩干净的两层板」这个方案从方向上就不对：**干净的板更多了，但没有一块是带板边端子的**。
要救这一条得去找「干净 + 有板边连接器」的板，而这不是层数问题。这一轮没找到，如实记下。

### 3.2 `stackup`：干净层 n=0 是**结构性**的

`stackup` 判的是「内层参考平面的覆盖率」。最干净的 5 块（low 层）**全是两层板**：complex_hierarchy、
ecc83、interf_u、multichannel、royalblue_nfc_antenna —— 两层板没有内层平面，`stackup` 对它们
本来就是 `n/a`（这条是仓库早就写死的）。

要判 `stackup` 需要一块**干净的多层板**。demos 里唯一的多层候选是 `kit_dev_coldfire`（4 层，
In1/In2 有平面 ⇒ `stackup` pass），但它 161 个 defects 落在 mid 层。所以这一条的实际结论是：

> 不是「样本不够所以以后再补」，而是**当前公开语料里最干净的那一档没有多层板**。
> 干净 + 多层这两件事在演示板上不同时出现：干净的演示板是两层小板，多层演示板都带着大量 DRC 历史债。

这一版把这个结论写进文档，而不是继续加两层板来凑数（那只会让 `stackup` 永远 n/a）。

## 5. 新读数 `pad_stub_mm`：焊盘级扇出几何

上一版写「没做焊盘级扇出几何」。这一版加了一条读数，定义写死：

> 对每个焊盘，取**最短的那根以端点落在该焊盘铜矩形内**（矩形向外放宽 20 µm）的 track 长度，
> 然后在所有「至少有一根 track 接上」的焊盘上取中位数。

- 焊盘矩形用**反旋转**判（按 `-rotation` 把偏移转回焊盘自身坐标），所以旋转过的 0402 不会被当成长条；
- 层要匹配（`*.Cu` 通孔则任意铜层）；
- **没有 track 的焊盘单独计数、不记 0**：过孔接地、测试点、安装孔本来就没有出线，
  记 0 会把中位数拉到无意义；
- 旋转、层、无 track 三种情况都在返回值里分开报：`pads_measured` / `pads_without_track` / `pads_total`。

读数（14 块有铜板）：手画 1.3382、自画 0.3973、语料中位 2.3165、区间 0.288–3.595。

**它必须不排序**（`better_when: "no_direction"`，且不进 `DIRECTED`，也不进 `place_quality`）：
0.4 mm 间距 BGA 被逼成短桩，via fence 是有意的短桩串，两者都不该被判成「丑」。
`bends_per_pad` 已经承担了密度归一化的职责，再来一条排过序的同向读数只会重复计分。

反向对照（`tests/test_aesthetics.py`，+4 例）：单 pad 上 2 mm 与 4 mm 两根 ⇒ 取 2.0（手算）；
两根 pad 只有一根接线 ⇒ `pads_measured 1` / `pads_without_track 1` / 值仍是 4.0（不被没接线的 pad 拉低）；
track 端点离焊盘边 2.5 mm ⇒ **不算接上**，`pads_measured 0`、`value None`（不是 7.0）；
`sorted` 语义自检：`pad_stub_mm` 不在 `DIRECTED`、也不在 `place_quality.readings`。

## 6. 为什么**不做**图像美学

「对齐、间距节奏、丝印层次」是人眼立刻能看见的东西，但它们**已经有了实现**：
`layout_quality` 管摆位（对齐/间距/成组），`place_gate` 管出厂门禁。在这里再写一套视觉美感打分，
等于同一个问题两把尺子——而两把尺子必然打架，打架时没有第三方能仲裁，这正是仓库一直在防的东西
（「比值判据能被整体增益骗过」「两次否证的是单点读数」）。

`aesthetics` 的辖区写死在文件头：**它只看铜的形状**，不看图。要看图请用 `layout_quality`。

## 8. RK3506 板级 5 条：仍不动，原因不是懒

锐角 10 / 非 45° 14 / 盘中孔 8 / `copper_under_magnetics` 41 段 / 未连接 7 / DDR 等长（need 342.2 只填 10.73）
——这六个数（上一版记 5 条，实际 6 条）全部是**布局层**的后果，不是布线器能自己修的东西：

- 盘中孔要换扇出策略（先出线再打孔），这改的是**焊盘级几何**，`pad_stub_mm` 只测不修；
- 电感底下走线要绕，绕不动是因为**器件位置**让出线只能从那儿过；
- 未连接 7 与 DDR 等长是**拓扑与约束**问题（要等长就得有绕线空间，空间由布局给）。

在这些前提没变的情况下，任何「修一下布线」都只是把同一条错线挪个位置。所以要动它们，第一步是重做
布局与扇出策略，而那是另一件工程，不是这一版欠账能顺手做掉的。这一点每版都要重申一次，不许变成「已经没事了」。
