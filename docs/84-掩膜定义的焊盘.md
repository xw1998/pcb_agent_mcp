# 掩膜定义的焊盘：唯一不来自「两个开窗之间」的掩膜缺陷

`0.0.56` 把「solder mask 这一层能不能判」这个问题收窄了一次：两个开窗之间的**掩膜桥**现在有数
（`min_mask_web_mm`）。但它当时把另一半留在了 `not_checked_by_design` 里，原文是「掩膜定义的焊盘
（开窗比铜小）以及任何不是两个开窗之间那条桥的掩膜残余」。

这一篇把前半截做掉：**开窗比铜还小的焊盘**是一个能从文件里量出来的几何事实，不需要读掩膜菲林。
后半截（菲林自己的边缘）仍然不做，理由写在最后。

---

## 1. 结论先行

| 问题 | 答案 | 依据 |
| --- | --- | --- |
| 什么算「掩膜定义焊盘」 | 焊盘的 `solder_mask_margin` **为负**：掩膜开窗比铜皮还小，暴露面积由掩膜决定 | KiCad 的 `(pad ... (solder_mask_margin x))`，优先级 `焊盘 > 封装 > (setup (pad_to_mask_clearance ...))` |
| 库房会怎么拒 | 两种完全不同的说法：**「我们不做这种焊盘」**（计数上限 0）与**「做，但重叠至少 x mm」**（下限） | 两者不是同一个问题的两种写法 |
| 一个板子能不能同时答 | 能，而且**方向相反**：同一块板可能「数量在允许范围内」而「重叠不够」 | 见 §4 的读数 |
| 为什么不能只加一条规则 | 一条规则只能表达一种拒法；拿计数去答重叠，或反过来，都是**错答案**而不是缺答案 | §2 |
| 这次仍然不做的 | 掩膜**菲林**本身：本层从不读它，所以它自己的边缘、zone 周围的残余都没有测量 | §6 |

---

## 2. 为什么必须是两条规则

库房的工艺能力书里，「掩膜定义焊盘」出现的方式有两种：

1. **「不做」** —— 完全不允许开窗小于铜。这是**计数**：`max_mask_defined_pads: 0`。
2. **「做，最小重叠 0.05 mm」** —— 允许，但重叠要够（重叠 = |负的 margin|）。
   这是**下限**：`min_mask_defined_overlap_mm: 0.05`。

如果把两者压成一条规则，会得到两种错答案：

- 只留计数：一块有 3 个重叠 0.5 µm 焊盘的板，「计数 3 ≤ 上限 10」会**通过**，而库房做不出来；
- 只留下限：库房说「不做」时，工艺书里根本没有一个数可填，用户只能瞎填一个，或者被
  「上限必须 > 0」的校验挡回来。

所以两条都加，而且**分开判**。方向相反这件事在实测里出现过（§4）。

---

## 3. 一次遍历，两个数

`oracle._mask_defined_pads()` 扫一遍焊盘，同时产出：

- `mask_defined_pads`（给计数规则）：`measured` = 焊盘个数，附带 `widest_overlap_mm` 与
  前 40 个的 `{ref, overlap_mm, margin_source}`，超过 40 个时 `list_truncated: true`；
- `min_mask_defined_overlap`（给下限规则）：`measured` = **最小**重叠（升序排序后的第一个）。

四条口径写死在代码里：

- **一个焊盘只数一次**，哪怕两面都开窗：它就是一个焊盘，两面的重叠是同一个 margin。按面数会让
  上限随「这个器件恰好是不是通孔」变化。
- **没过掩膜的焊盘不数**：`(layers "F.Cu")` 这种没有 `F.Mask` / `B.Mask` 的焊盘不暴露任何东西，
  负 margin 在它身上不构成「掩膜定义」。
- **margin 从哪来要登记**：`pad` / `footprint` / `setup` / `absent_treated_as_zero`。一个来自文件
  默认值的负数，和一个手写在焊盘上的负数，跟库房吵的时候是两件事。
- **没写就是 0**：KiCad 自己写 `(setup (pad_to_mask_clearance 0))` 时也是这样，`0` 不是负的。

## 4. 实测读数（夹具：两颗 1×1 mm 焊盘，间距 2.000 mm）

| 情形 | 计数 | 最小重叠 | 两个开窗之间的掩膜桥 |
| --- | --- | --- | --- |
| margin −0.05 / −0.03 | **2** | **0.030** | 1.000 + 0.05 + 0.03 = **1.080** |
| 同一个板，符号翻成正的 +0.05 / +0.03 | **0** | `not_applicable` | 1.000 − 0.05 − 0.03 = **0.920** |

第二行是**负控制**：同一块几何、只把符号翻过来，计数必须归零、重叠必须没有可测对象，而且
`0.0.56` 那条掩膜桥必须**朝相反方向**走（1.080 → 0.920）。一个符号错会同时把两个数推向同一边，
所以这两条一起断言。

两个限额在同一块板上给出相反结论：

```
capability: {"max_mask_defined_pads": 2, "min_mask_defined_overlap_mm": 0.05}
  max_mask_defined_pads        measured 2.0    pass   margin 0.0
  min_mask_defined_overlap_mm  measured 0.03   fail   margin -0.02
```

`margin` 的符号沿用 `dfm.evaluate` 的既有约定：**min 方向是 `measured − limit`，max 方向是
`limit − measured`**，所以负数总是「差了这么多」。

## 5. 工艺能力书这边：允许 `max` 取 0

`read_capability` 原来要求所有 limits `> 0`。这在 `max_mask_defined_pads: 0` 上就把一句**真话**
挡掉了：「这个特征一个都不许有」是一个合法的上限，而且是最常见的上限。

`0.0.82` 改成：

| 情况 | 处理 | 理由 |
| --- | --- | --- |
| `max` 规则取 0 | **接受** | 「不许出现」就是上限 0 |
| `min` 规则取 0 | 仍然拒绝，`why` = 「a minimum of 0 asks for nothing」 | 「至少 0」什么都不要求，那是漏填，不是限额；接受它等于报一个永远不会失败的检查 |
| 任何负值 | 仍然拒绝 | 本表没有一条规则是朝下指的 |
| 非数 | 仍然拒绝 | 没变 |

**这是本轮唯一一处放松既有校验的地方**，写在 CHANGELOG 里，并且两侧都有测试：
`max_mask_defined_pads: 0` 通过、`min_mask_defined_overlap_mm: 0` 被拒、`max_board_width_mm: -1`
被拒、`min_track_width_mm: 0` 仍被拒。放松不会让任何既有数字变样——它只是把一个「报错」变成一次
有判据的检查，而最坏的方向是 fail-closed（上限 0 配上任何正数量都是 fail）。

## 6. 仍然不做的，以及为什么

`not_checked_by_design` 里那条掩膜残余**改写了，没有删掉**：

> 远离焊盘、也远离两个开窗之间那条桥的掩膜残余（掩膜**菲林本身**不被读取，所以它自己的边缘
> 没有测量）。

理由：本项目读的是 PCB 文件里的对象（焊盘、走线、zone、图形），而「掩膜」在文件里是**每个对象
上的一个负数/正数扩张**，不是一张可以求边缘的膜。想知道「板边一圈掩膜只有 0.05 mm 宽」或者
「zone 到开窗之间剩了一条 0.03 mm 的掩膜」，就必须重建整张掩膜图像再求形态学——那是另一条通路
（等同于把菲林 Gerber 光栅化），不是这一层的取数方式。**没测到 ≠ 不存在**，所以它留在
`not_checked_by_design` 里，每次 `dfm_check` 都带着它一起回。

## 7. 门：不问就不量

和 `min_mask_web_mm` 一样，`_dfm_facts` 只在文档里出现这两条规则之一时才扫焊盘；否则两条事实都
带 `why`（「…were not examined」）而不是 `measured: 0`。**「没问」不能被读成「没有」**——
`0` 是这次测量得到的答案，`why` 才是没量的模样。

顺带一条：两条规则只要出现**一条**，两个数就一起算出来（一次遍历的副产品），
但**没被文档提到的那条规则不会出现在 `checks` 里**——事实在，判决不在。
