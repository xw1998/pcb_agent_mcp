# 阶段 4r —— 等长线为什么还是三角形：跑线期只有三角档，已进文件的铜没有重画入口

用户在一张 F.Cu 40 px/mm 的渲染上圈出 DDR 蛇形区，问：

> 「等长线怎么还是三角型？mcp问题还是你的？」

答案是**两个都是**，而且分属两层，缺一层都改不对这块板：

1. **工具面缺一档**：`route/tune.py::_serpentine` 没有 `style` 参数，`route/router.py` 在**跑线过程中**要补的那点等长只能出 45° 三角齿。`board_tune_length` 从 0.1.23 起默认就是 `style="arc"`（`docs/160`/`docs/185`），但那是**另一个入口**。
2. **没有任何入口能重画已经进文件的蛇形**：`board_tune_length` 只能在**直线段**上开新齿（它把一段直线换成 `arc_meander` 的片），面对「已经是 45° 三角波」的既有铜，它既不能识别、也不能替换——三角齿一旦落了盘就是永久的。所以 0.1.23 之后这块板上仍然是三角，每次渲染都被看一次。
3. **是我没去重画**：知道 `160`/`185` 做了圆弧档，也知道交付板上全是三角，却没补那一步。

本阶段交付 `tools/arc_reshape.py`（离线规划器，写盘仍走 MCP 自己的 `board_propose` + `board_apply`），把板上 35 条既有三角链里的 32 条**就地**重画成圆弧蛇形，长度一分不差、两端仍接在留下来的铜上。交付板 `examples/rk3506_som/rk3506_som.kicad_pcb` **逐字节未动**；工具面不动（`arc_reshape` 是 `tools/` 下的离线脚本，不进 `TOOLS`，工具数仍 266）；版本不动（阶段文档按先例不升版本、不进 CHANGELOG）。

## §1 结论先行

1. **重画成功的证据在文件里**：`_am5.kicad_pcb` 有 **440 条 `(arc)`**、4204 条 `(segment)`，1855951 B，sha256 `fdefda6999120afa3939b08296cc40b75df5789acd193b774ee1148827390711`；同一块板改前 `(arc)` 计数是 **0**。
2. **四道门禁全过**（`board_apply` 判 `status ok`，plan `plan-ace191559b18`，checkpoint `589c6bf803ad-20261118T064910Z-61dac3`）：字节 = 计划、重解析、逐 op 后置条件、KiCad 引擎 DRC 差分。
3. **重画只换形状，不换长度**：工具内按未取整几何逐链 `|after − before| ≤ LEN_TOL = 1e-4`，**32/32 全过**；`extra preserved 35.279 mm`、1226 op（删 460 条腿、加 766 片）。
4. **净空与形状重新被判了一遍**：`board_shape_gate` 判 **`shape_pass`**（`acute 0` / `off45 0` / `arc_tracks 440`）；`board_drc` **11 条违规全是 `lib_footprint_issues` 警告**、`unconnected_total 7`（改前同值）；`board_place_gate` 与交付板**完全同档**（`hole_in_pad 61` + `copper_under_magnetics`），本次编辑没有碰布局。
5. **DRC 差分是 0**：`before 11 / after 11 / NEW 0 / GONE 0`，带 `.kicad_pro` 与不带两种口径都是 0——旧变体是 `NEW 32 / GONE 0`（见 §3）。
6. **有 3 条链被拒，理由各不相同且都不是「画不了」**：`/DDR_DQ15`、`/DDR_DQ9` 判 `clearance`，`/DDR_A1` 判 `does_not_fit`。宁可留三角，也不许因为「想变好看」放宽净空。
7. **测试**：`tests/test_arc_reshape.py` 新增 **16 例**（全绿），每条判据都配了反向对照。

## §2 三层定性：为什么「还是三角」不奇怪

| 层 | 事实 | 后果 |
| --- | --- | --- |
| 跑线期 | `route/tune.py::_serpentine` 无 `style`，只出 45° 齿 | `board_route` 过程中补的等长**必然是三角** |
| 写盘后 | `board_tune_length` 只把**直线段**换成 `arc_meander` 的片 | 既有蛇形铜没有入口被替换 |
| 工程执行 | 0.1.23 之后没重画这块板 | 三角留在交付板上 |

第一、二是工具面的账，第三是我的账。~~「等长线只能三角」~~不成立：`160` 的弧蛇形早就在，缺的是**重画既有铜**那一步。

## §3 这次最值钱的一条：长度判据对「弦在错线」完全不敏感

第一版把弦取成链的首末**顶点**（`gs[0]["s"]` / `gs[-1]["e"]`），离线复现就报 **32 条 `track_dangling`**（`NEW 32 / GONE 0`），分布在 7 个网（`/DDR_DQ0` `/DDR_DQ2` `/DDR_DQ6` `/DDR_A0` `/DDR_A2` `/DDR_A4` `/DDR_A9` `/DDR_A14`，每条违规是「一条长直线段的一端 + 一个新弧的一端」，即 **16 处断口**）：

- 45° 三角波是「**齿挂在轨道上**」的形状：齿尖在 `x = 21.588`，铜真正走的那条轨道在 `x = 21.843`，邻居铜（0.2 mm 竖直 stub）全接在 `x = 21.843` 那侧；
- `Model.segs` 的 `s`/`e` 按 `(x, y)` 规范化，不保证「起点 = 航向起点」⇒ 用 `gs[0]["s"]` 当弦端，等于把整条波**整体挪到齿尖线上**；
- 长度仍然对（波的长度确实没变），所有长度闸门全绿，而新波两端各差 **0.1113 mm** 才碰到邻居铜。

修法两条，都写进了代码与测试：

1. **弦取自由端**：链首末那条腿里不与其邻居共享的那个端点（`_free_end()`）；
2. **新增硬门 `attach_connected`**：两端必须各有「留下来的铜」相接（`Model.touches()` 索引全部 track 端点 + via 跨层点 + pad 点，按 1 µm 取键），否则 `plan_chain` 直接 `attach_floating` 拒绝。

> 判据写死：**等长弦必须落在铜真正走的那条线上，两端要有别的铜。** 长度判据永远替代不了这一条——这次的 32 条 dangling 就是长度全绿换来的。

## §4 `--apply` 必须把 `.kicad_pro` 一起带过去

`fidelity/engine.py::drc` 会**自己找 `path` 同名 `.kicad_pro`**（`os.path.isfile` 分支）。把板子复制到没有 project 的目录，它按 **KiCad 默认规则**判，于是设计本就允许的 `0.1449 mm` 间距被报成新违规——那是「门禁在报别的地方」，不是这次编辑画的错。

`main()` 在 `board_propose` 之前把源板的 `.kicad_pro` 复制到输出板旁边（`_am5.kicad_pro`），理由写在代码注释里。**这不是为了让门禁变松**：before 与 after 两半用同一套规则，差分才有意义。

## §5 两个长度口径必须分开讲

| 口径 | 读数 | 说明 |
| --- | --- | --- |
| 工具内（未取整几何） | 逐链 `|after − before| ≤ 1e-4`，32/32 | `plan_chain` 的长度闭式 + `LEN_TOL` |
| 从**写盘后的 3 点弧**重算 | 总长 `4208.025204 → 4208.025592`（+0.000388 mm）；逐网最大偏差 **1.755e-03 mm**（`/DDR_DQ0` In4.Cu） | 11 个网超 1e-4 |

根因不是链几何错：`add_track_arc` 把 `mid` 写到 **6 位小数**，而弧长是从三点反解半径算出来的，**弧长对 `mid` 病态敏感**（半径 0.05–0.08 mm 的弧上，1e-6 mm 的 `mid` 抖动会被放大到 1e-3 mm 量级）。参考：`/DDR_CASN` 40 片波 `11.539983 → 11.540004`（+2.117e-05），片数越多累积越大。

**如实写清：文件级长度复算偏差 ≤ 2e-3 mm 来自 `mid` 的 6 位小数，不是长度判据的失败**；要更紧只能在写盘时提高 `mid` 精度（改 `edit/build.py::track_arc` 的格式化），不在本阶段动。

## §6 判据一览（`tools/arc_reshape.py`）

| 位置 | 判据 | 反向对照 |

| `chains()` | 腿长 ≤ `SHORT_MM 1.5`；每个关节 **90°±1**；所有顶点在弦的**同一侧** | 跨到弦两侧的链必须不被认出；45° 关节必须断链 |
| `chains()` | 弦取**自由端**（不与邻居共享的那个端点） | 真板 `/DDR_DQ0`：弦端 `x = 21.843`、齿尖 `21.588`（`amp 0.255`）；挪到齿尖线则 `touches == 0` |

## §9 未做（登记，不冒充完成）

1. **`route/tune.py::_serpentine` 仍无 `style`**：`board_route` 跑线过程中补的等长还是三角齿。要做就得让跑线期也用 `arc_meander`，那是路由器内部的改动（每一段都要过 45° 闸门与净空），需单独立项并预注册判据。
2. **`mid` 精度**：要把文件级长度漂移压到 1e-4 以内，得提高 `edit/build.py::track_arc` 的写盘精度（现在 6 位小数）。本阶段只把偏差量出来、写清楚来源。
3. **3 条被拒的链仍是三角**：`/DDR_DQ15`、`/DDR_DQ9`（`clearance`）、`/DDR_A1`（`does_not_fit`）。放宽净空或缩小半径能过，但那是用可制造性换外观，不做。
4. **交付板没有替换**：`_am5` 是证据副本；接不接受这版形状是设计决定（它与交付板唯一差异是蛇形形状 + 440 条弧）。
5. **`_am1.kicad_pcb` 不是成果**：它是上一轮 `board_apply` 回滚后的产物，与交付板 `md5` 完全相同（`72aa7c03…`）、`(arc)` 计数 0——门禁阻断时 `board_apply` 会把 target 还原成原字节。
