# 124 · 铺铜碎块计数与自适应倒角

这两件事都是在一真实板子（`examples/sky_star/`，44 × 72 mm、2 层、96 器件）上量出来的
缺口，不是设想出来的。

## 1. `board_pour_fragments`：一块铜是不是一块铜

### 为什么需要

把 +3V3 画成 8 个形状块（为了不把焊盘列罩进铜里），灌铜之后 DRC 报 38 条 +3V3 未连接。
原来的工具里 `board_pour_connectivity` 回答的是「某个焊盘的**中心**在不在铺铜多边形里」，
它明确标注自己不是连通性判定；`board_stitch_vias` 只管**跨层**缝合。**没有一个工具回答
「这块铺铜被切成几块、每块多大、相邻两块隔多远」**，而这三个数正是决定「还能不能连」的全部。

### 量到了什么

同一块板，同一个网络：

```
+3V3: 8 个 zone -> 14 个 filled_polygon 碎块
  最大  15.37 x 2.30 mm   面积 26.92 mm²
  最小   0.44 x 0.70 mm   面积  0.18 mm²
```

碎块里最小的那个 0.44 × 0.70 放不下一个 0.45 的缝合孔（需要半径 0.225 + 0.15 间距），
而碎块之间的最近距离是 8 mm 级别 —— 中间隔着 U1 的扇出走线，没有一条直线或单折线
能过去。这是「靠铺铜连通 +3V3」在这块板上不成立的全部原因，一句话说不清，三个数够了。

### 判据与对照

| 事实 | 对照（能反向失败的） |
|---|---|
| N 个 `filled_polygon` 环 = N 块 | 同一批环合并成 1 个环必须报 1（否则「3」可能是数顶点数出来的） |
| 面积用鞋带公式 | 2×1 与 3×1 的矩形必须精确报 2.0 与 3.0 |
| 间距是最近顶点对 | 把一块移远，gap 必须跟着变、别的字段不动 |
| 没灌铜的 zone 报 `pour_not_filled` | 必须是 `fragments: null`，不能是 `0`——「引擎还没浇」和「浇成一整块」是两件事 |

坐标是板文件自己的坐标系（原样输出，不做二次变换）。

## 2. `board_angle_audit(action="chamfer")` 的 `adaptive`

### 为什么需要

原来的 `chamfer_ops` 对每个 90° 拐角按 `max_cut_mm`（默认 1.0）切一刀，**切下去会撞到
已有铜就整条跳过**（`would_collide`）。在 0.4 mm 间距的扇出 lane 里，1.0 的切角必然跨进
邻道，于是一条条全被跳过 —— 板子上剩下大片直角，而工具报的是「已尽力」。

真实读数（sky_star，同一块板）：

```
adaptive=off : 切角 5 个，跳过 8 个
adaptive=on  : 切角 7 个，跳过 6 个，其中 2 个把切角从 1.0 缩到 0.25
```

### 做了什么

撞了就**二分**：在 `[0, cut]` 上 14 次二分，找最大的可行切角；低于 `min_cut_mm`
（默认 0.12，此时斜边 0.17 已经开始读成圆角而不是 45°）才真的放弃，并在 `skipped` 里
写明 `smallest_tried_mm`。

被缩短的拐角单独进 `cut_reduced`（记 `asked_mm` / `used_mm` / `blocked_by`），
所以「为什么这个拐角比别人短」有出处，不是靠看图猜。

### 判据与对照

- 挡住斜边中段的一条邻线 → 必须 `corners_chamfered == 1` 且 `cut_reduced_count == 1`，
  且 `used_mm < asked_mm`；
- **同一个几何、把障碍物挪远 6 mm → 必须 `cut_reduced_count == 0`**（否则「被缩短」只是
  说明它变短了，不说明是被挡的）；
- `adaptive=False` 跑同一几何 → 必须回到 `would_collide`，证明开关是真的。

三条都在 `tests/test_45_corners.py`。

## 3. `board_routability` 的 `width_scan_mm`：最宽能出去多少

### 为什么需要

`escape` 只回答「这个焊盘能不能出去」，用的是网类里给的线宽。可实际卡住的地方不是
「出不去」，是「**0.4 的电源线出不去 LQFP**」—— 给一个 yes/no，这块板永远画不成。

### 量到了什么

sky_star，同一个 `width_scan_mm=[0.6,0.5,0.4,0.3,0.25,0.2,0.15]`：

```
U1.14 / U1.19 / U1.21  只能 0.3   （0.5 pitch 的 LQFP100，扇出区）
P2.3 / P2.5            只能 0.25   （双列排针，两侧都是邻居）
C17                    只能 0.3
```

这就是「+3V3 全程 0.4」被推翻的数字依据：靠近扇出区只能 0.3，离开之后才有 0.4~0.5 的
空间。也解释了为什么它不写在 `escape` 里 —— 那是另一个问题。

### 判据与对照

| 事实 | 对照（能反向失败的） |
|---|---|
| 空板唯一焊盘取阶梯最上一档 | 同一个焊盘加两道墙后必须变小（对照组在同一个测试里，先量空板） |
| 不给 `width_scan_mm` 就不出这个字段 | 加了阶梯才出现 `widest_escape`，旧答案逐字节不变 |
| 只给 0.15 就只可能回 0.15 | 阶梯原样被尊重，不会自己去试更宽的 |

**一条被测试纠正的错判**：先写的对照是「三面围铜」—— 焊盘左边、上边、下边各一块铜。
它读回来仍是 0.6，一开始当成工具的漏洞，实际是**判据错了**：右边整条开着，0.6 线本来
就出得去。真正吃掉线宽的是**走廊**（两侧平行铜，两侧都只剩窄缝），换成长墙几何之后
0.6 立刻被拒、0.4 通过。所以这条测试现在自带空板对照（0.6 → 0.4），而不是靠另一个
测试的焊盘「应该一样」。

## 4. 没有做的事

- 没有自动布线、没有自动布局。`board_route` / `board_fanout` 仍是 `TOOL_RETIRED`。
- `board_pour_fragments` **不判断两块能不能连**：那取决于中间有没有 pad 和 track，
  是 `board_routability` 的问题。它只给几何，判断留给调用者。
- 没有动 `chamfer_ops` 的拓扑语义：仍然只改写段、不加过孔、不换层。
