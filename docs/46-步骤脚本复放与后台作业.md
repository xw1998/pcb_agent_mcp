# 46 · 步骤脚本的录制/复放，与「慢调用交出 id」

两件互不相干的事放在同一篇，因为它们是同一个毛病的两种表现：**把「跑过了」当成「就是这样」**。

- 复放：步骤跑完一圈没报错，不等于它复现了上一次的结果；
- 后台作业：一个跑不完的调用，不该用一个更大的超时或一个截断的答案来收场。

## 46.1 复放：`lceda_pro_steps` 的答案会蒸发

`lceda_pro_steps` 一次跑一串 snippet，逐步返回每一步的值，能看、能中断（`board_progress(action='stop')`）。
但它的答案是一次性读数：换一块板、换一个人，同样的 8 步就得凭记忆重写。

`lceda_step_record` 把**已经发生的那一次**留下来：

```
steps: [{label, code, fn, js_args, timeout_ms, value}]   # value 是那一步当时返回的
   ↓
script = {format, at, note, source, session, steps, sha256,
          recorded_values, steps_without_a_recorded_value, idempotent:"unknown"}
```

`value` 变成脚本里的 `expected`。**没有 `value` 的步骤照样记下来，但被标成「不可比」**——
它不是 `expected: null`（那会和「返回了 null」判等），而是根本没有 `expected` 这个键。
这个区别是整件事的支点：缺记录被当成巧合通过，比缺记录本身坏得多。

## 46.2 复放：`matches_recording` 是三态，不是两态

`lceda_step_replay` 逐步重跑并比较，每一行给四种结果之一：

| outcome | 含义 |
|---|---|
| `match` | 这次返回的值与记录相同 |
| `differs` | 返回了别的值，**两个值都贴出来** |
| `no_recorded_value` | 这一步没有记录可比 → 不是通过 |
| `failed` | 这一步抛错，复放**停在这里** |

整体 `status_verdict` 只有三种：`reproduced`（有可比的步骤且全部相同）、`differs`（有不同或有失败）、
`inconclusive`（一格可比的都没有）。

三条设计决定，都是为了不让「跑完了」冒充「复现了」：

1. **不同不是错误**。把同一个 `create` 再跑一次，第二次当然不一样（已经存在了）。
   本模块不知道这些 snippet 是否幂等，所以 `idempotent` 恒为 `"unknown"`，
   并写清理由：幂等性是 snippet 作者的属性，不是本服务能推出来的。
2. **失败就停**。第 3 步抛错之后继续跑第 4 步，是在一个与脚本假设不符的设计上继续动手。
   停下并把 `not_run` 列出来，比「尽力跑完」诚实。
3. **没有 before/after 全等口径**。比较的是**每步自己的返回值**，不是「末态一样」：
   末态一样可能来自一条完全不同的路径。

比较用的规范化与写路径同一个（`lceda_write._canon`）：键序无关、`1` 与 `1.0` 相等、
超过 2^53 的整数不转 float（转了两个相邻 uuid 会撞成同一个 double，把「变了」读成「没变」）。

## 46.3 脚本文件：自己带着 sha256

- 默认目录是**本服务自己的** `~/.pcb_agent_mcp/step-scripts/`（或 `PCB_AGENT_HOME`），
  文件名取 sha256 前 12 位；**绝不写在工程旁边**。
- `save` 默认 `False`：不给 `save=true` 也不给 `path`，脚本只在答案里，一个字节都不落盘。
- 已存在的路径要 `overwrite=true` 才覆盖（`FILE_EXISTS`），拒绝时不猜「那大概是想更新」。
- `load` 会**重算** sha256 并给 `sha256_matches`。对不上不拒——它可能是被有意改过的——
  但会带一句 `why_it_can_differ`：改过的脚本永远不该被当成记录的那一份。

## 46.4 后台作业：慢调用的正确收场是一个 id

`kicad-cli pcb drc` 在这台机器上对一块 88.7 MB 的板没有在单次调用预算内跑完。
此前的行为是：超时（900 s）报 `TIMEOUT`，不降级、不返回半个判决——这已经是对的一半，
错的是它让调用者**只能等**。

`board_drc(background=true)` 现在交回一个 id：

```
{status:"ok", value:{job:"drc-3-1a2b3c", state:"running", kind:"drc", timeout_s:900},
 precision:"NO RESULT YET. …"}
```

然后 `board_job(action=get|wait|list|cancel)`。

四条规矩，每条都对应一种「看起来对」的错答案：

- **运行中的作业没有结果**。不是空字典、不是上一轮的判决、不是「大概是 0 个违规」。
  `get` 只回 `state: running` + `elapsed_s` + `why_there_is_no_result`。
- **失败被留住**。异常的类型与消息存进 `error`，作业状态是 `failed`；
  不会在第二次轮询时抛出，也不会变成成功。
- **取消是请求，不是 kill**。已经交给子进程的工作会自己跑到底；`cancel` 只让结果被丢弃，
  并明说「机器仍然忙到它退出为止」。
- **作业活在内存里**。重启就没了，所以未知 id 是 `JOB_NOT_FOUND`，而不是一个空答案。
  `wait` 的预算**按次**算：想等五分钟就调四次，每次都能看到已经过了多久，
  而不是一次调用看起来像卡死。

并发按种类封顶（默认 2）：两个 DRC 同时在跑已经吃掉近 2 GB，再开不是更快，是机器开始不应答。
第三个直接 `JOB_BUSY`，并说明「更宽的上限意味着每次跑能占更多机器，而不是跑得更快」。

`DRC_TIMEOUT_S = 900` 现在是 `fidelity/engine.py` 里的一个常量（此前默认值是 300，
对这个尺寸的板等于把「超时」伪装成「判决」），可以按次覆盖：`board_drc(timeout_s=…)`。

## 46.5 落点与边界

- 代码：`lceda_steps.py`（record / save / load / replay）、`jobs.py`（submit / get / wait / list / cancel）、
  `fidelity/engine.py` 的 `DRC_TIMEOUT_S`、`tools.py` 的 `lceda_step_record` / `lceda_step_replay` /
  `board_job` 与 `board_drc(background=true)`。
- 测试：`tests/test_lceda_steps.py`（23 例）、`tests/test_jobs.py`（15 例）；
  DRC 那组用替身 `engine._run`，所以本机没有 KiCad 也能跑「引擎不说话」这条路径。
- selftest：856（记录的脚本带 64 位 sha256、值为 1、`idempotent` 是 `unknown`）、
  857（未知 id 是 `JOB_NOT_FOUND`，不是一个空判决）。
- 边界：**复放不做状态前置**。脚本里没有「开始前应该是什么样」的记录，
  所以「两次起点不同」只是 `not_verified` 里的一句话，不是一次拒绝。
- 边界：**作业不持久、不续跑**。当前每个慢调用都不可在已知点重入，续跑需要那个性质先存在。
- 边界：**取消杀不掉子进程**。要杀得让 `_run` 改用 `Popen` 并持有句柄；现在没有这样做。
