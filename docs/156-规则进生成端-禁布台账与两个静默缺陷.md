# 156 · 规则进生成端：禁布台账、两个静默缺陷，以及「布线到底用没用连接信息」

## §0 这一篇回答的两个问题

用户问：**布局和布线是不是没有借用转换的信息，类似自动布线做的？规则呢？**

两个问题的答案不一样，所以分开答，并且每个答案都带实测。

### §0.1 布线：有连接信息，可查

`design_constraints.net_binding()` 在交付板 `_v18.kicad_pcb` 上实测：

| 量 | 值 |
|---|---|
| pads | 682 |
| pads 带 net | **682**（100%） |
| 焊盘上出现的 net 数 | 145 |
| tracks | 4209 |
| tracks 带 net | **4209**（100%） |
| tracks 挂在「没有任何焊盘声明过」的 net 上 | **0** |

也就是说每一段铜都绑定到原理图网表分配的 net 上，走线是「同 net 两端之间」，不是按几何乱连。`_mazeH.py` 的输入就是板上焊盘的 `GetNetname()`（第 70/74/82/85 行），`_addops.py` 落盘时 `b.FindNet(name)` + `t.SetNet(n)`，两处都不允许无名铜。

**但「有 net」不等于「用了设计意图」。** net 只回答「这两点该连」。走线器不知道哪些 net 是 DDR 一组、哪几条要等长、哪条是差分对——这些信息在 0.1.15 之前根本没进过布线回路（0.1.15 只是加了判据，没有把约束喂回去）。这一点在 §5 里如实登记为欠账。

### §0.2 布局：借用了原设计的坐标，不是规则生成的

摆位来自解析立创工程文件：`_build.py` 读 `_clone/data/pcb.json`，用 `X(x)=(x-XL)/K`、`Y(y)=(YT-y)/K` 把原文件的 mil 坐标映射成 mm，逐器件落坐标。所以：

* 摆位是**原设计的摆位**，不是这套规则算出来的；
* 原板「电感下方走线」这类摆位缺陷被原样继承——这正是 0.1.17 量到 `magnetic_keepout` 多段、`magnetic_keepout_deep` 139 段的来源，也是为什么「改摆位」和「改布线」两条路都走不通（违规是摆位造成的，而摆位是从原设计继承的）。

这条界线之前没有被说清，是本篇要补的第一件事。

## §1 规则过去只在审计端

```
board ──> ruleset.audit.audit()  ──> 52 条判定      （规则读板）
规则  ──> 人手 ──> _ko.json      ──> _mazeH.py     （人读规则）
```

第二条箭头是「学了但不遵守」的现场：布线器只见过一张手写的矩形表，而那张表从来没有跟它所描述的那块板核对过。`_audit.py` 走的是第一条（`from pcb_agent_mcp.ruleset.audit import audit`），生成端走的是第二条，中间没有任何代码连接。

## §2 新模块：`ruleset/design_constraints.py`

把审计用的同一套几何（`measure._is_magnetic` / `_is_crystal` / `_pad_hull`）直接输出成布线器自己的输入格式，而不是再抄一份。

| 函数 | 作用 |
|---|---|
| `keepout_rects(board, grow_mm=0.1)` | 每个磁器件/晶振一个矩形，带 `ref`/`kind`/`rule`/`bbox`；无焊盘的器件进 `skipped` 并点名 |
| `maze_keepout(board)` | `[[cx, cy, hx, hy], ...]`，即 `_mazeH.py` 的 `KEEPOUT` 格式 |
| `write_maze_keepout(board, path)` | 落盘并回读报告 |
| `legal_window(board, ref, bbox)` | 该器件若挪到 `bbox`，会与哪些其它禁布 owner 重叠（只回答 part-to-part，铜的问题归 `measure`） |
| `net_binding(board)` | §0.1 那张表的机器版 |
| `classify_row(row, rect)` / `classify_rows` | 判一行是 `centre` / `corner_min` / `wrong_size` / `unrelated` |
| `constraints(board)` | 上面的合集，带 `schema_version` 与 `rule_ids` |

```
python -m pcb_agent_mcp.ruleset.design_constraints BOARD.kicad_pcb [OUT.json]
```

在 `_v18` 上：7 个 owner（FB1/FB2/L1..L4/Y1），0 skipped，输出 7 行。

## §3 两个静默缺陷（都是接上这条线才暴露的）

### D1 `24 MHz` 被读成 `24 mH`

`measure._is_magnetic` 的亨利值测试是 `[0-9]+(\.[0-9]+)?\s*(u|m|n|µ|μ)h`，`"24 MHz"` 小写化后是 `24 mhz`，正则匹配 `24 m` + `h` ⇒ **晶振 Y1 被判成电感**。

修法：加 `(?![a-z])` 前瞻，并注释说明为什么。修后：

| 器件 | 修前 kind | 修后 kind |
|---|---|---|
| Y1（24 MHz, `Package_Crystal_SMD_3225-4P`） | magnetic | **crystal** |

审计 52 条的级别计数不变（P0 20 / P1 8 / P2 9 / P3 11 / P4 4），`first_action` 仍是 `PCB.EDGE.ROUTED`；变的只是归属：`magnetic_keepout` 的证据里不再出现 Y1，`crystal_keepout_adjacent` 的 4 段（UART0_TX×2 / CLK_OUT / ETH_CLK0_25M）归位到晶振规则。这是**归属错**而不是**数量错**，所以之前没被任何数字抓到。

### D2 禁布矩形从来没有生效过（两处叠加）

1. **角 vs 中心**：0.1.17 的 `_ko.json` 每行是 `[x_min, y_min, hx, hy]`，布线器按 `[cx, cy, hx, hy]` 读 ⇒ 每个矩形沿 (−hx, −hy) 平移了半个尺寸。7 个 owner 全部命中这个模式（`classify_rows` 判 `corner_min` 7/7）。
2. **符号**：`_mazeH.py` 注入时写的是 `mkrect('__KO__', ..., cx, -cy, ...)`。但器件坐标在 maze 世界里是 `-ToMM(pos.y)`，而 KiCad 内部 `pos.y` 本身是负的（L1 实测 `pos mm 31.4 -25.6`），两个负号抵消 ⇒ 器件在 y=+25.6。注入再取一次负 ⇒ 矩形落在 y≈−25.6，**整块跑到板外**。

两个缺陷叠加的结果是：**0.1.17 那条「带禁布 vs 不带禁布逐网相同」的实验里，禁布一次也没挡过任何东西**，所以「逐网相同」不能读成「禁布无所谓」。

正控制（把禁布改成一块覆盖全板的矩形 `[22.5, 22.5, 21.0, 21.0]`，只看 `/SDMMC_D2` 一个网）：

| 状态 | 结果 |
|---|---|
| 修 D2 前 | `OK 3 parts, 14 segs, 2 vias` —— 全板禁布都挡不住 |
| 修 D2 后 | `REFUSED`（9 网全拒） |

## §4 用真正生效的禁布重跑 0.1.17 那条实验

对象：`_rip.kicad_pcb`（撕掉 10 个违规网后的板），9 个网，同一 `_mazeH.py`，唯一差别是禁布表。

| 网 | 0.1.17 记录（禁布实际无效） | 本轮（`_ko_fix.json`，真生效） |
|---|---|---|
| /SDMMC_D2 | OK 3 parts, **14 segs, 2 vias** | OK 3 parts, **10 segs, 2 vias** |
| /RMII0_MDC | OK 4 parts, **30 segs, 3 vias** | OK 5 parts, **27 segs, 4 vias** |
| 其余 7 网 | REFUSED | REFUSED（同名同序） |

结论：

* **主结论不变**：7 个网仍然布不通，且 0.1.17 的「无禁布臂逐网相同」说明拒绝来自逃逸口袋不存在，不是禁布造成的。
* **但数字要改**：两个能布的网路径确实变了（SDMMC_D2 少 4 段、RMII0_MDC 少 3 段多 1 孔），因为它们在 0.1.17 里是在没有禁布的世界里布的。
* 新结果自检：37 段走线**0 段**落在任一禁布矩形内（两端点判据，Liang–Barsky 前的粗判）。

## §5 这一版没做的事（不许读成做了）

1. **摆位仍不是规则生成的**。`legal_window` 只答 part-to-part 重叠，真正的摆位需要一个覆盖全场布局的代价函数；用一个矩形表冒充它会犯同一类错误。
2. **布线仍不接等长/差分/拓扑约束**。DDR 组、差分对的「必须同长」目前只有判据（0.1.15），没有作为生成约束进入搜索。
3. **22 条 uncited 规则没补出处**（0.1.18 已登记，`docs/155 §4`）。
4. **根 `data/` 仍不进 wheel**（与 `magnetic_materials.json` 同病）。

## §6 可复用口径

1. **「两条箭头」要分开检查**：规则读板（审计）通过，不等于规则进了生成。前者只要 measure 写对，后者要有人把它翻译成生成器的输入并**核对这份输入是否真的被吃到**。
2. **一个「没效果」的对照，先证明它有效果**：任何「加约束 vs 不加约束结果相同」的结论，必须先做正控制（把约束放到必然违规的位置，看是否真的拒绝）。0.1.17 缺这一步，于是把一个死掉的约束读成了「约束无关」。
3. **手写几何表必须能被反查**：矩形要有 owner、要有中心语义、要有生成它的规则 id。`classify_row` 让「角 vs 中心」变成可测的分类而不是一段注释。
4. **归属错不会自己冒出来**：`24 MHz`→`mH` 这种把晶振算成电感的错误，级别计数、`first_action` 全都不动，只有把证据里的器件名摊开才看得见。
