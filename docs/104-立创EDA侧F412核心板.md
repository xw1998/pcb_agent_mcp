# 104 · 立创 EDA 侧把同一块 F412RG 核心板重做一遍：Connection 101 → 0，Clearance 23 → 0

> 它回答的问题：**同一个 MCP、同一块板、换一个 EDA（立创 EDA Pro）从零走一遍完整流程，
> 能不能做到 DRC 干净、交付包齐全**？如果做不到，卡住的到底是「工具不会」还是「这个软件的 API 没有这个入口」？
>
> 它与 101 的关系：101 是 KiCad 侧那块板的读数（32 封装 / 54 网 / 53.34×30.48 mm）。本篇是**同一份 BOM 换到立创 EDA 重做**，
> 板子规格一样，路径完全不同——而且这里踩到的六条都**不是计算问题**，是立创 API 与几何的边界。
>
> 它推翻的前提：**「DRC 干净 = 画完了」**。这条板最后剩下的 1 条 Netlist Error 不是画错，
> 是「原理图网表 vs PCB 网表」的比对项，而这条路径下 PCB 侧的全部铜与网都是**直接建在 PCB 上**的。

## 104.0 两句话

1. 板子：立创 EDA Pro 侧的 `F412RG 核心板 LCEDA`，**STM32F412RGT6 + W25Q64（QSPI NOR）+ USB Micro-B + 双排 1×20 面包板口**，
   四层 **2100 × 1200 mil（53.34 × 30.48 mm）**、32 个元件 / 188 焊盘 / 54 网 / 126 过孔 / 681 段导线 / 257 个铺铜填充块，
   最终 **Clearance 0 · Connection 0 · Netlist 1**，交付包 6 种格式全部导出并落盘。
2. 必须说清的一条现状：**这 1 条 Netlist Error 没有消除**。它的类型是 `Schematic Netlist` ↔ `PCB Netlist`；
   这条路径是「器件直接放在 PCB 上、网络用 API 逐个赋给焊盘」，原理图页里没有对应对象，所以比对无从成立。
   我**没有**执行 `importChanges`（从原理图导入变更）——它在执行前看不到 diff，而一旦原理图侧是空的，
   它可能把这个 PCB 上的器件/网络当成"多余"删掉。这条属于 fail-safe，不是"证明了两边一致"。

## 104.2 这条板是怎么落出来的（14 步）

顺序即依赖顺序，前一步的输出是后一步的输入：

1. **18 个 LCSC 器件在线核实**（型号、封装、供应商编号，全部留来源）。
2. **板框** 2100 × 1200 mil。
3. **32 个器件对位**（`pcb_PrimitiveComponent` 移动必须 `toAsync()` + `done()`）。
4. **设网 179 处 / 54 网**（直接给焊盘赋网络，不经过原理图）。
5. **四层栈**（L1 顶 / L2 内1 / L15 内2 / L16 底）。
6. **走线 + 过孔**。
7. **覆铜消融对照**——证伪「未填充的 Pour 边框有铜」这条想当然。
8. **257 个 Fill 铺 GND(L15, 128 带) / +3V3(L16, 129 带) 平面**（见 104.4 第 5 条）。
9. **A\* 桥接**把 Connection 从 **101 → 6**。
10. **规则适配**：`viaOuterdiameterMin 0.45` / `viaInnerdiameterMin 0.2` mm（原值 0.5/0.3 会把所有 8/18 mil 过孔判成 `Physical Error|Via Size`）。
11. **删 49 条 L15/L16 上宽 8 mil 的错误线**（早期误落在内层的走线）。
12. **两个按键迁位**到 (1850,860) / (2010,850)。
13. **PB13/14/15 顶点松弛实验**（已完整回退）。
14. **收尾**：删 6 条悬空残线 → Connection **0**；再分四批把 Clearance **23 → 0**。

最后四批的清零路径（每一批都用 DRC 差值确认，不看"应该好了"）：

| 批 | 动作 | DRC 变化 |
|---|---|---|
| ① | GND 过孔从 (1850,700) 重落到 **(1940,840)** | 两条 GND Connection 同时消失 |
| ② | +3V3 两条线 + NRST 八段线 + BOOT0 双段（含 L2 长绕 847 mil） | Connection **8 → 0** |
| ③ | 删 1 个冗余 GND 过孔（Hole to Hole 17.9 mil）+ 8 块 +3V3 Fill 收窄 12–15 mil | Clearance **23 → 14** |
| ④ | PB13/14/15 重布两版 + NRST 拐角改直角 + XTAL_IN 改走 L1 绕底部 | Clearance **14 → 0** |

## 104.3 立创 EDA Pro 的六条硬边界（能力自述，都有实测）

1. **覆铜填充图元新建不了**：`pcb_PrimitivePoured.create` 的官方 remarks 原文就是「覆铜填充图元不支持新建」。
   所以"平面"只能用 `pcb_PrimitiveFill` 一条一条铺（见 104.4 第 5 条），**不是**用铺铜。
2. **焊盘尺寸改不了**：`pcb_PrimitiveComponent` 上没有 `setState_Pads`，立创库给的焊盘多大就是多大。
   这条直接把"缩焊盘让间距"的方案否掉了（见 104.5）。
3. **没有 repour / rebuild 入口**：`PCB_Document` 与 `SYS_HeaderMenu` 都查过，没有"重新铺铜"这种命令。
4. **`autoRouting` 在 headless 下不产出任何铜**（三重实测）。这块板的铜全部是脚本放下去的。
5. **文件系统被权限挡住**：`sys_FileSystem.getDocumentsPath()` 等一律返回
   「错误：未启用扩展和独立脚本的外部交互权限！」。交付包只能靠 `getXxxFile()` 拿 `File` 对象，
   再分块 base64 取回（本篇的 6 个文件就是这么落盘的，PDF 647 KB 走了 40 块）。
6. **脚本沙箱绑在当前文档上**：`dmt_EditorControl.activateDocument(...)` 返回成功、等 800 ms 之后
   `dmt_SelectControl.getCurrentDocumentInfo()` 仍报 `documentType 3 / PCB1`，
   `sch_PrimitiveComponent.getAll()` 也依旧「获取所有器件失败」——所以**在 PCB 脚本里读不到原理图**。

## 104.4 十条口径（重做这块板必须知道的）

1. **footprint pin1 约定不同 ⇒ 一律按 pad 编号配对**，不要按几何位置对。
2. **坐标换算**：`y_mil = (50.48 − y_mm) / 0.0254`，**不翻 Y**；x 有 −788 mil 的平移。
3. **三类特殊封装**：SW/KEY 用 2 焊盘；U2（SOT-223）tab 与引脚重号；J1（USB Micro-B）屏蔽壳是数字 6–10。
4. **`'R'` 多边形是 `[x, y, w, h, 0, 0]`，且 h 向 −y 延伸**（覆盖 `x..x+w`、`y−h..y`）。
   这条是 DRC 差值法实测出来的，文档里没写。
5. **平面铜 = 257 个 Fill 逐带铺**，不是铺铜。每块 Fill 的 `lineWidth` 默认 0.2 mm，描边外扩 0.1 mm ≈ 3.94 mil，
   所以相邻带之间是 **8 mil 的实交叠**——连通性正是靠这个交叠成立的；把 `lineWidth` 设 0 会断开平面。
6. **规则是被就地改过的**：当前 Track-Track 0.102 mm（4 mil）、Track-Pad / Pad-Pad / Via-* 0.152 mm（6 mil）、
   Copper/Plane Zone 0.254 mm；via 最小外径 0.45 / 内径 0.2 mm。
   **新建过孔必须用 8/18 mil**：7.8 mil 钻 = 0.198 mm 已经低于 0.2 下限，会报 `Physical Error|Via Size`。
7. **新建过孔必须给异网内层平面开隔离槽**（20 mil 的 splice 填充），否则过孔与平面短路。
   反过来：**GND 过孔落在 GND 平面上不需要开槽**，这是清零阶段最便宜的一招。
8. **立创库焊盘比 KiCad 大**：SOIC-8 焊盘 2.25 × 0.63 mm（KiCad 1.625 × 0.65），按键 1.3 × 1.7 mm（0.9 × 1.0）。
   这条直接决定了 104.5 的三个真因。
9. **A\* 通过 ≠ 几何合法**：栅格 2 mil 通过之后，`simplify()` 出来的直线段会切角，
   必须再用 shapely 逐段 `distance` 精确复核（本篇四次清零全部先过校验器再落线）。
   另外两条同样重要的：**TH 焊盘（`layer==12`）是全层障碍**；**刚落的线必须进下一轮掩码**。
10. **连通性只认 DRC**，不要自建连通分量模型。L15/L16 上还有 205 段信号线，
    只按 L1/L2 建模会得到假的"断网分量"。

## 104.5 最后 6 条 Clearance 的三个真因

清零阶段的 6 条不是"线画歪了"，三个真因各自能单独解释：

**(a) 20 mil 的焊盘间隙塞不下一个 8/18 mil 过孔。**
晶振 `X?` 的 2 号（GND）与 3 号（XTAL_OUT）焊盘各 55.1 × 47.2 mil，中间只有 **19.8 mil** 净空；
一个 17.8 mil 的过孔加上两侧各 6 mil 间距需要 **29.8 mil**。原方案把 XTAL_IN 的换层孔放在这个缝里，
所以 `SMD Pad to Via` 必然报两条。
**改法**：不再在这个缝里换层——把 XTAL_IN 整条改走 L1 绕到晶振下方（y = 800），
过孔与该 L2 短桩一起删掉（净减 2 过孔、2 段 L2），绕行 4 段。校验器全层（L1/L2/L15/L16 + TH 焊盘 + 过孔）**0 违规**后才落板。

**(b) 0.1 mil 级别的拐角间距。**
`NRST` 的斜段 `(1826.77,523.62)→(1840.55,509.84)` 与 `R?_2`（GND，RECT 31.8×34）的角点相距 **8.85 mil**，
而需要的是 6 + 2.955 = **8.955 mil**——差 0.105 mil。
这类"手算说够、DRC 说不够"的情形必须先量真实净距再动几何；
**改法**是把 45° 斜段改成直角（竖直到 y = 509.84 再横走），最近距离变成 **7.23 mil**（对焊盘）/ 10.19 mil（对角点），一次过。

**(c) 没有网络的焊盘 + 一个悬空过孔。**
MCU 的 `U?_4` 焊盘 `net` 为空（92.1 × 141.7 mil），而 `+3V3` 有一个**四周 120 mil 内没有任何走线**的过孔 `9de3a01c40fd3b5d`
正压在它的边上——既报 `SMD Pad to Via` 又报 `Hole to SMD Pad`。
**改法**：删掉这个过孔。判据是"它在 L1/L2/L15/L16 四层都没有任何线段端点与之相邻（120 mil 内 0 条）"，
它只是一颗落错位置的电源缝合孔，删掉后 DRC 的 Connection 仍然是 0。

第四批的 PB13/14/15 也有一次"第一版被证伪"：第一版把 PB15 斜降到 y = 494.1，与 PB14 横段只差 **3.9 mil**，
DRC 直接报 4 条 `Track to Track`。第二版把三条竖降在 x 上错开（1368 / 1354.3 / 1338）并把 PB15 抬到 y = 494.9，
校验器 0 违规，落板后这 4 条一次消失、Clearance 从 10 掉到 6。
