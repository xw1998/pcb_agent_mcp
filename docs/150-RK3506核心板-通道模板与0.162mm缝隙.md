# 150 · RK3506 核心板：通道模板与「每道缝只有一条中心线」的墙

## 1. 这一轮做了什么

`tools/route_bus.py`：给「两端都已经扇出到通孔」的网套一个**唯一形状**的模板

```
via A --45°--> (xm, ·) --竖直--> (xm, ·) --45°--> via B
```

`xm` 走固定候选表（A.x、B.x、中点，然后 0.5 mm 步进横扫），层按固定顺序 In2 → In4 → B.Cu（In1 与 In3 是平面层，不占）。第一个整条折线都干净的候选就用；**没有代价函数、不回溯**；放不下就计数并列出来。

落铜读数：**57 个待连网里 16 个走通**（`/DDR_*` 15 条 + `/SW_U7` 1 条），42 段 0.10 mm 走线，`tracks 559 → 601`，`unconnected 293 → 278`，DRC 仍只有 **199 条 `via_dangling`**，新增 0。

## 2. 为什么会撞墙（本轮最值钱的读数）

417 个逃逸通孔两两之间的**最小中心距是 0.562 mm**（实测：220 对 0.562、280 对 0.65、174 对 0.79、139 对 0.80）。

0.2/0.1 通孔 + 0.1 mm 净距 ⇒ 每个孔占掉半径 0.2 mm 的圆。两个孔 0.562 相距时，中间合法的**走线中心线**空间只剩

```
0.562 − 2 × 0.2 = 0.162 mm
```

也就是说：缝隙存在，但只有 0.162 mm 宽、还不到一个网格步进的两倍 —— 走线能穿过去，**但不能在缝里左右挪**。所以模板能连的是「起终点连线恰好落在一条现成缝里」的网，其余 41 条要绕，只能靠逐段的通道规划（不是这个模板能做的）。

这也解释了为什么之前估算「内层每道缝只过一根 0.1 线」是对的：不是容量按根数算好了，是**根本没有第二条中心线**。

## 3. 为什么不用通用布线器补

口径不变：`board_route` / `board_fanout` / `autoRouting` / `autoLayout` 一律不用，也不写通用布线器。这一轮加的是**一个形状 + 一张候选表 + 拒绝计数**，属于既有的固定几何模板做法（和 `_sky_route*.py`、`_gapfix*.py` 同一类）。

## 4. 网格与归属（这一轮的技术要点）

- 0.02 mm 栅格，`int16` 存**每格归谁**：自己的网不算障碍（自己的孔、自己的 stub 可以被自己接上去），两个不同网落进同一格就写 `-1`，对所有人都是墙。
- 障碍圆半径 = 实体半径 + **0.15 mm**（0.1 规则 + 0.05 栅格余量）。第一版按 0.1 打，`precondition.clearance_no_worse` 立刻回「tightest 0.0501」——栅格量化把余量吃掉了，所以余量要显式留。
- **numpy 掩码必须先拍快照再写**：`sub[bad & (sub == 0)] = nid` 之后再算 `bad & (sub != 0)`，后者会把刚写进去的格子判成「冲突」全部打成 `-1`。第一版 57 条全 REFUSED、失败点全在起点，就是这个 bug。
- `PL.propose()` 也要带 `options={"precheck_clearance_mm": 0.1}`：只在 `apply_plan` 上带没用，预检在 propose 阶段就把整批拦掉（`0 → 70 pair closer than 0.2`）。
- `PCB_VIA::GetWidth()` 不带层参数在 KiCad 10 里会弹断言对话框，**进程就此挂住**（表现为没有任何输出）。必须 `GetWidth(pcbnew.F_Cu)`。

## 5. 未做（明确边界）

- 这 35 条要连，需要的是「先规划缝、再排线」的通道方案（或者改扇出策略，把逃逸孔从「填满所有 interstitial」改成「留出成组的出线通道」）。这一步会改动已落铜的扇出，属于设计变更，不在这一轮擅自动。
