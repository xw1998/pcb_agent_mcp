# 175 · 把八关编排剩下的缺陷补掉（子进程隔离 / `not_run` 独立成桶 / 两个"拍的数"变成读数 / `--drc` 真接通）

用户的话是「补上全部缺陷再给我」。`docs/174` 末尾留了一张欠账表，这一版不是继续往表上加，
而是**把表上能补的先补掉，并且只把"补不掉的"留在表上**，同时补的过程里又自曝出一个真缺陷
（`--drc` 解析了却永远不生效），一并修掉并留下反向对照。

这一版**没有改任何板子**，也没有动任何判据的门槛值（`CROSS_FRAC_MAX` 仍是 0.15、
总线振幅判据仍是 0.30、`PLANE_COVER_MIN` 仍是 0.25）。改的全是**读数的可信度结构**：
哪一块板没跑完的时候不许装成跑完了、一个拍的阈值旁边必须同时给出别的阈值下的同一块板、
一个"碰撞"的词必须写清它量的是焊盘包围盒还是器件本体。

## 1. 补掉的缺陷（7 条，逐条带症状与反向对照）

| # | 缺陷 | 原来的症状 | 修法 | 反向对照 |
|---|---|---|---|---|
| 1 | `pcbnew.LoadBoard` 卡死会拖死整轮 | `royalblue54L_feather` 在主进程里 **124.6 s**、CPU **0 %** 卡在 C++ 里；Python 层定时器无法中断（持有 GIL），一旦卡住整轮语料就停在那块板上 | 每块板一个**子进程**（`evaluate_isolated`），`BOARD_TIMEOUT=180 s` 硬超时；子进程用 `_EMIT` 标记把 JSON 从 pcbnew 的 `Adding duplicate image handler ...` 噪声里分出来 | `--timeout 5` 跑同一块板 ⇒ **5.0 s `not_run`**（见 §2.3） |
| 2 | 卡死的板被算成"测过" | 超时后如果只把 8 关标成 `error`，语料表会把 8 个 `error` 计入 measured，于是"没跑完"与"跑完了没通过"同权 | `_unrun_report()` 给整板 `verdict="not_run"`、`not_judged=全部 8 关`；`run_corpus` 里 `not_run` 的板**整板跳过**，独立进 `not_run` 桶，表里单列 `nr` 列，并在表头上方打一行 `not run (process did not finish, NOT counted as pass)` | 1 块板 + `--timeout 5`：`nr` 列全 1、`n=0`、判词 `无可判样本` |
| 3 | `crossing_frac ≤ 0.15` 是"拍的数" | 0.15 没有任何语料支持，判决却只印这一个阈值 | `CROSS_SWEEP=(0.10,0.15,0.20,0.25,0.30)`，同一块板在 5 个阈值下各报一格 `by_threshold` | RK3506：5 个阈值**全 fail**（0.3673），说明判决不是 0.15 卡的 |
| 4 | 总线振幅 `0.30` 也是"拍的数" | `47/49 放不下` 无法回答"是不是我把齿距选小了" | `AMPLITUDE_SWEEP=(0.20,0.25,0.30)`，`short_by_amplitude` 三条同报 | RK3506：`0.20 → 44/49`、`0.25 → 45/49`、`0.30 → 47/49`（齿距加倍只从 44 挪到 47，不是数的产物） |
| 5 | `overlaps` 被读成"器件碰撞" | canonical 里没有器件本体几何，`overlaps` 量的是**功能簇焊盘包围盒相交**，但报告里只写 `proposal_overlaps: 5` | `plan_floorplan` 输出 `overlap_basis: "group pad bounding boxes (not part bodies)"`，`gate_floorplan` 原样带上去 | RK3506 的 floorplan 读数里该字段与 `proposal_overlaps: 5` 并排出现 |
| 6 | **`--drc` 解析了却永远不生效**（本轮自曝） | CLI 有 `--drc`、`evaluate_isolated` 会把 `--drc` 传给子进程、子进程还会写 `drc_requested: True`，但 `evaluate()` **从没把 `drc` 放进 `ctx`** ⇒ `gate_closure` 里 `ctx.get("drc")` 恒为 falsy，**一条 DRC 读数都不会出现**。这是最坏的一种缺陷：用户以为跑了、报告里没有 ⇒ 读成"DRC 干净" | `evaluate(..., drc=False)` + `ctx["drc"]=bool(drc)`；子进程模式与 `--inprocess` 两条路都接上；新增 `test_the_drc_flag_reaches_the_closure_step`（monkeypatch `_ctx`/`ORDER`/`GATES`，断言 `ctx["drc"]` 确实是 True/False） | `--board _corpus/microwave.kicad_pcb --independent --drc` 现在印出 `drc_real 24 / drc_by_type {'shorting_items': 6, 'clearance': 2, 'text_thickness': 8, 'text_height': 8}`；隔离模式与 `--inprocess` **同一份数字** |
| 7 | `plan_floorplan` 的 `raise SystemExit` 逃过 `except Exception` | 无闭合板框时 `outline_box` 直接 `SystemExit`，`plan_sequence` 的 `except (Exception, SystemExit)` 之外的地方会漏，且 CLI 退出码不明 | 改 `ValueError`，`main` 捕获后印 `error : ...` 返回 2（0.1.37 已落地，本轮核对并写进测试口径） | `tests/test_plan_floorplan.py` 断言 `method in ("exact","coordinate_descent")`、`enum_budget == P.ENUM_BUDGET` |

另外两项（`plan_floorplan` 的 `ENUM_BUDGET=30000000` 穷举预算 + 坐标下降降级、以及坐标下降分支
引用未定义 `now_side` 的 `UnboundLocalError`）已随 `0.1.37` 提交，本轮只做核对，
`test_the_budget_is_what_decides_exactness`（把 `ENUM_BUDGET` monkeypatch 成 1 ⇒ 必须落到
`coordinate_descent`）已经把它们钉住。

## 3. `--drc` 接上之后，冒出一条新读数（不是缺陷，但必须记）

`--drc` 只报不判（`drc_origin="reported only, never judged"`），原因是 closure 的判据是
"网表是否全连通"，而 DRC 里混着本项目**主动降级为 house** 的项（丝印到板边、热焊盘、
`lib_footprint_issues`）。把它塞进判据，等于让 house 规则冒充物理判据。

接上之后拿 5 块语料板一跑，读数是：

| 板 | `closure` | `unconnected` | `drc_real` | `drc_by_type`（只列非 lib） |
|---|---|---|---|---|
| `complex_hierarchy` | pass | 0 | **1** | `copper_edge_clearance 1`（+ `lib_footprint_issues 68`） |
| `ecc83` | pass | 0 | **2** | `silk_edge_clearance 2`（+ lib 15） |
| `interf_u` | pass | 0 | **3** | `copper_edge_clearance 1`、`starved_thermal 2`（+ lib 25） |
| `pic_programmer` | pass | 0 | **12** | `hole_clearance 4`、`silk_edge_clearance 4`、`starved_thermal 4`（+ lib 5） |
| `microwave` | pass | 0 | **24** | `shorting_items 6`、`clearance 2`、`text_thickness 8`、`text_height 8` |

读法写死两条：

1. **`unconnected == 0` 不等于 DRC 干净**。5/5 板网表全通，DRC 真实违规 1–24 条。这两个数回答的是
   两个问题，不许互相代替。
2. `drc_artefact` 是 `board_loop.CWD_ARTEFACT = ("lib_footprint_issues",)` 的计数，走的是
   **同一个读取器**（`board_loop.drc`），所以不会出现"这里 30、那里 41"的漂移——`docs/166` 的口径
   （"引用 DRC 读数必须连 cwd 一起写"）在这里自动成立：仓库 cwd 下 lib 类计 artefact，
   工作时另算。

## 4. 仍然补不掉的（欠账表，不加粉饰）

| # | 欠账 | 为什么这一版补不了 |
|---|---|---|
| 1 | `bus` 关在语料上是**单样本** | 12 块好板里**一块带 DDR 网都没有**（`bus` 全 `n/a`），唯一可判的是 RK3506。要补样本只能再加带 DDR 的好板，不是改代码 |
| 2 | `LoadBoard` 卡死**没有根因** | `royalblue54L_feather` 124.6 s、0 % CPU、在 KiCad C++ 内部；能做的只有进程边界 + 死线，说不出它为什么慢 |
| 3 | **布局层 5 条**（`docs/167` 第三节） | 43 条网落在错的板边、U2 转 270° 只在几何上更好（重布探针 3/10）、8 条网从未布通、DDR 等长 need 342.2 只填 10.73、`square_corner 422`。这些要重布半块板，且用户明令**禁止自动布局/自动布线**，本工具链只测量 |
| 4 | `hole_in_pad 61`（盘中孔） | 剩 10 个孔 10/10 承载真实层间连接，删孔即 7→8；合法出路只有 VIPPO（明令禁止）或改布局让出 0.40 mm 通道 |
| 5 | DRC 读数**不进语料汇总表** | 刻意的：表回答"这条规则对不对"，DRC 回答"这块板干不干净"。混进同一张表，`route` 那行 house 判词与 DRC 的 house 项会互相冒充。`--drc` 的读数在 JSON 的 `steps[closure].measured` 里，可逐板引用 |
