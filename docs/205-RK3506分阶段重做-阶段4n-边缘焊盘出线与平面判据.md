# 阶段 4n —— 边缘焊盘出线、平面判据，以及「那 2 条网是穿 GND 面接上的」

这一阶段回答的是「7 条断网能不能接上」，答案比预期难看得多：**一条都不该按现在的方式接**。途中先修掉一个把它们全挡在门外的假障碍（边缘焊盘），再把 `layout.reference_plane_continuous` 这条 Critical 规则从「台账里有」变成「写盘会拒」，最后量出来一件之前没人说清的事——那 2 条看起来能接的 DDR 网，是**从 In1.Cu 的 GND 面中间穿过去**接上的。

**交付板 `examples/rk3506_som/rk3506_som.kicad_pcb` 逐字节未动**，也没有新增工具（仍 265），版本不动（阶段文档按先例不升版本、不进 CHANGELOG）。

## §1 结论先行

1. **7 条网里 0 条可以合法写盘**。2 条（`/DDR_A8`、`/DDR_A11`）能出计划，但计划的 19 条 op 里有 **9 条落在 `In1.Cu`**，而这个层是这块板唯一一块铺满的 GND（`zone.outline` 1934.0 mm² / 板 2025 mm² = **95.51%**）。另外 5 条在 `pitch 0.1 / clearance 0.1` 下全是 `search_budget`，**`rejected` 为空**——不是被规则挡住，是没搜到。
2. **新判据落地并进了写盘闸门**：`edit/planes.py`（只测量：哪个铺铜够格叫平面、这个计划会往哪些铺铜上落别的网的铜）+ `ruleset/precondition.py::plane_pour_intact`（只判断）。真板读数 `verdict = refused_at_plane_pour_intact`、`blocking = [precondition.plane_pour_intact]`，文案点名 `/DDR_A8` 落在 `/GND`（1934.0 mm²、95.5%）上、以及「铺铜会被官方 `ZONE_FILLER` 重切，所以 DRC 一句话不说」。
3. **同一份计划开 `allow_plane_crossing=true` 就能写**，但那一行 `ok` 仍是 `false`、`severity` 降成 `report`：放行不是洗白（与 `docs/201` 的 `allow_layer_changes` 同构）。
4. **测量失败必须 block，override 也盖不住**——「我知道我在切」不等于「我不想知道」。
5. **`edit` 里的操作坐标就是 canonical（Y-up），不要再翻一次 y**。我在 `edit/planes.py` 里一度加了 `_Y_FLIP = -1.0`，结果 19 op 的真板计划量出 `crossings: []`、闸门报 "no copper lands on a plane pour" —— 新闸门形同虚设且**没有任何报错**。根因是 `edit/build.py::segment()` 只在写节点文本那一刻调 `y_file()`。撤销后同一份计划读出 **2 条去重 crossing**（9 段 In1 铜落在同一块面上，按 `(net, layer, pour_net)` 去重）。
6. **反向对照有牙**：把 `py = y` 改回 `py = -y`，`tests/test_plane_pours.py` **6 failed / 5 passed**；改回后 **11 passed**。
7. **一个更要紧的发现**（§7）：路由器**自己**把 `In1.Cu` 标成平面层（`layers_plane`），却又允许走线走上去——`grid_layers = routing + planes`、铺铜内部只标「边沿」不填内部、`walk_layers=None` 的含义是「栅格里的每一层」。所以「2 条网能接」不是布线的胜利，是**默认参数允许穿平面**的产物；把它们限制到信号层（`new_copper_layers=F/In2/In4/B`）之后，同一批网 **0 op**（A11 `search_budget`、A8 `no_path`）。
8. **边缘焊盘必须先豁免**，否则这 5 条网连「搜」的机会都没有：J1 是 140 pin 邮票孔连接器，焊盘中心正好落在 `Edge.Cuts` 上（`x=45.0`，焊盘 0.85 方），旧判据把焊盘自身那截铜当轨道铜去量到板边，首段一律 `too_close_to_edge`。合成反向对照：同一块板上 `WITH fix → ops 2 / rejected []`，`WITHOUT fix → failed / ops 0 / rejected too_close_to_edge short_by 0.425`。
9. **测试**：`test_plane_pours.py` **11 passed**；`test_edit + test_plane_pours + test_rule_projection + test_length_corridor + test_blockers` = **100 passed（39.48 s）**。

## §2 边缘焊盘出线：先把假障碍拆掉（提交 `8303f78`）

`grid._edge_for_segment` 原来把整段铜送给「到板边距离」去量。板上有一类焊盘**中心就在板边**（castellation / 邮票孔），焊盘自己的铜必然有一部分落在板边带里——那不是走线违规，`ruleset/measure.py::_castellated` 早就按这个口径放过它了（先例是出货的 Adafruit Feather）。于是这类网的首段（焊盘中心 → 最近的自由格）在真板上**没有任何一条能出去**。

改法：`grid._pad_span(a, b, poly)` 用二分 + `point_in_polygon`（不是 bbox 裁剪——圆角焊盘的角落在 bbox 内，用 bbox 会掩盖真违规）求出线段落在**同网焊盘铜**里的 `t` 区间，把这些区间从待测段里剪掉，只量剩下的铜。三个边界写死：两端都在焊盘内才整段豁免、只有一端在内只豁免一段、跨过焊盘但不落在其上的段不豁免（否则等于豁免与它无关的铜）。栅格侧不用动：合法逃逸必然有 `pad_half >= edge + track/2`，焊盘铜伸到带外，其带外格子在 `_mark_copper` 之后对本网是 free 的。

同一提交还修了一个**假成功**：`em.track` 失败时只写 `status/reason`、`ok` 仍是 `True`，随后 `if ok:` 又把 status 覆盖成 `routed` —— 板子回「routed」，可首段铜离焊盘 0.8 mm、什么都没连上。现在失败即 `escape_failed`、不加 segments、走 rollback，`status` 保持 `failed`。

两条都有合成反向对照（`_q3_reverse2.py` / `_q4_e06.py`，都以「关掉修的东西、同一块板必须换个答案」为判据）：

| 探针 | 条件 | 读数 |
| --- | --- | --- |
| `_q3` | 焊盘中心在 `x=0`（板边），`edge_clearance 0.3` | `WITH fix`: `failed=False ops=2 rejected=[]`；`WITHOUT fix`（`_pad_spans` 返回空）: `failed=True ops=0 rejected=[('too_close_to_edge', 0.425)]` |
| `_q4` | 同一块板，`edge_clearance 0.6`（大于可达距离） | `failed` = `terminal_unreachable`，`open_sectors` 空、8/8 方向全关，`probe_radius_mm 0.725`、`short_by_mm 0.225`，`via_in_pad.fits=False` |

`_q4` 是「宁可报错不给错答案」的那一半：豁免不是「一律放行」，出不去的时候点名报出来、并列 8 个方向与盘中孔也放不下的原因。

## §3 平面判据：测什么、判在哪

规则早就在：`calc/rules.py` 的 `layout.reference_plane_continuous`（**Critical**）。这一阶段之前，写盘路径里**没有任何一处问过它**。

- `edit/planes.py`（只测量，不做判断）
  - `board_area(board)`：外框 bbox 面积（adapter 的 outline 既可能是点列也可能是带 `points` 的 dict）。
  - `pours(board)`：每个非 keepout 铺铜的 `net / layers / ring / area_mm2 / share / bbox`。**面积取的是 `zone.outline` 的声明面积**，不是 `filled_polygon`——闸门文案里的 1934.0 mm² / 95.5% 就是这个口径；重填后的实际铜是 **1773.03 mm²**（`_r7_pa.json` 的 `pour.zones[0]`，`before 1809.1031 → after 1773.0278`）。两者都远超 0.5，分类不受影响，但这**两个数不是同一个数**，引用时不许混。
  - `PLANE_SHARE = 0.5`：铺铜**声明面积**覆盖板面 ≥ 50% 才叫平面。这是**声明不是证明**：本板 `In3.Cu` 三个网 352.59（17.41%）/ 234.35（11.57%）/ 23.78（1.17%）全部 < 50%，穿过它们只报不挡（「17% 的分割电源面能不能穿」是设计问题）。
  - `crossings(board, operations)`：`add_track` 沿段采 5 点、`add_via` 取 `op["layers"] or layers`，逐点判 bbox + `point_in_polygon`；同网铺铜不算穿越；结果按 `(net, layer, pour_net)` **去重**，每条带 `plane` 与 `at`。
- `ruleset/precondition.py::plane_pour_intact`
  - `copper_write=False`（纯读计划）→ `ok=None`、`severity=report`；
  - `report["error"]`（测量失败）→ `ok=False`、`severity="block"`，**`allow=True` 也盖不住**；
  - 命中平面 → block；`allow=True` 时 `severity` 降 `report`、`ok` 仍 `false`；
  - 命中非平面铺铜 → 只报。

**量的是「计划后」的板**：`edit/plan.py` 用 `adapters.kicad_pcb.parse_board_text(new_text, path=path)` 解析**将要写出去的那份字节**，所以本计划自己加的铺铜也在里面。

## §4 坐标帧：op 是 canonical，翻一次就够了（含我自己错一次的记录）

canonical adapter Board 是 **Y-up**（`adapters/kicad_pcb.xy()` 返回 `(x, -y)`），`edit` 模块内部一律 canonical，**写盘时才翻**（`edit/build.py::segment()` 用 `y_file()`；`track_arc` / `via` 同理）。所以 `board_propose` / `board_edit` 的 `add_track` / `add_via` 坐标就是 canonical，和 router 输出、和铺铜 `zone.outline` 同一帧。

铁证（不用猜）：`/DDR_A8` 的 U2.T8 焊盘 canonical 坐标 `(23.4, 4.0)`，而 `_r1_plan.json` 的 op#0 正是 `x1=23.4, y1=4.0`。

我在第一版 `edit/planes.py` 里加了 `_Y_FLIP = -1.0`（注释还振振有词：「KiCad 向下生长、canonical 向上，所以计划点要翻」），后果是**静默的**：19 op 的真板计划量出 `crossings: []`，闸门报 "no copper lands on a plane pour"，测试里的半板平面也照常通过——一次都不报错。

撤销后同一份计划：

```
plane_pours: board_mm2 2025.0
             planes [{In1.Cu /GND 1933.989 mm2 share 0.9551}]
             crossings [{/DDR_A8  In1.Cu /GND plane true at [23.8, 4.4]},
```

**去重是 2 条，不是 9 条**：19 条 op 里 9 条在 `In1.Cu`（A8 4 段、A11 5 段），它们落的是同一块面上的同一个网，`crossings` 按 `(net, layer, pour_net)` 去重后每网 1 条。闸门文案引用的是**第一条**（A8），完整列表在 `precheck.plane_pours.crossings`。

## §6 为什么一条都不该写盘

三条理由，按优先级从高到低（用户的口径是「规则也是有优先级的，应当先满足高优先级的设计」）：

1. **Critical：`layout.reference_plane_continuous`。** DDR 的唯一路径是穿 `In1.Cu` 的 GND。铜本身合法（`ZONE_FILLER` 会绕开它重切），所以 **DRC 一句话不说**；代价是回流路径被切两刀、GND 让出 36.08 mm²。这就是新判据要挡的东西：合法铜、静默的电气伤害。
2. **High：这 5 条网是布局问题不是布线问题。** 三面/四面被「可移动的焊盘」堵住（`fixed 0`），挪掉的代价由布局决定；在 0.1 mm 极限上把 `pitch` 降到 0.05 只买回 3 条、还破坏本板的工艺口径。
3. **DRC：0.2 mm 余量。** 闸门默认 floor 是 0.2，这块板净空是 0.1；真写一次就撞在 0.1222 mm 上。**这不是「本轮偷偷放水」**：`precheck_clearance_mm` 是 `docs/199` 就公开的选项，用它声明「本设计自己的 netclass 是 0.1」是正当用法，`allow_new_violations` 一次都没用过。

另外，`board_propose` 现在会把这三件事一次性摆在计划里：`precheck.plane_pours`（哪块面会被切）、`precheck.pour`（要不要重填）、`preconditions.checks`（逐条判据与 `how_to_clear`）。

## §7 新发现：路由器把 `In1.Cu` 叫平面，又允许走上去

`route/router.py::_split_layers` 只把**有电源样铺铜**的层降级为平面（`In1.Cu /GND`、`In3.Cu /+3V3`），这没问题；问题在下一行：

```python
grid_layers = list(routing) + [l for l in planes if l not in routing]
```

栅格把平面层也收进来（这是对的：过孔必须避让），但 `walk_layers` 的默认值是 `None`，而 `grid.astar` 的文档写得很清楚：**`None` = 栅格里的每一层**。再加上 `Grid._mark_keepouts` 对铺铜只标**边沿**（`fill_in=False`，注释还写着「a track crossing it is legal」），于是默认参数下走线可以横穿整块 GND 面。

两个连带事实：

1. `plan()` 的 docstring 说「`None`（默认）是历史行为：任何**收集到的**层也是新铜层」，而收集到的层只有 `routing`（平面层不参与 `_pad_terminals`）。**文档与行为不一致**——按文档读，默认不该在 In1 上出铜。
2. 所以 `_r1` 的「2 routed」和「GND 面被切」是**同一批铜**；`_r8` 把新铜限制到信号层后是 **0 op**。两个读数合起来才完整：这块板 DDR 在信号层上确实无路（`no_path` / `search_budget`），现在这条路是穿平面换来的。

**本轮不改默认值。** 把 `new_copper_layers=None` 改成「等于 `routing`」会一次性改变所有调用的输出（默认行为变更），必须带着「改完哪些板还能通、哪些不能」的读数单独立项；本轮只把它写成欠账，并把判据放在写盘闸门上——**闸门是最后一道，它现在真的会拒**。这也是「规则优先于工具便利」的落点：路由器可以提出穿平面的方案，写盘不许。
