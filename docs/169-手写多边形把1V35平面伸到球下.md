# 169 · 手写一个多边形：把 `/+1V35_DDR` 的 In3 平面伸到 U1 球下，未连接 8 → 7

`docs/168` 把 8 条未连接网量到了坐标级：五条 J1 网被 U1 顶边的扇出走廊挡住，`/+1V35_DDR` 被
"平面只到 y=16.5、球在 y=26.05"挡住。本文只动后一条——因为它是**唯一一条能靠人手写几何解决、
不需要重排扇出、也不需要任何搜索**的。

改法只有一句话：**在 In3.Cu 上把 `/+1V35_DDR` 的多边形往上长出一条 2.6 mm 宽的脖子**，够到板子
本来就已经布好、但一直悬空的那 5 个缝合孔。铜仍然由官方 `ZONE_FILLER` 灌注。

## 1. 先确认：这条网在信号层上真的没有通道

`docs/168` 证明过横向不行。这一版先补竖向：从平面顶边 `(22.3442, 16.0)` 竖直到母线
`(22.3442, 26.3309)`，四个信号层逐段采样：

| 层 | 最小余量 | 阻塞采样 |
|---|---|---|
| F.Cu | −0.093 | 39 / 104 |
| In2.Cu | −0.095 | 31 / 104 |
| In4.Cu | −0.095 | **102 / 104**（几乎整段是铜） |
| B.Cu | −0.097 | 61 / 104 |

四个层全是负余量（中心线落在别人铜里）⇒ **没有信号层通道**。同一批读数里还有一条结构性的事实：
`/USB1_DP` 在 y=33.058 横走时，**六个铜层（含 In1/In3/In4/B.Cu）的阻塞区间完全重合**在
x 23.37…27.67（各层 `min` 都是 −0.145，In4 是 −0.289），只有远端各有差异 ⇒ 那一段不是"某个层挤"，
是一排**贯穿所有层的过孔墙**（U1 顶边扇出的缝合孔），任何换层都绕不开。

所以 `/+1V35_DDR` 只能走平面。

## 2. 关键发现：那 5 个缝合孔本来就在，一直是悬空的

`docs/167/168` 一直把这条网描述成"缺口 9.72 mm、没有过孔"。这一版把该网的全部 26 个孔列出来才看清：

```
via ( 20.3060, 26.3309) 0.20/0.10
via ( 20.9560, 26.3309) 0.20/0.10
via ( 21.6060, 26.3309) 0.20/0.10
via ( 22.2560, 26.3309) 0.20/0.10
via ( 22.9060, 26.3309) 0.20/0.10
```

**y = 26.3309 这一排已经有 5 个 `/+1V35_DDR` 的 0.2/0.1 过孔**，正好压在 U1 那五颗 1V35 球的
0.1 mm 扇出母线（x 20.0251…22.9059 连成一条）上。它们悬空，唯一原因是 **In3 的平面在 y=16.5 就收了**。

这条读数是本轮最省力的地方：不需要放任何新孔，只需要让铜长过去。

### 2.1 一个真实的错，留在这里当记录

第一版我在 `(22.3442 / 21.6942 / 21.0442, 26.3309)` 又加了 3 个 0.2/0.1 过孔。DRC 立刻报 **3 条
`hole_to_hole`**（最小 0.15 mm，实际 **0.0000 mm**）——因为现有孔在 20.956 / 21.606 / 22.256，
两者相距 **0.088 mm**，等于钻在同一个位置。

**教训：动手前先把该网自己的几何列全**（`tracks` 与 `vias` 一起），否则"补一个孔"会变成"在已有的孔上
再钻一个"。删掉 3 个新孔后 DRC 里没有 `hole_to_hole`。

## 3. 手写的那一个多边形

原多边形是纯矩形，四个点（pcbnew `zone.Outline()` 实测）：

```
(12.8, 3.0) (36.5, 3.0) (36.5, 16.5) (12.8, 16.5)
```

新多边形，8 个点（在顶边上插一个脖子，x 20.0…23.2、顶到 y = 26.7）：

```
(12.8,3.0) (36.5,3.0) (36.5,16.5) (23.2,16.5)
(23.2,26.7) (20.0,26.7) (20.0,16.5) (12.8,16.5)
```

尺寸选法（都是量出来的，不是拍的）：

- **x 20.0…23.2**：那 5 个孔在 x 20.306…22.906 ⇒ 左右各留 0.3 mm 以上；脖子宽 **3.2 mm**。
- **顶 y = 26.7**：孔在 26.3309 ⇒ 上方留 0.37 mm，够 `ZONE_FILLER` 把热焊盘画出来。
- **不需要担心和 `/+3V3` 打架**：`/+3V3` 的 L 形在 y 23.8…27.3 那一段只占 **x 15.5…17.5**（下面第 5 节
  的自由空间图逐格印证：y=24.00 整行是 `.`，x 20…23.2 根本没有 3V3 铜）。所以脖子伸进去的是空地。

落盘顺序（工作区 `_plane_ext.py`）：`zone.Outline()` → `RemoveAllContours()` →
`idx = NewOutline()` → `o = Outline(idx)` → 逐点 `o.Append(FromMM(x), FromMM(-y))`（**两参数，
不是 VECTOR2I**；`NewOutline()` 返回 **int 不是对象**），然后 `pcbnew.ZONE_FILLER(b).Fill(b.Zones())`。
**不新建任何铜**，脖子是 zone 几何，铜由官方灌注器生成。

## 5. 视觉复核

渲染只含 In3.Cu 的图（`_rndz.py`，crop x 17…38.5 / y 1.5…28.5，1500 px）确认三件事：
脖子从下方矩形主铜箔向上延伸、**底部连为一体**；穿过的密集过孔只是圆环镂空，**没有把铜切成孤立小块**；
整层**无缺口或断裂**。这与 `1V35 outlines == 1` 的数值一致。

## 6. 这一步为什么可以只写坐标

平时"改一处铜"之所以要重布，是因为改动会破坏周边既有铜。这里不成立：

- 脖子伸进去的是 **In3 上没有铜的空地**（`/+3V3` 在那一段只占 x 15.5…17.5）；
- 唯一与之相交的是穿层过孔，而平面与过孔的净空、热焊盘、孤岛剔除**全部由 `ZONE_FILLER` 负责**，
  人只需要给多边形；
- 5 个缝合孔是既有铜，我没有移动、没有新增任何一件铜。

所以这是一次**纯粹的几何决策**（多边形 8 个点），不是布线。它也没有用到任何搜索。
