# 等效转换的信息丢失审计

日期：2026-10-27
承接 `01-AI原生的PCB表示.md`、`02-占用可通行表示与经验累积.md`。
本篇回答：**现在的 L1(spec)/L2(digest)/L3(query)/L4(算法) 四层表示，还会丢什么。**

---

## 0. 先定"不丢失"的判定标准

一条信息算**没丢**，当且仅当三条同时成立：

1. **可达**：digest 里有，或能通过 `query/measure/pads_of/...` 按需取回；
2. **精度够**：取回来的精度足以支撑它要支撑的那个决策；
3. **语义在**：有字段名和单位，不是一堆裸数字。

否则就是丢了。丢的方式分四种，处置完全不同：

| 丢失类型 | 含义 | 能否靠"更好的转换"解决 |
|---|---|---|
| **S 采样丢失** | 数据本来有，被栅格/降采样吞掉 | ✅ 加精确查询兜底即可 |
| **E 语义丢失** | 数据在，但表示里只剩裸数字/丢了含义 | ✅ 加字段即可 |
| **T 结构丢失** | 表示里根本没有这个维度 | ⚠️ 要改模型 |
| **G 源缺失** | **PCB 文件本身就不记录** | ❌ 转换再好也变不出来，只能外挂知识 |

**最重要的一句：G 类不是"转换的缺陷"，是"数据源的缺陷"。** 把所有力气花在无损压缩 PCB 文件上，得到的仍然是一个不知道"为什么这样设计"、也不知道"这条线下面有没有地平面"的模型。

---

## 1. 丢失清单

### 1.1 S 采样丢失（我设计里最明显的洞）

| 信息 | 现状 | 后果 | 补救 |
|---|---|---|---|
| 亚栅格隘口（0.6mm 缝） | 只在 `warnings` 里提一句，没有取回通道 | AI 认为通 → 布线失败 → 重试烧上下文 | 必须有精确 `clearance(a,b)` / `gap_at(x,y)`；digest 每条 warning 带可执行的查询句柄 |
| 走线几何形状（圆弧、45°、任意角） | 栅格化后只剩"这里有线" | 无法判断"这条线是否从焊盘边擦过" | `trace_geometry(net)` 返回原始折线/弧 |
| 板外形 | 只有 `size: [63,33]` | 丢了非矩形轮廓、**内部开槽**、异形边、拼板 V-cut | 板框改成多边形 + 孔/槽列表 |
| 局部极小器件/焊盘 | 1mm 栅格下 0402 就是 1~2 个格子 | 布局判断"这里空着"其实并不空 | 器件表优先于网格；网格只做粗判 |

### 1.2 E 语义丢失（有数据，没含义）

| 信息 | 现状 | 后果 | 补救 |
|---|---|---|---|
| **引脚电气类型** | 我的 Pin 只有 `number/name/type(笼统)` | 无法预判 ERC（两个 output 直连、power 未驱动）；只能跑完 ERC 被动改 | pin 表带 `etype: input/output/bidi/tri_state/passive/power_in/power_out/open_collector/open_emitter/nc` |
| **引脚↔焊盘映射** | 我假设 pin 号 = 焊盘号 | BGA 球号、多 pad 同 pin、**Thermal Pad（EPAD，常是 pad 9 但不是引脚 9）**、多单元器件 | 显式 `pin_pad_map`，且允许 1:N / N:1 |
| **多单元器件（multi-unit）** | Component 没有 unit 概念 | LM324 一个封装四个 opamp，AI 当四个器件 → 位号错乱、ERC 假报 | Component 带 `unit`/`unit_count`/`units_used` |
| 焊盘形状 | 只有 `w×h` | 丢了 roundrect 圆角、长圆孔/槽孔(NPTH slot)、自定义多边形焊盘、**阻焊开窗和钢网** | `pads_of(ref)` 返回 shape/mask_expansion/paste/hole；制造规则要用到 |
| 热焊盘（thermal spoke） | 覆铜画成 `~` | 不知道 spoke 数量/角度 → 焊接与散热都会出问题 | 覆铜对象带 `thermal` 参数 |
| 网络类继承与优先级 | 我给了 `constraints` 平铺列表 | 不知道哪条规则覆盖哪条 → AI 可能按被覆盖的旧规则判断 | rule 带 `priority` + `pattern`，并给出**生效后的最终值** |
| 等长组的长度参考点 | 只有 `match: ±0.5` | 从哪个 pin 算？从连接器还是从 BGA ball？差几 mm 就判错 | `match_ref: <pin>` 显式 |

### 1.3 T 结构丢失（表示里没有这个维度）

| 信息 | 后果 | 严重度 | 补救 |
|---|---|---|---|
| **参考平面连续性 / 跨分割** | 建议走一条下方无完整地平面的线 → SI 崩、EMC 崩，**但 DRC 全绿** | 🔴 最危险：AI 会以为自己对了 | 加 `reference_plane(path)` 查询 + `plane_split` 图层；把"跨分割"作为 hard gate |
| 孔的类型（通孔/盲孔/埋孔/背钻/孔环/塞孔） | 2 层板无感，4 层以上直接算错成本与可行性 | 🟠 | via 表带 `type/annular_ring/plugged` |
| 叠层结构（介质厚度、材料、铜厚） | `impedance: 90` 无法求解 → AI 会瞎给线宽 | 🟠 | stackup 进 spec；阻抗由叠层+线宽算出，不让模型猜 |
| 平面分割/负片/孤岛 | 覆铜被当成一整块 | 🟠 | 覆铜对象带 `islands[]` 与 `split_by` |
| 电流/载流与温升 | 线宽只是"规则最小值"，实际由电流决定 | 🟠 | `current_a` 进 net；最小线宽由 IPC-2221 算出 |
| 3D 高度/装配干涉 | AI 把高器件放进了外壳矮区 | 🟡 | component 带 `height_mm` + keepout 带 `z_max` |
| **协作/锁** | 立创有团队协作，AI 可能覆盖同事正在改的页 | 🟠 | `who_locks(page)`，写前检查 |
| 内存态 vs 磁盘态 | 用户有未保存修改，AI 读到旧的 | 🟠 | digest 标 `dirty: true` + 差异摘要 |

### 1.4 G 源缺失（PCB 文件里根本没有，转换变不出来）

这一组是**上限问题**，必须承认并外挂，不要假装能表示：

| 信息 | 为什么源里没有 | 外挂方式 |
|---|---|---|
| **设计意图**：为什么这样布、这条 net 为什么必须最短 | 只存在于设计者脑子里/datasheet | L1 spec 的 `constraints` + `rationale` 字段；经验库 |
| **datasheet 的 layout guideline**（"输入电容必须紧贴 VIN 与 GND"） | 在 PDF 里 | 经验库（per-MPN 条目）+ `part_search` 时一并召回 |
| **功耗/发热** | PCB 不记功率 | 从 MPN/BOM 查，或 spec 手填 `power_w`；否则热评估一律标"不可用" |
| **成本与工艺档位**（0.15mm 线宽加不加价、能不能 4 层） | 是商务/工厂信息 | spec 里 `fab_profile`；线宽/间距/孔环设定由板厂能力表约束 |
| **已豁免的 DRC（waiver）** | 在项目历史/评审记录里 | spec 的 `waivers[]`；`validate` 输出必须分 `new` / `waived` |
| **工艺约束**：Mark 点、工艺边（传送边）、拼板、V-cut、SMT 单面方向、底面重器件 | 一部分在文件里，一部分是工厂约定 | `fab_profile` 当 hard gate：贴边器件、双面回流冲突可机判 |
| **测试/生产需求**：测试点、ICT、烧录口、天线净空 | 部分是约定 | spec 显式声明，缺失时布局工具**拒绝**给出"可生产"结论 |
| **评审意见与历史决策** | 在 IM/邮件里 | 经验库 |
| **视觉观感**（丝印可读性、装配图人因） | 不是几何问题 | 只能 `preview()` 给图，且必须标"此项需人判断" |

## 2. 最危险的五个（会以"全绿"的方式骗过 AI）

按"错了但看不出来"排序：

1. **跨分割 / 参考平面不连续** —— DRC 不报，电气也未必立刻错，但 EMC/SI 崩。AI 会自信地继续。
2. **焊盘阻焊/钢网与制造能力** —— DRC 按设计规则过，但板厂做不出（阻焊桥 <0.1mm、孔环不足）。属于"过了规则、过不了工艺"。
3. **pin↔pad 映射（EPAD / BGA / multi-unit）** —— 连接对象错但名字看着对，ERC 可能也不报（因为符号是对的）。
4. **被栅格吞掉的隘口** —— AI 判定"这条走廊 1.2mm 够用"，实际是 1.2mm 被两根线夹住，真通不了。
5. **waiver 列表缺失** —— AI 反复去"修"一个项目已经接受的违规，改坏真设计。

**共同特征：这几项的错误都不会在 DRC 里现形。** 所以不能靠"跑一遍 DRC 就放心"。

## 3. 对策：三层兜底

### 3.1 每份 digest 自带 `blind_spots`（强制）

这是最便宜也最有效的一条——**让表示自己申报盲区**，模型就不会过度声称：

```yaml
blind_spots:
  - "参考平面连续性未建模：不能据此判断某条走线下方是否有完整地平面"
  - "未含焊盘阻焊开窗：0.5mm pitch 的最小可布线宽须用 pads_of(ref) 精确查询"
  - "未含功耗：热评估不可用"
  - "栅格 1.0mm：小于 1mm 的间隙未建模，判定'通行'前须用 gap_at(x,y) 复核"
  - "waiver 列表为空：DRC 输出可能包含已接受项"
```

规则：**任何 tool 的结论若依赖 `blind_spots` 里的条目，必须返回 `confidence: low` 并附"需补充查询"的具体调用**，而不是给一个看着确定的答案。

### 3.2 决策→查询 的强制绑定

不要指望模型自觉。把"高危判断"做成**必须带证据的 tool**：

| 决策 | 强制前置查询 |
|---|---|
| "这里能走线" | `gap_at(x,y, layer)` |
| "这个间距够" | `min_clearance(a, b)` |
| "这个器件放得下" | `fits(ref, rect)`（含 courtyard + 阻焊 + 丝印） |
| "电源线这样够" | `min_width_for(current_a)` |
| "布线完成" | `unrouted()` + `cross_split(net)` 双零 |

### 3.3 承认不可表示的部分，走算法/人

| 不可表示 | 交给谁 |
|---|---|
| 布线路径本身 | 布线器 |
| 布局坐标求解 | 装箱/退火求解器 |
| SI/PI 定量 | 场求解器（或直接不给结论） |
| 视觉观感 | 人（`preview` + 明确"需人判断"标记） |
| 设计意图 | spec 的 `rationale` + 经验库 |

---

## 4. 结论

**现在的设计丢的信息按危害排序是：G(源缺失) > T(结构) > E(语义) > S(采样)。**

- S 和 E 是工程活，加字段加查询就能补，且**必须补**（尤其 etype、pin_pad_map、pads 完整几何、waiver）。
- T 里只有一条是致命的：**参考平面/跨分割**。4 层以上板子不补这条，AI 的布线建议就是"看起来对、物理上错"。
- G 类无法靠转换解决。正确的姿势不是"想办法表示意图"，而是**在缺意图时拒绝给结论**——这也是 `blind_spots` 存在的意义。

一句话判据：**如果一条信息丢了之后，AI 的错误仍然能让 DRC 全绿，那这条信息就是最高优先级。**
