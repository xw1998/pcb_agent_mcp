# 14 · 原理图写路径：裁判换成网表与 ERC

> 回答的问题：**板**已经能写了（12、13 篇），**原理图**凭什么能写？
>
> 推翻的东西：**"板写路径的闸门可以照搬到原理图"**。DRC 判的是铜：间距、短路、开路线。
> 而原理图的产品是**连通性** —— 两条坐标完全正确的线，只要没搭在一起，就是两张互不相干的图，
> 而 DRC 那一套在这里没有任何话可说。所以这一层的裁判只能是 **网表 + ERC**。
>
> 结论先说：KiCad `.kicad_sch` 已在写路径上，18 个 op、四道闸门、在真实 demo 图纸上跑通；
> **立创 Pro 的 `.esch` 明确拒写**（不是"以后做"，是"现在拒"，见 §7）。

## 1. 坐标系是与板相反的，而且不许悄悄取反

原理图文件里 Y 向下（页面左上角为原点），板文件 Y 向上。两套坐标系共存是本层最容易埋雷的地方：
如果把板路径的习惯带过来取反，整张图会被镜像，**而 KiCad 不会报任何错** —— 镜像的原理图语法合法、
ERC 也能过，只是所有东西跑到别处去了。

决定：**原理图 op 全部用文件坐标系（mm，Y 向下，不取反）**，理由不是"更好"，而是**模型读到的
一切都在这个系里**：`.kicad_sch` 里的 `(at x y)`、库符号的引脚坐标、KiCad 状态栏的读数，全是 Y 向下。
模型的输入是这个系，输出却换一个系，等于要求它每次做一次心算镜像。

代价：两套坐标系。因此 `schematic_ops` 每一条 op 都带 `coordinates`，`schematic_view` /
`schematic_summary` / `schematic_apply` 的每个返回都重复 `frame` 字符串：

```
millimetres in the schematic's own file frame: origin at the page's top-left,
Y increases DOWNWARDS (the numbers you read in the .kicad_sch).
The board write path uses Y-up; this one does not.
```

## 2. 写什么：18 个 op，形状照抄真实文件

## 3. 符号体绝不发明

`add_symbol` 的定义来源有三级，**缺一级都不许编**：

1. 本图 `lib_symbols` 里已有同名定义 → 直接用；
2. 调用方给 `library`（如 `D:/KiCad/10.0/share/kicad/symbols/Device.kicad_sym`）→ 从库里取；
3. 调用方给 `definition`（一段 S 表达式）→ 用它。

三级都没有 → `MISSING_SYMBOL_DEFINITION`，报错，不生成一个"看起来像电阻"的空壳。
库版本与图纸版本不一致时只给 warning（KiCad 容忍未知字段，实测嵌入的是旧版投影，多/少
`in_pos_files` / `show_name` 之类的字段也不影响打开）。

`reference` 已存在 → `REFERENCE_EXISTS`；`value` 缺失 → 拒绝（Annotate 之前没有值不是错误，
但**以为有值**是）。

## 4. 四道闸门，裁判是厂商引擎

```
schematic_propose(path, operations) → plan_id + digest 前后 + 预测的 netlist/ERC diff
schematic_apply(plan_id, confirm=true) → checkpoint → 原子写 → 四道闸门 → 任何一道不过就回滚
```

| 闸门 | 问题 | 不通过时 |
|---|---|---|
| `bytes_written` | 盘上的字节 == 计划的字节？ | 回滚 |
| `token_identity` | 重新解析，逐原子重现计划的树？ | 回滚 |
| `postconditions` | 每条 op 的承诺能从盘上文件读回来？ | 回滚 |
| `engine` | KiCad 的**网表**与 **ERC** 在改前/改后的差集 | 见下 |

`engine` 的两条 blocking 规则是本篇的全部意义：

- **只动了 symbols / text，网表却变了 → 拦住。** 一个字段编辑不可能改变连通性；如果网表变了，
  说明某个隐藏的东西在动（最典型：改 `#PWR` 的 `Value` 就是给电源网改名）。测试
  `test_renaming_a_power_symbol_is_blocked_as_a_netlist_change` 把这件事钉成事实。
- **新增 ERC 违规 → 拦住。** 悬空的 label 会被 `kicad-cli sch erc` 看见，然后回滚。

反方向的偏差不拦但要说出来：计划声称改连通性而网表没变 → `warning`（删一条本来就孤立的短线是
合法编辑，但这正是"计划自欺"最可能的样子，所以出声）。

## 5. 真机取证：两个闸门 bug 是被真图抓出来的

跑真实 demo（`cm5_minima/CM5.kicad_sch`，176 条既有 ERC 违规）时，一个**纯字段改名**被拦下了，
理由两条，都是闸门自己错：

1. **把"元件值变了"报成"网表变了"。** 网表里每个元件是 `(ref, value, footprint)`，改 value 当然
   让这条记录变化 —— 但那不是连通性。修法：`netlist_diff.changed` 只认**网**（新增/消失/节点增删）
   与**元件增删**，值/封装的变化单独走 `metadata_changed`，只给 warning。
2. **同一条 ERC 违规被算成"新增一条 + 解决一条"。** KiCad 会把同一条 `net_not_bus_member` 在不同
   次运行里指向该违规的**不同 item**，于是坐标变了。修法：违规身份 = `(sheet, type, severity,
   description)`，**位置只报不判**。重复出现（计数上升）仍然会被抓到，只是移动不再伪装成新增。

第二条如果没修，任何一个"顺手改个注释"的提案都会在真板上被随机拦住 —— 而这种拦截比不拦更坏，
因为人会很快学会 `allow_new_violations=true` 一按了之。

## 6. ERC 与网表是怎么读的（实测 schema）

`kicad-cli sch erc --format json -o out.json <sch>`：

```json
{"$schema": "erc.v1", "coordinate_units": ..., "kicad_version": "10.0.7",
 "ignored_checks": [], "included_severities": [],
 "sheets": [{"path": ..., "uuid_path": ...,
             "violations": [{"type": ..., "severity": ..., "description": ...,
                             "items": [{"description": ..., "pos": {"x": .., "y": ..},
                                        "uuid": ...}]}]}],
 "source": ...}
```

`sheets[].violations` 里**没有** `sheet` 字段，所以本服务在扁平化时补上它 —— 否则多页图纸的
同一条违规分不清在哪一页。`erc_diff` 的比对键里第一位就是这个补上的 sheet。

`kicad-cli sch export netlist --format kicadsexpr -o out.net <sch>` 解析成
`{nets:[{name, nodes:[[ref,pin]]}], components:[{ref,value,footprint}]}`；**nets 按 name 排序、
nodes 排序**，消除 net code 带来的噪声，否则两次运行的同名网络可能因枚举顺序不同而"变化"。

report 与 netlist 全部写在临时目录，**一个字节都不写在工程旁边**。

## 7. 立创侧：明确拒写，而不是"以后做"

`.esch` 图纸在 `.epro` 归档里，是一套与 `.epcb` 不同的记录流。它在 13 篇之后**仍未被测量**：
没有在真实保存上比对过"一次保存改写了哪个成员、字段布局是什么"。所以这一层是
`WRITE_UNSUPPORTED_FORMAT`，并且**指名道姓说清楚**：

- 指向 zip（`.epro`/`.eprj`）→ "这是立创容器，原理图写路径未实现"
- 指向 SQLite（`.eprj`/`.eprj2`）→ "板/图的行在 `projects.ticket` 旁边，手改会让应用判为 stale"
- 指向 `.kicad_pcb` → `FORMAT_NOT_SUPPORTED` + 告诉它该用 `board_propose`
- 指向其它文本 → `NOT_A_SCHEMATIC`

容器判定**只看内容**，不看扩展名（`PK` / `SQLite format 3` / `(kicad_sch` / `(kicad_pcb`）。

## 8. 还差什么

- `.esch` 写路径：需要先在一台装了立创 Pro 的机器上做一次「保存前后逐成员比对」，13 篇那套方法
  换个成员再跑一遍。在此之前保持拒写。
- 多页工程：本层按**单张图纸文件**写。跨页改动（改 `sheet` 的引脚、改 `Sheetfile`）不在 op 表里，
  因为改子图会牵动父图的实例路径与页码，而"改一张图"和"改一个工程"是两个风险等级。
- `lib_symbols` 版本升级（把旧投影换成当前库定义）：只报 warning，不做替换 —— 替换会改所有实例
  的引脚号，风险远高于收益。
