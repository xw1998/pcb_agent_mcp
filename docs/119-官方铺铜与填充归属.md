# 119 · 官方铺铜做成了工具：边界在「谁负责填充」

日期：2026-11-05　版本：0.0.119

## 起因（用户的原话）

> 「你是猪？铺铜官方有实现 kicad 和立创 eda 铺铜都有官方实现禁止你使用自己的工具铺铜。
> 铺出来就是坨屎，你有常识吗？」

> 「我按完 Shift+B 了，你继续后续操作吧，**最好 mcp 要支持这种操作好吗？不然做了没什么意义**」

前一句否掉的是**做法**（自造几何铺铜）；后一句要的是**能力**（这个 MCP 自己能不能做这件事）。
两件事必须分开答：做法已经被换成官方对象了，能力上还差一半——差的那一半不是懒，
是**厂商 API 里就没有这个入口**。这一版把能做的做成工具，把不能做的写成结构化回答。

## 一、铺铜在两个 EDA 里都是两个对象

| | KiCad | 立创 EDA Pro |
|---|---|---|
| 边框 | `(zone ...)` | `eda.pcb_PrimitivePour` |
| 填充结果 | `(filled_polygon ...)`，由 `ZONE_FILLER` 算 | `eda.pcb_PrimitivePoured.pourFills`，由编辑器算 |
| 填充入口 | **有**：`ZONE_FILLER(board).Fill(board.Zones())` | **没有**（见第二节） |

已实现的两个工具：

* `board_fill_zones`（已有，KiCad 侧）：调 KiCad 自己的 `ZONE_FILLER`，默认在**副本**上算并测量，
  `in_place=true` 才把多边形移植回你的文件（先写检查点），随后跑一遍 KiCad 自己的 DRC 报
  `drc_after_fill.verdict`。**这是「官方填充器」的完整闭环。**
* `lceda_pour`（本版新增，立创侧）：`list` / `check` 读**两张表**（边框 + 填充），逐块报
  net / layer / name / priority / 边框多边形 / `fill_paths` / `filled_area_mm2` / `filled`；
  `create` 用 `eda.pcb_MathPolygon.createPolygon` + `eda.pcb_PrimitivePour.create` 建**官方边框**并读回校验；
  `delete` 删 id 并校验计数；`save` 让编辑器落盘。填充缺失时回 `needs_editor_rebuild=true` + 应按什么键。

## 二、立创侧为什么只能「建边框 + 读结果」

实测（LCEDA Pro V4.1.60，bridge `4.1.60.198f38ab`，2026-11-05），**不是猜的**：

1. **全 API 扫过 98 个 `eda.*` 命名空间**，加上所有 `dmt_*` / `sys_*` 方法，**没有任何 rebuild / refill / refresh 入口**：
   - `pcb_PrimitivePour` 与 `pcb_PrimitivePoured` 只有 `create / delete / modify / get / getAll / getAllPrimitiveId`；
   - `pcb_Document` 只有 `importChanges / importAutoRouteJsonFile / importAutoRouteSesFile / importAutoLayoutJsonFile /
     save / getCalculatingRatlineStatus / start|stopCalculatingRatline / convertCanvas↔DataOrigin(To) /
     get|setCanvasOrigin / navigateTo* / getPrimitiveAtPoint / getPrimitivesInRegion / zoomToBoardOutline /
     getCurrentFilterConfiguration / clearRouting / autoRouting / autoLayout`；
   - `dmt_EditorControl` 只有 `openDocument / openLibraryDocument / closeDocument / getSplitScreenTree /
     getSplitScreenIdByTabId / getTabsBySplitScreenId / createSplitScreen / moveDocumentToSplitScreen /
     activateDocument / activateSplitScreen / tile|merge`AllDocument* / `getCurrentRenderedAreaImage` / zoom / indicator；
   - `sys_ShortcutKey` 只有 `register / unregister / getShortcutKeys`（`getShortcutKeys()` 实测返回空数组），
     `sys_HeaderMenu` 只能插删菜单项、**不能执行**。
2. **以下手段逐个试过，`pourFills` 一个都没出现**（Poured 恒 0）：
   `save()`、`pcb_Drc.check()`、`pour.modify({pourPriority})`、`zoomToAllPrimitives()`、
   在顶层铺铜里嵌套一个同层小铺铜（靠「触发自动重建」的赌法）、**关闭文档再重开**
   （重开后边框仍在、填充仍为 0）。
3. **唯一有效的是人在画布上按 `Shift+B`**（「重建全部铺铜」；菜单 工具 → 铺铜区域 → 重建铺铜；
   设置-PCB/封装-通用 另有「自动重建铺铜区域」）。实测按一次：`Poured` 0 → 2，顶层 92 条路径 / 底层 37 条。
4. **本机也无法程序化注入输入**：`SetCursorPos` 返回 0、`GetCursorPos` 返回 0、`SendInput` 返回 0、
   `mouse_event` 静默无效，向 `Chrome_RenderWidgetHostHWND` `PostMessage` 的 WM_KEYDOWN / WM_RBUTTON 无反应；
   会话 id 与 lceda-pro 同会话、`OpenInputDesktop` 名为 `Default` 与线程桌面一致，仍被挡。
   页面内合成 `KeyboardEvent` 也不行——沙箱里没有 `document`/`window`。

于是工具的答案形态固定为：**能做的做完（官方边框 + 读回 + 校验），不能做的用 `needs_editor_rebuild` +
`editor_action`（按什么键）+ `api_can_rebuild=false` + 扫描证据一起给出来**。绝不退回自造填充几何。

## 三、自造填充为什么被彻底否掉（保留作坑）

早期做法是用 `eda.pcb_PrimitiveFill` 一条条铺带状矩形、自己管 clearance、`eda.pcb_PrimitiveVia` 补过孔：
**同一块板上 302 条 Clearance 违规**。原因是它不知道规则表（间隙、热焊盘、孤岛、优先级），
而官方填充器知道。所以本版把「自造铜」写进 `assumptions` 当作**拒绝理由**，不是当备选方案。

## 四、这一轮真正修掉的东西（GND 12 → 0）

铺铜填上之后 DRC 从 107 条 Connection Error 起步，其中 **GND 12 条**是「焊盘没接上铜」：

* 先用 shapely 解析 `pourFills` 量距离：QFP-64 的高密度区最近铜在 **42 mil**，0805 电容类在 **30 mil**；
* 按「实测铜距 + 8~12 mil 余量」画 **5.91 mil（0.15 mm）引出线**，QFP 一律向**芯片本体方向**（pad 内端 → 本体下铜皮），
  电容按离器件方向：一次修掉 **10 条**（12 → 2），Clearance 仍为 0；
* 剩下两条（`C11.pad2`、`Y1.pad3`）接的是**孤岛**——最近铜不属于主铜区，线接上去 DRC 仍判未连接。
  这两条改走「焊盘 → 12/20 mil 过孔 → 底层铺铜」，其中 `U1.53` 同样处理（它的引出线端点落在主铜区却被判未连接，
  说明「几何上看着连上」不等于「DRC 认为连上」）。⇒ **GND 0 条**，总数 107 → 95。
* 方法上的教训：**能连不能连只能由 DRC 回答，不能由几何距离回答**。shapely 量出来的「最近铜」可能是孤岛，
  而 `pourFills` 的环解析（首个环是外沿、其余是洞）一旦把多个独立外环当成一个多边形，就会得出「看着连着」的假答案。

## 五、给后续的固定口径

1. 铺铜只用官方对象：KiCad `zone` + `ZONE_FILLER`（`board_fill_zones`）；立创 `pcb_PrimitivePour` + 编辑器 `Shift+B`（`lceda_pour`）。
2. 立创侧**永远不要**在「填充」这一步上动手脚；需要填充就回 `needs_editor_rebuild=true`，由人按一次键。
3. `filled` 是**快照**：之后任何走线/焊盘/板框改动都会让它过期，而回答里看不出来。**几何定稿后再重建**。
4. 「焊盘连没连上」以 DRC 为准；引线方案必须是「先量、再画、立刻 DRC」，一次只改一批。
