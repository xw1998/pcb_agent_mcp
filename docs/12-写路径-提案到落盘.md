# 12 · 写路径：从"提案"到"落盘"

> 回答的问题：既然中间层是**等于那张板**（第 11 篇），那 **改那张板** 这件事凭什么可信？
>
> 推翻的东西：**"调用一个函数，得到一个改好的文件"**。写坏一块板不是 bug，是一块报废的拼板；
> 而两种格式的失败都是**静默**的 —— KiCad 忽略它不认识的字段，立创忽略字段数或单位不对的记录，
> 文件仍然合法。没有异常，没有提示，DRC 还是绿的。
>
> **⚠ 修订（实测）**：本篇 早期版本对 `.epro` 写路径的描述（append-only + ticket
> + 追加成员）**基于猜测，已推翻**。实测：一次保存原地重写那一个 `.epcb` 成员，其余 129 个
> 成员与 `project.json` 字节不变；坐标是 mil。现行写路径与它的六道闸门见
> `13-立创实测-真实存储与记录格式.md` 与 `src/pcb_agent_mcp/edit/epro_edit.py`。

## 1. 协议：计算与落盘之间隔两次调用

```
board_propose(path, operations)   →  plan_id + digest + 每条 op 的后置条件 + blocking
        （全程只算，一个字节都不写；plan 单次使用，1 小时过期）
board_apply(plan_id, confirm=true) →  checkpoint → 原子写 → 五道闸门 → 任何一道不过就回滚
```

三条硬规则：

1. **`confirm` 必须显式为 true**。写文件不是 Ctrl+Z 能撤销的动作。
2. **plan 是单次许可**，不是"以后随时可用"。文件 sha256 在提案后变了（有人在编辑器里存过盘）
   就拒：`BOARD_CHANGED_SINCE_PLAN`，一个字都不写。
3. **写之前强制 checkpoint**，写在 `~/.pcb_agent_mcp/checkpoints/<path-key>/`，
   `board_restore` 能回到逐字节相同（`.epro` 用例 `test_rollback_restores_the_exact_bytes`
   把这件事钉成事实）。checkpoint 的 body **沿用源文件扩展名** —— kicad-cli 靠文件名判格式，
   存成 `.board` 会让"改前基线"打不开，比较静默失效。

## 2. 五道闸门：不信任写代码本身

| 闸门 | 它问的问题 | 为什么不能被"写代码对了"替代 |
|---|---|---|
| `bytes_written` | 盘上的字节 == 计划要写的字节？ | 原子写也可能被别的东西插进来 |
| `token_identity` | 重新解析盘上文件，是否**逐原子**重现计划的树？ | 一个字段写丢在文本里看不出来 |
| `postconditions` | 每条 op 自己的承诺，能否从盘上文件**读回来**？ | "我插了线"和"线在文件里且在 A 到 B 之间"是两件事 |
| `engine` | KiCad 重读改前/改后：stats、Gerber、贴片坐标 | 对照厂商引擎，不是对照我的解析器 |
| `drc` | KiCad DRC 的**差集**：有没有**新增**违规？ | 真板本来就有违规，清零是错判据 |

两条防假绿的口径，都是踩过才写下的：

- **"没比较成"不算通过。** `engine.ok` 要求至少一个 comparable check。checkpoint 扩展名写错那次，
  kicad-cli 报 `Unknown file type`，三个比较全 skipped，而 `identical=None` 一度被当成绿灯。
- **meta-only 计划若改了 Gerber ⇒ 判静默损坏。** 只改元信息却动了铜，说明写别的字段时串了。

## 3. 这些闸门真的拦住了东西

自造示例板 `examples/build_demo_board.py`（60×40，4 层，1.6 mm，三段
`mechanical → holes → copper`）第一次跑起来时，DRC 闸门连拦三次，每次都是**真错**：

| 拦下的东西 | 真因（KiCad 10.0.7 实测） | 修法 |
|---|---|---|
| `silk_edge_clearance` | `gr_text` 以 `at` 点为中心，宽度≈`字符数 × 高度 × 1.1`；12 字符 × 1.6 mm 的文字放在 x=4 就压过 x=0 板边 | 挪到 x=12.5 / 44 |
| `track_dangling` ×2 | 过孔只接了单层走线 —— **铺铜的填充在 DRC 里不算连通性**，端点落在 zone 内照样报悬空 | F/B 两条同网走线成环（2 过孔），实测 0 违规 |
| `via_dangling` | 单个过孔 = 悬空，即使它落在 zone 里 | 同上，过孔要有另一层的回路 |

顺带确认两条容易误判的事实：DRC 违规项 `items[0].pos` **不总是悬空的那一端**，不能靠它反推端点；
`zone` 的 `filled_polygon` 存在与否**不影响** DRC 的连通性判定。

最终一次三段全绿，每段 10.95 / 11.54 / 11.98 s，产物
`examples/demo_board/demo60x40.kicad_pcb`（4,098 字节，492 原子）+ `build-report.json`：
`tracks 2 / vias 2 / zones 2 / nets 1 / Edge.Cuts 9 个图元`，板框 `closed`，
`share_with_a_reading_rule = 1.0`（228 个节点全部有读取规则），`token_identity = true`。

> 这块板是**自己造的**：没有等任何人的工程，也没有在用户工程旁边留下临时文件 ——
> 所有 kicad-cli 的 `cwd` 和输出都在 temp 目录，`--save-board` 从不出现。

## 4. 层号必须按文件版本写

写 v7 文件就写 v7 的层号，不能写 KiCad 10 的：

```
F.Cu=0  In1..In30=1..30  B.Cu=31  B.SilkS=36  F.SilkS=37  B.Mask=38  F.Mask=39
Dwgs.User=40  Cmts.User=41  Eco1=42  Eco2=43  Edge.Cuts=44  Margin=45
B.CrtYd=46  F.CrtYd=47  B.Fab=48  F.Fab=49  User.1=50
```

这份表不是查文档来的，是拿 `kicad-cli pcb upgrade` 把 v7 板升到 v10 后对读出来的。
KiCad 10 自己的表完全不同（`B.Cu=2`、`Edge.Cuts=25`），混用会让整层铜画到错误的层上，
而**文件仍然合法、DRC 仍然可能全绿**。

版本号本身也是判据：v7 用 `(tstamp <uuid>)` 裸原子，v8+ 用 `(uuid "<uuid>")` 且
`(version ...)` ≥ 20240000。写 v7 就写 `(version 20221018)`。

## 5. 立创 `.epro`：这是日志，不是文档

`.epro` 是 ZIP，板子在一个**追加式日志**里：一行一个 JSON
`{"type","id","ticket"}||{payload}`，同一 `(type,id)` 取 **ticket 最大**，payload 全空 = 删除。
写路径因此与 KiCad 完全不同，`edit/epro_edit.py` 照这个形状写：

- **改 = 追加一行**，不是改那一行。旧字节必须是新字节的**前缀**（闸门 `append_only` 逐字节验）。
- **ticket 必须比成员里已有的所有 ticket 都大**。小了就被应用静默忽略：文件合法、改动没发生。
  ticket 从日志里读出来（`ticket: {from, to, rule}`），写完再从盘上读回来核对。
- **其它 ZIP 成员必须逐字节不变**（`members_untouched`）。重建 `.ecop` 会改灌铜填充，
  而文件看起来完全正常 —— 这是最像"成功"的失败。
- **键名是读出来的，不是编的。** `set_fields` / `add_object` 先查 `key_inventory(type)`：
  这个文件里该类型真实出现过的键才准写，否则 `KEY_NOT_IN_FILE` 并把**实际存在的键**列出来。
  立创同样会静默忽略一个不存在的键。
- **单位没有被证实就明说。** `unit_verified: false` 每次都返回，且写路径**不做任何坐标换算**
  —— 写进去的值原样透传。等一份真实 `.epro` 到手，`board_fidelity(key_inventory)` 一跑就能把它变 true。

三个 op：`set_fields`（既有对象改字段）、`add_object`（新对象，id 不许与现存冲突）、
`delete_object`（追加空 payload，日志自己的"没了"）。五道闸门对应 KiCad 侧同名前四个 + `log_idempotent`
（追加后的每个文本成员从自己的行重新序列化仍逐字节相同 —— 证明它是日志，不是重写）。

## 6. 格式判定只看内容，不看文件名

`PK` 开头 = `.epro`（ZIP），`(kicad_pcb` / `(kicad_sch` 开头 = KiCad，两者都不是就
`FORMAT_NOT_SUPPORTED` 拒绝猜。把 `.epro` 改名成 `.kicad_pcb` 混不进来，反过来也一样
（`test_detected_by_content_not_by_name`）。

## 7. 这套东西**不做**什么

- 不删文件、不做运行期备份清理、不在用户工程旁边落任何临时文件。
- 不冒充厂商 DRC。`board_drc` 对 `.epro` 直接拒绝回答 —— 立创专业版没有命令行，
  一个"近似的 DRC"会让人以为板子过了。
- 不自己算灌铜。`add_zone` 只写 `(fill yes)` 并把 `fill_pending: true` 报出来，
  填充要由 KiCad 自己做（也正因如此，DRC 的连通性判据只认走线/过孔）。
- 不写原理图。两个 EDA 的原理图都不在这条写路径上。
