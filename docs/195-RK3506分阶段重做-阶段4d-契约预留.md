# 阶段 4d —— 预留改成「契约」：从端点先把走廊占下，这块板的齿仍然买不到

`193` 把预留做成了 band 的一个键，量完之后留下的那句话是：**环是从「已经画好的铜」上量出来的，等它能量的时候，走廊里已经站满了人**。`193 §7 #1` 原本记的是「band 生成期预留」这笔欠账，`194` 又把它按用户裁定改判成「不上工具面」——工具面不加键，但 `route.router.plan` 里那件事本身仍然该做：**走廊不该等铜落地才被主张**。

这一轮就是把它做完：预留从「围住已经存在的铜」变成「先在平面上画出这条组必须走的干线，再从第一格铜之前就开始收钱」。结论先说：**契约成立（读数可见、189 基线逐字节不变、rip 后重涂），但腰部的空气一分没多**——这块板的瓶颈是扇出间距，不是「谁先占了空间」。

本轮不升版本、不进 CHANGELOG（沿用 181–194 的先例）；工具数不变（262），因为没有任何工具面改动。

## §1 结论先行

**代码改动**（全部在 `route/router.py`，零新依赖、零工具面改动）：

| 位置 | 内容 |
|---|---|
| `_paint_spans(maps, spans, radius_mm)` | 由旧的 `_paint_ring` 拆出来的通用涂环：`spans` 是 `(layer, a, b)`。**`layer is None` ⇒ 在每个 routing 层上都涂**——契约环画在任何一层上都不对，因为在第一格铜之前还没有「哪一层」这个答案。`cells` 每格只计一次，不按层重复计 |
| `_paint_ring(maps, nets, radius_mm)` | 变成薄封装：从 `em.ops` 里取该组已落地的 track/via 生成 spans，再交给 `_paint_spans`。行为与 `193` 完全一致 |
| `_contract_ring()` | **新**：对每个带 reserve 的 band，取预留网的**全部端点**（`by_net`，已过 `nets`/`max_nets`/`terminal_override`/`new_copper_layers` 过滤），去重后走 `TOPO.tree(pts, mode="mst")` 得到「这组网必须走的干线」，再把每条边按 `layer=None` 涂环；`res["pre"] = res["painted"] = st["pre"]` |
| 调用点 | 一处在路由循环之前（`net_priority` 排序之前），一处在 **rip-up 清空 `band_reserve_stamp` 之后**——契约环不是铜做的，铜被 ripper 拔掉不会把它一起拔走，但它存在的那张图被清了，所以必须重涂 |
| 报表 | `stats["bundle_bands"][i]["reserve"]` 新增 **`pre_cells`**（契约环自己占的格），与 `ring_cells`（= `pre_cells` + 落地铜周围补涂的格）分开报 |

四条读法，一条一条写死：

1. **契约真的生效了，而且只改了「谁付钱」**：`pre_cells` 在 4 网（8649）与单网（4937）两种规模上都非零，`ring_cells ≥ pre_cells`（落地铜周围再补涂）。同一组参数下 elapsed 从 42.3 s 掉到 25.9 s、lane0 spread 从 6.539 收到 5.927 —— 走廊一开始就被标价，后来的网直接绕开，不再靠逐步试错。
2. **腰部的空气一分没多**：契约最好的一格仍是 **0.300 mm**（仅 DQ1 / price 3），与 `193` 的无契约最好格**同一个数**；4 网两档都在 0.2475–0.2828。可读齿要 0.475 ⇒ **契约也补不上这 0.175 mm**。
3. **价钱开过头照样掉网，而且比 193 更容易**：price 4 掉到 **9/12**（`/DDR_DQS0N` clearance、`/DDR_DQ7`/`/DDR_DQ5` search_budget），price 3 掉 `/DDR_DQ0`；单网 price 3 也从 12/12 掉到 11/12（`/DDR_DQ7`）。契约把整条干线一次性标价，等于让所有网**同时**付这笔钱，被挤出去的概率比「围着已画铜收钱」更高。
4. **price 4 的旧读数「净空 0.0000/0.0354」没有复现**：契约下同一档报 0.2475–0.2500。这不是契约更好——那一档掉的是三条网，`gap_mm` 只在**通了的**网上量，样本换了，数不能横着比。所以 `193` 那三个近似零的数字与本节数字**不可并引**。

## §2 机制：为什么「从端点画环」才是真预留

`193` 的环有两个时刻错误，契约版一次把两个都改掉：

- **时刻错误**：`_paint_ring` 只能看见 `em.ops` 里已经有的铜，而预留网在 band 内第二键上「先路由」——它一画完，环就被涂出来了，但此时**同组其他成员还没开始搜索**，环对它们有效、对**已经走过的前面几组**（`dqs0` 等）无效。契约版把环放在**任何人开始搜索之前**，所以它对整个 plan 生效。
- **形状错误**：围着一根已画好的 track 涂环，得到的是「这条实际路径周围 0.5 mm」，而那条路径本身可能就是被挤歪的结果。契约版画的是 `TOPO.tree(pts, mode="mst")`——**同一条 band 里所有预留网的端点**连成一棵最小生成树，也就是「这组网必须走的干线」。用它当预留骨架，预留与实际走线同源，而不是事后描边。

三个实现上的决定，都不是风格问题：

1. **涂在所有 routing 层**：第一格铜之前没有「这条线会走哪一层」这个答案，只在某一层涂等于赌一个还没做出的决定。
2. **幂等**：`_contract_ring()` 每次都重写一张新图并重算 `painted`（`res["painted"] = st["pre"]`），所以 rip-up 里 `band_reserve_stamp.clear()` + `painted = 0` 之后可以直接再调一次。不幂等的话，第一次 rip 就会让预留**静默消失**而报表仍报 `ring_cells > 0`。
3. **单端点网不涂**：`len(pts) < 2` 直接跳过——一个点是一个焊盘，绕它涂环等于把该网马上要用的空间先锁起来。

## §3 读数与读法

三条口径，全部来自本轮实测：

1. **`pre_cells` 与 `ring_cells` 必须分开报**：4 网 price 2 是 8649 / 15679，单网 price 3 是 4937 / 8482。若只报 `ring_cells`，会读成「契约环把空间全占了」，而实际上 `pre_cells` 只占 `ring_cells` 的 40%–58%，其余是落地铜周围的补涂。反过来只报 `pre_cells` 会漏掉补涂——两者是两种不同的主张（「这组要走的干线」vs「已经走过的铜旁边的空气」）。
2. **spread 与净空仍不同向**：单网 price 3 的 spread 从 10.048（193）收到 6.385（契约），净空却还是 0.300。契约让整组更齐（不用边搜边让），但腰部的最近者没换人。**这两件事不能同时当验收量**，`193 §1` 的读法 4 在契约下依然成立。
3. **契约的代价是「同时付钱」**：price 2 时契约更快（25.9 s vs 42.3 s），price ≥ 3 时更慢且掉网更多。原因是契约把整条干线一次性标价，所有网的第一批搜索就撞在同一片价钱上。

## §4 反向失败对照

- **无 band ⇒ 逐字节不变**：`_v2e.py` 复跑 `189` 基线（无 `bundle_bands`），`ops`（94 条，逐字段）与 `stats` 除 `elapsed_s` 外全部相同，`nets` 数组相同。`_contract_ring` 在每个 band 上 `res is None ⇒ continue`，一行代价都不产生。
- **小例上契约与描边同值**：`tests/test_route_reserve.py` 的三网小例，预留 `/BUS_C`（mm 1.0 / price 4）报 `pre_cells == ring_cells == 5389`（预留网沿契约干线走，铜周围的补涂全落在已涂区域内），`/BUS_C` 腰部净空 **1.100 mm**（→`/BUS_B`）、`/BUS_B` 被绕成 24.566 mm。这与 `193` 的读数一致，说明拆分没有改变已有行为。
- **price 变墙的反向对照仍在**：`test_it_stays_a_price_and_never_a_wall` 用 price 18 断言三网仍 3/3、`rejected_ops == 0`。
- **rip 后重涂**：`_contract_ring()` 在 `band_reserve_stamp.clear()` 之后调用，`painted` 先归零再重算；若不重涂，rip 之后 `pre_cells` 仍是旧值而图已经空了——报告与事实背离。

## §5 未做项

- **0.2 mm 余量仍是交换**：`188 §4` 已量过 floor 0.2→0.1 会让短网可加数从 5 掉到 2/4，且这块板上没有用户裁定，不在本轮。
- **`terminal_override` 换端点另立线**：契约环用的是过滤后的端点，换端点会把干线画到别处；这属于阶段 2e 的延续，不在这里做。
- **结论落到一句话**：这块板的等长齿**买不到**，不管预留是「描边」还是「契约」，瓶颈是扇出几何（焊盘/过孔间距 0.25–0.30 mm）。要真正的 0.475 mm，必须回头改扇出（escape）间距或换层分配——那是布局账，不是路由账。
- `193 §7` 其余项（band 生成期预留之外的）与阶段 2/3 旧欠账不变。
