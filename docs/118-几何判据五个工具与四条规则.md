# 118 · 把「难看」翻成能判死的数：五个几何判据工具 + 四条 skill 规则

日期：2026-11-05　版本：0.0.118

## 起因（用户的原话）

> 「你看看人家画的，你画的什么狗屎？这个 mcp 缺少什么让你不能画成这样？为什么直角走线，
> 你但凡学一点布线规则进 mcp 也知道不能画直角线」
>
> 「这次云得不错了，为什么之前做不出这样呢？mcp 差一点啥？还是 mcp 的 skill 里有什么规则没讲？
> 为什么总是要参考别人才能做好？」
>
> 「那就完善这些」

上一轮确实画出了一块像样的板子——但代价是**照着用户给的参考图临摹**。这一版要修的是
「为什么必须临摹才能画好」。

## 诊断：四层原因

1. **验收标准不可判定。** 「好看」不是判据，于是退化成唯一能自动算的代理指标：对齐、
   等间距、填满。代理指标和真实目标之间的差，就是用户眼里的「狗屎」。
2. **缺判据工具。** DRC 只回答「能不能打样」，不回答「画得对不对」。间距、拐角、扇出
   顺序、器件真实外框这些量，之前要么得跑 kicad-cli 拿一份和几何无关的报告，要么只能靠眼睛。
3. **缺可执行的特征库。** skill 里有「45° 别画直角」这种结论，但没有「一块板好看在哪几个
   数上」的对照表，于是每到新板子就重新猜。
4. **参考图的价值被理解错了。** 参考图提供的是**不变量**（间距恒定、扇出零交叉、器件按
   接口分组聚拢），不是像素模板。照抄形状换一块板就崩；抽出不变量换一块板照样成立。

## 五个工具（都只判，不画）

| 工具 | 回答什么 | 关键字段 |
|---|---|---|
| `board_constraints_report` | 项目里到底写了什么限制，我画的贴不贴边 | `limits`（标 `lives_in`）、`track_widths_in_use`、`hugging`、`contradictions` |
| `board_footprint_extents` | 这个器件到底占多大（四种盒分别多大） | `pads` / `courtyard` / `silk` / `copper_graphic`、`missing_courtyard` |
| `board_geometry_check` | 现在这些线：最近多少、有没有压焊盘、有没有锐角/直角 | `closest_pair`、`clearance_violations`、`track_pad_violations`、`acute_corners`、`right_angle_corners` |
| `board_pad_obstacle_map` | 这块区域还有没有合法落点 | `rows_bottom_up`（ASCII）、`free_fraction`、`probes[].pad_fits` |
| `board_fanout_order_check` | 这组配对能不能零交叉扇出（画之前问） | `verdict`、`inversions`、`simulated_crossings` |

五个都注册进 `TOOLS`，实测 `len(TOOLS) == 199`。**没有做任何自动布局/自动布线**：
`board_route` / `board_fanout` 仍然退休，`PCB_AGENT_TOOLSET=all` 也拿不回来。

### 为什么 `board_pad_obstacle_map` 不算器件本体

KiCad 不检查「走线从器件体下面穿过」，板厂也不管，几乎所有密板都这么做。把外框当障碍之后，
一块 8.5 mm 宽、要扫过 18 条线的走廊会被判成「放不下」，于是器件四处乱飞——这是前几版
最难看的直接原因之一。障碍物只有**焊盘 / 走线 / 过孔**；器件之间会不会打架用 courtyard 判。

焊盘膨胀按**矩形**做，不按外接圆。第一版用外接圆，SOT-223 的大 tab 与 1.5 mm 晶振焊盘的
四角被多占了一圈，合法点被报成不可用——错在「过阻塞」这个方向，看上去安全，实际又在逼人去乱放。

### 扇出可行性是配对的**不变量**

两条相邻 45° 平行线的垂距恒为 `d/√2`。0.5 mm 间距 ⇒ 中心距 **0.3536**，线宽 0.15 ⇒
边距 0.2036，刚越过 0.2 间距（余量 3.6 µm，精确算术）。

由此：在两组平行焊盘之间做「法向外伸 + 一段 45° + 水平进焊盘」的扇出时，
**交叉数 ≥ 配对相对两组顺序的逆序数**，且**零交叉存在 ⇔ 逆序数 = 0**。

所以「这组线能不能干净地扇出」是配对与朝向的性质，不是布线手艺。逆序不为 0 时唯一有效的
两件事是改排针的网络顺序或改器件朝向；绕多少圈都不会变好。

工具会**独立重算一遍扇出、数真实交点**，与逆序数矛盾时返回 `self_check_failed` **拒答**。
两个数不要求相等（一个交点可以了结多个逆序），只比「零 vs 非零」。

## 两处真缺陷（本轮修掉）

### 1. `move_footprint` 的后置条件把「角度 0」判成错

`(at x y)` 在 KiCad 里就是角度 0，但校验函数要求文件里**显式写出**角度，于是它把自己写出的
结果判成不合格：一块真实板上 19 个 move 挂了 17 个，**整批回滚**，而 `failed_detail` 是 `None`。
改用 `S.arg_num(at, 3, 0.0)`。整批 139 个 op 一次通过。

教训留在 skill 里：后置条件必须在**一块真实工程板**上整批跑一次，而且要有「合法但看着不典型」
的夹具（角度 0 省略、铺铜未 fill、零宽丝印线段）。

### 2. 适配器从来不解析 courtyard

`F.CrtYd` 既不匹配铜、也不匹配丝印/阻焊，被静默丢弃。于是所有「器件会不会打架」的判断都退化
成「焊盘盒 + 0.25 mm」——实测真实 courtyard 比它大 0.4~1.9 mm/边，按近似值摆会真重叠。

现在逐图元取局部盒加线宽一半、按封装旋转转到板坐标后取包络；没画外框的器件在
`missing_courtyard` 里列出（**那是不确定，不是零**）。顺带补了丝印 `bbox`，文字项明确标注
是 advance box 而不是字形墨迹。

## 反向对照（判据必须能失败）

`_scratch/geomctl/` 三块夹板，每个都是几十字节的 `.kicad_pcb`：

| 夹具 | 期望 | 实测 |
|---|---|---|
| `right90.kicad_pcb` | `right_angle_corner_count = 1`（90°） | 成立 |
| `fourtyfive.kicad_pcb` | `right_angle_corner_count = 0` | 成立 |
| `acute.kicad_pcb` | `acute_corner_count = 1`（45° 内角） | 成立 |
| 反单调 mapping（U1 右列 ↔ J2B 反向） | `crossing_forced`，两个数都 > 0 | 逆序 45 / 交点 42 |
| 单调 mapping（v42 现况） | `zero_crossing_exists`，两个数都是 0 | 0 / 0 |

在 `_scratch/f412rg2/v42_route.kicad_pcb` 上的真实读数（102 条 F.Cu 扇出）：

- `closest_pair` = PB13↔PB12，中心距 **0.3536**、边距 **0.2036**（与定理一致）；
- `clearance_violation_count = 0`、`track_pad_violation_count = 0`、`acute = 0`、`right = 0`；
- `corner_count = 68`（全部 135° 内角，即 45° 折线）；
- `constraints`：`min_track_width 0.15`（102 条全贴下限）、`Default.clearance 0.2`，
  且 `contradictions` 指出 `min_clearance=0.000` 与 `Default.clearance=0.200` 并存、引擎执行后者；
- `obstacle_map`（res 1.0 mm，41×67 格）：`free_fraction = 0.751`。

## 四条写进 skill 的规则

1. **「好看 → 几何判据」翻译表**（`pcb-layout-methodology/SKILL.md` §0b）：
   六句用户的原话逐条对到工具字段，并定死判读顺序：读限制 → 问落点 → 摆 → 判线 → 判扇出。
2. **扇出可行性 = 顺序单调性**（同文件「扇出算术」+ `references/07` §8b）：
   定理、0.3536 这个数、`side_a/side_b` 怎么取 LQFP 的一条边、`mapping` 怎么排除电源/GND。
3. **元件本体可以压线、焊盘不行；不许用 bbox 近似 courtyard**
   （同文件「布线之前必读」由四条扩成六条 + `references/07` §8c）。
4. **改服务自己的代码时，每条后置条件必须有能失败的反向对照**
   （`pcb-agent-mcp-usage/SKILL.md`「读数的纪律」）：在真实工程板上整批跑、
   要有非典型写法夹具、反向对照是必须的、「回滚成功」不等于「对的」。

同时把五个工具加进 `pcb-agent-mcp-usage/SKILL.md` 阶段 1 的表与
`references/01-tool-map.md`（由 `_scratch/gen_toolmap.py` 重生成，199 个）。

## 口径改动（不许静默）

`_scratch/f412rg2/v42_route.kicad_pro` 的 `min_track_width` 由 **0.2 降到 0.15**。
理由：0.5 mm 间距的 LQFP-64 扇出只能走 0.15（skill 的「扇出算术」早写着这个结论），
JLCPCB 最小线宽 0.09。`board_rules_write` 不写 `design_settings.rules`，
所以这个值是直接改的 json，**在此备案**。
