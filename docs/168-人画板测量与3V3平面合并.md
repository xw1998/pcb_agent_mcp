# 168 · 不许自动布线之后：把「画板」拆成测量与手写坐标，并落地第一处确定性修复（/+3V3 平面合并）

用户判词：**「不许自动布线啊，自动布线当然会画出垃圾」**。这句话不是"布线器参数不好"，是"这个动作
本身不该由程序做"。所以本文分两半：

- 前一半是**工作方式改变**：`tools/route_som_signal.py` 那类"给起点终点让它自己找路"的东西从交付
  路径上撤下来，只当测量工具；交付铜改成**人写坐标**——本文第 2、3 节把「哪里有缝」量出来，供人手写。
- 后一半是**本轮唯一真正落地的板改动**：`/+3V3` 在 In3.Cu 上本来是两个同网 zone 互相重叠（DRC 里
  唯一的 `error`），这一版把它们手工合并成一个多边形，用官方 `ZONE_FILLER` 重灌注。DRC **30 → 29**。

板子：`examples/rk3506_som/rk3506_som.kicad_pcb`（0.1.30 交付板 + 本轮 zone 合并）。
坐标系一律为正 y（`copper_geo` / 本文所有工具口径）；pcbnew 原始 API 的 y 是负的。

## 1. 为什么"更聪明的搜索"不是答案

0.1.30 已经在**四种参数**下把 8 条未连接网喂给自研确定性迷宫（CLR 0.15/0.10 × STEP 0.05/0.025），
结果 `jobs 8 placed 0 refused 8`——那次实测同时排除了"净空定太严"这条解释（0.15 那档本来就比板规
0.10 严，放到 0.10 仍全拒）。

本轮换成人手写的坐标去试，得到的是同一个结论，但**粒度更细**：不是"搜不到"，是**具体某一段被具体的
某块铜挡住，坐标可以点出来**。第 3 节的阻塞区间就是这个粒度。

差别在交付物上：搜索器只会说 REFUSED；手写 + 校验会说"x 23.2675 到 27.6753 这一段过不去，你挪哪个
顶点"。后者能推动设计，前者只能推动调参。

## 2. 两个工具：眼睛和尺子，都不是手

两个脚本的 docstring 第一行都写死 **"Nothing here is a route."**，它们不产生任何铜。

### `tools/free_space.py` —— 眼睛

在一块矩形区域内逐格打印"这里有多少余量"：

| 符号 | 含义 |
|---|---|
| `.` | 0.10 mm 线可以过，且铜边余量 ≥ 0.25 mm（还能再并一条） |
| `+` | 0.15…0.25 mm，够 0.10 mm 线过，但没有余量给第二条 |
| `#` | < 0.15 mm，0.10 mm 线 + 0.10 mm 净空过不去 |
| `@` | 操作者自己标的点（用 `--mark NAME:x,y`） |

```
free_space.py BOARD --layer F.Cu --x0 21 --y0 23 --x1 29 --y1 28 --step 0.5 \
    --mark "U1.1K6-ish:22.6251,26.05"
```

实测（`/+1V35_DDR` 从 U1 球往下那一段，F.Cu，0.5 mm 栅格）：

```
F.Cu  x 21.00..29.00  y 23.00..28.00  step 0.50  items 2163  excluded -
       12223444566678889
 28.00 +###+#####+##+###
 27.50 ##############+##
 27.00 ######++#####+++#
 26.50 #####+.#######+##
 26.00 +##@++..#+###++##
 25.50 ######..####+++##
 25.00 ##############+##
 24.50 ###+#########++##
 24.00 +###+####+####+##
 23.50 ##############+##
 23.00 #####++#######+##
```

y 23.5…26 在这里是**整片墙**（几乎全 `#`），只有两小块口袋（x≈24.0–24.75, y 26.0–26.5 与
x≈24.5, y 25.5）。这就是 `/+1V35_DDR` 缺口 9.72 mm 走不过去的样子——不是"算法没想到"，是**没有缝**。

### `tools/path_check.py` —— 尺子

输入是一串人手打的顶点，输出"这条折线合法不合法"：

- 每段的**角度**，以及是否落在 45° 栅格上（只认 `{0, 45, 90, 135}`）；
- 沿中心线每 `--step`（默认 0.10 mm）采样，算到**同层外来铜**的最小余量（本网自己的铜、别的层都不算）；
- 把阻塞采样**折叠成区间**，并打印区间的真实 `(x, y)`，这样才知道该挪哪个顶点。

```
path_check.py BOARD --net /USB1_DP --layer F.Cu --width 0.10 \
    --points "41.70,33.058 41.70,21.30 44.00,19.00 45.00,19.00"
```

实测（`/USB1_DP` 远端三段，这是**已经验证可用**的一段）：

```
net USB1_DP  layer F.Cu  width 0.100  segments 3  need 0.100
   0   11.758 mm  ang  90.00 OK   min +0.450  blocked 0/118
   1    3.253 mm  ang 135.00 OK   min +0.557  blocked 0/33
   2    1.000 mm  ang   0.00 OK   min +0.525  blocked 0/11
violations 0
```

净空用的是 `copper_geo` 的真实焊盘形状（圆 / 椭圆 / 圆角矩形 / 线段），不是包围盒——包围盒在
J1 的 0.85 mm 圆焊盘上会报出并不存在的碰撞，同时漏掉真实碰撞的角。

## 3. 量出来的硬事实：8 条网为什么接不通

### 3.1 J1 焊盘之间穿不过去（几何，不是布线）

`J1` 是 140 pin 邮票孔环，两列 x=0 与 x=45，**焊盘 0.85 mm 圆盘、中心间距 1.0 mm、钻孔 0.55 mm
的 PTH**（实测 `y 17..20` 四对：pad 61/120 @ y17、60/121 @ y18、59/122 @ y19、58/123 @ y20）。

相邻两个焊盘的铜边净距 = `1.0 − 0.85 = 0.15 mm`。一条 0.10 mm 的线要从中穿过需要
`0.10/2 + 0.10 = 0.15 mm` 每侧，即 `0.30 mm` 的缝 ⇒ **缝只有一半，穿不过**。

所以这五条 J1 网只有两种合法出口：从焊盘中心**水平出线**（进内层），或从焊盘中心**45° 出线**。
`/USB1_DP` 的远端三段（第 2 节）正是"从焊盘 59 水平出到 x=41.70，再 135° 收进"。

### 3.2 U1 顶边扇出墙：同一段横走，四个信号层都堵

`/USB1_DP` 从 U1.B15 (22.6861, 32.777) 出来后，最近的一个可用过孔是**已经存在的**
`(22.9670, 33.0579)`。从那里往右横走到 x=41.70 是唯一的横向通道，实测：

`min −0.145 mm` 意味着**中心线已经落在别人铜里**，不是"余量不足"。两层的阻塞区间几乎重合（x
23.3…27.7 全堵）⇒ 换层不解决问题：这里是 U1 顶边的扇出走廊，四层都被占满。

结论：**这 5 条 J1 网要接通，前提是 U1 顶边扇出重排**（按板边归属把 43 条错边网分开，见 `docs/167`
第五节），不是布线问题。

### 3.3 `/+1V35_DDR`：电源平面在 y=16.5 就截止了

DRC 报的两个断点之间直线 **9.721 mm**：`(22.6251, 26.05)`（U1 的 1V35 球族 1K6…1K10 的扇出 stub
起点）↔ `(23.8, 16.4)`（平面侧的走线端）。

实测：
- `/+1V35_DDR` 在板上有 43 段线 + 26 个孔，y 跨度 4.200…26.331，**y 16.4 到 26.05 之间一段铜都没有**；
- `/+1V35_DDR` 在 In3.Cu 的铺铜区包围盒是 **x 12.80…36.50, y 3.00…16.50**（priority 1）；
- U1 的 1V35 球在 **y = 26.05**。

也就是：**平面在 y=16.5 收工，球在 y=26.05，中间 9.55 mm 没有任何平面**，而这段空间被 `/+3V3`
平面（y 23.80…44.00）和四层走线占着。

所以这条网也不是"再努力一点就能布通"：要么**给 `/+1V35_DDR` 在 In3 上扩出一块伸到 U1 球下的平面**，
要么在信号层里找一条 9.7 mm 的通道——而第 2 节的自由空间图已经证明后者不存在（y 23.5…26 全 `#`）。

## 4. 本轮落地的唯一板改动：`/+3V3` 两个 zone 合并

### 4.1 缺陷

In3.Cu 上原本有**两个同网 `/+3V3` zone，且互相重叠 1.0 × 1.3 mm²**：

| zone | 多边形 |
|---|---|
| 原 zone 3 | L 形 `(15.5,23.8) (17.5,23.8) (17.5,27.3) (27.5,27.3) (27.5,33.8) (15.5,33.8)` |
| 原 zone 4 | 矩形 `x 26.5…39.6, y 32.5…44.0` |

重叠区 `x 26.5…27.5, y 32.5…33.8`。这是整块板 DRC 里**唯一的 `error`**（`zones_intersect`），其余
29 项全是 `via_dangling` warning。

### 4.2 为什么选"合并"而不是另外两条路

- 改 **priority**：不确定 KiCad 是否因此不再报 `zones_intersect`（它不是"谁赢"的问题，它是同网
  重叠本身）；
- 留 **0.5 mm 缝**：会在电源平面上开一道 slot，回流路径被切断，电气上比现在更差。

合并成**一个多边形**严格优于重叠：去掉 seam，去掉面积被算两次的填充，且不引入任何新的空隙。合并不
改变覆盖范围——手算的并集面积 `85.0 + 150.65 − 1.3 = 234.35 mm²`，落盘多边形的 shoelace 面积也是
**234.35 mm²**，逐位相同。

### 4.3 手工并集多边形（10 个顶点）

```
(15.5,23.8) (17.5,23.8) (17.5,27.3) (27.5,27.3) (27.5,32.5)
(39.6,32.5) (39.6,44.0) (26.5,44.0) (26.5,33.8) (15.5,33.8)
```

由 L 形的下/左/上沿 + 矩形的东/北沿 + 那一段 `x 26.5` 的南沿拼成。落盘用工作区脚本
`_zone_merge.py`（`poly.RemoveAllContours()` → `idx = poly.NewOutline()` → `o = poly.Outline(idx)`
→ `o.Append(FromMM(x), FromMM(-y))`，注意 `NewOutline()` 返回 **int** 不是对象），删掉另一个 zone，
然后用**官方 `ZONE_FILLER`** 重灌注（`_refill.py`，前必须有同名 `.kicad_pro`，否则段错误退出码 139）。
自建铺铜仍然禁止。

### 4.4 读数（改前 → 改后）

| 读数 | 改前 | 改后 |
|---|---|---|
| zone 数 | 5 | **4** |
| `/+3V3` 在 In3 的填充面积 | 59.6478 + 146.7202 = **206.3680 mm²** | **205.5943 mm²**（−0.7737） |
| In3 三层填充合计 | **530.3765 mm²** | **529.6027 mm²**（−0.7738） |
| `kicad-cli pcb drc --severity-all`（仓库 cwd） | 30（1 `zones_intersect` error + 29 `via_dangling`） | **29（只有 `via_dangling`）** |
| `unconnected_items` | 8 | **8**（不变） |
| tracks / vias | 4128 / 630 | **4128 / 630**（不变） |
| `board_shape_gate` | `shape_pass` | **`shape_pass`**（acute 0 / off45 0 / dup 0 / arcs 0 / `square_corner` 422 仅 judgement） |

填充面积只少 0.77 mm² 而不是整个重叠区 1.3 mm²，是因为填充多边形本来就被焊盘与走线净空咬掉了一部分，
重叠区里被咬掉的形状在两份填充里各算了一次——合并后这部分也不再重复计。

## 5. 已经确认不可用 / 明确不做

- 不用 KiCad `board_route` / `board_fanout` / `autoRouting` / `autoLayout`；
- **不用自研搜索式布线器生成交付铜**（`tools/route_som_signal.py` 降级为测量工具，参数已可被环境变量
  覆盖以便复跑归因）；
- 不自建铺铜（只能官方 `ZONE_FILLER`）；不做盘中孔；
- 不在半成品板上"看起来改了布局"——改 U1 顶边扇出 / In3 分区是下一步，需要先定板边归属。
