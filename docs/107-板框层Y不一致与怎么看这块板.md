# 107 · 板框层 GKO 的 Y 与其他层差一个 −30.48 mm 的平移，以及「怎么看这块板」的四张图

本篇两件事，互不依赖：

1. **一个真缺陷**：立创 EDA Pro 4.1.60 导出的 `Gerber_BoardOutlineLayer.GKO`，Y 坐标与同一包里所有其他层不在同一个坐标系——差一个 `−30.48 mm` 的平移（等价于 Y 取负）。板框尺寸本身是对的，位置是错的。
2. **一套图**：把这块板按层拆开画出来，附上编辑器实时截图与 PDF 渲染页，用来看「它到底长什么样」。

## 107.0 两句话

- 板框**尺寸对、位置错**：GKO 画的是 `(0,−30.48)…(53.34,0)`，其余所有层（铜、丝印、阻焊、两份钻孔）都在 `y ≥ 0.5`。同一份导出包里两套 Y。
- 原理图页是**空的**：整块板是在 PCB 里直接建器件、用 API 给焊盘赋网络做出来的，原理图从头到尾没有放过一个元件。DRC 那条 `Netlist Error 1` 就是这么来的。

## 107.1 证据链（每一步都可复算）

数据源：`_scratch/f412rg_fab/lceda/Gerber.zip`（70 456 B，`testzip()` 返回 `None`）与 `_scratch/f412rg_fab/board-odb.zip`（121 899 B，ODB++ 导出）。

| # | 做了什么 | 读到什么 |
|---|---|---|
| 1 | 读 `Gerber_BoardOutlineLayer.GKO` 原文 | `%FSLAX45Y45*%`、`%MOMM*%`，四条线段：`X0Y-3048000D02 → X0Y0D01 → X5334000Y0D01 → X5334000Y-3048000D01 → X0Y-3048000D01` |
| 2 | 按 5 位小数换算 | 板框 = `(0, −30.48) … (53.34, 0)` mm；尺寸 53.34 × 30.48 mm = 2100 × 1200 mil（与 `PCB_INFO.txt` 一致） |
| 3 | 同一包里其余层的坐标范围 | GTL `x 2.30..51.05 y 1.28..26.67`；GBL `x 2.30..50.80 y 1.28..27.74`；GTO `x −0.13..53.77 y 0.53..29.24`；GTS `x 2.33..51.05 y 1.28..26.67`；PTH 钻孔 `x 2.30..50.80 y 1.28..26.67`；Via 钻孔 `x 2.30..49.28 y 1.28..25.60` |
| 4 | 把 GKO 的 Y 取负 | `(0,0) … (53.34,30.48)`，**恰好**把第 3 步所有层框住 |
| 5 | 读 ODB++ 的 `steps/pcb/profile` 与 `steps/pcb/layers/edge.cuts/features` | 轮廓 `0,0 → 53.34,30.48`；edge.cuts 四条线 `(0,0)-(53.34,0)-(53.34,30.48)-(0,30.48)` ⇒ 权威板框是 **y 正方向**，与铜层同框 |
| 6 | 换一次导出复测（`_scratch/f412rg_fab/lceda3/Gerber.zip`） | GKO 仍为 `y −30.48..0` ⇒ 不是这一次导出的偶发，是这台机器上 v4.1.60 的写出行为 |

结论只到这里：**同一个 Gerber 包里，GKO 与其他层之间差一个 30.48 mm 的 Y 平移**。至于「嘉立创的 CAM 会不会自动按板框最小外框对齐、所以实际不算错」，本篇不下判断——没有证据。

## 107.2 影响与建议（可执行的部分）

- 若 CAM 严格按**绝对坐标**合并各层，铜皮与钻孔会整体落在板框之外（板框在 y<0，铜在 y>1.28）⇒ 典型报错是「图形超出板框」或「板框尺寸/层不匹配」。
- 板框**尺寸**是对的，所以只要 CAM 按外框对齐（或人工确认后重定位），出来的板子是 53.34 × 30.48 mm，不会变形。
- 三条可选出路：
  1. 下单前用任意 Gerber 预览器把 GKO 与 GTL 叠一次，看板框有没有框住铜；
  2. 直接用 ODB++（`board-odb.zip`）下单——它的 profile 与铜层同框，已验证；
  3. 或把 GKO 的 Y 取负（等价于整体上移 30.48 mm）另存一份再打样。
- 这个缺陷**不影响** `PCB.pdf`、`BOM.xlsx`、`PickPlace.xlsx`、`Netlist.enet`——它们各自独立正常。

## 107.4 为什么原理图页是空的

- **做法**：这块板是在 PCB 文档里用 `eda.pcb_PrimitiveComponent` 之类直接放封装、再用 API 逐焊盘赋网络做出来的（104 篇记录了全程），**没有**在原理图里放符号、连导线。
- **工程结构侧证据**：`project_structures` 最新一份里，`schematics/Schematic1` 与 `sheets/P1` 的 `version` 与 `updateTime` 完全相同（都是 `1793679047817`，即创建时刻），而 `pcbs/PCB1` 是 `1793691304809`（更晚）⇒ 原理图文档自创建起**从未被修改过**。
- **后果**：PCB 上 54 个网络在原理图侧没有对应网表，DRC 因此常驻 `Netlist Error 1`；`importChanges` 这条路没走（fail-safe：执行前看不到 diff，若原理图为空可能把 PCB 网当「多余」删掉）。
- **切不过去**：`eda.dmt_SelectControl.activateDocument` 在 v4.1.60 的注入环境里**不是函数**（`TypeError: ... is not a function`，实测），脚本沙箱绑在当前 PCB 文档上 ⇒ 连原理图页的截图也拿不到。这一条不是「读不到」，是「没有切换入口」。

要真让原理图不空，只有两条路：在 UI 里手工按 104 篇的 BOM/网表补一遍，或者另找写工程文件（SQLite）的路径——后者未验证，且工程文件的文档数据不在 `.eprj2` 主库里（`documents` / `schematics` / `components` 三张表都是 0 行），贸然写会让编辑器打不开。
