# 11 保真层：中间层要"等于那张 PCB"，不是"推导出那张 PCB"

> **⚠ 修订（0.5.0）**：本篇描述的方法（carry the tree, read facts out of it）成立，
> 但其中关于 `.epro` 的具体布局与"追加/ ticket"的说法当时是**从格式外观推测**的。
> 之后用 194 个真实工程把每一条改成了实测，见 `13-立创实测-真实存储与记录格式.md`。

这一篇是一次方向纠正的记录。前一版（`10`）把中间层做成了「手挑字段 + 需要时再算」，
用户一句话把它否掉了：

> 主要中间转换层要和实际画的 pcb 一样不能只是推导动吗？如果只是推导那还是猜还是会犯错，
> 我要的是 pcb 的信息转换成 AI 擅长处理的不是推导

下面是错在哪、改成了什么、以及凭什么说这次不是猜。

## 1 旧架构错在哪

| 位置 | 做法 | 后果 |
|---|---|---|
| `adapters/canonical.py` | 只把 14 类"离散事实"挑进 Canonical，其余字段不读 | 丝印、 courtyards、尺寸标注、分组、图像、3D、teardrop、pad 的精确形状、每对象 DRC 覆盖……全部**在中间层里不存在** |
| `oracle.py` | clearance / 占用 / 环路面积用自己的几何近似算 | 数字是自己的意见，不是工具的意见；和 KiCad 的判定不一致时无法自证谁对 |
| 文档 `01` | 写着"解析 5%，推事实 95%" | 把"猜"写成了卖点 |
| 测试样本 | 手写合成板 | **从来没过过 KiCad**。第一个被这个新裁判抓出来的，就是样本本身不合法 |

"信息不在中间层里、等提问时再算出来"= 推导 = 猜。用户要的是：**PCB 的信息被转换**，
转换后的表达 AI 好读，但内容与那张板一一对应。

## 2 新契约：什么才算"转换"

一条可执行的标准，三条都要满足：

1. **可逆**：中间层 → 写回 → 与原件等价。等价按 token 流比（不是按"我算出来的值比"）。
2. **覆盖**：文件里的每个节点都必须被携带；没有读取规则的节点**不许消失**，只能被点名。
3. **外部裁判**：把写回的文件交给厂商工具（KiCad）重跑，输出的铜箔/统计/位号与原板一致。

只要缺其中任何一条，就是"推导"而不是"转换"，那么答案就必须带 `authoritative: false`。

## 3 现在的三层

```
fidelity/            保真层：整份文档进树
  sexpr.py           atom 保留原始拼写（1.0000 / -0），引号与裸词分开，转义可逆
  kicad_doc.py       整棵 (kicad_pcb ...) + token 自证 + 覆盖报告
  epro_doc.py        整个 ZIP：每个成员、每行日志、ticket 解析、删除作为事实保留
  views.py           从树上读事实 —— 每条记录都带 raw（原始 S 表达式）
  engine.py          裁判：kicad-cli 的 DRC / stats / Gerbers / pos
adapters/            只是"便利视图"（mm、Y 上、net 用名字），不是真值
oracle.py            几何近似；现在每条答案都标 derived + authoritative=false
```

关键设计：**每条视图记录都带 `raw`**。视图是给模型看的索引，真值永远是 `raw` 与树；
视图没讲到的东西不会丢，会落在 `uninterpreted` 里并计入覆盖率。

## 4 三处自证（本轮实测）

| 证明 | 方法 | 实测 |
|---|---|---|
| token 双射 | `signature(parse(dumps(tree))) == signature(tree)` | `true`（435 atoms / 191 seqs） |
| 覆盖 | 统计没有读取规则的 head | `1.0`（0 个节点无规则） |
| 厂商裁判 | 原件与写回件各跑一次 stats/gerbers/pos | 全 `identical`：4 层 Gerber 逐字节相同、stats JSON 相同、位号 CSV 相同 |

**裁判有牙**（防假绿自检，写进测试）：故意从树上删掉铺铜 zone 节点，裁判立刻变红 ——
`back_copper_area` 变化、`Copper,L2,Bot` 的 Gerber 不相同。这条测试就在
`tests/test_fidelity.py::test_engine_check_has_teeth`。

## 5 顺带抓到三个真缺陷

这一层的价值先在自己身上兑现了：

1. **合成样本根本不是合法 KiCad 文件**：`(dnp)` 裸写、`(property ...)` 用在 v7 格式里、
   `(gr_rect ... (width ...))` 混用 v8 写法。KiCad 直接拒绝加载 —— 也就是说，
   之前所有"Adapter 通过"的结论都建立在一份 KiCad 不认的文件上。
   现在样本改为 v7 合法、并被 `kicad-cli` 每轮验证（含 DNP、keepout、铺铜填充、net_class、丝印文字）。
2. **`fp_text` vs `property`**：KiCad 7 用 `fp_text reference`，8+ 用 `(property "Reference" ...)`。
   只读一种就会在另一半文件里读到空 ref。
3. **net_class 键名**：v7 是 `trace_width` / `via_dia`，8+ 是 `track_width` / `via_diameter`。
   旧代码只认一个拼法，另一个静默 None。现在两个都读，并回报**实际命中的键名**
   （`trace_width_key`），这样"读到了"和"猜到了"能分开。

## 6 还剩下哪些"猜"，以及怎么关掉

诚实清单，每条都有明确的关闭方式：

| 剩余不确定 | 现在怎么处理 | 怎么关掉 |
|---|---|---|
| `.epro` payload 键名 | 候选表 + `declare_absent`，不猜值 | `board_fidelity` 的 `key_inventory`：对真实工程把每个 type 的真实键名读出来，用真实键绑定 |
| `.epro` 单位 0.254mm | `unit_verified: false` 写在 source 里 | 一份真实工程 + 一个已知尺寸（板框 60mm 之类）即可反证 |
| 立创的 DRC 判定 | 明确拒绝（`VERDICT_SOURCE_UNAVAILABLE`） | 立创 Pro 无命令行；需 API 网关客户端（49620-49629） |
| 写路径 | 完全没有 | V2：propose → simulate → digest → approve → apply |
| 板框/机械层语义 | 只原样携带 `Edge.Cuts` 图元 | 用户点名要单独谈的议题 |

## 7 什么时候允许"推导"

推导不是禁止，**不被标注的推导**才是问题。规则：

- 能从文件读到的 → 必须读，不许重算（铺铜面积、pad 尺寸、net class 数值、填充多边形）；
- 厂商工具有裁决的 → 用它（`board_drc`、`board_stats`）；
- 都不行的 → 可以算，但答案必须带 `answer_source` + `authoritative: false` +
  `verdict_available_from`，让模型知道"这是测量，不是判决"。

这三条已经落进代码：五个几何测量工具（clearance / free_space / pour_connectivity /
cross_split / loop_area）现在都会带这三个字段。
