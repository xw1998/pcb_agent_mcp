# 阶段 4l —— 电源铜规划器：四问判据，以及「平面载流」为什么测不了

上一阶段（`docs/202` §5）结论是「不喜欢铺铜不是偏好，是缺一个 planner」。这一阶段把它写出来，并且**先把判据的定义钉死，再让它跑板**——因为上一阶段最贵的一条教训是：一个没有否证的读数，比没有读数更贵。

先说清一件事：**这一版没有往板子上加任何铜**。交付板 `examples/rk3506_som/rk3506_som.kicad_pcb` 逐字节未动。planner 只回答「该铺什么、铺在哪层、优先级几」，形状仍然是 caller 的（`board_add_zone` 的既有契约），因为「自动布局 / 自动布线 / 自己发明一个 pour 轮廓」都是明令禁止的。

## §1 结论先行

1. **四问的顺序就是判据的优先级**：①覆盖（焊盘是否落在同网铜上）②宽度（IPC 需求宽 vs 实测线宽，以及**最窄那段还能合法变多宽**）③平面（pad/via 是否落在填充里，`min_thickness`，连接方式）④允许失败（每行必须写 `why`；没给电流就 `no_demand`，绝不默认安培数）。前一条不成立时后面的数字没有意义，所以 verdict 只报**第一个**缺陷，不是打分。
2. **交付板 8 个电源网全部「覆盖零缺陷」**：`orphan = 0`，8/8 网的焊盘 100% 落在同网铜上。这是本轮第一条好消息，也是唯一一条。
3. **6 个网 `pour_needed`**：`/+1V8_ANA`、`/+0V9_ANA`、`/+0V9_PMU`、`/+0V9_LOGIC`、`/+0V9_CPU`、`/+0V675_REF`。它们的最窄段全是 **0.1 mm**，而 IPC-2221 需求是 0.116–3.577 mm（内层）；**最窄那段的合法加宽上限只有 0.100–0.113 mm**——也就是说「加宽」这条路在物理上被邻居堵死，铜只能来自铺铜。表见 §3。
4. **2 个网有平面、覆盖齐、但载流「不可测」**：`/+3V3`、`/+5V_IN`，判 `plane_covered_capacity_unmeasured`。这不是「平面太薄」的指控。文件只说 `min_thickness = 0.1`，而这个数字**证明不了** 0.1 mm 的铜能过 2 A；真正决定载流的是填充轮廓减去空洞后的**通道宽度**，那是形状计算，本模块明确不做（§4）。
5. **上一版的口径是错的，已整段删掉**：早先的草稿用「焊盘中心到填充边界的距离 ×2」当「电流入口宽度（mouth）」，再拿它算安培、算「需要几个 mouth」。这条口径在本板上得到 `mouth_min 0.08 mm` 这种数字，而那个 0.08 来自一个**跨在填充边界上的过孔**——它不是载流口。**测不了就写测不了**，不发明一个能算的数（§4）。
6. **`/+5V_IN` 的 In3 平面是一块孤岛**：填充 23.65 mm²，**0 个同网焊盘、0 个同网过孔落在里面**；最近的同网焊盘是 `J1.42`，**0.987 mm 之外**；最近的同网过孔 **6.28 mm**。它由短路过/覆盖而「看起来有铜」，但**接不到自己那一网的任何东西**。新增旗标 `plane_reaches_nothing` 把它点出来（§5）。
7. **In3 有两网同 prio 0**：`/+3V3`（206.72 mm²）与 `/+5V_IN`（23.65 mm²）都写 `priority 0`。KiCad 在这种情形下没有优先级可依，重叠区谁赢取决于内部顺序，**这个文件没有留下「谁先」的信息**。`priority_ties` 把它当数据报出来（§5）。
8. **4 个 zone 全部 `connect solid`、`thermal_bridge_width 0.5`、`min_thickness 0.1`**。所以「热焊盘只有 4 根 0.5 mm 桥」这条常见借口在本板不成立——连接是实心的，载流瓶颈只可能来自形状，而形状恰好是测不了的那一项。
9. **`board_rail_plan` 上线（264 → 265）**；`board_pour_rail` **不加**：`board_add_zone` 已经收 caller 的 polygon 并走官方 `ZONE_FILLER`，再加一个只会诱使「自己猜轮廓」。planner 的 pour 动作里写 `needs_outline: true` 与 `next_tool`（§6）。
10. **测试 25 条（新建 `tests/test_rail_plan.py`），定向回归 61 passed，跨工具计数相关 349 passed**。每条判词至少一条反向对照（§7）。

## §2 四问：定义与为什么是这个顺序

| 问 | 定义（可测） | 不测什么 |
|---|---|---|
| ① 覆盖 | 焊盘的铜轮廓与同网平面多边形相交，或焊盘轮廓与同网走线距离 ≤ 线宽/2，或落在同网过孔铜上 | 不判断「连到哪」——那是 `board_drc` 的 `unconnected_total` |
| ② 宽度 | IPC-2221（或 IPC-2152）需求宽，与逐段实测宽比较；「还能变多宽」= 到最近异网铜/板边的**边到边**距离减净空，再 `w + 2*room` | 不假设走廊尽头是空的：`room=None` 只表示「窗内没东西」，不是「无限宽」 |
| ③ 平面 | 每个填充平面上：落在里面的 pad 数（含「中心在内 / 轮廓相交」两种口径）、via 数、`min_thickness`、`connect_pads_effective`、`thermal_bridge_width` | **不测通道宽度**（见 §4）；不把 mm² 面积、pad 个数当载流证据 |
| ④ 失败 | 每行 `why` + `flags` + `actions`；`currents` 里没有的网只能经 `nets` 点名巡检，结论是 `no_demand` | 不给默认安培数；不把「没量」写成「不合格」 |

顺序的理由是**信息依赖**：一个漏掉焊盘的平面，面积再大也是废铜；而一个「宽度不够但能加宽」的网，和「宽度不够且加宽不了」的网，要做的事完全不同（改宽度 vs 铺铜）。所以 verdict 只报第一个不成立的问题，后续数字仍然全部给出，供人自己看。

`room` 的语义写死：`room_mm` 是**边到边**余量减净空，所以合法宽度是 `w + 2*room`（假设对称加宽）。**负数不是错误**，它表示「这段已经贴在净空里了」——本板 6 个 `pour_needed` 网的 `room` 是 0.000–0.006 mm，都是这个形态；`neck_already_inside_clearance` 单独记一旗标，因为「现在这段是不是已经违规」只有 DRC 能判。

## §4 「平面载流」在现有信息下不可测（负读数）

一条平的、有填充多边形的 zone，文件里关于「多厚」的陈述只有一个：`min_thickness`。它的语义是**filler 不会铺比它更细的铜**，所以：

- `min_thickness ≥ 需求宽` ⇒ **保守证明**「这块铜能过这个电流」。这是 `covered`。
- `min_thickness < 需求宽` ⇒ **什么也证明不了**。它不表示铜太薄，只表示文件没说。

那真正的载流宽度是什么？是**填充轮廓减去内部空洞之后，电流实际要穿过的通道宽度**。要拿到它需要形状运算（并集轮廓 + void 边界 + 通道最窄截面）。本模块不做这个运算，所以答案只能是 `plane_covered_capacity_unmeasured`，而不是一个估出来的安培数。

上一版草稿用了一个替代口径：`mouth = 2 × dist(pad中心, 多边形边界)`，然后拿 mouth 去算安培、算「需要几个 mouth」。**这条口径为什么被删掉**，用本板的数说话：

- `/+3V3` 的 In3 填充是**一个 7986 点的岛**，bbox 约 `x 15.5–39.6, y 23.8–44.0`。落在里面的同网**焊盘 0 个**（板上的 SMD 焊盘都在 F.Cu，几何上在平面之下，但铜不接）、**过孔 9 个**。
- 上一版读出的 `mouth_min 0.08 mm` **不是**这 9 个过孔里的任何一个造成的载流瓶颈——它来自另一个跨在填充边界上的焊盘/孔，`dist` 很小只因为它压在边界上。**「离边界近」不是「铜窄」**。
- 更根本：`mouth` 只看见入口，看不见平面**中间**可能存在的窄桥；而平面真正载流靠的是「宽」，不是「文件里声明它厚」。

所以现在每个平面的报告改成「量了什么 / 没量什么」两列显式列出：

```
measured:      min_thickness_mm, connect_modes, pads_touching, pads_inside,
               pads_straddling, vias_inside, thermal_bridge_mm
not_measured:  current_corridor_width
```

`pad_rim_min_mm` 仍然给出（`/+3V3` 是 0.04 mm，来自一个距边界 0.04 mm 的过孔），但它被明确定义为**焊盘/孔到填充边的距离，是「边上有铜」的读数，不是截面**，且在 `why_unmeasured` 里写死了这句话。`actions` 从「加几个 mouth」改成 `prove_plane_capacity`，`why` 里直接说：这不是「平面太薄」的结论，要收口只有两条路——**做形状/空洞分析**，或**声明一个 ≥ 需求的 `min_thickness`**（后者 KiCad 只在平面真能有那么厚时才接受）。

本板的四个 zone 全部 `connect solid`（实心连接，不是 4 根热桥），所以「热焊盘限流」这条退路也不成立：瓶颈只能来自形状，而形状没量。

## §5 两条只有跑真板才会看见的读数

### `/+5V_IN` 的 In3 平面接不到自己

| 读数 | 值 |
|---|---|
| 填充面积 | 23.65 mm²（单岛 63 点） |
| bbox | x 40.20–44.30 / y 37.20–43.00 |
| 同网焊盘落在里面 | **0**（最近的是 `J1.42` @(45.00,36.00)，**0.987 mm** 之外） |
| 同网过孔落在里面 | **0**（最近 **6.28 mm**） |
| `pads_touching`（轮廓相交） | 0 |

一块 23.65 mm² 的填充，和它自己那一网最近的铜隔着 1 mm。它不短路、不违规（净空够），**但它是死铜**：电流进不去。旗标 `plane_reaches_nothing` 只在「无 pad 相交且无 via 在内」时置位，`/+3V3` 因有 9 个过孔在里面而不触发——这就是反向对照。

顺带说清一个容易读错的口径：`/+3V3` 的 `pads_inside = 0` **不是缺陷**。平面在 In3，`U1.1B10` 这些是 F.Cu 的 SMD 焊盘，几何投影落在平面里但铜不接触；它靠 9 个过孔与平面相连。所以「pads_inside=0 但有通过孔」是正常供电路径，只有**两者都为 0** 才是孤岛。

### In3 两网同 prio 0

`/+3V3` 与 `/+5V_IN` 都写 `priority 0`，同层。KiCad 的规则是「高优先级赢」，同优先级时谁先被填充取决于内部顺序，**文件里没有这个信息**。planner 不替它决定，只报 `priority_ties`；`_next_priority()` 在生成新 pour 时会给「比该层其他网的最大值 +1」，避免把这个歧义再带进新铜。

## §6 铺铜动作：只给数，不给形状

`pour_needed` 的行动项长这样（截断）：

```json
{"op": "add_zone", "net": "/+0V9_CPU", "layer": "In1.Cu", "priority": 1,
 "required_width_mm": 3.5767, "min_thickness_mm": null, "needs_outline": true,
 "next_tool": "board_add_zone",
 "why": "no room to widen the neck (widest legal on it is 0.104 mm), so the
         copper has to come from a pour. min_thickness stays the zone default:
         a plane carries current by being WIDE, not by declaring itself thick -
         what has to be >= 3.577 mm is the copper at the neck, which is a shape
         decision, not a zone parameter"}
```

三个刻意的选择：

1. **候选层 inner 优先**：`inner = cu[1:-1]`，先空层后占用层，取前 2。先往 F.Cu 铺会把信号面浇掉——这正是上一阶段被骂的那种「屎」。
2. **`min_thickness_mm: null`**：因为「把 min_thickness 设成需求宽」是个假答案。KiCad 会拒绝在铺不出那么厚的平面上声明那么厚（结果是把平面删光），而平面载流本来就靠**宽**。要 ≥ 需求宽的是**咽喉处的铜**，那是形状决定。
3. **`needs_outline: true` + `next_tool: board_add_zone`**：轮廓是 caller 的。planner 不发明多边形，也不调用 `board_add_zone` 自己铺。**所以本轮没有新增 `board_pour_rail` 工具**——它除了重复 `board_add_zone` 之外，唯一的作用是引诱「自动生成一个轮廓」，而那是被明令禁止的。

## §8 改了什么

**新增 `src/pcb_agent_mcp/route/rail_plan.py`**（约 740 行），四问判据 + 层账 + 动作生成。写的过程里修掉六个真 bug，每个都留下痕迹：

| bug | 现象 | 修法 |
|---|---|---|
| 网名 sheet path | 板上是 `/+3V3`，用户写 `+3V3` ⇒ 全部 `no_copper` | `alias = lstrip("/")`，行里同时给 `net` 与 `net_asked` |
| 通孔焊盘层通配 | pad 层是 `['*.Cu','*.Mask']`，按 `endswith(".Cu")` 得到 `['*.Cu']` ⇒ 4 个 `+3V3` 孤儿焊盘、4 个 `+5V_IN` 孤儿 | `_pad_layers()` 展开 `*.Cu` / `F&B.Cu` 到全部铜层 |
| 默认净空写死 0.2 | 板规 0.1 ⇒ 细间距逃逸处算出 `room = -0.1` | 默认读 `board.rules.min_clearance` / `min_copper_edge_clearance`，并记账 `*_source` |
| `min_thickness` 恒 0 | `prev = plane_min_thk.get(lay, 0.0)` + `min(prev, thk)` ⇒ 永远 0.0 | sentinel `"unset"`，读数就是文件里的值 |
| mouth 载流口径 | 见 §4 | 整段删除，改 `prove_plane_capacity` |
| `no_copper` 抢在 `pads_uncovered` 前 | 有焊盘无铜的网被判 `no_copper`（推导：nothing to judge） | 只有「走线/过孔/平面/焊盘全无」才是 `no_copper`；且网名解析改成先读**网表** `board.nets`，否则「声明了但没铜」的网连名字都解析不出来 |

**新增 `tests/test_rail_plan.py`**（25 条）。

**`src/pcb_agent_mcp/tools.py`**：注册 `board_rail_plan`（read-only，`derived=True`），信封走 `ok()`（`model`/`precision` 来自 planner，`basis` 写明「IPC-2221/2152 对照文件里真实的铜」），`PlanError` → `err(..., "BAD_INPUT")`，`top` 截断时记 `rows_truncated_from`。

**`tests/_toolcount.py`**：`EXPECTED_TOOL_COUNT` 264 → 265，并补一条历史（含「为什么不进 `available`」）。

## §9 没做什么

- **没有往板上加铜**，交付板未改。planner 只给数。
