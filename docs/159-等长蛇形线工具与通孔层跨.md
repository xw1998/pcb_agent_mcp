# 等长蛇形线工具 board_tune_length 与通孔层跨（0.1.22）

用户原话：「你现在继续改进重画rk3506的板子，还有就是等长蛇形线mcp是不是没有工具？没有就加。」

---

## 1. 结论先写

- **有算法，没有工具**。`route/tune.py::_serpentine` 早就存在，但它只服务
  `board_route` 的 `length_groups`——**只调自己布出来的线**。对一块已经布好的板
  等于没有：没有入口、不会量盘上的铜、不能只改一条网。
- 本版补上**第 254 个工具 `board_tune_length`**：量→选组→在短网的一条直段上插 45°
  蛇形（两端点不变）→每段新铜过 `Grid.seg_blockers`→出 `delete_track` + `add_track`
  →走 `edit.propose` + `edit.apply_plan` 四道闸。
- 在 `_v18.kicad_pcb` 的副本上真写盘，三组 DDR pair 的 skew 从
  1.60 / 1.95 / 0.94 mm 收到 **0.0000**，`kicad-cli pcb drc` 与基线**同为 41 条**
  （无新增净空违规），铜层 arc **0 条**。
- 写盘过程中撞到一个**真实缺陷**：通孔 `(layers "F.Cu" "B.Cu")` 在布线器眼里
  **不存在于任何内层**，于是蛇形被放在离一颗 GND 通孔 0.0069 mm 的地方，
  第一次写盘的板被 `kicad-cli pcb drc` 判了 1 条净空违规——本版修掉两处
  （`oracle._items` 与 `edit/checks._copper_items`），修完重画，违规回落基线。

---

## 2. 工具边界（写死在 schema 里）

| 项 | 口径 |
| --- | --- |
| 长度来源 | 只算 `segment` 的欧氏长度；**via 计数不加入**（钻孔深度不是电长度） |
| arc | `arcs_not_counted` 只报数字，**不调**（圆弧是形状不是段） |
| 蛇形形状 | 只用 45° 齿；30° 段扇出的齿落在 75/105°，`not_on_45_grid` 直接点名 |
| 拓扑 | 替换一条直段、两端点不变 ⇒ 连接关系不动，只加长度 |
| 只加不减 | 不会为了对齐而剪短任何网 |
| 默认 | `apply=false`，只出计划；写盘要显式 `apply=true` |

拒绝原因逐条可读：`does_not_fit` / `clearance` / `keepout` / `board_edge` /
`not_on_45_grid` / `copper_is_locked` / `replacement_budget` / `no_candidate_segment`。

## 3. 「0.2 mm 地板」不是判据，是代价

`ruleset.precondition.CLEARANCE_FLOOR_MM = 0.2` 是写盘闸门的地板，
而这块板的 netclass 只要求 0.1 mm、走线本身就按 0.1 密排。

把它当**硬约束**喂进蛇形搜索，三组 pair 会全部掉成 `length_not_matched`
（只剩 0.03 mm 余量）——等于**禁止等长**。所以口径改成：

- 搜索按**规则**判（`plan(..., floor_mm=0.0)`）；
- 另外用 `floor_mm=0.2` 复判一遍，只统计「落到地板以下的**新**不同网对」，
  返回 `clearance_floor {floor_mm, new_pairs, worst(按 gap 升序前 5), why}`；
- 工具在 `new_pairs > 0` 且未显式 `allow_new_violations=true` 时**不写盘**，
  `next_step` 点名「N new pairs 低于 0.2 mm、最紧 X mm」。
- `tune_board.FLOOR_MM = 0.2` 由测试断言等于 `precondition.CLEARANCE_FLOOR_MM`，
  避免 route 层 import ruleset 成环。

本次三组写盘：`new_pairs = 38`，worst 0.1119 mm —— 是「0.1 密排 bundle 里做蛇形」
必然付的代价，读的人看得见，不是静默放宽。

## 4. 通孔层跨：两个方向都错过

写盘第一次被 `kicad-cli pcb drc` 打了 1 条：

```
[clearance]: 0.0069 mm; actual 0.0069 mm; Via [/GND] on F.Cu - B.Cu
        vs Track [/DDR_DQS1P] on In2.Cu
```

两处实现各错一个方向：

| 位置 | 错误 | 后果 |
| --- | --- | --- |
| `oracle.py::_items` | via 只按 `(from, to)` 两个端点过滤层 | 通孔的环**在内层不存在**⇒蛇形被放进 0.0069 mm 的空隙 |
| `edit/checks.py::_copper_items` | `(layers "F.Cu" "B.Cu")` 被读成「只有两层」 | 反过来把**真实的**内层净空对藏起来，闸门读数偏乐观 |

正确语义只有一条：`(layers "F.Cu" "B.Cu")` 是**通孔**，环在所有内层都有铜；
只有盲孔/埋孔（如 `(layers "F.Cu" "In1.Cu")`，本板 2 颗 0.2/0.1 激光孔）
才是它名字里那两层。两处都按这条改，并留了**反向失败对照**：
`tests/test_tune_board.py::TestThroughViaCopperIsOnEveryInnerLayer` 三个测试——
通孔必须在 In2.Cu 被拦（`actual_mm = 0.5 − 0.125 − 0.3`）、
同一坐标的盲孔 F.Cu→In1.Cu 在 In2.Cu **必须不被拦**、
`checks._copper_items` 对通孔出 `"*"` 对盲孔出 `["F.Cu","In1.Cu"]`。

## 7. 顺带修掉的另一个既有缺陷

`edit/plan.py` 的 plan seed 原来是 `path:秒级时间戳`，同一秒内两次 propose 会撞
同一个 base、生成同 id 的 op，表现为「改 A 却改到 B」。改为
`path:秒:uuid4[:8]`，`tests/test_edit.py` 覆盖。
