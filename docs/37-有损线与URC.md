# 37 有损线 `O` 与分布 RC 线 `U`：把「一条线」换成一串 R/L/C

## 37.1 为什么 0.0.30 做 T 时把 O 拒掉，这一版又做了

`36` 的判据是：`T` 的答案在理想定义下**唯一**——没有模型卡、没有材料参数，只有 `Z0` 与 `TD`
两个数，三个分析都有闭式解。`O`（`LTRA` 模型）与 `U`（`URC` 模型）不一样：它们的答案取决于
**你把损耗怎么分配**（`R L G C` 四个数、每单位长度、还随频率变），换一种分配换一个答案。
所以 `0.0.30` 把 `O`/`U` 继续按名拒绝，并指给 `engine="ngspice"`。

这一版把两个卡接上，但**不是假装它们是分布线**。做法是解析期展开：

> 一张 `O`/`U` 卡 = 模型给出的 `r l g c len`，切成 `lump` 段，每段是普通的 `R`（串联）、`L`
> （串联）、`G`/`C`（对地）元件。

也就是说内置引擎解的是**那串 R/L/C**，不是麦克斯韦方程下的分布线。这个区别必须写进答案里，
否则就是本模块存在的意义所要消灭的那类东西：一个看起来像分布线答案的集总答案。所以：

- 每个答案都报 `segments`（用了几段）与 `segments_from`（是调用方给的还是默认的）；
- 默认段数进 `assumptions.defaulted_model_params`（`{"O1.lump": 20}`），默认值不埋在代码里；
- `NOT_COMPUTED` 里写死：皮肤效应、介质损耗（`G` 以外）、频变 `r`/`l` 都不在这个模型里；
- 收敛性本身是被测的对象：段数加倍误差必须下降（§37.4、§37.5）。

## 37.2 语法：卡上是节点，段数在 `.model` 里

```
Oname n1 n2 n3 n4 model        ; 信号：n1→n2，返回：n3→n4
Uname n1 n2 n3 model           ; 信号：n1→n2，分布电容回流：n3

.model m LTRA(r=1 l=250n g=0 c=100p len=1 lump=20)
.model m URC(r=1000 c=1n len=1 lump=20)
```

**`lump=` 只能写在 `.model` 里**，这不是审美。实测（ngspice-47）：

- 写在卡上（`O1 2 0 3 0 m lump=20`）→ **FATAL**：`Error on line 4 or its substitute`，
  退出码 1，整份 deck 一个数都不出来；
- 写在 `.model` 里 → 只是 warning（`unrecognized parameter - ignored`），deck 照常解。

同一份 deck 要既能内置解、又能原样委派给引擎，所以段数只能放 `.model`。卡上出现任何尾部参数
一律拒绝，错误里带一句为什么（`_LUMP_HINT`）。

`LTRA` 的键是 `R L G C LEN LUMP`，`URC` 的键是 `R RPERL C CPERL LEN LUMP`（`R`/`RPERL` 是同一
个量的两个名字，同时给就拒绝：`under two names`）。`Z0=`/`TD=`/`REL=`/`ABS=` 按名拒绝，
前两个的提示直接指向 `T` 卡。

**`LEN` 必须给。** ngspice 自己也拒绝没有长度的 `LTRA`（`length must be given`）；默认 1 会让
调用方看到的每一个总量都差一个没人声明的倍数。

**两个返回节点拒绝。** `O1 2 0 3 0` 的最后两个节点是返回导体，梯形把全部 `r + jωl` 放在信号
导体上、返回当成**一个理想节点**。如果 `n3 != n4`，那意味着返回导体自己也有延迟——本梯形表达
不了，拒绝并指向 `engine="ngspice"`，而不是静默把串联电阻减半（那是一个能算出来的错答案）。

## 37.3 DC：没有 `G` 的时候，梯形就是一段电阻链，而且是精确的

`r=1 Ω/m`、`len=1 m`、`g=0`，放进 `V1 1 0 3` / `R1 1 2 50` / `O1 2 0 3 0 m` / `R2 3 0 50`：

| 量 | 内置 | 解析 | ngspice-47 |
|---|---|---|---|
| `v(2)` | 1.514851485 | `3·51/101` | 1.514851 |
| `v(3)` | 1.485148515 | `3·50/101` | 1.485149 |
| `port1.current_a` | 0.029702970326 | `3/101` | — |

**段数完全不影响这个数**：`lump=1/2/8/20/50` 逐位相同（末位 1e-9 级浮点漂移）。这正是「每段
分到的值有没有除对」的负控制——如果实现按 `r·len` 给每**段**，读数会随段数线性跑掉，而
`tests/test_spice_oline.py` 里 `test_the_section_count_does_not_change_the_dc_answer` 就是
为这一条写的。

U 卡在直流同理：`URC(r=2000 c=1n len=0.5)` 串联总阻 1 kΩ，与 50 Ω 源阻、1 kΩ 负载构成分压，
`v(2)=2.926829`、`v(3)=1.463415`，两端之差正好是那 1 kΩ 上的压降。

负控制：模型只给 `c`（`LTRA(c=100p len=1)`）时直流上没有通路，远端由它的负载钉住——
`v(2)=3.0`、`v(3)=0.0`。这条断言能失败的方式是「串联支路被误建出来」。

## 37.4 有 `G` 时 DC 收敛到**分布**解，而且是一阶收敛

`r=1 Ω/m`、`l=250 nH/m`、`g=1 S/m`、`c=100 pF/m`、`len=1 m`、50 Ω 负载。分布解的直流转移是

```
V(L)/V(0) = 1 / (cosh(gL) + Z0c/RL·sinh(gL)) = 0.6383312861223945
```

实测相对误差（`lump` → 误差）：

| lump | 1 | 2 | 5 | 10 | 20 | 50 | 100 |
|---|---|---|---|---|---|---|---|
| 误差 | −1.433e-1 | −9.337e-2 | −4.350e-2 | −2.284e-2 | −1.169e-2 | −4.744e-3 | −2.383e-3 |

单调下降、大致一阶（1/N）。这就是「梯形是模型不是线」的量化形式：它收敛到分布答案，但它
**不是**分布答案，任何一处段数不够都会以这个量级出现。测试断言的是**单调性 + 60 段误差
< 5e-3**，而不是「等于解析解」——后者会是一条永远为假的断言。

**g>0 没有引擎可对拍。** ngspice-47 自己拒绝零以外的 `G`：
`Nonzero G (except RG) line not supported yet`。所以这一档的外部参照只能是解析式，这也是
`RealEngineAgrees` 里只对 `g=0` 做 `cross_check` 的原因。

## 37.5 AC：无耗时与 `T` 逐位一致，有耗时读出 `α`

**无耗（`r=0 l=250n g=0 c=100p len=1 lump=100`）vs `T1 Z0=50 TD=5n`**，50/50 分压、源 1 V AC：
在 100 kHz / 550 kHz / 1 MHz 三档，两者 `|V(2)| = |V(3)| = 0.5`、相位 −0.18 / −0.99 / −1.8°
完全一致（幅值 places=4、相位差 < 0.02°）。这是两套完全不同的实现解同一个物理：`T` 打的是
精确 Y 参数矩阵，`O` 打的是一百段 R/L/C。

**有耗（`r=1`，`lump=100`）在 1 MHz**：`|V(3)| = 0.495049`，即 `0.5·exp(-0.01)`，
`α = r/(2Z0) = 1/100` neper/m；`|V(2)| = 0.504945`（近端看到的是 `Z0` 与损耗的并联效果）。
与 ngspice 的 `cross_check`：`max_abs_diff_v = 1.57835e-07`（`worst_node 2`，
`compared_nodes 3`）。负控制：一个不建串联电阻的梯形会读 0.5，测试里 `|V(3)| < 0.5` 那条
断言就为它写。

**U 卡的 AC 用解析解做外部参照**（ngspice 的 `URC` 在 `rperl/cperl` 下给出的数是「能跑但值不
直观」，与 `0.0.30` 对 `F` 卡的判断同类，所以不当参照）。`r=1000 Ω/m`、`c=1 nF/m`、`len=1 m`、
远端开路、50 Ω 源：

```
γ = sqrt(jωrc),  Z0c = sqrt(r/(jωc)),  Z_in = Z0c·coth(γL),  V(2) = Z_in/(50 + Z_in)
```

| f | 解析 \|V(2)\| | lump=1 | 2 | 5 | 20 | 60 |
|---|---|---|---|---|---|---|
| 100 kHz | 0.993416 (−1.700°) | 0.985802 | 0.989188 | 0.991720 | 0.992998 | 0.993277 |
| 1 MHz | 0.909627 (−4.765°) | 0.953477 (−0.424°) | 0.929348 (−1.534°) | 0.915335 (−3.173°) | 0.910689 (−4.327°) | 0.909951 (−4.616°) |

相位比幅值收敛得慢，这是 RC 线在集总化下的固有形态（每段的极点都往高频推）。测试断言
`lump=60` 的幅值误差 < 5e-3（实测 1.1e-3）。

## 37.6 `.tran`：波前在 `TD` 到达，且随段数变陡

`LTRA(r=0 l=250n g=0 c=100p len=1)`（即 `Z0=50`、`TD=5 ns`），`PULSE(0 3 0 0.05n)`、
`tstep=0.1n`、`tstop=20n`。半幅跨越时刻：

| lump | 5 | 10 | 20 | 40 |
|---|---|---|---|---|
| 半幅时刻 | 5.3 ns | 5.2 ns | 5.1 ns | 5.1 ns |
| 末值 | 1.48157 | 1.48510 | 1.48515 | 1.48515 |

`lump=20` 的细节：`t=2 ns` 远端 `1e-5`、3 ns `0.0029`、4 ns `0.108`、5 ns `0.696`、
8 ns `1.48512`、20 ns `1.48515`（末值是 DC 分压）。测试断言「`TD` 之前远端 < 1e-3」与
「20 段的半幅时刻离 5 ns 不到 0.3 ns」。

代价：`lump=5/10/20/40` 分别 0.14 / 0.44 / 1.96 / 9.94 s（200 步）。纯 Python 稠密 LU 是
O(n³)，`lump=100` 的瞬态（≈303 个未知量 × 200 步 × Newton 迭代）直接把一次调用顶到分钟级；
`lump=200`（603 未知量）报 `TOO_LARGE`，提示里加了一句「lower lump= on a lossy line」。

## 37.7 内部节点：算，但不往外报

20 段的梯形会造出 39 个内部节点（`o1#n3`、`o1#a3`、`o1#g3`…）。它们**不是**调用方的电路节点：

- `_Circuit.__init__` 算 `internal_nodes = 全部节点 − 被非内部元件引用的节点`；
- `_node_dict` 跳过它们，所以 `nodes_v` 里只有 `{"1","2","3"}`；
- 每个 O/U 卡在 `elements` 里一条记录（类型、段数、总量、两端口电压、端口 1 电流）。

**抓到并修掉的真缺陷**：`U1 2 3 0 m` 里远端节点 `3` 只被内部元件引用，于是被当成内部节点
藏起来，读 `nodes_v["3"]` 直接 `KeyError`。修法是把所有 O/U 的**端口**节点从内部集合里
`discard` 掉——「远端什么都没接」是合法的电路（开路端），它必须出现在答案里。

端口电流只报 port1（集总线上没有单一「沿线电流」，报 port2 就是编一个数），
`current_convention` 里写清楚；第一段没有串联元件时电流报 0（数学上正确：端口 1 开路）。

## 37.8 顺手抓到的真缺陷：`.ac` 里没有 `AC` 说明的源不该被当成 1 V 激励

写这一版的 `cross_check` 时用了 `V1 1 0 3`（只有直流值、没有 `AC` 关键字），内置给了满幅
AC 答案，ngspice 给的全是 0。实测对照（`* d / V1 1 0 3 / R1 1 2 50 / R2 2 0 50 / .ac`）：

| | v(1) | v(2) |
|---|---|---|
| 内置（旧） | 1.0 | 0.5 |
| ngspice-47 | 0.0 | 0.0 |

SPICE 的规则是：**`AC` 关键字才是激励**，`V1 1 0 3` 里的 `3` 只是直流值，AC 幅度是 0。旧实现
`el.get("ac") or (1.0, 0.0)` 给了一份「电路没被驱动却满幅有答案」的读数——正是本模块要消灭的
那类东西。改成 `(0.0, 0.0)`，并且当整份 deck 没有任何 V/I 源带 `AC` 说明时，在 `warnings` 里
写一句「没有人驱动这次扫描，每个节点都会读到 0，要驱动就写 `V1 1 0 AC 1`」。既有测试全部
显式写了 `ac 1`，所以这个改动没有一处基线漂移。

## 37.9 自检探针第三次搬家：`T` → `O` → `S`

「内置拒绝、引擎能跑」那条自检条目（id 96）的作用是证明**引擎这条路真的通**，它的前提是
「有一张内置按名拒绝的卡」。随着内置能力增长，这条探针必须换：

| 版本 | 探针卡 | 内置 | ngspice |
|---|---|---|---|
| ≤0.0.29 | `T`（无损线） | 拒 | 1.5/1.5 |
| 0.0.30 | `O`（有损线） | 拒 | 1.5149/1.4851 |
| 0.0.31 | `S`（压控开关） | 拒 | 0.500 |

`S` 的 deck：`V1 1 0 1 / R1 1 2 1k / S1 2 0 1 0 sw / .model sw SW(VT=0.5 VH=0 RON=1k ROFF=10meg)`。
控制节点 1 V 对 `VT=0.5` 闭合，读数 0.500 V（断开会是 0.333 V），ngspice 精确给 0.5。
一条自检如果永远不会红，它就不是自检。

## 37.10 拒绝清单（每条都有用例）

- 缺模型名 / 模型未定义 / 模型类型不是 `LTRA`/`URC`；
- `LTRA` 里给 `Z0=`/`TD=`（指向 `T` 卡），`URC` 里给 `ISPERL`/`RSPERL`/`FMAX`（非线性参数不实现）；
- 缺 `LEN`、`LEN <= 0`、模型四个参数全 0（`chain of nothing`）；
- 未知模型参数按名拒绝；`per-length` 负值拒绝；`LUMP` 不是 ≥1 的整数；
- `lump=` 写在卡上（fatal to ngspice，错误里说明）；
- 两个不同的返回节点（`two different return nodes`）、端口两端同节点（`port %d shorted`）、
  `n1==n3 and n2==n4`（自己是自己的负载）、四端全地、`U` 的 `n1==n2`；
- `U` 缺 `R`/缺 `C`、`R` 与 `RPERL` 同时给；
- 段数大到放不下（`TOO_LARGE`，提示里给 `lump=` 这个旋钮）。

## 37.11 负控制：每一条都能失败

`tests/test_spice_oline.py`（34 例，5 个测试类 + 引擎对拍）。基线 0 红。

| 断言 | 如果机制不在会怎样 |
|---|---|
| DC 1 Ω 在 50/50 分压里读 1.514851/1.485149，`lump=1/4/20` 全等 | 每段按 `r·len` 建 ⇒ 读数随段数缩放 |
| 卡上 `lump=7` 时 `defaulted_model_params` 为空、不给时是 `{"O1.lump": 20}` | 默认值不明说 ⇒ 调用方不知道答案是 20 段的 |
| `nodes_v` 只有 `1/2/3`，`elements` 只有一条 `O1` | 内部节点泄漏 ⇒ 39 个假节点淹掉答案 |
| `g=1` 时误差随 `lump` 单调下降且 60 段 < 5e-3 | 并联电导建错 ⇒ 收敛到错的渐近值 |
| 无耗梯形与 `T` 在三个频点幅值一致、相位差 < 0.02° | R/L 值或拓扑错 ⇒ 两套实现分家 |
| 1 MHz 时 `|V(3)| = 0.495049 = 0.5·e^-0.01` | 没有串联电阻 ⇒ 读 0.5 |
| `U` 在 1 MHz 读 0.909951（解析 0.909627） | 每长度 RC 建错 ⇒ 输入分压偏 |
| 波前半幅时刻落在 5 ns ± 0.3 ns、`TD` 前远端 < 1e-3 | 电感/电容切错 ⇒ 波前不到或早到 |
| `U` 的瞬态远端滞后于近端、末值收敛到源 | RC 线被当成纯电阻 ⇒ 两端同刻 |
| 17 条拒绝逐条 | 任一漏掉 ⇒ 静默给一个能算出来的错答案 |
| `cross_check` DC < 1e-6、AC < 1e-5（lump=100） | 模型与 ngspice 不同（不是精度，是模型） |

## 37.12 仍然不做

- **皮肤效应、介质损耗（`G` 以外）、频变 `r`/`l`**：不在 `LTRA`/`URC` 这两个集总模型里；
- **`g > 0` 的引擎对拍**：ngspice-47 自己拒绝非零 `G`；
- **两个不同返回节点**：见 §37.2，梯形表达不了返回导体的延迟；
- **多导体 / 耦合线**：`K`（互感）仍按名拒绝；
- **`REL=`/`ABS=`**：固定步长解器，容限没有意义。
