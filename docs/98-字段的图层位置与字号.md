# 98 · 位号不只是字符串：`set_footprint_field` 终于能改它印在哪、印多大

> 它回答的问题：一块板报 **32 条 `text_height`** 和 **46 条丝印冲突**，全都是参考字段
> 惹的——可那个 op 只能改文字和显隐。**一个改不了位置和字号的文本操作，等于让人回去手改文件。**
>
> 它推翻的前提：**「字段只有内容和可见性两个属性」**——写在文件里的还有 `layer`、
> `(at x y rot)`、`(effects (font (size h w)))`，这三样恰好就是丝印能不能过 DRC 的全部。

---

## 98.0 两句话

1. `set_footprint_field` 新增五个**可选**参数：`layer` / `x` / `y` / `text_height` /
   `text_width`。一个都不点名时，行为与 0.0.97 **逐字节相同**（原有的 71 例全绿）。
2. 顺带修掉一个既有缺陷：**「把 Reference 改成别的名字」这件事在 0.0.97 之前根本不可能成功**
   ——写后的 `verify` 还按旧 `ref` 去找封装，找不到就 `REFERENCE_NOT_FOUND`，于是整笔回滚。

---

## 98.1 触发它的三个读数

STM32F412RGT6 核心板的 `kicad-cli pcb drc --format json --severity-all --units mm`
第一版报 **118 条**：

| 类别 | 条数 | 涉及的是什么 |
|---|---|---|
| `text_height` | **32** | 位号字高 0.7 mm，低于板厂「丝印最小字高 0.8 mm」 |
| `holes_co_located` | 28 | 过孔堆叠（与字段无关） |
| `silk_over_copper` | 24 | 丝印压在焊盘上 |
| `hole_to_hole` | 16 | 孔间距（与字段无关） |
| `silk_overlap` | 14 | 丝印压丝印 |
| `via_dangling` / `silk_edge_clearance` | 2 / 2 | — |

两次绕过：先把 32 条字高**直接改文件**从 0.7 抬到 0.8（`text_height 32 → 0`），总量
**118 → 46**；剩下的 46 条是 `silk_over_copper 26 + silk_overlap 18 + silk_edge 2`，
逐条看下去 **100 % 涉及参考字段**——位号要么压在自己的丝印框上，要么压到邻居的焊盘上。
要修它只有一条路：**把位号挪走**（偶尔还要换层或换字号）。

而当时 MCP 这一侧没有这个能力。两处 DRC 数字是同一句话：**这块板上真正需要动的，
是文本的几何，而不是文本的内容。**

## 98.2 五个参数，以及它们各自的约定

| 参数 | 语义 | 拒绝条件 |
|---|---|---|
| `layer` | 文本印在哪一层 | 不在板的 `(layers)` 表里 → `LAYER_NOT_IN_BOARD`；不在白名单 → `LAYER_NOT_ALLOWED` |
| `x` / `y` | 封装**局部**坐标，**Y-up**（与全仓入参一致） | 非数 / 布尔 / `NaN` / `±inf` → `ARG_INVALID` |
| `text_height` / `text_width` | 字高 / 字宽，mm | `≤ 0` → `ARG_INVALID` |

三条设计上的硬规矩：

**① 白名单只有 8 层**：`F.SilkS` / `B.SilkS` / `F.Fab` / `B.Fab` / `F.CrtYd` /
`B.CrtYd` / `Dwgs.User` / `Cmts.User`。**故意不许写到铜层**——把文字放到 `F.Cu` 上就是
真的加了一块铜，DRC 会按铜来判，而调用者想的通常只是「这块字能不能换个地方」。
分不清意图的操作就不提供，报 `LAYER_NOT_ALLOWED` 并把这 8 个名字列出来。

**② `(at x y)` 在封装局部帧、Y 向下；参数是 Y-up。** 文件里 `(at …)` 的 Y 与整份文件
一样向下，而本服务器所有坐标入参都是 Y-up，所以**恰好翻转一次**（`ny_file = -want_y`），
返回的 `detail.geometry.y` 再翻回来。这条与 97 篇的教训是同一类：**坐标系翻转必须
数清楚有几次**，一次不多一次不少。

**③ 只校验被点名的那一维。** `x` 给了 `y` 没给，写后 `verify` 只断言 `x`，`y` 保持原值
但标为未检查。理由很简单：校验一个没人要求改的数字，通过率就是装饰。

## 98.3 顺带修掉的既有缺陷：改不掉的名字

旧的 `_verify_set_field` 第一句是 `fp = ed.footprint(ref)`。当这次操作改的正是
**Reference 的值**时，写完之后旧名字已经不存在了：

```
postcondition check failed ... {"error": "REFERENCE_NOT_FOUND: no footprint with reference 'R1'"}
```

于是「改位号」这个操作在 0.0.97 之前**永远不可能成功**：写对了也回滚。现在捕获这一种
情况——`REFERENCE_NOT_FOUND` 且 `field == "Reference"` 且新 `value` 非空——改按新名字找。
其他任何 `REFERENCE_NOT_FOUND`（比如 `ref` 本来就不存在）仍然原样抛出，不吞。

这条是「字段几何」这个需求连带出来的：给位号挪位置时按名字定位，才让人发现名字本身改不了。

## 98.4 反向对照：七条用例里有一条是为了让别的六条有意义

`tests/test_ops_edit.py::FieldGeometry`（7 例）：

1. `test_naming_no_geometry_leaves_the_field_where_it_was` —— 只改文字，`at` 的 x/y、
   `layer`、`effects` **全都不许出现/不许变**（断言 `effects` 仍是 `None`：没人要的字号
   不能被凭空造出来）。
2. `test_a_field_can_move_layer_position_and_size_at_once` —— 五项一起给，落盘后逐个核对，
   并断言 `y` 的符号只翻了一次（入 `-3.25` ⇒ 文件里 `+3.25`）。
3. `test_naming_one_axis_keeps_the_other_and_the_angle` —— 只给 `x`，`y` 与 `rot` 不动。
4. `test_a_layer_the_board_does_not_declare_is_refused` —— `F.Nope` ⇒ `LAYER_NOT_IN_BOARD`，
   并回头断言**文件没被写**（拒绝必须是零副作用）。
5. `test_a_position_written_as_text_is_refused` —— `x = "1.5"` ⇒ `ARG_INVALID`。字符串数字
   意味着调用方与服务器对单位或类型有分歧，写入不是搞清这件事的地方。
6. `test_a_non_positive_text_size_is_refused` —— `0` 与 `-0.8` 都拒。
7. `test_the_verifier_notices_a_field_that_did_not_move` —— **反假绿**：真写到 `x = 2.5` 之后，
   拿 `x = 4.0` 去问 `verify`，必须 `ok = False`；再拿 `2.5` 问，必须 `True`。
   没有这一条，`all_verified: true` 就永远为真。

## 98.5 边界：这次没做的事

- **不做自动避让。** 「把 13 个位号摆到不压任何东西的位置」是搜索，不是 op；
  它在 `_scratch` 里跑（把 194 个焊盘 + 96 条丝印线当障碍，算出坐标），再把结果
  作为普通参数喂给这个 op。op 只负责**按说的写，并按说的验**。
- **不改 `justify` / `angle` / 字体粗细。** 没有需求，也不猜。
- **不动 Value 与其它 property 的语义。** 同一套参数对任何字段都适用，因为它们改的是
  文件里同一组子节点。
- **不改封装库里的定义。** 只改**板级实例**上的字段；库那一侧仍是 DRC 的
  `lib_footprint_issues` 的事（32 条 warning，见 95 篇）。

## 98.6 三条可复用的教训

1. **一个「能改文字」的操作，在 PCB 上是半成品。** 丝印过不过 DRC，取决于它**印在哪、多大**，
   不取决于它写了什么。缺了这两个维度，用户只能回去手改文件——那这条 MCP 链就断了。
2. **新参数默认不改变既有答案，是可以用断言证明的**：第一条用例断言的是「`effects` 仍是
   `None`」这种**曾经不存在的东西不许出现**，比「结果相同」更难糊弄。
3. **拒绝必须零副作用，且要能被验。** 第 4 条用例拒绝之后回头读文件，才让「报错了」
   与「什么都没写」成为同一件事。
