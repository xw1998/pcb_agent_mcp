# 167 · 布局硬读数：8 条网布不通、U1 有 43/97 条网在错的边、U2 转 270° 的反序数 95→55

本文只做测量与归因，**不改板**。之所以不改，是本文第 9 节量出来的代价：动一次布局要把
2192 件铜（占全板 4128 段的一半以上）撕掉重布，而本仓库自带的迷宫布线器布不了 DDR 总线
（10 条探针只通 3 条）。在半成品上改布局等于拿已经交付的板换一个"看起来改了"的读数。

板子：`examples/rk3506_som/rk3506_som.kicad_pcb`（= 0.1.29 交付板，4128 段 / 630 孔 /
5 zone / `board_shape_gate` `shape_pass`）。下文所有读数都在这块板上，坐标系为正 y。

## 1. 形状已经是干净的，剩下的全是布局层

0.1.29 收掉的是形状：`acute_corner` 8 → 0、`duplicate_copper` 21 → 0、`track_dangling` 0、
`off_45_heading` 0、`arcs` 0；`square_corner` 422 只作 judgement（0.1 mm 级 90° 转角，
要消得改布线器栅格，属生成端）。DRC 30 项与基线逐类别逐条数相同。

所以用户说的"布局根本没改""DDR 画的线还是狗屎""线还是很丑"，**不可能再从形状闸门里读出来**，
必须换一组读数：连通性、等长、车道顺序、空气线、模块网落边。本文给的就是这五组。

## 3. 读数二：迷宫布线器在四种参数下 8/8 全拒

`tools/route_som_signal.py`（自研确定性迷宫，非 KiCad 自动布线）只跑这 8 条网：

| 净空 CLR | 栅格 STEP | 结果 |
|---|---|---|
| 0.15 | 0.05 | `jobs 8 placed 0 refused 8`（完整日志 `_n_route.log`） |
| 0.10 | 0.05 | 8/8 REFUSED |
| 0.10 | 0.025 | 8/8 REFUSED |

板级 `min_clearance` = 0.1，Default netclass clearance 0.1 / track 0.1 / via 0.2–0.1 ⇒
0.15 那档本来就比板规更严，**拒不能记到"净空太紧"头上**；把净空放到板规 0.10、栅格从
0.05 收到 0.025（再细就超过板子 0.1 mm 的走线宽度本身了）仍然 8/8 全拒 ⇒ **根因在布局/密度，
不在搜索参数**。

每层铜量（`_r_layers.py`，本板）：

```
B.Cu      1080 items  1099.81 mm
F.Cu       851 items   809.50 mm
In2.Cu    1083 items  1027.46 mm
In3.Cu      38 items   193.24 mm     <- 唯一还有空的地方，是 GND 平面
In4.Cu    1076 items  1098.13 mm
vias 630
```

四个信号层都塞到 1 mm/件量级，只剩 In3.Cu 一块平面。**J1 那 5 条要过的走廊没有空余通道**，
所以搜索再细也只是在已经满了的格子上找路。

直接量走廊（`_pinch.py`：沿两端点直线每 0.25 mm 采一点，算到同层外来铜的距离；
0.10 线要 0.05 半宽 + 0.10 净空 = 每侧 0.15 mm，小于 0.15 记一堵墙）：**四个信号层全部是墙，
而且沿线各层的墙占整条的 1/5 到 1/2**，负值表示直线直接压在别的网上：

```
                  墙采样 / 总采样（F.Cu / In2.Cu / In4.Cu / B.Cu）
/USB1_DP     26.22mm   51/105  30/105  44/105  39/105
/ACODEC_INN  31.11mm   60/125  38/125  40/125  23/125
/+1V35_DDR    9.72mm   18/39   31/39   37/39   34/39
/DDR_A11     18.38mm   42/74   36/74   44/74   32/74
/DDR_A8      18.85mm   43/76   41/76   41/76   41/76
```

这条读数的意思不是"直线走不通"（布线当然不沿直线），而是：**四个可走信号层里，没有一个层
在起点到终点的任何一个区段是空的**——布线器要找的不是一条线，而是一条缝，而这条走廊上
每层都有大段无缝隙区域（`/+1V35_DDR` 的 In4/B 甚至 37/39、34/39）。

```

A10   16.528 / 0.000     CKE   16.197 / 0.000     A4    13.100 / 0.387
```

## 6. 读数五（根因）：43/97 条模块网落在"错的板边"

同一次 `place_score` 的模块落边统计：**54 条在该在的边，43 条在别的边**。

```
SoC N -> board E : 18 nets   /ACODEC_INN, /ACODEC_INP, /MIPI_DSI_CLKN, /MIPI_DSI_CLKP, /MIPI_DSI_D0N, /MIPI_DSI_D0P …
SoC N -> board S : 20 nets   /+3V3, /RMII0_CLK, /RMII0_MDC, /RMII0_MDIO, /RMII0_RXD0, /RMII0_RXD1 …
SoC E -> board S :  5 nets   /RMII1_CLK, /RMII1_MDC, /RMII1_MDIO, /RMII1_RXDVCRS, /RMII1_TXEN
```

这 43 条要从 SoC 的一条边出发、**横穿整板**到对角/对边的连接器，正好就是读数一的 5 条
未连接网（ACODEC / SARADC / USB）和读数三的 `/RMII1_*`（空气线 40–42 mm）——
**"有些线绕了一大圈"是可量化的：43 条网在错的边。** 解决它必须动 SoC 方向或连接器位置，
不是布线器能补的。

## 7. 读数六：U2 转 270° 能把 DDR 车道反序数从 95 降到 55

`_ord2.py`：U2 的 22 条 DQ/DM/DQS 按焊盘→球位的车道顺序排，算 Kendall 反序数（231 对里
多少对反了）。八种朝向：

| 朝向 | 反序数 /231 |
|---|---|
| 0°（现建成） | **95** |
| 0° + mirror | 102 |
| 90° | 176 |
| 90° + mirror | 184 |
| 180° | 136 |
| 180° + mirror | 129 |
| **270°** | **55** |
| 270° + mirror | 47 |

mirror 不是顶面元件能做的操作 ⇒ **合法选项只有纯旋转，270° 是 55，比 0° 的 95 好**
（顶面元件转 270° 合法是因为它本来就可以转）。这条说明"DDR 线还是很丑"的几何根因：
**球位顺序和焊盘顺序对不上，走线必然互相交叉**。

## 8. 转 270° 的合法性已查清，但重布探针只通 3/10（负读数）

合法性（都在 U2 转 270° 之后测）：

- **同层外来铜冲突只有 1 条**：`/RMII1_MDC`（原板 0 项）。按层判据是关键——不分层会误报 40 项，
  全是内层走线（合法）。
- **courtyard 压到 4 个件**：C11 0.543 mm²、C13 0.181、R9 0.204、R10 0.184。
- **找到 0 重叠挪位解**（`_r_crtall.py` 全对检查，基线 0 对）：
  `C11:0.5:-1.8`、`C13:-1.0:-1.0`、`R9:-1.0:0.0`、`R10:-1.0:0.0` ⇒ `_r1d.kicad_pcb` 0 对重叠。

重布代价与能力（`_r1e` 上跑迷宫布线器，CLR=0.10 / STEP=0.05 / BUDGET=25）：

- 撕掉 58 条 U2 网 = **2192 件铜**，占全板 4128 段的一半以上；
- 60 个 job 只试前 10 条：**3 OK（`/SW_U6`、`/BS_U6`、`/DDR_DQ0`）/ 7 REFUSED**
  （`/+1V35_DDR`、`/+0V675_REF`、`/DDR_DQ2`、`/DDR_DQ6`、`/DDR_ODT`、`/DDR_DQS0P`、`/DDR_DQS0N`）。

⇒ **本仓库自带的迷宫布线器布不了 DDR 总线。** 旋转方案在几何上更好（95→55）、在合法性上
可做（1 条外来铜 + 4 个件挪位有解），但**在交付能力上不可行**。这条负读数是本节不落地的
唯一理由，也是下一步要补的能力缺口。

## 9. 为什么本轮一个布局改动都没有落地

把三件事放在一起看：

1. 改布局就要重布 U2 的 58 条网 = 2192 件铜（一半的板）；
2. 布线器只能通 3/10；
3. 剩下的 7 条里有 4 条是 DQS/DQ/ODT——正是读数三要求"等长"的那一族，而等长本身又因为
   **没有空间**补不上（342.2 mm 的缺口只填了 10.73 mm）。

半成品落地 = 交付一块比现在差得多的板去换"布局改过了"这句话。所以本轮**只量不改**，
把缺口写清楚：**缺的是一条带长度预算的 DDR 总线布线策略**（在布线时就按组分配长度、
把蛇形空间预留出来，而不是先布完再回头补），以及"布局改了就整板重布"的整段重布能力。
这两样都没有之前，动布局不是改好，是改坏。

## 10. 工具改动：`route_som_signal.py` 的 STEP / CLR / TW 参数化

原来这一行是硬写的：

```python
STEP = 0.05
CLR = 0.15
TW = 0.10
```

板规是 clearance 0.10 / track 0.10，硬写 0.15 会把合法板全判拒——**拒就变成了这个文件
自己发明的数字造成的，而不是布局造成的**，归因直接失效。改成：

```python
STEP = float(os.environ.get("STEP") or 0.05)
CLR = float(os.environ.get("CLR") or 0.15)
TW = float(os.environ.get("TW") or 0.10)
```

默认行为一个字没变（还是 0.05 / 0.15 / 0.10），只是允许 `CLR=0.10 STEP=0.025 …` 复跑，
让"拒"这个结论可以指向布局而不是参数。

## 11. 坑与口径

- **分层判据**：查"焊盘底下有没有外来铜"必须按焊盘所在层过滤；不分层会把内层走线全算进来，
  原板就"40 件外来铜在 U2 焊盘下"，全是合法的。
- **courtyard 冲突要查全对**：只查"U2 vs 全板"会漏掉"挪动的电容之间互撞"，第一版就是这么
  漏的，写 `_r_crtall.py` 查所有对才拿到 0 重叠解。
- **`_r_near.py` 要传负 y**：pcbnew 原生 API 的 y 是负的；正 y 是 adapter/工具打印口径。
  传 `"12,3,30,21"` 返回空，要传 `"12,-21,30,-3"`。
- **等长判据的参考是最长的那一个**：蛇形只能加铜，所以"太长"是重布不是微调——`check_length.py`
  和 `meander_som_length.py` 的 docstring 都写死了这一条。
- **`meander` 的输出是整网重写**：`delete_copper(net) + add_track(原始和蛇形全部) + add_via(原始过孔)`，
  不留半蛇形的网。
- 读数必须带 cwd：同一块板在仓库路径下 DRC 30 项、在工作区 41 项（差 11 条
  `lib_footprint_issues`，工作区没有 `fp-lib-table` 与 `lib/`）。
