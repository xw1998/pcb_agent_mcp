# 174 · 补上第四块缺口：八关顺序编排，并用 12 块好板验这条规则表

`docs/173` 诊断出四个缺口，只造了三个。第四个是：

> 好板子只被提炼成**阈值**（净空 0.10、线宽 0.15、过孔 0.20/0.10），没被提炼成**编排**——
> 不知道哪条规则必须先满足、哪一步的读数在被前一步污染时根本不能当判决。

这一版把它造成可执行的东西：`tools/plan_sequence.py`。它**不写板、不挪件、不布线、不加 `--apply`**，
只回答两个不同的问题：

* 单板模式（`--board`）：**我现在该先做哪一步**；
* 语料模式（`--corpus`）：**这条规则本身对不对**。

这两个问题不能共用一个判据，原因见 §3。

---

## 1. 八关与它们为什么必须按这个顺序

| # | 步 | 判据（物理） | 为什么必须在这一步之前 |
|---|---|---|---|
| 1 | `frame` | 板框闭合；走线/过孔离板边 ≥ `EDGE_HARD_MM=0.10` mm；无越界铜 | 板框决定「哪里根本没有位置」，是所有坐标的前提 |
| 2 | `floorplan` | `crossing_frac ≤ 0.15` 且 `proposal_overlaps == 0`（复用 `plan_floorplan`） | 器件朝向错了，它连的网就必然跨板；这个误差只能用整块板重布来偿还 |
| 3 | `stackup` | 每个走线层都有相邻参考平面（覆盖 ≥ `PLANE_COVER_MIN=0.25`） | 层数与平面决定有几条通道、回流从哪回去；改它等于重画 |
| 4 | `fanout` | 阵列封装（≥ `ARRAY_PADS_MIN=64` 焊盘）逃逸率 ≥ 0.98 | 出口位置决定走廊入口；**盘中孔在这一步产生，不是布线阶段** |
| 5 | `power` | 电源网至少有一条铜（不是只有焊盘） | 平面要绕开扇出过孔成形；反过来做就得重新扇出 |
| 6 | `bus` | 每组总线（按网名前缀）都有足量蛇形带（`plan_meander` 的 `fits`） | 总线要走廊**和**长度预算，两样都在布线前定 |
| 7 | `route` | `shape_gate` blocking 全 0 | 信号铜最后画，它只能使用前面几步留下的空间 |
| 8 | `closure` | `unconnected == 0` | 只有前面全过，「还有几条没连通」才是一句有意义的话 |

顺序不是我排的偏好，是**因果**：每一步的输入都是上一步的输出。RK3506 上这句话是可以量化读出来的——
`plan_meander` 说 47/49 条 DDR 放不下蛇形带，真因不是蛇形算法差，是 `floorplan` 那 36 条跨板网把走廊用掉了。

## 2. 判词的四种状态，缺一个就会出假绿

| 状态 | 含义 |
|---|---|
| `pass` | 前提全满足，判据过 |
| `fail` | **只有前面每一步都 pass 时才可能判 fail** |
| `blocked` | 前面有 fail/error ⇒ 数照测照打，但**明确不作判**，并写清被哪一步挡住 |
| `n/a` | 这条规则对这块板不适用（2 层板没有内层平面、板上没有总线网、板上既无走线又无过孔），**不是通过** |
| `error` | 这一关算不出来（如 `LoadBoard` 超时），**绝不等于通过** |

`blocked` 与 `n/a` 是这一版最重要的两个词。没有它们，就会出现 `docs/167` 那种读数：
`meander` 报「35/39 放不下」，然后被读成「等长算法不行」——其实是被上游污染的数字。

## 3. 规则分两类：`physical` 与 `house`

```python
ORIGIN = {"frame": "physical", "floorplan": "physical", "stackup": "physical",
          "fanout": "physical", "power": "physical", "bus": "physical",
          "route": "house", "closure": "physical"}
```

* `physical`：违了就是物理上不行（未连通、铜在板边外、电源网一点铜都没有）。语料不过 ⇒ **规则可能是错的**。
* `house`：本项目方针（45°、禁圆弧、禁死端、盘中孔、去耦距离、线宽）。语料不过 ⇒ **不算反证**。

这一层区分是必须的：拿 12 块 2005 年前后的手绘 demo 板去反证「走线必须 45°」，是不讲理；
反过来把「盘中孔」留在物理判据里，等于宣布 `royalblue54L_feather`（89 个）和 `video`（23 个）这些能出货的板有罪。

只是现在由程序说出来，不再靠我事后归因。

## 5. 语料：12 块 KiCad demo 板，每关**独立**判

`--corpus` 模式下 `evaluate(..., chain=False)`：每一关按自己的判据独立判，不经链式阻断。
样本数因此是**板数**（12）而不是「通过了前几关的板数」。理由见 §3——语料问的是「这条规则对不对」。

`judge_corpus`：`rate ≥ 0.9` ⇒ 规则成立；`0.5 ≤ rate < 0.9` ⇒ 阈值可能过严；
`< 0.5` 且 `physical` ⇒ 这条规则是错的；`house` ⇒ 不算反证；**`n < MIN_JUDGED(3)` ⇒ 样本不足，不下结论**。

```
corpus 12 board(s), bus amplitude 0.30, each step judged on its own (no chain blocking)

step      pass  fail  blk   n/a  rate    n    judgement
frame     10    1     0     1    0.91    11   好板子都过 => 规则成立
          fail on: tiny_tapeout.kicad_pcb（无闭合板框）
floorplan 0     2     0     9    0.00    2    可判样本只有 2 份（<3）=> 样本不足，不下结论
          fail on: royalblue54L_feather（8/28=0.2857）、stickhub（3/4=0.75）
stackup   5     0     0     7    1.00    5    好板子都过 => 规则成立
fanout    12    0     0     0    1.00    12   好板子都过 => 规则成立
power     12    0     0     0    1.00    12   好板子都过 => 规则成立
bus       0     0     0     12   -       0    无可判样本
route     1     11    0     0    0.08    12   house rule（本项目方针）—— 语料不过不算反证
closure   10    0     0     2    1.00    10   好板子都过 => 规则成立
          n/a: royalblue54L_feather、tiny_tapeout（pcbnew 在 120 s 内没读完，LoadBoard 卡死）
```

读法（逐条，不许合并）：

1. **`closure` 10/10 全过，一个未连通都没有** —— 这条是硬的。2005 年的 demo 板也能做到，说明「网表连通」不是高标准。
2. **`power` 12/12 全过，`fanout` 12/12 全过** —— 两关都在判据修订后从「大面积不过」翻成「全过」（§7），
   翻的原因是我原来的判据在判**风格**（线宽 0.15 才算数、必须有过孔才算逃逸），不是判**事实**。
3. **`frame` 10/11 = 0.91** —— 唯一 FAIL 是 `tiny_tapeout`，它真的没有闭合板框（`outline_closed False`）。
   `microwave` 判 `n/a`：8 焊盘、0 track、0 via，板边间距无从测量——**不能判 pass**（提取器漏铜时会变成假绿）。
4. **`floorplan` 样本只有 2 份**，都 FAIL。9 块板判 `n/a`（没有到板边的网，即没有半孔/接插件端子）。
   2 < 3 ⇒ `样本不足，不下结论`。**不改阈值去凑一个通过**：`0.15` 是从 RK3506 的 0.3673 与 `cc` 判据里定下来的，
   语料证不动它，就明说证不动。
5. **`bus` 无可判样本** —— 12 块 demo 板没有一块有 DDR/BUS 名前缀的网。这一关只有 RK3506 自己有读数。
6. **`route` 1/12 = 0.08，`house`** —— 11 块板有锐角/非 45°/重复铜。这条**不算反证**：
   2005 年的板是手工拉的、按当时的工艺；而它正是用户对本项目的要求（`docs/165` 之后 `shape_gate` 一直是 blocking）。
   语料能给的唯一信息是「这条规则比业界普遍做法严」，这一点写在这里，不粉饰。

## 6. 训练这块工具时，自曝出来的四个 bug

这些是**本轮写代码时自己撞出来的**，都留下了判据/注释，属于「宁可报错不给错答案」的落地：

1. **`outline_segments` 不闭合环 ⇒ 假绿**。用 `range(len(contour)-1)` 连边，板框最后一段（末点→首点）不存在。
   一块 45×45 的板左边距读成 **19.9 mm**（真值 0.05）——即「铜离板边 19.9 mm，完美」。
   修法：末点与首点不等时补一段闭合边。RK3506 复测 `edge_min 0.4512` 不变（它本来闭合）。
2. **`SystemExit` 逃过 `except Exception`**。`plan_floorplan.outline_box()` 原来 `raise SystemExit("board has no outline")`，
   它继承 `BaseException` ⇒ 一块 `tiny_tapeout` 把整轮语料 `exit=1` 打断。本轮把 `evaluate` 改成
   `except (Exception, SystemExit)`，并把 `outline_box` 自己改成 `ValueError` + CLI 打印 `error : ...` 返回 2。
3. **`pcbnew.LoadBoard` 会静默卡死**。`royalblue54L_feather` 与 `tiny_tapeout` 各卡死一次（0% CPU、输出 0 字节），
   用 `faulthandler.dump_traceback_later(90, exit=True)` 定位到 `pcbnew.py:9896 LoadBoard`。
   修法三条：`_ctx` 改**惰性加载**（`raw=None`，只在真要 pcbnew 的那一关才读）；`gate_bus` 先按网名前缀**便宜预筛**，
   没有 DDR 网就直接 `n/a` 不加载；`gate_closure` 的未连接数走**子进程 + 120 s 超时**，超时 ⇒ `n/a` 并写明
   「pcbnew 子进程没给出未连接数」。本轮 `royalblue` 用了 **124.6 s** 才走完（`tiny_tapeout` 吃满 **125.7 s** 超时）。
4. **`4**N` 精确枚举没有预算**。原来 `len(names) <= 8` 才枚举，否则静默退回「不搜」——而报告里仍写着
   「the search is exact over 4**N」。一块有 12 个功能簇的板会是 1677 万次，看起来像卡死。
   修法：`ENUM_BUDGET = 30000000`，超预算降级为**坐标下降**，并在答案里加 `method ∈ {exact, coordinate_descent}`，
   `how` 字段一起改；`tests/test_plan_floorplan.py` 新增反向对照——把 `ENUM_BUDGET` 降到 1，
   `method` 必须变成 `coordinate_descent`，**启发式的数字不许被印成 exact**。
   （同时抓到一个真 bug：坐标下降分支引用了尚未定义的 `now_side`，`UnboundLocalError`——只有超预算的板才会走到那行，
   正是「没测过的分支就是没写过的分支」。）

## 7. 判据按语料证据修订了四处（每处都因为「好板子被判有罪」）

| 关 | 原来错在哪 | 现在 |
|---|---|---|
| `fanout` | ① 经**同网铺铜**连出去的焊盘算「没逃逸」（cm5 J701 45% 未逃逸）；② 焊盘盒测试**忽略 rotation**（cm5 模块焊盘 270°）；③ 只测端点，漏掉**线段穿过焊盘**（FPC 常见，cm5 J701 0.5775→1.0）；④ 剩余 30 个未逃逸其实是**单焊盘网**（模块引脚没用） | 四处全修：`_in_poly`/`zone_cover`/`_poured`、`_in_pad` 在焊盘自身坐标系做盒测试、`_seg_in_pad`（Liang–Barsky）、`pad_count ≤ 1` 直接计逃逸 ⇒ cm5 三阵列全 **1.0**，语料 **12/12** |
| `power` | `segments < POWER_SEG_MIN(4)` 当失败：好板子 7/12 不过 | 段数/线宽只是**未声明电流的代理量**（RK3506 的 9 条电源网全 0.10 mm、29–91 段；2002 年的 demo 用 0.8 mm、40 段，两边不该互相判罪）⇒ **只判「电源网只有焊盘、一点铜都没有」**，细线与去耦距离降 `house` 只报告 ⇒ 12/12 |
| `closure` | 把 `house` 的 `shape_pass` 混进物理判据 ⇒ 12 块好板 10 块「未收口」，而 `unconnected` 全是 0 | **只判 `unconnected == 0`**；`hole_in_pad` 标 `house`，`shape_verdict` 仅 `reported_only` |
| `frame` | 单一阈值 0.30 mm（本项目 house），把 `stickhub` 的 0.2414 判死 | **双阈值**：物理下限 `EDGE_HARD_MM=0.10` 判决，`edge_needed_mm(0.30, house)` 只报告 ⇒ `stickhub` PASS 并附一句「比本项目 0.30 mm 紧 0.0586 mm（house，不判）」 |

盘中孔/去耦/线宽从「判决」降为「报告」这一条，是这一版最值得记住的转向：
**它们不是物理不可能，是本项目的方针**。方针要能说出来，但不能假装是物理。

## 8. 边界（这一版明确不做的）

* 不写板、不挪件、不布线、不加 `--apply`；`plan_floorplan` 的提案只是坐标，落地永远是人手改。
* 不讲「权重」（哪条规则更重要）——只讲**先后**与**能否作判**。真正要加权的是同一关内部的取舍，
  那是 `shape_gate`/`place_gate` 的 priority 字段，不在这一版。
* `floorplan` 的 `0.15` 与 `bus` 的 `0.30` 振幅是**假设**，语料只证到「样本不足」，没证它们对错。
* `bus` 只有 RK3506 一块板有读数，没有第二个带 DDR 的样本。
* `LoadBoard` 卡死是 KiCad 侧现象，只能靠超时兜住；`royalblue` 124.6 s 属「能读完但极慢」，没有根因。

| 12 | **把「规则」当成「物理」** | 线宽、去耦距离、盘中孔一路当硬判据，导致语料里好板子 7/12 不过。本轮才把它们降为 `house` |

总根因两条，其余都是它们的形态：

* **顺序错**（先布线后量空间）——所以读数是污染的，所以修的都是症状。
* **判据太松或太僵**——松的造成假绿（8 vs 61），僵的把好板判有罪（线宽 0.15、盘中孔）。

「画不出好板子」不是审美问题，是**这条流水线缺了编排层，而判据没有经过好板子的反向检验**。
这一版补的就是这两件事：`plan_sequence` 给编排，12 块 demo 板给反向检验。
