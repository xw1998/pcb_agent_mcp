# 177 · 立创 EDA 真实语料进门：六条格式缺陷，和三处判据缺陷

`docs/174` 把八关编排造出来时，语料全是 KiCad demo 板（`_corpus/` 12 块）。用户的原话是
「收集比较完美的板子确认这些规则是否合理」——12 块 KiCad demo 只能证明**规则在 KiCad 的读法下自洽**，
不能证明它在**别人画的、已经量产的板子**上成立。这一版把 6 块立创 EDA 工程（`.epro`）接进同一套八关，
接进去的第一秒就发现：**不是规则不对，是我把文件读错了**。

六条格式缺陷全部在 `src/pcb_agent_mcp/adapters/epro.py`，三处判据缺陷在
`src/pcb_agent_mcp/shape_gate.py` 与 `tools/plan_sequence.py`。**这一版没有改任何板子，
也没有改任何判据的门槛值**（`CROSS_FRAC_MAX` 0.15 / `EDGE_HARD_MM` 0.10 / 环路判据的 blocking 属性
一个字没变）——改的是「读数是不是读对了」。

---

## 1. 六块真实立创板接进来（`tools/plan_sequence.py`）

`corpus_paths()` 以前只 glob `*.kicad_pcb`，立创工程文件（`.epro` / `.eprj` / `.eprj2`）在同一个
目录里躺着却一块都没进过任何一次规则体检。现在后缀表是
`CORPUS_SUFFIXES = (".kicad_pcb", ".epro", ".eprj", ".eprj2")`。

语料：`_scratch/corpus/packed/` 六块（`1dc6aafb…52x_`、`5c71f32e`、`7f8fbddc`、`99593ab6`、`dcfea2db…2.4G_`、`fadd8cdd`）。
六块都是**画完并出过板的成品**，所以「好板子不过」的每一格都必须能追到一条具体的读取错误。

## 2. 六条格式缺陷：每条都有前后读数

### 2.1 `["R", x, y, w, h, rot, radius]` 里的 `y` 是**上边缘**，不是左上角

矩形实际跨度是 `x … x+w` × `y-h … y`。以前读成 `y … y+h`，得到的是一个**整体下移一个矩形高**的形状。
三组独立证据（两块不同的板 + 板框本身）：

| 证据 | 记录 | 只有 `y-h … y` 才说得通 |
|---|---|---|
| `5c71f32e` 的 GND 铺铜 | `["R", …, y=3522.73, h=7176.96]` | 该网走线 y 实测 −370…1094 mil，只有 `−3654…3523` 才包住；`3523…10700` 包不到 |
| `fadd8cdd` 的 `$6N3821` 铺铜 | `["R", …, y=1330.84, h=34.66]` | 该网走线 y 1331…1365 与 `y…y+h` 重叠、而铜实际在 1304…1307 mil ⇒ 只有 `1296…1331` 说得通 |
| `7f8fbddc` 的**板框** | `POLY ["R",5,2610,6340,2375]` | 只有读成 235…2610 mil 才包住全部铜（5.97…66.30 mm） |

读反的后果是可量化的：`fadd8cdd` 的板级铺铜被放到板外之后，503 个过孔里 **348 个**被判「只有一侧铜」。
修法一处：`_rect_prims()` 里 `y0 = y - h`，旋转中心随之改成 `cy = y0 + h/2`，
docstring 把上面三组证据写进去（下一个人不该再靠猜）。

### 2.2 `POURED` 的坐标单位是 **10 mil**，不是 mil

同一块板上，`POUR` 轮廓用 mil、`POURED` 灌注结果用 10 mil。以前按 mil 读，灌注面缩到原来的 1/100，
于是「铺铜里的铜」几乎全部消失。修法：`FILL_UNIT_MIL = 10.0`，并补一条测试
`test_poured_fill_is_written_in_ten_mil`（fill 的包围盒要等于 pour 的包围盒，且落在 pour 轮廓内）。

### 2.3 一个铺铜可以有多条 `POURED` 记录，以前只留最后一条

多岛 / 被切碎的铺铜是**多条** `POURED`。以前 `filled_polygons = [...]`（覆盖），现在 `extend`。
测试 `TestEproManyPouredRecordsForOnePour`：给两条记录，`len(filled_polygons) == 2`，
且 x 跨度分别是 50…900 与 100…400 mil。

### 2.4 有的项目**根本没有 `POURED` 记录**

`fadd8cdd` 这个工程有 10 个 `POUR`、**0 个 `POURED`**——文件里就是「画了铺铜但没灌注」的状态。
以前于是「铺铜区域里的铜」全部读成不存在，死过孔 **363**（含 348 + 15 死线）。

处理方式是**回退 + 声明出处**，而不是悄悄补上：

```
zone["fill_source"] = "POURED" | "pour_outline" | "FILL" | None
board.source["fill_note"] = "N pour zone(s) had no POURED record; their outline was used as the filled copper"
```

方向上的权衡写在代码注释里：不回退 ⇒ 把一块好板判死（948 死过孔，见 §5 表）；
回退但不声明 ⇒ 可能掩盖真断点。选后者 + 把出处暴露给读者，因为立创保存「未灌注」项目时，
轮廓就是文件里唯一的铜区域信息。**`fadd8cdd` 死过孔 363 → 3。**

### 2.5 重名内层铜：`SIGNAL#15` / `SIGNAL#16`

立创的多层板里内层可以两条都叫 `SIGNAL`。以前两条同名，`_copper_layer_ids()` 按名字去重 ⇒ 一条内层整个消失，
于是「别的层上的铜」被判成同一层，环路/死端/间距全部错位。修法：`_disambiguate_copper()` 给重名层编号
（`SIGNAL#15`、`SIGNAL#16`），并在 `board.copper_layers` 与 `layer_note` 里带上编号。
配套 `via["layers"]` 也补上了——过孔跨哪几层是判断「孔只有一侧铜」的唯一依据。

### 2.6 焊盘尺寸：custom pad 没有 `w`/`h`

自定义焊盘（`shape="custom"`）只给点集，`w`/`h` 是 `None`。`max(None, None)` 抛异常 ⇒ 整块板 `error`。
实测一块立创板 **13 个**这样的焊盘。修法：`pad_wh` / `pad_half` 在缺 w/h 时取点集跨度，5 处调用点统一。

## 3. 三处判据缺陷（这才是「好板子被判有罪」的真正原因）

### 3.1 落在**别的网焊盘**上的线端，被当成悬空尾巴

`1dc6aafb` 报 **136 个死端**，逐条看下去 **94 个**的端点正落在**另一个网的焊盘中心**
（`$$$10132` 的线端压在 `PA_35_USB_DP_U1_TXD_EC1` 焊盘上；文件 NET 表里两个网都存在）。
**铜是有的**——问题是两个网名不一致，属于「网身份 / 连接性」问题，属 DRC 的事，不是悬空尾巴。

修法：`_dead_end()` 里加 `pad_here(lay, x, y, radius)`（任何网的焊盘，返回它属于哪个网），
命中则记 `kind="track_end_on_foreign_pad"` + `on_pad_of`，**不计入 `measured`、不 blocking**，
但在 `detail` 里单列数量：`N more end(s) stand on a pad of another net - the copper is there,
the two nets disagree, so that is a net-identity question and it is listed but not counted above`。

读数：`1dc6` 死端 **136 → 43**（+93 别网焊盘）；`99593ab6` 死端 **7 → 0**（+7 别网焊盘）。

### 3.2 `GND` 和按电压命名的电源轨没被当成 rail

`POWER_HINTS` 里没有 `gnd`、也没有 `24v`，于是 GND 缝合环、24 V 电源环被判成**信号环阻塞**。
规则原文写的是「Rails are reported and exempt from blocking：喂一排球从两条缝合轨并联取电是标准做法」，
所以这是判据没认出 rail，不是板子有罪。

修法：`GROUND_HINTS = ("gnd","ground","vss")` + `_RAIL_VOLT = \d+(?:[._-]?\d+)?v` + `_is_rail(name)`，
环路规则的 rail/signal 划分改用它（`_is_powerish` 保留给 detour 阈值，用途不同，不合并）。

读数：`1dc6` 信号环 **17 → 16**，另有 **9 个 rail 网 / 25 个环**被列出但不阻塞（`GND` 9 环、
`VDD33_MAGNETIC` 6、`VDD_LCD3V3` 3、`VSYS_3V3` 2、`VDD33_BSTRAP` 等）；`dcfea2db` 的 `24V` 环被豁免。

### 3.3 自曝：`dead_end` 的 blocking 用的是 items，不是计数

上一处修完之后 `99593ab6` 的 `dead_end` 报 **measured 0，blocking True**——有 0 个死端，
7 个「别网焊盘」条目排在 `items` 里，而 `_rule(RULES[4], dead_ends + dead_vias, bool(dead_items), …)`
拿 `bool(dead_items)` 当阻塞条件。**「列出来」和「算它」被同一行代码粘在了一起。**

修法：`blocking` 改成 `bool(dead_ends + dead_vias)`；`items` 保持完整（别网焊盘照样列）。
反向对照：`tests/test_shape_gate_deadend.py::test_a_foreign_pad_end_is_listed_but_does_not_block`
——一块「线端压在同网焊盘外的地方、但压在别网焊盘上」的板子，必须 `measured 0` + `blocking False`，
同时在 `items` 里能看到 `on_pad_of`。修后 `99593ab6` 的 blocking 只剩 `redundant_loop`。

## 4. 八关本身的两处口径：**测不出 ≠ 有罪**

### 4.1 `frame`：板框没闭合 ⇒ `n/a`，不是 `fail`

三块量产板的板框是**分段画**的、首尾不接。以前读成「到板边距离」= 0 ⇒ `fail`，
语料就打印「好板子多数不过 ⇒ 这条规则是错的」——**用一次缺失的测量给规则定罪**。
现在 `outline_closed == False` ⇒ `ok = None`（`n/a`）+ `measured["outline_note"]`，
note 写明「板框闭不闭合是 DRC 的入口，这一关只判铜到板边的距离」。

### 4.2 `floorplan`：没有板框 ⇒ 也必须是 `n/a`（这一版新修）

`plan_floorplan.analyse()` 对没有板框的板 `raise ValueError("board has no outline - cannot measure sides")`。
编排层把「抛异常」翻译成 `error`，而 `error` **会打断整条链**（后面每一关变成 `blocked`）。
于是三块量产板在语料里从「1 pass」变成 **3 个 `error`**：`5c71f32e`、`99593ab6`、`fadd8cdd`。

同一个事实（板边没连成闭环），上一关说「测不出」、这一关说「算不出来还打断别人」，口径自相矛盾。
修法：`gate_floorplan()` 先看 `board.outline`，为空则直接返回 `ok=None` 与
`这块板的板边没有连成闭环，没有四条边可量，「朝向错」这一问测不出（与 frame 同一类：板框闭不闭合是 DRC 的入口，不是这一关的判据）`。

两条反向对照（`tests/test_plan_sequence.py`）：
- `test_floorplan_without_an_outline_is_unmeasurable_not_an_error`：无板框 ⇒ `ok is None`、note 含「测不出」；
- `test_floorplan_still_measures_a_board_that_has_a_closed_outline`：有板框时**必须真的去调 `analyse()`**
  （用 monkeypatch 记调用），保证这条护栏不会把真读数一起吞掉。第二条是必需的——只写第一条，
  一个「永远返回 n/a」的实现也能过。

## 6. 没有粉饰的三件事

1. **`1dc6` 的 16 个信号环是真的。** 逐条的可删长度是
   `0.025 / 0.036 / 0.05 / 0.07 / 0.08 / 0.1 / 0.125 / 0.155 / 0.2 / 0.255 / 0.351 / 0.384 / 0.45 / 0.475 / 1.414 / 1.62` mm。
   最小的那些是 0.02–0.1 mm 的微桥（两个已经连通的点之间又画了一小段），`docs/166` 在 RK3506 上
   见过同型的「0.05 mm 台阶微段」。`99593ab6` 的 2 个环里 0.452 mm 那个**已单独核实是真冗余**
   （`$R12_2` 有两条几乎重合的段，去掉可省 0.452 mm）。
2. **`4/6` 块量产板 `shape_fail` 是一个待决的判据问题，不是读取问题。** 按 `judge_corpus` 的逻辑，
   一条 physical 规则在好板子上 `rate < 0.5` 就该判「规则错」。但 `redundant_loop` 是本项目的
   **house** 规则（用户原话：信号网闭环就是铜画了两遍），而且这里失败的全是 0.1 mm 量级的微桥，
   不是「绕一大圈」。**要不要给环路规则加一个可删长度下限，需要一个数—不是一句话**：
   加了等于宣布「0.1 mm 级冗余铜可以接受」，不加等于拒收 2/3 的量产板。本轮**不动**这个判据
   （方向上是「拒收」这一侧，安全），把分布列在这里，让下一步有数可依。**不拍阈值。**
3. **`route` 在立创板上是 4/6 fail，`house` 不算反证**——这条口径没变。真正值得记的是：
   `1dc6` 的 `detour_ratio` 14 个硬档里最差的是 `$$$16832` **10.01 倍**（67.47 mm 对 6.74 mm 的焊盘生成树），
   那是画板人自己绕的，说明这条规则在真实板上**确实能抓到东西**，不是自说自话。

## 6.5 顺手补的一条：60 个测试文件单独跑根本跑不起来

跑这一轮验证时发现的：`pytest tests/test_blockers.py` 直接报

```
E   ModuleNotFoundError: No module named 'pcb_agent_mcp'
!!! Interrupted: 1 error during collection !!!
```

原因不是这一版改坏的——包在 `src/`，而这批测试文件在模块顶层 `from pcb_agent_mcp import …`，
没有任何一行 `sys.path` 处理。它们一直**只因为**别处先执行了 `sys.path.insert` 的文件（pytest 按目录顺序导入）
才「能跑」。单独跑就崩，而**收藏失败（collection error）是最坏的一种绿**：文件里的用例一条都没跑，
`pytest tests` 打出来的数字和跑过了一模一样。

实测受影响的有 **60 个文件**（`test_blockers.py` 23 例、`test_board_ops_footprint.py` 19 例等）。
修法不是给 60 个文件各加三行（那只是把同一个补丁抄 60 遍），而是 `tests/conftest.py` 一处：

```python
_SRC = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "src")
if _SRC not in sys.path:
    sys.path.insert(0, _SRC)
```

`conftest.py` 由 pytest 在任何测试模块之前导入，一处覆盖全部。补上之后
`test_blockers.py` 23 passed、`test_board_ops_footprint.py` 19 passed、`test_tools_profile.py` +
`test_zone_pairing.py` + `test_step_apply.py` 32 passed（这三个此前单独跑都是收藏失败）。
