# 40. 受控源 F/H 与互感 K：三张卡的第三个 token 不是节点

到 `0.0.33`，内置求解器按名字拒绝的卡只剩 `J`、`S`、`W`、`A`——而这三张（`F`、`H`、`K`）在
`0.0.34` 之前也在那张名单里。它们被挑出来先做，理由很具体：**三者都是纯线性 stamp，可以对着
ngspice 逐位对账**，不需要新模型、不需要第二套表达式体系，也不会把"没做"藏进"没算"。

这一篇记的是四件只在实现时才暴露出来的事：F 的第三格是**名字**不是节点、H 必须有自己的行而 F 不必、
K 根本不是器件、以及"瞬态对不上 1.22%"到底该归给谁。

---

## 40.1 F/H 的第三个字段是一个元件名

SPICE 的两张受控源卡：

```
Fname n+ n- vname gain      ; CCCS: 电流源，i = gain * i(vname)，方向 n+ -> n-
Hname n+ n- vname gain      ; CCVS: 电压源，v = gain * i(vname)
```

`vname` 是"控制元件"的**名字**。它和 `E`/`G` 的四节点形式长得很像，于是最容易犯的错就是**按位置读**：

```
F1 2 0 V1 2      ; 正确：读 V1 的支路电流
F1 2 0 1 0 2     ; 按 E/G 读：把 1、0 当控制节点 —— 不是这张卡
```

按位置读的后果不是报错，是**解出一份看起来正常的答案**：控制项取了两个不存在的节点之间的电压
（0 V），于是 `F1 2 0 V1 2` 变成"一个 0 A 的电流源"，节点 2 读 0 V，整个 deck 依旧 `status: ok`。
这就是本仓库最不能接受的那类输出。所以解析器在这里做三件事：

- token 数必须是 5（`F` + 两个节点 + 名字 + 增益），少一个报 `needs two nodes, the NAME of the
  element …, and a gain`，多一个报 `has trailing …`；
- 名字里出现 `=` 或**能当数字读**（`_looks_numeric`）直接拒绝，并在消息里说清"控制元件是读它电流
  的那一个，所以必须写名字，不能写测量值"；
- 控制元件必须在 `branch_name` 里（`V`/`E`/`H`/`L`/`BV`），否则报 "has no branch current"——`R`、
  `C`、`D`、`F`、`G`、`I` 都没有可命名的支路未知量，硬读一个等于凭空发明一个数。

报告里因此多一个字段：`control_current_a`。调用方必须能看见**读到的是谁的多少电流**，否则"控制元件
写错"在答案里是完全隐形的（`current_a` 只是 `gain * control_current_a` 的结果）。

## 40.2 为什么 H 要一行，F 不要

MNA 里"电流源"是向 KCL 行搬移一项，"电压源"是自己占一个未知量。这两张卡正好落在两边：

| | 加什么 | 未知量 | 行内 stamp |
|---|---|---|---|
| `F` CCCS | 往**已有的**支路列上加 | 不加 | `A[a][ctrl] += g`、`A[b][ctrl] -= g` |
| `H` CCVS | 自己一行 + KCL 两项 | **加 1** | `A[row][a] += 1`、`A[row][b] -= 1`、`A[row][ctrl] -= g` |

测试里把这条写成可数的断言：`V1 1 0 1 / R1 / F1 2 0 V1 2 / R2` 的 `unknowns` 必须是 **3**
（2 节点 + V1 支路），而把 `F1` 换成 `H1` 必须是 **4**。这是那种"实现错了也能跑"的地方——
F 若偷偷分配一行，矩阵仍然可解，只是多了一个没人约束的未知量。

## 40.3 K 不是器件

```
Kname L1 L2 k        ; M = k * sqrt(L1 * L2)
```

它没有 `n+`/`n-`，不占未知量，也没有"自己的电流"。它是关于**两个已经存在的电感**的一句陈述：

- 解析产物 `nodes: ()`，`assemble` 的元素循环开头直接 `continue`（否则 `el["nodes"][0]` 会
  `IndexError`——这是本轮唯一一次真崩，见 40.5 第 1 条）；
- AC 在两条**已有的**电感支路行之间交叉加 `-jωM`；瞬态交叉加 `-M/h`，并在 RHS 补
  `-(M/h) * i_prev_other`（另一支路上一步的电流）；DC 什么也不加；
- 报告是一条 `type: "K"` 记录：`inductors`、`coupling`、`mutual_h`、以及一句
  "a K card is a statement about two inductors, not a device: it has no terminals and no current
  of its own"。**它没有 `voltage_v` 字段**，因为它没有端子可量。

所以 `unknowns` 对 `K` 是不动的：同一张 deck 加不加 `K1 L1 L2 0.5` 都是 6。DC 也一样——
`d/dt = 0` 时两个电感都是导线，互感没有可以作用的东西，这份 deck 在 0.5 V 工作点上逐位相同
（测试里刻意用 0.5 V 而不是 0 V，否则"没变"比较的是两个零）。

## 40.4 |k| > 1 是拒绝，不是钳位

`M² = k²·L1·L2`。`|k| > 1` 意味着互感大于产生它的两个磁通本身——物理上不存在。给一个钳到 1 的
数等于**把不可能的输入变成一个看起来正常的答案**，所以这里直接拒绝，并把范围写进消息：

```
K1: coupling coefficient 1.5 is outside [-1, 1]. |k| > 1 would put M^2 above L1*L2,
    i.e. a mutual flux larger than both of the fluxes that produce it
```

同一批拒绝里还有四条：引用的名字不是本 deck 的元件、引用的不是 `L` 卡（"coupling anything else is
not a smaller model, it is a different one"）、耦合到自己、电感 ≤ 0（`M = k·sqrt(L1·L2)` 要求两个
被开方数的积为正）。边界 `|k| = 1` 本身是**合法**的，测试里对 `1` 和 `-1` 都断言 `ok`。

## 40.5 子电路里的名字是实例局部的

一个 `.subckt` 体内写 `F1 o g Vi 2` 或 `K1 L1 L2 1`，`Vi`/`L1`/`L2` 指的是**体内**的那个。拍平时
必须给它们加实例前缀，否则会出现两种静默错误：

- 体内有、顶层没有 → 报 "no card in this deck defines"，`F`/`K` 白做；
- 体内有、顶层**也有同名的** → 静默耦合到顶层那个。这一种最坏：解出来了，数是错的。

`_instantiate` 因此新增 `body_names` + `scoped_ref()`，只对 `F`/`H` 的 `ctrl_name` 与 `K` 的
`l1`/`l2` 做前缀。测试给了三条能失败的对照：体内控制源（顶层无同名）读 2.000 V、顶层放一个
1 mH 的诱饵 `L1` 而体内 `L1` 是 100 uH（比例仍必须是 2.000，若是全局解析会变成 0.632）、以及同一
变压器子电路实例化两次（第二个实例被驱动侧为 0 时，其次级必须低于 1e-9）。

## 40.6 对账：为什么 AC 是 0.0 而瞬态是 1.22%

| 口径 | 结果 | 说法 |
|---|---|---|
| `F`/`H` 的 `.op` 对 ngspice-47 | `max_abs_diff_v = 0.0` | 线性 deck，两种独立实现给出同一位 |
| `F`/`H` 的 `.ac` 对 ngspice | `0.0` | 同上 |
| `K` 的 `.ac`（k = 1 / 0.5 / −0.5，含带载） | `0.0`（`compared_nodes` 3） | 交叉项 `-jωM` 逐位正确 |
| `K` 瞬态结构判据（k=1、L1=L2） | `max |v2-v1| = 0.0` | 两个等绕组就是同一个绕组 |
| `K` 瞬态结构判据（k=1 开路次级，L2/L1=4） | `v2/v1 = 1.9999999864 ~ 2.0000000098` | 变比 `sqrt(L2/L1)` |
| `K` 瞬态对 ngspice（正弦 20 kHz，插值比较） | 最差 **2.862e-03**（幅度 0.2342，**1.222%**） | 积分器差异，不是耦合项 |

最后一行必须**归因**而不是**修掉**：本内置求解器是**后向欧拉**，ngspice 默认用梯形法。同一张不含
`K` 卡的 deck 也会差同量级，所以这 1.22% 属于积分器，不属于互感模型。要证这一点，用的是前面五条
**精确**读数：如果交叉项写错（符号、`M` 与 `k` 混淆、漏掉 RHS 的 `i_prev`），那五条里至少有一条
会崩，而不会整齐地停在"积分器量级"。

另外两条数字是"物理正确但不直观"的，写在这里免得下次被当成 bug：

- k=1 的两个电感**并联在同一对节点上**在 DC 是奇异矩阵（`M²=L1·L2` 让 [L] 奇异），零阻抗是正确
  物理；测试 deck 一律串一个电阻，并且**不帶 K 卡的同一份 deck 报同一个错**，用它证明与 K 无关。
- k=1、两个 1 mH、次级 1 kΩ 的 200 µs 稳态是 `v ≈ 0、i1 ≈ 20 mA`（理想变压器把次级短路等效到
  初级，初级看到的是 0 Ω）——不是收敛失败。

## 40.7 仍然不做

- `J`（JFET）、`S`/`W`（开关）、`A`（XSPICE）继续按名字拒绝：它们各自需要一份**模型**（器件方程或
  第二套器件描述语言），不是一条 stamp。
- `K` 只有理想耦合：没有磁芯损耗、没有频变电感、没有饱和/磁滞，也没有绕组电阻（那是 `L` 之外的
  `R` 卡）。
- `F`/`H` 的增益是常数或 `.param` 表达式，不是表格/多项式（那需要 `POLY()`，属于"第二种表达式体系"）。
- `F`/`H` 的控制元件可以是 `V E H L BV`——这是 ngspice 的超集（它只收电压源名）。多收的部分在
  数学上良定义，报告里用 `_ctrl_resolved` 让调用方看得见控制的是谁；但**不要**指望 ngspice 能跑
  `F1 3 0 L1 2`（它报错退出），所以这一类 deck 不做双引擎对账。
