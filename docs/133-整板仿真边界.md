# 133 · 整板仿真的边界：从 .kicad_pcb 到一张可解的网表

上一版（0.0.141）解决的是"规则说不说得出话"。这一版解决另一个要求：

> 「那些仿真功能都要支持真实的整板仿真，不能只做简单的仿真。」

"简单仿真"在这里有很具体的含义：`sim_spice` 一直能解网表，但网表得**你手打**；
`thermal_plate`、`board_electrothermal`、`current_density_field` 都要**你给几何**。
也就是说，这些工具算的是"我给你的一块铜"，不是"这块板"。整板仿真缺的不是又一个
求解器，是**从板文件里把铜抽成电路这一步**。这一版补的就是这一步，并且用 12 块
KiCad 官方成品板当对照，把"这一步值不值得信"变成可复算的数字。

---

## 1. 链路：五段，每段都能单独核

```
.kicad_pcb
  └─(adapters/kicad_pcb)─→ 走线段 / 过孔 / 焊盘 / 铺铜 / 叠层
      └─(oracle.board_ir_drop(return_network=True))─→ 图：节点 + 边 + 所在的层 + 铜厚
          └─(sim/board.build)─→ R / L / C 元件 + 名字是 U1.1 的节点  → SPICE deck
              └─(sim/run.simulate)─→ 源、负载、分析卡片、接地 tie
                  └─(calc/spice.simulate)─→ builtin 或 ngspice 求解
```

三件**没有**发生的事，写在这里免得读者以为发生了：

- **没有第二个提取器**。R 不重写一遍：`build` 调的是 `board_ir_drop` 的图
  （新增 `return_network=True`，该参数下只出图、不求解）。两个提取器是让 "deck"
  和 "IR-drop 报告" 在同一块板上互相矛盾的**必然**办法。
- **没有自造铺铜**。铺铜在 `model_zones=true` 时才进网络，而且一直是
  `board_ir_drop` 的那条路径（官方 `ZONE_FILLER` 填出来的多边形）。
- **没有自动布线/自动布局**。这一版一行布线代码都没有加。

## 2. L 与 C 不是拍的：一条传输线，两半

每段铜按它和参考面构成的传输线算（`calc/feedline`）：得到 `z0_ohm` 与 `eps_eff` 后

```
L' = z0 * sqrt(ee) / c0        [H/mm]
C' = sqrt(ee) / (c0 * z0)      [F/mm]
```

于是 `L' * C' * 1e6 == ee / c0^2` 构造上成立——这就是测试
`test_the_transmission_line_identity`（places=9）。参考面取**返回网上最近的节点**，
不是网格化平面；平面自身的扩展电阻/电感不在里面，`value.not_modelled` 第 1 条说的
就是它（要电阻请用 `board_ir_drop(model_zones=true)`）。

## 3. 三个"看起来合理"的错答案，都是这次量出来的

这一节是本文档的核心。三个数字在各自的代码里都"跑通了"，也都错得很有说服力。

### 3.1 整板直流 0.000000 mV —— R 和 L 写成了并联

第一版把一段铜的 R 和 L 写在**同一对节点之间**。那是并联，而理想电感在直流上必赢：
整板 `.op` 读到 **0.000000 mV**，100 % 电流躺在 L 元件里。20 mm / 0.5 mm 的条带答案
应该是 **19.7029 mV**。

改法：R 与 L 是同一块铜，**串联**。插一个中间节点 `mid`，`R a mid` + `L mid b`，
该段的并联电容挂在 `tail = mid or a`。

### 3.2 中间节点只在真有一根 L 时才存在

串联修好之后还有第二个坑，它是 sweep 抓出来的：`include_lc=false`（或没有叠层、
没有参考面）时不写 L，但**R 已经写成了 `R a mid`**——于是每段铜的远端悬空。
两焊盘的网在"纯电阻 deck"里停在 mid 节点，求解器报"这段铜没连上"。

实测：`_island_board` 的 VCC 条带在 `include_lc=false` 下从 19.7029 mV 变成
`NOT_CONNECTED`。改法：**先决定 L，再写 R**；没有 L 时 R 直接跨 `a b`。

### 3.3 builtin 的电流源符号和 SPICE 相反 —— 同一张 deck 两个引擎差一个负号

`I1 1 0 1m` + `R1 1 0 10k`：builtin 给 **+10 V**，ngspice-47 给 **−10 V**。
根因是 `calc/spice.py` 里 I 源的 stamp 多了一个负号（`_current(b, na, nb, -value)`），
而 `_current` 本身是标准 SPICE 的写法。改掉 I 的两处（DC 与 AC），**不动
`_current` 本体**——电容的瞬态 companion 用的是同一个调用，两条引擎的 RC 瞬态本来
就一致（4.7507 vs 4.7511），动它会连带改对的东西。

顺带说明一件事：原来有一条测试在**防守错的符号**（期望 +10 V，注释自称
"the SPICE convention"）。错答案被测试锁住，比没有测试更坏；它已改成 −10 V，并加了
反向一档 `I1 0 1 1m → +10 V`。

### 3.4 浮空的网络"解出来了"

在纯电阻路径里给一个**没有铜**的焊盘接地：`Vgnd u4_1 0 0` 落在一个孤节点上，
其余网络和 0 之间只有一根电流源。这样的网络没有唯一解——但 ngspice 用 gmin 把它
解了出来，返回 `status: ok` 和 **1000.000000 mV**。这是最坏的一种：不是报错，是数字。

两道闸门：

1. **孤岛先量再剪**。一个网的焊盘不总是一块铜（只有铺铜才连起来的、根本没线到达的）。
   `build(keep_pads=[...])` 只保留**含被接线焊盘**的连通块，其余逐块记进
   `skipped`（`ISLAND_NOT_WIRED` / `PAD_WITHOUT_COPPER` / `FLOATING_NET`）和 `islands`。
2. **解之前查连通**。把 deck 里的 R / L / V 元件做并查集（电容在直流上是开路、
   电流源不定电位，都不算通路），**每个节点必须和 0 V tie 同根**，否则
   `NOT_CONNECTED` 并列出是哪几个焊盘在漂。

## 4. "singular at column 181" 不是关于板子的话

在 12 块成品板上跑 `board_ir_drop`，第一轮**几乎每块**都返回：

```
NOT_APPLICABLE  singular at 181 (a node with no conductive path to ground?)
```

这句话是关于**矩阵**的，不是关于**板子**的：它既没说哪个焊盘，也没说原因是"布局有孤岛"
还是"模型缺了铺铜"。真因是同一个网上的焊盘分布在几个互不连通的铜块上（成品板上很常见：
只有铺铜才连起来的、焊盘没线到达的）。

修法：稠密路径也做铺铜路径一直在做的那件事——**先从源点可达集合里剪，再解**。
被剪掉的节点数写进 `warnings`，落在外面的 sink 直接点名：

```
NOT_CONNECTED  sink(s) U3.1 are not connected to U1.1 on net 'VCC' by any track
hint: 要么布局真有孤岛，要么连它们的是铺铜：model_zones=true 把铺铜放进网络
```

## 6. 这款仿真不做什么（`value.not_modelled`，逐条）

拿答案之前先读这一栏，它比我写的任何一句话都准：

1. **参考面本身不是一个网络**。每段铜的并联电容挂在返回网最近的节点上，平面的扩展
   电阻与电感不在里面（要电阻：`board_ir_drop(model_zones=true)`）。
2. **相邻走线之间的互感**。段电感是传输线的自值，已经含了它自己回流的镜像。
3. **拐角的额外电容**。两段各算一次，共用一个节点。
4. **焊盘电容、连接器接触电阻、全部元件**。deck 是**板**：电容、芯片、源都是你的。
5. **铜温升反哺 rho(T)**。rho 按 `temp_c` 取常数。
6. **被仿真网上的铺铜不当导体**（除非 `model_zones=true`）。所以"整板回流走平面"
   目前不成立，必须走 `model_zones=true` 才会进网络。

还有两件登记但**没做**的事，不算在这六条里：

- `board_electrothermal` 仍吃"宽×高×k"的几何，不吃板文件；`board_sim` 也还不输出
  每元件功耗，所以"板文件 → 热图"这条链没闭。
- 有铺铜才有回流的网，在 `model_zones=false` 下会被判 `ISLAND_NOT_WIRED`——这不是
  布局问题，是模型的边界，hint 里直接写了 `model_zones=true`。
