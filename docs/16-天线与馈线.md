# 16 天线与馈线：从「先切一版打出来」到「知道自己在猜什么」

> 前十五篇解决的是「把板子读成事实、把改动写成提案」。这一篇是第一个**纯设计**能力：
> 给定频率、基材、可用尺寸，先算出第一个能打样的几何，并说清楚**哪几个数不能信**。

## 0 边界：这里没有全波求解器

先把最容易误解的一句话放在最前面：

**本仓库不含任何全波电磁求解器，也不会假装有一个。**

能给的：用闭式模型（Balanis / Hammerstad / Chu-Harrington / Kraus / Friis）算出的
**第一个原型几何 + 一阶阻抗/带宽 + 硬性上限**；不能给的：方向图、外壳/手持失谐、
互耦、SAR、效率的最终值。这些不是"精度不够"，而是**模型类别不同**——闭式模型里根本没有
相位与电流分布这两个自由度，任何声称能给出方向图的闭式公式都是错的。

所以每个天线类工具的返回里都硬带 `not_computed` 列表。`antenna_patch` 的实测返回：

```
"not_computed": [
  "radiation pattern / directivity shape (needs full-wave)",
  "radiation efficiency and gain on a real substrate with a real ground plane",
  "detuning by the enclosure, the hand, the battery or nearby metal",
  "mutual coupling between two antennas on the same board",
  "SAR and the human-body interaction",
  "impedance bandwidth after matching, beyond the physical ceiling below"
]
```

## 1 馈线：先把 50 Ω 做对

`calc/feedline.py` — 4 种走线：微带、带状线、CPW、GCPW。

| 函数 | 作用 |
|---|---|
| `feedline_impedance(kind, width_mm, dielectric_mm, gap_mm, copper_um, er, freq_ghz, tan_delta, verify_field, field_levels)` | 给定几何算 Z0 |
| `feedline_width(target_ohm, kind, dielectric_mm, gap_mm, copper_um, er, tol_ohm)` | 给定 Z0 反解宽度（目标不可达时 `OUT_OF_RANGE` + `reachable_ohm`） |

**微带**用 Hammerstad 闭式，w/h≤1 与 w/h>1 两段都带 `/√εeff`；铜厚按 IPC-2141A 的 `1.25t`
折算成等效展宽（与 `calc/impedance.py` 同一约定）。

**带状线**：`Z0 = 60/√er · ln(4b/(0.67π(0.8w+t)))`，均匀介质所以 εeff ≡ er。

**CPW/GCPW 是从电容推的，不是背公式**——因为模数 k 的顺序记不准，而电容法可以被两个极限检验：

```
a = w/2,  b = w/2 + gap,  k0 = a/b
无背地: k1 = sinh(πa/2h) / sinh(πb/2h)
有背地: k2 = tanh(πa/2h) / tanh(πb/2h)
Z0 = ETA0 / sqrt(c_air * c)        ← 不是 1/(c·C)
εeff = c / c_air
```

这条 `ETA0/sqrt(c_air·c)` 不是推导出来的结论，而是**被极限测试当场纠正过的**：写成 `1/(c·C)`
时结果差一个 √εeff，而 h→∞ 的解析极限立刻暴露了它。留下这个极限测试当回归。

金标（`tests/test_feedline.py`，18 项）：

| 调用 | 结果 |
|---|---|
| `feedline_width(50,'microstrip',1.6,er=4.3)` | **3.136746 mm** |
| `feedline_impedance('microstrip',3.0,1.6,er=4.3)` | **51.351 Ω**，εeff 3.25655 |
| `stripline(0.4,0.4,er=4.3)` | **48.433 Ω**，εeff 4.3 |
| `cpw(1.8745,1.6,gap=0.2,er=4.3)` | **50.0 Ω**，εeff 2.5263 |
| `gcpw` 同几何 | 44.094 Ω，εeff 2.77498（有背地 ⇒ 更低） |
| `cpw(1.0,h=1e6,gap=0.5,er=4.3)` | **74.013 Ω**，εeff 2.65（h→∞ 解析极限） |
| `cpw er=1` | 120.484 Ω，且与 h 无关 |
| `feedline_width(200,'microstrip',0.2)` | `OUT_OF_RANGE`，`reachable_ohm = {最宽 4.0→8.089, 最窄 0.01→181.47}` |

**CPW 不建模铜厚**，并明说"requested X µm but NOT modelled"——而不是套一个可能大 2 倍的
Gupta 修正。导体损耗对 CPW 返回 `null` + 原因（需要边缘电流分布），只给介质损耗并标 `lower bound`。

**`verify_field=True`** 会额外跑二维有限体积静电场（`calc/field2d.py`）交叉验证。注意直接
掉的坑：`field2d` 的网格是 `fine = min(w,h,t)/fine_div`，若把铜厚传进去网格会爆炸（0.3 s → 数分钟），
所以这条交叉验证一律按 **t=0** 求。

## 2 印刷天线：把长度给成区间

`printed_wire(freq_ghz, er, height_mm, shape="ifa"|"meander"|... , target_rin=50, bbox_mm, wire_width_mm=0.2)`

薄导体印刷线的 εeff 落在 `1` 与 `(er+1)/2` 之间，**没有一个可信的闭式**。所以这里不给单值，
给区间 + 明确的起点建议：

```
total_length_mm = { max_all_air: 30.591, min_half_dielectric: 18.617 }   # 2.45 GHz / FR4 / 1.6 mm
suggested_start_mm = 30.591
suggested_start_why = "薄膜基材(<=2mm)上的经验值靠自由空间四分之一波长，
                       只有厚基材才用几何中点"
```

IFA 还返回馈电抽头位置 `tap_for_target_mm = 10.641`，附 `tap_table`（6 行 offset↔Rin，
从 0.612 mm/36.5 Ω 到 15.296 mm/73.0 Ω），并明确 `tap_note`：真实印刷振子通常比这个**更短**
就能匹配，从短端往长端试。

**蛇形（meander）**是这一轮唯一被重写过的实现。原版把打包方向算错了（`turns=int((bl+gap)/(bw+gap))`，
等于按长度方向数折），而且**没有"装不装得下"的判定**——一个把长度印出来的工具，如果不管
装不下，就等于在骗人。现在的口径：

```
gap   = 0.5 mm                                     # 蛇形相邻线的间距(固定假设)
pitch = wire_width + gap                           # 2.45 GHz 例: 0.2 + 0.5 = 0.7 mm
turns = max(1, int((bw + gap) // pitch))           # 沿宽度方向折
wire  = turns*bl + max(0, turns-1)*bw
```

返回 `wire_length_mm=328.0` / `wire_needed_mm={30.591..18.617}` / `fits=true` /
`fits_without_meandering=false` / `fits_against`（对哪个边判的，写明是较长的自由空间端）/
`trace_width_assumed_mm`。20×8 mm 的框在 2.45 GHz 下折 12 折、展开 328 mm，远超需要的 30.6 mm——
这就是为什么 `note` 里必须提醒：**能装下不代表装得好**，折叠会让相邻电流反向抵消，
`bandwidth_ceiling` 那一档才是该看的数（该例 `ka=0.513`、`Q_min=9.334`、
`max_bandwidth_vswr_lt_2 = 7.58%`）。

## 3 结构天线

| 工具 | 模型 | 金标（2.45 GHz） |
|---|---|---|
| `dipole_monopole(freq, kind, length_mm, wire_radius_mm)` | 细线端效应 `0.475λ0` | 偶极 λ0 122.364 → 长 **58.123 mm**、**73.1 Ω**、2.15 dBi、馈电缝隙 0.612；单极 → 29.062 mm / 36.5 Ω |
| `helix_axial(freq, turns, diameter_mm, turn_spacing_mm / pitch_deg)` | Kraus | 6 匝 40 mm 径 30 mm 距 → C/λ **1.027**、pitch **13.43°**、轴长 180、**13.71 dBic**、HPBW 41.7°、Zin 143.8 |
| `small_loop(freq, area_mm2 / diameter_mm, turns)` | 均匀电流小环 | 3.5 mm 径 3 匝 → C/λ 0.0899、`r_rad = 0.115939 Ω`（`r_rad_mohm = 115.939`） |
| `q_limit(freq, size_mm, vswr, dimension)` | Chu/Harrington | 2.4 GHz / 10 mm → r 5、ka 0.2515、**Q_min 66.837**、1.058% / 25.39 MHz |

**小环的 `r_rad` 用 6 位有效数字输出，另给 `r_rad_mohm`。** 原来是 `round(...,5)`，把
2e-7 Ω 舍成 `0.0`，读者会以为"不辐射"——而真实结论恰恰相反：小环的效率问题是**损耗**问题，
不是辐射问题（这一点写在 `r_rad` 旁边的 `notes` 里，而不是靠读者自己算）。

**螺旋与小环越界即拒绝。** 这两个公式在有效性边界外不是退化，是**无界错**。所以
`small_loop(diameter_mm=10)` 在 2.45 GHz 直接 `OUT_OF_VALIDITY`：

```
message: "circumference is 0.257 lambda0: the uniform-current small-loop formula only holds below 0.1 lambda0"
hint:     "a loop between 0.1 and 1 lambda is a resonant loop: R_rad is 50-200 ohm and depends on
           the shape and the feed position. That needs a full-wave solver, and this tool will not guess it"
r_rad_if_formula_were_used_ohm: 0.858452      ← 把"如果硬套会得到什么"也摆出来
```

## 4 陶瓷 / 芯片天线：只算净空与清单，不算它自己

`chip_antenna(freq_ghz, max_gain_dbi, keepout_x_mm, keepout_y_mm)`

芯片天线的增益和匹配元件是**厂商实测数据**，任何闭式都不会对。所以这个工具只做三件事：

1. 给净空参考尺寸与 `near_field_boundary_mm`（2.45 GHz → 19.475 mm）；
2. 给一张"必须自己核"的 `checklist`（净空矩形含底层地、地平面边缘属于天线、匹配网络依赖
   具体布局、datasheet 的 gain 是参考板上的 peak gain）；
3. 净空偏小时在**顶层**给 `warnings`（同时镜像进 `keepout.warnings`）：小于 λ/20 一条，
   小于近场边界一半一条。

`not_computed` 明写：增益/效率、匹配元件值、外壳失谐。

## 5 微带贴片

`patch_rectangular(freq_ghz, er, height_mm, copper_um=35, tan_delta, target_rin=50, ground_margin_h)`

Balanis 传输线模型：

```
W   = λ0/2 · sqrt(2/(er+1))
dL  = 0.412h(εeff+0.3)(W/h+0.264) / ((εeff-0.258)(W/h+0.8))
L   = λ0/(2√εeff) - 2dL
Rin(edge) = 90·er²/(er-1)·(L/W)²
1/Q = 1/Q_rad + 1/Q_c + 1/Q_d,     BW = (S-1)/(Q√S)
```

金标（2.45 GHz / er 4.4 / 1.6 mm / tanδ 0.02）：**W 37.234 × L 28.808**、εeff 4.0811、
dL **0.7386**、λg 60.5709、Rin(edge) **306.77 Ω**、内缩馈电 **10.593 mm**、
Q = {rad 38.62, conductor 1198386.5, dielectric 50, **total 21.79**}、
效率 **0.564**、BW(VSWR<2) **3.24% / 79.5 MHz**、BW(<1.5) 1.87% / 45.9 MHz、
地边距 **9.6 mm**（= 6h）。

不带 `tan_delta` 时 Q 只算辐射与导体（total 38.62）、带宽 1.83%——**这就是"给不给 tanδ 差两倍带宽"**，
所以 `precision` 里写明"efficiency needs tan_delta"。内缩模型不含开槽宽度（那是另一个匹配变量），
这点也在 `inset_note` 里写清。

## 6 匹配网络：每个解都回代重算

`calc/matching.py`：`reflection` / `l_match` / `pi_match` / `t_match` / `single_stub` / `quarter_wave`。

**纪律：每个解都必须回代到 Zin 并报 `residual_vswr`，不许只给元件值。** 这条纪律抓到了一个真缺陷：
`l_match` 的 series-first 分支原来写 `b = -xtot/den`（应为 `+xtot/den`），症状是 25 Ω 纯阻负载
被"匹配"成 10+j20、残差 VSWR 0.707——只报元件值的话它会安静地输出一组错数（0.66 pF + 3.32 nH）。
修好后 5 / 25 / 25-30j / 49 / 50 / 100 / 150-60j / 200+100j 全部残差 ≤ 4e-5。

阻抗入参接受字符串：`"100+25j"` / `"-j30"` / `"j30"` / `"100j"` / `"50"`。纯电抗（R≤0）直接
`ARG_RANGE`（"non-positive resistance"），不猜。

金标：

| 调用 | 结果 |
|---|---|
| `reflection(100)` | γ 1/3、VSWR 2.0、RL 9.542 dB、失配 0.5116 dB |
| `reflection("100+25j",2.4)` | VSWR **2.1626**、RL 8.692 dB、反射 13.514%、串 L 1.658 nH |
| `l_match(100+0j,2.4)` | shunt C **0.6631 pF** + series L **3.3157 nH**，Q=1，残差 0 |
| `single_stub(100+0j,2.4,open)` | **d 43.4645 mm / l 12.2361 mm**（0.348λ / 0.098λ），第二解 d 18.9923 / l 50.2207 |
| `quarter_wave(100,2.4)` | **70.7107 Ω / 31.2284 mm** |
| `pi_match(50,200,2.4,q=3)` | Rv 11.09123、2.4841 pF / 4.4131 nH / 1.3684 pF |
| `t_match(...)` | 键 `series_source_side` / `shunt` / `series_load_side` |

短截线两解按距离配对：`l = 43.4645 @ d 43.46`、`l = 18.9923 @ d 18.99`——**不能把 d 和 l 交叉配**，
那是另一个完全不同的网络。这个配对逻辑在测试里有专门断言。

## 7 链路预算与远场距离

`calc/link.py`：`fspl_db` / `friis` / `max_range` / `aperture` / `far_field` / `fresnel_radius`。

**这里有个 60 dB 的坑**：`K = 20log10(4π/c)+120 = -27.5522`。写成 `+180` 就整体差 60 dB，
射程差 1000 倍，而数值看上去仍然"像个自由空间损耗"。金标：

| 调用 | 结果 |
|---|---|
| `fspl_db(2400,1)` | **40.052 dB** |
| `fspl_db(2400,10)` | 60.052 dB |
| `friis(0,2400,10,2,2)` | **-56.052 dBm**、EIRP 2.0、ERP -0.15 |
| `max_range(0,2400,-95)` | **558.984 m**（0 dB 额外损耗） |
| 同上 + `other_loss_db=4` | **352.695 m** |
| `aperture(2,2400)` | 1967.93 mm² |
| `far_field(30,2400)` | fraunhofer 14.41 / reactive 19.881 → 取 150（`5*D`） |
| `far_field(2,...)` | **`λ/(2π)`**（电小天线，reactive 边界主导） |
| `far_field(400,...)` | **`2D²/λ`**（Fraunhofer 主导） |
| `fresnel_radius(2400,500,500)` | **5.5882 m**，60% 净空 3.3529 m |

远场判据是"三者取最大"：`max(2D²/λ, 5D, λ/2π)`。三段都要测——只测一段会把"哪个机制在主导"
这件事漏掉，而这正是设计天线间距时唯一要回答的问题。

## 8 板级净空：把 zone 单独列出来

`board_antenna_keepout(board, x_mm, y_mm, width_mm, length_mm, layer, margin_mm, top)` —
走 `_board_tool(derived=True)`，因此自动带 `answer_source` / `authoritative:false` /
`verdict_available_from`。

**为什么必须自己算而不是信 DRC**：天线净空违规在 DRC 里通常只报成"间距"，而真正杀死天线的是
**铺铜**——地平面延伸到天线下面把谐振频率拉低，DRC 完全无视。

实跑（`stickhub.kicad_pcb`）：

- `(20,20,10,8)` → `clear:true`（在板外）
- `(150,-100,8,6)` → **406 项铜 + 2 个 zone**（pad 39 / track 353 / via 14；zone0 F.Cu GND、
  zone2 B.Cu GND），`layer='F.Cu'` 时 193 项

返回里 **pad/track/via 与 zone 分开计数**：pad/track 列表看不到铺铜，而铺铜才是失谐元凶。
`precision` 明说这是保守判据（bbox 相交即报，不做形状裁剪）。

## 9 拒绝路径清单

| 情形 | 行为 |
|---|---|
| CPW/GCPW 传了 `copper_um` | 接受但明说 **not modelled** |
| CPW 导体损耗 | `null` + 原因（需边缘电流分布），介质损耗标 `lower bound` |
| `feedline_width` 目标不可达 | `OUT_OF_RANGE` + `reachable_ohm` 两端实测值 |

| 芯片天线小净空 | 顶层 `warnings`（λ/20、近场边界一半两条阈值） |

## 11 这一轮被真答案抓出来的两个缺陷

1. **L-match 符号错**（`b = -xtot/den` → `+xtot/den`）：靠"每个解回代重算残差"发现，
   否则会安静输出一组 0.66 pF + 3.32 nH 的错答案。
2. **蛇形打包方向与 fits 判定**：原实现按长度方向数折、且不判装不装得下，
   输出一个"看着合理"的展开长度。重写为按宽度方向打包 + `fits` / `fits_without_meandering`。

两个都属于同一类错误：**数值算得出来，但语义错了**。所以这一层的验收标准是"能不能被世界上
已知的数检验"（3.14 mm 微带、37×29 mm 贴片、40.05 dB FSPL、回代 50 Ω），而不是"代码自洽"。

## 12 交接给全波

当下面任一条成立时，该换求解器（HFSS / CST / openEMS / nec2），本仓库不做：

- 需要方向图、增益、交叉极化；
- 需要外壳 / 手持 / 电池 / 邻近金属引起的失谐；
- 同一块板上两个以上天线的互耦、隔离度、ECC；
- SAR、HAC、人体贴近；
- 需要"优化到某个 S11 门限"而不是"切一版打样"。

工具给出的几何是**求解器的良好初值**，不是最终答案。
