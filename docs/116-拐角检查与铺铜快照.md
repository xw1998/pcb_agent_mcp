# 116 · 角度第一次成为被检查的量；以及「铺铜是快照」这个把 DRC 变成谎言的坑

日期：2026-11-04　版本：0.0.116

## 0. 两句话

1. 这个服务器此前只量**距离**（clearance / edge / annular ring），**从不问角度**，
   所以一块 123 个 90° 直角、0 个 45° 的板子「全项通过」。新增 `board_45_corners` 把角度变成读数。
2. `board_drc` 此前**不重铺铜**就在判定，而 `filled_polygon` 只是**填铜那一刻的快照**。
   同一份 231 段走线的字节：不重铺 502 条违规，重铺后 52 条。**不重铺的 DRC 不是更严格，是错的。**

## 1. 现场：为什么一块板能被画成「自动布线都不如」

用户的判词（逐字）：

> 「你看看人家画的，你画的什么狗屎？这个mcp缺少什么让你不能画成这样？为什么直角走线，
> 你但凡学一点布线规则进mcp也知道不能画直角线」

把参考图和自己的板子放在一起看，差的东西数得出来：参考图全部 45°/圆弧转角、USB 差分对走圆弧、
顶层红色铺铜 + 底层完整地平面、大量接地缝合过孔、晶振/USB/按键/安装孔局部 keepout、
中心 QFN 向两侧排针 45° 扇出、电源线明显加宽。

而本服务器当时的**全部**几何判据是：

| 判据 | 量的是什么 |
|---|---|
| `board_clearance` | 铜与铜的距离 |
| `board_edge_clearance` | 铜到板边 |
| `board_annular_ring` | 孔环宽度 |
| `board_routability` | 焊盘能不能出去 |
| `board_pour_connectivity` | 焊盘有没有埋进铺铜 |

**一条都没有在问「这根线拐了多少度」**。于是 123 个直角是「合规」的。这不是审美问题，
是判据缺口：板子上有一整类缺陷，工具结构上不可能看见。

## 2. 新增 `board_45_corners`

### 2.1 读什么

```
segments / arcs_skipped / zero_length
off45_segments / off45_worst_deg / off45_median_deg      # 段方向偏离 45° 网格
corners / corner_kinds{right,miter45,straight,other,acute}
right_angle_corners / acute_corners / junctions
right_angle_shortlist[20] / junction_shortlist[10]
```

**角的定义**：恰好两条**同网同层**线段共享一个端点。从顶点看两腿的夹角：
180° 共线（straight）／135° 已 45°（miter45）／90° 直角（right）／<90° 锐角（acute）。

**≥3 条线交于一点 = junction，只报不动。** T 型没有「一个角」，选哪条当主干是人的决定，
工具不替人猜。这是刻意的沉默，不是漏做。

### 2.2 写什么（chamfer）

保持拓扑的对称斜切：顶点替换为沿两腿各退 `cut` 的两点 + 一条对角。
两腿垂直 ⇒ 对角恰好 45°；两边退同样长度 ⇒ 对称。

**五种拒绝，见到就当结论读**：

| reason | 含义 |
|---|---|
| `vertex_on_pad` | 顶点在焊盘上。切 = 从焊盘里拔铜 = 断路 |
| `vertex_on_via` | 同上，过孔 |
| `leg_too_short` | 腿不够长（会吃掉 `min_leg_mm` 保留量） |
| `leg_reserved` | 同一段的两端都要切，会互穿；按短腿优先贪心分配后让位 |
| `would_collide` | 对角会撞邻网，附 `with` / `with_net` / `gap_mm` |

另有 `width_mismatch`（两腿线宽不同，按较宽切）。

### 2.3 实测（F412 核心板 v36，先重铺再倒角）

| | segments | right | miter45 | acute |
|---|---|---|---|---|
| before | 231 | 123 | 3 | 0 |
| after | 312 | 42 | 165 | 0 |

`chamfered 81 / skipped {would_collide:28, vertex_on_via:6, vertex_on_pad:5, leg_too_short:2, leg_reserved:1}`。

DRC（重铺口径）：**52 → 52，一条不增**；unconnected 45 → 44。

**这行数字本身就是结论**：123 个直角只有 81 个切得动。**45° 必须在布线的当下走出来**，
倒角是验收工具，不是补救工具。想靠后处理把曼哈顿布出来的板子救回参考图那样，救不回来。

## 3. 「铺铜是快照」：一条把闸门变成噪声的机制

`filled_polygon` 是把铺铜结果**烘成多边形顶点**存进文件的。这个快照只对「填的那一刻板上的铜」成立。
填之后画的每一根线、每一个过孔，**都没有从多边形里被挖掉**。

于是：

- DRC 把每根新线判成 **「走线 → 填充区，要求 0.25 mm，实际 0.0000 mm」**；
- 一次真实只新增 3 条违规的编辑，写闸门报 **169~178 条新违规**并回滚 ⇒ 编辑永远写不进去；
- 反过来，习惯性 `allow_new_violations=true` 硬写，会把**真短路**当合格。

实测（同一份字节，kicad-cli 10.0.7，两片 GND 区 F.Cu 优先级 1 / B.Cu 优先级 0）：

| 检查方式 | violations | clearance |
|---|---|---|
| 不重铺 | **502** | **324** |
| `--refill-zones`（scratch 副本，内存里填） | **52** | **0** |

那 324 条 clearance **一条都不在走线之间**。

### 3.1 改了什么

| 位置 | 改动 | 是否改变读数 |
|---|---|---|
| `fidelity.engine.drc(refill=False)` | 新增参数，True 时加 `--refill-zones`（**不加 `--save-board`**，不写你的文件） | 否（默认 False） |
| `board_drc` | `refill_zones` 参数，**默认 true**；回包带 `zones_refilled_for_check` / `zone_refill_note` | **是**（且更正确） |
| `edit.plan` 写闸门 | before / after 两侧都 `refill=True`，`gates.drc.zones_refilled_for_check = true` | 是（去幻觉） |

**为什么这不是放水**：重铺只会去掉幻觉。两根线太近，重铺后还是太近。
反过来，重铺不能让任何真实违规消失——它只是让「走线对铺铜 0 mm」这种**观察不到的信息**变成观察得到的。

### 4.1 关于「直角到底有多坏」的口径（必须诚实）

- 10 GHz 下 90° 与 45° 的插损差 **0.15–0.28 dB**，与板材批次波动同量级 ⇒ **不要把直角说成 SI 灾难**。
- 真正的收益是铜箔拐角应力：微切片显示 45° 比 90° 的拐角塑性变形低约 **37%**（CTE 失配开裂）。
- **锐角（<90°）是真缺陷**：蚀刻液滞留微区（酸角），过蚀/残留药水，是良率问题。
- 来源：捷配 `design/9465`、`design/15135`；电子发烧友专题；IPC-2221B。

## 5. 已知边界

- `chamfer` 不产生新层、不改走线方向、不做弧线；圆弧仍要人给坐标。
- `junctions > 0` 不处理。
- 倒角后 `off45_segments` 仍是 7 —— 那是**段方向**（斜线本身），不是拐角，与倒角无关。
- 剩下 44 个 unconnected 是真活（QSPI 六条 / 西侧四条 / VBUS / 两片电源区与缝合孔），未做。
