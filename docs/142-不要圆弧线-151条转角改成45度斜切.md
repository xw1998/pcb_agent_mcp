# 142 · 不要圆弧线：151 条转角改成 45° 斜切

用户一句话：「不要用圆弧线」。板上 151 条铜层圆弧全部换成直线，**换完 DRC 不能变差**。
这条要求的难点不在「删弧加弦」，而在**弦比弧更靠外**，一换就把弯内/弯外的过孔、焊盘撞上。

## 1 先量清楚：151 条弧是什么

`_de_arc.py` 只读统计（板 = `examples/sky_star/sky_star_routed.kicad_pcb`）：

| 量 | 读数 |
| --- | --- |
| 铜层 arc 条数 | **151**（全部 `w=0.15`，无一例外） |
| 几何形态 | **151/151 都是 90° 拐角的圆角**，R ≤ 1.2，拱高最大 0.351 mm |
| 弦长 | 0.312 … 1.697 mm |
| 弦的方向 | **151/151 精确 45°** |

最后一行是整件事的支点：90° 圆角的弦恒为 45° 斜切 ⇒ **删弧、加弦，一次就在 45° 规则内**，
不用另造几何。端点不动、网不变，只换中间那一段。

## 2 第一次翻车：y 符号把 151 条弦整段镜像

`add_track` 的 `y` 参数吃的是**文件坐标（负数）**，等价于 `-y_up`（与 `_rowup.py` 的 `gf.r(-a[1])` 同源）。
第一次写成 `y1=gf.r(-p0[1])`（`p0[1]` 本身已是负值）⇒ 变成正的 `y_up`，151 条弦全被镜像到 y 另一侧。

结果：**未连接 54 → 337**。回滚到 `_pre_noarc.kicad_pcb`，改成 `gf.r(p0[1])` 重跑 ⇒ `arc=0 / segment=928 / 未连接 54`，与换弧前完全一致。

第二条坑：`propose` 的房规门槛默认 0.20，而板级规则是 0.15。
紧弦必然被 `BLOCKED`（实测报 0.1874 mm），必须显式 `precheck_clearance_mm=0.15` 才不会被自己的房规挡住。

## 3 弦换上了，DRC 从 188 涨到 197

弦替换本身连接完好（54 未连接不变），但 DRC **188 → 197**，净 +16 / −7。
真·弦引起的新违规 9 条，量级 0.0303–0.1455（板规 0.15）：

| 违规对 | 实际间距 |
| --- | --- |
| `$1N4750` 弦 × 过孔 `$1N4748` | 0.096 |
| `PC5` 弦 × 过孔 `PC4` | 0.1455 |
| `PA2` 弦 × 过孔 `PA1` | 0.1455 |
| `OSC_OUT` 弦 × `X1.2(GND)` | 0.1033 |
| `$1I8749/$2N1176` 弦 × 过孔 `$2N1173` | 0.0536 |
| `$1N4905` 弦 × P1 焊盘 10 | 0.0303（原为 shorting） |

机制只有一句：**45° 弦比圆弧更靠外**。设拐角尖点为 Q、圆角半径 R，则

- 弧最靠外的一点离 Q 只有 `(√2−1)R = 0.414R`
- 弦整条落在离 Q `R/√2 = 0.707R` 的直线上

⇒ 弦吃掉了弧没占过的那一圈外沿，撞到的正是原本「弧刚好绕过」的过孔与焊盘。

## 4 修法：只能改腿长，不能改弦

弦是唯一几何（45° + 两个切点），所以自由度只剩一个：**斜切的两条腿有多长**。
把腿从 `L = R` 缩短，斜切就沿 45° 方向朝拐角尖点方向平移，离开外侧那些障碍。

写进 `_corner.py` 的两条判据：

1. **腿只会变短，不会变长**（`A` 落在 `f1` 与 `p1` 之间、`B` 落在 `f2` 与 `p2` 之间）⇒ 新腿是旧腿的点集**子集** ⇒ 腿的最小余量只可能变大 ⇒ **只需要判斜切自身**。这条把搜索空间从 3 段缩到 1 段。
2. 同一次搜索里也允许 `L > R`（腿变长、斜切外移），但那时必须把两条腿一起纳入评分（`min(斜切, 腿)`），因为腿不再是子集。

实测收益（`_corner.py` 只读报告 → `--write`）：14 条紧弦里 **9 条可重建**，
余量从 0.030–0.150 抬到 **0.178–0.372**，8 条落地（`$1N4891` F.Cu 一条最好只有 −0.740，被 0.155 闸门拦下）。

## 5 一个把 174 条弦读成 0 的 Python 坑

`corners()` 起初恒返回 0，而独立统计明明有 245 条双端唯一邻居的弦。根因是一行：

```python
for key, pt in ((round(p1[0],4), round(p1[1],4)), (round(p2[0],4), round(p2[1],4))):
```

本意是「每个端点的 (x,y) 元组」，实际 Python 把**每个二元组拆成 `key=x`、`pt=y`**。
于是 `key` 是个 float，`by_end.get(key)` 恒空 ⇒ 每条弦都在第一步被判「没有唯一邻居」。
改成 `for pt in (p1, p2): key = (round(pt[0],4), round(pt[1],4))` 后立刻找到 174 条转角。

## 6 两处收尾（`_oscfix.py`，9 op）

- **`$1I8749/OSC_IN` 悬空**：2.8 mm 横段停在 `(148.9, 92.625)`，原作只有旧弧的铜能碰上它。
  改成 `(146.1,92.625) → (148.625,92.625)` 加一段 45° 上抬到弧端 `(148.9,92.9)`。
  **不许**补 0.275 mm 竖段——那是 90° 转。
- **`$1I8749/OSC_OUT` 0.1033**：把斜切腿从 `L=0.423` 缩到 `0.30`（弦 `(145.423,93.5)-(145.0,93.923)` → `(145.30,93.5)-(145.0,93.80)`），
  下方 0.101 mm 竖桩顺势长到 0.224 mm；横段同步收口到 `x=145.30`。
