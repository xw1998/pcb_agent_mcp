# 138 · 全量回归从 48 红到 0：抱出来的六件事，其中一件会写坏它读的板子

`0.0.146` 之后跑了一次全量回归（`pytest -n 6`，4108 passed / 48 failed），再跑就是
`4165 passed, 9 skipped, 53 subtests passed in 644.20s`。48 个红不是「本来就红所以不算」：
其中 12 个是永远红的棘轮（红数字等于没有守卫），19 个在断言一个**已经被明令退役**的能力，
其余几个是夹具与闸门对不上。逐类修完，只有一个真缺陷——**DRC 会改它读的板子**。

## 1. 棘轮漂移：十二份拷贝各自写着 229，而 surface 早就是 250

`0.0.144` 起工具总数从 229 走到 250、`0.0.146` 走到 252，但「工具数不许变」这条断言抄在
十二个文件里，全都还写着 `assertEqual(len(tools.TOOLS), 229)`。这种断言一旦红了就没人再看，
等于把守卫弄丢。

收口到唯一来源 `tests/_toolcount.py`：

- `EXPECTED_TOOL_COUNT = 252`
- `EXPECTED_AVAILABLE_COUNT = 222`（`calc_capabilities()["available"]`）

十二个文件改成 `import _toolcount` + 引用常量，另三处散落的 `assertEqual(len(cap["available"]), 204)`
（`test_loss_audit` / `test_powder_curve` / `test_toroid_mlt`）同样接到常量上。改数从此是
一次刻意编辑、只改一处，而不是十二处一起漂。

## 2. 十九个用例在断言 `board_route` 返回 ok——那个工具已被禁止

用户明令「不再允许自动布线和自动布局」，`board_route` / `board_fanout` 已从 surface 退役
（`call_tool` 返回 `TOOL_RETIRED`）。但 `tests/test_route*.py` 仍走 `tools.call_tool("board_route", ...)`，
于是 19 个用例把「被拒绝」当成失败。

改法分两层，**不删测试**：

- 单元层改走库函数 `tools._board_route(args)`——planner 本身没坏，坏的是它被当成工具广告出去。
  这与仓库既有 house style 一致（`tests/test_fanout.py::test_the_planner_itself_still_works_as_a_library`）。
- 退役本身用一个类单独钉住（`TestTheToolIsRetiredNotTheRouter`，3 例）：返回 `TOOL_RETIRED`
  且**不等于** `TOOL_NOT_FOUND`、message 里带 `autorout`、四个 profile 都不广告这两个名字、
  且拒绝时不写盘。

## 3. 真缺陷：`engine.drc(save_to=...)` 会把 `--save-board` 打给调用方自己的文件

这条是这轮唯一的行为错误，表现很阴：一次 `apply_plan(engine=True)` 之后紧接着
`board_route` 报 `RULES_ABSENT`。

根因：`kicad-cli pcb drc --refill-zones --save-board` 会**写**它拿到的那个 `.kicad_pcb`。
`engine.drc()` 原本把 `save_to` 的副本路径当作目标，但当板子旁边没有同名 `.kicad_pro` 时，
落点会落回调用方自己的文件；KiCad 10 重存时把 `(net_class "Default" ...)` 当 legacy 丢弃，
板子的 `clearance 0.2` 与 `net class Default` 就一起没了。

修：refill 且目标就是原件时，先 `shutil.copyfile` 到 scratch 再交给 `kicad-cli`。

实测（`tests/test_drc_reads_only.py` 钉住）：修前 `engine=False → net_class=1`、
`engine=True → net_class=0`；修后两次都是 `1`。四个用例分别是字节不变、`save_to` 副本存在
且与原件不同、`(net_class "Default"` 与 `(clearance 0.2)` 仍在、以及 `engine=True` 的 apply
之后 `R.resolve` 仍读出 0.2 与 `net class Default`。

DRC 是**读**操作，不能改动它读的东西。

## 4. 夹具里的板子没有闭合板框

`tests/test_sync.py` 的 `BOARD` 字面量只有一条 `gr_line`，是「开框」。新的状态闸门
`precondition.outline_known` 如实拒绝——闸门没坏，是夹具不成立。补齐成 0..40 × 0..25 的
闭合矩形。

## 5. 新闸门 vs 旧期望：`clearance_no_worse` 与改板形

- `tests/test_ops_edit.py`：原来一例同时测「过孔跟随焊盘网络」和「指定另一个网络」，后者现在被
  `precondition.clearance_no_worse` 判成短路并拒绝，是正确的。拆成两例：跟随时断言网络与
  `pad_size`；指定他网时断言 `gates == ["precondition.clearance_no_worse"]` 且**文件不变**。
- `SetBoardOutlinePolygon` 类改的就是板形，`apply()` 覆写里显式传
  `allow_edge_changes=True`（propose 与 apply 都传）。
- `tests/test_crosscheck.py` 故意造 0.15 mm 间距，那一处违规就是被测对象 ⇒ 该类的
  `propose` / `apply` 传 `preconditions=False`。

只在「违规就是被测对象」的地方开闸，不做全局放水。

## 6. 本机 ngspice-47 没有 spinit，`gain1` 找不到定义

`test_spice_bundled` 的标题就是「仓库 vendor/ngspice 里那个引擎」，但 `engine="ngspice"`
会先走 PATH，落到本机 `ngspice_con.exe`——它没有 `share/ngspice/scripts/spinit`，于是
XSPICE 不可用、`MIF-ERROR: unable to find definition of gain1`，8 个红。

`setUp` 把 `spice.NGSPICE_CMD` 钉到 `vendor/ngspice/bin/ngspice_con.exe`，跑 38 passed；
另加一条**反向对照** `test_the_machines_own_engine_is_told_apart_from_the_bundle`：临时把
`NGSPICE_CMD` 置空去问 `find_ngspice()`，断言本机引擎在这张卡上确实 `problem is not None`
并报 `gain1`——避免 pin 把两个引擎的差异藏起来（本机没有独立引擎时 skip）。
