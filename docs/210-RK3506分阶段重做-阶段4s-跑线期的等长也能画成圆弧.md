# 阶段 4s —— 跑线期的等长也能画成圆弧：`style` 进了路由器

`209 §9` 第 1 条登记的欠账是：

> `route/tune.py::_serpentine` 仍无 `style`：`board_route` 跑线过程中补的等长还是三角齿。要做就得让跑线期也用 `arc_meander`……

这一条现在做完了，而且不是「换个默认值」那种做法：**同一个几何、两个调用方**，跑线期与离线规划器（`board_tune_length` / `tools/arc_reshape.py`）从此写出来的是同一种圆弧蛇形，不可能再各自漂。

交付板 `examples/rk3506_som/rk3506_som.kicad_pcb` **逐字节未动**；工具数不变（仍 **266**，没有新增工具，只给既有 `length_groups` 加了一个字段）；版本不动（阶段文档按先例不升版本、不进 CHANGELOG）。

## §1 结论先行

1. **形状是「组」的属性，不是全局开关**：`length_groups` 每一项可以带 `style`，取值 `"chamfer"`（45° 三角齿，**默认**）或 `"arc"`（圆弧蛇形）。不写就是 `chamfer`，**坐标一位不动**。
2. **一个几何，两个调用方**：`route/tune.py::_wave()` 在 `style="arc"` 时把同一段算术直接交给 `route/tune_board.arc_meander`（`import` 在函数内，因为 `tune_board` 已经 `import tune`）。没有第二份圆弧实现。
3. **零变化的默认档有反证**：同一块两网板上跑两次，`chamfer` 档 `add_track_arc` 计数 **0**、报告里没有 `arcs` 键；`arc` 档 **12 条弧、半径全 0.35 mm**。两档最终长度都是 **L1 = 33.999996 / 34.000000 mm**、`skew_after = 0.0`。
4. **长度口径跟着改**：`tune.net_length()` 从「只数直线」改成「直线 + `edit.ops.arc_length_mm` 三点弧长」，只在存在弧时才走那一支；`tune._tracks()` 仍只认直线（弧可以加长，但不是蛇形宿主）。
5. **形状不能画就说不能**：`style` 不认识时 `route/router.py::plan` 在**开工之前**报 `ARG_INVALID`（不是跑完 20 分钟后在提示里炸），`tune._wave` 也自己 `raise ValueError`。
6. **测试 4 例**（`tests/test_route.py::TestTheMeanderShapeIsTheOneAskedFor`），每条判据都配了能单独变假的反向对照；全量回归 `test_route + test_tune_board + test_arc_reshape` **152 passed**。

## §2 为什么改这里，而不是再写一个工具

`209` 已经说清三层：跑线期只有三角档、进文件的三角没有重画入口、我知道却没重画。第三层由 `tools/arc_reshape.py` 了结（把板上既有三角就地重画）；第一层就是本条——**跑线过程中**补的那点等长，出自 `route/tune.py` 自己的 `_serpentine`，它是唯一还只会画齿的地方：

| 入口 | 会不会画弧 | 走的是哪份几何 |
| --- | --- | --- |
| `board_tune_length`（`route/tune_board.plan`） | 会（`style` 默认 `"arc"`） | `tune_board.arc_meander` |
| `tools/arc_reshape.py`（离线重画） | 会 | 同上 |
| `router.plan` → `tune.finish` → `match_group` | **本条之前：只会画齿** | `tune._serpentine` |

新增一个「跑线完再重画」的工具等于把 `209` 的离线器再包一层，这在本仓库是明确不要的方向（能少一个入口就少一个）。所以改的是**既有那个入口的形状能力**，并且把它接到已经在用的那份几何上。

## §3 改了四处（少一处就是假的）

1. **`route/tune.py`**
   - 新增 `MEANDER_STYLES = ("chamfer", "arc")` / `MEANDER_STYLE_DEFAULT = "chamfer"`；
   - 新增 `_wave(a, b, extra_mm, amplitude, side, style, width)`：返回 `(pieces, info)`，`pieces` 和 `tune_board.plan` 一样是 `("line", p, q)` / `("arc", s, m, e)`；`info` 带 `teeth` / `arcs` / `radius_mm` / `sub_legible`；画不出来时返回 `(None, refusal)`，理由分 `no_segment_long_enough` / `too_shallow` / `no_legible_radius` 三种（三种的修法不同）；
   - `_emit_meander()` 从「点列」改成「片列表」，净空检查与占位都走 `tune_board._pieces_probe`（弧=弦，探针按矢高加宽）——**和 `tune_board.plan` 判弧用的是同一个探针**，不是第二套近似；
   - `net_length()` 直线 + 弧（`edit.ops.arc_length_mm`），`_tracks()` 仍只认直线，新增 `_arcs()`；
   - `match_group()` 读 `group["style"]`，报告里写 `style`（组级）与每个蛇形的 `style` / `teeth` / `arcs` / `radius_mm` / `sub_legible`；`chamfer` 档的 `parts` 结构与之前逐键相同。
2. **`route/router.py`**
   - `_replay()` 之前是 `if add_track … else 视为 via`，一条 `add_track_arc` 会让**重建栅格时 KeyError**（`op["x"]`）。现在第三种分支按弦 + 矢高探针入栅格；
   - `plan()` 在开工前校验每个组的 `style`，不认识就 `RouteError(ARG_INVALID)`。
3. **`tools.py`**：`length_groups` 的 schema 增加 `style`（说明 `'arc'` 是圆弧波、`'chamfer'` 是默认齿、其它一律按名字拒绝）。
4. **`tests/test_route.py`**：新增 `TestTheMeanderShapeIsTheOneAskedFor` 4 例。

## §4 四条判据，每条都能单独变假

| 判据 | 怎么变假 |
| --- | --- |
| `style="arc"` **真的写出弧**（`add_track_arc` 存在；每条三点反解出半径且扫角 ≈ 90°） | 若 `_wave` 把 `arc` 退化成齿，这里立刻红 |
| **报告的毫米数就是写的铜**（测试自己按 op 重算直线+弧长，两网差 ≤ 0.5，短网确实长了 >0.5，且与 `after` 差 ≤2e-3） | 若 `net_length` 漏数弧，`after` 会偏小而测试抓不到「多写了铜」，现在对照的是外部重算 |
| **不写 `style` 就一条弧都没有**（`add_track_arc == []`，报告无 `arcs` 键） | 任何「顺手把默认改成弧」都会红 |
| **画不了的形状按名字拒绝**（`status=error` / `reason_code=ARG_INVALID` / `message` 含那个词） | 若校验被挪到事后，这里变成 `TOOL_RAISED` |

外加一条只做不写的性质断言：`arc` 档里该网所有直线段的角度对 45° 取模为 0——**圆弧波不引入新角度**（齿被否掉的理由是直角，不是曲线）。

## §5 读数（合成两网板，`F.Cu` 单层，`max_skew 0.5`）

| style | `status` | `after` | `skew_after` | 弧数 | 半径 | L1 铜长 | L2 铜长 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `chamfer`（默认） | matched | 34.0 / 34.0 | 0.0 | **0** | — | 33.999998 | 34.000000 |
| `arc` | matched | 34.0 / 34.0 | 0.0 | **12** | 0.35（唯一值） | 33.999996 | 34.000000 |

两档同样是 `added_mm = 4.0`、同样落在 34 mm：**选项只换形状，不换长度**。

## §6 边界与未做

1. **默认仍是 `chamfer`**。理由是新功能一律可配置开关、默认档体积与行为零变化；把默认翻成弧是「跑线期行为改变」，那要用户点头，不在本轮。
2. **粗探针不认弧的那几处没有改**：`router._stamp` / `_paint_ring` / `_crowded` / 预留带量距 / 铺铜失效判断都只遍历 `add_track`，弧会被跳过。它们全部跑在**布线轮次里**（`tune.finish` 之前），那时程序里不可能有弧——`finish` 才是唯一写蛇形的地方，写完只做 `rebuild()` 与 `return_path.stitch`。所以这是「现在够用、将来动顺序就要补」的一条，登记在此，不假装已经覆盖。
3. **`_recompute_lengths()` 没有改**：它在当前代码里没有任何调用点（死代码），改它是无证据的改动。登记。
4. **真实板上没有跑板级弧读数**：这块板的弧已经由 `arc_reshape` 落在 `_am7` 上（488 条），再让路由器重跑一遍是几十分钟的搜索，而本轮改的是**写形状的那一跳**，判据在合成板上可判定、可反向对照。交付板不动。
5. **被拒的 4 条链与交付板仍未处理**（`209 §9` 第 3、4 条）：`/DDR_DQ15`、`/DDR_DQ9`（`clearance`），`/DDR_A1`、`/DDR_DQ13`（`does_not_fit`），理由不变。
