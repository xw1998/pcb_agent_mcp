- 日期：2026-11-12

- 权威数据源：`RK3506J Datasheet Rev 1.3`，50 页，**2,724,252 B，文末 `%%EOF` 完整**

## 0. 数据源修复记录（先记坑，否则下面的数没有意义）

上一轮解析用的 `RK3506J_datasheet_V1.3.pdf` 只有 **1,231,973 B**，是**下载了 45% 就断的残件**（`tail` 停在
`386 0 obj`，无 `%%EOF`；`pdftotext`/`pdfminer` 直接 `Unexpected EOF`）。PyMuPDF 能靠重建 xref 打开 50 页，
所以「页数看起来对」极具欺骗性，但它把被截断的文本流按缺字吐出，造成两类系统性错误：

1. 球号/引脚名**重复末位被吞一位**：`A11→A1`、`A22→A2`、`1A11→1A1`、`1F11→1F1`、`DDR3_A11→DDR3_A1`、
   `DDR_DQ11→DDR_DQ1`。上一轮用「重复末位补位」的启发式去补，产生了两处**真错数**（见 §3 的 DQ1/DQ11）。
2. 整行整表缺失：`1C`/`1E`/`1G` 三行当时判为「手册没有」，其实**是残件没了**；`LOGIC_DVDD` 的球位被读成
   `1F1 1H1 1J10`（正确是 `1F11 1G11 1H11`），`SYS_PLL_AVDD1V8` 被判成「手册未给球位」（正确是 `1H1`）。

本文件所有数字来自**重下的完整 PDF**（`J_v13_fresh.pdf` = `https://mail.rockchip.fr/RK3506J%20datasheet%20V1.3.pdf`，
curl 跟随 301 → `rockchip.fr`，最终 200 / 2,724,252 B）并用 `rawdict` 逐 span 几何重解析。
**结论：凡「因为文档残缺而得到的否定结论」都不能当事实；下载件先验 `%%EOF` 再解析。**

## 5. 板级方案（冻结）

| 项 | 决定 | 依据 |
|---|---|---|
| 板框 | **45 × 45 mm**，四角 R2 | 333-BGA 11.3×13.3 + DDR3L + 板载 SPI-NAND + 电源 + 140 邮票孔；单面贴片要留布线通道 |
| 层数 | **6 层**，1.6 mm，ENIG | 用户指定 4–6；DDR 需完整参考面 |
| 叠层 | L1 信号 / **L2 GND** / L3 信号 / L4 PWR 分区 / **L5 GND** / L6 GND | 背面无走线、单面贴片，L2/L5 两个完整地平面夹信号 |
| 贴片 | 全部器件在 **L1（Top）**；背面只有平面与邮票孔焊盘 | 用户要求单面贴片 |
| 邮票孔 | **140 pin @1.0 mm**，四边 **2×30 + 2×40**；半孔钻孔 **φ0.55**、焊盘 **φ0.85**、相邻焊盘间隙 **0.15 mm**；四角 2 mm 禁布（R2 圆弧区不放半孔） | 140@1.0 mm 与参考 SOM（创龙 SOM-TL3506「2x30pin + 2x40pin，共 140pin，间距 1.0mm」）同构；半孔尺寸按嘉立创半孔工艺（孔径 ≥0.5 mm、焊盘 ≥孔径+0.30 mm、相邻半孔间隙做得出）反算 |
| 阻抗 | 单端 50Ω ±10%、差分 100Ω ±10% | DDR3L-1333/1600 |

> **§5 修订 r1（2026-11-12）**：上一版本把邮票孔写成「半孔 φ1.0 / 孔盘 φ1.6 / 四边 35 pin」，两处都错——
> ① 焊盘 φ1.6 在 1.0 mm 间距下相邻焊盘会互相覆盖（1.6 > 1.0），物理上不成立；
> ② 四边 35 pin 与同行参考设计的 2×30 + 2×40 不符。现按「间距 1.0 mm 是硬约束」反算焊盘：
> 间隙下限 0.15 mm ⇒ 焊盘 ≤ 0.85 mm；嘉立创半孔要求焊盘 ≥ 孔径 + 0.30 mm ⇒ 孔径 ≤ 0.55 mm。
> 取 **孔 0.55 / 盘 0.85 / 间隙 0.15 / 环 0.15**，四条同时满足。跨度：40 脚 39.0 mm、30 脚 29.0 mm，
> 均 ≤ 45 − 2×2 = 41 mm。
| 电源输入/输出 | 输入 **5V 4 pin 并联**（E 边）；输出 **3.3V 4 pin**（S 边）；其余电压全部板内产生不外引 | 5V 4×1A 覆盖实测量级（参考 SOM 满负载 ~0.7 W）；3V3 供底板取用 |
| 板载存储 | **SPI-NAND 走 FSPI**（6 球内部占用）→ SDMMC **6 球外引**给底板做 SD/eMMC | NAND 6×8 mm 比 eMMC 11.5×13 省面积；SDMMC 留给用户，两种存储不争同一组球 |

## 6. 电源树（电压已核，器件选型待核）

```
5V in ──┬─ Buck 0.95V/2A (DVFS 可调 0.855–1.103) ── CPU_DVDD  (1C2 1C3 1C4)
        ├─ Buck 0.90V/2A ────────────────────────── LOGIC_DVDD (1E4..1J10) + PMU_LOGIC_DVDD0V9 (1K2)
        ├─ Buck 1.35V/2A ──┬─────────────────────── DDR_VDDQ (1K6..1K10)
        │                  └─ VTT 0.675V/1A ──────── DDR 地址/命令端接（灌/拉双向）
        ├─ Buck 3.3V/2A ───┬─────────────────────── PMUIO_VCC3V3 (1L1) / VCCIO* 3.3V 档 / USB AVDD3V3 (1B10)
        │                  └─ LDO 1.8V/1A ────────── SYS_PLL (1H1) / MIPI 1V8 (1B7) / USB 1V8 (1B9) /
        │                                            ACODEC 1V8 (1B13) / SARADC (1B14) / TSADC (1B6) / VCCIO* 1.8V 档
        └─ LDO 0.9V/0.3A ─────────────────────────── MIPI 0V9 (1C7) / USB 0V9 (1C8)
```
- 约束：CPU_DVDD 必须可调（DVFS 0.855–1.103），不许固定输出；DDR3L VREF = 0.675 V（0.1 µF 就近）；
  VTT 需能灌/拉；`VCM`(1B11)/`AVDD1V6`(1B12) 电压手册未给，**不接电源、只留测试点**。

## 8. 140 pin 邮票孔引脚分配（`som_pinout_140.csv`）

### 8.1 数量闭合（每个数都能从上一行推出来）

| 项 | 数 | 推导 |
|---|---|---|
| SoC 具名信号球 | 161 | §2 |
| − DDR3L 占用 | 55 | §3（不外引，板内闭合） |
| − 板载/内部占用 | 11 | 24M 晶振 XIN/XOUT 2 + CPU_AVS 1 + VCM/AVDD1V6 2 + SPI-NAND FSPI 6 |
| = **外引信号** | **95** | 全部可用脚，不做“挑一部分”的主观取舍 |
| + GND | 37 | 140 − 95 − 8 |
| + 电源（5V 4 / 3V3 4） | 8 | §5 电源行 |
| = **邮票孔总数** | **140** | 2×40 + 2×30 @1.0 mm |

### 8.2 规则（优先级自上而下，冲突时高优先级先满足，脚本逐条断言）

| 编号 | 规则 | 理由 |
|---|---|---|
| R1 | 同一接口全部脚在同一条边，组内不得插入别的接口的脚（GND 可插在其间作回流） | 底板上同一接口的控制器/flip-flop 在一侧，跨边拆分会横穿全板 |
| R2 | 差分对（MIPI CLK/D0/D1、USB0/1 D+/D-）相邻两脚，中间不得插 GND/电源 | 打断差分对 = 共模回流断裂、长度不等 |
| R3 | 任何连续非 GND 脚 ≤ 6 个 | 1.0 mm 半孔阵列需要地做回流与热焊盘 |
| R4 | 每边 GND ≥ 3，GND 按边均摊 | 避免某边整边无地 |
| R5 | DDR 55 球与内部占用球绝不外引 | DDR 必须在板内闭合；VCM/AVDD1V6 电压手册未给，不外供 |
| R6 | 电源脚不得紧贴 MIPI/USB | 电源块与高速差分共存会把大电流回路引到差分参考面 |
| R7 | 几何可达：边跨度 ≤ 边长方 − 2×2 mm；焊盘间隙 ≥ 0.15 mm；半孔环 ≥ 0.15 mm | §5 修订 r1 反算 |
| R8 | 引脚编号逆时针：N 左→右 1–40、E 上→下 41–70、S 右→左 71–110、W 下→上 111–140 | 邮票孔模块通用编号约定，底板丝印 pin1 可对 |

### 8.3 四条边的分配

| 边 | 脚 | 内容 |
|---|---|---|
| N (1–40) | 40 | RGB LCDC 28（D0–D23 + CLK/HSYNC/VSYNC/DEN）+ GND 12 |
| E (41–70) | 30 | 5V×4、MIPI DSI 6、USB 6（OTG0 DP/DM/ID/VBUSDET + OTG1 DP/DM）、SARADC 4、ACODEC INP/INN、GND 8 |

跨度：40 脚 39.0 mm、30 脚 29.0 mm（最长 39.0 ≤ 41.0）。最长无地段 6 脚（R3 上限）。

### 8.4 本表**不声称**的事（防止被误引）

- **不与任何厂商的 SOM 引脚定义兼容**：物理排布（2×30+2×40 @1.0 mm）与创龙 SOM-TL3506 同构，但对方
  的引脚定义表未取得，**逐脚分配是自研的**，不得当作可直接换板。
- 5V/3V3 电流能力是**端口计数**（4 pin 各按 1 A 估算），不是仿真结果；实际按底板负载核。
- 引脚复用（一个 GPIO 球的多个功能）只标注首选功能；RM_IO 矩阵可重映射的名单需另表，不在本表范围。

## 9. RK3506J 封装与符号（0.1.3，几何取自官方库）

### 9.1 为什么不再说“硬阻塞”

0.1.2 把 333 球坐标判成硬阻塞，前提是“手册无 ball map 且本地无库”。这个前提只对了一半：
本地离线 `lceda-std.elib`（SQLite，461 MB，4,044 个封装）**确实没有 RK3506**（搜 0 命中，标准库只收通用器件），
但**在线器件库有**，且匿名可查、可解密。所以改成自己去找，不再向用户要资料。

### 9.2 四个步骤的取几何链路（可推广到任何立创器件）

| 步 | 动作 | 实测要点 |
|---|---|---|
| 1 | `POST https://pro.lceda.cn/api/v5/devices/search`，body `{"wd":"RK3506","page":1,"pageSize":10}` | 匿名可用；命中 `RK3506J` = **LCSC C48642327 / FBGA-333L**，另有 `RK3506B`(SMD-135P) 与 `RK3506G2`(QFN-128) |
| 2 | `GET /api/v5/components/<uuid>` | 返回 `dataStrId` + `key`(32 hex) + `iv`(**12 hex**) |

### 9.3 单位陷阱：比例是“解”出来的，不是“读”出来的

该封装 `CANVAS` 行写 `["CANVAS",0,0,"mm",1,1,0.3937,0.3937]`，但坐标真值是 **mil（0.0254 mm/单位）**。
按声明解释会得到 486 mm 宽的器件。用手册当尺子才能证伪：

| 量 | 文档值 | 按 mil | 手册 | 结论 |
|---|---|---|---|---|
| 焊盘直径 | 9.843 | 0.250 mm | b=0.30（**球径**） | 焊盘取 0.250 |
| X 跨 | 486.78 | **12.364 mm** | E1 = 12.364 | 命中 |
| Y 跨 | 420.40 | **10.678 mm** | D1 = 10.678 | 命中 |
| 本体 | ±261.8105 / ±222.4405 | **13.300 × 11.300 mm** | E × D | 命中 |

所以 `solve_scale()` 在 `("mil",0.0254)` 与 `("mm",1.0)` 两候选中**用 D1/E1 解唯一命中**；命中数 ≠ 1 即 `SystemExit`。
测试里两个方向都有反向对照：声明 mm 实为 mil、声明 mil 实为 mm。

### 9.6 KiCad 10 语法三坑（写错就整库加载失败）

1. 封装头 `(version 20260206)`；写 `20240108` 报 `Unable to convert library`。
2. 元件属性用 `(property "Reference" …)`，不是 `fp_text`。
3. `(tags …)` **只接受一个字符串**（空格分隔），多字符串直接解析失败。

另：括号必须平衡、`-0.0` 要归零；校验放在仓库盘目录做（同一文件在 `C:\…\Temp` 下会报 `Unable to convert library`）。

## 10. DDR3L 颗粒封装与符号（0.1.4，同一条官方库链路）

### 10.1 选型（LCSC 在线库，2026-11-12 检索）

| 项 | 值 | 来源 |
|---|---|---|
| 型号 | **MT41K256M16HA-125:E**（micron 美光） | LCSC **C248057** |
| 规格 | DDR3L SDRAM 4 Gbit，x16，800 MHz（-125 = 1.25 ns） | 目录 description |
| 封装 | **FBGA-96（9 × 14 mm）**，库名 `FBGA-96_L14.0-W9.0-R16-C6-P0.80-TL` | 目录 package + 封装 HEAD.title |
| 电压 | 1.283 ~ 1.45 V（与 RK3506 `DDR_VDDQ` 的 1.283/1.35/1.418 同档） | 目录 attributes |

为什么是 4 Gb x16：SoC 侧 Table 2-1 的 DDR3L 接口就是 **16 bit 数据（DQ0–DQ15）**、55 信号 +
5 颗 `DDR_VDDQ`，单颗粒 x16 直接铺满一条通道，不需要两颗拼位宽。**8 Gb 或 x8 的型号不在本板范围**。

### 10.2 取件链路已工具化（`tools/fetch_lceda_part.py`）

上一轮（RK3506J）的四步链路写死在脚本里，这轮抽成仓库工具，用法：

```
python tools/fetch_lceda_part.py search "MT41K256M16" --limit 10
python tools/fetch_lceda_part.py fetch <component_uuid> --out examples/rk3506_som/library --stem <名字>
```

- 产出 `<stem>.efp`（解密后的文档）、`<stem>_source.json`（uuid/key/iv/title/version/文件字节/`doc_sha256`/版权声明/日期）、
  `<stem>_meta.json`（原始组件记录）。已存在 `.efp` 时不覆盖，需 `--force`。
- **device uuid ≠ component uuid**：目录检索返回的 `uuid` 是**器件**记录，直接喂给 `/api/v5/components/` 会得到
  `component not found (code=1111113)`。要取几何必须用 `attributes.Footprint` / `attributes.Symbol` 里的那两个 uuid。
- 失败一律**具名报错**，不猜：key 不是 32 字节、iv 不是 12 字节、GCM 拒绝、明文不是 gzip、明文不像文档，各有独立分支。

### 10.6 交叉一致性（这轮新增的判据）

`tests/test_ddr3l_footprint.py` 里两条不是查单件，而是查**两侧能不能对接**：

1. 符号的 96 个 pin number 与封装的 96 个焊盘号**集合相等**（逐字相同，不是"数量都是 96"）。
2. 符号里 DQ0–DQ15 全在，且 `LDQS/UDQS/LDM/UDM/RAS#/CAS#/WE#/CK/CS#/ZQ` 全在 —— 缺一条数据线，
   SoC 侧 55 根 DDR 信号就有对不上的。

### 10.7 KiCad 10 语法又三个坑（这轮踩的，与 9.6 不重复）

1. `(size 1.27)` 单值字体尺寸**非法**，必须 `(size 1.27 1.27)`；报错同样是笼统的「无法加载库」。
2. `(justify center)` **非法**：KiCad 用"不写 justify"表示居中，只接受 left/right/top/bottom/mirror。
3. `(generator pcb_agent_mcp)` 必须带引号；不写引号也报同一句「无法加载库」。

**教训**：KiCad 的库加载错误永远只说一句「无法加载库/Unable to convert library」，所以排错只能二分——
本轮的做法是"删掉整块 property 能过 ⇒ 逐条加回 ⇒ 定位到 justify ⇒ 再定位到单值 size"，每次只留一个可疑项。
