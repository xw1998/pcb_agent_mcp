# 105 · 交付包是拼出来的：Gerber 独立复核、拼接缺陷与嘉立创工艺对照

> 它回答的问题：**104 交出去的 6 个文件，字节本身可信吗**？
> 以及：**不信任任何一方 DRC 的前提下，怎么用 Gerber/钻孔反向核对这块板**？
>
> 它推翻的前提：**「导出成功 = 文件正确」**。104 那一版的 `Gerber.zip` 有 70 467 字节、
> 能被解压软件列出 17 个成员、能被 `zipfile` 打开列目录——**但 `unzip -t` 报 16 个成员坏、16 个 CRC 全不符**。
> 文件名、大小、目录结构全都对，只有内容不对。

---

## 105.0 两句话

1. **根因在我自己的取回脚本，不在立创**：`getGerberFile()` **每调用一次就重新生成一个压缩包**，
   同接口连续五次拿到 **70 464 / 70 438 / 70 467 / 70 434 / 70 456** 五个体积。
   我按「每块 16 KiB 重新调一次接口」取，等于把**五个不同压缩包的各一段**首尾相接——拼出来的当然是坏包。
2. 修法是把文件先读进 `globalThis`（会话内跨调用保留），之后每块都从**同一份 Uint8Array** 上取；
   重导后 `zipfile.testzip()` 返回 **None（全体 CRC 通过）**、`unzip -t` 全 OK。
   导出 70 KB 从 **30.0 s 降到 1.0 s**（块 8192 字节，无需反复生成）。

---

## 105.1 缺陷的完整证据链

| 步骤 | 观测 | 说明 |
|---|---|---|
| 1 | `unzip -t Gerber.zip` → `bad zipfile offset (local header sig)` 逐成员 | 结构错位 |
| 2 | `zipfile.testzip()` → 16/17 成员 CRC 不符 | 内容错 |
| 3 | 逐成员 `zlib.decompressobj(-15)` → GTL/GTO/GTP/DRL 直接 `Error -3` | 压缩流本身非法 |
| 4 | 在 JS 侧解析 EOCD：`ntot 17`、`csize 1214`、`coff+…==u.length`、`cd 首字节 == PK\x01\x02` | **立创给出来的包在它自己看来是自洽的** |
| 5 | 同一 1024 字节分块：JS 侧哈希（`h=h*131+b`）与 Python 侧哈希三块全等 | **传输是逐字节精确的** |
| 6 | 同一 File 句柄连读 5 次 → 70 465 / 70 465 / 70 465 / 70 465 / 70 465 | 句柄稳定，**变的是「每次新生成一份」** |
| 7 | 连续三次 `getGerberFile()` 各读一次 → 70 467 / 70 465 / 70 460 | 每次生成一份新的，体积都不同 |

所以：**传输没错、立创生成的单份包没错、错在「拼接了不同份」**。
第 4、5 步是关键——没有这两步，很容易误判成「立创的 Gerber 导出坏了」。

## 105.2 修法（可复用）

```
第 1 次调用：globalThis.__X = new Uint8Array(await f.arrayBuffer())
             同时回报 __X.length —— 从此这份缓冲就是唯一事实来源
第 N 次调用：从 globalThis.__X 上按 offset 取一段，base64 回传，
             同一次调用里回 len / total / b64.length，接收端逐块断言
```

三条硬要求：

1. **绝对不要**在分块循环里重新调 `getXxxFile()`。任何 `getXxxFile()` 都是一次新生成。
2. 每块自带 `{n 总长, i 起点, len 本块长度, total base64 长度}`，接收端**四个数全对**才收，缺一即报错退出，
   不写半成品文件（写「坏但看起来完整」的文件比报错更糟）。
3. 落盘后**必须自证**：`.zip` 用 `testzip()`、`.xlsx` 同、`.pdf` 看 `%%EOF` 与页数、文本看首尾行。
   104 那一版的教训就是「文件名对、大小对、目录列表对 ⇒ 就以为对了」。

`_scratch/lc_export4.py` 是这一版实现；`_scratch/lc_export2.py` 是坏的那一版（保留作对照）。

## 105.3 独立复核读数（不信立创 DRC，直接解析 Gerber）

解析器只做能确定的事：读 `%FSLAX45Y45` 坐标格式、读 `%ADDn` 光圈表、
按 `D01`（画线）/`D03`（闪光）/`G36`（区域）归类；读不懂的行落在 `stray` 里计数，本板铜层 `stray` 全为 0。

| 层 | 光圈 | `D01` 画线 | `D03` 闪光 | `G36` 区域 | 线宽分布 |
|---|---|---|---|---|---|
| `Gerber_TopLayer.GTL` | 26 | **325** | 312 | 0 | 0.1501 ×324、0.2032 ×1 |
| `Gerber_InnerLayer1.G1` | 9 | **131** | 175 | **128** | 0.1501 ×50、0.2032 ×81 |
| `Gerber_InnerLayer2.G2` | 9 | **74** | 175 | **127** | 0.1501 ×40、0.2032 ×34 |
| `Gerber_BottomLayer.GBL` | 9 | **150** | 177 | 0 | 0.1501 ×150 |

- 坐标格式全层 `%FSLAX45Y45`、单位 `%MOMM`，与 4.5 位定点一致。
- 铜层 `D01` 合计 **680** 条；PCB 侧线段表 **681** 条（L1 324 / L2 152 / L15 131 / L16 74）。
  逐层差：**L1 多 1 条（323×5.91 + 1×8 → 324×0.1501 + 1×0.2032）、L2 少 2 条、L15/L16 完全相等**，净 −1。
  **不做结论**：两条统计口径不是同一件事，这条差值没定位。
- 铺铜：板内 257 块（L15 GND 128 + L16 +3V3 129），Gerber 里 **255 个 region**（128 + 127）。
  **L16 少 2 个 region，未定位**（无零面积块，最小块 1026 mil²）。
- 焊盘最小闪光 **0.2997 mm**；每层都有 **125 个 0.4501 mm** 的闪光，就是 125 个过孔的盘。

钻孔（Excellon，`METRIC` 显式声明，故不按 inch 换算）：

| 文件 | 孔数 | 刀具 |
|---|---|---|
| `Drill_PTH_Through.DRL` | **175** | 0.1999 ×125、0.2032 ×1、0.7 ×2、0.9 ×2、1.0 ×40、1.02 ×5 |
| `Drill_PTH_Through_Via.DRL` | **126** | 0.1999 ×125、0.2032 ×1 |

> 两个文件里都出现 125 个 0.1999 mm 孔（过孔同时被计入 PTH 文件），**不把两数相加当总孔数**。

## 105.4 嘉立创四层板工艺对照（数值已联网核实）

来源：嘉立创《制造工艺要求》 <https://www.jlc.com/portal/q7i35541.html>（2022-03-03）

| 项目 | 官方下限（四/六层） | 本板实测 | 判定 |
|---|---|---|---|
| 最小线宽 / 线隙 | 0.09 / 0.09 mm | 线宽 **0.1501 mm**；线隙见 104 的 DRC 6 mil = 0.152 mm | 通过，余量约 1.6 倍 |
| 最小过孔 | 内径 **0.2** / 外径 **0.45** mm（外径极限 0.40） | 内径 **0.1999**、外径 **0.4501** mm | **踩线**（见下） |
| 除过孔外的插件孔 | 最小 0.5 mm | 最小 0.7 mm | 通过 |
| 最小焊盘边到线边 | 0.127 mm | DRC 规则 0.152 mm（6 mil）且 Clearance 0 | 通过 |
| 过孔孔边间距 | 0.254 mm | **未测**（本轮没算孔到孔） | 未覆盖 |

「踩线」这一条要写清楚，不许写成「不达标」也不许写成「随便过」：
钻孔文件里写的是 **0.1999 mm**，官方下限是 **0.2 mm**，差 **0.0001 mm（0.1 µm）**——
这是 mm↔mil 换算取整写出来的数（0.2 mm = 7.874 mil），不是超差设计；
外径 0.4501 / 内径 0.1999 → 环宽 **0.1251 mm**，正好等于官方「内径 0.2 + 外径 0.45」组合隐含的环宽。
**结论：这块板的过孔就压在嘉立创四层板的最小过孔规格上，没有余量。**
下单时应按 **0.2 mm / 0.45 mm** 标注，不要写成 7.87 mil / 17.7 mil。

## 105.5 三条口径

1. **任何「导出/生成」类接口都可能每次重新生成**。取多块之前先取一次总长，
   并**把内容固定在会话级全局对象里**；只在「重新生成不改变语义」的前提下才能重调。
2. **计数口径不同 ≠ 有一方错了**。Gerber 的 `D01` 数（680）、PCB 线段表（681）、
   `PCB_INFO` 的「导线长度」是三件事；对不上先记差值，别急着解释成「丢了/多了」。
3. **交付自证要落在字节上**：CRC / `testzip` / `%%EOF` / 首尾行。
   104 那版「文件名对、大小对、目录对」的自证方式是不够的——**它对内容一无所知**。

## 105.6 没做完

1. **L1 +1 / L2 −2 的差值**没定位；**L16 少 2 个 region** 没定位。都只登记，不下结论。
2. **孔边到孔边 0.254 mm** 这条官方规则本轮没算（要会聚所有钻孔中心再求最近距离）。
3. `Drill_PTH_Through.DRL` 与 `Drill_PTH_Through_Via.DRL` 的**归属口径**（过孔为何两边都出现）没搞清，
   本轮只用「不把两数相加」规避。
4. 104.7 的其余欠账（Netlist 1、铺铜区域 0、测试点 0%）状态不变。
