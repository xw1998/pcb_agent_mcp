# 137 · 板级仿真的语料基线：12 块真板、两个「不需要调用方给数」的入口

`142`–`145` 把四个板级入口接到了 `.kicad_pcb` 上：电路（`board_netlist`）、热
（`board_thermal`）、电流密度（`board_current_field`）、腔与串扰
（`board_plane_resonance` / `board_crosstalk`）。这一页不是新能力，是**基线**：拿 KiCad
自带的 12 块 demo 板当语料，把「不需要调用方给数」的两个入口全跑一遍，看它们在真文件上
是**答**还是**拒**、拒得对不对。

为什么只有两个入口能扫：热要电流、场要两个接触焊盘、串扰要上升时间——这些**不在文件
里**（这也是它们被设计成必填的理由）。用基线的名义给它们编一个电流，得到的是一张好看
的表和一堆假数。所以语料只覆盖腔（几何全在文件里）与网表（拓扑全在文件里），另外三个
入口的证据是 `143`–`145` 里逐块的实测。

## 1. 腔：12 块板，6 答 6 拒，拒的理由三种

| 板 | 结果 | 板对 / 理由 |
|---|---|---|
| video | (1,0) **0.226452 GHz** | In1.Cu / In2.Cu，0.48 mm，312 × 106.7 mm，帧盖 80.5 % / 79.1 % |
| openair-max | (1,0) **0.710525 GHz** | F.Cu / B.Cu，1.04 mm，99.45 × 72 mm，99.8 % / 95.6 % |
| complex_hierarchy | **拒** | 第二块板 F.Cu 只盖 **0.2 %** 的包围盒 |
| cm5_minima | (0,1) **1.09213 GHz** | In4.Cu / In2.Cu，0.68 mm（er 串联平均 **4.571**），61.2 × 64.2 mm，**外形只有盒的 77.8 %** |
| royalblue54L_feather | (1,0) **1.20955 GHz** | In6.Cu / In5.Cu，0.3 mm，58.42 × 22.86 mm |
| stickhub | (0,1) **1.76654 GHz** | B.Cu / F.Cu，1.51 mm，16.5 × 40 mm，F.Cu 只盖 84.9 %（点名） |
| ecc83 / interf_u / pic_programmer | **拒** | 只有一层铺铜（B.Cu 0.91 / 0.88 / 0.95），没有第二块板 |
| microwave / multichannel | **拒** | 文件里**没有叠层**：铜层与 er 都没说 |
| tiny_tapeout | **拒** | 没有闭合外形（`Edge.Cuts` 只出现在封装的 `fp_line`/`fp_arc` 里） |

第一行 video 的 0.226 GHz 是最值钱的一条：**312 mm 长的大板，第一模落在 226 MHz**，
一块 100 MHz 级的板子会正好踩在它上面；而它两块板都只盖八成（中间是分割的），所以
`notes` 里两行都点名「板上有洞」。

### 扫描抓到的两个真缺陷（0.0.146 修掉）

1. **按覆盖率排序会把 0.2 % 的铜当板**。`complex_hierarchy` 只有 F.Cu/B.Cu 两层铜，F.Cu
   上只有一块小铺铜，排序照旧把 B.Cu 与它配成腔——算出来的是一个不存在的谐振腔。现在
   **第二块板盖不住包围盒 50 % 就拒答**，并把 `pours_found` 逐层列出；点名
   `layer_a`/`layer_b` 仍然放行（那是调用方的假设）。
2. **「文件没有叠层」被说成「铺铜不够」**。`microwave`/`multichannel` 整个文件没有
   `(stackup)`，`copper_layers` 是空的，旧文案却说「没有两块铺了铜的层」。现在分开：
   没有叠层就直说铜层与 er 都没说，并指出点名 + 给 er 的出路。

## 2. 网表：12 块板，10 块抽出 19–97 个网，2 块每个网都拒

| 板 | 网 | 节点 | 跳过 | 跳过原因 |
|---|---|---|---|---|
| video | 97 | 907 | 274 | 全部 `plating_um not given` |
| openair-max | 66 | 578 | 51 | 同上 |
| interf_u | 63 | 479 | 47 | 同上 |
| complex_hierarchy | 49 | 566 | 0 | —— |
| tiny_tapeout | 36 | 199 | 72 | 同上 |
| pic_programmer | 31 | 455 | 2 | 同上 |
| cm5_minima | 19 | 126 | 77 | 同上 |
| stickhub | 17 | 365 | 28 | 同上 |
| royalblue54L_feather | 14 | 104 | 54 | 同上 |
| ecc83 | 8 | 101 | 0 | —— |
| multichannel | 0 | 0 | 79 | 全部 `no copper thickness … stackup does not carry it` |
| microwave | 0 | 0 | 0 | 板上没有走线（0 段 / 4 个封装） |

两种「0」完全不同，而且是这一页最该记住的一条：**multichannel 有 576 段走线**，只是文件
没有叠层 ⇒ 没有铜厚 ⇒ 每个网都 `ARG_REQUIRED`；**microwave 真的没有走线**。只看
`nets=0` 会把这两件事读成一件。

跳过的主因是 `plating_um`（过孔桶壁厚度）：板上只要有孔，桶壁厚度就是调用方的数，不给
就算不出来——不是解析失败。

## 3. 怎么复现

```bash
PYTHONPATH=src python - <<'PY'
import glob, os
from pcb_agent_mcp.tools import TOOLS
cav = TOOLS["board_plane_resonance"]["handler"]
net = TOOLS["board_netlist"]["handler"]
for p in sorted(glob.glob("_corpus/*.kicad_pcb")):
    o = cav({"path": p}); v = o.get("value") or {}
    print(os.path.basename(p), o["status"], o.get("reason_code") or "",
          ((v.get("lowest_mode") or {}).get("f_ghz")))
PY
```

`_corpus/` 是本地留存的 KiCad demo 副本（**不入库**，`.gitignore` 之外，也不在任何提交
里），所以这一页的数是**可复现但不可自证**的（板子来自 KiCad 官方仓库，同一版本应当逐位
相同）。12 块板的腔扫描合计约 5 s，网表约 5 s——这就是「基线」能随手重跑的意思。

## 4. 这一页不做什么

- 不给热、电流密度、串扰的语料数：它们的输入不在文件里，编一个数扫出来的表没有意义。
- 不判板子好坏：0.226 GHz 的第一模是不是问题，取决于板上有没有 226 MHz 的能量——那是
  设计，不是文件。
- 不改 `_corpus/`、不提交它：语料只用来量工具，不是仓库内容。
