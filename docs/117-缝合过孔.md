# 117 · 缝合过孔：从「只算」到「能落」

**这个版本回答一个具体的能力空洞，不是回答「好不好看」。**

## 1. 现场：所有检查都过，人眼一眼说不对

F412 核心板 v36：双层、两片 GND 铺铜（F.Cu 优先级 1 / B.Cu 优先级 0）、
`board_drc(refill_zones=true)` 74 条违规里 `clearance` **0**、`isolated_copper` **0**，
`board_45_corners` 的直角只剩焊盘处不可避的那几个。

**而两面地之间一个过孔都没有。**

这不是 DRC 漏了，是这套服务器从来没有「放孔」这个动作：

| 工具 | 它回答的问题 | 它对这块板说什么 |
|---|---|---|
| `via_resistance` / `via_current_allowed` | 这个孔合不合格 | 与你有没有孔无关 |
| `thermal_via_array` / `cavity_via_fence` | 这个阵列该多密 | 同上 |
| `pdn_plane_*` | 平面阻抗够不够 | 它按「平面」算，而没孔的板其实不是平面 |
| `board_fill_zones` | 把铜铺出来 | 铺铜不等于缝合 |

所以「缺什么」这个问题的答案很具体：**缺一个把铜变成「一片」的动作**。

## 2. 加的东西

`board_stitch_vias`（`route/stitch.py`）。

### 2.1 判据：点在**填充**里，不在外框里

一个缝合孔的环形必须落在同网的 `filled_polygon` 内，而且是**它跨的每一层**都如此。

- 只看 zone 外框等于看「铜可以去哪」，不看「铜在哪」：外框会覆盖走线让出来的间隙，
  于是孔被放进间隙里，看起来像缝合，其实只是多了一个钻。
- 所以还有一个 `pour_edge_too_close`：点在填充内，但离填充边界不足 `半径 + clearance`。
  这种孔的环形一半在铜上、一半在铺铜自己的间隙上。

**这一点直接来自 0.0.116 那条教训的反面**：铺铜是快照，所以 DRC 要重铺；
但**判断「这里有没有铜」只能看快照（填充）本身**，不能看「本来可以铺到哪」。

### 2.2 单层没填充 = 拒绝，不是「放个孔试试」

`coverage()` 报每层的 `zones_declared` / `zones_filled` / `filled_polygons` / `has_fill` / `area_mm2`。
任一目标层 `has_fill == False` ⇒ `plan()` 返回 `refused: "no_same_net_pour"` 与 `layers_without_fill`，
`ops` 为空。

理由是电气而非格式：一个只连到单层铜的过孔是**悬空残桩**，它不缝合任何东西，
只增加一次钻孔和一段可以被天线化的铜。

### 2.3 间距规则分出两类：铜间距（按网）与孔间距（不按网）

- **铜间距**：异网走线/焊盘/过孔 ≥ `clearance_mm`（默认 0.25）从**环形边缘**算；
  同时检查两层，因为通孔过孔在它跨的每层上都是铜。
- **孔间距**：任意两个钻孔中心距 ≥ 0.25 mm，**同网也一样**。
  同网短路不是问题，重叠钻孔是制造缺陷 —— 这是 KiCad 的 `hole_clearance` 默认值，
  也是唯一一条与网络无关的规则。这一条在测试里有专门的反向对照。

### 2.4 拒绝按原因记账，不并成一个数

`skipped` 是 list[{x, y, source, reason, ...}]，`skip_counts` 只是它的汇总：

```
no_pour_here            这一点没有该网的填充铜
pour_edge_too_close     离填充边界不足 半径+clearance
too_close               异网铜太近（带 with / with_net / gap_mm / with_pad）
hole_too_close          与已有钻孔太近（不按网）
too_near_board_edge     离板边不足 edge_mm
existing_via            与已有过孔重叠
on_same_net_pad         落在同网焊盘上（via-in-pad 是另一个工具的事）
no_room_around_signal_via  信号过孔四周全满，放不下回流孔
outside_board           落到了板外
```

`skip_counts` 之和 == `skipped_total`；这条在测试里断言。

### 2.5 差 0.05 mm 的点不丢：nudge

网格点被拒，若原因是**局部**的（`pour_edge_too_close` / `too_close` / `hole_too_close` /
`on_same_net_pad` / `existing_via`），按 `nudge_mm`（默认 0.4）在 8 个方向上试挪，
`nudge_mm/2` 先试。挪成功记 `nudged` 计数。

**`no_pour_here` 不挪**：那说明这一点没有铜，挪 0.4 mm 也不会凭空长出铜来——
去找铜是搜索，不是微调。

### 2.6 换层信号过孔旁的回流孔

对每个 `net != GND` 的过孔：若 `near_via_mm`（默认 = pitch）内没有任何同网过孔，
就在它旁边放一个地孔。方向先试四条对角线（同 pitch 内，且不占信号过孔自己的轴线），
距离先试「两个环形刚好 clear」的一步，再试 1.6 步 —— 扇出区里一圈空间经常是满的，
0.9 mm 外的回流孔仍然比没有强得多。

## 3. 实测（F412 核心板 v36 → v37）

```
board_stitch_vias(audit)  ：existing 0 / gaps 104 / 44 个换层过孔全部无回流
board_stitch_vias(place)   ：placed 114（103 网格 + 11 回流，40 个挪过）
                             skip: no_pour_here 98, pour_edge_too_close 33,
                                   no_room_around_signal_via 33
写入后 audit                ：existing 114 / gaps 104→5 / 无回流 44→14
board_drc(refill=true)     ：74 条，clearance 0，逐类与加孔前相同
```

- **重铺后逐类相同**才说明这 114 个孔是真的没引入违规；不重铺的数（111 条）不能用来判这件事。
- `no_pour_here` 98 是因为网格铺在填充的包围盒上，而板中间有大量走线让出来的通道 ——
  这些点**本来就不该有孔**，它们不是缺口。
- 剩下 33 个信号过孔四周确实没地方：如实报，不硬塞。

## 4. 诚实边界

1. **「多少个才够」不是我算的。** `pitch_mm` 是调用者给的策略参数；低速板 2–5 mm
   是经验值。工具只回答「按这个 pitch 还差哪些点」。
2. **间距是本服务器量的，不是 KiCad 判的。** 与其它几何工具一样，
   `authoritative: false`；最终判词只能由 `board_drc` 给。
3. **只加孔，不动线。** 没有寻路、没有推挤、没有自动布线。孔位是网格 + 局部微调。
4. **差分对/跨分割的回流问题不在本工具内**，那属于 `board_cross_split` 那一条线。
5. `board_45_corners` 与本工具都只碰「几何」，都不判断某个网络在电气上是否需要。

## 5. 顺手修掉的诚实性缺陷

`skills/pcb-layout-methodology/references/07` 在 0.0.116 里写过 `board_stitch` / `return_path`
两个**不存在的工具名**（`board_route` 已被禁用）。本版改成真名 `board_stitch_vias`，
并写明那批 `via_*` / `pdn_*` / `thermal_via_array` 回答的是「这个孔行不行」，
不是「这块板缝没缝上」。
