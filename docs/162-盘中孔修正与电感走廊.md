# 162 盘中孔从 61 修到 9，以及「删铜不是答案」

用户这一轮的原话是三条判词：

> 「1盘中孔工艺不能用焊盘打孔会导致工艺缺陷　2还是在电感底下走线了　3布局和走线简直就是坨狗屎」

本篇只写**能量到的三条**，以及一条被实验锁死的负面结论。**缺陷 ② 和 ③ 没有修完，本篇不写成修完了。**

## 1 盘中孔：61 → 9（严格口径）

起点是 `_v25h`：`_vip9.py`（严格口径＝过孔**完全**落在某焊盘铜内）报 **15** 个，`_audit_vip.py`
（宽口径）报 61 个。宽窄差别在于「孔心在盘内」还是「整颗孔都在盘内」。

做法是狗骨（dogbone），不是换焊盘、也不是加 fill note：

- 孔移到焊盘旁边，靠一根短颈接回焊盘；孔不再穿过焊盘铜。
- 落点只在**八个晶格方向**上搜，所以颈和板子其余铜一样是 0/45/90；
- 三档尝试：原尺寸直颈 → 一次折颈 → **缩孔**（body 缩小，drill 同步缩）。

缩孔这一档踩到两个真规则，都是 DRC 逼出来的，不是猜的：

| 约束 | 数 | 来历 |
|---|---|---|
| 孔环（annular ring）≥ 0.05 | `(size - drill)/2` | `kicad-cli` 报 `annular_width` 实际 0.0300 / 最小 0.0500 |
| 孔径 ≥ 0.15 | `drill` | 板厂可制造下限；0.14 的孔不值得为省一颗盘中孔去换 |

第一版缩孔写的是 `drill = min(drill, size - 0.06)` ⇒ 0.26/0.20 得到孔环 **0.03**，DRC 立刻多一条
`[annular_width]`（`Via [/FB_U5] @(37.2000,-21.6600)`）。改成 `size - 0.12` 后孔环 0.06 达标，但
`min(v['drill'], size - 0.12)` 会把**原尺寸**档也一起掐掉（0.20/0.10 的孔算出 drill 0.08 < 0.15），
导致 15 个全判「没有落点」。正确写法是**只对缩孔档**改 drill：

```python
drill = v['drill']
if size < v['r'] * 2 - 1e-9:              # 只有缩孔档才动 drill
    drill = min(v['drill'], size - 0.12)  # 孔环 >= 0.06
    if drill < 0.149:                     # 没有 0.15 以下的孔
        continue
if (size - drill) / 2.0 < 0.045:
    continue
```

交付板 `_v27c`：**修掉 6 个**（`SW1.2 /RESET_N`、`SW1.3 /GND`、`R2.2 /GND`、`SW1.4 /GND`、
`FB1.1 /+0V9_LOGIC`、`U2.F3 /DDR_DQS0P`），严格口径 15 → **9**。

三道门：

- `kicad-cli pcb drc --severity-all`：**41 violations + 8 unconnected**，
  `29 via_dangling + 11 lib_footprint_issues + 1 zones_intersect + 8 unconnected`，
  与基线 `_v25h`（49 = 29 + 11 + 8 + 1）**逐类别、逐条数相同**；
- `_vip9.py` 严格口径复核 **9**；
- `_refill.py`（官方 `ZONE_FILLER`，5 个 zone）在 DRC 之前跑过——加过孔会让铺铜填充过期，
  不重铺就会凭空多出 `实际 0.0000 mm` 的过孔对铺铜违规。

**剩下 9 个如实点名**，各有各的原因，不许合并成「几何不可能」：

| 焊盘 | 网 | 孔 | 卡在哪 |
|---|---|---|---|
| `C2.2` | /GND | 0.20/0.10 | F.Cu 单层接铜，四周被 B.Cu 的 SDMMC 走廊堵死 |
| `C5.2` | /GND | 0.20/0.10 | 四层全接铜（B/In4/In2/F），任一方向挪出去都会断别的层 |
| `FB1.2` | /+0V9_PMU | 0.20/0.10 | 电感两垫之间，两侧 0.25 内没空 |
| `R3.2` | /FB_U5 | 0.40/0.20 | 缩到 0.26 要 drill 0.14 < 0.15 |
| `U3.8` | /+3V3 | 0.50/0.20 | 0.50 的孔在 0.5 间距引脚行里无位可挪 |
| `C2.1` | /+0V9_CPU | 0.40/0.20 | 三面被自身网络的 B.Cu/In4 铜围着 |
| `U6.3` | /FB_U6 | 0.45/0.20 | 同上，且邻近焊盘 gap 只 0.684 起点就是孔 |
| `C9.1` | /BS_U4 | 0.40/0.20 | 邻近 gap 0.650 |
| `U3.2` | /FSPI_D1 | 0.20/0.10 | 邻近焊盘 gap 只有 0.127，连 0.10 的孔都放不下 |

## 2 缺陷 ②「还在电感底下走线」：机制量清了，没修完

先量，不猜。`_gapdump.py` + `_band.py`（都只读）：

- 电感两焊盘之间那道缝（`L1` = x 30.9..31.9 / y −27.45..−23.75）里 **33 段外来铜**：
  `RMII0_CLK 9, RMII0_TXD0 7, SDMMC_CMD 5, RMII0_TXEN 5, RMII0_MDC 3, SDMMC_D2 2, RMII0_RXD0 1, +0V9_LOGIC 1`。
- 把口径放大到**整个器件体**（x 29.2..33.6 / y −27.45..−23.75，含焊盘下方）：
  **82 段、13 个外来网**——`F.Cu 9 段 3 孔 / In2.Cu 19 / In4.Cu 15 / B.Cu 39`，本网只有 `SW_U4` 与 `+0V9_CPU`。
- 原因不是布线器偶然：这 13 个网是 **BGA 往东的扇出走廊**（RMII0/SDMMC/USB0/RMII1），
  走廊的方向正好是西南→东北的 45°，而 `L1`（连同 U4/C2/C9 的 buck 回路）**正坐在走廊上**。
  也就是说这是**布局**问题，不是布线问题。
- 顺带量到一个可利用的空区：`L1` 器件体**正北**（x 29.2..33.6 / y −20.5..−23.75，3.25 mm 高）
  在**全部六层上零铜、零焊盘**。这是走廊本该走的地方。

为什么这一轮没动：把这 13 个网绕到北侧空区要整体挪走 `BGA→东` 的扇出通道，涉 82 段、
6 个缝内过孔、4 个层；而搬 buck 簇（`U4+L1+C2+C9` 等五簇）虽然可以做**刚体平移**保住 SW 回路，
但 `tools/route_som.py` 的功率铜是 **200+ 个绝对坐标路点**的手写表，簇一挪整表要重推。
**这是工程量，不是判断争议**，本条如实记为未完成。

## 4 生成端断根：`tools/route_som.py` 反过来判

缺陷 ① 的**生成端**根因在这张表：`VIAS` 里 45 条全是「孔打在焊盘正中心」，`audit()` 的规则
写的是「via 必须**塞得进**焊盘」（`min(pad w,h) < size` 就报问题），`route()` 用
`add_via_in_pad` 落盘。也就是说这个工具以前是**主动生产**盘中孔的。

本版把三处全部反过来：

- **`audit()`**：`min(pad) < size` 这条撤掉，改成「**必须存在一个不在焊盘铜里的落点**」。
  规则不再是「塞得进去」，而是「塞不进去才好」。
- **落点搜索 `via_slots()`**：八向晶格、半径 0.25..2.20（步进 0.05）、
  跳过「压住自己焊盘」「离别的焊盘/走线 < r + 0.10」的位置；**首选方向＝来线方向**，
  这样来线是**共线延长**而不是拐弯。
- **终判用真检查器**：候选落点不看角度推理，而是把整条走线喂给 `chamfer()` + `assert_45()`，
  逐边要求 0/45/90/135 且无零长边。这一步是必须的——只保证「新边本身是晶格方向」不够，
  实测仍会撞出 `corner turns 135.00 deg` 与 `zero-length edge`。
- **`route()`**：`add_via_in_pad` 换成 `add_via`（落在槽位）+ 一条 `F.Cu` 颈（宽 0.15，
  焊盘中心 → 槽位）；`TRACKS` 里原本落在焊盘中心的路点由 `via_shifted()` 改到孔位，
  改法是**插入一个折点**让两条新边都落在晶格方向上（`_lpath()`），不是把端点硬拽过去。

读数：45 条里 **43 条拿到合法槽位**，2 条（`L4.1` 0.45、`C1.1` 0.40）在八向 2.20 mm 内
**一个合法落点都没有**（`_band` 式统计：分别有 51 / 110 个候选被终判驳回）。
这两条**报出来、不隐藏**：

```
VIA IN PAD (no dogbone home, reported not hidden): L4.1 (0.45 via), C1.1 (0.40 via)
```

`--audit` 仍以 0 退出（否则 `--route` 就整块不可用了，等于把这个工具的产线掐死），
但这行字每次都会打；真正的修法是改封装或改布局，不是把搜索半径放大。

**没验到的部分**：本版没有做「整板重生成 + DRC 对拍」，因为 `examples/rk3506_som` 那张板
已经带着上一次生成的铜（45 孔 / 4209 段），`--route` 再跑一遍会叠铜，手上没有未布铜的起点板。
所以生成端这一版的证据是**同一条 `assert_45`/`chamfer` 门**（`audit()` 内部就调 `via_shifted()`），
不是整板 DRC。这一条登记为欠账。

## 5 被实验锁死的负面结论：删铜不能替代重布线

上一轮为了收拾「穿缝铜」试了四种剪枝，全部失败，写在这里免得下一个人再走一遍：

| 工具 | 判据 | 结果 |
|---|---|---|
| `_prune.py` | 启发式死端 | 删 95 段（含 6.8 mm 主干），过剪；且 `b.Remove()` 后 `GetTracks()` 失效（`TypeError: 'SwigPyObject' object is not iterable`）⇒ 必须先全量 prefetch 到 Python 结构、算完再统一 Remove |
| `_prunedrc.py` | DRC 驱动逐段剪 | 31 → 19 → 15 → 12 段，但 `via_dangling` 31→34、`unconnected` 11→11，收敛极慢 |
| `_stubs.py` | 零焊盘连通分量 | 删 140 段后 DRC **恶化**：`track_dangling 31→46`、`unconnected 11→18`（0.07 mm 短腿导致焊盘连接漏判） |
| `_despur.py` | 从松散端回溯到分叉点整段切 | 形态最正确，但切 61 段/3 孔后 `track_dangling 31→26` 而 `unconnected 11→16` ⇒ **被切掉的其实是某些焊盘唯一的铜** |

结论写死：**断裂的网只能重布，不能靠删铜收拾**。另外「全新信号布线」这条路也不通——
`route_som_signal.py` 在全拆 23 网的板子（`_v26e`）上跑到第 4 个网就
`RESET_N REFUSED / FB_U5 REFUSED / SAI0_SDI1 OK / SAI0_SDI0 REFUSED`，
当前迷宫布线器在拥挤板面上的成功率远低于增量补线。

## 6 口径

- 判官永远是 `kicad-cli pcb drc --severity-all`，`copper_clearance` 只当粗筛（0.1.24 已写死）。
- 端起 DRC 必须把同名 `.kicad_pro` 放好，否则 netclass 读不到、读数不可比。
- 加过孔/移动过孔之后必须官方 `ZONE_FILLER` 重铺，否则多出全是「过孔对铺铜 0.0000」的假违规。
- 交付图必须自己先看过再给。
