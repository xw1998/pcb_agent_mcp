# 27 自动布线器：搜索是提议，精确几何才是判决

这一篇记的是 `board_route`（`route/{rules,grid,router}.py` 三个模块）从零到能在一块真实的
50 网核心板上跑完的过程，以及在这一轮里被抓出来的五个**真缺陷**——其中四个会让工具在
「看起来布线成功了」的状态下给出错答案，这正是本项目最不能容忍的错法。

一句话结论先放在这里：

> **栅格只负责提议，精确多边形几何才是判决；两套栅格（走线/过孔）必须分开；凡是搜索没走到的
> 地方就不能说「没有路」；凡是铜没有真的接到焊盘上就不能说「这个网布通了」。**

## 27.1 规则：三个来源，每个来源都要写清是谁给的

布线器的每个数字都必须能回答「谁说的」。`route/rules.py` 的解析次序：

1. **调用方**（`clearance_mm` / `track_mm` / `via_*`）——最高优先，来源记 `"caller"`；
2. **板内 `(net_class ...)`**——v6/v7 时代写在 `.kicad_pcb` 里的那一份；
3. **`.kicad_pro` 的 `net_classes` / `netclass_assignments` / `netclass_patterns`**——通配匹配，
   取该网络实际命中的类；
4. 同一个数在多个来源里出现时，取**最严**的那个（网络类之间也是最严取胜）；
5. `edge_clearance` 这类板里根本没有的事实：**不设 0、不猜**，如实写进
   `assumed: [{"fact": "edge_clearance", "value": null, "why": ...}]`，并且
   `sources["edge_clearance"] = "not in the file"`。

**板里一条 clearance 都没有时，`RULES_ABSENT` 直接拒绝**（fail closed）。这条不是形式主义：
一个「按经验取 0.2 mm」的默认值，会让整块板在别人家的工艺上重画一遍。

来源三元组在输出里逐项公示：

```
"sources": {"clearance": "net class Default", "track_width": "net class Default",
            "via_diameter": "net class Default", "via_drill": "net class Default",
            "edge_clearance": "not in the file"}
```

测试 `TestRulesAreResolvedNotInvented` 三条：值来自网络类且来源写对；空板拒绝且 hint 里
写明「will not guess」；调用方覆盖后来源变成 `"caller"`。

## 27.2 双栅格：一张图回答不了两个问题

「这里能不能放一条 0.25 mm 的线」与「这里能不能打一个 0.6 mm 的孔」，答案不一样：

* 走线栅格的 margin = `clearance + track/2`；
* 过孔栅格的 margin = `clearance + via_dia/2`。

合成一张（取大的）会把所有 0.5 mm 间距的焊盘整排封死——相邻焊盘的铜离焊盘中心只有
0.35 mm；合成一张（取小的）则让搜索把过孔放在精确检查随后否掉的位置：F401 核心板上
**50 个网里有 7 个是这么失败的，失败原因全部是过孔上的 `clearance`**。

所以两张图并存，`free()` 查走线图、`free_via()` 查过孔图，A* 里的换层动作只查过孔图。
测试 `TestRastersArePessimistic` 直接盯这一点：距铜边 0.4 mm 处「线可走、孔不可走」，板外
一律不可走。

## 27.3 精确判定：栅格永远不是证据

搜索提出的每一段铜，落地前都要过 `seg_blockers()`：

* 逐对 `pair_clearance(net_a, net_b)`——不是一刀切用全局 clearance；
* 6 个量级不同的几何用同一个距离函数（pad 多边形、track 线段、via 圆、zone 环…）；
* 包围盒先做粗筛（`hypot(gapx, gapy) >= need` 直接跳过），再算精确距离；
* 被拒的段**保留拒绝理由**（`net / kind / reference / needed_mm / actual_mm / short_by_mm`），
  这是失败报告里唯一能让人动手改的东西。

`TestTheExactCheckIsTheJudge` 不信路由器自己的判决：它在测试里用 `geometry.dist_point_polygon`
**自己**把每条输出线段对那块挡路焊盘采样量一遍，断言 `gap - width/2 >= clearance`。

## 27.4 A*：四个必须项

| 项 | 取值 | 为什么 |
|---|---|---|
| 8 向 + 禁切角 | 对角移动前先查两个正交邻格 | 允许切角会产出物理上不存在的对角穿越 |
| 转向代价 | `TURN_COST = 0.55`（格距单位） | 没有它就是一地楼梯；有它才是「尽量一段直」 |
| 过孔代价 | `VIA_COST = 9.0` | 一次换层≈9 格，等于「能同层就同层」 |
| 搜索预算 | `MAX_BUDGET = 400000` 节点 | 超了要**说超了**，不能说「没有路」 |

最后一条是本项目的老规矩的直接应用：**预算是搜索的停止原因，不是几何的结论**。
预算耗尽时 `diag["budget_hit"] = True`，失败码写成 `search_budget`，与真的没有路
（`no_path`）分开报。调参实测：预算 400k 与 150k 的结果**完全相同**（29/50、469 ops），
说明失败网并没有耗尽预算——它们是「可达集被走完了」，所以默认预算维持在 400k 不动。

## 27.5 事务化：一个网的铜只在这个网成功之后才进图

`_Emitter` 三态：**buffered**（过了精确检查，但网还没布完，**不进图**）/ **committed**（网布完，
进图并占位）/ **rolled back**（网失败，缓冲丢弃，拒绝理由留着）。

为什么必须是这个形状：如果边搜边占，一个最终失败的网会在图上留下半条路，后面每个网都要
绕着一段**不存在的铜**走，而且这块板写出来以后没有人会知道为什么绕。

rip-up 需要「撤掉若干个网的铜再重来」，而图的单元与空间哈希没有 per-net undo，所以
`forget(nets)` 的做法是**重建**：把剩下的 ops 重新 `_replay` 进一张新图。慢，但不会留下一张
「记着已被撕掉的铜」的图。

## 27.6 性能：229 s → 41.4 s，逐条说改了什么

12 网的控制实验（cProfile，旧实现）：

| 位置 | 时间 | 调用数 |
|---|---|---|
| `astar` 总计 | 204.8 s | — |
| `grid.free()` | 63.2 s | 71.4 M |
| 其背后的 `dict.get` | 53.3 s | 140 M |
| 过孔门 `_via_gate` | 33.5 s | 9.7 M |
| `_mark_cells` | 23.1 s | — |
| `Grid.__init__` | 21.2 s | — |

改法（全部是「同一个逻辑换成一次乘法」这一类，不改语义）：

1. `dict[(layer, i, j)] → int` 换成**每层一个扁平 list**，状态编码 `0`=全网可走、`-1`=全禁、
   `k>0`=第 k 个 interned 网集合（`_sets[k-1]` 是 tuple，`_set_ids` 用 frozenset 做键）；
2. A* 内联读栅格（`mp[nj * nx + ni]`），goal 层用 int 索引表，`best / parent` 用整数标量键
   `((node) * nlayer + li) * 9 + d`；
3. 过孔门**每节点算一次**（`via_memo`）而不是每节点每层一次；
4. `_mark_cells` 两套 margin **一趟走完**（每格只做一次距离计算，按 d 与两个 margin 的关系
   分别写入两张图）；
5. 轴对齐矩形（4~5 点且顶点集==bbox 四角）走**角差/到边距离**的快路径，与
   `dist_point_polygon` 结果一致，缓存在 item 上。

结果：**12 网 229 s → 41.4 s（5.5×），`rejected_ops: 0`**（没有因为提速放过任何一段）。

> 注：本机在同一时段还有别人的 4 个实验进程占满 CPU，所以文档里所有**绝对秒数**都要打折看；
> 上表是同一进程内的前后对比，加速比不受影响。

## 27.7 全板 50 网：失败是争用，不是几何

F401 核心板（`_scratch/core/stm32f401re_core.kicad_pcb`，53.34 × 30.48 mm，4 层，32 封装 /
194 pad / 51 net / 0 zone），`rip_up_rounds=0, second_sweep=False, pitch=0.1`：

* **本次出货代码：27/50 布通，461 ops，102.9 s**，失败 23 个：
  `SWDIO PA5 PA7 PA4 PA6 PC14 PA1 PB10 PA0 VCAP1 PB7 PB2 XTAL_IN PB6 PB1 PB5 PB0 PB4 PB3 PA15 PD2 LED2_A LED1_A`
* 修板边距之前同一个 baseline 臂是 **29/50、469 ops**，多出来的两个正是 `LED1_A` / `LED2_A`
  ——它们当时是把铜贴在 y = −0.4 溜过去的（铜边距板边 0.275 mm，见 §27.9.6）。**那两根不算布通，
  它们是非法铜**；所以真实的起点是 27，不是 29。

决定性对照（这一条推翻了我自己的假设）：

| 臂 | pitch | 结果 |
|---|---|---|
| 6 个失败网（`SWDIO PA5 PA7 PA4 PA6 PC14`）单独布 | 0.1 mm | **5/6**，37 ops，8.3 s，只剩 `PA6` |
| 同上 | 0.05 mm | **5/6**，42 ops，23.1 s，只剩 `PA6` |
| 再加一条对照：`PA6 + PA5` 两条 | 0.1 mm | **2/2 全通**，`failed=[]` |

同一批网在空板上基本都布得通，细栅格也没有更好（细了一倍反而多花 2.8 倍时间）；`PA6` 丢的
原因是这五条同批的网就在它旁边——**所以 27/50 的差距来自先布的铜占位，不是细间距逃逸**。
这条直接把「必须更细的栅格」这个假设否掉，也把 rip-up 的重要性顶到第一位。

## 27.8 rip-up：按位置挑牺牲者

旧写法撕「最短的几个网」，理由是「短的便宜」。实测站不住：挡路的网可能长在板子另一头，
撕它一点用没有。现在按**物理重叠**挑：

* 取失败网所有焊盘的包围盒，外扩 1.5 mm；
* 与**已经真正发出去的** ops（track/via）求交，统计每个网络命中几段；
* 取重叠最多的 3 个非平面网作为牺牲者，`forget` 它们，重布「失败者 + 被撕者」；
* `rip_up_rounds` 的语义是「**对每个仍失败的网各做一次定位 rip-up 的遍数**」，不是「总轮数」；
* 只有 loser 与被撕的网重跑，其他网的铜不动（旧代码每轮把 `routed[3:]` 全部重跑，实测每轮 20 s
  纯浪费）。

`stats["rips"]` / `stats["rip_passes"]` 如实回报撕了几个、跑了几遍。

### 27.8.1 两臂实测：+11 个网，代价是 5 倍时间

同一块板（`_scratch/core/stm32f401re_core.kicad_pcb`，栅格 534×305 = 162 870 cells），
只改开关，代码同一份：

| 臂 | 开关 | 布通 | ops | 耗时 |
|---|---|---|---|---|
| baseline | `rip_up_rounds=0, second_sweep=False` | **27/50** | 461 | **102.9 s** |
| sweep + rip | `rip_up_rounds=1, second_sweep=True` | **38/50** | **351** | **521.8 s** |

`rips=64 / rip_passes=1 / sweeps=2 / rejected_ops=0`。两臂失败网清单：

* baseline 失败 23 个：`SWDIO PA5 PA7 PA4 PA6 PC14 PA1 PB10 PA0 VCAP1 PB7 PB2 XTAL_IN PB6 PB1 PB5 PB0 PB4 PB3 PA15 PD2 LED2_A LED1_A`
* sweep + rip 失败 12 个：`GND +3V3 PA7 PA6 PC15 PB13 PB12 PB10 VCAP1 PB7 PB2 PB6`

读法有三条：

1. **净赚 +11 网不是靠多画铜**——ops 反而从 461 降到 351。被撕掉的 64 段旧铜没白撕，
   重布之后总铜量更少、连通更多。
2. **GND / +3V3 进来了**：这两个平面网在 baseline 里就是失败项，sweep 之后它们变成
   失败清单的前两位 —— 说明它们是**最后才被尝试的长网**，而反向 second sweep 让短网先落地，
   长网拿到的是「别人已经占位」的图。这不是回退，是排序换了；但这条也说明**平面网不该
   跟信号网用同一个 8 方向 A\***（它们本该靠铺铜解决，见 §27.10）。
3. **绝对秒数只做参考**：两臂都是本机跑、但不同时段机器负载不同（同一份代码的 baseline
   早先量到过 221.5 s，另一天量到 102.9 s）。可比的是**同一进程内前后两臂的比值**：
   rip-up 要 `forget()` 重建整张图（162 870 cells × 4 层）再重放全部已发 ops，一轮总值 ≈5 倍，
   这是真实开销。次可比的是**同一台机器上的两次 sweep+rip**：451.3 s → 521.8 s 就是板边距
   那三处检查的价格（+15.6%）。

## 27.9 本轮抓出的五个真缺陷

这五条都不是「写得不好看」，而是**会在成功状态里给出错答案**，所以逐条记下来。
前四条是写测试和写代码时自己发现的；第五条是**跑完端到端、拿 kicad-cli DRC 当裁判**才现形的
——这也正是它值钱的地方：前四条的错法在工具自己的日志里看不出来，第五条的错法在自己眼里也
看不出来。

### 27.9.1 越界下标在 Python 里会**回卷**

栅格是扁平 list，`free(i, j)` 用 `j * nx + i` 取值。问一个板外 5 mm 的点（`i = -50`）时，
下标回卷到板上某个**普普通通的空格**，于是「板外」被回答成「可走」。路由器自己不会问这种点，
但任何按坐标查询的调用方都会。修法：`index(i, j)` 越界一律返回 `None`，`free / free_via`
返回 False，`blocked_reason` 回 `off_board`。

### 27.9.2 keepout 只封了**边框一条带**

第一版沿用铺铜的写法：把距 ring 小于 margin 的格子标成禁行。结果是 keepout 的**内部**完全
可走——搜索直接从框里穿过去，还理直气壮地说这里空着。真值显然相反：keepout 禁的就是「框里
有铜」这件事。修法：keepout 额外做 `point_in_polygon` 判定，命中即 `d = 0`。

修的时候还踩了第二个坑：这个判定最初写在 `d >= m`（m = 两个 margin 的较大者）**之后**，
于是在 `[m_track, m_via)` 这一条带里，走线图说「可走」、过孔图说「不可走」——同一块铜上两张
图互相矛盾。现在判定放在两个 margin 决定任何事**之前**。

### 27.9.3 精确判定里**根本没有 keepout**

`seg_blockers` / `via_blockers` 只看铜的 clearance，keepout 只活在栅格里。于是「栅格说能走、
精确判定说干净」可以同时成立，而铜实实在在横穿了一个 keepout。修法：keepout 进
`self.keepouts`（ring + 层 + tracks/vias 标志 + bbox），精确判定新增：

* 线段：端点在环内 / 与环边相交 / 到环边距离 < `width/2`，三者任一即拒；
* 过孔：圆心在环内 / 圆环与环相碰即拒；
* 且**尊重 `(keepout (tracks allowed))` 这类标志**——一个只禁过孔的 keepout 不该把走线也封死，
  否则后面每个网都在绕一条板文件里根本不存在的规则。

包围盒先做四则比较再算距离：`_via_gate` 在 A* 里是**逐节点**调用的（60×40 mm 板 0.1 mm 栅格
= 24 万节点 × 4 层），任何一个 per-keepout 的距离计算都会变成热点。

### 27.9.4 焊盘逃逸链路：网说「布通了」，铜却没接到焊盘上

`_free_terminal` 在焊盘中心被别人的铜光环盖住时，会退到最近的空格作为起点（真实场景：连接器
底下藏测试点、焊盘落在别人 footprint 的 courtyard 里）。但**从焊盘中心到这个起点的这段铜，
第一版从来没画过、也没检查过**——A* 从那个空格开始布线，于是输出的第一段线离焊盘 1~2 mm，
什么都不挨着，而 `status` 是 `routed`。

修法：这段链路当成一段普通铜——走 `em.track()`（与其他段同一个精确判定），失败则整网拒绝，
失败码 `terminal_unreachable`，并带上「焊盘 / 逃逸点 / 被谁挡住」；成功则在 `notes` 里写明
「有 N 个焊盘的格子被占，已接到最近的空格」。

### 27.9.5 修完之后失败更快也更准

同一块测试板上的 `WALLED` 网（焊盘落在 keepout 正中）：

| 版本 | 判定 | 耗时 |
|---|---|---|
| 修之前 | `search_budget`（跑完 24 万格才放弃） | 9.3 s（单遍） |
| keepout 内部封住之后 | `no_terminal`，detail 里写明 `J4.1 at (40,20)` 被 keepout 挡 | 0.17 s |

「报错快」只是顺带的；值钱的是理由从「我没找到」变成「这块焊盘离不开，因为它在 keepout 里」。

### 27.9.6 板边距只管过孔、不管走线

`via_blockers` 里有 `too_close_to_edge`，`seg_blockers` 里没有。看起来像「顺手漏了一行」，实际
后果是**工具亲手往板边写非法铜**：这块板的 net class 里只有 `clearance 0.2 / trace 0.25`，没有
`min_copper_edge_clearance`，而 KiCad 不因为没有 `.kicad_pro` 就不查板边——它用板设置里的默认
0.5 mm。于是 `LED1_A` / `LED2_A` 两根网从焊盘直着往板边走，走在 y = −0.4（铜边距边 **0.275 mm**），
路由器把两个网都报成 `routed`，`apply` 的四道闸门也全绿（那时候 DRC 闸门还没把
`copper_edge_clearance` 当阻断项看）。

`kicad-cli pcb drc` 的读数把这件事钉死了：**6 条 `copper_edge_clearance`，全部指向这两根网的
Track**，`最少 0.5 mm / 实际 0.275 mm`。

修法分三处，缺一不可：

1. **规则**：`edge_clearance_mm` 没有来源时不再留空，取 KiCad 板设置的默认 **0.5 mm**，并写进
   `assumed` 里说清楚「文件里没有，但裁判会按这个查，所以按这个来；要换就传 `edge_clearance_mm`」。
   这里第一次没沿用「缺规则就拒」：板边距是**关于板**的规则，不是两个网之间的规则，一份没有
   `.kicad_pro` 的板照样躲不过 DRC，留空等于假绿。
2. **栅格**：`_mark_edge()` 沿 Edge.Cuts 每一条边封一条 `edge + track/2` 宽（过孔图
   `edge + via/2`）的带，**对每个网都封**（`-1`）。这条带不进图，搜索就不会把「贴着板边走」
   当成近路去试。
3. **精确判定**：`_edge_for_segment()` / `_edge_for_via()` 算「铜到 Edge.Cuts 的距离」——
   与 keepout 同一套写法（bbox 预热 + 线段/点距离），因为**栅格永远不是证据**。

一根网被板边挡住时的读数是**「这个网布不通」**，不是「路由到了板边」。宁可少布一根网，也不
往板边写铜。

### 27.9.7 端到端：自己的闸门绿不算绿，`kicad-cli` 说绿才算

修完五条后，把整条链路跑一遍（**同一份代码**，`rip_up_rounds=1, second_sweep=True`）：

| 环节 | 读数 |
|---|---|
| `board_route` 计划 | **38/50**、351 ops、**521.8 s**、`rips=64`、`sweeps=2`、`rejected=0` |
| `propose` | `blocking=[]` |
| `apply`（`engine:true`） | `status=ok`、18.6 s、`new_blocking_total=**0**`（新增 4 条 advisory，旧账清掉 4 条，总账 69 → 69） |
| `kicad-cli pcb drc`（独立裁判） | 69 条，全是既有 silkscreen/text 告警；**shorting_items 0 / tracks_crossing 0 / clearance 0 / copper_edge_clearance 0** |
| `unconnected_items` | 71（对应的就是那 12 个没布通的网，不是新增断裂） |

板边修好前后的差别就两行：**修前 6 条 `copper_edge_clearance`（全部 error）、布通 38/50；
修后 0 条、布通还是 38/50**。也就是说，那 6 段贴着板边的铜既没换来一个布通的网，又让整块板
Dirty——比「少布一根网」差得多。代价是计划时间 451.3 → 521.8 s（+15.6%），因为过孔门在

**仍然没做的，照旧不假装做了**

* **多端网拓扑优化**：还是 Prim MST 降序，不是 Steiner，也不是「先布短线再布长线」的全部变体。
* **热焊盘（thermal relief）**：焊盘接铺铜的辐条形状没做，也不改。`board_route` 只在报告里说铺铜过期了。
* **铺铜重填本身**：知道过期，不等于会重填。重填仍然是 KiCad 自己的事（`kicad-cli pcb drc --refill-zones`
  或编辑器里点一下）。
* **异形 pad 的圆角**：`roundrect` 有半径，异形 pad 走的是多边形距离，图元里的 `gr_arc` 是按弦近似，
  圆角半径意义上的精确弧长不做；多图元的凸包对凹形 union 会偏严。
* **差分对的共模 / 对内等长之外的东西**：共模阻抗、对间串扰、拐角处的电场优化都不做。
* **回流路径的真板 DRC 取证**：只有单测（`TestALayerChangeGetsAGroundVia`）与真板上
  `nothing_to_stitch` 的读数，**没有**「缝合后的板子跑 `kicad-cli pcb drc` 变干净」这条证据。
* **立创 Pro 写路径**：`verified_against_app` 恒为 `false`——vendor 的写方法名本机一步都没验过，
  工具只保证「你的 snippet 真的改变了设计」，不保证它写出的东西是对的。
* **拥塞协商的普适性**：读数只有一块板（38→41）。它默认关闭，就是这个原因。

写了 `routed` 不等于 DRC 干净：`board_route` 的 `precision` 一栏写死「跑 `board_drc` 复核」，
`apply=true` 时铜走的仍然是 `board_propose + board_apply` 那五道闸门 + KiCad DRC 裁判。

## 27.11 爬电 / 等长 / 差分对：三条距离规则怎么进搜索

这一节记的是把 `kicad-free` 与 `rf-circuit-design` 里那几条**走线规则**变成搜索里的约束之后，
`board_route` 到底多知道了什么、又到底多不知道什么。三条规则的形状完全不同，所以处理方式也不同：

| 规则 | 来自 | 本质 | 在搜索里的位置 |
|---|---|---|---|
| 爬电距离 | 安规（IEC 60664 那一类表） | 一个**必须由人给**的距离 | 全局最严间距，进栅格 + 进精确判定 |
| 差分对间距 / 同宽 | `rf-circuit-design`§3.4（对内 5 mil、45°、禁直角） | 一条**局部**最小间距 | 每对各自的数，进栅格 + 进精确判定 |
| 等长（对内 < 5 mil） | `rf-circuit-design`§3.4 | 一个**全局**长度目标 | 后处理：布完之后加蛇形 |

### 27.11.1 爬电距离：只认调用方给的数值，没给就是没施加

规则层（`rules.py`）有一条写死的红线：

> `creepage_mm` 只有 caller 给值才用（`sources["creepage"] = "caller"`），否则
> `sources["creepage"] = "not supplied: creepage comes from a standard table keyed to working
> voltage / pollution degree / coating and is never invented here"`，并且**不写进 `assumed`**。

依据是 `kicad-free` 技能自己的一句话：「不编造安全间距：安规爬电距离必须按适用标准与电压等级
查表，本技能不给确定值」。既然技能文档都不敢给数，这个工具也不该给。把 0.2 mm 的电气间距当爬电
是最典型的「看起来合规」错答案，所以宁可空着。

给了值之后它要**同时**进两个地方，缺一边就有一边会撒谎：

* **进栅格**：`grid.py` 取 `spacing = max(creepage_max, spacing_max)`，若比电气间距还宽就直接顶掉
  `clr`，连 `margin = clr + track/2` 都跟着变大，并在 `notes` 里公示「a creepage / diff-pair rule
  of X mm is wider than every electrical clearance here, so the raster keeps that distance everywhere
  (the exact check uses each pair's own number)」。栅格是**悲观**的：全板按最严那一个数让路。
* **进精确判定**：`seg_blockers` / `via_blockers` 里原本用 `pair_clearance` 的地方换成
  `pair_spacing = max(pair_clearance, creepage(本对), diff_gap(本对))`，每个网对用自己的数。

只进栅格会让栅格当法官（别的对会被无辜挡）；只进精确判定会让搜索一头撞进违规区，然后在判决时
集体失败。所以两边都进，只是各自的粒度不同。

**真板上的一个诚实结论**：在 F401 那块板上，`creepage_mm=0.4` 会让 `SWDIO/SWCLK/PA5` 三条网
**全部 `terminal_unreachable`**，详情写着 `needed_mm 0.4 / actual 0.2189`——那颗 MCU 是 0.5 mm
间距的，从焊盘之间就出不来线。这不是 bug，是这块板在 0.4 mm 爬电下的物理事实，工具如实报死。

### 27.11.2 差分对：只做「最小间距 + 同宽 + 记账」，不耦合

`diff_pairs` 每项是 `{p, n, gap_mm, width_mm?, max_skew_mm?}`。它的全部作用：

1. `gap_mm` 进上面那个 `pair_spacing`（两网之间永远不许比它更近）；
2. `width_mm` 覆盖两条成员的 `track_mm`（对内必须同宽，别的网不受影响——测试里专门断言了
   「两网 0.2 而第三个网仍是 0.25」）；
3. `max_skew_mm` 让这一对**自动**变成一个等长组（不需要再写一遍 `length_groups`）；
4. 报告里给 `gap_declared_mm / spacing_required_mm / gap_achieved_mm / length_p_mm / length_n_mm /
   skew_mm / coupled: False`。

`coupled: False` 是这一条的重点。两条网是**各自独立**布出来的，间距被当成下限，于是它们不会
肩并肩跑；实测那块板上声明 0.2 mm 的一对，`gap_achieved_mm` 是 **1.65 mm**，状态 `pair_not_coupled`，
note 原话是：

> the two nets are routed with the declared spacing as a minimum; they did not end up running side by
> side and this router does not couple them

耦合跟随（沿 P 偏移出 N、拐角 miter、对内等价长度而不是两条长度）是另一套算法，本轮没做，也
不假装做了——一个「声明了差分对」的调用方看到 `coupled: false` 就知道这个数字不能拿去投板。

### 27.11.3 等长：布完之后加蛇形，而不是布的时候求等长

最短合法路径**必然**长度不对，所以等长不能是搜索约束，只能是后处理。`tune.py` 的做法：

* 目标：`target_mm`，没给就取组内最长那条；只给**偏短**的网加长（不加长就没法缩短）。
* 蛇形：连续 45° 三角波（不用直角，`rf-circuit-design` 禁直角），腿距
  `amplitude = max(3w, 0.5 mm)`（3w 出自 `rf-circuit-design`§3.4 的弯曲最小半径/相邻间距）。
  一整齿加长 `2A(√2−1)`，所以一段线最多能加 `max_extra(L, A) = 0.828·(L−0.5)/2`。
* **最后一齿允许更矮**：把长度落到目标上，而不是落到下一个整齿（否则 0.6 mm 的过冲比原失配更糟）。
* **跨多段分配**：单段装不下就按长度降序换下一段继续，`remaining` 递减、`parts` 记账。
* **每次改铜之前先精确复检**：用 `grid.seg_blockers` 把蛇形拆成小段逐段校验，任何一段被拒就
  整次放弃、一个点都不写（不做「先写再撤」）。写成功才**原位替换** `em.ops` 里那一条 track，
  并调 `em.rebuild()` 从现存 ops 重放重建栅格，让 Map 与铜重新一致。
* 报 `before / after / skew_before_mm / skew_after_mm`，`status ∈ {matched, length_not_matched, reported}`；
  配不上就报 `length_not_matched` 并在 detail 里给 `no_segment_long_enough` / `blocked` 与可达的真实
  数字——**「没配上」≠「没尝试」**，测试就是按这个语义写的（3 mm 的短桩也能被加长约 1 mm，
  只是仍达不到目标）。

真板实测（`SWDIO/SWCLK`，`layers=["F.Cu"]` 禁换层、`rip_up_rounds=0`、`second_sweep=False`）：

| 项 | 值 |
|---|---|
| plan 时间 | 9.2 ~ 10.5 s（三次重复），`failed=[]`，`ops=61` |
| 等长组 `swd`（`max_skew_mm=1.0`） | `matched`：SWDIO 29.6255 → 38.9039 mm（跨 2 段：5.0948 + 4.1836），SWCLK 39.4037 mm |
| skew | **9.7782 → 0.4998 mm** |
| 差分对 | `pair_not_coupled`，`gap_achieved 1.65 mm`（声明 0.2） |
| 端到端 | `board_propose`+`board_apply`：`status=ok`，五道闸门 `['bytes_written','drc','engine','postconditions','token_identity']` 全过 |
| `kicad-cli pcb drc` | 69 条（before 69 / after 69），`new_blocking_total 0`、`new_advisory_total 4`（4 条 `silk_overlap`）；`unconnected 122` |

也就是说：蛇形是在**真实板上**验证过能落地并被 KiCad 接受（铜类新违规 0），而不只是合成用例过。

### 27.11.4 三条规则共同的形状

* **每条规则的「数」只有一个来源，且必须写明是谁给的**：`rules` 块里 `creepage_mm` /
  `creepage_pairs` / `diff_pairs` 与 `sources` 一起返回。
* **规则不能静默丢弃**：非正数、非数字、对里两网相同、坏串（`'A:B:1.0'` 少一截）一律
  `RULES_INVALID`，结构写错则 `ARG_INVALID`。
* **进了搜索就一定要在两处都进**：栅格（悲观、全局）+ 精确判定（每对各自的数），只有一处进就
  必然产生错答案。
* **做不到的部分写在返回值里，而不是只写在注释里**：`coupled: false`、`length_not_matched`、
  `no_segment_long_enough`、爬电的 `not supplied` 都是可见字段。

## 27.12 把 §27.10 的九项欠账做完（0.0.16）

上一版的 §27.10 是一份「没做什么，也不假装做了什么」的清单。这一版把其中九条逐条做完，
每一节都分开写两件事：**机制**（代码怎么做的）与**证据**（单元级还是真板读数）。
凡是只有单测的，这里就写明只有单测——「测试绿了」不等于「真板上量过」。

九项分别为：差分对真耦合 / 回流路径 / 阻抗目标进搜索 / 爬电自动查表 / 拥塞协商 /
连接意图 / 蛇形振幅阶梯 / 异形焊盘全图元 / 新铜使铺铜过期，外加一条立创 Pro 写路径。

### 27.12.1 差分对真耦合：第二条网变成第一条网的偏移副本

`route/couple.py`。`coupled_route` 只用 p 的链（`_chain` 在容差内串起 p 的走线），
把 n 的铜换成这条链的**逐段偏移**：`offset_polyline` 每段平移 `gap+width`，拐角用 miter
（`MITRE_LIMIT = 3.0`，超过 3 倍线宽就退化成两段），偏移结果每段仍走一次 `seg_blockers`
精确复检——**先精确判定再写铜**，和搜索里其他铜一样的门槛。

三条拒绝，都点名原因：

| `why.reason` | 什么时候 | 为什么不能猜 |
|---|---|---|
| `pair_needs_two_pads_each` | 任一条网不是恰好两个焊盘 | 偏移行走有两个端点；第三个焊盘该接哪个分支，工具不知道 |
| `offset_blocked` | 偏移落到别人的铜（或自己参考网的焊盘）上 | 两侧分别报出 blocker 名字与 `short_by_mm`，才能让人知道该挪哪块 |
| `fanout_too_long` | 扇出超过 `COUPLE_MAX_FANOUT_MM = 5.0` | 为了并排跑 5 mm 而绕 20 mm，那不是耦合，是绕远 |

记账新增 `coupled_fraction`（`coupled_fraction(ops, p, n, gap, tol=0.05)`）：第二条网有多大比例
**真的**跑在声明 gap 上。只在对的扇出处挨一下不算耦合的对，所以 `coupled: true` 必须由这个数支撑，
不能由「gap_achieved_mm ≥ gap」支撑。

**真板读数（F401 核心板，`layers=["F.Cu"]`，`gap 0.2 / width 0.2`）**

| 对 | 结果 | 数字 |
|---|---|---|
| `SWDIO / SWCLK` | `pair_not_coupled`，`why.reason = pair_needs_two_pads_each` | `p_pads=3 / n_pads=3`（SWD 连接器 + MCU + 测试点） |
| `PA8 / PA9` | `pair_not_coupled`，`why.reason = offset_blocked` | blocker = `U1.41`（参考网自己的焊盘），`needed 0.2 / actual 0.1601 / short_by 0.0399 mm` |

第二行是这一节最值钱的一条：**同一对 `couple=false` 时读数一模一样**（`gap_achieved 0.3 mm`、
空白 0.3 的来源是两条网各自布的），所以那 0.3 不是「耦合得挺好」，而是「耦合一次都没成功」。
0.5 mm 间距的 MCU 焊盘边上买不到 0.2 mm 的对内间距，这是板子的物理事实；工具的职责是把它点名，
不是把它藏进一个看起来合格的 `gap_achieved_mm` 里。合成板上的成功路径见
`TestAPairCanBeCoupled`（4 个焊盘、gap 0.3、`coupled_fraction > 0.8`、扇出 1.45 mm 全部报出）。

### 27.12.2 回流路径：换层的信号旁边必须有地

`route/return_path.py`，在等长之后做（顺序：耦合 → 等长 → 地缝合）。每颗信号过孔配一颗地过孔：

* `GROUND_REACH_MM = 2.0`：只在 2 mm 内找位置（`RINGS_MM` 逐环 × `_ANGLES` 八方向）；
* `ALREADY_MM = 0.6`：0.6 mm 内已经有地过孔就不再叠一颗；
* 位置必须**精确复检接受**，而且换层两侧都已经有地铜（`_points_on_copper`）——往裸基材里放一颗地过孔
  不是回流路径，是桩；
* `_GROUND_NAMES`（`GND/GROUND/VSS/0V/GNDD/GNDPWR`）**故意不含 AGND**：模拟地与数字地是不是同一个网络
  是设计判断，不让工具替人合并。板上不止一个候选时是拒绝，不是掷硬币。

状态只有四个：`stitched / refused / nothing_to_stitch / not_attempted`。
真板读数：`PA5` 单层布通 7 段 0 过孔 ⇒ `nothing_to_stitch`、`added=0`——**没有换层就没有回流问题，
这个数不是「缝合失败」**。换层场景的证据在单测 `TestALayerChangeGetsAGroundVia`（真板 DRC 尚未补，
这一条本轮没做，别把它当已完成）。

### 27.12.3 阻抗目标：反解成宽度，叠层不明就报错

`calc/impedance.py` 的 IPC-2141A 正/反解（`trace_impedance` / `width_for_impedance`），
`rules.impedance_targets` 把一个 ohm 值变成该网的 `track_mm`，再进搜索——**阻抗是作为宽度进搜索的**，
不是布完再「检查一下」。

两条拒绝：

* `IMPEDANCE_NEEDS_STACKUP`：介质厚度既没由调用方给、叠层里也不是唯一一个 ⇒ 拒绝；不去假设 0.2 mm。
* `IMPEDANCE_UNREACHABLE`：反解落在 w/h 窗口（`W_OVER_H_MIN 0.05`–`W_OVER_H_MAX 3.0`）之外 ⇒
  报错并给出这块叠层能给到的范围。

**真板读数（同一块 F401 核心板）**

| 输入 | 结果 |
|---|---|
| `{net: PA8, ohm: 50}` | 叠层里恰好一个介质层 ⇒ `derived: dielectric_mm 0.5100 from stackup`，`width_mm = 0.92177`，`z0_recomputed = 50.0` |
| `{net: PA8, ohm: 50, dielectric_mm: 0.2}` | `width_mm = 0.33488`，`sources["impedance"] = "PA8: 50 ohm -> 0.3349 mm (microstrip, h=0.2000 mm, er=4.30, t=35 um)"` |
| `{net: PA8, ohm: 200, dielectric_mm: 0.2}` | `IMPEDANCE_UNREACHABLE` |

`precision` 一栏写死 `+/-12%`（继承正演模型的误差），并写明要去对场求解器或板厂的阻抗报告——
一个 IPC 近似式不是「板上一定 50 ohm」。

### 27.12.4 爬电距离：从「只认调用方给值」变成「也能自己查表」

`calc/iec60664.py`（IEC 60664-1:2020-05 Table F.5 的移植，`MODEL = iec60664_1_2020_table_lookup`）。
`rules.resolve` 新增 `working_voltage_v / pollution_degree / material_group / insulation / coating /
altitude_m`，给了电压就查表，查到的值和调用方同时给的 `creepage_mm` **取严**，
两个来源都写进 `sources["creepage"]`。

三处「宁可报错不给错答案」：

* `_pd` 只接受整数 1/2/3（`1.5` 也拒）；污染等级 4 标准不表列 ⇒ 拒绝而不是外推；
* 输入落在表的最后一档之外 ⇒ `_out_of_validity`，不延长曲线；
* `coating=true` 不放松表值，只加 IEC 60664-3 的 caveat（涂层能不能算，取决于工艺，不取决于开关）。

真板读数：250 V / PD2 / IIIa / basic ⇒ **2.5 mm**，
`basis = "IEC 60664-1:2020-05 Table F.5 (creepage), inhomogeneous field"`。
单测 5 条见 `TestCreepageCanBeLookedUpNotJustGiven`。

### 27.12.5 拥塞协商：先问「想要哪条走廊」，再按代价重分配

`route/router.py` 的 `_wish / _price / _negotiate / _reconcile`，加上 `grid` 与 `astar(soft=...)`
的一路软代价。原来的流程是「一次贪心 + 有限 rip-up」：谁先布谁占住走廊，后来者只看得到
「这里已经满了」。协商把它换成需求驱动：

1. **需求**（`_wish`）：把每条失败网的 wish 路径叠起来，数出被想要太多次的格子；
2. **定价**（`_price`）：被 `>= SOFT_BLOCK` 条网想要的格子涨价，价格进 A* 的软代价（不封路，
   只让它变贵）——所以搜索会自己去找「近乎直线但没那么挤」的那条走廊；
3. **重分配**（`_negotiate`）：每轮把所有网的 wish 都算一遍，按「让出这条边代价最小」挑牺牲者
   撕掉（`max_rips` 上限），再重布；
4. **只收最好的一轮**（`best_round` / `reverted_to_best`）：晚期价格会让绕路变长，末轮不该
   因为跑得晚就成为答案。

两个数是被实测逼出来的，不是拍出来的：

* `SOFT_BLOCK = 0.5`：一开始取 60.0（「躲开拥挤就别回来」），结果一次搜索跑过一分钟——问题问的是
  「想要哪条走廊」，诚实答案就是近乎直线的那条，大价格等于在回答另一个问题并把预算烧光。
* `WISH_BUDGET = 40000`：wish 搜索是诊断不是交付，超出就退回上一轮，不把整块板的时间押上去。

`congestion` 只在**确有 `pending`** 时才跑，所以合成板（`gate`/`corridor`）上它恒为 `None`——
那两张板上第二轮一布就通，没有可协商的东西。这一条本轮只能从真板拿读数。

**真板读数（同一块 F401 核心板、同一份规则、`congestion_max_rips=12`、`weight=1.0`）**

| 臂 | 布通 | 耗时 | 失败 |
|---|---|---|---|
| `congestion_rounds=0`（默认） | **38/50**，ops 352 | 442.9 s | `GND +3V3 PA7 PA6 PC15 PB13 PB12 PB10 VCAP1 PB7 PB2 PB6` |
| `congestion_rounds=2` | **41/50**，ops 658 | 713.0 s（+61%） | `SWDIO PA7 PA4 PA6 PC15 PB9 PA1 VCAP1 PB1` |

两轮协商的账：`round 1: before 38 → after 41`（demand 3534 格、挡路 35 处、撕 24 条、12 条未回收），
`round 2: 41 → 36`（demand 1361 格、撕 21 条），于是 `best_round=1`、`reverted_to_best=true`、
`history_cells=4863`。**这就是「只收最好一轮」第一次真的救了场**——第二轮把已经布通的三条网换掉了回来。

必须说清的一点：**41 不是 38 的超集**。这一臂新布通 8 条（`GND +3V3 PB13 PB12 PB10 PB7 PB2 PB6`，
其中 GND 与 +3V3 是两条电源网，本来就是最该布通的），同时新失败 5 条
（`SWDIO PA4 PB9 PA1 PB1`）——两次 sweep 下撕谁不撕谁会被重排。所以这一节能主张的只有
「多了 3 条」，不能主张「原来的 38 条都还在」。

`congestion_rounds` 的 schema 默认值是 **0**（关）：开启要多花 61% 的时间，换来的 +3 条是**一块板**
上的读数，不是对所有板的承诺。要开就显式打开，读数会原样写进 `report.congestion`。


### 27.12.6 连接意图：一份对象，三个消费者

`route/intent.py` + 新工具 `board_intent`（第 128 个）。三种消费者以前各自解析同一堆参数，
于是「用 net class 的间距量板、再用 0.2 mm 布板」这种错法是被允许的——**两块不同的板，两个答案都「对」**。

三条规则，都是 fail-closed：

1. **未知键一律拒绝**：`constraints.clearance` 这种拼错不会静默变成「没有约束」，
   错误里连可用词表一起给；
2. **调用方赢**，且每个不一致的键逐条进 `conflicts`（`{key, intent, caller, used}`）——
   分歧被报告，不被沉默地解决；
3. **什么都不发明**：没声明的键保持「未要求」，而不是 0 或默认值。

板级检查（`check_against_board`）分两个严重度，这一点是刻意的：

| 情况 | 处理 | 理由 |
|---|---|---|
| keepout 吞了焊盘 | 拦（`INTENT_INVALID`） | 那个焊盘在这个意图下不可达，布十分钟必然失败 |
| keepout / region 出板 | 拦 | 板上不存在这块地 |
| `ref` 不存在 | 拦 | 意图说的元件不在这块板上 |
| footprint 还没搬进自己的 region | **只报** | 那是这块板今天的现状，不是错误 |

`board_intent` 的回答只做检查，不搬元件（搬是 `edit` 的事）；`value.problems` 是**数量**，
`findings` 是**清单**，两个键故意不同名。

### 27.12.7 蛇形先挑宿主，再决定多高

原来按「段最长」挑宿主，这是错两次：更短但四周空旷的段比最长但被夹住的段更合适，
而**端点落在过孔上的段是最差的宿主**（换层处的蛇形是桩，每个齿都是板上原本没有的反射）。

`tune._candidate_order` 按 `room_mm = max_extra(seg_len, widest_amplitude)` 打分，
`ends_at_a_via ×0.25`、中点 2 mm 内有别人的铜 `×0.25`，并把 `why` 一起带出来
（`length_mm / room_mm / ends_at_a_via / other_copper_within_mm`）。

再加上 `AMPLITUDE_LADDER = (1.0, 0.75, 0.5, 0.35, 0.25)`：宽振幅放不下就窄一点再试，
每一次仍走精确复检（窄的从不因宽的「差不多」而被写下去）。报告新增
`amplitude_ladder_mm`、每个 meander 的 `narrowed`、以及 `hosts_considered`。
这把「`length_not_matched`：配不上」变成「配上了，振幅 0.9 mm」。

### 27.12.8 异形焊盘 = 它全部图元（单图元原样，多图元凸包）

原来的 custom pad 只取第一个 `gr_poly`，会把铜量**小了**——漏报 clearance，是检查最不能犯的方向。
现在 `gr_poly / gr_rect / gr_circle / gr_line / gr_arc` 全部收集成一个 polygon，字段 `outline` 明写
`convex_hull_of_primitives` 或 `primitive`；表达不了的 kind
（`gr_curve / gr_bbox / gr_vector / gr_text / gr_arc_ex / gr_bezier`）进 `ignored_primitives`
而不是消失。**多个图元**取 `_convex_hull`（monotone chain）：凸包只会更严不会更松。

**单个图元必须原样保留**，这一条是被全量门禁抓出来的：`pic_programmer` 的 `JP1.2` 是一个
**凹**的五点多边形（矩形被切了个 V 形缺口），第一版把单图元也去取凸包，凸包把缺口填成了铜，
于是 pcbnew 的 `HitTest` 在焊盘内部的一个点上与我们的多边形判反——**在一块焊盘的自己的铜里**。
改法只有一句：`len(polys) == 1` 时直接用那条 polyline，不 hull。缺口是「这里没有铜」，
把它填掉就是把 clearance 判松，方向正好是检查最不能错的那一头。

证据：`TestACustomPadIsItsWholeOutline` 三条——两个相距 6 mm 的矩形 + 一个 `gr_curve`
断言 `w = 6.0 mm`（不是单个矩形的 2.0）与 `ignored_primitives = ["gr_curve"]`；
一个三点凹多边形断言 `len(polygon) == 5`、缺口里那点在多边形外、而 `w/h` 仍是 1.15/1.50 mm。
真板侧的判据是 `test_pad_outlines_match_hittest`：KiCad 10.0 demo 板逐点比对 pcbnew 自己的
`HitTest`，`JP1.2` 修复后零分歧。

### 27.12.9 新铜让铺铜过期

`router._pour_report`：对每个非 keepout、有 net 的 zone，track 取两端点 + 中点、
via 取中心并算全栈（`add_via` 没有 span ⇒ 通孔）；输出
`needs_refill / zones[{layer, zone_net, segments_inside, same_net_as_the_new_copper}] / why`。

为什么值得单独记一笔：穿过别人的 pour 不是短路（pour 会重新让开），但**文件里的填充多边形描述的是
布线之前的那块板**。布完不复检，「填好的铜 + 新走线」读起来就是一块完成的板。
同一个网的新铜也单独报（`same_net_as_the_new_copper`），因为它同样让快照过期。

### 27.12.10 立创 Pro 的写路径：probe 纪律，而不是合成 snippet

新工具 `lceda_pcb_write`（第 129 个，`lceda_write.py`）：

```
probe（写之前） → 你的 snippet → 同一个 probe（写之后） → 比较
```

* `expect="change"` 而没给 probe ⇒ `ARG_REQUIRED`，**发都不发**：没有观测量就无法区分「写成功」与
  「写了个空」，而这个工具不做二选一的猜测；
* 前后一致 ⇒ `WRITE_HAD_NO_EFFECT`：「snippet 跑了、应用没抛错、设计没动」——这正是看起来像成功的
  那种失败；
* `save` 没有可观测量 ⇒ `expect="no_error"`，并明说只证实了「调用没抛错」（`verified_by` 写清）；
* 每条答案 `verified_against_app: false`，并列 `not_verified`（磁盘上的文件真的变了吗 / 重载后还在吗）。

**为什么不合成 snippet**：vendor 的写方法名与参数形状，在本机一步都没验证过。生成
「把 U1 沿 y 挪 1 mm」这种代码就是本项目一直在拒绝的「plausible wrong answer」。
所以 snippet 是调用方的，纪律才是这个工具的。

`_canon` 还有一个刻意的细节：整数与同值浮点不算变化（`1` 与 `1.0` 是同一个读数），
但只对 `abs(int) <= 2**53` 生效——把两个相邻的 uuid 圆成同一个 double 会读成「没变化」，
那是往错的方向错。
