# 27 自动布线器：搜索是提议，精确几何才是判决

这一篇记的是 `board_route`（`route/{rules,grid,router}.py` 三个模块）从零到能在一块真实的
50 网核心板上跑完的过程，以及在这一轮里被抓出来的五个**真缺陷**——其中四个会让工具在
「看起来布线成功了」的状态下给出错答案，这正是本项目最不能容忍的错法。

一句话结论先放在这里：

> **栅格只负责提议，精确多边形几何才是判决；两套栅格（走线/过孔）必须分开；凡是搜索没走到的
> 地方就不能说「没有路」；凡是铜没有真的接到焊盘上就不能说「这个网布通了」。**

## 27.1 规则：三个来源，每个来源都要写清是谁给的

布线器的每个数字都必须能回答「谁说的」。`route/rules.py` 的解析次序：

1. **调用方**（`clearance_mm` / `track_mm` / `via_*`）——最高优先，来源记 `"caller"`；
2. **板内 `(net_class ...)`**——v6/v7 时代写在 `.kicad_pcb` 里的那一份；
3. **`.kicad_pro` 的 `net_classes` / `netclass_assignments` / `netclass_patterns`**——通配匹配，
   取该网络实际命中的类；
4. 同一个数在多个来源里出现时，取**最严**的那个（网络类之间也是最严取胜）；
5. `edge_clearance` 这类板里根本没有的事实：**不设 0、不猜**，如实写进
   `assumed: [{"fact": "edge_clearance", "value": null, "why": ...}]`，并且
   `sources["edge_clearance"] = "not in the file"`。

**板里一条 clearance 都没有时，`RULES_ABSENT` 直接拒绝**（fail closed）。这条不是形式主义：
一个「按经验取 0.2 mm」的默认值，会让整块板在别人家的工艺上重画一遍。

来源三元组在输出里逐项公示：

```
"sources": {"clearance": "net class Default", "track_width": "net class Default",
            "via_diameter": "net class Default", "via_drill": "net class Default",
            "edge_clearance": "not in the file"}
```

测试 `TestRulesAreResolvedNotInvented` 三条：值来自网络类且来源写对；空板拒绝且 hint 里
写明「will not guess」；调用方覆盖后来源变成 `"caller"`。

## 27.2 双栅格：一张图回答不了两个问题

「这里能不能放一条 0.25 mm 的线」与「这里能不能打一个 0.6 mm 的孔」，答案不一样：

* 走线栅格的 margin = `clearance + track/2`；
* 过孔栅格的 margin = `clearance + via_dia/2`。

合成一张（取大的）会把所有 0.5 mm 间距的焊盘整排封死——相邻焊盘的铜离焊盘中心只有
0.35 mm；合成一张（取小的）则让搜索把过孔放在精确检查随后否掉的位置：F401 核心板上
**50 个网里有 7 个是这么失败的，失败原因全部是过孔上的 `clearance`**。

所以两张图并存，`free()` 查走线图、`free_via()` 查过孔图，A* 里的换层动作只查过孔图。
测试 `TestRastersArePessimistic` 直接盯这一点：距铜边 0.4 mm 处「线可走、孔不可走」，板外
一律不可走。

## 27.3 精确判定：栅格永远不是证据

搜索提出的每一段铜，落地前都要过 `seg_blockers()`：

* 逐对 `pair_clearance(net_a, net_b)`——不是一刀切用全局 clearance；
* 6 个量级不同的几何用同一个距离函数（pad 多边形、track 线段、via 圆、zone 环…）；
* 包围盒先做粗筛（`hypot(gapx, gapy) >= need` 直接跳过），再算精确距离；
* 被拒的段**保留拒绝理由**（`net / kind / reference / needed_mm / actual_mm / short_by_mm`），
  这是失败报告里唯一能让人动手改的东西。

`TestTheExactCheckIsTheJudge` 不信路由器自己的判决：它在测试里用 `geometry.dist_point_polygon`
**自己**把每条输出线段对那块挡路焊盘采样量一遍，断言 `gap - width/2 >= clearance`。

## 27.4 A*：四个必须项

| 项 | 取值 | 为什么 |
|---|---|---|
| 8 向 + 禁切角 | 对角移动前先查两个正交邻格 | 允许切角会产出物理上不存在的对角穿越 |
| 转向代价 | `TURN_COST = 0.55`（格距单位） | 没有它就是一地楼梯；有它才是「尽量一段直」 |
| 过孔代价 | `VIA_COST = 9.0` | 一次换层≈9 格，等于「能同层就同层」 |
| 搜索预算 | `MAX_BUDGET = 400000` 节点 | 超了要**说超了**，不能说「没有路」 |

最后一条是本项目的老规矩的直接应用：**预算是搜索的停止原因，不是几何的结论**。
预算耗尽时 `diag["budget_hit"] = True`，失败码写成 `search_budget`，与真的没有路
（`no_path`）分开报。调参实测：预算 400k 与 150k 的结果**完全相同**（29/50、469 ops），
说明失败网并没有耗尽预算——它们是「可达集被走完了」，所以默认预算维持在 400k 不动。

## 27.5 事务化：一个网的铜只在这个网成功之后才进图

`_Emitter` 三态：**buffered**（过了精确检查，但网还没布完，**不进图**）/ **committed**（网布完，
进图并占位）/ **rolled back**（网失败，缓冲丢弃，拒绝理由留着）。

为什么必须是这个形状：如果边搜边占，一个最终失败的网会在图上留下半条路，后面每个网都要
绕着一段**不存在的铜**走，而且这块板写出来以后没有人会知道为什么绕。

rip-up 需要「撤掉若干个网的铜再重来」，而图的单元与空间哈希没有 per-net undo，所以
`forget(nets)` 的做法是**重建**：把剩下的 ops 重新 `_replay` 进一张新图。慢，但不会留下一张
「记着已被撕掉的铜」的图。

## 27.6 性能：229 s → 41.4 s，逐条说改了什么

12 网的控制实验（cProfile，旧实现）：

| 位置 | 时间 | 调用数 |
|---|---|---|
| `astar` 总计 | 204.8 s | — |
| `grid.free()` | 63.2 s | 71.4 M |
| 其背后的 `dict.get` | 53.3 s | 140 M |
| 过孔门 `_via_gate` | 33.5 s | 9.7 M |
| `_mark_cells` | 23.1 s | — |
| `Grid.__init__` | 21.2 s | — |

改法（全部是「同一个逻辑换成一次乘法」这一类，不改语义）：

1. `dict[(layer, i, j)] → int` 换成**每层一个扁平 list**，状态编码 `0`=全网可走、`-1`=全禁、
   `k>0`=第 k 个 interned 网集合（`_sets[k-1]` 是 tuple，`_set_ids` 用 frozenset 做键）；
2. A* 内联读栅格（`mp[nj * nx + ni]`），goal 层用 int 索引表，`best / parent` 用整数标量键
   `((node) * nlayer + li) * 9 + d`；
3. 过孔门**每节点算一次**（`via_memo`）而不是每节点每层一次；
4. `_mark_cells` 两套 margin **一趟走完**（每格只做一次距离计算，按 d 与两个 margin 的关系
   分别写入两张图）；
5. 轴对齐矩形（4~5 点且顶点集==bbox 四角）走**角差/到边距离**的快路径，与
   `dist_point_polygon` 结果一致，缓存在 item 上。

结果：**12 网 229 s → 41.4 s（5.5×），`rejected_ops: 0`**（没有因为提速放过任何一段）。

> 注：本机在同一时段还有别人的 4 个实验进程占满 CPU，所以文档里所有**绝对秒数**都要打折看；
> 上表是同一进程内的前后对比，加速比不受影响。

## 27.7 全板 50 网：失败是争用，不是几何

F401 核心板（`_scratch/core/stm32f401re_core.kicad_pcb`，53.34 × 30.48 mm，4 层，32 封装 /
194 pad / 51 net / 0 zone），`rip_up_rounds=0, second_sweep=False, pitch=0.1`：

* **本次出货代码：27/50 布通，461 ops，102.9 s**，失败 23 个：
  `SWDIO PA5 PA7 PA4 PA6 PC14 PA1 PB10 PA0 VCAP1 PB7 PB2 XTAL_IN PB6 PB1 PB5 PB0 PB4 PB3 PA15 PD2 LED2_A LED1_A`
* 修板边距之前同一个 baseline 臂是 **29/50、469 ops**，多出来的两个正是 `LED1_A` / `LED2_A`
  ——它们当时是把铜贴在 y = −0.4 溜过去的（铜边距板边 0.275 mm，见 §27.9.6）。**那两根不算布通，
  它们是非法铜**；所以真实的起点是 27，不是 29。

决定性对照（这一条推翻了我自己的假设）：

| 臂 | pitch | 结果 |
|---|---|---|
| 6 个失败网（`SWDIO PA5 PA7 PA4 PA6 PC14`）单独布 | 0.1 mm | **5/6**，37 ops，8.3 s，只剩 `PA6` |
| 同上 | 0.05 mm | **5/6**，42 ops，23.1 s，只剩 `PA6` |
| 再加一条对照：`PA6 + PA5` 两条 | 0.1 mm | **2/2 全通**，`failed=[]` |

同一批网在空板上基本都布得通，细栅格也没有更好（细了一倍反而多花 2.8 倍时间）；`PA6` 丢的
原因是这五条同批的网就在它旁边——**所以 27/50 的差距来自先布的铜占位，不是细间距逃逸**。
这条直接把「必须更细的栅格」这个假设否掉，也把 rip-up 的重要性顶到第一位。

## 27.8 rip-up：按位置挑牺牲者

旧写法撕「最短的几个网」，理由是「短的便宜」。实测站不住：挡路的网可能长在板子另一头，
撕它一点用没有。现在按**物理重叠**挑：

* 取失败网所有焊盘的包围盒，外扩 1.5 mm；
* 与**已经真正发出去的** ops（track/via）求交，统计每个网络命中几段；
* 取重叠最多的 3 个非平面网作为牺牲者，`forget` 它们，重布「失败者 + 被撕者」；
* `rip_up_rounds` 的语义是「**对每个仍失败的网各做一次定位 rip-up 的遍数**」，不是「总轮数」；
* 只有 loser 与被撕的网重跑，其他网的铜不动（旧代码每轮把 `routed[3:]` 全部重跑，实测每轮 20 s
  纯浪费）。

`stats["rips"]` / `stats["rip_passes"]` 如实回报撕了几个、跑了几遍。

### 27.8.1 两臂实测：+11 个网，代价是 5 倍时间

同一块板（`_scratch/core/stm32f401re_core.kicad_pcb`，栅格 534×305 = 162 870 cells），
只改开关，代码同一份：

| 臂 | 开关 | 布通 | ops | 耗时 |
|---|---|---|---|---|
| baseline | `rip_up_rounds=0, second_sweep=False` | **27/50** | 461 | **102.9 s** |
| sweep + rip | `rip_up_rounds=1, second_sweep=True` | **38/50** | **351** | **521.8 s** |

`rips=64 / rip_passes=1 / sweeps=2 / rejected_ops=0`。两臂失败网清单：

* baseline 失败 23 个：`SWDIO PA5 PA7 PA4 PA6 PC14 PA1 PB10 PA0 VCAP1 PB7 PB2 XTAL_IN PB6 PB1 PB5 PB0 PB4 PB3 PA15 PD2 LED2_A LED1_A`
* sweep + rip 失败 12 个：`GND +3V3 PA7 PA6 PC15 PB13 PB12 PB10 VCAP1 PB7 PB2 PB6`

读法有三条：

1. **净赚 +11 网不是靠多画铜**——ops 反而从 461 降到 351。被撕掉的 64 段旧铜没白撕，
   重布之后总铜量更少、连通更多。
2. **GND / +3V3 进来了**：这两个平面网在 baseline 里就是失败项，sweep 之后它们变成
   失败清单的前两位 —— 说明它们是**最后才被尝试的长网**，而反向 second sweep 让短网先落地，
   长网拿到的是「别人已经占位」的图。这不是回退，是排序换了；但这条也说明**平面网不该
   跟信号网用同一个 8 方向 A\***（它们本该靠铺铜解决，见 §27.10）。
3. **绝对秒数只做参考**：两臂都是本机跑、但不同时段机器负载不同（同一份代码的 baseline
   早先量到过 221.5 s，另一天量到 102.9 s）。可比的是**同一进程内前后两臂的比值**：
   rip-up 要 `forget()` 重建整张图（162 870 cells × 4 层）再重放全部已发 ops，一轮总值 ≈5 倍，
   这是真实开销。次可比的是**同一台机器上的两次 sweep+rip**：451.3 s → 521.8 s 就是板边距
   那三处检查的价格（+15.6%）。

## 27.9 本轮抓出的五个真缺陷

这五条都不是「写得不好看」，而是**会在成功状态里给出错答案**，所以逐条记下来。
前四条是写测试和写代码时自己发现的；第五条是**跑完端到端、拿 kicad-cli DRC 当裁判**才现形的
——这也正是它值钱的地方：前四条的错法在工具自己的日志里看不出来，第五条的错法在自己眼里也
看不出来。

### 27.9.1 越界下标在 Python 里会**回卷**

栅格是扁平 list，`free(i, j)` 用 `j * nx + i` 取值。问一个板外 5 mm 的点（`i = -50`）时，
下标回卷到板上某个**普普通通的空格**，于是「板外」被回答成「可走」。路由器自己不会问这种点，
但任何按坐标查询的调用方都会。修法：`index(i, j)` 越界一律返回 `None`，`free / free_via`
返回 False，`blocked_reason` 回 `off_board`。

### 27.9.2 keepout 只封了**边框一条带**

第一版沿用铺铜的写法：把距 ring 小于 margin 的格子标成禁行。结果是 keepout 的**内部**完全
可走——搜索直接从框里穿过去，还理直气壮地说这里空着。真值显然相反：keepout 禁的就是「框里
有铜」这件事。修法：keepout 额外做 `point_in_polygon` 判定，命中即 `d = 0`。

修的时候还踩了第二个坑：这个判定最初写在 `d >= m`（m = 两个 margin 的较大者）**之后**，
于是在 `[m_track, m_via)` 这一条带里，走线图说「可走」、过孔图说「不可走」——同一块铜上两张
图互相矛盾。现在判定放在两个 margin 决定任何事**之前**。

### 27.9.3 精确判定里**根本没有 keepout**

`seg_blockers` / `via_blockers` 只看铜的 clearance，keepout 只活在栅格里。于是「栅格说能走、
精确判定说干净」可以同时成立，而铜实实在在横穿了一个 keepout。修法：keepout 进
`self.keepouts`（ring + 层 + tracks/vias 标志 + bbox），精确判定新增：

* 线段：端点在环内 / 与环边相交 / 到环边距离 < `width/2`，三者任一即拒；
* 过孔：圆心在环内 / 圆环与环相碰即拒；
* 且**尊重 `(keepout (tracks allowed))` 这类标志**——一个只禁过孔的 keepout 不该把走线也封死，
  否则后面每个网都在绕一条板文件里根本不存在的规则。

包围盒先做四则比较再算距离：`_via_gate` 在 A* 里是**逐节点**调用的（60×40 mm 板 0.1 mm 栅格
= 24 万节点 × 4 层），任何一个 per-keepout 的距离计算都会变成热点。

### 27.9.4 焊盘逃逸链路：网说「布通了」，铜却没接到焊盘上

`_free_terminal` 在焊盘中心被别人的铜光环盖住时，会退到最近的空格作为起点（真实场景：连接器
底下藏测试点、焊盘落在别人 footprint 的 courtyard 里）。但**从焊盘中心到这个起点的这段铜，
第一版从来没画过、也没检查过**——A* 从那个空格开始布线，于是输出的第一段线离焊盘 1~2 mm，
什么都不挨着，而 `status` 是 `routed`。

修法：这段链路当成一段普通铜——走 `em.track()`（与其他段同一个精确判定），失败则整网拒绝，
失败码 `terminal_unreachable`，并带上「焊盘 / 逃逸点 / 被谁挡住」；成功则在 `notes` 里写明
「有 N 个焊盘的格子被占，已接到最近的空格」。

### 27.9.5 修完之后失败更快也更准

同一块测试板上的 `WALLED` 网（焊盘落在 keepout 正中）：

| 版本 | 判定 | 耗时 |
|---|---|---|
| 修之前 | `search_budget`（跑完 24 万格才放弃） | 9.3 s（单遍） |
| keepout 内部封住之后 | `no_terminal`，detail 里写明 `J4.1 at (40,20)` 被 keepout 挡 | 0.17 s |

「报错快」只是顺带的；值钱的是理由从「我没找到」变成「这块焊盘离不开，因为它在 keepout 里」。

### 27.9.6 板边距只管过孔、不管走线

`via_blockers` 里有 `too_close_to_edge`，`seg_blockers` 里没有。看起来像「顺手漏了一行」，实际
后果是**工具亲手往板边写非法铜**：这块板的 net class 里只有 `clearance 0.2 / trace 0.25`，没有
`min_copper_edge_clearance`，而 KiCad 不因为没有 `.kicad_pro` 就不查板边——它用板设置里的默认
0.5 mm。于是 `LED1_A` / `LED2_A` 两根网从焊盘直着往板边走，走在 y = −0.4（铜边距边 **0.275 mm**），
路由器把两个网都报成 `routed`，`apply` 的四道闸门也全绿（那时候 DRC 闸门还没把
`copper_edge_clearance` 当阻断项看）。

`kicad-cli pcb drc` 的读数把这件事钉死了：**6 条 `copper_edge_clearance`，全部指向这两根网的
Track**，`最少 0.5 mm / 实际 0.275 mm`。

修法分三处，缺一不可：

1. **规则**：`edge_clearance_mm` 没有来源时不再留空，取 KiCad 板设置的默认 **0.5 mm**，并写进
   `assumed` 里说清楚「文件里没有，但裁判会按这个查，所以按这个来；要换就传 `edge_clearance_mm`」。
   这里第一次没沿用「缺规则就拒」：板边距是**关于板**的规则，不是两个网之间的规则，一份没有
   `.kicad_pro` 的板照样躲不过 DRC，留空等于假绿。
2. **栅格**：`_mark_edge()` 沿 Edge.Cuts 每一条边封一条 `edge + track/2` 宽（过孔图
   `edge + via/2`）的带，**对每个网都封**（`-1`）。这条带不进图，搜索就不会把「贴着板边走」
   当成近路去试。
3. **精确判定**：`_edge_for_segment()` / `_edge_for_via()` 算「铜到 Edge.Cuts 的距离」——
   与 keepout 同一套写法（bbox 预热 + 线段/点距离），因为**栅格永远不是证据**。

一根网被板边挡住时的读数是**「这个网布不通」**，不是「路由到了板边」。宁可少布一根网，也不
往板边写铜。

### 27.9.7 端到端：自己的闸门绿不算绿，`kicad-cli` 说绿才算

修完五条后，把整条链路跑一遍（**同一份代码**，`rip_up_rounds=1, second_sweep=True`）：

| 环节 | 读数 |
|---|---|
| `board_route` 计划 | **38/50**、351 ops、**521.8 s**、`rips=64`、`sweeps=2`、`rejected=0` |
| `propose` | `blocking=[]` |
| `apply`（`engine:true`） | `status=ok`、18.6 s、`new_blocking_total=**0**`（新增 4 条 advisory，旧账清掉 4 条，总账 69 → 69） |
| `kicad-cli pcb drc`（独立裁判） | 69 条，全是既有 silkscreen/text 告警；**shorting_items 0 / tracks_crossing 0 / clearance 0 / copper_edge_clearance 0** |
| `unconnected_items` | 71（对应的就是那 12 个没布通的网，不是新增断裂） |

板边修好前后的差别就两行：**修前 6 条 `copper_edge_clearance`（全部 error）、布通 38/50；
修后 0 条、布通还是 38/50**。也就是说，那 6 段贴着板边的铜既没换来一个布通的网，又让整块板
Dirty——比「少布一根网」差得多。代价是计划时间 451.3 → 521.8 s（+15.6%），因为过孔门在
A* 里是逐节点调的，多了一次沿板框的距离计算。

## 27.10 没做什么，也不假装做了什么

* **差分对 / 等长 / 阻抗目标**：没有。`board_route` 不知道哪两根线是一对，也不知道要等长。
* **回流路径**：没有。换层不带地过孔，参考平面连续性不参与搜索（那是 `board_cross_split`
  与 `board_loop_area` 的事，是**检查**不是**布线**）。
* **爬电距离 / 安规间距**：没有。规则解析只吃 clearance 这一层，`creepage` 一栏不存在。
* **拥塞协商（negotiated congestion）**：没有。现在是无协商的一次 Greedy + 有限 rip-up。
  真实现代布线器的核心是「先全部布通再按代价重分配」，这一层没有做，也解释了为什么 50 网
  板上还能有 21 个失败。
* **多端网拓扑优化**：用的 Prim MST 降序，不是 Steiner，也不是「先布短线再布长线」的全部变体。
* **热焊盘 / 铺铜重填**：新线穿过 pour 区不会触发重填，pour 的边缘只按 rim margin 让开。
* **D 形/异形 pad 的圆角处理**：走的多边形距离，忽略 pad 圆角半径。

写了 `routed` 不等于 DRC 干净：`board_route` 的 `precision` 一栏写死「跑 `board_drc` 复核」，
`apply=true` 时铜走的仍然是 `board_propose + board_apply` 那五道闸门 + KiCad DRC 裁判。
