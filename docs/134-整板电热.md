# 134 · 整板电热：从板文件到一块会发热的板

`133` 把 `.kicad_pcb` 接进了电路求解（deck、IR-drop）。这一页接后半段：

> 「那些仿真功能都要支持真实的整板仿真，不能只做简单的仿真。」

`thermal_plate` 和 `board_electrothermal` 一直能算温度，但要**你给几何**。整板热缺的
不是又一个平板求解器，而是"这块板自己的铜，按你给的电流，发多少热"这一步。补上它的
同时要守住一件事：**热必须能追到可算的物理量**，否则只是"简单仿真"换个说法。

---

## 1. 链路：三段，每段都能单独核

```
.kicad_pcb
  └─(adapters/kicad_pcb + oracle.board_ir_drop(return_network=True))─→ 图
      └─(sim/power.dissipation)─→ 每焊盘电流 → 一次 DC 解 → 每条边的 I²R
          └─(oracle.board_electrothermal)─→ 2-D 平板（外形框 + 叠层 + 铺铜矩形）
```

| 段 | 谁算 | 判据 |
|---|---|---|
| 铜与图 | `board_ir_drop` | 与 `board_netlist` / `board_sim` 同一张图，没有第二个提取器 |
| 功耗 | `dissipation` | `total_power_w` == 同网同源的 `total_copper_loss_w` |
| 温度 | `board_electrothermal` | 能量平衡（0.5 % 输入功率），容差按物理尺度收紧 |

自证不是"跑通就算"：合成板 20 mm × 0.5 mm × 35 µm 走线 1 A 下
`total_power_w` = `board_ir_drop.total_copper_loss_w`（places=9）；ecc83 实测
**8.471667803002245e-05 对 8.4717e-05**，差 3.2e-10 全部来自发布位数。

---

## 2. 只有两种输入是调用方的，其余都从文件量

- **电流**：`.kicad_pcb` 里没有电流，`currents: [{"at": "U2.1", "a": 1.0}]` 必填。
- **对流**：`h_w_m2k` 必填，缺了就是 `ARG_MISSING`——边界条件猜不出来。

其余（铜厚、层数、板厚、铺铜范围、走线几何、过孔）全部来自板文件。这就是"真实整板"
与"我给的一块铜"的分界。

---

## 3. 三种拒答，都是"半个电路"

| 情形 | 结果 | 为什么不能算 |
|---|---|---|
| 某网电流和不为 0 | `ARG_INVALID`（"add up to … A, not zero"） | 板上没有器件模型，能把电流带到别的网去的对象不存在 |
| 焊盘存在但不在任何网 | `ARG_INVALID` | 机械铜，没有网就无从注入 |
| 焊盘在任何网上但一块铜都不通 | `NOT_CONNECTED` 并点名 | 交给 gmin 会解出一个浮空网络，`status: ok` 的假答案 |

第三种是 `133` 里那条"1000.000000 mV"的同一个坑，只是这次出现在热的入口。

---

## 4. 孤岛：不是缺陷，是"电流落在两块铜上"才是

实测 ecc83：`Net-(P3-P1)` 的铜分裂，稠密求解直接
`singular at 11 (a node with no conductive path to ground?)`。孤岛在电路里是一个
**没有方程的未知量**，不是板子的缺陷。所以：

- 按连通块剪枝，只解"被驱动焊盘所在的那一块"；
- 被丢下的块**计数并点名**（`value.dissipation.islands`，同时写进 `notes`）——
  它们不承载电流，也不贡献热；
- 如果被驱动的焊盘分居两块铜，电流根本流不动 → `NOT_CONNECTED`
  "sit on … separate pieces of copper"，因为串联在同一网的电流必须有一条路。

两个方向都写成测试：同一块 split 夹具上，只驱动一侧 → `ok` 且 `segment_count == 1`、
`islands == ["VCC"]`；两侧各驱一个 → 拒答。

---

## 5. 温度：容差是"最后一轮扫描"还是"模型"

平板的能量平衡门槛是 0.5 % 输入功率，而 `tol_k` 默认 1e-4 K 是按"器件在倒瓦"选的。
板子只升百分之一度时，1e-4 K 的容差停在**最后一轮 SOR** 上，于是：

| 板 | 报出的残差 | 真相 |
|---|---|---|
| ecc83 | `energy does not balance: 5.149%` | 温升约 0.05 K，容差过松 |
| 合成板（带铺铜） | `does not balance: 0.534%` | 温升 0.1 K，刚过门槛 |

`sor_max_iter` 从 60 000 加到 400 000 没有变化（是固定点，不是迭代不够）。
**门槛不放松**——放松就等于编一个温度。改成按调用方已经给出的物理量收紧：

```
rise ≈ P / (2·h·A)          # 均匀平板温升
tol  ≤ 1e-5 · rise          # 再低四个数量级
```

失败就继续收紧并重试（`tol`、`tol/100`、`tol/1e4`），**实际用了多少写进 `notes`**
（ecc83：1.79e-08 K）。

---

## 6. 两块铜的口径先写清，再报数

- **过孔**：功耗算（`value.dissipation.via_power`），但**不作为 2-D 源**——桶是竖直的，
  平面场没地方放它。这件事写在 `notes` 里，不静默丢掉。
- **铺铜**：按 zone 外形框的矩形交给平板；非矩形覆盖不到时会**多算面积**，同样在
  `notes` 里说清。
- **温漂**：平板在 25 °C 上解，所以损耗不是 20 °C 的阻值。合成板实测
  0.020090018285714283 对 0.019702857142857143 = **1.01966**，正好 `1 + 0.00393×5`。
  报 20 °C 的数等于"热在 25 °C 算、在 20 °C 放"。
- **"温差四倍"不是 4.000**：2 A 对 1 A 实测 **4.2244**。干净的 4.000 反倒说明
  铜的温漂被丢掉了。

## 7. 实测

ecc83（0.1 A 走 `Net-(P3-P1)`，h = 10 W/(m²K)，文件自带 1 块铺铜矩形）：

| 量 | 值 |
|---|---|
| 总功耗 | 8.638e-05 W（7 段走线 + 2e-08 W 焊盘镀层） |
| `t_max` / `t_min` | 25.004072 / 25.000962 °C |
| 平板 | 52.07 × 46.355 × 1.6 mm |
| 孤岛 | `Net-(P3-P1)` 2 节点 1 边，不承载电流 |

`board_thermal` 不在 core profile 里（core 那页已顶到 25 KiB 预算）；它在注册表、
`calc_capabilities` 列得出来、`tool_search` / `tool_call` 够得着。
