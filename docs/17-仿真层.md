# 17 - 仿真层：电路（SPICE）、电流（PDN / IR drop）、热

这一层回答的是「这张板子通电会怎样」，而不是「这张板子画得对不对」。
画得对不对由保真层与 Oracle 负责；这里负责的是**物理**：电压、电流、温度。

三个子模块，全部只用 Python 标准库（`math` / `cmath`），没有 numpy、没有
ngspice、没有外部可执行文件：

| 模块 | 文件 | 解决什么问题 |
| --- | --- | --- |
| 电路仿真 | `calc/spice.py` | 网表 → 工作点 / 瞬态 / 小信号 AC，逐元件回报 V/I/P |
| 电流与 PDN | `calc/power.py` | 铜阻、过孔、电感、IR drop 链、电容群 \|Z(f)\|、去耦判定 |
| 热 | `calc/thermal.py` | 1-D 叠层热阻、过孔阵列、2-D 板温场、Foster 瞬态、散热片预算、对流 h |

对外的 14 个工具：

```
sim_spice  trace_resistance  via_resistance  trace_inductance  ir_drop_chain
pdn_impedance  decoupling_check
thermal_stack  thermal_via_array  thermal_plate  thermal_transient
thermal_heatsink  thermal_convection
board_ir_drop            <- 走板文件，真实铜箔拓扑
```

## 17.1 电路仿真（`sim_spice`）

### 能做什么

把 SPICE 网表跑出真实解：修正节点分析（MNA）+ 牛顿迭代 + 结电压限幅（pnjlim）
+ gmin 阶梯下降。支持 `.op` / `.tran` / `.ac`，元件卡 R C L V I E G D Q M、行为源 `B`
（`0.0.29`）、无损传输线 `T`（`0.0.30`）与两张分布卡——有损线 `O`（`LTRA` 模型）与
分布 RC 线 `U`（`URC` 模型，`0.0.31`）。

**每个元件都回报自己的电压、电流、功率**，而不是只给节点电压：

- 二极管：`current_a`、`conductance_s`、`dynamic_resistance_ohm`、`power_w`、
  `model_params`（含**未缩放**的 `IS_nominal` 与缩放后的 `IS`）
- BJT：`vbe_v` / `vbc_v` / `vce_v` / `current_a{ib,ic,ie}` / `beta` / `region`
- MOSFET：`vgs_v` / `vds_v` / `vov_v` / `id` / `gm_s` / `region`
- JFET：`vgs_v` / `vds_v` / `vov_v` / `current_a{id}` / `gm_s` / `power_w` / `region` / `polarity`
  / `model_params{VTO,BETA,LAMBDA,AREA,BETA_eff}` / `gate_junction_forward_v`（见 `42`）

端电流的符号约定是「**正方向为流入该端子**」，所以 NPN 导通时 `ic > 0`、
`ie < 0`。这是唯一能让人不重新推导就自查的口径。

### 做不到的，逐条点名

未实现的卡只剩 `A`，**按名字拒绝**（`NETLIST_INVALID`）；`F`/`H`/`K`/`S`/`W`/`J` 都已进内置，
`O`/`U` 不是「未实现」而是「实现了，但实现的是集总模型」（见 §17.8、§17.10）。
不是跳过。理由很直接：静默跳过一张卡，网表就"跑起来了"，然后给出一个
属于另一张电路图的数字。同理，收敛失败是 `NOT_CONVERGED` 错误，不是
"差不多收敛了"的字段。

### 三个只在真算过之后才会知道的坑

1. **二极管温度**。只让 `Vt` 随温度升高、`IS` 不变，会得到"温度越高正向压降
   越大"——符号是反的。现在按 SPICE 实现 `IS(T) = IS*(T/Tnom)^(XTI/N) *
   exp((T/Tnom-1)*EG/(N*Vt))`，1k 串 5 V 供电的二极管：27 ℃ → 0.6925 V，
   100 ℃ → 0.5709 V（约 −2 mV/K）。`not_computed` 里明写**没有自热**：结温等于
   你声明的环境温度，不会因为自身功耗升高。
2. **AC 扫描截断必须喊出来**。`max_points` 默认 200，`dec 200 1k 100k` 要 401 点。
   截断后最后一个频点不是 `fstop`，一个还在上升的曲线会被读成"电路在这里谐振"。
   现在截断时给一条 warning，点名实际扫到哪个频率。
3. **步数不能用裸 `ceil(tstop/h)`**。`1e-3/1e-5` 在二进制里是 `100.00000000000001`，
   `ceil` 就多跑一步：1 ms 的瞬态最后一个点在 1.01 ms。已加相对 eps 容差。

## 17.2 电流（`calc/power.py`）

### 铜阻不是"方数 × 方阻"就完事

`trace_resistance` / `via_resistance` 会同时报出**方数、方阻、铜厚来源**，
因为错的从来不是公式而是几何：35 µm 铜箔蚀刻后通常是 30~38 µm，
`copper_um` 显式传入时会在 `assumptions.copper_um_source` 里说明它覆盖了叠层。

过孔的截面是**桶壁圆环**，不是钻孔圆：`A = π((d/2)² − (d/2−t)²)`。
`plating_um` 大于钻孔半径时返回 `ARG_RANGE`——那是单位写错，不是"很小的孔"。

### IR drop：链式和网络是两件事

- `ir_drop_chain`：一串不同宽度的线段**各自算各自的**。三段线不是一段"平均宽度"。
- `board_ir_drop`：**从板文件里的真实铜箔建电阻网络**。节点是 `(x, y, layer)`，
  两层只在过孔或镀通孔焊盘处相连。这是「长度 × 方阻」估算永远看不见的那一段：
  同样 20 mm 总长，全程一层是 19.70 mV，中途过一次孔（0.3 mm 钻 / 25 µm 镀 /
  1.6 mm 板）变成 20.98 mV，多出来的 1.28 mV 就是孔。

`board_ir_drop` 的拒绝清单：无铜厚（点名列）、有孔但没给 `plating_um`、
汇点在网络上但没有铜连过去（`NOT_APPLICABLE`，**不是 0 mV**）、焊盘不在该网络。

### PDN：判"最坏 |Z|"，不判"最小 |Z|"

`pdn_impedance` 给整条 `|Z(f)|` 曲线；`decoupling_check` 给三态判定
`pass` / `fail` / `indeterminate`。

三态是必须的。低频端电容不是短路（10 µF 在 1 kHz 是 15.76 Ω），所以"宽频段
一定 fail"这句话里没有一个字是关于电容的——那段由**稳压器**闭环维持，不由
电容。当最坏点正落在判定频段的下沿时，结论只能是 `indeterminate`，并告诉你
该给 `regulator_bandwidth_hz` 还是抬高 `f_low`。

真正的失效是**两个容值之间的反谐振**：10 µF（ESL 2 nH）与 100 nF（ESL 2 nH）
在 7.94 MHz 处的并联结果是 0.951 Ω，比任何一只电容单独都差十倍。
"多放几颗更好"这种推理看不到这个峰。

## 17.3 热（`calc/thermal.py`）

### 1-D 与 2-D 分开，因为它们的用途不同

- `thermal_stack`：`Rth = Σ t_i/(k_i·A)`。严格 1-D，**看不到扩展电阻**，
  所以它系统地高估（保守）。用于"这叠层能不能把热传过去"。
- `thermal_plate`：`k·t·∇²T − 2h(T−Tamb) + q'' = 0`，SOR 求解。它才有热点、
  才有扩展、才有"边缘多热"。默认 `cell_mm` 自适应，`max_cells` 上限防跑飞。

2-D 板有两条硬约束：

1. **必须自检能量平衡**（残差 < 0.5%），不守恒就报错不给场。这个检查抓到过一次
   真实缺陷：固定边界项符号写反，残差 199%。
2. **点源必须按焊盘尺寸铺开**。一个 3 mm 焊盘按 0.5 mm 网格是 32 个格子。
   如果当成单格，热点温度就变成"网格尺寸的属性"而不是板的属性——所以单格时
   给 warning 明说这一点。

`h_w_m2k` 不猜：不给就 `ARG_REQUIRED`。`convection_coefficient` 返回的是关联式
（自然 `1.42*(ΔT/L)^0.25`、强制 `10.45 − v + 10√v`），并明写 ±25%。

### 过孔阵列

`thermal_via_array` 有两个数：纯铜桶壁并联（192.4 K/W ÷ N），以及**把孔径周围
的板也算进去**的 per-cell 值（1 mm 间距时每格 185.7 K/W，9 孔 20.6 K/W，
而同样面积的纯 FR4 是 592.6 K/W）。两个都给，因为"过孔有没有用"取决于你比的
是哪一对数。

### 散热片：只给预算，不给表

`thermal_heatsink` 算 `Rth_sa = (Tj_max − Tamb)/P − Rjc − Rcs`，再乘安全系数
（默认 0.8，**大于 1 直接拒绝**——那是概率写反了）。`P` 太大导致 Rjc+Rcs 已经
吃光预算时返回 `INFEASIBLE` 并说清楚"换封装或降功耗，散热片救不了"。

本模块**不带散热片型号表**：数据手册的一个数字是在实验室平板上、单一朝向测的，
装进用户机箱后不是那个数。给表就是给一个不属于这张板子的答案。

## 17.4 已知未实现（诚实清单）

`calc_capabilities` 的 `not_implemented_yet` 里与本层有关的条目：

- SPICE 只是子集：有 `.subckt`（拍平，见 `33`）、`.param`（见 `34`）、行为源 `B`（见 `35`）、**无损**传输线 `T`（见 `36`）、**有损**线 `O` / URC `U`（见 `37`，但那是集总梯形不是分布解，皮肤效应/介质损耗/频变 r,l 都不在里面）、`.noise`（见 `38`，只有热噪声/散粒噪声/沟道热噪声，没有 `1/f`、burst、induced gate）、受控源 `F`/`H` 加互感 `K`（见 `40`，但 `K` 是理想耦合：没有磁芯损耗、频变电感与饱和，`F`/`H` 的增益也只能是常数，没有 `POLY()`）与压控/流控开关 `S`/`W`（见 `41`，但它是**分段线性电导**：没有电荷注入、没有结电容、没有先断后合，`RON` 不许为 0）

  XSPICE（`code_model:` 命令不存在），所以「内置拒绝、引擎能跑」在本仓库**已无真实载体**

## 17.6 行为源 `B` 进内置（`0.0.29`）

`B` 卡不再按名字拒绝：右侧表达式在**解析期**翻译成拼写等价的 Python、再经 `ast` 白名单变成一棵
树，求解期只对这棵树求值。因此语法错带行号报在解析阶段（`cannot read the expression`），而不是
伪装成「牛顿不收敛」。节点引用按源码文本取（`V(1)`、`V(n-1)`、`V(in)` 在 Python 里分别是数字、
减法、关键字——三种都曾被静默读错），参数在构建期折成数字，AC 按偏置点线性化。

同一轮抓到一个与 B 无关却由 B 逼出来的真缺陷：牛顿的 KCL 残差判据原来用**全局**尺度
（`1e-9 + 1e-6*max|x|`），于是一个 4000 V 节点把门槛抬到 4 mV，1 kΩ 支路上 1 mA 的残差被当成
收敛。改成**按行**缩放后同一张 deck 7 次迭代收敛到 4000.000 / 2000.000。

不做：`laplace()`（复频域）、`I(Vname)`、`ddt`/`idt`、B 源噪声——全部按名拒绝并进 `not_computed`；
传输线 `T`/`O`/`U` 已经补上（§17.7、§17.8），`.noise` 在 `0.0.32` 进内置（§17.9）。
口径见 [`35`](35-B源与表达式.md)。

## 17.7 无损传输线 `T` 进内置（`0.0.30`）

`T` 卡（`T1 n1 n2 n3 n4 Z0=<ohm> TD=<s>`，或 `F=`/`NL=` 给同一个延迟）不再按名字拒绝。
三个分析各用各的式子，都是**理想无损线**的解析答案而不是它的离散近似：

- **DC**：无损线没有压降，所以它就是导线。实现是**一个**支路未知量加一行
  `v(n1) - v(n2) - v(n3) + v(n4) = 0`，`i2 = -i1` 由构造给出。第一版按「每个端口一个未知量」
  写，`T1 2 0 3 0`（两端口共地）会让第二行退化成 `0 = 0`、矩阵奇异——这是一个只在最常见的
  单端画法上才现形的坑。
- **AC**：精确 Y 参数（`Y11 = Y22 = -jY0·cot θ`、`Y12 = Y21 = +jY0·csc θ`，`θ = 2πf·TD`）。
  判据是定义本身：终端接 `Z0` 时必须**恰好**呈现 `Z0`（`|V(3)| = 0.5` 与频率无关）、
  相位必须恰好是 `-ωTD`（50 MHz 一档 `-18°`）、近端相位必须为 0。
  `θ = kπ` 处导纳无穷，**拒绝**（`SINGULAR`）而不是返回矩阵算出来的巨大数；
  `|sin θ| < 1e-3` 给答案但只告警一次（数字病态，不能说它可信）。
- **瞬态**：特征线法（Bergeron），每个端口一个 `1/Z0` 电导加一个「一个延迟之前那一端」的电流源。
  对理想线这不是离散化：误差只来自 `t-TD` 落在两步之间的线性插值。`t=0` 用直流点播种。
  匹配阶跃 ⇒ 远端在 `TD` 前 0 V、后 1.5 V 而近端恒 1.5 V；开路 ⇒ 远端 `TD` 处翻倍到 3.0 V、
  近端 `2·TD` 处翻倍（反射回来）；短路 ⇒ 反射系数 −1。

两条拒绝：`TD` 缺失或为 0（ngspice 会静默默认 0，把线变成导线）、`TD < tstep`
（远端要读一个还没解出来的时刻，钳到一步会把每次反射整体挪一步——第一版钳位实测晚约 2 步）。
`IC=`/`REL=`/`ABS=` 按名拒绝。

同一轮修掉一个与本卡无关、由它逼出来的真缺陷：`PULSE` 的宽度缺省原来是 0（零宽尖峰），
SPICE 的缺省是 `tstop`。这一条会让任何「不给宽度的阶跃」静默失效。

不做：`IC=`/`REL=`/`ABS=`、频变损耗/色散、多导体耦合线；半波点的有限答案需要损耗，理想模型
没有，所以不给。口径见 [`36`](36-无损传输线.md)。

## 17.8 有损线 `O` 与 URC `U` 进内置（`0.0.31`）

两张卡都不再按名字拒绝，但**它们不是分布线解**：解析期把 `LTRA`/`URC` 模型的 `r l g c len`
切成 `lump` 段普通的 `R`/`L`/`G`/`C`，求解器见到的是那串梯形（方程层一行没改）。所以

- 每个答案都报 `segments` 与 `segments_from`，默认段数进 `defaulted_model_params`
  （`{"O1.lump": 20}`），客服不知道答案是几段的这件事被消灭；
- **DC 是精确的**：没有 `g` 时梯形就是一段电阻链，1 Ω 在 3 V/50 Ω 分压里读
  `1.514851/1.485149`，`lump=1/2/8/20/50` 逐位相同（`v2=1.514851485`、`port1 = 3/101 A`，
  与 ngspice 的 `LTRA` 一致到 1e-6 以下）；
- **AC 收敛到分布解**：`g=1` 的 DC 解误差 `lump=1/2/5/10/20/50/100` →
  −1.433e-1/−9.337e-2/−4.350e-2/−2.284e-2/−1.169e-2/−4.744e-3/−2.383e-3；无耗梯形与 `T`
  在三个频点幅值一致、相位差 < 0.02°；`r=1` 时 1 MHz 读出 `0.5·e^-0.01 = 0.4950`，
  与 ngspice 的 `cross_check` 差 1.58e-7 V；`U` 与解析 `Z0c·coth(γL)` 在 1 MHz 差 1.1e-3；
- **`lump=` 只许写在 `.model`**：写在卡上对 ngspice 是 FATAL（`Error on line 4 or its
  substitute`），写在 `.model` 只是 warning——同一份 deck 要两边都能跑，段数只能进 `.model`；
- `LEN` 必须给（ngspice 也拒绝没有长度的 `LTRA`）；两个不同的返回节点拒绝（梯形把返回当
  理想单节点，`n3 != n4` 意味着返回导体自己有延迟，本梯形表达不了）；
- **顺手抓到的真缺陷**：`.ac` 里没有 `AC` 关键字的源原来被当成 1 V 激励（内置满幅、
  ngspice 全是 0）——SPICE 的规则是 `AC` 关键字才是激励，已改为 0 并在整份 deck 无人驱动时
  给出告警。

不做：皮肤效应、介质损耗（`G` 以外）、频变 `r`/`l`、两个不同返回节点、多导体耦合线；
`g>0` 没有引擎可对拍（ngspice-47 自己拒绝非零 `G`）。口径见
[`37`](37-有损线与URC.md)。

## 17.9 噪声分析 `.noise` 进内置（`0.0.32`）

`.noise V(out) <source> dec|oct|lin n fstart fstop`，输出也可以写差分 `V(2,3)`。它不再是
「只走委派」的那一项，但接上的方式是**伴随法**，不是「每个源解一次」：

- 在每个频点，`.ac` 那套复数 MNA 矩阵转置一次、解一次（`Aᵀy = e_out`），
  于是 a、b 两节点之间注入的任何电流源的输出响应就是 `y[a] − y[b]`，
  **一次求解覆盖全部噪声源**；增益与 `.ac` 的 `|V(2)|` 因此不可能分叉（它就是那个矩阵反着读），
  测试里 61 个点逐个对齐到 1e-9；
- 机制只有四条：`4kT/R`（`R`）、`2q|Id|`（`D`）、`2q|Ic|` 与 `2q|Ib|`（`Q`）、
  `4kT(2/3)gm`（`M`，饱和区）；`1/f`、burst、induced gate、雪崩**都没有**，所以低频 CMOS
  拿到的是**下限**；理想源/`C`/`L` 按构造无噪声（电容的 ESR 噪声是那颗 `R` 卡的）；
- 答案四件套：逐点谱密度、带内 rms、每元件份额、输入折算密度（增益为零时给 `null` + 告警，
  而不是 `inf`）。带内 rms 用**网格自己的变量**做梯形：`dec/oct` 在 `ln f`、`lin` 在 `f`，
  实测 `dec 10` 对 arctan 闭式差 −0.0009 %，而 `lin 1000` 差 +47 %（拐点被跨过去，不是实现错）；
- 解析对账：单只 1 kΩ 读 `4.071372237e-09`（`sqrt(4kTR)` 逐位），两只并联 `sqrt(4kT·500)`，
  四只串联是单只的**2 倍**（不是 4 倍——密度相加会读 4 倍），理想源短路一只电阻读 0，
  27 °C 与 327.15 °C 差 `sqrt(2)`；
- 与 ngspice-47 逐点对拍：分压/RC `1.7e-07`、MOS `1.7e-07`（`W/L` 修好后逐位）、
  二极管 `0.20 %`、BJT `0.29 %`（后两者是各自求偏置点的差，不是数值误差）；
- 兼容性差异：ngspice 要求输入源带 `AC` 说明否则整份 deck 中止，内置不要求；
  委派路径的 rawfile 有两个 plot（谱 + 积分），所以 raw 解析加了 `bytes_used` 与 `_raw_plots`；
- **顺手抓到的真缺陷**：MOSFET 的 `W=`/`L=` 一直被静默忽略（解析了但没进模型），
  等于每个器件弱 10~100 倍，噪声的 `gm` 直接继承这个错——已修，且因为唯一的旧用例不带 `W/L`，
  基线漂移为零。

不做：`1/f`/burst/induced gate/雪崩、失真相干噪声、Monte Carlo 器件离散、多噪声输出、
时域噪声。口径见 [`38`](38-噪声分析.md)。

## 17.10 JFET `J` 进内置（`0.0.36`）

`J`（结型场效应管）不再按名字拒绝。它需要一条新的器件方程，而不是一条 stamp，这一条比前几节都
更接近「换模型」；四条只能量出来的事实：

- **平方律里没有 `1/2`**。`BETA=1m`、`Vov=1` 读 `1.000 mA`，不是 MOSFET 的 `0.500 mA`；两式
  （饱和 `BETA·Vov²`、线性 `BETA(2·Vov·Vds − Vds²)`）在 `Vds=Vov` 处精确相接，故区域边界不需要
  平滑项，`Vds=0.999` 读 `0.999999 mA`（linear）、`Vds=1.001` 读 `1.000 mA`（saturation）；
- **`AREA` 是卡覆盖模型，不是相乘**：model `AREA=2` 配卡 `AREA=3` 读 **3×**（不是 6×）；
- **缺省要公示**：空 `NJF()` 用 `VTO=-2 / BETA=1e-4 / LAMBDA=0 / AREA=1`，全部列进
  `assumptions.defaulted_model_params`；
- **栅结不 stamp，但越界要说**：`gate_junction_forward_v` 超过 `0.5 V` 时加 `outside_model`
  并进信封 `warnings`；方向是实测的（NJF `max(vg-vd, vg-vs)`、PJF 镜像），不是从手册推的。

拒绝清单 15 条按名字（`RD`/`RS`/`B`/`IS`/`PB`/`MJ`/`FC`/`CGS`/`CGD`/`KF`/`AF`/`TCV`/`BEX`/
`BETA1`/`LAMBDA1`，另 `BETA<=0`/`LAMBDA<0`/`AREA<=0`），每条都实测「不拒会错多少」；`W=`/`L=`
由 ngspice 自己拒绝。口径与三口径对账见 [`42`](42-JFET.md)。

## 17.11 随包 SPICE 内核（`0.0.37`）

`A`（XSPICE 代码模型）不自己实现，改成把官方 `ngspice-47` 的**最小可运行子集**随工具打包
（`vendor/ngspice/`，14 MB），只由 `engine="ngspice"` 在「本机一个都没装」时兜底。完整口径、许可
证混搭表与三条路径事实见 [`43`](43-随包SPICE内核.md)，这里只留与本层直接相关的四条：

- **`engine="auto"` 不看随包**。`find_ngspice(allow_bundled=True)` 只被 `engine="ngspice"` 调用；
  默认引擎仍是 `builtin`。理由是「仓库长出 14 MB 目录不改变既有安装上 `auto` 的答案」——否则
  每一台已经跑通 `auto` 的机器都会换引擎。
- **查找顺序**：`PCB_AGENT_NGSPICE` → `PATH` 上的 `ngspice`/`ngspice_con` → **随包** → 目录扫描。
  随包排在启发式扫描之前、用户显式选择之后。撞不到时要能从信封看出来：`ENGINE_NOT_FOUND` 的
  `tried` 里会有一行 `bundled: …/vendor/ngspice/bin/ngspice_con.exe`；`auto` 失败时另有
  `bundled_engine` 字段 + `hint` 指路。
- **`A` 卡跑的三个数字**都在 `tests/test_spice_bundled.py` 与 selftest 里：`gain` 的 op 2.000 V、
  `limit` 对 5 V 削到 1.000 V、`gain(gain=3)` 的 `.tran 10u 100u` 末点 3.000 V。诚实项照旧：
  `netlist_parsed:false`、`netlist_parse_note` 点名 XSPICE、`cross_check` 报「无可比」。
- **数值风险为零**：系统手工解包副本与随包官方副本对 divider/diode/bjt/tran/ac/tline 六类 deck
  逐点对拍，`maxdiff` 全 0.0 到 1 ulp（`tran` 2045 点、`ac` 21 点、`tline` 97 点；复测同一张 AC deck 最大差 5.6e-17）。所以「随包优先」不会
  改动任何既有期望值。

不做：只随包 Windows x86_64（Linux/macOS 上 `find_bundled_ngspice()` 返回 `None`，查找顺序退回
原样）；不做 DLL 进程内方案（要写 raw 回调 + 线程安全，只省 ~10 ms 启动）；不翻译引擎报错；
不把 `A` 教会内置解析器（那是第二套器件描述语言，等于再写一个 ngspice 前端）。
