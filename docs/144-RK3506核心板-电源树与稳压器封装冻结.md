# 144 · RK3506 核心板：电源树与两颗稳压器封装冻结（0.1.6）

本批只做两件事，且两件都有边界：

1. **把电源从"20 个电源组"变成一棵可算树**——10 条轨、176 个球逐个落到轨上，5 V 取电的
   四条轨输出和算出来、与预算对账；
2. **把树上出现的两颗稳压器做成真封装与真符号**——几何仍取自立创官方库，不手画。

零板改动：`examples/rk3506_som/rk3506_som.kicad_pcb` 不动（仍是 0.1.1 的 6 层空板骨架）。

> 全文口径：**"没有时序表"这件事是查出来的，不是猜的**——手册两次全文检索 `sequence` 与 `DCDC` 各 0 命中。
> 因此本批**不编上电时序**、**不编每轨电流**：电流一律标注为 `design value`，`basis` 列里逐条写出依据。

### 2.4 两个实证的"没有"

- `grep -c sequence` = **0**、`grep -c DCDC` = **0** ⇒ 手册**没有上电时序表、没有 DCDC 设计指引**。
- Table 2-2 / 3-2 **不给每轨电流** ⇒ 任何"典型电流"都只能是设计取值，不许写成手册数。

### 2.5 一处关键读法（p39 Interface 表）

`ACODEC_ADC_VCM`(1B11) 与 `ACODEC_ADC_AVDD1V6`(1B12) 的方向列是 **O = 内部输出**。
⇒ 它们是 SoC 自己吐出来的，**不许接稳压器**（接了就是两电源对接）。本批把它们标 `INTERNAL`，
要求只有去耦电容（VCM 通常 1 µF + 100 nF，AVDD1V6 通常 1 µF）。**没有为它们画供电轨**。

### 4.1 分压轨为什么要设硬门禁

`+0V675_REF` 的带子 `0.6415 / 0.675 / 0.7090` 是 **DDR_VDDQ 带的一半**，由 `check_rail_bands`
的 `check_vref` 断言：`|typ − VDDQ_typ/2| ≤ 1e-6` **且** min/max 各自等于 VDDQ 的 min/max 折半。
换成 1 % 电阻后实际误差是 ±0.03 V 量级，**门禁查的是"定义对不对"，不是"电阻对不对"**——
两者分开，否则门禁会变成"我选的电阻是否满足我自己的判据"的自证。

合计 **176**，等于 0.1.1/0.1.3 记的球数（140 VSS + 1 AVSS + 33 电源 + 2 VREF… 逐组见下）。

按手册组名拆开（这是"哪个组去哪条轨"的唯一对照表，也是 `power_tree.py` 的全部映射逻辑）：

| 手册组 | 球数 | → 轨 |
|---|---|---|

| `LOGIC_DVDD` | 7 | `+0V9_LOGIC` |
| `CPU_DVDD` | 3 | `+0V9_CPU` |
| `PMU_LOGIC_DVDD0V9` | 1 | `+0V9_PMU` |

| `SYS_PLL_AVDD1V8` + `USB20_OTG_AVDD1V8` + `ACODEC_ADC_AVDD1V8` + `SARADC_AVDD1V8` + `TSADC_VCC1V8` + `MIPI_DPHY_AVDD1V8` | 1×6 | `+1V8_ANA` |
| `ACODEC_ADC_VCM` + `ACODEC_ADC_AVDD1V6` | 1 + 1 | `INTERNAL`（不接轨，只去耦） |

四条球级判据（任一不过即非零退出，退出码 **2**，不写字节）：

- `check_cover`：每个 Table 2-2 组都必须出现在 `power_balls.csv` 里；
- `check_unique`：一个球只能属于一条轨（`1A13` 的双列由它挡住，双列单独点名不去重）；
- `check_sources`：`source` 必须是已定义的轨（不许指向不存在的上游）；
- `check_load`：`load_ma ≤ rating_ma × 0.80`（`DERATING`，80 % 降额）。

### 5.1 输入侧 8.220 W 的算法（可复算，不含任何"典型效率"）

`8.220 W` 的口径是 `check_load()` 里**唯一**那个求和：只累加 `src == "+5V_IN"` 且
`kind == "regulator"` 的轨，项是 **`typ_v × load_ma / 1000`**。四颗 SY8113 全部命中：

```
+0V9_CPU   0.95 × 1200 mA = 1.140 W
+0V9_LOGIC 0.90 ×  800 mA = 0.720 W
+1V35_DDR  1.35 ×  800 mA = 1.080 W
+3V3       3.30 × 1600 mA = 5.280 W
                    合计 = 8.220 W
```

⇒ **这是"从 5 V 取电的四条轨的输出功率之和"，不是折算到输入侧的功率，也**没有**任何
效率系数**。所以 `8.220 / 10.0 = 82.2 %` 的正确读法是**输出侧 82.2 %**；真正从 5 V 抽的
电流还要按效率再放大——而手册不给效率、也不给每轨电流，本批**不编这个数**，故
`check_load()` 只把它当**下界**用（`input_power_w > 10.0` 才报错）。

同样**故意不进这个数**的：

- `AMS1117-1.8`（`src = +3V3`）——它的输入功率已经算在 `+3V3` 的 1600 mA 里，再算一次就是重复计数；
- `+0V9_PMU` / `+0V9_ANA`（`kind = bead`）——磁珠不产功率，它们的电流来自 `+0V9_LOGIC` 的 800 mA；
- `+0V675_REF`（`kind = divider`）——2 mA 从 1.35 V 分压取，量级可忽略且已含在 DDR 的 800 mA 之外，
  **不摊回去**（摊回去就是拿一个自己设的数再去证明这个数）。

**这个数不构成"选型正确"的证据**：它只说明在现有设计取值下 10 W 够用（且是下界）。
真正定器件要看 §4 的 `rating_ma` 是否被 `DERATING = 0.80` 挡住——那才是 `check_load()` 的另一半。

## 6. 取值理由（每条都有"为什么不选另一个"）

### 6.1 CPU 轨给固定 0.95 V，不做 DVFS

`CPU_DVDD` 的带是 0.855–1.103 V，说明它**能吃动态调压**。但 DVFS 需要 I2C 可编程
稳压器 + 反馈电阻切换 + 内核驱动配合，**核心板不做这件事**（它不是整机）。所以取带中央
**0.95 V** 的固定输出，`+0V9_CPU` 与 `+0V9_LOGIC` 用**同型号**（SY8113BADC）两颗分开供，
理由是手册要求两个独立电压域，且 CPU 电流尖峰不许污染 LOGIC。

### 6.2 PMU 与 ANA 用磁珠，不各配一颗稳压器

手册 p8 明确说 PMU 有**三个独立电压域**，但 `PMU_LOGIC_DVDD0V9` 的带 **0.81/0.90/0.99 与
`LOGIC_DVDD` 完全相同** ⇒ "独立域"是**去耦隔离**要求，不是"独立稳压器"要求。
一颗 0.9 V 经磁珠分到两处，比分三颗稳压器更省面积、更少一个环路。**这是本批唯一的
"少用器件"决定**，依据是两条带的 min/max 逐值相等（可被用例反查）。

### 6.3 VCCIO 全走 3.3 V，且 SDMMC 不切 1.8 V

`VCCIO*` 有**两个带**：1.62–1.98 或 3.00–3.63 ⇒ 它本身支持 1.8 V 与 3.3 V 两种电平。
本批全取 3.3 V，理由：外引到邮票孔的是通用 IO，3.3 V 兼容绝大多数外设；而 SD 3.0 的高速
模式要求 1.8 V 切换，本批**不做**（`VDD_ADJ_SD_OUT` 那套 1.8/3.3 可切是创龙的做法，需要
额外负载开关，属于整机功能）。**这条是限制，写出来**：如果后续要跑 SD UHS-I，`+1V8_ANA`
的 250 mA 余量里必须再切一份给 VCCIO，且要加负载开关。

### 6.4 无源参数留空（本批最诚实的一格）

要算 SY8113 的反馈分压、电感、输出电容，需要三样数：**Vref、fsw、ILIM**。这三样
**不在本仓库**（只有封装/符号，取自官方库），也没有从厂商手册核到 ⇒ `fb_divider` 字段
**留空**且在报告里显式列出。下一批的第一件事是取 SY8113BADC 厂商手册再算，
**在这之前不写任何电感的 µH 值、不写任何分压电阻的阻值**。

### 6.5 四条设计说明（都属于"现在不做，但必须记下来"）

1. **手册无上电时序** ⇒ 只依靠 SoC 内部 POR；外部不排时序（不编 `EN` 级联）。
2. **DDR3L 单 x16 无 VTT**：x16 单颗粒不需要 VTT 端接电源，只有多 rank/多颗粒并联才要。
   ⇒ 不生成 `+0V675_VTT` 轨，也不做"VTT = 拉/灌双向源"这个额外论证。
3. **VREF 用 1 % 分压而非稳压器**：VREF 只吸 µA 级，稳压器环路噪声反而更大；
   `1k/1k + 100 nF` 的分压阻抗足够低。
4. **`+3V3` 的 1600 mA 是打包值**：含 SoC IO + NAND + `+1V8_ANA` LDO 的输入电流 + `3V3_OUT`。
   逐项拆分留到原理图阶段做（现在拆是编）。

## 7. 工具修正：三条审计原来会拒掉真封装

这轮不是"让封装通过审计"，是**审计本身错了**，而错误是靠**仓库之外的官方库**发现的。

### 7.1 G6 包络必须用标题 LS，不能只用本体

旧规则：`|pad edge| ≤ body/2 + 0.75`。用 KiCad 官方尺子一量就崩：

- 官方 `Package_TO_SOT_SMD.pretty/TSOT-23-6.kicad_mod`：6 盘 **1.325 × 0.6** @ `x = ±1.1375`、`y = ±0.95/0`
  ⇒ 焊盘外缘 **1.80 mm**；本体 1.6 mm 宽（半宽 0.80）；`0.80 + 0.75 = 1.55 < 1.80`
  ⇒ **旧 G6 会拒掉 KiCad 自己的封装**。
- 修法：`land envelope = max(body/2, lead span/2) + 0.75`，`lead span` 从**库标题的 `LS`** 读
  （`--lead-span`）。TSOT 的 `LS2.8` ⇒ `1.4 + 0.75 = 2.15 ≥ 1.80` ✔。

反向对照（已写成用例 `test_land_envelope_uses_lead_span_from_title`）：同一份 TSOT 文档不给
`--lead-span` 时报 G6；给 2.8 之后过。另一条 `test_reverse_land_envelope_refuses_a_flying_pad`
把整组盘外移 1 mm，仍须被 G6 拒——**放宽不等于失效**。

### 7.2 G5 的节距轴必须测，不能假定 x

SOT-23 / TSOT-23 是"两列三行"：**节距在 y 上**。旧 G5 拿 x 判簇内间隙 ⇒ 0.800 mm 宽的盘
被判死，而沿 y 的真实间隙是 0.418 mm（合法）。

修法：`min_grid_gap_info(pad_rows)` 返回 `{"gap","axis","spans"}`，**同时给出轴**；
`pitch_axis` 一路传进 `resolve_pad_box()` 与 `audit()`。
用例 `test_pitch_axis_is_measured_not_assumed` **故意用未舍入的 gap 0.94996**（用舍入后的
`0.95` 会恰好通过，测不出刀锋边界）：x 轴抛 `GeometryError` 含 `along x`，y 轴解出 `0.8 × 0.532`、
间隙落在 0.41–0.42。

另一条反向对照 `test_reverse_pad_box_without_pitch_neighbour_is_not_guessed`：**没有节距邻居的盘
不许猜**——单候选直接接受，双候选抛 `GeometryError`（"has no pitch neighbour and its rot flag
swaps … state the box explicitly"）。SOT-223 的散热盘就是这种盘。

### 7.3 G4 必须用焊盘并集 bbox，不能用质心

SOT-223 是 **1 个散热盘在一侧 + 3 个信号盘在另一侧**的非对称盘组：质心偏 **1.42 mm**，
而图形完全居中 ⇒ 质心判据会误拒真封装。

修法：改判 **pad union bbox 居中 ±0.02**。它保住"原点没偏"的检测力（`test_reverse_off_centre`
断言文案 `"G4 pad union is not centred"`），又不误拒。
`KeyError: '4'` 的坑也由此来：G5 失败后 `boxes` 缺键 ⇒ G4 的 bbox 生成崩；已加 `_bw/_bh` 兜底。

### 7.4 无法判定的盘交给显式 override，不猜

`--pad-box NUM:WxH`（可重复）优先级最高，且**写进报告** (`pad_box_overrides`），
并用 G4 居中审计**反向确认**这个 override 没把图形推偏。
AMS1117 的散热盘就用了它：**(2.47, 3.6)**。

依据是外部尺子（§8.2）：官方 `SOT-223-3_TabPin2` 的散热盘是 **2.0 × 3.8 @ x=+3.15，长轴在 y**。
⇒ 立创文档里那个 `(2.47 沿 x, 3.6 沿 y)` 的**原样读法**与官方同向；交换读法 `(3.6, 2.47)` 会把
bbox 中心推到 `x = −0.28` ⇒ 被 G4 拒。这条已写成用例
`test_reverse_swapped_tab_box_is_refused_by_the_centring_audit`——**"我选的读法对不对"由审计反向回答，不由我说**。

### 7.5 courtyard 必须包住焊盘

`emit_generic()` 改成 `cw = max(hw, pw_max) + margin`（`pw_max = max(|x| + pw/2)`）。
理由：焊盘**合法越出**本体（SOT-223 4.07 对 1.75、TSOT 1.60 对 0.80），裁到自己盘的 courtyard
就报不出与邻居的真重叠。**只增不减** ⇒ 焊盘在本体内的封装**字节不变**（已用 `diff` 过滤
`descr`/`tags` 后确认零几何差）。

**踩过的坑（留在这里防复发）**：第一次编辑误改到 `emit_footprint()`（圆盘路径，无 `pad_specs`
变量）⇒ BGA/DDR 生成路径会 `NameError`。已回退 `emit_footprint()` 为 `hw + margin`，修复只留在
`emit_generic()`。判据是 `inspect.getsource` + `grep pw_max`，不是"跑一次没报错"。
