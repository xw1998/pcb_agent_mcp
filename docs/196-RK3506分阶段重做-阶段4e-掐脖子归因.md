# 阶段 4e —— 掐住走廊的到底是谁：报表能点名了，而这块板上的上界就是半个球距

`193` 量出「环买到的空气上限只有 +0.05 mm」，`195` 量出「契约也补不上那 0.175 mm」。两轮之后留下的都是同一个数——**腰部净空 0.300 mm，可读齿要 0.475 mm**（按 `188` 的 0.25 线宽；这块板 0.1 线宽下是 0.40 mm）——但没有人回答那个必须回答的问题：**差的那 0.10–0.175 mm 是被什么挡住的？** 一个「小」字不是归因，`gap_mm` 只能看见本轮自己画出来的铜，而真板上站在走廊里的大多不是本轮的东西，是出线（escape）先落下的过孔与短线。

这一轮做两件事：**把归因做进能力**（`stats.bundle_bands[].reserve.gap_mm[<net>].pinch`，报最近那个对象的边到边距离、类型、网名、来源、位置、层），**再把这块板的几何上界算出来**。结论先说：**上界是半个球距**——`0.5621/2 = 0.281 mm`，实测 0.2475–0.2828 恰好贴着它；可读齿要 0.40–0.475 mm ⇒ 在这块 0.5621 mm 的 BGA 上，走廊里那个宽度 **是几何不可能，与路由顺序、预留、契约都无关**。要它必须动出线几何（或把等长挪到 U2 侧 0.8 mm 间距的走廊）。

本轮不升版本、不进 CHANGELOG（沿用 181–195 的先例）；工具数不变（262），因为 `bundle_bands` 三参数按 `194` 的裁定不上工具面，`pinch` 只是离线报表里的一个字段。

## §1 结论先行

**代码改动**（全部在 `route/router.py::_band_reserve_gap`，零新依赖、零工具面改动）：

| 位置 | 内容 |
|---|---|
| 老铜清单 | 一次性从 `board.tracks` / `board.vias` / `board.footprints[].pads` 建 `bsegs`（网、层、线段、半宽）/`bvias`（网、中心、半径）/`bpads`（网、中心、宽高、层集、`ref.number`）；半宽缺失时按 `bundle["track_mm"]`/`via_diameter_mm` 兜底 |
| `_pinch(n, mine, hw, nsegs, nvias, npads)` | 沿该网**每一段自己的铜**按 0.1 mm 采样（跳过自身焊盘 1.0 mm 内的样本，沿用 `gap_mm` 的口径），对同层的外来 track / 全部 via / 同层焊盘取**边到边**最小，返回 `{edge_mm, kind, net, source, at, layer}`；`source ∈ {"board", "this_plan"}`，焊盘时 `source` 是 `ref.number` |
| 剪枝 | 按网框一次筛掉不可能进 `gap + 0.5` 的对象（bbox 下界是合法下界），不是每个采样点重扫全板 |
| 计时 | `reserve["pinch_s"]`：只给 `pinch` 自己计时，用来把「新代码到底花了多少」和「机器今天多忙」分开 |
| 报表 | `gap_mm[<net>]` 新增 `pinch`（无外来铜时不写这一键，不臆造） |

**真板读数**（`D:/tmp/_s1d.esc2.kicad_pcb`，12 网、端点钉 `In2.Cu`/`B.Cu`、pitch 0.05、track 0.1、via 0.2/0.1、clearance 0.105；4 网 mm 0.5 / price 2，12/12 通、118 op、spread 5.927、`pre 8649 / ring 15679`）：

| 预留网 | `gap_mm`（只管本轮自己的铜） | `pinch.edge_mm` | 掐住者 | 来源 | 位置 | 层 |
|---|---|---|---|---|---|---|
| `/DDR_DQ1` | 0.2828（`/DDR_DQ3`） | **0.1828** | track `/DDR_DQ3` | this_plan | (20.843, 14.243) | In2.Cu |
| `/DDR_DQ2` | 0.2475（`/DDR_DQ4`） | **0.1475** | track `/DDR_DQ4` | this_plan | (20.671, 15.479) | B.Cu |
| `/DDR_DQ3` | 0.2500（`/DDR_DQS0N`） | **0.1123** | via `/DDR_DQ2` | **board** | (20.700, 22.299) | In2.Cu |
| `/DDR_DQ6` | 0.2500（`/DDR_DM0`） | **0.1500** | track `/DDR_DM0` | this_plan | (19.050, 15.575) | In2.Cu |

四条读法：

1. **`gap_mm` 会给你一个「看起来正常」的错答案**：DQ3 的 `gap_mm` 报 0.2500（和另外三条一个量级），但真正贴住它的是**老出线过孔 `/DDR_DQ2` @(20.700, 22.299)，边到边只有 0.1123 mm**。只看 `gap_mm` 会读成「走廊就这样」，而实际答案在「板上早就有的东西」里——这就是 `pinch` 存在的唯一理由。
2. **三个 `this_plan` 的读数与 `gap_mm` 逐位自洽**：0.2828−0.05−0.05=0.1828、0.2475−0.1=0.1475、0.2500−0.1=0.1500（track 减两条半宽）。也就是说 `pinch` 没有另算一套几何，它只是在同一把尺上把「谁」和「边到边」补齐。差 0.05 的那两条说明最近对象本身也是 0.1 mm 线。
3. **via 不受层过滤**（via 穿全层），track/焊盘必须同层——跨层量距离会把合法的交叉报成 0.00 mm，那是「空气」的反面。
4. **口径边界照实写**：`pinch` 继承 `gap_mm` 的「跳过自身焊盘 1.0 mm 内样本」，所以它报的是**走廊腰部**，不是焊盘出口；出口那一两格按定义就是扇出间距，量它没有信息。因此 `pinch` 与「整网扫一遍」的探针会给出不同的最近对象，两者不是同一个搜索空间，不可互相校验。

## §2 为什么上界是半个球距

真板 DDR 两侧出线栅栏实测（`D:/tmp/_ddr_esc6.json`，50 网两侧）：

| 侧 | 最近中心距 min / 中位 / max | 扣掉两个 0.2 mm 孔后的空气 |
|---|---|---|
| U1（MCU 侧） | **0.3462 / 0.5620 / 0.8944** | min **0.1462** |
| U2（DDR 侧） | 0.8000 / 0.8000 / 1.1314 | min **0.6000** |

U1 侧的排列是两行球各自出线：Y 行 `y = 22.661`、W 行 `y = 23.223`（行距 **0.5621**），Y 行直出到 `y = 22.311`，W 行斜出（`+0.25, +0.25`）到 `y = 22.973`。于是同一行相邻两个出线孔的中心距就是 0.5621（例：`/DDR_DQ2` @20.438、`/DDR_DQ1` @21.000），扣掉两个 0.2 mm 孔剩下 **0.362 mm 的缝**。

任意一条网要从这条缝里穿过去，它到**任一**邻居的中心距上限就是**半个中心距**：

```
0.5621 / 2 = 0.281 mm
```

实测腰部 `gap_mm`（中心距口径）0.2475–0.2828 **正好贴着这个上界**；0.2828 略超 0.0018，是因为那一段最近的对象不是出线孔而是同层的 plan 短线（`nearest` 就报 `/DDR_DQ3`），上界不约束它。这不是路由没做好，是**走廊宽度由出线栅栏的球距定死**：中心距上界 0.281 mm，减去两条 0.05 半宽 ⇒ 边到边上限 **0.181 mm**（`pinch` 实测 0.1123 / 0.1475 / 0.1500 / 0.1828，同一量级同一条线上）。

而可读齿要的中心距是 `0.15 可读振幅 + 半线宽 + 0.20 清洁地板`（`188 §7` 的算式）：按 `188` 的 0.25 mm 线宽是 **0.475 mm**，按这块板的 0.1 mm 线宽是 **0.40 mm**。两种口径都远大于 0.281 —— `0.281 < 0.40 < 0.475`，差至少 **0.119 mm**。这一格缺口到此就归因完了：**不是谁没让，是这块 BGA 的出线栅栏上根本没有那么宽的格子**。

同一批读数里另有一条同向证据：`/DDR_DQ3` 腰部的物理走廊宽度是 **0.370 mm**（垂直射线两侧各打到一个出线过孔：`+0.205` 到 `/DDR_DQ1`、`−0.165` 到 `/DDR_DQ2`，`_width.py` 实测），`/DDR_DQ6` 那一段反而是 1.005 mm —— 说明「挤」是局部的、位置在出线栅栏的腰部，不是整条走廊都窄。

## §3 读数与三条反向失败对照

- **`pinch` 真的看板上的老铜**：`test_route_reserve.py::TestPinchNamesWhatIsInTheWay` 在路由前写一条 `F.Cu` 上的老 track（`/GND`），断言 `pinch.source == "board"`、`kind == "track"`、`net == "/GND"`、`layer == "F.Cu"`，并且 `edge_mm ≈ 0.25`（= 0.5 中心距 − 0.25 两条半宽）。**这一条同时是定量对照**：若代码量的是中心距会报 0.5、若忘了减两条半宽会报 0.375，两者都过不了 `delta=0.06`。
- **不臆造**：没有 reserve 就不进这个函数（`test_the_reserved_net_gains_room_at_the_waist` 断言无预留时 `stats.bundle_bands[0].get("reserve") is None`）；有预留但没有外来铜时 `pinch` 键不存在（`if corner`）。
- **不把自己算成别人**：所有断言都带 `pinch.net != <本网>`。
- **代价是量出来的，不是猜的**：`pinch_s = 0.026 s`（12 网、4 个预留网）。同一配置今天跑了三次：`elapsed` 33.6 / 32.5 / 33.1 s，三次 `ops 118`、`spread 5.927`、`pre 8649`、`ring 15679`、四个 `pinch` 读数**逐字段相同**；`195` 同配置当初报 25.9 s。相差 6–8 s 而 `pinch_s` 只有 0.026 s ⇒ **差的是机器负载，不是这段新代码**，这一点不实测就没法说。

## §4 未做项与真正的出路

这一节不写「布局账」这种空话，写具体动作与各自的代价：

1. **要 0.40–0.475 mm，必须动出线几何**（球距 0.5621 决定了上界 0.281）。三条候选：① 相邻球交替分到不同层出线（同一层的栅栏间距翻倍到 1.124 mm，代价是每对相邻球多一个 via）；② 加宽出线孔的行距（改封装/改球定义，属于器件级）；③ 加层（出线不再是单层瓶颈）。三条都不是路由能自己决定的，需要单独立项并先预注册判据。
2. **或者把等长挪到 U2 侧**：U2 侧最近中心距 **0.800 ≥ 0.475**（空气 0.600，边到边余量 0.325 mm），够可读齿。代价是走线全部压到 DDR 端，回到 MCU 端的长度要靠绕行补齐——这是「哪一端做等长」的选择题，不是优化题。
3. **`pinch` 的适用边界**：它只看同层铜与 all-layer via，不看 zone（铺铜由官方 `ZONE_FILLER` 生成，不在本函数视野内），也不看 keepout；因此「pinch 很大」**不等于**「这段能走 0.475 的齿」。
4. **0.2 mm 余量仍是交换不是解法**（`188 §4`：floor 0.2→0.1 让短网可加数 5→2/4），本轮未动。
