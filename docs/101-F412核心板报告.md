# 101 · STM32F412RGT6 核心板：DRC 118 → 0 之后，把读数落成一张可对账的板

> 它回答的问题：一块用本仓库全流程做出来的板，DRC 清零、出图落位、交付包八种格式齐全之后，
> **它到底是一块什么样的板**？哪些数是量出来的、哪些是没做的？
>
> 它推翻的前提：**「DRC 0 就等于做完了」**——DRC 只检查规则，不检查「电源和信号同宽」
> 这种**合规但工程上会被追问**的事实。下面第 101.4 节就是这件事的量化。

---

## 101.0 两句话

1. 板子：**STM32F412RGT6 + W25Q64JVSSIQ（QSPI NOR）+ USB Micro-B + 面包板兼容双排 1×20**，
   四层 **53.34 × 30.48 mm**、32 个封装、54 个网、DRC **0 / 0 / 0**、交付包八种格式全出。
2. 必须说清的一条现状：**全部 556 段导线都是 0.15 mm**（含 +3V3），因为一个叫 `Fanout` 的网络类
   把 54 个网**全部**装了进去。0.5 A 下压降 2.943 mV 完全可接受，但按 IPC-2221 算，
   0.15 mm/1 oz 外层在 ΔT = 10 °C 只到 **0.604 A**——**这块板不能当大电流板用**。

## 101.3 布线读数是量出来的，不是「看图上差不多」

| 读数 | 值 |
|---|---|
| 导线段 | **556** 段 `segment`，**宽度全部 0.15 mm**（不做四舍五入，逐段统计只有这一个值） |
| 按层 | `F.Cu 336` / `B.Cu 130` / `In1.Cu 50` / `In2.Cu 40` |
| 过孔 | **129** 个，**全部 0.45 / 0.2 mm**，全部 `F.Cu↔B.Cu` |
| 过孔按网 | `GND 37`、`+3V3 22`、`NRST 6`、`BOOT0 5`、`USB_DM 4`、`W25_IO2 4` |
| 铺铜 | **2 个**：`GND → In1.Cu`、`+3V3 → In2.Cu`，各 **1 个** `filled_polygon`，`min_thickness 0.1`、`connect_pads clearance 0.25` |
| 走线覆盖网 | 54 个（板上一共 55 个 net 条目，含空网 0） |
| +3V3 的走线 | 22 段，**全在 F.Cu**（另 24 个焊盘在 +3V3 上，靠 In2 铺铜与过孔连） |
| GND 的走线 | 31 段（`F.Cu 30` / `B.Cu 1`），其余靠 In1 铺铜 |

两个岛（In1 的 GND、In2 的 +3V3）**各只有一块 filled_polygon**，说明填充没有裂岛；
`island_removal` 未写（KiCad 默认「删除孤立岛」），`fill_mode yes`（整板填充）。

## 101.4 电源和信号同一个线宽：真实的因，量化后的后果

### 因

`board_view.facts.net_classes` 里只有两个类：

| 类 | clearance | trace_width | via_dia/drill | 装了哪些网 |
|---|---|---|---|---|
| `Default` | 0.2 | 0.25 | 0.6 / 0.3 | **无**（`nets_in_class: []`） |
| `Fanout` | 0.15 | **0.15** | 0.45 / 0.2 | **54 个，全部**——`+3V3`、`GND`、`USB_DP/DM`、`W25_*`、每一个 GPIO 都在里面 |

所以「556 段全是 0.15」不是布线器随手挑的宽度，而是**一个网络类把电源网和信号网绑在同一档**。
这条事实 DRC 不会报（0.15 ≥ 板级最小 0.15），只有把类读出来才看得见。

### 后果（IPC-2221，外部层）

公式 `I = k · ΔT^0.44 · A^0.725`，`k = 0.048`（外层）/ `0.024`（内层），`A` 为 **mil²**
（来源：[IPC-2221 载流式说明](https://blog.raatools.net/pcb-design-basics-trace-width-current)、
[嘉立创线宽指南](https://jlcpcb.com/blog/pcb-trace-width-guide)，两处常数一致）。

`0.15 mm × 1 oz` ⇒ `A = 5.905 mil × 1.378 mil = 8.1378 mil²`，代入：

| 工况 | ΔT |
|---|---|
| 0.5 A，外层 | **6.50 °C** |
| 1.0 A，外层 | **31.4 °C** |
| 0.5 A，内层（`k=0.024`） | **31.4 °C** |
| ΔT = 10 °C 允许的电流 | 外层 **0.604 A** / 内层 **0.302 A** |

结论：这块板的 +3V3 走 0.5 A 温升 6.5 °C，可以；**到 1 A 就不该再用 0.15 mm**。
本板 +3V3 的 22 段走线全在外层，而且大部分电流实际走 In2 铺铜（那里截面大得多），
所以 `board_ir_drop` 报的压降是**铺铜参与建模**后的数（`model_zones=True`）。

## 101.5 IR drop：三个数互相咬合

`+3V3`，源 `J2A.1` → 汇 `U1.1`，电镀 25 µm，`model_zones=True`：

| 电流 | `max_drop_mv` | `worst_sink_drop_pct_of_3v3` | `total_copper_loss_w` |
|---|---|---|---|
| 0.5 A | **2.943345** | **0.089192** | `0.001471197` |
| 1.0 A | **5.886690** | **0.178385** | `0.005886420` |

两行各自内部咬合：`100 × 2.943345 / 1000 / 3.3 = 0.089192`（[100 篇](100-百分比与毫伏的单位.md) 修好后
的口径）。两行之间也咬合：线性网络 ⇒ 压降 **恰好 2.000000 倍**、铜损 **恰好 4.000000 倍**
（`0.001471197 × 4 = 0.005884788`，实测差 1.6e-6 来自输出的 6 位有效数字），
这正好是一条**不需要外部真值**的自洽校验。

最坏的一段：`F.Cu 0.65 mm × 0.15 mm`，`R = 2.134412 mΩ`，`0.5 A` 下
`drop 1.067206 mV`、`power 0.533603 mW`、**电流密度 95.238095 A/mm²**。
95 A/mm² 这个数字看着吓人，但它不等于会烧：温升由上面那套 IPC 算式给出（6.5 °C），
密度只是「这段为什么是瓶颈」的定位量，**引用时必须带线宽与铜厚**，否则是无意义的大数。
1 A 下它变成 `190.476190 A/mm²`、温升 31.4 °C —— 这就是 101.4 那排数字的现场版本。

## 101.6 DRC：七个读数，每一档修什么

全部由 `kicad-cli 10.0.7 pcb drc --format json` 产出，文件都在 `_scratch/f412rg/`：

| 文件 | 违规 | 按规则拆开 |
|---|---|---|
| `drc_before97.json` | **118** | `text_height 32` / `holes_co_located 28` / `silk_over_copper 24` / `hole_to_hole 16` / `silk_overlap 14` / `via_dangling 2` |
| `drc_after_holes.json` | **76** | `text_height 32` / `silk_over_copper 24` / `silk_overlap 14` / `via_dangling 2` / `silk_edge_clearance 2` / `hole_to_hole 2` |
| `drc_after_holes2.json` | **72** | 同上去掉 `via_dangling` 与 `hole_to_hole` |
| `drc_silk1.json` | **46** | `silk_over_copper 26` / `silk_overlap 18` / `silk_edge_clearance 2` |
| `drc_silk2.json` | **17** | `silk_overlap 15` / `silk_over_copper 2` |
| `drc_silk3.json` | **2** | `silk_overlap 1` / `silk_over_copper 1` |
| `drc_silk4.json` | **0** | — |
| `drc_shift.json` | **0** | 整板平移之后重跑，`unconnected 0` / `schematic_parity 0` |

三段的因（KiCad 自己的描述原文照抄）：

- **28 + 16 条孔**：`Drilled holes co-located`、`钻孔太靠近其他孔（最小 0.2500 mm；实际 0.0000 mm）`
  —— LQFP-64 与 SOIC-8 的焊盘钻孔和手工放的过孔重合了。
- **32 条字高**：`文字高度超出范围（"丝印文本高度" 约束 最小高度 0.8000 mm；实际 0.7000 mm）`
  —— 这条**不是板厂规矩**，是本板 DRC 配置里 `min_text_height = 0.8`。0.8 mm 才是常见板厂
  丝印下限，原来的 0.7 mm 连自己的规则都过不了。
- **24 + 14 条丝印**：`Silkscreen clipped by solder mask`、`Silkscreen clearance`
  —— 位号压在焊盘上。做法见 [98 篇](98-字段的图层位置与字号.md)：先改字号再改位置，不靠「挪一点点运气」。

`unconnected` 与 `schematic_parity` **从第一份起就是 0**：布线是连通的，网络表也和原理图一致，
118 条全是**工艺/丝印类警告**，不是「板子不通」。这一点必须写出来——否则「118 → 0」会被读成
「原来板子是坏的」。

## 101.9 诚实披露：这块板**没做**什么

1. **没有阻抗控制**。USB_DP/DM 是 0.15 mm 单端走线，不是 90 Ω 差分对；
   QSPI 也没有等长/间距约束。四层 1.6 mm 上算 90 Ω 差分需要专门的线宽间距组合，
   本板没做，也不假装做了。
2. **电源与信号同宽（0.15 mm）**，见 101.4。想上 1 A 必须：把 `+3V3` 从 `Fanout` 类里拿出来单独给
   0.5 mm 上下，或者继续让铺铜承流并把过孔加密。
3. **缝合孔不是先做的**。129 个过孔里 37 个 GND、22 个 +3V3 是布线过程中补的，
   不是「先铺 GND、先缝合、再走信号」那条顺序。
4. **没有板边工艺**：无邮票孔、无 V-cut、无拼板、无阻抗测试条。
5. **单板、无原理图工程交付**：本目录只落地 `.kicad_pcb`；网络表来自生成本身，
   `schematic_parity` 为 0 是因为没有原理图可比，不是「比对通过」。
6. **没做热与机械**：`board_ir_drop` 只算铜的直流压降（0.5 A/1 A 档），
   没跑 `thermal_*`、没跑振动、没做电流密度随频率的分布。

## 101.10 三条教训

1. **DRC 0 是规则 0，不是工程 0**。0.15 mm 的电源线在 DRC 里完全合法，
   工程上却是「只能到 0.6 A」。规则检查与设计意图之间那一段，只能靠**读出网络类**来补。
2. **「全是同一个值」是一个信号，不是一个巧合**。556 段全 0.15 时正确的动作不是
   「看看合不合规」，而是去问「谁把它们绑在一起的」——答案是 `Fanout` 类的 `trace_width`。
3. **数字要能互相咬合**。2.943 mV / 0.089 % / 1.471 mW、0.5 A 与 1 A 的 2 倍与 4 倍关系、
   ΔT 算式与 0.604 A 上限——这些都在没有外部真值的情况下互相钉住了对方的数量级；
   反过来，89.19 % 那个数当年就是**谁都不咬合**才藏了 1000 倍。
