# 转化架构总纲：无损索引 + 六种离散原语 + 精确问答

日期：2026-10-27
本文件推翻 01~04 篇的一个隐含前提（"把 PCB 压缩成一份好读的摘要交给模型"），给出真正的转化方式。

---

## 0. 错误的前提：把"无损"和"可读"当成一个东西

前面四篇都在找"摘要的粒度"。这个方向本身错了：

- 摘要越粗 → 模型好读，但丢信息（用户已经指出：布局全丢）；
- 摘要越细 → 信息在，但模型读不动（247 个 tool、几十万坐标就是这条路）。

这两者之间**没有最优点**，因为它们是同一个量的两端。正确的做法是**换一个维度**：

> **无损不是"模型看到全部"，而是"任何一条事实都问得到准确答案"。**
> 可读不是"摘要够短"，而是"模型只操作它擅长的离散对象"。

换成可执行的定义：

**«无损» = 对信息分类表中的每一条 F，要么 F 精确地存在于离散层，要么存在一个精确查询 Q_F 能返回 F 的完整精度。不允许第三种情况。**

这是一条**可以被 CI 验证**的性质，而不是一种说法。整篇设计就是围绕它展开。

---

## 1. 三件套（职责严格分离）

```
┌──────────────────────────────────────────────────────────────┐
│ ① Canonical  权威层 = EDA 自己的模型（文件 / IPC / 扩展对象） │
│   · 唯一的真值，永不重新编码、永不二次序列化                  │
│   · 所有写操作经引擎 API 落盘，保证不破坏引擎不变量             │
│   · 无损在这里是 trivial 的：它就是原件                        │
├──────────────────────────────────────────────────────────────┤
│ ② Discrete   离散层 = 只装"本来就离散"的事实                  │
│   · 六种原语：图 / 关系 / 模式 / 预算 / 裁决 / 地图            │
│   · 每一条都可机判、都可追溯到 ① 里的句柄                      │
│   · 这是模型唯一直接阅读的东西；它按定义不携带连续量            │
├──────────────────────────────────────────────────────────────┤
│ ③ Oracle     问答层 = 精确测量函数                            │
│   · 任何连续问题（多长/多远/放得下吗/共路径多少）都到这里算     │
│   · 返回精确值 + 精度标签；模型不自己算                        │
└──────────────────────────────────────────────────────────────┘
```

**关键点：② 不需要压缩 ①，因为 ② 里根本没有 ① 的连续量。** 所以"粗化"这件事被彻底取消了——不存在"把 63×33mm 的板子降采样到 60×30 格"这一步，只有"模型需要看大概时，问地图；需要判断时，问 oracle"。

## 2. 六种原语（覆盖全部 PCB 信息，且全部是模型擅长的形态）

| 原语 | 形式 | 精确性 | 模型擅长度 | 覆盖的信息 |
|---|---|---|---|---|
| **G 图 Graph** | 节点+边，节点是句柄 | 精确（拓扑天然离散） | ★★★★★ | 连接关系、层次、接地拓扑、信号流、依赖、通路 |
| **R 关系 Relation** | 谓词 + 容差 + 参与者 | 精确（可机判真假） | ★★★★☆ | 对称、邻接、远离、同面、共轴、包含、顺序、朝向 |
| **P 模式 Pattern** | 命名模板 + 参数绑定 | 精确（实例化由求解器） | ★★★★★ | 共质心、交错、差分对、Kelvin 取样、去耦环路、屏蔽环、星点 |
| **B 预算 Budget** | 目标 / 已消耗 / 余量 | 精确（由 oracle 算） | ★★★★☆ | 噪声、增益、温漂、环路面积、载流、间距、成本 |
| **V 裁决 Verdict** | 三态：ok / warn / error + 成因 + 动作 | 精确（判定器产出） | ★★★★★ | DRC、ERC、布局指标、制造可行性、豁免 |
| **M 地图 Map** | 粗栅格，**显式标注不可用于判定** | 近似（声明） | ★★★☆☆ | 只用于"东西大概在哪"的定位感 |

这六种原语**没有一种需要模型做连续数学**。而 PCB 的全部信息都能归到其中一种——这是下面 §3 要逐条验证的。

### 2.1 连续量去哪了？

连续量只走三条通道，全部不经过模型的自由阅读：

| 通道 | 处理 | 例子 |
|---|---|---|
| **可无损离散化** | 写进离散层 | 连接、层次、拓扑、顺序、是否同面、矩形区域归属 |
| **必须精确查询** | 留在 ①，用 ③ 取 | 坐标、间距、环路面积、共路径长度、旋转角、多边形顶点、孔位 |
| **只能估算** | 由 ③ 算并**强制标注 `estimated: true` + 方法** | 温度场、回流路径、耦合强度、SI/PI 定量 |

**禁止第四条通道**（"给个大概数字让模型自己推"）——这正是前面所有摘要方案的失败点。

## 3. 信息分类表 → 原语映射（无损性清单）

每条都要落到 `digest` 或 `oracle`，落不到就是 bug。下表是必须覆盖的最小集。

### 3.1 连续量 → oracle（不进 tokens）

| 事实 | Oracle 查询 | 精度 |
|---|---|---|
| 器件/焊盘精确位置与角度 | `at(ref, {frame: absolute\|anchor})` | exact |
| 焊盘几何（形状/圆角/槽孔/阻焊/钢网） | `pads_of(ref, {detail: full})` | exact |
| 两点间距、最小间距、间隙 | `dist(a,b)` / `min_clearance(a,b)` / `gap_at(x,y,layer)` | exact |
| 能否放下某器件 | `fits(ref, rect)` | exact（多边形求交，不是栅格） |
| 走线几何（含圆弧） | `trace_geometry(net)` | exact |
| 板框多边形 / 内部开槽 | `outline()` | exact |
| 环路面积 / 共路径长度 | `loop_area(nets)` / `shared_path(na,nb)` | exact |
| 跨分割数 | `cross_split(net)` | exact |
| 叠层参数与阻抗 | `stackup()` / `impedance(trace)` | exact（查表） |
| 位号/属性/MPN/功耗 | `props(ref)` | exact |
| 3D 高度与净空 | `height(ref)` / `z_clearance(rect)` | exact |

### 3.2 天然离散 → digest（精确且进 tokens）

| 事实 | 原语 |
|---|---|
| 网表、引脚↔网络 | G |
| 层次（工程/页/块）、多单元器件 | G |
| 接地拓扑（星点、分割、连接点） | G |
| 信号流顺序、功能块划分 | G + R(order) |
| 对称、邻接、远离、同面、共轴、包含 | R |
| 共质心/交错/差分对/Kelvin/去耦环/屏蔽环 | P |
| 预算目标与消耗、余量 | B |
| DRC/ERC/布局指标/制造可行性/豁免 | V |
| 引脚电气类型、单元、pin↔pad 映射（1:N/N:1） | G（节点带属性） |
| 规则与优先级（含生效后的最终值） | G + B |
| 协作锁、dirty 状态 | V |

### 3.3 只能近似 → 必须标注

温度场、回流路径长度、耦合强度、拥塞度、栅格地图片。全部带 `estimated: true` + `method`，且**任何判定不得单独依赖近似量**（例：`fits()` 不许用栅格，必须精确求交）。

## 4. 让"不丢"变成可测的：`info_manifest` + 覆盖率 CI

这是本设计最关键的一件工程化产物。

```yaml
# info_manifest.yaml —— 信息完备性契约
- id: geom.pad.aperture
  desc: 焊盘圆角/槽孔/阻焊开窗/钢网
  home: oracle
  query: "pads_of(ref, {detail: full})"
  precision: exact
  consumer: [solver, ai]        # ai=模型可以直接读结果做判断
  fixture_test: "fixture/board_a: U1.pad3 有 mask_expansion 字段且值>0"
- id: topo.return_path.cross_split
  home: both
  digest: "layout_report.cross_split_count"
  query: "cross_split(net)"
  precision: exact
- id: intent.datasheet_layout_rule
  home: external                # 源缺失，必须外挂
  source: "experience_lib(scope=mpn)"
  on_missing: "blind_spot('该 MPN 的布局准则未知')"
```

**三条 CI 门禁**

1. **覆盖率**：manifest 中每条都必须 `home ∈ {digest, oracle, both, external}`，且 `both/digest` 有 digest 路径、`oracle/both` 有 query。**不存在 `home: none`** —— 这条就是"没丢"的机器证明。
2. **精确性**：每条 `precision: exact` 的 query 必须在 fixture 板上跑通并返回声明字段，字段缺失即失败。
3. **回避性**：`home: external` 的条目，当外部源缺失时，`blind_spots` 必须出现对应条目；否则失败。

⇒ 从此"这份表示丢了什么"不再是争论，而是**构建失败或通过**。

## 5. 投影：按问题取片，不是一次摘要

同一个真值，不同问题给不同的 token 流——这是"可读"的真正来源。

### 问题 A：「8×6 的新模块放哪？」
```
QUERY fits_where(8x6, rules={courtyard:0.3, edge:0.5})
→ 候选 3 个（按 bus 距离升序）
  1. rect:F1 14.2x6.0 @(2.0,12.0)  余量 +6.2x0.0   最近 net: VIN(3.2mm)
  2. rect:F3  9.5x3.2 @(40.0,4.0)  余量 +1.5x-2.8  ✗ 高不足
  3. rect:R1 15.0x4.0 @(20,12) B.Cu 余量 +7.0x-2.0  ✗ 单面约束冲突
→ 推荐 F1；若须靠右，需移 C2 打开 2.8mm
```
（全部数字由 oracle 精确算出，模型只做选择）

### 问题 B：「为什么这个放大器增益误差可能超标？」
```
QUERY diagnose(budget=gain_error)
→ 该预算由 3 条约束守护，2 条告警
  R-sym(R1,R2):   offset 0.41mm > tol 0.10  ✗
  P-kelvin:       shared_path 1.8mm > 0.5   ✗
  R-match(Q1,Q2): ΔT 0.42C ok
→ 结论: 先修对称（影响 ×2.3 于 kelvin，按灵敏度估计）
```
（灵敏度也是工具算的，不是模型猜的）

### 问题 C：「现在整体长什么样？」
```
QUERY map(pitch=2mm, layers=merged)
→ 只给字母图 + 图例。禁止据此做任何判定（已标注）。
```

**"信息不够"的根因就是：旧设计只提供 C，没有 A 和 B。**

## 6. 写路径的无损（同等重要）

读能问全，写也必须不破坏任何东西：

1. **所有写经引擎**：立创走扩展 API、KiCad PCB 走 IPC，让引擎维护不变量；只有 KiCad 原理图因为无 API 才走 S-expr 改写，且必须过 `validate` + 逐字段回读。
2. **写前 gate**：`hard 经验` + 预算护栏 + 协作锁 + dirty 检查。
3. **幂等**：同一 spec 重放不产生副本（按 `plan_id` 去重）。
4. **round-trip 自证**：读 → 重放 → 再读，比对**语义等价**（不是字节，因为引擎自己会重排）；不等则报错并回滚 checkpoint。
5. **diff 必须给**：每次 apply 回 `Δ`（新增/删除/移动/改网），而不是回全量。

## 7. 分工矩阵：谁做什么（这是"AI 擅长"的落地）

| 工作 | AI | 算法/求解器 | 人 |
|---|---|---|---|
| 需求 → spec | ✅ | | 确认预算 |
| 选模式（共质心/交错/星点） | ✅ | | |
| 写关系约束（对称/邻接/远离） | ✅ | | |
| 求解坐标 | | ✅ | |
| 布线 | | ✅ | |
| 算指标/余量 | | ✅ | |
| 按余量做取舍（哪个预算先保） | ✅ | | |
| 裁决分诊（先修哪个） | ✅ | | 拍板 |
| 视觉观感 | | （出图） | ✅ |
| SI/PI 定量 | | ✅ 或拒绝 | |
| 设计意图补全 | ❌ 必须问 | | ✅ |

**判定"AI 擅长的形态"的唯一标准：模型的操作对象里不出现需要它自己计算的连续量。**

## 8. Token 设计八条（把"擅长"落到每条消息上）

1. **用句柄，不用坐标**：`U1` / `net:VIN` / `rect:F1` / `pin:U1.VIN`。句柄可解析到精确几何。
2. **相对优先**：`bearing: SE, d: 2.6mm, same_side, rotΔ: 90` 优于两个绝对坐标。
3. **只给 top-k**：按当前问题相关性排序，默认 k≤8；其余用 `expand()`。
4. **分档 + 原值双轨**：`density: high (>0.8)`，原始 0.7823 留在 oracle。
5. **给差量**：`Δ vs step6: +2 parts, unrouted 13→11`；模型已有前文，不必重发全量。
6. **三态标注**：每个数都带 `exact | estimated(method) | unknown`。
7. **告警三件套**：`成因 + 可执行动作 + 句柄`。缺一项即为不合格输出。
8. **成本自述**：每个查询声明 token 成本，系统按预算裁剪（超预算时降 k 或换投影，而不是截断 JSON）。

---

## 9. 这套设计如何回答用户的三个担心

| 担心 | 回答 |
|---|---|
| "会丢信息" | 丢不丢由 `info_manifest` 覆盖 + 三条 CI 门禁判定，不靠人保证；连续量一律走精确 oracle |
| "AI 拿到的布局信息不够" | 布局不进 tokens 的只有坐标；对称/模式/预算/余量/成因全部进，且 `layout_report` 是独立闸门 |
| "AI 不擅长" | 模型只见六种离散原语；所有连续计算由 oracle 完成；坐标由求解器产出 |

---

## 10. 结论（一句话）

> **转化不是"把 PCB 压成文本"，而是「建立无损索引 + 精确问答」，再把模型的操作界面限定为六种离散原语：图、关系、模式、预算、裁决、地图。**
> 无损由 manifest 覆盖率证明；可读由"模型永不自己算连续量"保证。

---

## 11. 立即可做的三件事（按性价比排序）

1. **写 `info_manifest.yaml` 首版**（按 §3 两张表逐条列全，约 60~80 条）——这是整个项目的契约，先于任何代码。
2. **在 fixture 板上把 `oracle` 的 11 个查询实现出来**（§3.1 那张表），每个返回 `{value, precision, handles}`。
3. **用 fixture 跑 §5 的三个投影**，人工检查"模型拿到这些够不够做决定"——这是唯一值得先花时间的验证。
