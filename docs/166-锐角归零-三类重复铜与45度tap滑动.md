# 166 · 锐角归零：三类重复铜、45° tap 滑动、以及「让 KiCad 当 oracle」

用户的原话是「还是狗屎，mcp对你缺少太多约束了…之前说的问题还有还有锐角走线」。
0.1.28 已经把锐角变成**会拒绝的闸门**（`board_shape_gate` 的 `acute_corner` 是 blocking），
但闸门只是报警，板子上的 **8 个锐角还在**。这一版把它们逐个归因、逐个修掉，
交付板 `board_shape_gate` 判 **`shape_pass`**（acute 0 / off_45 0 / duplicate 0 / arcs 0）。

版本 **0.1.29**。

## 1. 先归因：8 个锐角不是 8 种病，是 3 种病

拿 `_k0`（仓库板 `examples/rk3506_som/rk3506_som.kicad_pcb` 的副本，4209 段 / 630 孔 /
未连接 8 / acute 8 / duplicate 21 / off_45 0）逐顶点 dump 同网同层段（`_k9.py`），
按 `shape_gate` 的口径：顶点收「离开顶点方向」的射线，两两夹角 `<90` 记 blocking 锐角。
**0° 不是第六种几何，它是「两条射线同向」**——也就是同一段铜画了两遍，其中一遍是另一遍的前缀。

**结论：8 个锐角里 5 个是重复铜（#1/#3/#4/#6/#7，其中 #3/#4 是同一对），
2 个是「重复铜清掉后剩下的真 2 腿锐角」（#2/#5），1 个是拓扑性的 45° tap（#8）。**
所以工具也要三类，不能一把锤子。

## 2. 四个工具，各自只干一件事

`dedup_copper.py`（既有）只认「两端点都相同」；
`chamfer_acute.py`（既有）只认「2 条腿」；
本轮新增两个，正好补上它们够不到的两类。

### 2.1 `dedup_partial.py` —— 删「画在自己身上」的那一段

判据（全部满足才删，任一条不满足就 `refused` 并打印理由）：

* 同网同层，短段**严格更短**（容差 `--tol`，默认 **0.01 mm**）；
* 短段的**两个端点都落**在长段的体内（`_on_seg()`：投影 u ∈ [−tol/len, 1+tol/len]
  且垂距 ≤ tol）；
* 留下的铜**不比删掉的细**（`kept.w >= gone.w`）。这条是硬门——把 0.5 的粗线删了留 0.1，
  板上就多一条载流只有 1/5 的线，比锐角糟糕得多；
* 写盘前重算未连接数，**升了就不落盘**。

实测：**17 对 / 21.32 mm 冗余铜，未连接 8 → 8，acute 8 → 5**（tracks 4209 → 4137）。

### 2.2 `heal_acute_loop.py` —— 三腿、三角形、45° tap

`chamfer_acute` 只会处理 2 条腿；3 条腿以上直接跳过（它自己说得对：切哪个都不知道）。
这个工具换策略：**不求「切」，而求「少一条腿」**。

* 策略 A（drop 子集）：在锐角附近同网同层段里枚举 ≤ `--max-drop`（默认 3）个删除，
  四个条件同时成立才接受
  1. 局部不再有锐角；
  2. 不产生悬空端点（`covered(strict=True)`——**只认「落在别的段内部 / 焊盘 / 过孔」，
     自己那条段的端点不算覆盖**，这是第一版最大的 bug，见 §4.1）；
  3. 被删段的端点仍然落在同网铜上（没有把某段从中间断开）；
  4. **局部 pad/via 的连通分组不变**（`_groups` + `keeps_anchors_together` 并查集，
     T 型交点用「端点落在另一段内部」的规则合并）。这条是第二版补的：不加它，
     工具会把 U1 的三颗电源球切成孤岛（未连接 8 → 9）。
* 策略 B（slide tap）：45° 斜线接一条直通线成 45° 时，若斜线远端还有一条**轴向**段，
  把那条轴向段的端点**滑到与直通线的交点**（`SLIDE_MAX=0.80 mm`，交点须落在同网铜内部），
  再删斜线——这样斜线消失、交点变成 T，全部是 90°。

实测：

* `/+1V35_DDR` F.Cu `(20.306,26.331)`：drop 2 片（`(20.675,26.050)→(20.394,26.331)` 0.40 mm
  与 `(20.394,26.331)→(20.306,26.331)` 0.09 mm），三角形的两条斜边一起走，两个锐角同灭；
* `/+3V3` In4.Cu `(10.200,3.900)`：slide tap 0.30 mm 把 `(10.500,3.600)→(11.090,3.600)`
  的端点移到 `(10.200,3.600)` 成 T，再删斜线；
* **未连接 8 → 8**，acute 3 → 0，tracks 4139 → 4136（净 −3）。

### 2.3 `prune_dangling.py` —— 判官是 KiCad，不是我的几何

删完重复铜会剩 0.05 mm 级的孤子：它不改网络、不撞净空，但 DRC 报 `track_dangling`。

这个工具的第一版是**自己判连通**，结果一次标出 **80 条「悬空」**，全删后
**未连接 8 → 56** —— 板上有大量 0.05 mm 台阶微段（0.0707 = 0.05√2、0.0500），
相邻两条平行偏 0.05 mm、**中心线永不相交但 0.1 宽的铜叠在一起**。
第二版改判「铜是否重叠」（`d <= 0.003 + half + w/2`）又太松，把 DRC 真报的 5 条也判成连通，**0 条候选**。

正解是**不要自己重写引擎已经知道的判断**（和「铺铜只能用官方 `ZONE_FILLER`」是同一条纪律）：
读 `kicad-cli pcb drc --format json` 里 `type=track_dangling` 的 `items[].uuid`，
按 `GetUuid().AsString()` 匹配，只删这些、且长度 ≤ `--max-len 0.25` 的。

实测要**跑两轮**才归零：第一轮删 5 条（0.050–0.078 mm）后，DRC 又报 3 条
（端点更极端的幸存者暴露出来），第二轮删完 `track_dangling` 归零。

## 3. 流水线与交付读数

```
_k0  仓库板原样                              4209 段 / 630 孔 / acute 8 / dup 21
     ↓ dedup_copper            −55 段 / 27.73 mm        → _k1  4154 段 / dup 0 / acute 8
     ↓ dedup_partial           −17 段 / 21.32 mm        → _k2  4137 段 / acute 5
     ↓ chamfer_acute           +2 段（2 处倒角）         → _k3  4139 段 / acute 3
     ↓ heal_acute_loop         −3 段 +1 次 tap 滑动      → _k4  4136 段 / acute 0
     ↓ prune_dangling  ×2 轮    −5 −3 段                → _k6  4128 段 / acute 0
     ↓ 官方 ZONE_FILLER（_refill.py）                    → _k7  4128 段 / 630 孔（逐位不变）
```

`_k7` 实测：

| 门 | 读数 |
|----|------|
| `board_shape_gate` | **`shape_pass`**：`acute_corner` 0 / `off_45_heading` 0 / `duplicate_copper` 0 / `arc_tracks` 0 / `square_corner` 422（judgement 非 blocking）|
| `kicad-cli pcb drc --severity-all` | **30 项**（`zones_intersect` 1 error + `via_dangling` 29 warning）、**未连接 8**，与 `_k0` 在仓库路径下的基线**逐类别逐条数相同**，无新增类别 |
| `track_dangling` | **0** |
| 过孔数 | **630 不变**（全程没动过孔）|
| 灌注 | 官方 `ZONE_FILLER` 前后 tracks / vias / zones 与 DRC 全一致 ⇒ 删铜没有让铺铜失效 |

三点必须讲清楚，不粉饰：

1. **`square_corner 422` 没消。** 它是 0.1 mm 级的 90° 转角，闸门里是 judgement 不是 blocking
   （`strict` 才拦）。这些是绕净空墙的必然产物，要消得改布线器栅格，见 0.1.28 的负读数。
2. **`detour_ratio` 硬档还剩 2 项**：`/FB_U7` **2.83**（16.71 mm / MST 5.91）、
   `/SW_U7` **2.54**（27.74 / 10.90），硬帽 2.5。这两条是「绕了一大圈」的那类丑，
   根因在布局（U7 周围的 buck 簇与走廊），不是把某段掰直能解决的。
3. **DDR 线仍是原样。** U1↔U2 的 22 条 DQ/DM/DQS 网 Kendall 反序数 **95/231**
   （转 90° 176、转 180° 136、**转 270°+镜像 47**），也就是说「DDR 画的线还是狗屎」
   的根因是**球位顺序天然交叉**，属布局/映射层。这一版没动布局。

## 4. 四个只在真板才现形的坑

### 4.1 「自己的端点」被当成覆盖

`covered()` 第一版把「落在这条段的端点上」也算有铜。于是 0.088 mm 的死胡同被判「不悬空」，
工具选出「删两条对角线」的错解 —— 网络就在那两个端点之间，删完未连接 8 → 9。
修法：加 `_interior_of(p, s)`，判悬空用 `strict=True`（只认落在**别的**段内部 / 焊盘 / 过孔），
判「端点还连着铜」用 loose。**同一块板上两种「连通」语义必须分开写，一个函数顶不住。**

### 4.2 删掉锐角的同时把焊盘切成孤岛

`/+1V35_DDR` 那个三角形，两条斜线删掉后角上那颗 via 与相邻球之间只剩一条边，
局部 pad 分成两组。修法是 §2.2 的条件 4：`_groups()` 按「端点落在另一段内部」做并查集，
删前删后分组必须逐组相同。加上之后工具自动改选「删斜线 + 删 0.09 水平段」，未连接 8 → 8。

### 4.3 悬空判据不能自己发明（见 §2.3）

### 4.4 `w 0.000`

`heal_acute_loop` 第一版打印的宽度全是 0：`MM(t.GetWidth())/1e3` 里 `MM()` 已经除过 1000，
又除了一次。读数错不会崩，但判断「留下的铜不比删掉的细」直接失效。
