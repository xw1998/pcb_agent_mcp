## 2 MCP 能动的那一侧只有一件事：让每次交接便宜

不能对宿主撒谎，也不能编一个不存在的 MCP 缺陷。但「补回记忆」这件事当前的
代价是让模型重写一篇多页交接摘要——那正好是 260 秒里最贵的一段。于是 0.0.114
加的是一个**只写不删的进度日志**：

| 动作 | 行为 | 反向对照 |
|---|---|---|
| `board_journal(action='add')` | 一行 JSON（≈100 B），`text` 硬上限 400 字符 | 401 字符 → `ARG_TOO_LONG`，库内条数不变 |
| `board_journal(action='tail', limit=8)` | 最后 N 条 + 字节成本 | 8 条回包实测 < 2 KiB（自检断言） |
| `board_journal(action='clear', confirm=true)` | `os.replace` 改名 `.bak-<stamp>` | 不给 `confirm` → `CONFIRM_REQUIRED`；旧文件仍在 |
| 写满 4000 条 / 2 MiB | `JOURNAL_FULL` 拒绝新增 | 绝不为了腾地方丢旧条目 |

存储：`$PCB_AGENT_HOME/journal.jsonl`（默认 `~/.pcb_agent_mcp`），只在该有写入时
创建；`PCB_AGENT_JOURNAL=0` 可关。

## 3 三条不许读错的边界

1. **日志证明「这行字在盘上」**，不证明任何布线/DRC 发生过。`tail` 每次原样
   返回 `what_this_proves`，就是为了让这句话不可能被漏读。
2. **`PCB_AGENT_JOURNAL=0` 时 `tail` 报 `status=disabled`，同时报出磁盘上仍有
   几条**。「没读到」不等于「没做过」——这条和 ACU 线「读数层失败 ≠ 被测对象
   被否证」是同一条纪律。
3. **`clear` 是改名不是删除。**

## 4 用法（长任务的标准动作）

```python
board_journal(action='add', kind='route',
              text='g4n4 PC15->J2B.3 / PC2->J2B.7 走完，issues 0',
              board='v21_g4n4.kicad_pcb', data={'issues': 0})
board_journal(action='add', kind='handover',
              text='下一步 g4n5：PA8/PA9/PA10；PA8 不能用 x=54.45 的缝（0.45<0.625）',
              board='v21_g4n4.kicad_pcb')
```

新会话第一件事：`board_journal(action='tail', limit=8)`，然后**仍然要**重读板子
文件并跑 DRC——日志是路标，不是证据。
