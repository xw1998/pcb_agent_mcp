# 25 技能并入：八个技能里哪几条进了工具，哪几条拒绝进

这一篇记的是**外部技能文本 → 代码**的那一步，以及为什么有的技能整份被拒。取舍的唯一
标准是：它能不能变成**一个可复算、可回代、量不到就说量不到**的工具。凡是只能变成一段
建议的，就不进代码（AI 自己会说话，不需要我替它写一段模板）。

## 25.1 八个技能的处置

| 技能 | 内容 | 处置 | 理由 |
|---|---|---|---|
| `boost-inductor-circuit-calc` | CCM Boost 电感公式 + 算例脚本 | **改用**：`calc/magnetics.py`（顺手把 buck / buck-boost 同族补齐） | 纯算术，每条公式可手算复核 |
| `kicad-free` | 布局/布线规则、去耦配置、打样清单、Gerber 层表 | **改用**：`calc/rules.py` 布局目录 22 条 | 规则本身是「量一个数、比一个门限」，正是可机判的形态 |
| `circuit-analysis` | 漏件清单、可复算参数、证据阶梯 L0~L3、严重度分级 | **改用**：`calc/rules.py` 原理图目录 14 条 + 每条规则的 `evidence_level` | 清单可变成事实项；证据阶梯变成「这条规则要靠什么等级的证据才能判」 |
| `rf-circuit-design` | 匹配/PA/频段/板材/层叠/走线/接地/调试 | **改用**：`calc/stackup.py`（板材表 + 4/6 层叠 + 每层 50Ω 线宽 + λ_g/20）、`calc/chain.py`（Friis 级联 NF + IIP3 + 灵敏度）、`matching.bandwidth`（BW=f0/Q）、`calc/rules.py` 的射频条目 | 有公式的部分进代码；「先调输出再调输入」这类调试顺序只进了规则的 `how_to_measure` 文案 |
| `circuit-diagram-generator` | 生成 CircuiTikZ/LaTeX 并编译 PDF | **拒** | 要 LaTeX 工具链，与「零 runtime 依赖、只用 stdlib」直接冲突；它解决的是**出图**，不是**算数** |
| `circuit-analyze` | 目录为空 | **拒（无内容）** | 本机没装，连 SKILL.md 都没有 |
| `gmai-pcb-manufacturing` | 按制造能力核对参数 | **拒** | 付费壳（¥29.90/次，X402）：`references/` 只有使用说明，业务逻辑在付费墙后 |
| `gmai-pcb-layout-review` | 按阻抗/回流/EMC 审查布局 | **拒** | 同上（¥34.90/次）。而且实测其 `main.py` 的 `PARAMS` 是**固件安全审计**样板（签名校验 / 调试口 / 端到端校验），与 PCB 制造与布局无关——模板串了域，搬过来只会污染规则目录 |

## 25.2 新增的八个工具

| 工具 | 回答什么 | 它明确不回答什么 |
|---|---|---|
| `magnetics_inductor` | CCM boost/buck/buck-boost 的占空比、电感量、峰/谷/有效电流、CCM 结束点 | 磁芯选型、磁芯损耗、DCR、DCM 稳态（DCM 里 D ≠ 1−Vin/Vout）、环路补偿 |
| `stackup_material` | 这个频率该用什么板材，为什么，代价是什么 | Dk 随频率/玻纤的曲线、批次公差、工艺兼容性 |
| `stackup_design` | 4/6 层叠 + 每信号层 50Ω 线宽 + 缝合孔间距 + 铜平衡 | 真实压合结构（本工具的介质分配是**等比**的） |
| `rf_chain` | 级联增益、Friis NF（含各级占比）、级联 IIP3/OIP3、kTB 底噪与灵敏度 | 级间失配损耗、IP3 相关性（公式是worst case）、压缩点与 IP3 的 10 dB 经验关系 |
| `match_bandwidth` | BW = f0/Q，以及 VSWR≤S 圈内的带宽（乘 (S−1)/√S） | 多谐振匹配（不服从这条关系）、带内 S11 形状 |
| `design_rules` | 两套规则目录：id、需要哪个事实、怎么测、证据等级、出处 | —— |
| `layout_review` | 用你测到的事实给布局规则判 pass/fail/**undetermined** | 不替你读板（只判事实） |
| `schematic_review` | 漏件清单 + IEC 60664 隔离间距 | 不把网表解析成「这颗 IC 的电源脚」（事实要你自己数） |

## 25.3 三条被写进代码的「不许错答案」

1. **没量过 ≠ 通过。** `layout_review` / `schematic_review` 里，事实缺失一律 `undetermined`，
   并带上 `next_check`（怎么测、什么证据等级）。空事实集直接 `ARG_MISSING` 拒答，不给一份
   全绿的假报告。测试里有专门一条：`a_missing_measurement_is_never_a_pass`。
2. **限值能算就算，不算就拒。** 3W 间距的门限是 `3 × 该线自身线宽`（线宽没给 ⇒ 无门限）；
   缝合孔间距是 λ_g/20（没给频率 ⇒ 无门限）；电源线宽按 IPC 图表算，但**必须显式指定标准**
   （`ipc2221` 与 `ipc2152` 同一问题差 3 倍以上，替调用方选就是错答案）；隔离间距走
   IEC 60664-1，而那张表在本仓库里是 `verified: false`，所以这条规则**永远 fail-closed**，
   报「安全距离表不可用，拒绝回答」。
3. **饱和只有拿到器件才判。** 电感峰流算出来只是「绕组要承受多少」，没有任何磁芯信息时
   `saturation.verdict = undetermined`，并说明缺的是 Isat 及其温度降额。

## 25.4 可复核的锚点

| 断言 | 数值 | 复核方式 |
|---|---|---|
| Boost 5→12 V / 1 A / 500 kHz / η=0.9 / r=0.3 的占空比 | 0.625 | `1 − 0.9×5/12` |
| 同一设计点的电感量 | 7.8125 µH | `5×0.625/(0.3×2.6667×500e3)` |
| 有效值 | √(Iavg²+ΔI²/12) | 三角波定义 |
| 技能 §4.4 的三级 LNA（0.8/15、1.2/20、2.0/10 dB） | 本工具 0.8369 dB，技能原文 0.83 dB | Friis |
| 级联 IIP3（0 dBm 经 20 dB 增益到 10 dBm） | −10.4139 dBm | `1/IIP3 = 1/1mW + 100/10mW = 11/mW` |
| 2.4 GHz FR4 的 λ_g | 60.2 mm ⇒ λ_g/20 = 3.01 mm | `c/(f√er)/20` |
| 4 层 1.0 mm FR4 的 L1 50Ω 线宽 | ≈0.63 mm（介质 0.3333 mm） | `feedline_width` 同模型回代 |

其中 2.4 GHz 那一行值得单独记：技能 §3.5 的表写「2.4 GHz、FR4、λ/20 = 1.5 mm」，与
`λ_g/20 = 3.01 mm` 差一倍（1.5 mm 实际是 λ_g/40）。**表里的数字与它自己的公式不自洽**，
所以工具只实现公式（`rf.lambda_over_20` 早就在了），并把 `divisor` 暴露给调用方，
不搬那张表。

## 25.5 没搬的部分（诚实清单）

- **调试/测量流程**（VNA 校准顺序、S11/S21 测法、匹配分步调试、常见问题与解决）：
  这些是人的动作，不是计算。它们的可用部分已经落进规则目录的 `how_to_measure`。
- **真知报告方法论**（`circuit-analysis` 的 `references/truth-knowledge-report.md`：
  证据标签「已确认/强支持/中度支持/可行备选/未决/已反驳」、四真门、Kxx 模块模板、
  报告章节骨架）：这是**写作格式**，不是计算，也不属于本 MCP 的产物形态（本 MCP 返回
  信封，不写报告）。唯一被吸收的是「证据等级」这个思想——它变成了每条规则的
  `evidence_level`（L0 读文件 / L1 计算或万用表 / L2 仿真或台架 / L3 实验室）。
- **封装焊盘推导**（`pad_w = W×1.1`、`pad_l = L×0.6+0.6`）：技能自己注明「以 datasheet
  为准」，属于必须查表的东西，本仓库不做封装生成，故未实现。
- **屏蔽腔 / 腔体谐振设计**：尺寸 < λ/20 的判据可以机判，但腔体一旦成形就是 3-D 问题，
  `cavity_*` 已经给了平行板模与过孔围栏比值，不再加「屏蔽腔够不够」的判据——那需要
  全波，没有全波就是猜。

## 25.6 复现

```bash
python -m pcb_agent_mcp.server --selftest          # 87 项，含本节全部锚点
python -m unittest discover -s tests -p "test_skills.py" -v
```

工具自述里对应的能力段：`calc_capabilities` 的 `magnetics` / `stackup` / `review` 三节，
以及 `evidence` 里的 `magnetics / stackup / chain / bandwidth`、`rule catalogues` 两行。
